# Генератор формы рабочего места производства

`src/cf/src/DataProcessors/АРМПроизводство/Forms/Форма/Form.form` собрана скриптом, а не руками в EDT: форма большая
(три таблицы с вводом, панели отмеченных строк, панель фильтров), и EDT-XML удобнее порождать кодом.

Источник правды — по-прежнему `Form.form` в `src/cf`. Генераторы нужны, чтобы следующая правка формы не начиналась с
нуля:

| Файл | Редакция формы |
|---|---|
| `gen.py` | общие построители элементов EDT-XML, тексты на четырёх языках (редакция 1, E12.1 — 2.0.15.29) |
| `gen2.py` | редакция 2 — панель фильтров, свойства таблиц по эталону списка реализаций (2.0.15.30) |
| `gen3.py` | редакция 3 — команды таблиц в панели отмеченных строк, сворачиваемая цепочка, фильтры строкой (2.0.15.31) |
| `gen4.py` | редакция 4 — закладки «Заказы поставщику» и «Поступления» (E12.2, 2.0.15.32) |
| `gen5.py` | редакция 5 — закладки «Выпуск» и «Отгрузки», «Выпуск по заказу», общие команды строк (E12.3a, 2.0.15.33) |

Проверка, что генератор совпадает с формой в репозитории:

```bash
cd scripts/formgen/arm
python3 gen5.py | diff - ../../../src/cf/src/DataProcessors/АРМПроизводство/Forms/Форма/Form.form
```

Если форму правили в EDT, генератор устарел: сначала перенести правку в него или править `Form.form` напрямую. После
генерации — Refresh в EDT, `scripts/listcheck.py`, смок (урок tiny1C forms-009: форма, собранная скриптом, может
уронить клиент там, где ручная — нет).
