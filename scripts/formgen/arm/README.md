# Генератор формы рабочего места производства

`src/cf/src/DataProcessors/АРМПроизводство/Forms/Форма/Form.form` собрана скриптом, а не руками в EDT: форма большая
(три таблицы с вводом, панели отмеченных строк, панель фильтров), и EDT-XML удобнее порождать кодом.

Источник правды — по-прежнему `Form.form` в `src/cf`. Генераторы нужны, чтобы следующая правка формы не начиналась с
нуля:

| Файл | Редакция формы |
|---|---|
| `gen.py` | общие построители элементов EDT-XML, тексты на четырёх языках (редакция 1, E12.1 — 2.0.15.29) |
| `gen2.py` | редакция 2 — панель фильтров, свойства таблиц по эталону списка реализаций (2.0.15.30) |
| `gen3.py` | редакция 3 — команды таблиц в панели отмеченных строк, сворачиваемая цепочка, фильтры строкой (2.0.15.31) |
| `gen4.py` | редакция 4 — закладки «Заказы поставщику» и «Поступления» (E12.2, 2.0.15.32) |
| `gen5.py` | редакция 5 — закладки «Выпуск» и «Отгрузки», «Выпуск по заказу», общие команды строк (E12.3a, 2.0.15.33) |
| `gen6.py` | редакция 6 — закладка «Переработка», «Поступление из переработки» (E12.3b, 2.0.15.34) |
| `gen7.py` | редакция 7 — кнопки ввода на основании в панелях своих закладок, ширины колонок, движение и подвал на «Документах» (E12.4, 2.0.15.35) |
| `gen8.py` | редакция 8 — генератор догнан до формы: способ изготовления и дерево материалов (2.0.15.39–40), закладка «Поступления из переработки» и её команды (S6, 2.0.15.48), обработчики активизации строки нижних таблиц (2026-09-22) |
| `gen10.py` | редакция 10 — поверх `gen9.py`: `gen10_columns.py` (узкие количественные колонки, короткие заголовки с подсказкой во всех таблицах документов) и `gen10_panel.py` (закладка «Передача в переработку», колонка ПФ/ГП, таблица свойств ПФ/ГП справа) (2.0.16.16) |
| `gen9.py` | редакция 9 — поверх вывода `gen8.py` фрагментами `gen9_materials.py` (колонки «Материалов») и `gen9_panel.py` (панель фильтров со справочниками, стадией и периодом отгрузки, запрос списка, пагинатор с легендой) (2.0.16.14) |

**Генератор совпадает с формой** (редакция 10, 2026-10-05; редакция 8 — 2026-09-22): `gen10.py` печатает `Form.form` из `src/cf` байт в байт.
Перенесены правки, которые делались руками после редакции 7: колонка «Способ изготовления» (2.0.15.39), дерево
материалов (2.0.15.40 — реквизит `Материалы` типа `ValueTree`, колонки «СпособИзготовления» и «Уровень»,
`representation Tree`, «Материал» перед «Продукцией»), закладка «Поступления из переработки» с её реквизитами,
командами и кнопкой «Поступление строкой» (S6, 2.0.15.48), обработчики `ПриАктивизацииСтроки` нижних таблиц и
редактируемый склад передачи.

Идентификаторы элементов генератор выдаёт счётчиком по порядку вывода. Элементы, которые при ручной правке получили
номера вне этого порядка (колонка способа изготовления — 431, страница поступлений из переработки — 500–548, кнопка
«Поступление строкой» — 549), собираются под `with_ids`: счётчик прижимается к их номерам, иначе редакция
перенумеровала бы половину формы и дифф с репозиторием стал бы нечитаемым.

Проверка, что генератор совпадает с формой в репозитории:

```bash
cd scripts/formgen/arm
python3 gen10.py | diff - ../../../src/cf/src/DataProcessors/АРМПроизводство/Forms/Форма/Form.form
```

Если форму правили в EDT, генератор устарел: сначала перенести правку в него или править `Form.form` напрямую. После
генерации — Refresh в EDT, `scripts/listcheck.py`, смок (урок tiny1C forms-009: форма, собранная скриптом, может
уронить клиент там, где ручная — нет).
