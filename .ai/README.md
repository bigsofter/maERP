# .ai/ — слой AI-оркестрации maERP

USER → CLAUDE → SPECIALIZED AGENTS → CLAUDE → VALIDATION → USER.

Claude Code — оркестратор, архитектор и основной разработчик. Codex (состязательный ревьюер) и
OpenCode (дешёвые специалисты) подключаются обёртками `.ai/bin/ai-*`, когда ставки задачи этого
требуют: промпты между инструментами руками не копируются. Этот файл — источник истины о том, как
это устроено в maERP. Секция «Оркестрация» в `CLAUDE.md` только ссылается сюда.

Перенесено 2026-09-13 с эталона TinyCIO (`~/Dev/tinycio/.ai`). Механика обёрток — оттуда без
изменений; паёк ревьюера, маркеры риска, гейты, промпты и агенты переписаны под 1С. Всё в разделе
«Verified facts» проверено на этой машине в тот же день, а не предположено.

## Из чего состоит

| Часть | Роль | Пишет код? |
|---|---|---|
| Claude Code (главная сессия) | оркестратор, архитектор, основной разработчик, финальный интегратор | да |
| Codex (`codex exec`, вход через ChatGPT) | независимый состязательный ревьюер | **никогда** на ревью (`-s read-only`) |
| OpenCode (`opencode run`, подписка **OpenCode Go**, `opencode-go/kimi-k3`) | дешёвые специалисты: explorer / reviewer / database / security / tester | только `routine-dev`, и только в изолированном worktree |
| `.claude/agents/*.md` | субагенты Claude внутри сессии — фоллбэк, когда OpenCode недоступен, или когда дешевле не выходить из процесса | нет (у всех четырёх нет Edit/Write) |

**Модель под задачу** (`model:` во фронтматтере `.claude/agents/*.md`, перебивается параметром
`model` у вызова Agent):

| Субагент | Модель | Почему |
|---|---|---|
| `architecture-critic` | `opus` | состязательный разбор плана — единственное место, где нужна глубина, и он дешевле внешнего `ai-review-plan` |
| `test-analyzer` | `sonnet` | анализ покрытия (смок, `ТестыДокументов`, реестр) + запуск тестов |
| `repository-explorer` | `haiku` | поиск по репозиторию: грепы и точечное чтение |
| `final-validator` | `haiku` | запустить `ai-final-check` и выжать вердикт из отчёта |

`docs-registrar` из эталона **не заведён**: у maERP нет журналов `docs/ai/**`, которые он ведёт.
Документацию по теме (TESTING, TECHDEBT, ROADMAP, «Что нового») главная сессия правит сама.

Модель главной сессии субагентам с `model:` не наследуется, а сама себя сессия с Sonnet на Opus
не поднимает — это делает человек (`/model`). Рабочая схема: главная сессия на сильной модели
планирует и делает сложную правку, механическое (поиск, гейты) уходит в дешёвых субагентов и в
OpenCode.

## Обёртки (`.ai/bin/`)

Все скрипты подключают `.ai/bin/ai-lib.sh` (общие функции) и `.ai/config.sh` (пути, модели,
таймауты; локальные оверрайды — `.ai/config.local.sh`, в git не попадает). Первый позиционный
аргумент — **slug задачи** (короткое kebab-case имя). Артефакты: `.ai/state/<slug>/` (транскрипты,
gitignored) и `.ai/reviews/<slug>/` (находки, коммитятся).

- **`ai-doctor`** — реальная доступность бэкендов и инструментов гейтов (Codex, OpenCode и ключ Go,
  BSL LS + JDK 21, baseline линта, платформа 8.5.1, `SMOKE_USER`/`SMOKE_PWD`, клон tiny1C). Первое,
  что запускать, если что-то ведёт себя странно.
- **`ai-explore <slug> "<задача>"`** — read-only исследование агентом OpenCode `explorer`. Exit 2 =
  `BACKEND_UNAVAILABLE` → субагент `repository-explorer` (Agent tool): скрипт умеет звать только
  внешние CLI, субагента Claude он не создаст.
- **`ai-review-plan <slug> <plan-file|->`** — план реализации в Codex (`-s read-only`) до первой
  строчки кода. Обязателен для существенных изменений. Exit 2 — Codex не установлен или не залогинен:
  **сказать владельцу, что обязательный гейт не прошёл**, а не пропустить молча.
- **`ai-review <slug> [--base <ветка>|--commit <sha>|--uncommitted] [--verify] [--force]
  [--tier auto|free|codex] [--with-docs]`** — дифф в Codex (`-s read-only`). По умолчанию — рабочее
  дерево против HEAD. В промпт идёт **контекстный паёк** (`ai_context_pack`), чтобы ревьюер не тратил
  ходы на перечитывание правил:
  - срезы `CLAUDE.md` по заголовкам: «Где исходники» … «Проверка себя» и «Версия и список
    изменений»;
  - `AGENTS.md` затронутых каталогов (в maERP их пока нет);
  - оглавление правил tiny1C (core + greenfield, по строке на правило) с рецептом точечного чтения;
  - раздел «Правила» `docs/FORMS-STYLE.md`, если дифф трогает `Form.form`.

  Пустой срез (переименовали заголовок) не превращается в молча пустой паёк: печатается WARN и
  явная инструкция «прочитай раздел сам».
  - **`--verify`** — второй и последующие круги. Уходит ДЕЛЬТА с прошлого ревью (снимок дерева —
    `git write-tree` во временный индекс, настоящий индекс не трогается) плюс находки прошлого круга
    с вопросом «закрыты ли, не сломал ли фикс новое». Без прошлого ревью или снимка — внятная ошибка,
    а не тихий полный круг. Дельта показывает и содержимое новых, ещё не `git add`-нутых файлов.
  - **`--tier`** — `auto` (по умолчанию: полный круг → Codex, `--verify` → сначала OpenCode
    `reviewer`, фоллбэк на Codex), `free` (OpenCode и на полном круге), `codex` (только Codex;
    недоступен — честный `BACKEND_UNAVAILABLE`, а не тихий даунгрейд).
  - **Порог тривиальности.** `ai_diff_tier` делит дифф на `trivial`/`normal`/`risky`. Тривиальный
    (≤ 3 файлов и ≤ 30 строк; пороги `AI_TRIVIAL_MAX_FILES`/`AI_TRIVIAL_MAX_LINES`) платного ревьюера
    не зовёт: печатает `SKIPPED_TRIVIAL`, пишет заметку в `.ai/reviews/<slug>/`, выходит с 0. **Маркеры
    риска перевешивают размер** (см. «Маркеры риска maERP»). Нужно всё равно — `--force`. Пропуск по
    порогу — это НЕ «ревью пройдено», так и написано в заметке.
- **`ai-database <slug> [--base …]`** / **`ai-security <slug> [--base …]`** — специализированные
  ревью. Сначала агент OpenCode `database`/`security`, фоллбэк на Codex read-only. Exit 2 — только
  если недоступны **оба**. `database` в 1С — это реструктуризация, типы в `.mdo`, uuid из
  конфигураций клиентов, проведение и блокировки, обработчики обновления, запросы и динсписки.
  `security` — права ролей, привилегированные серверные вызовы, исполнение кода, пользователи и
  пароли, секреты в публичном репозитории, интеграция с хабом.
- **`--with-docs`** (все три ревью-обёртки) — `docs/**` и `.ai/**` **по умолчанию исключены из
  диффа**: в эталоне журнал + правила раздували промпт на ~60 %, а ревьюеру кода сказать про них
  нечего. `CLAUDE.md` и `AGENTS.md` не исключаются никогда — это правила. Если изменились только
  исключённые файлы, обёртка говорит «nothing changed» и называет флаг, чтобы пустое ревью не
  читалось как одобрение.
- **`ai-test <slug> [--analyze "<ожидаемое поведение>"] [--db]`** — `--analyze` просит агента
  OpenCode `tester` проанализировать покрытие (best effort, при недоступности — WARN). Затем
  **всегда** реальные тесты по составу изменений: уровни 0.5/0.7 (`scripts/refcheck.py`,
  `scripts/listcheck.py`) при правке `src/cf/**`. Уровни 1–3 (`scripts/smoke.sh`,
  `scripts/doctests.sh`) — только с `--db`: они проверяют `build/ib`, которую обновляет из EDT
  владелец. Без `--db` — явная строка «НЕ запускались», а не тишина. Плюс напоминания регламента
  `docs/TESTING.md` п. 2: новый документ без сценария в `ТестыДокументов`, новые объекты без
  `docs/TESTS.xlsx`.
- **`ai-final-check <slug> [--db]`** — реальные гейты maERP по составу изменений:

  | гейт | команда | когда |
  |---|---|---|
  | уровень 0: BSL LS | `scripts/lint.sh` (15 с) | правка `src/cf/**.bsl` |
  | уровень 0: нет новых замечаний | сверка `build/bsl-json.json` с `build/bsl-json-baseline.json` по «файл, код» со счётчиками, только изменённые модули (процедура RELEASING.md, шаг 2) | правка `src/cf/**.bsl` |
  | уровень 0.5 | `scripts/refcheck.py` | правка `src/cf/**` |
  | уровень 0.7 | `scripts/listcheck.py` | правка `src/cf/**` |
  | «Что нового» | `scripts/changelog.sh <версия>` + пункты на ru/fr/en/es (CLAUDE.md) | правка `src/cf/**` |
  | уровни 1–3 | `scripts/smoke.sh`, `scripts/doctests.sh` | только `--db` |

  Гигиена: запретные пути (`build/`, `DT-INF/`, `ConfigDumpInfo.xml`); бинарники 1С в индексе и
  untracked; NFC/NFD-дубликаты путей (tiny1C workflow-007); грубый поиск секретов + точный поиск
  значения `SMOKE_PWD` из env (печатаются только имена файлов); новые TODO/FIXME и подавления
  `// BSLLS:`; поднята ли версия; регламент тестов. Отчёт — `.ai/reports/<slug>-final-check.md`,
  **это не мастер-отчёт задачи**. Заканчивается разделом **`## Gates run`**: сколько гейтов ран,
  какие упали, какие семейства пропущены и ПОЧЕМУ. Всегда пропущен с причиной «EDT: синтаксический
  контроль и ссылочная целостность — только у владельца после Refresh»: отсюда его не запустить, а
  молча пропущенный гейт выглядит как пройденный.

Ни одна обёртка не выдумывает результат. Недоступный или упавший бэкенд — `BACKEND_UNAVAILABLE` (или
явная ошибка) в stderr и ненулевой код: см. FAILURE HANDLING.

**Цепочка бэкендов при лимитах** (2026-09-13). Каждый вызов OpenCode идёт по моделям:
`AI_OPENCODE_MODEL` (подписка Go, `opencode-go/kimi-k3`) → `AI_OPENCODE_FALLBACK_MODELS` (по умолчанию
бесплатный Zen `opencode/big-pickle`, cost:0). Переход — при ошибке, пустом ответе, общем таймауте и при
**зависании без вывода**: исчерпанный лимит Go не даёт ни ошибки, ни события, `opencode run` молча висит,
поэтому сторож `AI_OPENCODE_FIRST_EVENT_SECS` (90 с) снимает попытку без единого байта событий (rc 125).
Первая строка отчёта называет модель — ревью запасной бесплатной моделью слабее, и это видно в артефакте.
Дальше по-старому: `ai-database`/`ai-security`/`ai-review --verify` падают в Codex; полный `ai-review`
по умолчанию сразу Codex, при его лимите — `--tier free` (та же цепочка OpenCode). Кончилось всё —
субагенты Claude (`architecture-critic`, `repository-explorer`, разбор данных `general-purpose`) из
главной сессии; скрипт их не вызовет, и в отчёте прямо пишется, что обязательный гейт прошёл не на
своём бэкенде.

## Когда что запускать (не гнать максимальный сценарий на всё)

- **Тривиальная** (опечатка, мелкий изолированный фикс без вопроса архитектуры): Claude
  реализует → `ai-test` → `ai-final-check`. Без Codex и OpenCode. `ai-review` на такой дифф сам
  откажется звать платного ревьюера.
- **Средняя**: план в пару фраз → реализация → `ai-test` (с `--analyze`, если покрытие неочевидно) →
  `ai-review` → фикс подтверждённых находок → **`ai-review --verify`** (дельта, OpenCode) →
  `ai-final-check`. Полный круг — ОДИН, дальше только `--verify`.
- **Существенная**:
  - Что относится: новый объект метаданных или регистр, реструктуризация (новое измерение или
    ресурс, смена типа или удаление реквизита), проведение и движения, блокировки и транзакции,
    права ролей и привилегированный режим, обработчики обновления и первый запуск, перенос объектов
    из конфигураций клиентов, интеграция с хабом, сборка поставки.
  - Порядок: `ai-explore` (или `repository-explorer`) → план → по желанию `architecture-critic`
    как дешёвый отсев → **`ai-review-plan` обязателен** → правка плана по реальным находкам →
    реализация → `ai-test` → **`ai-review` обязателен**. **`ai-database`/`ai-security` обязательны**,
    если изменение трогает данные, метаданные и проведение или права, привилегии, пароли и
    интеграцию. Затем фикс подтверждённых находок → **`ai-review --verify --tier codex`** →
    `ai-final-check` (с `--db`, если владелец обновил `build/ib`) → отчёт.

Сдача владельцу — по-прежнему по CLAUDE.md: поднятый `Y`, секция «Что нового» на четырёх языках,
явное напоминание про Refresh и проверку в EDT.

## Маркеры риска maERP (`ai_diff_tier`)

Пути (по заголовкам диффа — сам факт правки уже риск):
- `.mdo` регистров, планов счетов и видов характеристик, последовательностей, констант, планов
  обмена;
- `Roles/`, `SessionParameters/`, `ScheduledJobs/`, `EventSubscriptions/`, HTTP- и веб-сервисы;
- скрипты сборки и развёртывания (`dist-build`, `push-release-to-hub`, `release-notes`, `changelog`,
  `ib-*`, `cf-*`, `xml-*`, `initial-fill*`, `env`), `.github/`, `.mcp.json`;
- удаление и переименование файлов.

Строки (только изменённые `+`/`-`, не контекст):
- метаданные: `<types>`, `<privileged>`, `<compatibilityMode>`, `<dataLockControlMode>`, запрос
  динсписка (`<queryText>`, `<customQuery>`, `<mainTable>`);
- транзакции и блокировки: `…Транзакцию`, `Блокировк*`, `Заблокировать`, `ОбменДанными.Загрузка`;
- проведение: `ОбработкаПроведения`, `Движения`, `НаборЗаписей`, `Отказ =`;
- деньги: `Себестоимост*`, `НДС`, `Взаиморасч*`, `ДенежныеСредства`, `Оплат*`, `КурсыВалют`;
- привилегии и пользователи: `ПривилегированныйРежим`, `РольДоступна`, `ПравоДоступа`,
  `ПользователиИнформационнойБазы`, `ПараметрыСеанса`, `БезопасныйРежим`;
- секреты: `Пароль`, `password`, `secret`, `token`, `hmac`, `api key`, `SMOKE_PWD`;
- внешний код и файлы: `HTTPСоединение`, `HTTPЗапрос`, `COMОбъект`, `КомандаСистемы`,
  `ЗапуститьПриложение`, `ВнешниеОбработки`/`ВнешниеОтчеты`, голые `Выполнить(`/`Вычислить(`
  (`Запрос.Выполнить()` отсекается точкой), `УдалитьФайлы`;
- обновление и фон: `ОбновлениеДанных`, `ОбработчикиОбновления`, `ВерсииПодсистем`,
  `НачальноеЗаполнение`, `ФоновыеЗадания`, `РегламентныеЗадания`.

Маркеры — основы слов: смоук показал, что удалённый `Блокировка.Заблокировать();` при маркере
`БлокировкаДанных` проходил как trivial. Правишь маркеры — прогони `ai_diff_tier` на однострочнике
с удалением блокировки и на правке комментария.

## Бюджет токенов — что на самом деле стоит денег

Замеры эталона TinyCIO (2026-09-11/12, один дифф ~150 строк, 10 файлов): **платит не промпт, а
ХОДЫ**. Ревьюер первым делом делал `cat CLAUDE.md` и файлы целиком, и весь этот контекст
переотправлялся на каждом следующем ходу. Паёк + запрет широких чтений: ходов 11 → 6,
некэшированный вход −14…−25 %. Поэтому в промптах ревьюеров maERP — прямой запрет читать целиком
большие файлы с их размером:
- документы: `docs/CHANGELOG.md` 145 КБ, `docs/TECHDEBT.md` 68 КБ, `docs/TESTING.md` 51 КБ;
- метаданные: `Form.form` до 315 КБ, `Rights.rights` до 246 КБ, `Configuration.mdo` 69 КБ;
- модули: `МенеджерОборудования*` до 490 КБ;
- `build/bsl-json.json` 14 МБ.

Вместо этого — рецепты точечного чтения (`rg -n '<name>Элемент</name>'`, `rg -n -A6 'Document.X'`).

Первый замер maERP (2026-09-13, однострочник «удалён `Блокировка.Заблокировать()`», полный круг
Codex): промпт 21,5 КБ, **3 shell-команды**, вход 104 927 токенов (из кэша 72 064, **некэшированный
32 863**), выход 1 083; находка P1 верная, 40 с. Круг `--verify` после фикса: промпт 6,4 КБ (только
дельта), OpenCode `reviewer` на Kimi K3 подтвердил закрытие за 31 с.

Мерить так: `.ai/state/<slug>/review-*.jsonl`, последнее событие `turn.completed` с `usage`
(`input_tokens` / `cached_input_tokens` / `output_tokens`), число ходов — `item.completed` с
`type=command_execution`. Меняешь промпт — сравни ДО/ПОСЛЕ на одном и том же диффе.

## Finding policy

Severity: P0 (потеря/порча данных клиента, безопасность, конфигурация не загружается или не
обновляется) · P1 (серьёзная функциональная ошибка) · P2 (функциональная или сопровождаемость) · P3
(мелочь). P0/P1 блокируют сдачу — чинить. P2 — чинить или явно отклонить с причиной в отчёте. P3
можно оставить рекомендацией. **Находку не принимать механически** — сверить с кодом. Ложная
находка помечается `rejected` с причиной, а не выбрасывается молча.

## Review policy

Агент, написавший код, никогда не единственный его ревьюер: реализация Claude → независимое ревью
Codex → тесты → интеграция Claude → финальная проверка. Если код написал OpenCode `routine-dev` (в
своём worktree), он всё равно проходит ревью Codex или Claude до слияния.

## Worktree strategy

Никогда два пишущих агента в одном рабочем дереве. Основное дерево принадлежит оркестрирующей
сессии Claude. Пишущий делегат (OpenCode `routine-dev` или Codex, которого явно попросили применить
фиксы) получает свой `git worktree add .claude/worktrees/<slug>` (уже в `.git/info/exclude`) или
`codex exec --worktree`. Read-only ревьюеры работают по диффу или плану и worktree не требуют.

## FAILURE HANDLING

Codex или OpenCode не установлен, не авторизован, упал, вышел по таймауту, несовместимый CLI —
**результат не симулировать.** Обёртка печатает `BACKEND_UNAVAILABLE` (exit 2) или явную ошибку
(exit 1); это прямо сообщается владельцу. Claude может продолжить сам, только если упавшая проверка
не обязательна для ставок этого изменения (см. «Когда что запускать»). Если *обязательное*
независимое ревью не прошло — так и написать в отчёте, а не сдавать задачу как проверенную.

## Отчёты и наблюдаемость

- `.ai/reviews/<slug>/NN-<шаг>.{json,md}` — сырые находки каждого шага, **коммитятся**: 01-explore,
  02-plan-review, 03-code-review (+03b verify), 04-database-review, 05-security-review,
  06-test-analysis.
- `.ai/reports/<slug>-final-check.md` — вывод `ai-final-check`. Не мастер-отчёт.
- `.ai/reports/<slug>.md` — **мастер-отчёт задачи, пишет Claude сам**: Task / Plan / Agents used /
  Files changed / Tests executed / Review findings / Findings fixed / Findings rejected (+why) /
  Remaining risks. Только для задач, прошедших цикл план/ревью. Тривиальному фиксу отчёт не нужен.
- `.ai/state/<slug>/` — сырые промпты и JSONL, gitignored, удалять можно в любой момент.

## Known limitations (честно, без замазывания)

- **Untracked-файлы в обычном ревью**: `git diff HEAD` новых файлов не показывает — обёртка
  перечисляет их пути, но содержимого ревьюер не видит, пока их не застейджить. Обёртка сама не
  стейджит — это побочный эффект, который ей не принадлежит. `--verify` содержимое новых файлов
  показывает.
- **OpenCode не держит схему вывода.** У `opencode run` нет аналога `--output-schema`: отчёт
  сохраняется markdown'ом. Смоук 2026-09-13: `database` на Kimi K3 вернул JSON с ключами `title`/
  `recommendation` вместо `problem`/`recommended_fix` и перепутал год инцидента. Выводы верны, но
  это первый проход, не финальное слово. «free» в `--tier free` значит «OpenCode-путь», а не
  «бесплатно»: на Go он тратит лимит подписки.
- **Лимит OpenCode Go — в долларах за окно** (5 ч / неделя / месяц). Пинг «pong» стоил $0,003–0,035,
  крупное ревью заметно больше. Исчерпан → **не ошибка, а молчаливое зависание** (проверено
  2026-09-13: 45 с без байта в stdout/stderr) → сторож первого события → запасная модель Zen → Codex.
  До сторожа каждая попытка съедала полный таймаут 600 с.
- **`bash:`-разрешения OpenCode — фильтр по ШАБЛОНУ строки, не песочница.** Read-only агенты
  получили только явные безопасные подкоманды (`git status/log/diff/show/blame/ls-files/grep`,
  `grep`, `rg`, `ls`, `cat`, `head`, `wc`, `sed -n`). Также `scripts/refcheck.py` и
  `scripts/listcheck.py` — строго без аргументов: `--update-known` переписывает файлы известных
  расхождений. Никогда `git *` и `find *`. Остаточный риск принят, не решён:
  - `cat a > b` матчит `cat *`;
  - `sed -n 'w файл'` пишет.

  Смоук 2026-09-13: на прямую просьбу выполнить `cat … > файл` агент отказался **сам**, до фильтра
  дело не дошло — то есть шаблоном этот обход не проверен и не закрыт. `edit: deny` — сдерживание, а
  не стена.
- **Инструменты субагентов Claude — на уровне инструмента**, не пути: у четырёх субагентов просто нет
  Edit/Write.
- **Baseline линта устаревает.** `build/bsl-json-baseline.json` от 2026-08-26. Замечание, осознанно
  принятое после этой даты в изменённом модуле, гейт покажет как новое. Практика проекта —
  пересоздавать baseline в начале волны. Гейт печатает дату baseline первой строкой.
- **Уровни 1–3 проверяют `build/ib`, а не `src/cf`.** Базу обновляет из EDT владелец. Пока EDT
  держит базу через агент, headless-операции с ней невозможны («база заблокирована»).
  `ai-final-check --db` в этом случае падает честно, но ничего не проверяет.
- **EDT-проверки отсюда не запускаются** — синтаксис и ссылочная целостность метаданных только у
  владельца после Refresh.
- **Сканера секретов нет** (gitleaks не установлен): поиск в `ai-final-check` — грубый grep плюс
  точное значение `SMOKE_PWD` из env. Репозиторий публичный — это важнее, чем в эталоне.
- **`.opencode/.gitignore` игнорирует сам себя** и управляется OpenCode (как в эталоне): в git
  попадают только `.opencode/agents/*.md`.

## Грабли, найденные при переносе в maERP (дописаны в промпт внедрения)

1. **`bin/` в `.gitignore`** (блок EDT/Eclipse) молча игнорировал `.ai/bin/` — обёртки не попали
   бы в коммит. Лечится `!.ai/bin/`. Проверка: `git check-ignore -v .ai/bin/ai-lib.sh` пуст.
2. **Кириллические пути и `core.quotepath`.** С умолчанием git заголовок диффа —
   `+++ "b/src/cf/src/\320\236…"`: `^+++ b/` не находит файлов (проверено: 0 вместо 1), паёк и
   `ai_changed_has` слепнут. В репо `off` стоит только в локальном `.git/config`. Весь git в обёртках
   идёт через `ai_git` с `-c core.quotepath=off`.
3. **`printf … | python3 - <<'PY'`**: heredoc с программой забирает stdin, пайп молча теряется —
   гейт линта получил бы пустой список модулей и позеленел. Данные — через env или аргументы.
4. **`source .ai/config.sh` из zsh**: `BASH_SOURCE` пуст, корень репо и `config.local.sh` не
   находятся, ключ Go не экспортируется. Подключать только из bash (`bash -c 'source …'`).
5. **Двоеточие в `description:` агента OpenCode** без кавычек — невалидный YAML. Описания в кавычках.
6. **`opencode-go/*` без `OPENCODE_API_KEY`** на opencode 1.18.30 отвечает
   `UnknownError: Unexpected server error` (rc=1), а не `Provider not found`. Выглядит как сбой
   сервера, а на деле нет ключа — смотри `ai-doctor`, строка `opencode`.
7. **Маркеры риска полными идентификаторами** пропускают удаление строки блокировки — только основы
   слов (см. «Маркеры риска»).
8. **zsh: `echo =====`** — `=слово` раскрывается как путь к команде (`=cmd`), вывод обрывается
   ошибкой. В разделителях не начинать слово с `=`.
