## Пути
1. **Проведение** (ПКО/РКО `ОбработкаПроведения` - `УстановитьПривилегированныйРежим(Истина)`; регистры взаиморасчётов - привилегированно): `ОстатокОбъектаРасчетов`, `СтрокаОплатыВРасчеты`, запись `Убытки` из `ЗаписатьКурсовуюРазницу` идут в привилегированном режиме, прав ролей не требуют. Нового расширения прав нет. Для безналичных документов привилегия не проверялась (диф ObjectModule не показал `УстановитьПривилегированныйРежим` у Поступления/Списания): запись движений при проведении и так не проверяет права на регистры, чтение остатков идёт в регистровом ManagerModule (привилегированно).
2. **Формы** (`ЗаполнитьВалютуНаСервере`, `ПолучитьСуммуОснованияДляПлатёжногоДокумента`, `ПолучитьЗадолженностьДляОплаты`): работают с правами пользователя. Новое: `ДолгВВалютеПлатежа` читает Валюта/КурсВалюты основания (Реализация/Поступление) и `ПолучитьСуммуОснования...` читает больше реквизитов основания. Все роли с правом редактировать ПКО/РКО/банк (Казначей, PDV, МенеджерПоЗакупкам, Админ, Руководитель) читают Реализацию и Поступление (PDV - R/V Поступление, достаточно). Вызов только при интерактивном изменении суммы/строк - у read-only ролей не срабатывает.
3. **Серверный вызов с клиента** `РаботаСДокументамиВызовСервера.ПолучитьСуммуОснованияДляПлатёжногоДокумента(Документ, ВалютаПлатежа)`: непривилегированный; новый параметр `ВалютаПлатежа` (структура Валюта/Курс) от клиента влияет только на пересчёт числа в ответе; произвольной ссылкой `Документ` пользователь получает лишь то, что может прочитать по своим правам (чтение идёт под его правами). Эскалации и раскрытия сверх прав нет.
4. **Получение данных, не положенных роли**: курсы валют/валюта кассы - справочные, читаются всеми ролями; суммы долгов видны тем же ролям, что и раньше (регистры взаиморасчётов). Курсовая разница в `Убытки` - новая статья ДДС, отчёт о прибыли - только роли с правом на регистр/отчёт; отдельных данных, скрываемых от ОператорПроизводства, не выводится.
5. **Предопределённые элементы**: `СтатьиДвиженияДенежныхСредств.КурсовыеРазницы` (код 0, uuid задан), `СтатьиФинансовогоРезультата.EcartsDeChange` (isFolder). Права на справочники не менялись. Обработчик обновления `ЗаполнитьДанныеОплатВВалюте` - привилегированный, идемпотентный, использует запросы без параметров из ввода, `ОбменДанными.Загрузка` при записи старых списаний сознательно (без проведения). Секретов, паролей, ключей, URL в диффе нет (поиск по password/secret/token/key/SMOKE_ - пусто).

## Находки
- **P3** Казначей и PDV не имеют прав на `Catalog.СтатьиФинансовогоРезультата` (None в Rights.rights); новая строка «Écarts de change» показывается отчётом о финансовом результате. Если отчёт читает справочник под правами пользователя (не привилегированно), у Казначея/PDV строка/порядок может не прочитаться. Предложение: проверить, что отчёт строится у ролей, которым доступен (Руководитель/Админ/МенеджерПоЗакупкам RV); не блокер, функциональное, не доступ сверх прав.
- **P3** `РаботаСДокументамиВызовСервера.ПолучитьСуммуОснования...` принимает `ВалютаПлатежа` от клиента без проверки типа/полей: некорректная структура даст исключение сервера (отказ в обслуживании только для себя), без утечки. Можно добавить защиту (`Свойство`), необязательно.
- Ограничений через скрытие в UI (видимость валюты/курса) не выдавалось за защиту: поля `Валюта` и `КурсВалюты` редактируются только как реквизиты документа; `ПроверитьВалютуПлатежа` перезаписывает `Валюта` из кассы и `СуммаРегл` на сервере в `ПередЗаписью`, то есть клиентская подмена валюты не проходит (курс при этом можно править вручную - сознательное решение плана, роль с правом на документ).

## Ответ на «может ли роль X получить/изменить то, что ей не положено»
Нет: ни одна роль не получает новых данных или действий; ни одна роль, которая проводит/открывает ПКО/РКО/банк, не теряет доступ к Кассы.Валюта, КурсыВалют, константе, реквизитам оснований. Привилегированные участки (проведение, обработчик обновления) не принимают пользовательского ввода как текст запроса/имя объекта.
