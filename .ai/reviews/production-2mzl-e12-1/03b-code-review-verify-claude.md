## Проверено по вопросам вызвавшего
- **`&НаКлиенте Перем` в области `ОписаниеПеременных` модуля формы.** Допустимо. Переменная живёт, пока открыта форма; последствия — в N1.
- **`&НаСервере`-функция возвращает `Структура` из ссылки, ссылки и строки.** Сериализуется, в порядке. Ветки `Перечитать`, «отказ» и «нет позиции» возвращают `Неопределено`, клиент это обрабатывает (`Module.bsl:172`).
- **Сценарий уровня 3 `СценарийАРМПроизводство` не сломан.**
  - «В работу»: `НовыйКонтрагент()` (`ТестыДокументов/ManagerModule.bsl:4748`) не ставит `ЗапретОтгрузок` и `КонтрольКредита`, значит `КлиентуЗапрещеноОтгружать` вернёт `Ложь`.
  - Пометка: право `InteractiveSetDeletionMark` на `ЗаказПокупателя` есть у `ОператорПроизводства`, у `Администратор` стоит `setForNewObjects`.
  - Вторая строка с версией по-прежнему пишется, потому что версия у новой строки теперь игнорируется.
  - Устаревшая правка (`НомерСтроки = 1`) по-прежнему отклоняется с `Перечитать`.
  - `Цена = 0` у пользователя без сумм в сценарии не используется.

## Новые находки

### P2. N1: черновик по умолчанию берётся только из памяти сеанса, без опоры на записанные строки таблицы
- **Где:** `Forms/Форма/Module.bsl:204-219` (`ПродукцияКлиентПриИзменении`) и `:5`.
- **Против чего:** план §3.2 (`.ai/plans/production-2mzl-e12-1.md:118`, решение 3) требует брать «последний черновик клиента из уже записанных строк таблицы». «Что нового» обещает: «Следующие строки того же клиента попадают в тот же черновик».
- **Сценарий:**
  1. Вчера оператор записал строку клиенту K, черновик X.
  2. Сегодня он открывает рабочее место. X виден в «Продукции», `ПоследниеЧерновики = Неопределено`.
  3. Он добавляет строку клиенту K: подставляется «Новый заказ», и окончание редактирования создаёт второй черновик Y.
  4. Так при каждом новом открытии формы у каждого клиента появляется ещё один черновик.
- **Как исправить:** когда в `ПоследниеЧерновики` записи нет, брать заказ первой строки клиента в таблице с `Записана И Редактируется`. Таблица отсортирована по дате заказа по убыванию, так что это самый свежий черновик. Память сеанса оставить приоритетной: этого достаточно, чтобы не вернуть P2 Codex.

### P3. N2: устаревшая запись в `ПоследниеЧерновики`
- **Где:** `Module.bsl:176` пишет запись, но её никто не удаляет. Устаревает запись в `ИзменитьСтатусНаСервере` («В работу» и «Отменить»), при `ЗаказПомечен` в `УдалитьСтрокиНаСервере` и после действий другого пользователя.
- **Сценарий:**
  1. Строка клиента K записана в X.
  2. Оператор нажимает «Статус → В работу» по X.
  3. Следующая строка K по умолчанию уходит в X. `ТекстЗапретаПравкиСтроки` отказывает («заказ проведён»), строка остаётся «Не записано».
  4. Оператор должен сам выбрать «Новый заказ».
  5. Если X пометили на удаление после проверки, но до блокировки, сработает отказ в `ЗаблокированныйЗаказ` с полным перечитыванием. Строка сохранится, но уедет в начало таблицы.
- **Как исправить:** в `ПродукцияКлиентПриИзменении` пропускать запись, если в таблице нет строки `Записана И Редактируется` с этим заказом. Это закрывает и N1 одной проверкой.

### P3. N3: смена продукции у первой из строк с повторным кодом всё ещё портит материалы (недозакрытая находка 10)
- **Где:** `ManagerModule.bsl:1105-1135` (`ПрименитьДанныеСтроки`) → `Documents/ЗаказПокупателя/ManagerModule.bsl:146-150` и `АРМПроизводство/ManagerModule.bsl:1217`.
- **Сценарий:** данные загрузки, у строк 1 и 2 одинаковый код K и есть материалы K. Оператор меняет продукцию строки 1.
  1. `УдалитьМатериалыСвоегоКода` удаление правильно пропускает.
  2. `ЗаполнитьМатериалыПоТехкартам` вызывает `ОбеспечитьКодыСтрокТоваров(ТЧТовары, [строка 1])`. Строка 1 — первая с кодом K, поэтому код остаётся K.
  3. `УдалитьМатериалыСтроки(K)` удаляет общие материалы, их место занимает состав новой продукции.
  4. Если сработала ветка `СкопироватьМатериалыПродукции`, материалы добавляются под K вперемешку со старыми.
  5. Затем `ПередЗаписью → РазвестиПовторныеКодыСтрокСМатериалами` даёт строке 2 новый код без материалов и очищает её техкарту.
- **Как исправить:** при `НоваяНоменклатура` и неединственном коде присваивать правленой строке новый код (максимальный + 1) до заполнения материалов. Отдельно завести обещанный пункт в `docs/TECHDEBT.md`: переназначение кода оставшейся строке при удалении.
