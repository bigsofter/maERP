## Находки

[P2] ManagerModule.bsl:162-178, 416-425, 537-587 (ОплатыЗаказов/ЗапросОплат) — индикатор оплаты сравнивает
денежный поток ДвиженияПоКассе с валовой СуммаРегл проведённых поступлений, а не с закрытием долга. Сценарии:
(а) возврат поставщику на 1 ед. + возврат денег за неё ПоступлениемБезналичных → Оплачено уменьшается, СуммаПоступлений
нет → «◐» у полностью рассчитанного заказа; (б) взаимозачёт КорректировкаДолга по поступлению ДвиженияПоКассе не пишет →
«○»/«◐» у закрытого долга; (в) заказ в EUR, поступление по курсу 1,10, оплата всей суммы в EUR по 1,08 → Оплачено в
основной валюте < СуммаРегл → «◐» навсегда (курсовая разница). План («доля оплаченного долга поступлений») — про долг.
Исправление: база = СуммаРегл поступлений минус СуммаРегл проведённых возвратов по ним; критерий «оплачено полностью» —
по остатку ВзаиморасчётыСПоставщиками по объектам (поступления + доля накладной) ≥ 0, либо сравнение в валюте документа;
как минимум — записать ограничение в TECHDEBT и пояснить в легенде. Добавить шаги в сценарий (возврат + возврат денег).

[P3] ManagerModule.bsl:119-126 — на непоследней странице выгрузка заново сортируется «Дата Убыв» до пропуска
НачальныйИндекс; сортировка ТЗ не гарантирует порядок равных дат, а запрос упорядочен ещё и по Ссылке. Заказы с
одинаковой датой-временем на границе страниц (групповое создание, загрузка из drissotex) могут задвоиться на одной
странице и пропасть на другой. Исправление: как в АРМПроизводство.СтраницаЗаказов — сначала пропуск по индексу, а
разворот порядка только для последней страницы (обход с конца), без Сортировать.

[P3] Forms/Форма/Module.bsl:195-199, 60-64, 9-10 — ЗагрузитьСтраницу делает два серверных вызова (страница, затем
ДанныеЗаказа), а установка ТекущаяСтрока на сервере вызывает ПриАктивизацииСтроки → третий вызов с повторным чтением
нижних закладок (6 запросов) через 0,2 с; то же при открытии формы. Исправление: читать страницу и данные текущего заказа
одним серверным вызовом и в ОбновитьТекущийЗаказ не перечитывать, если ТекущийЗаказ не изменился и данные свежие.

[P3] ManagerModule.bsl:691-703, 765-767 — закладка «Оплаты» показывает платёж на общую накладную полной суммой (индикатор
берёт долю), а «Документы» не показывают непроведённую налоговую накладную и накладные по непроведённым поступлениям
(ВТНакладные фильтрует Проведен). Пользователь видит оплат больше суммы заказа и «неполную» цепочку. Исправление: колонка
«в т.ч. по заказу» (доля) или пометка «общая накладная»; для «Документов» брать накладные без фильтра проведения.

[P3] ТестыДокументов (Область РабочееМестоЗакупок) — нет шага «общая накладная на поступления двух заказов с
неравномерной оплатой» (план, «Тесты»): логика ВсегоПокрыто/доли между заказами не проверена; тест с одним поступлением
даёт долю 1. Добавить в этой или следующей сборке.
