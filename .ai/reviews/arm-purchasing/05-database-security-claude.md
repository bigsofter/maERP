  не пишется — таблицы клиента не меняются. Регистрация Enum и DataProcessor в Configuration.mdo есть, версия 2.0.16.28.
- Права (Rights.rights поимённо, без RLS): Read есть у всех 11 читаемых таблиц — Документ.ЗаказПоставщику,
  ПоступлениеТоваровУслуг, ВозвратПоставщику, НалоговаяНакладнаяПокупка, СписаниеБезналичныхДС, РКО,
  ПоступлениеБезналичныхДС, ПКО; РН ЗаказыПоставщикам, ДвиженияПоКассе, ВзаиморасчётыСПоставщиками. Для
  представлений ссылок: Контрагенты, Номенклатура, ХарактеристикиНоменклатуры, Валюты, Пользователи,
  ЗаказПокупателя (Основание), ДоговорыСКонтрагентами, Организации — Read есть. Запросы без РАЗРЕШЕННЫЕ не упадут.
- mdo-006: Subsystem.Закупки View=true в роли есть. DataProcessor.АРМЗакупки — Use+View только МенеджерПоЗакупкам;
  Руководитель/Администратор — setForNewObjects=true, тот же шаблон, что у АРМПроизводство.
- Безопасность: нет привилегированного режима, Выполнить/Вычислить, секретов. Текст условий собирается только из
  литералов, значения — параметрами с проверкой типа (ManagerModule.bsl:272-305, 63-67); размер/номер страницы
  нормализуются (48-49). ДанныеЗаказа(Заказ) принимает любую ссылку с клиента, но читает её под правами роли —
  эскалации нет. «Может ли МенеджерПоЗакупкам получить чужие данные этим путём?» — нет: всё показываемое (суммы
  заказов, платежи, сальдо по договору) он уже читает списками документов и регистром взаиморасчётов.
- Валюты: ДвиженияПоКассе.Сумма — в основной валюте (ДвиженияПоКассе/ManagerModule.bsl:3-5), сравнение с
  Поступления.СуммаРегл корректно; знак возврата денег (ТипДвижения=Поступление → минус, :542-544) верен.
  Доля платежа на НН считается от полного покрытия накладной (ВсегоПокрыто по всем строкам НН), двойного счёта нет.

## Находки
- [P2] DataProcessors/АРМЗакупки/ManagerModule.bsl:548-556 — ДвиженияПоКассе.Обороты(,,Регистратор, ДокументПродажи В …)
  без периода; измерение ДокументПродажи не индексировано (AccumulationRegisters/ДвиженияПоКассе/ДвиженияПоКассе.mdo:90,
  нет `<indexing>`), периодичность Регистратор итоги не использует. Сценарий: база с годами кассовых смен (каждая
  продажа POS пишет ДвиженияПоКассе) — каждое листание страницы (СтраницаЗаказов→ОплатыЗаказов, :128) и каждый клик
  по заказу (ДанныеЗаказа, :201) = полный скан таблицы движений. Исправление: `indexing Index` на ДокументПродажи
  (реструктуризация только индекса, данные не трогает) или запись в TECHDEBT с порогом объёма.
- [P2] ManagerModule.bsl:326-358, 617-620 — РН ЗаказыПоставщикам читается таблицей движений; измерения без индексов
  (ЗаказыПоставщикам.mdo:123), ТекстЗапросаТоваров фильтрует `ЗаказПоставщику = &Заказ` полным сканом; ВТЗаказы/ВТСтатусы
  считаются по ВСЕМ непредварительным заказам при каждом обновлении страницы. При тысячах заказов терпимо, при десятках
  тысяч — секунды на клик. Исправление: индекс на ЗаказПоставщику; ограничение ВТЗаказы периодом по умолчанию; TECHDEBT.
- [P2] ManagerModule.bsl:416-425, 156-177, 900-905 — СуммаПоступлений = СуммаРегл поступлений без вычета
  ВозвратПоставщику. Сценарий: поступление 1000, возврат 200, оплачено 800 — расчёты закрыты, а кружок оплаты
  навсегда «◐ частично». Исправление: вычесть СуммаРегл проведённых возвратов по поступлениям (Возврат.Основание =
  Поступление) или явно описать в плане/«Что нового», что индикатор считает от суммы поступлений брутто.
- [P3] ManagerModule.bsl:372-376 — частичное поступление + остаток перенесён в другой заказ (Остаток<=0, 0<Пришло<Заказано)
  даёт статус «Поступил», а кружок поставки «◐» (:883). Статус и индикатор расходятся; при желании — «Поступил»
  только при Пришло >= Заказано, иначе «Перенесен».
- [P3] ManagerModule.bsl:424; 437, 446 — отборы `Поступления.Основание В (&Заказы)` и `ТЧ*.ПоступлениеТовара = …`
  по неиндексированным реквизитам (ПоступлениеТоваровУслуг.mdo:359, НалоговаяНакладнаяПокупка.mdo:1392/1826) — скан
  таблиц документа/ТЧ на каждую страницу. Индексировать при росте объёмов.
- [P3] ManagerModule.bsl:48 — РазмерСтраницы с клиента ограничен только снизу: вызов с 10^9 выгрузит все заказы за
  один серверный вызов (нагрузка, не утечка — данные роли доступны). Добавить Мин(…, 200).
- [P3] Оплаты прямо на заказ (аванс с основанием ЗаказПоставщику) не учитываются — ДокументПродажи таких типов не
  содержит (ДвиженияПоКассе.mdo:90-115); по плану это ожидаемо, но легенда «оплата» может вводить в заблуждение до
  поступления. Упомянуть в «Что нового»/подсказке.
