## Находки

### P1-1. `СравнениеЗначений` упорядочивает ссылки по идентификатору, а не по представлению — сортировка по колонкам-ссылкам в случайном порядке

- Файл: `src/cf/src/CommonModules/СортировкаТаблицФормы/Module.bsl:120` (`УпорядочитьСтроки`,
  `Ключи.Сортировать(..., Новый СравнениеЗначений)`), комментарий там же и `:349` («сравнивается по представлению»).
- Справка 8.5.1 (`ValueTable/methods/Sort`, `CompareValues`): «если объект сравнения **не задан**, элементы
  остальных типов сравниваются по строковому представлению; если объект сравнения **задан**, то объекты
  сравниваются по идентификатору». То есть код делает ровно обратное заявленному в комментарии и в плане
  (п. 4 варианта A, P1-4 «прочая ссылка — по представлению»).
- Сценарий: в «Заказах» закупок команда «Сортировать по возрастанию» на колонке «Поставщик» (так же
  «Номенклатура», «Склад», «Материал» в дереве, «Контрагент», «Ответственный», «Заказ клиента», документ без права
  чтения) → строки выстраиваются по внутреннему идентификатору ссылки, т. е. в порядке, не связанном с
  наименованием; в шапке при этом стрелка ▲. Основная жалоба клиента (сортировка кликом/командой) для
  ссылочных колонок не исправлена. Даты, числа, строки и документы с датой (ЗаменитьДокументыДатами) не затронуты.
- Тест `СортировкаТаблицАРМ` («по поставщику по наименованию», ожидание `10,40,20,30`) на этом должен падать
  в 5 случаях из 6 — если он прошёл, это совпадение идентификаторов, а не подтверждение.
- Исправление: в `УпорядочитьСтроки` для ссылок (кроме уже заменённых датой документов) класть в `Ключ`
  `Строка(Значение)` (представление считается один раз на строку), либо сортировать без объекта сравнения
  (простые типы — по значению, типы — по коду типа, прочее — по представлению; но представления тогда
  вычисляются при каждом сравнении). Поправить комментарии и раздел «Риски» плана.

### P1-2. `ДинамическийСписок.ПоляКлюча` — `ФиксированныйМассив`, код присваивает строку

- Файл: `src/cf/src/DataProcessors/АРМЗакупки/Forms/Форма/Module.bsl:1287`
  (`Список.ПоляКлюча = Ключи[КлючИЗначение.Ключ];`, значения — `"Документ"`, `"Склад"`, `"Предложение"`).
- Справка (`DynamicList/properties/KeyFields`): «Тип: ФиксированныйМассив. Содержит фиксированный массив строк —
  путей ключевых полей. Доступность: Сервер».
- Сценарий: `ПриСозданииНаСервере` → `НастроитьДинамическиеСписки` → присваивание строки свойству типа
  `ФиксированныйМассив` → исключение «Неверный тип значения» → рабочее место закупок не открывается ни у кого
  (и в режиме приёмки). Если платформа строку молча приводит — находка снимается, но опираться на
  недокументированное приведение не стоит.
- Тестом не ловится: сценарий `СортировкаТаблицАРМ` после переписывания форму больше не создаёт
  (`ПолучитьФорму` убран), `СпискиАРМЗакупок` выполняет только тексты запросов. Ловит только смок «открыть все
  формы» — прогнать обязательно.
- Исправление: `Список.ПоляКлюча = Новый ФиксированныйМассив(СтрРазделить(Ключи[КлючИЗначение.Ключ], ","));`
  и проверить в смоке открытие формы под администратором, менеджером по закупкам и в режиме приёмки.

### P2-1. Форменная часть сортировки и динамических списков без автотеста

- Файл: `src/cf/src/DataProcessors/ТестыДокументов/ManagerModule.bsl`, `СценарийСортировкаТаблицАРМ`.
- После переписывания сценарий проверяет только `УпорядочитьСтроки` на `ТаблицаЗначений`/`ДеревоЗначений`.
  Не исполняются: `УстановитьПорядок`/`ПрименитьПорядок` на `ДанныеФормыКоллекция` (`Сдвинуть`/`Индекс` у данных
  формы), ветка `ДанныеФормыДерево` (`РеквизитФормыВЗначение` → `ЗначениеВРеквизитФормы` → возврат курсора),
  `КолонкаПоля`/`КолонкаВидна`/сброс по скрытой колонке, стрелки `ПоказатьПорядокВШапке`, хранение в
  `ПорядокТаблиц`, `НастроитьДинамическиеСписки`/`УстановитьПараметрыСписка` (P1-2). План (раздел «Проверки»)
  требовал сценарий «на форме рабочего места закупок».
- Сценарий отказа: ошибка в любой из перечисленных процедур (как P1-2) уходит владельцу, автотесты зелёные.
- Исправление: вернуть в сценарий форму (`ПолучитьФорму("Обработка.АРМЗакупки.Форма.Форма")` на сервере — ≤ 3
  параметров) с проверкой `УстановитьПорядок` + `ПрименитьПорядок` после перезаполнения + стрелки, и дерево
  `Материалы` формы производства; если создание формы на сервере мешало — записать причину в отчёт.

### P3-1. Лишние запросы на каждую активизацию строки «Потребности»

- `src/cf/src/DataProcessors/АРМЗакупки/Forms/Форма/Module.bsl:2521` → `ManagerModule.bsl:1181`
  (`ДанныеСтрокиПотребности`): функция по-прежнему выполняет запросы заказов поставщику и остатков, а форма
  берёт из результата только `Источники`; те же данные затем читают динамические списки. Каждое перемещение
  курсора по «Потребности» — два лишних запроса к регистрам. Вынести заказы/остатки из функции в отдельные (для
  тестов) или передавать признак «только источники».

### P3-2. Право по таблицам запросов списков товара — только режим приёмки

- `ManagerModule.bsl:3761` (`ТекстСпискаОстатковТовара`), `ТекстСпискаЗаказовТовара`: заглушка ставится только
  в режиме приёмки; P1-2 ревью плана предписывал заглушку и без чтения `РегистрНакопления.ЗаказыПоставщикам`,
  `МатериалыНаСтанках`, `Справочник.ПроизводственноеОборудование`. У текущих ролей (МенеджерПоЗакупкам) права есть,
  регрессии нет; но теперь запрос выполняется при открытии формы, а не при выборе строки — у пользователя со
  сборной ролью (изменение заказов поставщику без чтения станков) рабочее место откроется с ошибкой списка.
  Либо добавить `ПравоДоступа` по таблицам, либо зафиксировать отступление от плана.

### P3-4. Нестабильные ожидания в тесте

- `ПроверитьСортировкуПоДатеДокумента`: эталон — `УПОРЯДОЧИТЬ ПО Д.Дата, Д.Ссылка`, код при равной дате
  упорядочивает по `Номер` → при двух поступлениях с одинаковой датой ожидание может разойтись. Брать два
  документа с разными датами (`ГДЕ` по разнице дат) или сравнивать с `Дата, Номер`.
- Порядок «по наименованию» из СУБД (`УПОРЯДОЧИТЬ ПО К.Наименование`, сопоставление СУБД) и сравнение строк
  платформы могут расходиться на регистре/кавычках в наименованиях контрагентов — после исправления P1-1
  лучше задавать ожидание через `Строка(Ссылка)` и сортировку ТЗ.

## Проверено без замечаний

- `УпорядочитьСтроки`: устойчивость (`Позиция` последним ключом, всегда по возрастанию), перестановка на месте
  (`Индекс` ≥ целевого, `Сдвинуть` с отрицательным смещением) — идентификаторы строк и `ТекущаяСтрока`
  сохраняются; незаписанные первыми; смешанные типы в `Ключ` — по коду типа; пустая ссылка документа → пустая дата.
  O(n²) по `Индекс`/`Сдвинуть` — нативные операции, для сотен–тысяч строк приемлемо.
- Точки `ПрименитьПорядок`: производство — `ЗагрузитьПродукцию` (после вставки незаписанных, до курсора),
  `ЗаписатьСтрокуНаСервере` (после установки курсора — строки на месте), `ЗагрузитьСтрокиДокументов`,
  `ДокументыЗаказа`, `Материалы` (дерево значений до загрузки), `ДокументыВерх` (после настройки колонок);
  закупки — `Заказы`, `Товары/Поступления/Оплаты/Документы`, `Потребность`, `ИсточникиТовара`,
  `ТоварыПоступлений`. Пропусков среди таблиц с командами меню не нашёл; клиентская вставка новой строки в
  начало и обращения `Заказы[0]`/`Потребность[0]` после сортировки — ожидаемо по плану.
- Колонки отбора незаписанных: `Записана` у таблиц производства, `НомерСтроки` у `Товары`, `Поступления`,
  `ТоварыПоступлений`; у прочих `ЕстьКолонки` тихо отключает отбор. Колонки дерева «Материалы» в реквизите и в
  `НовоеДеревоМатериалов` совпадают — `СтрокаКоллекции[КолонкаКлюча]` не упадёт.
- Тексты динсписков против HEAD: поступления — те же части, отборы параметрами `&Любой…`, `ЗаказНомер/ЗаказДата`
  заменены колонкой-ссылкой; заказы товара — ВТОсталось → вложенный запрос, `ПЕРВЫЕ 100` снят по плану;
  остатки — ВТЗакреплено → виртуальная таблица в объединении, `&ЕстьСтрока` в обеих частях; предложения —
  ВТДефициты подставлены в два места, группировка по `Предложения.Ссылка` (ключ уникален). Ключи `Документ`,
  `Склад`, `Предложение` уникальны и не `Неопределено` (требование `ЗначениеПоля`). Заглушки — те же поля,
  `ГДЕ ЛОЖЬ`. `ПредложенияДоступны` = тендеры с правом чтения и не приёмка.
- Форма: `ВидКлючаДинамическогоСписка.ЗначениеПоля` существует с 8.3.14; `ДоступныеПараметры.НайтиПараметр`
  у `ЗначенияПараметровДанныхКомпоновкиДанных` есть; `ТаблицаФормы.Обновить()` доступна на сервере;
  `УстановитьПараметрыСписка` (`&НаСервереБезКонтекста`) вызывается с сервера — без сериализации. Параметры
  задаются в `ПриСозданииНаСервере` до ранних выходов (их нет), ранний выход строки и режим приёмки — пустые
  параметры. `ПриЗагрузкеДанныхИзНастроекНаСервере` — параметры поступлений по восстановленным отборам.
  Курсор поступлений — ссылкой. Form.form: `DynamicList` без `mainTable`, `customQuery`, автосохранения нет,
  `notDefaultUseAlwaysAttributes` для `Документ`/`ЗаказПоставщику`/`Склад`/`Предложение`, у колонок по 4
  заголовка, `DynamicListTableExtInfo`, дополнения поиска, кнопок в таблицах динсписков нет; `ListSettings.dcss`
  с `userSettingID` и порядком по умолчанию. Команды `СортироватьПо…` — заголовки и подсказки на 4 языках,
  обработчики объявлены. `ПорядокТаблиц` без сохранения в настройках.
- Компиляция: директивы явные; локальные имена не перекрывают глобальные (`Документы2`/`Поступления` в тесте,
  `Документы.ТипВсеСсылки()` — в общем модуле, где реквизита «Документы» нет); цепочек `Новый X().Метод` нет.
- Версия 2.0.17.32, секция «Что нового» на ru/fr/en/es есть; `CommonModule` зарегистрирован в Configuration.mdo.

## Вердикт

**reject** — две P1: сортировка по колонкам-ссылкам идёт по идентификатору (`СравнениеЗначений`), и
присваивание строки `ПоляКлюча` (по справке — `ФиксированныйМассив`) с риском, что рабочее место закупок не
откроется. После исправления — смок «открыть все формы» (закупки: администратор, менеджер по закупкам, приёмка),
возврат форменной части в сценарий `СортировкаТаблицАРМ` (P2-1), затем `ai-review --verify`. В EDT нужен Refresh
и проверка проекта.
