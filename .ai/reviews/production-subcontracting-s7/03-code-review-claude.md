и в заказе на производство. Файлы не правились.

## Вердикт: approve_with_changes

P0/P1 нет. Находки только P3, плюс риски, которые можно снять только ручной приёмкой на клиенте.

## Что проверено по коду

1. **Рефакторинг (bsl-016).** `ЗакупкиМатериалПриИзменении` → `ПослеСменыМатериала`: сравнил с `git show HEAD`.
   При ручном вводе порядок тот же: сброс характеристики (передаётся пустая), упаковки и `ЦенаИзменена`,
   поставщик и `ПодставитьДокументСтроки` не у переработки, количество по той же колонке (вынесена
   в `КолонкаКоличестваМатериала`, отображение Поступления→КПоступлению, Переработки→Потребность, иначе Дефицит
   не изменилось), `ПодобратьСтрокуОснования` у поступления. Ранний выход при `ТекущиеДанные = Неопределено`
   сохранён. `ПродукцияНоменклатураПриИзменении` → `ПослеСменыНоменклатурыПродукции`: те же три присваивания.
   Заказ: `ТЧТоварыНоменклатураПриИзменении` (УстановитьПараметрыНоменклатуры + последние цены) и
   `ТЧМатериалыНоменклатураПриИзменении` (тело `ПересчитатьТекущийМатериал` встроено с переданной строкой вместо
   `ТекущиеДанные`) — эквивалентны. Ничего не потеряно.
2. **Клиент/сервер.** Директивы у всех новых методов форм явные. `НастроитьЭлементы` (АРМ) и `НастроитьМатериалы`
   (заказ) — `&НаСервере`, там обращаются к `Справочники.Номенклатура`. На клиенте один серверный вызов на нажатие
   (`ДанныеПодбораНоменклатуры`, `&НаСервереБезКонтекста`); возвращаемые данные сериализуемы (ФиксированныйМассив
   ссылок перечисления, СписокЗначений со Структурами). `РаботаСДокументамиКлиент` — клиентский неглобальный модуль,
   `ПослеВыбораПунктаПодбораНоменклатуры` экспортирована, так что цель ОписаниеОповещения допустима.
   `ОткрытьФорму(..., Элемент)` с владельцем-полем: выбор кладёт платформа и вызывает ПриИзменении колонки,
   поэтому в пути «из справочника» пересчёт идёт штатным обработчиком. Путь «пункт списка» сам вызывает `ПослеСмены*`.
   Имена элементов `ЗаказыПоставщикуМатериал`, `ПоступленияМатериал`, `ПереработкиМатериал` существуют; имена
   таблиц совпадают с путями данных (`ЭтотОбъект[ИмяТаблицы]` корректен). Своих StartChoice у этих колонок
   в Form.form не было, так что УстановитьДействие ничего не затирает.
3. **Заказ.** `ПараметрыВыбора` поля пересчитываются в `НастроитьМатериалы`, а её вызывают ПриСоздании,
   ПослеЗаписи и `ВидОперацииПриИзмененииНаСервере`: смена вида операции включает и снимает отбор без переоткрытия
   формы. Своих choiceParameters у поля в Form.form нет, поэтому пустой массив у продажи ничего не теряет.
   Автоподбор: `АвтоподборНоменклатуры` → `ПолучитьДанныеВыбора` → `ОбработкаПолученияДанныхВыбора` учитывает
   `Отбор.ТипНоменклатуры` (`&ЕстьТипыНоменклатуры`) и `Отбор.ПометкаУдаления = Ложь`. У АРМ обработчика
   автоподбора нет: работает штатный поиск платформы с параметрами выбора поля. `ТЧТоварыНоменклатураОбработкаВыбора`
   ссылку из формы выбора пропускает (действует только на Структуру). Смена продукции пунктом списка очищает
   материалы по тому же механизму `НоменклатураДоРедактирования` / `ПриОкончанииРедактирования`, что и при ручном вводе.
4. **Запрос `ПоследниеСозданные`.** Подстановка ПЕРВЫЕ через `СтрЗаменить` безопасна (строка встречается один раз,
   число через `Формат(..., "ЧГ=0")`, минимум 1). `Новый Массив(Типы)` принимает и Массив, и ФиксированныйМассив.
   Группы, помеченные на удаление и позиции без даты исключены. Тест `ПроверитьПодборНоменклатурыАРМ` детерминирован:
   даты в будущем (+1..+5 ч) обгоняют номенклатуру базы, дата ставится второй записью после
   `ПередЗаписью` (там `ДатаСоздания` заполняется только у нового элемента), сценарий идёт внутри транзакции
   `ВыполнитьСценарий`, которая всегда откатывается.
5. **Тексты.** НСтр везде на ru/fr/en/es. Строк длиннее 140 символов нет (проверено по символам). «Что нового»
   2.0.15.49 есть на четырёх языках, версия в Configuration.mdo поднята, описание совпадает с кодом (включая
   побочный эффект: форма выбора становится плоской при любом отборе по типу).

## Находки

### P3-1. Форма выбора, открытая кодом, не встаёт на текущее значение
- file: `src/cf/src/CommonModules/РаботаСДокументамиКлиент/Module.bsl` (`ОткрытьВыборНоменклатуры`, ~стр. 227–237)
- scenario: в строке АРМ «Заказы поставщику» уже стоит материал М, пользователь жмёт кнопку выбора → «Выбрать из
  справочника». Штатная кнопка раньше открывала форму на позиции М, теперь форма открывается в начале списка.
  Замена строки материала требует поиска заново. То же в продукции и в заказе.
- fix: передать в параметрах `ТекущаяСтрока` — текущее значение поля (из `Контекст`/`Элемент`, значение строки
  данных); можно добавить параметр в `ПоказатьПодборНоменклатуры`.

### P3-2. У экспортной процедуры общего модуля нет описания назначения
- file: `src/cf/src/CommonModules/РаботаСДокументамиКлиент/Module.bsl`, ~стр. 203–207 (`ПослеВыбораПунктаПодбораНоменклатуры`)
- scenario: CLAUDE.md требует документировать у экспортных методов общих модулей назначение, параметры и
  возвращаемое значение. Здесь есть только «Параметры». Процедура экспортирована лишь как цель ОписаниеОповещения,
  и из комментария этого не понять.
- fix: одна строка назначения: «Обработчик выбора пункта списка ПоказатьПодборНоменклатуры; экспорт — для
  ОписаниеОповещения».

### P3-3. Представления последних созданных строятся из ссылки
- file: `src/cf/src/Catalogs/Номенклатура/ManagerModule.bsl`, ~стр. 115–121 (`ПоследниеСозданные`)
- scenario: `СтрШаблон("%1 - %2", Выборка.Номенклатура, ...)` на каждой строке получает представление ссылки
  отдельным чтением. Запрос к тому же сортирует по неиндексированной (вероятно) `ДатаСоздания`, и всё это на каждое
  нажатие кнопки. На справочнике в десятки тысяч позиций список появляется заметно медленнее.
- fix: выбрать в запросе `Номенклатура.Наименование`/`ПРЕДСТАВЛЕНИЕ(...)` и строить представление из него; индекс
  по `ДатаСоздания` — на усмотрение (запись в TECHDEBT).

### P3-4. Реестр тестов и техдолг, обещанные планом, не обновлены
