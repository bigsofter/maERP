## Находки

### P2-1. «Запросить предложения» пропускает поставщика целиком, если в его предложении есть хотя бы один из материалов
`АРМЗакупки/ManagerModule.bsl:748` (`ЗапроситьПредложения`) + `:2173` (`ЕстьПредложениеПоставщика`: `Номенклатура В (&Товары)`).
**Сценарий:** по заказу клиента у поставщика A уже есть предложение с M1. Закупщик отмечает M1 и новый дефицитный M2
и запрашивает предложения у A → ответ «предложение по этому заказу с этими материалами уже есть — новое не создано»;
M2 у A не запрошен вовсе, хотя в сообщении сказано «с этими материалами». Обойти можно только пометкой старого
предложения или ручным вводом. План (P3) требовал дубль «по наличию предложения с **этим** материалом».
**Исправление:** запросом получить материалы, уже имеющиеся в непомеченных предложениях поставщика по заказу; создать
предложение только с остальными строками, пропускать поставщика, лишь когда покрыты все; в сообщении перечислить
пропущенные материалы. Добавить шаг в тест.

### P2-2. После «Заказать у победителя» нет сообщения, что осталось с дефицитом (P2-5 плана)
`АРМЗакупки/ManagerModule.bsl:834-858`, `:2335`. `Пояснение` перечисляет только отброшенные строки **предложения**
(без дефицита, без цены, с черновиком). Материалы заказа клиента с дефицитом, которых в предложении нет, и остаток,
когда количество в предложении меньше дефицита, не упоминаются.
**Сценарий:** дефицит заказа — M1, M2, M3; победитель предлагал M1 и M2 (M2 — 5 из 10). Пользователь видит «Создан
заказ …» и считает тендер закрытым; M3 и 5 шт. M2 остаются незаказанными без подсказки.
**Исправление:** после успешной записи — `ИсточникиПотребности` по заказу клиента и текст «осталось с дефицитом: …»
(материал и количество) в `Итог.Текст`.

### P2-3. Тест `ПроверитьТендерПотребности` не покрывает обязательные по плану случаи
`ТестыДокументов/ManagerModule.bsl:9790-9856`. Нет: строки с упаковкой (P2-6, именно там ошибка P1-3 — коробки против
штук); двух строк одного материала (P1-1 — перезаказ); проверки курса заказа (`КурсВалюты` = 11 на дату заказа —
главный риск раздела «Риски»; сейчас проверяется только `Валюта`); черновика заказа по товару (P2-1); отказа при
другой организации; колонки «Тендер» и покрытия (план «Тесты»). Отказы («без флажка», «повтор», «без опции»)
проверяют только `Не Успех`, не текст — пройдут и при отказе по другой причине. Опция `ТендерыПоставщиков` в конце
безусловно выключается, исходное значение не восстанавливается.
**Сценарий:** регресс в свёртке или пересчёте упаковки (например, вернули `КоличествоУпаковок` строки предложения)
даст в заказ 2 шт. по цене коробки, а тест останется зелёным — количество в нём совпадает с дефицитом, упаковка = единица.
**Исправление:** добавить в предложение строку M2 в упаковке с коэффициентом ≠ 1 и вторую строку того же M2;
проверить `КурсВалюты`, количество = дефицит (не сумма строк) и цену за единицу; шаг с черновиком; проверять тексты
отказов; запомнить и вернуть значение опции.

### P3-1. Нет записи в TECHDEBT (пункт плана P3)
Форма предложения («Заказ поставщику» на основании, `ЗаказПоставщику.ЗаполнитьПоПредложениюПоставщика`) по-прежнему
заказывает все строки без перепроверки дефицита и раскладки — по плану нужна запись в `docs/TECHDEBT.md` (и очередь
в `docs/ROADMAP.md`). Файлы не тронуты.

### P3-2. `ВыбратьПобедителя` по помеченному предложению молча снимает текущего победителя
`ПредложениеПоставщика/ManagerModule.bsl:93-115`, `АРМЗакупки:808`. `ПредложенияЗаказа` исключает помеченные, поэтому
для помеченного (например, пометили после загрузки закладки) цикл только сбрасывает флажок у всех остальных, а АРМ
отвечает «Успех». **Исправление:** под блокировкой убедиться, что `Предложение` есть в `ТЗПредложения`, иначе
`ВызватьИсключение` с понятным текстом.

### P3-3. Флажок победителя в «Заказать у победителя» читается без блокировки
`АРМЗакупки:840-841`. Между чтением и записью заказа другой пользователь может перевыбрать победителя — заказ уйдёт
снятому победителю. Окно узкое, дубля по дефициту не будет (перепроверка под блокировкой). При желании — разделяемая
блокировка `Документ.ПредложениеПоставщика` по ссылке в транзакции пакета и перечитывание флажка в ней (это не вызов
`ВыбратьПобедителя` в транзакции, запрет P2-2 не нарушается).

### P3-4. Ставка НДС строк заказа — из номенклатуры, а не из строки предложения
`СтрокиПредложенияКЗаказу` не передаёт `СтавкаНДС`, `ПрименитьДанныеСтрокиЗакупки` ставит ставку номенклатуры. Если
поставщик в предложении указал другую ставку, итог заказа «с НДС» разойдётся с предложением. Решить: переносить
ставку строки (после свёртки — при единой ставке) или зафиксировать решение.

### P3-5. Колонка «Тендер»: видна во всех группировках, не обновляется после «Победитель», считается по всем строкам
`Module.bsl:1136` — видимость только по опции, в группировках «по товару/поставщику» колонка пустая (план: «только в
группировке по заказу клиента»). `ВыбратьПобедителяНаСервере` (`Module.bsl:1240`) перезагружает только нижнюю закладку —
в верхней остаётся «запрошено N». `ЗаполнитьТендерСтрок` (`АРМЗакупки:2493`) вызывается до отбора и пагинации — по
всем строкам, а не по странице, как в плане. Плюс поиск по (Заказ, Номенклатура) без характеристики.

### P3-6. Цена на закладке «Предложения» — в валюте предложения без указания валюты
`ТекстЗапросаПредложенийТовара`: `Цена` — в валюте предложения, рядом `СуммаРегл` — в основной; у валютного
предложения пользователь сравнивает несопоставимые числа. Добавить колонку валюты или цену в основной валюте.

### P3-7. Запрос предложений не проверяет строки
`ЗапроситьПредложенияНаСервере` передаёт `КЗаказу` (`Module.bsl:1226`), сервер не проверяет `Количество > 0` и заполненность
номенклатуры — при выключенном «Только с дефицитом» в предложение попадают строки с количеством 0. Цена прайса ищется
только по номенклатуре (`АРМЗакупки:2229`), без характеристики. Повторный двойной запуск (без блокировки) даст два
черновика — терпимо для черновиков.

### P3-8. Сообщение с пустым поставщиком
`ЗапроситьПредложенияНаСервере`: общий отказ (`Итог.Поставщик = Неопределено`) выводится как «: текст». Без поставщика —
выводить только текст.
