## P2

**P2-1. Путь динамического списка (СКД) с реальным заказом не проверен автоматически.**
- Где: `СценарийСпискиДокументовЗаказаАРМ` (`ТестыДокументов/ManagerModule.bsl:21716`) выполняет тексты обычным
  `Запрос`. Динамический список выполняет тот же текст через компоновку: добавляет порядок по колонке щелчка,
  поля представлений (`getInvisibleFieldPresentations`), отбор строки поиска и порядок по ключу. Смок открывает форму с
  неактивными закладками «Оплаты» и «Документы», а у производства — с пустым заказом.
- Без проверки остаются оба риска из раздела «Риски» плана. Первый: подзапрос в параметре `ДвиженияПоКассе.Обороты`
  (`АРМЗакупки/ManagerModule.bsl:4904`, `4937`), сгруппированный верхний запрос «Оплат» и сортировка по агрегатам
  `Дата`/`Сумма`. Второй: формат `ЧФ='+Ч'` условным оформлением (`АРМПроизводство/Forms/Форма/Module.bsl:2125`).
  Если СКД откажет, закладка покажет ошибку вместо строк, а ни один сценарий этого не поймает.
- Что сделать (любой из вариантов):
  1. В отчёте о сдаче явно назвать ручную проверку на клиенте. Открыть заказ с оплатами и с поступлением из
     переработки. Щёлкнуть по каждому заголовку «Оплат», «Документов» и «Документов» заказа, включая «Дата»,
     «Сумма», «Через» и «Продукция». Набрать текст в строке поиска. Проверить «+» и цвет.
  2. Или добавить в сценарий прогон через компоновку: `СхемаКомпоновкиДанных` с `НаборДанныхЗапрос`
     (`АвтоЗаполнениеДоступныхПолей = Истина`), параметры из `ПараметрыСписка…`, порядок по каждому полю колонки
     по очереди, `КомпоновщикМакетаКомпоновкиДанных` → `ПроцессорКомпоновкиДанных` → `ТаблицаЗначений`. В модуле
     тестов такой шаблон уже есть (`ТестыДокументов/ManagerModule.bsl:9314`).

## P3

- **P3-1. Задвоение движения из P2-2 ревью плана не закреплено тестом.** Устройство верное: одна часть движения на
  пару, условия частей одного типа объединены через `ИЛИ` (`ТекстЧастиДвиженияДокументов`,
  `АРМПроизводство/ManagerModule.bsl:3809`). Но регресс «+2N» ничто не ловит. Ключевая уникальность в новом
  сценарии проверяет только число строк, а не количество. Ревью плана просило сценарий: поступление из переработки,
  у которого основание — передача заказа, а в `ТЧГотоваяПродукция.Заказ` указан этот же заказ. Ожидается одна строка
  и `ПродукцияЧисло = +N`. Есть ли такой документ в копии базы, на которой делалась разовая сверка, неизвестно.
- **P3-2. `docs/TESTS.xlsx`: изменился только счётчик** (`C11`, 347 → 348). В строке 14 у 2.0.17.32 записано «сценарии
  СпискиАРМЗакупок и СортировкаТаблицАРМ», а для 2.0.17.33 упоминания `СпискиДокументовЗаказаАРМ` нет. План (раздел
  «Проверки») требует строку в реестре.
- **P3-3. Строка длиннее 140 символов** (CLAUDE.md, `.bslls.json`): `АРМПроизводство/ManagerModule.bsl:3666`, 147
  символов, комментарий `ПараметрыСпискаДокументовЗаказа`. Её надо перенести.
- **P3-4. Список видов задан дважды.** `ВидыДокументовКонтура` (`АРМПроизводство/ManagerModule.bsl:3690`) повторяет
  имена из `ОписаниеЧастейДокументовЗаказа` (`:3705`). Часть, добавленная без правки списка, даёт `&Вид<Имя>` без
  значения. Тогда список падает «параметр не задан», а `ДокументыЗаказа` — исключением. Надёжнее строить параметры
  `Вид…` обходом `ОписаниеЧастейДокументовЗаказа()`, по уникальным `ИмяДокумента`.
- **P3-5. Номер в производстве больше не обрезается.** Старый `ДобавитьДокументЗаказа` делал `СокрЛП(Номер)`, новый
  текст отдаёт номер как есть. Разовая сверка тоже сравнивала номера после `СокрЛП`. На экране хвостовые пробелы не
  видны. Для `ДокументыЗаказа(Заказ)` это изменение контракта, сейчас Номер там никто не читает. Достаточно принять
  его осознанно, правка не нужна.
- **P3-6. Имя параметра `Документы` в `ОбновитьИтогиДвижения(Документы)`** (`АРМПроизводство/Forms/Форма/Module.bsl:4455`)
  перекрывает глобальный `Документы`. Формальный параметр работает: такой же есть у `КоличестваЗаказа(Материалы,
  Документы)`. Но в памяти проекта имя `Документы` записано как ловушка компиляции. Лучше переименовать в
  `СтрокиДокументов`.
- **P3-7. Гигиена коммита.** В рабочем дереве лежат неотслеживаемые `docs/.!95431!TESTS.xlsx` (файл блокировки
  Excel, 0 байт, от 10.11) и `docs/plans/order-payment-state.md` (чужая задача). В коммит сборки их не добавлять.

## Проверено, замечаний нет

- **Эквивалентность закупок.** `ПодзапросОбъектовОплат`/`ПодзапросНакладныхЗаказа` повторяют `ВТПоступления` →
  `ВТНакладныеВсе` → `ВТНакладные` (проведённые поступления заказа, проведённые накладные; `В (…)` вместо `РАЗЛИЧНЫЕ`).
  Платежи берутся одной частью: регистраторы четырёх видов, прочие типы отсекаются, как и раньше. Группировка
  «Оплат» по `Регистратор, ДокументПродажи` с `МАКСИМУМ(Период)` принята в плане. Вид — `Синоним`, как раньше.
  Статус — те же `ПараметрыСтатусаДокумента`.
- **Эквивалентность производства.** Набор частей и права (`ДобавитьЧастьДокументов`, `ДобавитьПаруДвижения`) прежние.
  Движение считается только у проведённых непомеченных: это внешний `ВЫБОР`, он эквивалентен
  `ДокументыСДвижением`. Условие ордера и исключение услуг перенесены. «Через» пусто при первом уровне (`МАКСИМУМ(ПервыйУровень)`).
  Автовыпуск и первый уровень у `ВыпускПродукции` взаимоисключающие. `Сумма` обнуляется по `&СуммыВидны`.
  `ПредставлениеСтатусаДокумента` проверяет `ПометкаУдаления` первой, и `ВЫБОР` идёт в том же порядке.
- **Защита от пустого заказа (P1-1).** `&ЕстьЗаказ` стоит в каждой части обоих текстов закупок, в условии `Обороты`,
  в подзапросах объектов оплат и накладных, в каждой части и в каждом подзапросе движения производства. Параметр
  ставится до раннего возврата (`ЗагрузитьДанныеЗаказа`) и при пустом заказе производства.
- **Параметры.** Каждый `&` в текстах (`Заказ`, `ЕстьЗаказ`, `Вид<Имя>` восьми и десяти видов, три статуса,
  `ПометкаАвтовыпуска`, `СуммыВидны`) есть в `ПараметрыСпискаЗаказа` и `ПараметрыСпискаДокументовЗаказа`. Лишние
  параметры отсекает `ДоступныеПараметры.НайтиПараметр`. Заглушки используют только `&СтатусЧерновик`.
- **Права.** В `Form.form` лежит полный текст, код подменяет его текстом по правам. Заглушки сделаны без таблиц, у
  `ТекстЗаглушкиСписка` есть явные ветки и исключение на неизвестное имя (P3-1 плана). `ТекстыЗапросовОплат` отдаёт
  полные тексты (P3-2 плана).
- **Обращения как к коллекции.** Их не осталось. `Оплаты`/`Документы` убраны из `КлючиТекущихСтрок`, `Очистить`,
  `Загрузить`, `ПрименитьПорядок`. В производстве убраны `Загрузить`, `КлючТекущейСтроки`/`ВернутьТекущуюСтроку`,
  `ПрименитьПорядок`. Подвал и подсказка индикатора считаются по `Данные.Документы`, счётчик — по
  `КоличествоДокументовЗаказа`. `ОбновитьЗаголовкиЗакладок` (`&НаКлиентеНаСервереБезКонтекста`) у динамического
  списка `Количество()` не вызывает, только берёт значение по имени. Удалённые функции нигде не вызываются, кнопки
  сортировки у трёх таблиц сняты. `СортироватьПоТекущейКолонке` к ним теперь не доходит.
- **Form.form.** Обе формы: id элементов и реквизитов верхнего уровня уникальны. «Использовать всегда» есть у
  `Оплаты.Документ`, `Оплаты.Основание`, `Документы.Документ`, `ДокументыЗаказа.Документ`: их читают
  `ОткрытьДокументСтроки` и `ДокументыЗаказаВыбор`. У таблиц `DynamicListTableExtInfo`, подвал сохранён (`ТекстПодвала`).
  Колонки движения связаны с `…Число`, формат `ЧН=; ЧГ=0` задан на четырёх языках. `КоличествоДокументовЗаказа`
  (id 801) имеет тип Число(10,0). `ListSettings.dcss` у трёх списков: порядок `Дата` по возрастанию, свои
  userSettingID.
- **Перечитывание (P2-1 плана).** `Обновить()` вызывается безусловно в `УстановитьПараметрыСписковЗаказа` и
  `УстановитьПараметрыСпискаДокументов`, и при том же заказе тоже.
