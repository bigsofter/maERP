## P2-1. План ошибочно отождествляет ввод на основании выпуска с хранением ссылки на выпуск

**Где:** §1, §2–4, §8.

**Подтверждение:** `src/cf/src/Documents/ПередачаВПереработку/ПередачаВПереработку.mdo:228–230` — тип `Основание` только `DocumentRef.ЗаказПокупателя`. В `ObjectModule.bsl:92–102` заполнение по выпуску сохраняет **заказ выпуска**, а по автовыпуску — заказ реализации. Ссылка на исходный выпуск в основании передачи не сохраняется.

**Сценарий отказа:** пользователь создаёт передачу на основании выпуска полуфабриката по заказу Z. После записи её основание — Z. Запрос закладки `Переработка` по условию `Основание = Z` покажет эту передачу, хотя §4 обещает показывать такие передачи только в «Документах». Предлагаемые дополнительные ветки поиска «передача → ручной/автоматический выпуск → заказ» не соответствуют хранимым данным и не решают исключение таких передач.

**Правка:** использовать единственную фактическую цепочку `Поступление → Передача → Заказ` в E8, E9 и обработчике обновления. Убрать обещание исключать передачи, созданные по выпуску: без сохранённого признака происхождения отличить их нельзя. Применять к ним обычные ограничения по содержимому документа. Добавить проверку передачи, заполненной по ручному выпуску и автовыпуску. Расширять тип основания для этого не требуется.

## P2-2. Блокировка остатков не защищает проверку наличия черновиков поступлений

**Где:** §4, запрет изменения передачи с поступлениями, включая черновики.

**Подтверждение:** `src/cf/src/Documents/ПоступлениеИзПереработки/ObjectModule.bsl:11–19` — блокировка `ТоварыВПереработке` берётся только при проведении. В `ПередЗаписью` и `ПриЗаписи` (`45–56`) общей блокировки с передачей нет. Объектная блокировка передачи также не блокирует запись другого документа — поступления.

**Сценарий отказа:**
1. Сеанс A в рабочем месте начинает отмену передачи, блокирует остатки и повторно проверяет: поступлений нет.
2. Сеанс B сохраняет непомеченный **черновик** поступления по этой передаче. Блокировка остатков ему не мешает.
3. Сеанс A завершает отмену передачи.

В результате отменена передача, у которой уже сохранено поступление, — вопреки заявленному запрету. Повтор запроса под блокировкой остатков этот случай не закрывает. Сам по себе черновик отрицательных остатков не создаёт.

**Правка:** синхронизировать проверку зависимостей и запись поступления общей управляемой блокировкой по ссылке передачи. Поступление должно участвовать в этом протоколе и при записи черновика; после блокировки необходимо повторно проверять допустимость основания. Зафиксировать единый порядок этой блокировки относительно складских блокировок. Добавить двухсеансовую проверку «отмена передачи одновременно с записью черновика поступления».
