# Круги верификации S2+S3 — субагент Claude по `.ai/prompts/reviewer-verify.md`

Два круга. Codex в лимите до 18:00, гейты на субагентах.

## Круг 1 — вердикт `reject`

Из восьми находок полного ревью кода и ревью данных закрыты семь (одна частично), плюс пять новых
дефектов, из них один P0.

**P0. `СогласоватьМатериалы` звал три несуществующих метода — модуль объекта заказа не собрался бы.**
Правка, заменявшая блок нормализации по диапазону «от комментария до комментария», снесла заодно три
соседние процедуры: `ЕстьТехкартыСтрок`, `ОчиститьМатериалыЗаказаНеНаПроизводство`,
`РазвестиПовторныеКодыСтрокСМатериалами`. Места вызова остались. Любая запись заказа падала бы с
«Процедура или функция с указанным именем не определена»; вместе с `ОчиститьМатериалыЗаказаНеНаПроизводство`
терялась очистка материалов у заказа не на производство (решение владельца 2026-09-13).
**Ни один статический гейт этого не увидел**: BSL LS дал ноль новых замечаний, `refcheck` и `listcheck`
прошли чисто. Урок записан правилом `bsl-016` в tiny1C.

**P2. Новый код строки мог сесть на висящую ссылку родителя.** `МаксимальныйКод` считался только по
`КодСтроки`. У данных обмена коды строк бывают нулевыми при заполненных ссылках: максимум = 0, новые
коды 1, 2, 3 садятся ровно на чужие ссылки — сирота молча усыновляется в чужое поддерево и теряет
потребность, в худшем случае замыкает кольцо и даёт ложный отказ записи.

**P2. `Новый Соответствие(Пройденные)`** — документированный конструктор принимает
`ФиксированноеСоответствие`; прецедента вызова от обычного `Соответствие` в конфигурации нет, а падало
бы построение дерева на любом заказе с двухуровневыми материалами, то есть основной сценарий этапа.
Синтаксическая проверка EDT такого не ловит.

**P3.** После сужения до производимых строк `ПроверитьРазворачиваниеКартБезМатериалов` перестала быть
гейтом: отказ к этому моменту уже выставлен сообщением выше. Комментарий-контракт утверждал обратное.

**P3.** Первый блок `ПроверитьНормализациюДереваМатериалов` проходил по совпадению и не был сторожем.

## Круг 2 — вердикт `approve`

Все пять закрыты, новых дефектов в дельте нет.

- Список процедур модуля объекта сверен с HEAD поимённо: удалённых нет ни одной, добавлено ровно пять
  задуманных; тела трёх восстановленных совпадают с HEAD посимвольно; во всём модуле один блок
  удаления — намеренный `МатериалыПоКодам` в `ПроверитьСоставОднойПродукции`.
- `МаксимальныйКод` считается и по `КодСтрокиРодителя`: новый код больше любого существующего кода и
  любой ссылки, самоссылка невозможна, потомки не перевешиваются.
- Копия набора пройденных сделана циклом, исходный набор не мутируется, ветвь остаётся ветвью,
  повторное вхождение материала в разных ветвях не теряется, кольцо ловится.
- Комментарий-контракт соответствует коду; сопоставление ошибок по продукции-владельцу работает.
- Сторож коллизии в сценарии проверен прогоном по коду: **без** фикса утверждение упало бы, **с**
  фиксом проходит. Не случайный.

### Замечание вне дельты (не регресс)

`РазвестиПовторныеКодыСтрокСМатериалами` (код HEAD, восстановлен как есть) считает максимум только по
`ТЧТовары.КодСтроки`: новый код строки товаров теоретически может сесть на висящую
`ТЧМатериалы.КодСтрокиПродукции`. Исходное поведение, записано в `docs/TECHDEBT.md`.
