# Ревью кода сборки A — субагент Claude (фоллбэк `ai-review`)

Дата: 2026-09-20. Слаг: `production-subcontracting-s4`, сборка A (2.0.15.42).
Бэкенд: субагент Claude с промптом `.ai/prompts/reviewer.md`. **Причина фоллбэка: Codex в лимите квоты.**

## Вердикт

`approve_with_changes` — P0, P1 и P2 нет. Три находки P3.

## Находки

**P3-1. Тринадцатое место опознания автовыпуска по типу основания, пропущенное «полным» перечнем A.4.**
`ПередачаВПереработку.ЗаполнитьПоВыпускуПродукции` (`ObjectModule.bsl:101-105`) разбирает основание
выпуска через `ТипЗнч(...) = Тип("ДокументСсылка.РеализацияТоваровУслуг")`. Сегодня поведение тождественно
признаку; в сборке B основанием автовыпуска станет передача, условие уйдёт в `Иначе`, и передача,
введённая на основании такого выпуска, получит основанием **саму передачу-родителя** вместо заказа.
**Исправлено сразу, а не отложено в B:** ветка переведена на признак, реквизит добавлен в тот же вызов
`ЗначенияРеквизитовОбъекта` — лишнего чтения не появилось. Строка добавлена в таблицу A.4: заявление о
полноте перечня должно быть верным, иначе оно хуже отсутствия перечня.

**P3-2. Мёртвое поле `Д.Основание КАК Основание`** в пакете закладки «Выпуски»
(`АРМПроизводство/ManagerModule.bsl:5472`): после правки псевдоним никем не читается, соединение с
реализацией использует поле таблицы напрямую.
**Отклонено с причиной:** в сборке B этот путь снова обращается к основанию (разворачивание заказа у
автовыпуска с основанием-передачей). Убрать поле сейчас, чтобы вернуть через сборку, — churn в запросе,
который и так правится в B. Помечено к пересмотру там.

**P3-3. Тексты остались про реализацию там, где условие стало общим** — инфопанель списка
(`ФормаСписка/Module.bsl:355-361`), `ТекстАвтовыпускЧерезРеализацию`, `НадписьАвтовыпуск.Заголовок`.
В сборке A это верно: других оснований нет. Плюс развилка инфопанели вложена в
`Если ЗначениеЗаполнено(Шапка.Основание)` — выпуск с признаком и пустым основанием молча покажет обычную
панель.
**Принято как работа сборки B:** обе правки записаны в план (B.4), включая вынос проверки признака
из-под условия заполненности основания.

## Что проверено и находкой не является

1. **Запрет ручной правки не ослаблен.** Четырёхчастное условие и новая `ЭтоЗаписьАвтовыпуска` прогнаны по
   трём веткам (механизм пишет свой выпуск; пользователь сменил основание у записанного автовыпуска;
   `ЗаписьМеханизма` не равен основанию) — поведение совпадает. Новая ветка «признак без распознанного
   основания» — строго **ужесточение**, достижима только на испорченных данных.
2. **Лишнего чтения базы на горячем пути нет.** Старый код на том же условии читал `Основание` одним
   запросом, новый читает два поля тем же одним запросом. В `ОбработкаПроведения` и `ПриКопировании`
   стало дешевле: было сравнение типа ссылки, стало чтение булева из памяти.
3. **`ЗначениеЗаполнено` корректно накрывает `Истина`/`Ложь`/`Неопределено`**, а
   `ЗначенияРеквизитовОбъекта` действительно возвращает структуру с `Неопределено` у незаполненной ссылки.
4. **Обработчик обновления**: идемпотентность, отсечение пустой ссылки, безопасность записи в режиме
   загрузки, поведение на пустой базе, равенство версии обработчика версии конфигурации (равенство не
   отсекается), безопасность падения посреди прогона.
5. **АРМ**: условная ветка имени по образцу `НомерВходящегоДокумента`; строка закупки не падает; поле
   добавлено именно в тот запрос пакета, чью выборку читает `СтрокаВыпуска`; группировок в нём нет.
6. **`ПриКопировании`**: порядок снятия признака и вычисления заказа верен.
7. **Проверка копии в сценарии не вырожденная**: если бы `Скопировать()` не вызывал `ПриКопировании`,
   утверждение `Не Копия.СозданАвтоматически` упало бы, а не прошло.
8. **`.mdo`**: форма объявления, позиция `<comment>`, `fillValue`; права ролей на реквизиты
   `Document.ВыпускПродукции` нигде не перечисляются. `Form.form` правки не требует — форма перечисляет
   только основной реквизит `Объект` без дочерних.

Регламент: строк длиннее 140 символов в модулях нет, секция «Что нового» на четырёх языках есть, версия
поднята, реестр `docs/TESTS.xlsx` синхронизирован с `docs/TESTING.md`, запретные пути не тронуты.
