# Ревью данных и проведения — 2.0.16.25 (multicurrency-returns)

Ревьюер: субагент Claude (замена `ai-database`, Codex недоступен до 2026-10-09). Режим read-only, объём — `git diff HEAD`
плюс `docs/plans/multicurrency-returns.md`. Сценарии прослежены по коду; на базе не прогонялись.

## Что проверено и сходится

- **Возврат → оплата.** R = 1000 EUR по курсу 10 (10000). Возврат 400 EUR по курсу R: `Расход 4000/400` на R → 6000/600.
  ПКО в MAD 6300 по курсу 10,5: `СуммаВВалюте` 600, доводка до остатка (`ЗакрыватьОстаток`), `Расход 6000/600`, курсовая
  разница 300 уходит в Убытки. R = 0/0. С округлением (333,33 EUR по 10,8312, возврат 111,11) тоже ноль: в той же валюте
  платёж закрывает остаток ровно.
- **Оплата в другой валюте → НН → перепроведение НН.** ПКО 10500 MAD на R пишет `Расход 10000/1000`. В
  `ОплатыВалютныхОтгрузок` эта запись читается с `Регистратор` = ПКО; на R сторнируется тем же видом движения с минусом и
  заводится на N обеими суммами. Итог: R = 0/0, N = 0/0. Старая ветка перенесла бы 10500 (деньги по курсу платежа) —
  новая права. Повторное проведение даёт тот же результат: собственные движения N запрос не читает (фильтр по
  регистраторам-оплатам), двойного переноса нет. Аванс оплаты лежит на самой оплате и отсекается фильтром
  `ОбъектРасчётов В (&Отгрузки)`; оплата нескольких отгрузок переносится построчно, каждая строка в своей доле.
- **Оплата, выписанная прямо на N.** Она пишет на N по курсу N (`ВалютаОбъектаРасчетов(N)` — валюта, средний курс), в
  запрос не попадает: её объект не отгрузка. Полная оплата закрывает остаток ровно за счёт доводки до остатка.
- **Оплата, проведённая после N** (основание — R). Пишет на R. Подписка `ПослеПроведенияДокументаОплаты` перепроводит N
  в той же транзакции. Оплата записывает движения явно (`Движения.Записать()`), поэтому N их видит и переносит. Так же,
  как в старой ветке.
- **Возврат после N.** `НакладнаяПокрывающаяОснование` → N, `Сумма` по курсу R, `СуммаВВалюте` — как есть. Валюта
  возврата = валюта R = валюта N (проверка в `ЗаполнитьВалютуПоОтгрузкам`), измерение `Валюта` не дробится. РКО возврата
  денег (основание — R) переносится на N через `ОплатыВалютныхОтгрузок` с правильным знаком (сторно, `Расход` с минусом).
- **Знаки.** `СформироватьПоУслугамПереработчика` — как в HEAD: `Расход` (`Приход = Ложь`), добавлена `СуммаВВалюте`.
  В `ВзаиморасчётыСКонтрагентамиПрочие` расходы пишутся расходом, возврат — приходом, как в HEAD. В `Убытки` у возврата
  стоит `Знак = -1`, как прежде `-Стр.Сумма`.
- **Согласованность внутри документа.**
  - Переработка: долг = `СуммаРегл(Стоимость) + СуммаРегл(НДС)`. Капитализация даёт те же числа в обеих ветках: в ветке
    по строкам `СуммыСтрокВОсновнойВалюте` сводит итог к `СуммаРегл(Σ)`, а `УслугиСтрокПоступления` гарантирует, что
    Σ строк равна шапке, и раскладывает НДС с остатком на последнюю строку.
  - Прочие расходы: в `Убытки` пишется Σ строк, в `ВКП` — `СуммаРегл(шапка)`. Совпадает, если шапка равна Σ строк; это
    условие было и раньше.
- **Старые документы.** `ВалютаИКурсПоРеквизитам` при `ВВалюте = Ложь`, пустой валюте или курсе 0 даёт основную валюту и
  курс 1. Перепроведение без записи сумм не меняет: `СуммаРегл(x, 1)` = x. Фоновое перепроведение идёт через
  `Записать(Проведение)`, поэтому `ПередЗаписью` выравнивает реквизиты в основную валюту. Записанная `СуммаРегл`
  читается только при `ВВалюте` (`ПроизводственныеЗаказы`). Обработчик обновления не нужен — согласен с планом.
- **Блокировки.** `ОплатыВалютныхОтгрузок` читает `ВзаиморасчётыСПокупателями` внутри проведения N, где регистр уже
  заблокирован исключительно по `Контрагент`. Оплата держит ту же блокировку, проведение сериализовано. Возврат
  блокирует `ВзаиморасчётыСПокупателями` и `ТоварыВНаличии`. Прочие расходы и переработка новых чтений остатков не
  добавили. Нового элемента блокировки не нужно.

## Находки

### P2-1. Средний курс N с 4 знаками: налоговый и обычный регистры расходятся
`CommonModules/РаботаСВалютами/Module.bsl:316` (`Окр(СуммаРегл / СуммаВВалюте, 4)`) и
`AccumulationRegisters/ВзаиморасчётыСПокупателямиНалоговый/ManagerModule.bsl:10`.

Долг N в `ВзаиморасчётыСПокупателями` = Σ `СуммаРегл(покрытие_i, курс_i)`. В налоговом регистре — `СуммаРегл(N.Сумма,
округлённый средний курс)`. Пример: A = 1000,00 EUR по 10,8312 (10831,20), B = 333,33 EUR по 10,9000 (3633,30).
Σ = 14464,50 / 1333,33 → курс 10,848469 → 10,8485 → в налоговом 14464,53, в обычном 14464,50: расхождение 0,03.
Погрешность до 0,00005 × Σ EUR, то есть около 10 MAD на 200 000 EUR. То же число получат `ПолучитьСуммуДокумента(N)`
(корректировка долга) и сертификат — они пересчитывают по курсу N.

Фикс: считать сумму N в основной валюте как Σ по отгрузкам (та же формула, что в `ДолгПоОтгрузкам`) и записывать в
`N.СуммаРегл` в `ПередЗаписью`. Налоговому регистру брать `СуммаРегл` вместо `СуммаРегл(Сумма, курс)`. Для одной
отгрузки ≥ 100 EUR расхождения нет.

### P2-2. Оплата на R после N не доводится до остатка — копейка повисает на N
`РаботаСВалютами.РасчетСтрокиОплаты` (стр. ~530) ищет долг по `Объект` = R, а после N остаток R = 0. Доводки нет, и
`СуммаВВалюте` платежа в MAD по чужому курсу может разойтись на 0,01: 333,33 EUR → 333,32. Перенос на N сохранит это
расхождение: N останется 0,01 EUR / ~0,11 MAD. До 2.0.16.25 сценарий был невозможен (валютной N не было).

Фикс: в `ДолгОбъектаРасчетов` / `РасчетСтрокиОплаты` искать остаток по `НакладнаяПокрывающаяОснование(Объект)` для
реализаций. Объект записи оставить R — его перенесёт N.

### P2-3. Тесты не покрывают новую ветку переноса оплат
`DataProcessors/ТестыДокументов` — `СценарийВозвратыВВалюте` проверяет только перенос долга на N без оплат.
`ОплатыВалютныхОтгрузок` — главный новый код этой сборки, он не исполняется ни одним тестом.

Фикс: добавить шаг «R в EUR → ПКО в MAD по другому курсу → N → остатки R и N = 0/0 в обеих суммах → повторное
проведение N → то же самое». По возможности добавить «ПКО на R после N» (P2-2) и «возврат после N + РКО возврата денег».

### P3-1. Запросы в цикле
- `ДанныеРеализаций` (`ВзаиморасчётыСПокупателями/ManagerModule.bsl:244`) и `ЗаполнитьВалютуПоОтгрузкам`
  (`РаботаСВалютами:300`) вызывают `ВалютаИКурсОбъекта` на каждую отгрузку, а это отдельный `ЗначенияРеквизитовОбъекта`.
  В первом случае хватит добавить `ВВалюте, Валюта, КурсВалюты` в уже существующий запрос.
- `Движение` вызывает `ВалютаОбъектаРасчетов` на каждую запись. `ОплатыВалютныхОтгрузок` даёт 2 записи на каждую
  запись оплаты: N на 50 отгрузок по 3 оплаты — около 400 одиночных запросов. Фикс: кэш валюты объекта в
  `Соответствие` на время проведения.

### P3-2. Ручная разбивка оплат накладной без подписи валюты
В `ТЧСпособыОплаты` суммы трактуются как основная валюта (налоговый регистр, `ДСО.СформироватьПоНалоговойНакладной`),
но колонка формы не подписана. У валютной N пользователь введёт сумму в EUR, и она уйдёт в MAD.

Фикс: заголовок колонки `ТЧСпособыОплатыСумма` с основной валютой, как у `СуммаРегл`.

### P3-3. N по заказу без отгрузок в валюте
`ЗаполнитьВалютуПоОснованию(…, заказ)` делает N валютной по курсу дня, но долга в `ВзаиморасчётыСПокупателями` у неё
нет (нет отгрузок). Оплата, выписанная на такую N, ляжет на неё с `Валюта` = EUR отрицательным остатком. Для N в
основной валюте поведение то же — краевой случай, достаточно записи в TECHDEBT.

### Вне диффа (существовало и раньше, новая ветка унаследовала) — проверить на базе
- **Зачёт авансов реализации (`ТЧЗачётАвансов`) на N не переносится.** Реализация пишет на себя «долг + оплата» (в
  сумме 0) и остаток `Σ − зачёт`. `ДолгПоОтгрузкам` переносит всё покрытие: R уходит в −зачёт, N показывает долг на
  сумму зачёта.
- **Отмена проведения оплаты.** Подписка `ПослеОтменыПроведенияДокументаОплаты` перепроводит N. Если в этот момент
  движения оплаты ещё не удалены платформой (ПКО чистит их явно только при заказах на производство), N сохранит перенос
  уже отменённой оплаты. Проверить на базе: «ПКО на R → N → отменить проведение ПКО → остатки R и N».

## verdict: approve_with_changes

Блокирующих (P0/P1) находок нет. Логика переноса оплат валютной накладной, знаки и согласованность сумм внутри
документов корректны, старые документы не затронуты, обработчик обновления не нужен. До сдачи рекомендуются P2-3
(тест новой ветки) и P2-1 (сумма N в основной валюте как Σ по отгрузкам). P2-2 и P3 — в эту сборку или в TECHDEBT.
