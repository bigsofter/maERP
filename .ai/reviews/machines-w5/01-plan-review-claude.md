## P1
1. C: черновые строки в контексте окна с пустым регистратором пропускаются `ОкончаниеПомехи` (`Неопределено <>
   Неопределено` = Ложь) — все строки станка лягут в одно окно. → маркер-регистратор черновика.
2. C: `ОкончаниеПомехи` прерывает цикл по началу — занятость после добавления строки сортировать по началу.
3. E: у общих команд своё право `View` — выдать ролям `Кладовщик` и `ОператорПроизводства` осознанно.
4. E: учётное «свободный остаток» не совпадает с физическим пересчётом (закреплённое лежит там же) → фантомный излишек
   и проведённое оприходование. → учётное = всё на складе станка, закреплённое — колонкой.

10. A: требования без нормы размывают производительность — исключать из обеих сумм.

## Решения (главная сессия)
- 1, 2, 6, 7, 11–13: в план C и реализацию; 7 — длительность черновика через тот же `ДлительностьМатериалов` по
  материалам, заполненным как у требования (`ЗаполнитьПоСтрокеЗаказа` во временном объекте), + тест равенства окончаний.
- 3: `View` трёх команд — `Кладовщик` все три, `ОператорПроизводства` — оприходование и списание материалов
  (пересчёт у него только чтение).
- 4: принято — учётное = всё на складе станка, колонка «Закреплено» справочно; списание закреплённого остаётся под
  инвариантом.
- 5: в виде «По станку» — отказ проведения показывается, пустой документ не создаётся (вне вида — поведение прежнее,
  TECHDEBT).
- 8: фактический ремонт с плановыми датами (был запланирован) отказом MTBF не считается.
- 9, 10, 21: в код A.
- 14: страница в обеих формах элемента, если в ECommerce есть производственные реквизиты; иначе только `ФормаЭлемента`.
- 15: смена станка при переносе сбрасывает ручную длительность.
- 16: в тест D.
- 17: закреплённое в «По станку» не вычитается (учётное = всё), вопрос снят.
- 18: функция не нужна (п. 4).
- 19: «Заполнить по заданиям» в виде «По станку» — склад станка как и есть (полный остаток) — совпадает с п. 4.
- 20: принято.
