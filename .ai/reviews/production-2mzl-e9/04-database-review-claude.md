Бэкенд: субагент Claude `general-purpose` + `.ai/prompts/database.md`. Первый проход — `04-database-review.md`
(`opencode/gpt-6-astra`, временная замена Codex): reject, 2×P1 — закрытый период автовыпуска; серийный материал из
общего остатка.

**Вердикт: approve_with_changes** — P0/P1 нет. Код прочитан, прогонов не было.

## Находки и решения

| # | Находка | Решение |
|---|---|---|
| P2-1 | автовыпуск переписывается в закрытом периоде (реализация 00:00:00) | **исправлено** (та же находка у astra): `МожноИзменитьАвтовыпуск` по прежней и новой дате до любых изменений, проверка в `ПередЗаписью` выпуска безусловная |
| P2-2 | отчёт «Потребности производства» считает дефицит без «Из остатка», расходится с «Заполнить по потребности» | **исправлено**: `Дефицит`, `КЗаказу`, «только дефицит» вычитают `ИзОстаткаОстаток` |
| P3-1 | встречные блокировки: строки реализации по складу и номенклатура автовыпуска без склада | **исправлено**: при автовыпуске один элемент остатков без склада по объединённой номенклатуре |
| P3-2 | партия под заказ - весь документ поступления, в т. ч. строки без заказа | TECHDEBT |
| P3-3 | смена основания проведённой реализации без блокировки старого заказа (если у автовыпуска не было «ИзОстатка») | TECHDEBT |
| P3-4 | `ЕстьВыпускиПослеДаты` советует перезаполнить автовыпуски; АРМ и дашборд | TECHDEBT (АРМ — E12) |
| P3-5 | план: константа выключается в `Продажа` | план поправлен: только `СтадииЗаказа` |

## Подтверждено

Исключений при вложенной записи не видно; `ПроверитьЗаполнение()` покрывает обязательные поля; граница остатков пробы и
проведения одна (`МоментВремени()` записанного объекта), наборы после пробы очищаются; блокировка выпуска — подмножество
блокировки реализации, расхождение ловит `ВПределахБлокировки`; распроведение вложенного выпуска удаляет движения
платформой до блокировки истории; двойного счёта в количестве к выпуску нет; «ИзОстатка» только при сформированной
потребности; реструктуризация без потери данных, индекс сохранён, регистратор регистра составной; все чтения основания
выпуска как заказа учтены; `Список.Основание.Контрагент` работает для обоих типов; критерий `СвязанныеДокументы` содержит
реализацию; ожидания сценария сходятся с кодом (210/360/320, «ИзОстатка» 4, M1 42, индикаторы, доля 0,8), две реализации
в одну секунду — 6 и 4 при любом порядке ссылок.
