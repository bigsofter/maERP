## Заключения

1. **`ОтразитьПередачу`.** Приход строится из расходов `ТоварыВНаличии` самой передачи; списание вызывается без
   `ПоСтрокам` (`ТоварыВНаличии/ManagerModule.bsl:408`), код строки = 0, строки ТЧ свёрнуты (:731-757) — связи с
   заказом нет. Механизм `ПоСтрокам = Истина` есть (расходный ордер, `ОрдераСклада:2762`): код строки пишется в
   `ТоварыВНаличии` и `ДополнительныеРасходы` (:963, :968), затем свёртка по коду строки → заказ строки. Не проверено:
   комплекты, колонка МестоХранения, читатели `КодСтроки`. Запасной вариант — пропорциональное деление партии.
2. **Списание у переработчика.** Отбор по заказу идёт через передачи, приход которых несёт заказ (:120-130, :361-367),
   из-за асимметрии старых расходов (обработчик 1.0.11.5, комментарий :355-360). Предложение: ремонт данных
   (заказ расхода = заказ прихода той же партии и передачи), затем отбор по измерению `ЗаказПокупателя В (&Заказ,
   пустой)` по группам; группы разбираются по очереди на общей таблице партий; контроль недостачи по группам.
3. **Автовыпуск ПФ (S4)** завязан на один заказ полностью (Производство:1145-1149, 2114, 2509, 2037, 3080/3144, 2448,
   505, 538, 38-41; один выпуск на передачу; заказ выпуска — из `Передача.Основание`). Поддержка — N автовыпусков на
   передачу, высокий риск. Рекомендация — запрет в многозаказной передаче с явным текстом; при пустом основании расчёт
   неактивен, прежний автовыпуск распроводится (:158-161). Нужен инвариант «один заказ строк ⇒ `Основание` = он».
4. **Себестоимость поступления** делится по весам на всю продукцию документа (ТоварыВНаличии:509-546) — в
   многозаказном документе нужно по группам. Беззаказная партия, списанная под заказ A, в движениях остаётся
   беззаказной — суммы групп возвращать из `СписатьИзПереработки` в памяти. Одинаковая позиция двух заказов — одна
   партия продукции со средней стоимостью.
5. **Стадии.** `ЗаказыДокумента` — из `Основание` (до записи — из базы, :729; поступление — через передачу, :711-716);
   дальше массив (:621-638). Нужно объединение заказов строк + шапка. `ЗаблокироватьИсторию` (:830) — порядок
   заказов не проверен.
6. **Ожидаемая продукция и сырьё** — по группам заказа (передача: деление `ТЧТовары`; поступление:
   `ОжидаемаяПродукция`, `ВычестьПоступившуюПродукцию` с ключом `Заказ`, `ОграничитьОстаткомЗаказа` по заказам,
   `СырьеПоПродукции` по группам, беззаказные — последовательно, дочистка по партиям передачи и заказа).
7. **Обработчики обновления.** Догоняющая база проходит все обработчики подряд на новом коде до нового обработчика
   (ОбновлениеПрограммы:357-385, Обработчики:242-255). Безопасны 1.0.11.4, 1.0.11.5, 2.0.16.120. Опасны 2.0.15.48
   (`СырьеСовпадаетСРасчетом`), 2.0.16.41 и 2.0.16.99 (`ЗаписатьСтадиюЗаказа`) — нужен запасной путь «заказ строки,
   иначе шапки» во всех новых чтениях.
