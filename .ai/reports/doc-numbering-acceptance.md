# Приёмка: настройка нумерации документов (префикс, год, разрядность), тикет 2604744

Сборка - следующая после 2.0.18.5. Критерии и однотипные объекты (все 54 документа) дописываются перед
планом; здесь зафиксирована постановка, чтобы решения владельца не потерялись.

## Постановка

Тикет 2604744 дословно:

«сделать настройку для назначения префиксов по типам документов + возможность добавить номер года. Пример:
Реализация (Bon de livraison) L26000001, накладная F26000001»

Вопросы исполнителя (2026-11-22) и ответы владельца дословно:

0. «у налоговых накладных повышай длину номера до 11, а зашитый в код префикс заменяем на наш модуль
   префиксации»
1. (вид номера, число цифр) «Да, делай как в примере, но будет здорово, если мы дадим через Администрирование -
   выбери пункт настроек, возможность сами задавать префиксы, разделители, год и разрядность нумерации в разрезе
   типов документов. Эту таблицу лучше сразу сделать заоплненными значениями по умолчанию, например, расходная
   налоговая накладная имеет префикс F, обычный расход префикс BL (Bon de Livraison), приходная накладная BR (Bon de
   Reception) и т.д. Остальные сам подбери. Шаблон по умолчанию сделай PPYYNNNNNNN, где PP - префикс, YY - год,
   NNNNNNN - номер по порядку с лидирующими нулями. Еще надо ввести R - разделитель (тоже можно указать), YYYY -
   год в 4 значном выражении, WW - неделя по порядку, MM - месяц двузначный с лидирующим нулем, DDD - номер дня в
   году. По умолчанию надо заполнить, но дать возможность менять. По умолчанию заполнять для новой базы тоже.»
2. (префикс организации) «Префикс организации нужен, для него давай введем отдельный символ CC, например. Если он
   не предусмотрен в шаблоне д,Т то не подставляется префикс организации. А если преудсмотрен в шаблоне, то
   подставляется по организации или 00, если в шаблоне включен, а в организации не указан.»
3. (префикс контрагента у реализации с месяцем отгрузки) «Нет, это удаляем совсем, этот функционал не нужен.»
4. (охват) «По всем абсолютно, и там где префикс уже работает.»
5. (стартовый номер при смене посреди года) «Нет, стартуем с 1 всегда. Если нужен будет стартовый, то вручную
   поменяют номер у первого сгенерированного»
6. (номер в печатных формах целиком) «Целиком, да.»
7. («AC» у налоговой накладной покупки - из кода в настройку) «да»

Вопросы исполнителя (2026-11-24, выбор из вариантов) и ответы владельца:

8. (охват первой сборки: все документы, кроме двух платёжных документов банковского обмена - им только префикс без
   года, автоматического коммерческого предложения и сертификата на оплату) «Согласен с исключениями»
9. (повторная печать документов, записанных до обновления) «Старые - как раньше»: номера прежнего вида (только
   цифры) печатаются без ведущих нулей и с годом, как сейчас; новые - целиком.
10. (длина номера) «15 у всех» - не 20.
11. (счёт заново посреди года у действующих клиентов: после реализации № 1530 следующая BL260000001) «Да, с 1 сразу»
12. (смена числа цифр счётчика посреди года при прежних префиксе и годе) «Разрешить, счёт с 1»: смена разрядности
    начинает новую серию с 1, номера прежней длины остаются.

## Критерии приёмки

| № | Критерий | Статус | Доказательство |
|---|---|---|---|
| 1 | В «Администрировании» есть пункт настройки нумерации документов: таблица, в которой по строке на каждый вид документа конфигурации - префикс, шаблон номера, разделитель | не закрыт | |
| 2 | На новой базе и после обновления существующей таблица заполнена значениями по умолчанию: шаблон `PPYYNNNNNNN`; расходная налоговая накладная - префикс F, реализация - BL, поступление - BR, налоговая накладная покупки - AC, у остальных документов - свой префикс; префиксы не повторяются | не закрыт | |
| 3 | Администратор меняет в строке префикс, шаблон или разделитель и записывает; неверный шаблон (неизвестный элемент, нет счётчика N, номер длиннее допустимого) не записывается с понятным сообщением | не закрыт | |
| 4 | Новая реализация с датой в 2026 году при настройке по умолчанию получает номер вида `BL260000001`, следующая - `BL260000002`; налоговая накладная - `F260000001` | не закрыт | |
| 5 | Элементы шаблона работают: YYYY - год четырьмя цифрами, MM - месяц с лидирующим нулём, WW - номер недели, DDD - номер дня в году, R - заданный разделитель, число букв N - разрядность счётчика; год, месяц, неделя и день берутся из даты документа | не закрыт | |
| 6 | Префикс организации подставляется только при элементе CC в шаблоне: по организации документа, а если у организации он пуст - `00`; без CC в шаблоне префикс организации в номер не попадает | не закрыт | |
| 7 | Счётчик нового префикса и нового года начинается с 1; если пользователь вручную поменял номер документа на больший, следующий документ получает номер после него | не закрыт | |
| 8 | Нумерация по настройке действует у документов конфигурации, включая те, где префикса раньше не было; номер вмещает 15 знаков (у налоговых накладных длина увеличена с 6; ответ 10). У двух платёжных документов банковского обмена настраивается только префикс, без года (ответ 8). Исключения, названные владельцу: сертификат на оплату (его номер - код, который кассир вводит числом) и автоматическое коммерческое предложение (носит номер своей реализации) | не закрыт | |
| 9 | Префикса контрагента у реализации больше нет: в карточке контрагента нет полей «Префикс» и «Добавлять к префиксу месяц отгрузки», номер реализации от контрагента не зависит | не закрыт | |
| 10 | Уже записанные документы после обновления сохраняют свои номера | не закрыт | |
| 11 | В печатных формах номер нового вида выводится целиком, как в документе (`BL260000001`); документ, записанный до обновления (номер только из цифр), при повторной печати показывает номер как раньше - без ведущих нулей и с годом («13/26») (ответ 9) | не закрыт | |
| 13 | Администратор посреди года меняет число цифр счётчика при прежних префиксе и годе: настройка записывается, следующий документ получает номер 1 новой длины, документы с номерами прежней длины остаются и открываются (ответ 12) | не закрыт | |
| 14 | После обновления действующей базы посреди года первый новый документ вида получает номер 1 по шаблону (после реализации № 1530 - `BL260000001`) (ответ 11) | не закрыт | |
| 12 | Два пользователя, одновременно записывающие документы одного вида в серии, начатой после записи настройки (со второго её номера), получают разные номера, записи без ошибки. Вне этой гарантии - первый номер серии, документы задним числом в год с прежними номерами и серия, куда загрузкой или обменом попал номер не по образцу: дублей нет, второй пользователь может получить отказ по уникальности номера и повторяет запись | не закрыт | |
