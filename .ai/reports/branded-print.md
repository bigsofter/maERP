## Фаза 2 — 2.0.16.69: КП из реализации по опции

Промпт — `docs/plans/branded-print-s2-prompt.md`, детальный план фазы — раздел 9 плана, находки — раздел 8.
Артефакты ревью — `.ai/reviews/branded-print-s2/`.

**Ревью плана** (`ai-review-plan` Codex): reject (5: P0, P1, P2 ×3) → reject (4: P0 ×2, P1, P2) → reject (4: P0,
P2 ×3; два P2 отклонены с обоснованием) → approve_with_changes (1 P2: отклонение про обрезку описания не принято —
`Описание` строки КП сделано неограниченным). Отклонение про видимость кнопки в уже открытых формах ревьюер признал.

**Сделано**
- КП: реквизит `Автосинхронизация`, индекс `Основание`, снят `checkUnique`, `ТЧТовары.Описание` — неограниченная
  строка; колонка «Из реализации» в списке. `ПередЗаписью`: отказ ручной записи при выключенной опции (кроме
  синхронизации и служебных записей), снятие флага любой несинхронной записью, запрет периода — кроме синхронизации,
  проверка уникальности номера ручного КП под блокировкой таблицы; `ПриКопировании` — флаг Ложь.
- Менеджер КП: `КПВводятсяВручную()` (константа в привилегированном режиме, bsl-023), пакетный протокол
  `СинхронизироватьСРеализациями`: блокировка реализаций → блокировка найденных авто-КП и их редакций → один пакет
  запросов только по заблокированным → защищённые КП (статус не «Черновик», `Версия > 0`, есть запись архива
  редакций) только теряют флаг записью загрузкой → создание / запись только при отличии (нормализация валюты, номер
  без дополняющих пробелов, `СуммаРегл` не сравнивается) → дубли теряют флаг, журнал регистрации.
- Реализация: протокол первым шагом `ПриЗаписи` (порядок блокировок как у заказа: КП до истории статусов); адаптер
  `ДанныеФирменнойПечати` — одна транзакция: блокировка реализаций → проверка доступа без привилегий (`ВЫБРАТЬ
  РАЗРЕШЕННЫЕ` с явными соединениями контрагента, договора, организации и право чтения справочников печати) →
  протокол → адаптер КП в узком привилегированном режиме; проверка `ПечатьКПДоступна()` и в самом адаптере; команда печати `КоммерческоеПредложение` — `ПечатьКПДоступна()`: опция выключена и роль не
  `ОператорПроизводства`; команда формы в `ФормаДокумента` и `ФормаСписка` (команда объекта в группе печати
  выводилась бы всегда — функциональная опция умеет скрывать только при выключенном значении).
- Заказ покупателя: удалены 4 команды и печатные формы КП (метаданные, модули команд, описания, ветки, права PDV и
  Казначей); «Выигран» — служебная запись под блокировкой КП.
- Скрыто при выключенной опции: страница КП в списке заказов, КП в «Связанных документах».
- Смок: каждая печатная форма — в транзакции с откатом. Демо-набор пишет КП служебной записью.
- Тесты: сценарии `КПИзРеализации`, `КПИзРеализацииНомер`; существующие сценарии ручных КП включают опцию константой.
  Скрипт `scripts/kp-concurrency.sh`; `print-preview.sh` и скрипт снимают окно «Предупреждение безопасности»
  ключом `/DisableUnsafeActionProtection` только для своей базы.

**Предпросмотр** (`build/ib-kp`, опция выключена; реализации №12 — смешанная и №13 — только услуги созданы в копии
базы для проверки): №11 товары, №12, №13 на ru/fr/en/es — все 12 сформированы; снимки
`branded-print-phase2/kp-sale-goods-ru.png`, `kp-sale-mixed-fr.png`, `kp-sale-mixed-es.png`,
`kp-sale-services-en.png`: строки товаров и услуги с содержанием, количество, итоги, тексты на языке печати.
Попутно найдено (поведение фазы 1, в TECHDEBT): итоги больших сумм срезаются шириной ячейки.

**Проверки**
- BSL LS: новых замечаний сборка не добавила. `ai-final-check` помечает FAIL «SetPrivilegedMode +1» в
  `ЗаказПокупателя/ObjectModule.bsl:244` и `РеализацияТоваровУслуг/ObjectModule.bsl:232` — обе строки из коммита
  85cc1851 (2026-10-09, ревью техдолга), позже baseline 2026-10-02; модули попали в гейт, потому что изменены этой
  сборкой. refcheck, listcheck, queryfields, colfont, menucheck — без расхождений.
- `build/ib-kp` (обновлена `ib-sync.sh`), **в обоих состояниях опции**: тесты документов 75/75 и 75/75; смок —
  CheckConfig и расширенная проверка без ошибок, 411 форм / 112 на образцах / 64 варианта отчётов — 0 ошибок, печатных
  форм 50 при выключенной опции (с КП реализации) и 49 при включённой; `kp-concurrency.sh` — 9/9 (две одновременные печати → один КП; печать одновременно с заказом «Выигран» → выигранный КП не перезаписан,
  повторная печать ведёт новый авто-КП).
- `ai-review` Codex: reject (P1 неоднозначный псевдоним `Номенклатура` в запросе протокола — исправлено; P2 сравнение
  массивов в тесте — исправлено; P2 версия и «Что нового» — сделано до ревью, verify видит только дельту) →
  `--verify`: approve_with_changes, обе исправленные — fixed.
- `ai-database` Codex: reject, P1 — служебная запись «Выигран» читала КП без блокировки, синхронизация могла сорвать
  запись заказа → блокировка КП до чтения.
- `ai-database` повторно — **approve**, 0 находок.
- `ai-security` Codex — 5 кругов: P0 печать КП открывала цены и суммы роли `ОператорПроизводства` →
  `ПечатьКПДоступна()`; P0 проверка обходилась передачей реализации менеджеру печати КП (адаптер выбирается по типу
  ссылки) → проверка в адаптере; P0 роль «Клиент» читает реализации без RLS, а контрагентов и договоры — только свои,
  привилегированный адаптер это обходил → `РАЗРЕШЕННЫЕ` с явными соединениями; P0 проверка до блокировки, чтение после
  (смена контрагента между ними) → одна транзакция под блокировкой; пятый круг — **approve**, 0 находок.
- `ai-review --verify` (Codex) после исправлений: новых дефектов дельты 0; три прежние находки помечены partially_fixed
  только потому, что их исправления попали в прошлый снимок, — ревьюер подтверждает их в рабочих файлах, сверено.
  Второй verify нашёл P2 в очистке скрипта (удаление заказов всех прогонов по префиксу метки) — сужено до метки и
  основания, скрипт перепроверен.
- Тест-граблей прогона: `ДемоНабор` при выключенной опции находил авто-КП по ключу комментария (КП повторяет
  комментарий реализации) — поиск ключей исключает авто-КП; `ДемоНаборПовтор` помечал демо-КП как человек — опция
  включается на этот шаг; `ВидОперацииЗаказа` ждал номер КП ровно в 11 знаков — сравнение без дополняющих пробелов.
  Первый зелёный прогон 75/75 шёл при включённой опции; выключенной её оставил ранний запуск скрипта конкурентности
  (до ловушки на выходе) — копии базы значение возвращено.

**Остаточные риски** (TECHDEBT, раздел фазы 2): полнотекстовый поиск при выключенной опции не проверен; запись
реализации под пользователем роли без прав на КП — только предпосылка в тесте; исключение запрета периода — без
автотеста; видимость кнопки в открытых формах после переключения опции.

**Копия базы `build/ib-kp`** после прогонов: опция включена (как была); для предпросмотра созданы реализации №12
(смешанная) и №13 (только услуги) с комментарием «print-preview фаза 2» и их КП, служба «Installation et mise en
service» — данные проверочной копии.

**Владельцу**: Refresh и проверка в EDT — новый реквизит и индекс КП, снятый `checkUnique`, тип `Описание` строки КП,
удалённые команды заказа, новые команды форм реализации, права PDV и Казначей.
