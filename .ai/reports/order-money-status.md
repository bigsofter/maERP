# Деньги и статусы заказов клиентов — 2.0.16.130 (2026-11-01)

План: `docs/plans/order-money-status.md`. Учёт времени — Drissotex. В конфигурации клиент не упоминается.

## Поиск готового

maERP — «Неотгруженные заказы» (без денег), «Ведомость по продажам» (без заказа и оплат), «Долги покупателей» (без
заказа целиком), список заказов (форма, без себестоимости); УНФ — «Сводный анализ заказов покупателей» (без
себестоимости и маржи, другая модель регистров). Готового нет.

## Что сделано

- Отчёт `ДеньгиИСтатусыЗаказов` (раздел «Продажи», общая форма отчёта): модуль объекта считает показатели пакетом
  запросов, результат — внешний набор «Заказы» схемы компоновки (образец «Эффективность станков»).
- Варианты «Деньги по заказам» (Заказчик → Заказ: сумма, отгружено по расчётам, оплачено, корректировки, долг, осталось
  оплатить, выручка без НДС, себестоимость, маржа, %; на заказчике — долг заказчика и «Не распределено») и «Статусы
  заказов» (статус сейчас, плановая отгрузка, % отгружено, просрочка красным).
- Правила плана: заказ реализации (прямая ссылка, иначе единственная обратная), налоговый документ — объект заказа, только
  если все основания ведут в один заказ; общий — исключение переноса, оплаты в «Не распределено»; деньги — в основной
  валюте по `ВзаиморасчётыСПокупателями`; % отгрузки и закрытие — по позициям [0; заказано] с расходными ордерами и
  возвратами.
- «Не распределено» считается в запросе по всем заказам заказчика, до отборов пользователя (находка ревью).
- Права: `Администратор`, `Руководитель` (новые объекты), `МенеджерПоЗакупкам` — единственные роли с чтением всех
  13 источников; `МенеджерПоПродажам` не читает `НалоговаяНакладная` и `СертификатНаОплату` — отчёт не получает.
- Сценарии уровня 3 `ДеньгиИСтатусыЗаказов` и `ДеньгиИСтатусыЗаказовНалоговые`; версия 2.0.16.130; «Что нового»
  ru/fr/en/es.

- Вложенная группировка варианта СКД без `xsi:type="dcsset:StructureItemGroup"` — загрузка конфигурации падает голым
  `std::exception`; найдено делением схемы. Правило tiny1C `tmpl-009`.
- Второй метод с тем же именем в модуле тестов — lint молчит, тонкий клиент виснет на окне ошибки; теперь перед
  тестами документов — `CheckConfig`.
- Ордерный склад в тесте — только при включённой опции «Ордерные склады».
