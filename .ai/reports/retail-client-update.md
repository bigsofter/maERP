# Отчёт: retail-client-update — сборка 2.0.17.20 (переход базы старой ветки Commerce на maERP)

Дата: 2026-11-12. План — `docs/plans/retail-client-update.md` (решение владельца: волна 7 раньше сборок обмена).

## Что сделано

- **Комплект переноса** `tools/migration/`: выгрузка «до» на старой конфигурации (условия «ничего не теряется»,
  отпечаток базы, значения реквизитов с другим uuid, наборы `Убытки`, реквизиты обмена, роли, итоги сверки), загрузка
  «после» (обработка `ЗагрузкаПереносаСтаройРедакции`), сквозной скрипт `client-update.sh` (копия → выгрузка →
  удаление расширения → тип кода трёх справочников → CF maERP → обработчики → загрузка и сверка → граница
  последовательности → `.dt`), генератор внешних обработок.
- **Тип кода** `Бренды`, `ВидыЦен`, `TypesDePayment` (у старой ветки строковый, у maERP числовой): прямая смена не
  проходит реструктуризацию ни в одну сторону; путь — строковый вариант CF → коды цифрами → числовой вариант без
  автообновления предопределённых → CF maERP (найдено опытами на копиях, у справочников с предопределёнными смена
  типа кода проходит только с `PredefinedDataUpdate = DontAutoUpdate`). maERP не меняется.
- **Защита перенесённой истории**: регистр `ПеренесенныеДокументы`, подписки на ПКО, РКО, `КорректировкаРегистров`,
  `СписаниеТоваров` и набор `Убытки`; убытки списаний — в корректировку регистров (maERP их не пишет).
- **Реквизиты с uuid клиента**: `ПеремещениеТоваров.СрокПеремещения`, `СписаниеТоваров.Контрагент`.
- **Файлы** на поступлениях и списаниях безналичных денег (у клиента ~240 файлов); право — с правом изменения документа.
- **Обработчик переноса себестоимости продаж** (2.0.16.121): излишек возвратов и расхождение сверки — предупреждения
  с перечнем (у клиента — 6 излишков, расхождения по возвратам: себестоимость старой ветки).
- **Граница последовательности** после переноса — на момент переноса (иначе регламентное перепроведение пересчитало
  бы историю логикой maERP); сеансы переноса — без регламентных заданий.
- Отчёт «Долги покупателей»: долг без даты отсчёта больше не роняет отчёт (найдено смоком на данных клиента).
- Тесты: 3 сценария `Перенос*` (302 всего).

## Пробный перенос (копия выгрузки клиента 09.11)

Выгрузка: условия выполнены; перенесено — кассовые ордера 72 283, кассы 11, наборы `Убытки` 3 538 (10 списаний →
корректировка), статусы пересчётов 47, контрагенты 11, узлы обмена 9; роли: `РуководительПродаж` → роли без записи
денег (`Руководитель` не назначен — по правам платформы пишет деньги), `PDVПросмотрРеализаций` и роль расширения сняты.
**Сверка «до/после» (товары по складу и номенклатуре/характеристике/серии, деньги, взаиморасчёты, убытки по складу/
операции и организации/статье, продажи, касса) — 0 расхождений.** Отпечаток совпал (кроме видов, которых нет в maERP).

|---|---|

| ТестыДокументов (копия) | 302/302 |
| смок (копия maERP) | 0 ошибок |
| смок (пробная база клиента) | 1-й: печать перемещения — конфликт блокировок от регламентного перепроведения (исправлено границей), «Долги покупателей» — исправлено; финальный прогон скриптом — 427 форм, 28 печатных форм, 71 вариант отчёта, 0 ошибок (подозрение: номер в прайсе установки цен) |
| lint / refcheck | 0 новых |

Отклонено с причиной: строгая сверка себестоимости для собственных баз (версия 2.0.16.121 пройдена всеми базами до
2.0.16.150); мягкая защита списаний допускает правку строк (убыток списания maERP не считает, исторический убыток —
в неизменяемой корректировке); удаление каталога пробной базы (скрипт удаляет только каталог файловой базы 1С).

## Результат

`build/dist/flycdi-maERP-2.0.17.20-20261112.dt` — финальный прогон скриптом: сверка 0 расхождений, граница
последовательности на момент переноса, файл выгрузки с паролями удалён. Прежний `...-trial-...dt` (до исправления
границы) не использовать.
