## 1. Исследование — что найдено

- **ВыпускПродукции.** Шапка: `Основание` (ЗаказПокупателя или РеализацияТоваровУслуг), одиночная продукция в шапке
  (`Номенклатура`, `Характеристика`, `Серия`, `Упаковка`, `КоличествоУпаковок`, `Количество`, `ЦенаРозничная`),
  `МестоХранения` (материалы), `МестоХраненияОприходование` (продукция) — обязательны. `ТЧГотоваяПродукция` (КодСтроки,
  Номенклатура, Характеристика, Упаковка, Серия, КоличествоУпаковок, Количество), `ТЧТовары` — материалы (Цена,
  Себестоимость). `СинхронизироватьГотовуюПродукцию` (объект): при ≤1 строке и заполненной шапке строка перестраивается
  из шапки, при >1 шапка повторяет первую строку. `Документы.ВыпускПродукции.ЗаполнитьМатериалыПоТехкартам(Выпуск,
  НесколькоСтрокГП)` — материалы по техкартам на дату документа (E10). Проведение списывает материалы без разрешения
  недостачи (отказ с сообщением), при одной строке пишет `ЦеныНоменклатуры` из `ЦенаРозничная`, пересчитывает стадии.
  **Автовыпуск** — `Основание` = реализация (`Производство.ЭтоАвтовыпуск`), правка его запрещена
  (`ПроверитьПравкуАвтовыпуска`). У выпуска **нет `basedOn` и нет заполнения по заказу**.
- **РеализацияТоваровУслуг.** Шапка: Контрагент, Договор, Менеджер, МестоХранения, Организация, Основание,
  ХозяйственнаяОперация, ЦенаВключаетНДС, ВидЦен. `ОбработкаЗаполнения` по заказу: шапка из заказа, дата — текущая,
  `ТЧТовары.Загрузить` **всех строк заказа с полным количеством**. Проведение: `Производство.ОбеспечитьАвтовыпуск` (E9) —
  при нехватке материалов автовыпуска реализация **не проводится** (сообщения `ТекстНехваткаМатериалов` и др.), отказ
  нигде не хранится; затем списание без недостачи, взаиморасчёты, продажи, стадии. Автовыпуск реализации — выпуск с
  `Основание = &Реализация`. Клиентские проверки формы, которых нет в объекте: запрет отгрузки клиенту
  (`РаботаСДокументамиКлиент.КлиентуЗапрещеноОтгружать`), соответствие серий, авансы больше суммы, `ВидЦен` шапки из
  реквизита формы.
- **Выполнение заказа.** `ПроизводственныеЗаказы.ДанныеРасчёта(Заказ, Неопределено).Строки` — по продукции и
  характеристике: Заказано, КВыпуску (строки с материалами), Выпущено (ручные выпуски по заказу и автовыпуски его
  реализаций), Отгружено. Функция служебная — наружу выводится экспортной обёрткой (§5).
- **Суммы у оператора** — только интерфейсное скрытие: цены и суммы реализации не уходят на клиент без сумм
  (`СкрытьСуммыСтроки`); цена клиента без сумм не принимается; `Цена`, `Себестоимость`, `ЦенаРозничная` выпуска в рабочем
  месте не показываются и не вводятся.
- **Отказ проведения в сценарии**: исключение записи внутри транзакции сценария портит её — ветка «черновик после отказа»
  в сценарии не гоняется, отказ проверяется последним шагом (как `ПроверитьОтказПоМатериаламАвтовыпуска`).

## 3. Движок строк документов

Обобщение E12.2 без копирования: `Вид` строки получает ещё два значения — `ВыпускПродукции`, `РеализацияТоваровУслуг`.
Общие части (`ЗаписатьСтрокуЗакупки` → переименование в `ЗаписатьСтрокуДокумента` с сохранением старых имён не нужно —
вызывающих вне обработки нет; `УдалитьСтроки…`, `ИзменитьСтатусДокументов…`, блокировка, версия, `СтрокаВБазеНеИзменилась`,
запись с черновиком после отказа нового документа, `ЗаписатьДокументСтатусом`) принимают вид; различия вынесены в
функции по виду: новый документ, строки для таблиц, запреты значений, запреты документа, применение строки, табличная
часть строк (`ТЧГотоваяПродукция` у выпуска, `ТЧТовары` у остальных), документ пуст.

Имена: область `Закупки` переименовывается в `СтрокиДокументов`; тексты и имена функций со словом «Закупки» — там, где
они общие, — нейтральные. Экспортные API: `СтрокиДокументовЗаказа(Заказ)` (все четыре таблицы; `СтрокиЗакупок` остаётся
как часть), `НовыеДанныеСтрокиДокумента()` (поля закупок + общие), `ТекстЗапретаСтрокиДокумента`, `ЗаписатьСтрокуДокумента`,
`УдалитьСтрокиДокументов`, `ИзменитьСтатусДокументов(Документы, Действие, Заказ)`, `ДокументыДляВыбора`. Сценарий
`АРМЗакупки` переводится на новые имена.

## 4. «Выпуск»: запись строки

- **Запреты без записи**: заказ на производство в работе (решение 7); продукция — одна из строк товаров заказа, у
  которой есть материалы (`КВыпуску > 0`); количество > 0; выбранный документ — ручной выпуск этого заказа (основание —
  заказ, не автовыпуск), не помечен, новая строка — только в сегодняшний; характеристика — этой продукции.
- **Запреты документа** после блокировки: автовыпуск (правка — через реализацию), серия у строки продукции, помечен.
- **Новый документ**: `СоздатьДокумент` + `Заполнить(Неопределено)` (реквизиты по умолчанию и склады пользователя),
  `Основание = Заказ`, `Организация` заказа, `Дата` — текущая, `МестоХраненияОприходование` — из заполнения, пустое —
  `МестоХранения`.
- **Строка**: `ТЧГотоваяПродукция` (новая — КодСтроки максимум + 1), продукция, характеристика, упаковка (пустая — единица),
  количество упаковок, `РассчитатьКоличество`; **синхронизация шапки** — одна строка: шапка = строка; несколько: шапка =
  первая строка (как форма и `СинхронизироватьГотовуюПродукцию`); `ЦенаРозничная` шапки не трогается.
- **Материалы**: `ЗаполнитьМатериалыПоТехкартам(ДокОбъект, ТЧГотоваяПродукция.Количество() > 1)` — перезаполнение всех
  материалов по картам на дату документа при любой правке продукции или количества. Нет карты — материалы пусты,
  проверка заполнения отказывает «Не записано» с причиной.
- **Запись**: новый и проведённый — с проведением; нехватка материалов у нового — черновик свежим объектом с причиной;
  у существующего — «Не записано», документ не меняется; черновик — записью.
- **Удаление**: строка из `ТЧГотоваяПродукция`, синхронизация шапки, материалы по картам; последняя строка — пометка
  документа свежим объектом.

## 5. «Отгрузки»: запись строки

- **Выполнение заказа наружу**: `ПроизводственныеЗаказы.СтрокиВыполненияЗаказа(Заказ) Экспорт` — `ДанныеРасчёта(...).Строки`
  (Номенклатура, Характеристика, Заказано, КВыпуску, Выпущено, Отгружено); пустая таблица у заказа-продажи. Рабочее место
  отдаёт её форме в `ДанныеТекущегоЗаказа` для количеств по умолчанию: выпуск — `КВыпуску − Выпущено`, отгрузка —
  `Заказано − Отгружено`.
- **Запреты без записи**: заказ на производство в работе; запрет отгрузки клиенту (`ТекстЗапретаОтгрузки(Контрагент, Дата)`
  — серверный повтор клиентской проверки формы); продукция — строка товаров заказа (по номенклатуре и характеристике);
  документ — реализация этого заказа, не помечена, сегодняшняя для новой строки.
- **Запреты документа**: строки с сериями (`Серия`, `УказаноНесколькоСерий`), документ с `ТЧУслуги`,
  `ТЧДополнительныеРасходы`, `ТЧЗачётАвансов` — только в форме документа.
- **Новый документ**: `СоздатьДокумент` + `Заполнить(Заказ)` (шапка из заказа как при вводе на основании) и
  `ТЧТовары.Очистить()`, `ТЧСерии.Очистить()`; `Дата` — текущая; `ВидЦен` — вид цены первой строки заказа, если пуст.
- **Строка**: из строки заказа с той же продукцией и характеристикой — упаковка (если в строке не выбрана), `ВидЦены`,
  `Цена` (за упаковку строки: цена заказа за базовую единицу × коэффициент), `СтавкаНДС`, `ПроцентСкидки`; количество
  из строки формы; `РассчитатьСтроку`. Цену пользователь с суммами может изменить; без сумм — только цена заказа.
  КодСтроки — максимум + 1.
- **Запись**: как в §4. Отказ автовыпуска — отказ проведения реализации: новый документ — черновик с причиной из
  сообщений (`ТекстНехваткаМатериалов`), существующий — «Не записано». Перепроведение реализации пересчитывает автовыпуск
  механизмом E9.
- **Колонка «Автовыпуск»**: представление непомеченного выпуска с основанием этой реализации («№ от дд.ММ, проведён /
  черновик»), одинаковое у всех строк документа.

## 6. «Выпуск по заказу» — кнопка ввода на основании

- `Documents/ВыпускПродукции/ВыпускПродукции.mdo`: `basedOn` — `Document.ЗаказПокупателя` (правка метаданных, без
  реструктуризации).
- `ОбработкаЗаполнения` выпуска: `ДокументСсылка.ЗаказПокупателя` заказа на производство → `Основание`, `Организация`,
  `ТЧГотоваяПродукция` — строки `СтрокиВыполненияЗаказа` с `КВыпуску − Выпущено > 0` (упаковка — единица номенклатуры),
  шапка по первой строке, материалы по техкартам; заказ-продажа или нечего выпускать — сообщение, документ без строк.
  Вызов через `Заполнить` из рабочего места не используется (строчный ввод — §4).
- Форма выпуска открывается с `Основание` — платформа вызывает заполнение; режим `НесколькоСтрокГП` форма берёт по
  числу строк (`ПриСозданииНаСервере`).
- Рабочее место: команды таблиц `ЗаказыСоздатьВыпуск`, `ПродукцияСоздатьВыпуск` (панели отмеченных строк),
  `ДокументыНаОсновании` + `МожноВыпуск`.

## 7. «Статус» и удаление

Общий `ИзменитьСтатусДокументов(Документы, Действие, Заказ)`: документ этого заказа (у автовыпуска — через реализацию;
«Статус» автовыпуска — отказ «меняется через реализацию»); реализация «В черновик»/«Отменить» — механизм реализации сам
распроводит и помечает её автовыпуск.

## 8. Сценарий уровня 3 `АРМВыпускОтгрузка`

Заказ на производство в работе на продукцию контекста (карта есть) 10 шт.; материалы на складе по `ДокументЗакупки`;
константа автовыпуска включена в транзакции сценария.
1. Строка выпуска 4 шт. → новый проведённый выпуск: основание — заказ, шапка = строка, материалы по карте
   (количество = расход × 4), «Выпущено» 4 в `СтрокиВыполненияЗаказа`.
2. Правка количества до 5 → перепроведение, материалы пересчитаны; устаревшая версия — отказ с перечитыванием.
3. Запреты: продукция не из заказа, строка во вчерашний выпуск, автовыпуск как документ строки.
4. Строка отгрузки 3 шт. → проведённая реализация: основание — заказ, цена строки заказа, контрагент и договор заказа,
   «Отгружено» 3; автовыпуска нет (выпущено 5 ≥ 3).
5. Вторая строка отгрузки 4 шт. в ту же реализацию → перепроведение, автовыпуск 2 шт. создан (колонка «Автовыпуск»
   заполнена), выпуск-автовыпуск в строках «Выпуска» только для чтения.
6. «Статус» «В черновик» реализации — автовыпуск распроведён механизмом; «Провести» — снова проведён.
7. Удаление строк выпуска до пустого — пометка документа.
8. Заполнение выпуска на основании заказа (`Заполнить(Заказ)`): строки к выпуску с остатком, материалы по карте.
9. **Последним шагом**: строка отгрузки сверх материалов автовыпуска → `Не Успех` (черновик в транзакции сценария не
   пишется, §1).

## 10. Риски

- **Материалы ручного выпуска по техкарте, автовыпуска — по составу заказа** (`Производство.ПродукцияЗаказа`): состав
  заказа мог быть отредактирован — ручной выпуск спишет по карте. Как в форме выпуска (E10); TECHDEBT.
- **Ручной выпуск не пишет «ИзОстатка» и не берёт партии под заказ** — дефицит на «Материалах» после ручного выпуска не
  уменьшается (прежнее поведение формы).
- **Выпуск сверх заказа** не ограничен: автовыпуск уменьшится сам (`Заказано − ВыпущеноВсего`).
- **Отказ автовыпуска** не хранится — статус строки после перечитывания показывает «Черновик», причина — в сообщении
  (как E12.2).
- **Размер модуля менеджера** (~4400 строк): обобщение движка вместо копии; если модуль вырастет выше ~5500 строк —
  вынос движка строк в общий модуль `АРМПроизводствоСтроки` в E12.3b (решение по итогам ревью).
- **Правка метаданных выпуска** (`basedOn`) — Refresh и проверка EDT у владельца; реструктуризации нет.

## 11. Редакция 2 — изменения по ревью плана

Критик (`01-architecture-critic.md`): reject, 7×P1, 9×P2, 3×P3. astra (`02-plan-review-astra.md`): reject, 4×P1. Решения:

| Находка | Источник | Решение |
|---|---|---|
| `ЦенаSKU` реализации перезаписывает цену при `РассчитатьСтроку` | critic P1-1, astra P1 | из строки заказа копируются `ЦенаSKU`, `Цена`, `ВидЦены`, `СтавкаНДС`, `ПроцентСкидки`, `СкидкаНаЦену`, `НоменклатураСтрока`; пересчёт после установки цены — `РассчитатьСтроку(Стр, ЦенаВключаетНДС, "Цена")`; сценарий сверяет сумму строки |
| `ЦенаРозничная` шапки выпуска уходит в цены другой продукции | critic P1-2, astra P1 | при смене продукции шапки (ключ номенклатура + характеристика) или переходе к одной строке `ЦенаРозничная` обнуляется |
| Нет техкарты — материалы прежней продукции остаются; частично покрытый мультивыпуск | critic P1-3, astra P1 | до правки: у каждой строки продукции должна быть карта на дату (`ТехнологическиеКарты.ТекущиеТехкарты`), иначе отказ с именем продукции; материалы считаются во временной таблице и заменяют `ТЧТовары` целиком |
| Коэффициент упаковки продукции не доходит до расчёта материалов | astra P1 | в `ТехнологическиеКарты.ЗаполнитьМатериалыПоТехкартам` передаётся количество в базовых единицах (колонка `КоличествоУпаковок` таблицы продукции = `Количество`); фасад `Документы.ВыпускПродукции.ЗаполнитьМатериалыПоТехкартам` рабочее место не вызывает (коэффициент в конфигурации сейчас всегда 1 — тест с упаковкой невозможен, TECHDEBT) |
| Перезаполнение по картам стирает услуги, партии, серии, ручные количества материалов | critic P1-4 | запрет правки выпуска в рабочем месте, если в `ТЧТовары` есть услуга, `Партия` или `Серия`, или материалы отличаются от расчёта по картам для текущей продукции (ключ номенклатура + характеристика + количество) — «правка в форме документа» |
| Автовыпуск не видит ручной выпуск, проведённый после реализации | critic P1-5 | новая строка отгрузки, правка строки и «Провести» реализации — только если после неё (по моменту времени) нет проведённого ручного выпуска этого заказа; иначе отказ «после отгрузки по заказу проведён выпуск: создайте новую отгрузку или правьте в форме»; выбор «сегодняшних» реализаций исключает такие; сценарий разводит даты документов явно |
| Реализация с налоговой накладной или кассовой сменой | critic P1-6 | только в форме документа (запрет документа и «Статуса») |
| Режим НДС цены заказа в реализации | critic P1-7 | цена приводится к режиму НДС реализации по `ПроцентСтавкиНДС` (как `ЦенаСтрокиЗакупки`) |
| Серии выпуска (`Серия` шапки, `ТЧСерии`), партии реализации | critic P2 | запрет документа; при смене продукции реализации `Партия` очищается |
| `КодСтроки` строки реализации | critic P2 | код строки заказа, если он свободен в документе, иначе максимум + 1 |
| Несколько строк заказа с одной продукцией | critic P2 | берётся первая по `НомерСтроки`; правка количества цену не сбрасывает |
| Запрет отгрузки в «Статусе» | critic P2 | «Провести» реализации проверяет `ТекстЗапретаОтгрузки` |
| Склад реализации | critic P2 | склад оприходования последнего проведённого ручного выпуска заказа, иначе склад по умолчанию |
| Уменьшение или распроведение выпуска с отгруженной продукцией | critic P2 | TECHDEBT (как в форме) |
| Продукция по техкарте без материалов заказа | critic P2 | к выпуску допускается строка заказа с материалами или с картой на дату; расхождение со стадией E8 (КВыпуску только по материалам) — TECHDEBT |
| Выпуск сверх заказа | critic P2 | предупреждение в сообщении, запись не запрещается; текст риска §10 исправлен |
| `ДанныеРасчёта` тяжёлый | critic P3 | количества по умолчанию — отдельным серверным вызовом при выборе продукции (лёгкий запрос по заказу, выпускам и реализациям), не в `ДанныеТекущегоЗаказа`; экспорт из `ПроизводственныеЗаказы` не делается |
| Заполнение выпуска по заказу — только заказ в работе | critic P3 | проверка проведён и не помечен |
| Размер модуля | critic P3 | остаётся в модуле менеджера (вынос движка — большой регресс закупок E12.2); TECHDEBT |

§10 «Выпуск сверх заказа не ограничен: автовыпуск уменьшится сам» — **неверно**: автовыпуск учитывает только выпуски раньше
реализации; ограничение — правило P1-5 выше.
