# План: E5 — материалы в заказе клиента на производство (maERP 2.0.15.13)

Бриф: `docs/plans/production-2mzl-e5-materialy.md`. Основание: `docs/plans/production-2mzl.md`, E5.
Конфигурация 1С 8.5.1, EDT-проект `src/cf`. У `ЗаказПокупателя` `posting = Deny`, E5 проведения и
движений не добавляет.

Решения владельца 2026-09-13:
1. Заказ на производство по КП заполняет материалы **сразу**.
2. Смена вида на «не производство» — материалы **очищаются при записи** с предупреждением.
3. Разный состав одной продукции в двух строках — **запрещён уже в E5** (отказ записи). Бриф
   предлагал отложить до E6; решение владельца другое.

Редакция 2: учтены находки `architecture-critic` (`.ai/reviews/production-2mzl-e5/01b-architecture-critic.md`).
Редакция 3: учтены находки ревью плана (OpenCode Go, Kimi K3; Codex в лимите) —
`.ai/reviews/production-2mzl-e5/02b-plan-review-decisions.md`.
Отклонения от брифа отмечены **[отклонение]**.

## 0. Исследование (итог)

- У drissotex табличной части материалов в заказе нет (`build/drissotex/Documents/ЗаказПокупателя.xml`,
  одна ТЧ `ТЧТовары`) — новые uuid.
- Права: у 18 из 19 ролей `setForAttributesByDefault = true`; у `Клиент` — false (права на поля
  перечислены явно; права на реквизиты — только интерактивные просмотр/редактирование, серверный код
  объекта они не ограничивают). Роль работает с заказами-продажами, новые поля ей не выдаются.
  Чтение `InformationRegister.СоставТехКарты` и `Document.ТехнологическаяКарта` есть у всех ролей с
  правом на заказ — привилегированный режим не нужен, права ролей не меняются.
- Коды строк товаров: форма ставит `КодСтроки` в `ТЧТоварыПриНачалеРедактирования` (при копировании
  — новый), подбор (`СтрокаДляПодбора`) — тоже; **штрихкод код не ставит (0)**, заполнение по КП и
  по реализации **копирует код основания** (`ЗаполнитьЗначенияСвойств`) — возможны нули и повторы.
- `ТЧТовары.КодСтроки` заказа читает перезаполнение цен реализации по заказу-основанию
  (`РеализацияТоваровУслуг/Forms/ФормаДокумента/Module.bsl:399`) — переномеровка кодов у записанных
  заказов меняет это сопоставление; см. п. 3.2, нормализация сужена.
- Фасад: `ТехнологическиеКарты.СоставТехкарт(Продукция, Дата)` отдаёт Продукция, Регистратор,
  материал, характеристику, упаковку и количество на единицу; упаковку при выключенной опции
  «Использовать упаковку» **не** очищает (это делает только `ЗаполнитьМатериалыПоТехкартам`) —
  очистку делаем у себя. Фасад меняется в одном месте: экспортная `КлючСоставаСтрок` (п. 3.2).
- Единицы в документах: `КоличествоУпаковок` — в `Упаковка`, `Количество` — базовая единица,
  пересчёт `РаботаСДокументамиКлиентСервер.РассчитатьКоличество` (коэффициент
  `ОбщегоНазначенияВызовСервера.РассчитатьКоэффициентЕдиницы` сейчас всегда 1 — тело закомментировано).
  Выпуск кладёт в материалы `КоличествоЗаЕдиницу` и `КоличествоУпаковок` = карта × `КоличествоУпаковок`
  продукции (упаковка продукции выпуска по умолчанию = базовая единица).
- В форме у `Объект.ТЧТовары` есть дополнительные колонки (`additionalColumns`: Неотгружено, остатки,
  последние цены) — серверная команда формы **не** гоняет объект через
  `РеквизитФормыВЗначение`/`ЗначениеВРеквизитФормы` (сбросило бы колонки), а работает с данными формы.
- `ОбщегоНазначенияКлиентСервер.СообщитьПользователю` **безусловно** ставит переданный `Отказ = Истина`
  — информационные сообщения вызываются без этого параметра.
- Автоподбор номенклатуры в строке (`ТЧТоварыНоменклатураОбработкаВыбора` →
  `ОбрабокаВыбораПриАвтоподбореНоменклатуры`) присваивает номенклатуру кодом со
  `СтандартнаяОбработка = Ложь` — `ПриИзменении` не срабатывает.

**[отклонение]** Бриф: колонки `КоличествоНаЕдиницу` и `Количество`. Принято `КоличествоЗаЕдиницу` —
имя колонки выпуска (E9 переносит строки `ЗаполнитьЗначенияСвойств`), и пара `КоличествоУпаковок` /
`Количество` по соглашению всех документов: иначе E7 прочитал бы количество в упаковках как базовое.
Основа продукции — `ТЧТовары.Количество` (базовые единицы), как в брифе. **Обязательство для E9**
(записывается в `production-2mzl.md`): доля автовыпуска считается от базового количества продукции.

`fillChecking` у материала: у документа без проведения проверка заполнения идёт при интерактивной
записи; пустая строка материала — ошибка пользователя, а не молча сохраняемый мусор. У продаж ТЧ
пуста — проверка не срабатывает.

1.2. `ТЧТовары.Attribute.Техкарта` — `DocumentRef.ТехнологическаяКарта`, синоним ru «Техкарта»,

1.3. Функциональные опции (content): `Производство` — `…TabularSection.ТЧМатериалы` и

## 2. Модуль менеджера — общая логика

**[отклонение]** Бриф: «серверной процедурой объекта, общей с командой формы». Общая часть — экспортные
процедуры **модуля менеджера** над коллекциями строк (`ТабличнаяЧасть` объекта или
`ДанныеФормыКоллекция`), чтобы команда формы не сбрасывала дополнительные колонки. Область
`#Если Сервер Или ТолстыйКлиентОбычноеПриложение Или ВнешнееСоединение Тогда` (в модуле есть клиентский
обработчик представления). Используется только общее подмножество методов коллекций: обход, индекс,
`Количество`, `Добавить`, `Удалить(Строка)` (обход с конца), `НайтиСтроки(Структура)`, `Индекс`.
Без `Итог`, `Найти`, `Выгрузить`, `Загрузить`, `ПолучитьИдентификатор`.

2.1. `ОбеспечитьКодыСтрокТоваров(ТЧТовары, Строки = Неопределено)` — строкам (всем или переданным) с
`КодСтроки = 0` или с кодом, повторяющим код более ранней строки, ставит `Макс + 1`. Возвращает Булево.

2.2. `ЗаполнитьМатериалыПоТехкартам(ТЧТовары, ТЧМатериалы, Дата, Строки = Неопределено,
СообщатьТолькоПроизводимые = Ложь, КлючДанных = Неопределено)`:
- `Строки` — **массив строк коллекции товаров**, а не кодов: код строки может смениться при
  нормализации. `Неопределено` — все строки с заполненной номенклатурой;
- `ОбеспечитьКодыСтрокТоваров(ТЧТовары, Строки)`;
- продукция строк — массив различных; `ТехнологическиеКарты.СоставТехкарт(Продукция, Дата)` одним
  вызовом; `ИспользоватьУпаковку` читается один раз;
- по каждой строке: удалить материалы с её `КодСтрокиПродукции`; строки состава по продукции
  (`НайтиСтроки`); нет — `Техкарта` пустая, строка в «без карты»; есть — добавить материалы:
  `КодСтроки` = следующий в ТЧ материалов, `КодСтрокиПродукции`, материал, характеристика, упаковка
  (только при опции, иначе пустая), `КоличествоЗаЕдиницу` = количество карты, затем
  `ПересчитатьСтрокуМатериала`; `Техкарта` = регистратор;
- сообщения о строках без карты: `СообщитьПользователю(Текст, КлючДанных, Поле)` **без `Отказ`**;
  `Поле = "ТЧТовары[i].Номенклатура"` и `КлючДанных` = объект либо `ПутьКДанным = "Объект"` в форме; текст на ru/fr/en/es. При `СообщатьТолькоПроизводимые` (все строки, КП) — только позиции со
  `СпособПополнения` в («Производство», «Оба») (один запрос по номенклатуре строк без карты);
- возвращает `Структура`: `Заполнено` (Число), `БезКарты` (Массив номенклатуры).

2.3. `ПересчитатьСтрокуМатериала(СтрокаМатериала, КоличествоПродукции)` —
`КоличествоУпаковок = КоличествоЗаЕдиницу × КоличествоПродукции`, затем
`РаботаСДокументамиКлиентСервер.РассчитатьКоличество(СтрокаМатериала)`. На клиенте формы вызывается
тот же клиент-серверный расчёт (п. 4.4), формула одна.

## 3. Модуль объекта

3.1. `ЗаполнитьПоКоммерческомуПредложению`: после `ВидОперации = Производство` —
`Документы.ЗаказПокупателя.ЗаполнитьМатериалыПоТехкартам(ТЧТовары, ТЧМатериалы, Дата, , Истина,
ЭтотОбъект)`. `Дата` нового документа пуста → фасад берёт дату сеанса. Нормализация кодов здесь
безопасна: заказ новый, реализаций по нему нет. При выключенной опции «Производство» вид «Продажа»
(E4), заполнения нет.

3.2. `ПередЗаписью` — блок E5 после выхода по `ОбменДанными.Загрузка`, страховки вида операции и
`МожноРедактироватьДокумент`; **если `Отказ` уже установлен — пропускается**:
- **вид ≠ Производство** (`<>`, инвариант E4): если `ТЧМатериалы` не пуста или хоть одна `Техкарта`
  заполнена — очистить ТЧ и колонку, сообщение «Материалы очищены: заказ не на производство» без
  `Отказ` (решение 2). Продажи без материалов — ничего, поведение прежнее;
- **вид = Производство** — `СогласоватьМатериалы(Отказ)`:
  0. материалов нет и ни одна `Техкарта` не заполнена — выход (коды не трогаются);
  1. строки товаров, у которых `Техкарта` заполнена, а её `Номенклатура` ≠ номенклатуре строки (один
     запрос `ВЫБРАТЬ Карты.Ссылка КАК Ссылка, Карты.Номенклатура КАК Номенклатура ИЗ
     Документ.ТехнологическаяКарта КАК Карты ГДЕ Карты.Ссылка В (&Техкарты)`, псевдоним не совпадает с
     полями ТЧ, query-003) — очистить `Техкарта` и материалы строки;
  2. коды: **повторяющийся** код товаров, на который ссылаются материалы, остаётся у первой строки,
     последующие строки с этим кодом получают новый; нулевые коды строк без материалов не трогаются
     (сопоставление реализации по заказу не меняется);
  3. удалить материалы с `КодСтрокиПродукции`, которого нет среди кодов товаров (в т.ч. 0);
  4. `ПересчитатьСтрокуМатериала` у всех материалов по количеству своей строки товаров (подбор,
     штрихкод и ECommerce-форма меняют количество без обработчиков формы);
  5. **решение 3**: строки товаров с одинаковой `Номенклатура` и **непустыми**
     материалами сравниваются по ключу состава `ТехнологическиеКарты.КлючСоставаСтрок(Материалы,
     "КоличествоЗаЕдиницу")` — **сравнивается количество на единицу, а не итоговое** (строки одной
     продукции с разным количеством законны). **Фасад**: новая экспортная `КлючСоставаСтрок` (обёртка служебной `КлючСостава`, получившей
     необязательный параметр `ИмяПоляКоличества = "Количество"`) с описанием; прежние вызовы не
     меняются; E6–E9 получат тот же ключ. Отдельная строка в отчёте владельцу. Продукция —
     **номенклатура без характеристики**: карта и версии ведутся по номенклатуре, характеристика
     продукции на состав не влияет. Разные — `Отказ = Истина`, сообщение с номерами строк и продукцией.
     Строка без материалов не сравнивается: это «ещё не заполнено», иначе вторую строку той же продукции
     нельзя было бы записать черновиком.

## 4. Форма документа (`ФормаДокумента`)

4.1. **Элементы** (XML копируется с работающих элементов этой же формы целиком: `visible`, `enabled`,
`userVisible`, `extendedTooltip`, `contextMenu`; id — после максимума 586 в пространстве элементов):
- на странице `СтраницаТоварыИУслуги` после `ТЧТовары` — группа `ГруппаМатериалы` (UsualGroup,
  Vertical, `representation None`, `showTitle false`), в ней:
  - тумблер `РежимМатериалов` (RadioButtonField/Tumbler, XML — копия `ФильтрОтгрузки` списка
    заказов), заголовок «Материалы» слева, значения 0 «По строке товаров» / 1 «Все материалы» на
    четырёх языках (forms-010), обработчик `РежимМатериаловПриИзменении`;
  - таблица `ТЧМатериалы` (`Объект.ТЧМатериалы`, XML по образцу `ТЧТовары`: список без иерархии,
    `heightInTableRows` 5, `verticalStretch true`, `rowFilter` Undefined), колонки
    `ТЧМатериалыНомерСтроки`, `…Номенклатура`, `…Характеристика`, `…Упаковка`,
    `…КоличествоЗаЕдиницу` (редактируемая), `…КоличествоУпаковок` и `…Количество` (**обе только
    просмотр**: вычисляются, `ПередЗаписью` их пересчитывает),
    `…Комментарий`, `…КодСтрокиПродукции` (`userVisible false`, только просмотр). Заголовки —
    синонимы реквизитов;
  - кнопки в командной панели таблицы `ТЧМатериалыЗаполнитьПоТехкарте` и
    `ТЧМатериалыЗаполнитьВсеПоТехкартам` (образец — кнопка `ТЧТоварыЗаполнитьТехкарту` выпуска);
- колонка `ТЧТоварыТехкарта` в `ТЧТовары` (LabelField, `userVisible false`).

4.2. **Реквизиты формы** (пространство реквизитов, следующие id после 6, forms-001):
`РежимМатериалов` — Number(1); `ЭтоЗаказНаПроизводство` — Boolean. Заголовки на четырёх языках.

4.3. **Команды формы** `ЗаполнитьМатериалыПоТехкарте` («Заполнить по техкарте» / «Remplir selon la
fiche technique» / «Fill from bill of materials» / «Rellenar según ficha técnica») и
`ЗаполнитьВсеМатериалыПоТехкартам` («Заполнить все по техкартам» / «Tout remplir selon les fiches
techniques» / «Fill all from bills of materials» / «Rellenar todo según fichas técnicas»), заголовки и
подсказки на четырёх языках, `modifiesStoredData = true`.

4.4. **Обработчики** (все в `<handlers>` Form.form, forms-004). Все новые клиентские ветки начинаются с
`Если Не ЭтоЗаказНаПроизводство Тогда Возврат` — у продаж поведение формы прежнее.
- `ПриСозданииНаСервере` и `ВидОперацииПриИзмененииНаСервере` → серверная `НастроитьМатериалы()`:
  `ЭтоЗаказНаПроизводство = ПолучитьФункциональнуюОпцию("Производство") И Объект.ВидОперации =
  Производство` (bsl-009 — только на сервере); видимость `ГруппаМатериалы` и `ТЧТоварыТехкарта` — через
  `Элементы.Найти` (страховка на выключенную опцию). При смене на «не производство» с материалами —
  сообщение «материалы будут очищены при записи».
- `ПрименитьОтборМатериалов()` (клиент): режим 0 — `Элементы.ТЧМатериалы.ОтборСтрок = Новый
  ФиксированнаяСтруктура("КодСтрокиПродукции", Код)`, нет текущей строки товаров — код -1; режим 1 —
  `Неопределено`. Вызывается из: `ПриОткрытии`, `ВидОперацииПриИзменении` (после серверного вызова),
  `ТЧТоварыПриАктивизацииСтроки` (новое OnActivateRow), `РежимМатериаловПриИзменении`, конца
  `ТЧТоварыПриНачалеРедактирования`, `ТЧМатериалыПередНачаломДобавления` (после присвоения кода),
  `ПослеЗаписи` (новое AfterWrite: сервер мог переномеровать коды), после команд заполнения.
- `ТЧТоварыПриНачалеРедактирования` (новая строка): до присвоения нового кода запомнить код текущих
  данных (при копировании — код исходной строки); после присвоения — удалить материалы с новым кодом
  (остатки отменённой вставки) и при копировании скопировать материалы исходной строки с новым
  `КодСтрокиПродукции` и новыми `КодСтроки`. `Техкарта` копируется платформой.
- `ТЧТоварыПриОкончанииРедактирования` (новое OnEditEnd): `НоваяСтрока И ОтменаРедактирования` —
  удалить материалы, чьих кодов больше нет в товарах (скопированная строка отменена Esc).
- `ТЧТоварыНоменклатураПриИзменении` и `ТЧТоварыНоменклатураОбработкаВыбора` (если выбранная
  номенклатура отличается от текущей): очистить материалы строки и `Техкарта`.
- `ТЧТоварыКоличествоУпаковокПриИзменении`, `ТЧТоварыУпаковкаПриИзменении`: после существующего
  расчёта — пересчёт материалов строки.
- `ТЧТоварыПослеУдаления` (новое AfterDeleteRow) — удалить материалы с кодами, которых нет в товарах.
- `ОбработкаВыбора` (подбор) и штрихкод в `ОбработкаОповещения` — после добавления пересчёт всех
  материалов.
- `ТЧМатериалыПередНачаломДобавления(Элемент, Отказ, Копирование, …)`: в **обоих** режимах без текущей
  строки товаров — отказ с сообщением «Выберите строку товаров»; нулевой или повторный код текущей
  строки товаров — присвоить новый (`ПолучитьСледующийКодСтроки`).
- `ТЧМатериалыПриНачалеРедактирования`: новая строка (в том числе копия) — `КодСтроки` = следующий в
  материалах, `КодСтрокиПродукции` = код текущей строки товаров: копия материала в режиме «все»
  добавляется к той продукции, на которой стоит пользователь.
- `ТЧМатериалыКоличествоЗаЕдиницуПриИзменении`, `ТЧМатериалыУпаковкаПриИзменении` → пересчёт строки
  материала по количеству строки товаров.
- `ТЧМатериалыНоменклатураПриИзменении` → очистить характеристику и упаковку, пересчитать.
- Команды: `ЗаполнитьМатериалыПоТехкарте` — нет текущей строки товаров → сообщение; иначе серверная
  `ЗаполнитьМатериалыНаСервере(ИдентификаторСтроки)` → `Объект.ТЧТовары.НайтиПоИдентификатору` →
  `Документы.ЗаказПокупателя.ЗаполнитьМатериалыПоТехкартам(Объект.ТЧТовары, Объект.ТЧМатериалы,
  Объект.Дата, Массив из строки)`; `ЗаполнитьВсеМатериалыПоТехкартам` — если `Объект.ТЧМатериалы` не пуста,
  `ПоказатьВопрос` «Перезаполнить материалы всех строк по техкартам? Ручные изменения будут потеряны»
  (четыре языка) с продолжением в обработчике оповещения; затем `Неопределено`,
  `СообщатьТолькоПроизводимые = Истина`. Заполнение одной строки — без вопроса. После вызова — `Модифицированность = Истина`,
  `ПрименитьОтборМатериалов()`.

4.5. `ФормаДокументаECommerce` не меняется: её строки товаров согласует `ПередЗаписью` (п. 3.2).

## 5. Тест уровня 3 `МатериалыЗаказа` (`ТестыДокументов`)

Имя в `ИменаСценариев()`, ветка в `СценарийПоИмени`. Транзакция с откатом; ПРОПУСК при выключенной
опции «Производство». Данные — `Контекст.Продукция` (карта: сырьё, `РасходСырьяНаЕдиницу`, упаковка —
единица), `Контекст.Товар` (без карты, способ «Закупка»).
1. Заказ на производство: строка продукции (N), строка товара, у обеих `КодСтроки = 0` → заполнение
   всех: коды уникальны и ненулевые; один материал — сырьё, `КоличествоЗаЕдиницу` = расход,
   `КоличествоУпаковок` и `Количество` = расход × N, `КодСтрокиПродукции` = код строки продукции,
   `Техкарта` = `ТекущиеТехкарты(…)[Продукция].Версия`; `Упаковка` пуста при выключенной опции
   «Использовать упаковку», иначе = единица; `БезКарты` пуст (товар — закупка).
2. Заполнение текущей строки товара (переданной строкой) — `БезКарты` содержит товар, материалов у
   строки нет; заполнение строки продукции с повторным кодом (две строки с одним кодом) — материалы
   получает именно переданная строка под новым кодом.
3. Количество продукции M, запись → материал = расход × M.
4. Вторая строка той же продукции с **другим количеством** (N и K), заполненная картой, → запись
   проходит, `КоличествоУпаковок` материалов пропорциональны; у одной строки `КоличествоЗаЕдиницу`
   изменено → запись отклонена (исключение), в базе прежний состав; строка той же продукции без
   материалов → запись проходит; та же номенклатура с другой характеристикой и другим составом →
   запись отклонена.
5. Номенклатура строки продукции заменена товаром (Техкарта осталась) → запись: `Техкарта` пуста,
   материалов строки нет.
6. Удаление строки продукции → запись → материалов с её кодом нет.
7. Нулевой код строки товаров без материалов после записи заказа с материалами остаётся нулём.
8. Заказ по КП с продукцией → после `Заполнить` материалы есть, `Техкарта` заполнена; запись.
9. Смена вида на «Продажа» у заказа с материалами → запись: ТЧ материалов и `Техкарта` пусты.
10. Запись в режиме загрузки у заказа «Продажа» с материалами — материалы не тронуты.
11. Продажа без материалов пишется без изменений.

Коэффициент упаковки ≠ 1 проверить нельзя: `РассчитатьКоэффициентЕдиницы` сейчас всегда 1.
Клиентскую логику (копирование и отмена строки, отбор, видимость, автоподбор) уровень 3 не видит — в
отчёте владельцу «что посмотреть глазами».

## 8. Риски и вопросы ревьюеру

- **Отказ записи при разном составе** (решение 3): пути, правящие материалы не формой, появятся в
  E6–E9 — им нужен тот же ключ состава.
- **Округление**: `КоличествоУпаковок` 12.3 — произведение усечётся до трёх знаков.
- **Сообщения при заполнении по КП** выводятся в момент создания формы по основанию.
- **Раскладка**: две растягиваемые таблицы на одной странице — только глазами.
- **ECommerce-форма** (не меняется по брифу): замена номенклатуры строки с ручными материалами без
  `Техкарта` оставляет материалы у новой продукции — серверу нечем это заметить. Запись в
  `docs/TECHDEBT.md`; ECommerce-заказы на производство на практике не заводятся.
- **Смена даты заказа** материалы не перезаполняет; копирование заказа переносит `Техкарта` старой
  версии — сознательно, перезаполнение кнопкой.
