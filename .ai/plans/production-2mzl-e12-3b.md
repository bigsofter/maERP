## 1. Исследование — что найдено

- **ПередачаВПереработку.** `basedOn` — `ЗаказПокупателя`, `ВыпускПродукции`. Шапка: Основание, Контрагент
  (переработчик, в проверке заполнения — признак `Субподрядчик`), МестоХранения, Организация. `ТЧТовары` — сырьё
  (Серия, Партия), `ТЧГотоваяПродукция` — ожидаемая продукция (заполнение по заказу — строки продукции и полуфабрикатов
  заказа). Проведение: расход `ТоварыВНаличии`, приход `ТоварыВПереработке` (блокировки склада и переработчика). В E8 не
  участвует (стадию не меняет), зовёт старое `ОбновитьПроизводственныйСтатусЗаказа` — оно заказы на производство пропускает.
- **ПоступлениеИзПереработки.** `basedOn` — `ПередачаВПереработку`; заполнение: сырьё — остаток `ТоварыВПереработке` по
  передаче, продукция — ожидаемая продукция передачи. Проведение: расход у переработчика, приход продукции на склад,
  долг переработчику за услуги. **В E8 не участвует**: нет `ЗапомнитьЗаказыДокумента`, `ОбновитьСтадииПослеПроведения`,
  `ОбновитьСтадииПриЗаписи`, `ОбработкаУдаленияПроведения`.
- **Стадия E8.** `ТекстЗапросаОтгрузок` — `ВТВыпущено`: ручные выпуски по заказу и автовыпуски его реализаций.
  `ЗаказОснованияДокумента` знает выпуск, реализацию, возврат. Пересчёт идёт только при записи документов контура;
  обработчика пересчёта стадий существующих заказов нет. `ВыполнениеПоПродукции` (E12.3a) использует тот же текст.
- **Автовыпуск E9.** Выпущенное раньше реализации — только `Производство.ВыпущеноИОтгруженоРанее` (выпуски по заказу и
  автовыпуски предшествующих реализаций, по моменту времени). Проведение реализации с автовыпуском блокирует остатки
  номенклатуры автовыпуска на всех складах (`ЗаполнитьБлокировкуОстатковАвтовыпуска`) до расчёта; проведение поступления
  из переработки блокирует `ТоварыВНаличии` по своей продукции — пересекающиеся исключительные блокировки упорядочивают
  их, как ручной выпуск и реализацию.
- **Права.** У `ОператорПроизводства` на оба документа — Read, Insert, Update, Posting, UndoPosting, пометка; на
  `ТоварыВПереработке` — чтение и запись; контрагенты — чтение. Права не меняются.
- **Начальная страница** (`Configuration/HomePageWorkArea.hpwa`): колонка — дашборд `DataProcessor.Дашборд.Form.
  БазовыйДашборд` (видимость `common`), списки лидов и заданий на пересчёт для перечня ролей; оператор производства в
  перечнях отсутствует. Синтаксис видимости — `common` и `<for><role>…</role><value>…</value></for>` (значение по
  умолчанию — ложь).

## 2. Стадия E8: поступление из переработки — выпуск

- `ПоступлениеИзПереработки/ObjectModule.bsl` по обязательству E8: `ЗапомнитьЗаказыДокумента` в `ПередЗаписью` (после
  `МожноРедактироватьДокумент`, при `Не Отказ`), `ОбновитьСтадииПослеПроведения` последней строкой `ОбработкаПроведения`,
  `ОбновитьСтадииПриЗаписи` в `ПриЗаписи`, `ОбработкаУдаленияПроведения` → `ОтменитьПроведениеДокумента` с тем же набором
  блокировок (`ЗаполнитьБлокировкуПроведения` — выносится из проведения). Старый вызов `ОбновитьПроизводственныйСтатусЗаказа`
  остаётся (заказам-продажам).
- `ПроизводственныеЗаказы.ЗаказОснованияДокумента`: ветка поступления из переработки — основание (из объекта или из базы
  до записи): заказ — он; передача — её основание (у передачи тип основания только `ЗаказПокупателя`; заполнение по выпуску
  пишет туда заказ выпуска).
- `ТекстЗапросаОтгрузок`, `ВТВыпущено`: третья ветка — `ТЧГотоваяПродукция` поступлений из переработки с основанием —
  заказ или передача с основанием — заказ; учитывается по правилу `&Документ/&ДокументПроведён`; проведение и пометка
  передачи не учитываются (важны только проведение и пометка поступления). Индексы пакета
  не меняются. Автоматически попадает в `ВыполнениеПоПродукции` (количества рабочего места, «Выпуск по заказу»).
- **Существующие заказы:** обработчик обновления `2.0.15.34` — пересчёт стадий заказов на производство, у которых есть
  проведённые поступления из переработки (через передачи). Для него — экспортная `ПроизводственныеЗаказы.
  ПересчитатьСтадииЗаказов(Заказы)`: блокировка истории в порядке идентификаторов, `ЗаписатьСтадию` без контекста документа
  (запись только при изменении). Порциями по 500 заказов, каждая в своей транзакции.

## 3. Автовыпуск E9

- `Производство.ВыпущеноИОтгруженоРанее`: ветка «выпущено» — `ТЧГотоваяПродукция` проведённых поступлений из переработки
  с основанием — заказ или передача по заказу, момент времени поступления раньше реализации.
- Порядок проведений: пересекающиеся блокировки остатков (§1). Обязательство E9 «автовыпуск видит только выпуски раньше
  реализации» распространяется на поступления из переработки.
- Правило E12.3a «после реализации проведён ручной выпуск» в рабочем месте считает и поступления из переработки по
  передачам заказа, проведённые позже реализации: запрет строки отгрузки, «Провести», выбор реализации, повтор проверки в
  транзакции проведения. Поступление из переработки рабочим местом не пишется — обратное правило к нему не применяется
  (TECHDEBT: форма поступления правило не проверяет, как формы выпуска и реализации).

## 4. Закладка «Переработка»

Нижние закладки: Материалы, Заказы поставщику, Поступления, Выпуск, Отгрузки, **Переработка**, Документы. Генератор
`scripts/formgen/arm/gen6.py` поверх `gen5.py`.

- **Строки** (ТЗ `Переработки`): строки `ТЧТовары` непомеченных передач с основанием — текущий заказ. Колонки: Статус,
  Переработчик, Материал, Характеристика, Количество, Упаковка, Склад (только чтение), Поступления (представление
  непомеченных поступлений по передаче: «№ от дд.ММ, проведено», несколько — через запятую; только чтение), Документ.
  Скрытые: Документ, НомерСтроки, ВерсияДанных, Проведен, Записана, ТолькоПросмотр, ДокументЗаСегодня, ЕстьПоступления.
- **Панель отмеченных строк:** подменю «Статус» и кнопка «Поступление из переработки» — форма поступления на основании
  передачи отмеченной строки (одна передача, проведённая; иначе сообщение). Право — `МожноПоступлениеИзПереработки`
  (Добавление), ввода строк — `МожноВводитьПереработку` (Добавление, Изменение, Проведение передачи).
- **Движок строк**: вид `ВидПередача()` = «ПередачаВПереработку» во всех точках обобщения E12.3a (`ВидыСтрокДокументов`,
  `СтрокиДокументов`, `ТекстЗапретаЗначенийСтрокиДокумента`, `ТекстЗапретаДокументаСтроки`, `ТекстЗапретаДокументаОбъекта`,
  `ТекстЗапретаПравкиСтрокиДокумента`, `НовыйДокументСтроки`, `ПрименитьДанныеСтрокиДокумента`, `ДокументыСтрокиДляВыбора`,
  `ТекстЗапретаУдаленияСтроки`, `ТекстЗапретаСтатусаДокумента`, сверка «без правок»). Поле данных строки — `Материал`, поле
  переработчика — `Поставщик` (одно поле контрагента строки; в форме — колонка «Переработчик»).
- **Запреты без записи:** заказ на производство в работе; переработчик заполнен и помечен `Субподрядчик`; материал и
  количество > 0; характеристика материала; документ — передача этого заказа (основание — заказ), не помечена, того же
  переработчика, новая строка — только в сегодняшнюю.
- **Передача, по партиям которой уже списано** (расход `ТоварыВПереработке` с этой передачей от другого регистратора —
  поступления по ней или по другим передачам переработчика, FIFO): строки не добавляются, не правятся и не удаляются, «В
  черновик» и «Отменить» отклоняются — остаток «Товары в переработке» ушёл бы в минус. Проверка до блокировки и в транзакции
  записи с предблокировкой в порядке проведения передачи (`ТоварыВНаличии` склада, затем `ТоварыВПереработке`
  переработчика). Черновики поступлений не запрещают: их проведение само проверит остаток.
- **Смена основания или переработчика** передачи с таким расходом — отказ в `ПередачаВПереработку.ПередЗаписью` (и в
  форме документа).
- **Запреты документа:** строка с серией или партией — правка в форме документа.
- **Новая передача:** `СоздатьДокумент` + `Заполнить(Заказ)` (основание, организация, реквизиты и склад по умолчанию,
  ожидаемая продукция по заказу), `ТЧТовары` очищается, Контрагент — переработчик строки, Дата — текущая.
- **Строка:** новая — код строки максимум + 1; смена материала — серия и партия очищаются, упаковка — единица, если не
  выбрана; `РассчитатьКоличество`.
- **Запись:** новая и проведённая — с проведением; нехватка сырья у новой — черновик с причиной; у существующей — «Не
  записано»; черновик — записью; удаление последней строки — пометка передачи.
- **Клиент:** вставка строки в начало, переработчик и документ — по ближайшей строке ниже (как у закупок), количество по
  умолчанию — «Потребность» материала на закладке «Материалы»; колонка «Переработчик» с отбором `Субподрядчик = Истина`.

## 6. Сценарий уровня 3 `АРМПереработка` (30-й)

Заказ на производство в работе: продукция P (карта и материал M), контрагент-субподрядчик; M на складе.
1. Запреты: переработчик без признака `Субподрядчик`, строка без количества.
2. Строка переработки M 6 → новая проведённая передача: основание — заказ, контрагент — переработчик, ожидаемая продукция
   по заказу, остаток «в переработке» 6; вторая строка в ту же передачу; правка количества; устаревшая версия — отказ.
3. Поступление из переработки на основании передачи (`Заполнить` + проведение в сценарии), P 4: `ВыполнениеПоПродукции`
   — «Выпущено» 4; стадия заказа пересчитана (доля выпуска > 0).
4. Передача с поступлением: правка строки, удаление, «В черновик» — отказ.
5. Реализация P 3 строкой отгрузки: автовыпуска нет (выпущено 4 поступлением).
6. Поступление из переработки P 1 после реализации: правка строки отгрузки этой реализации — отказ.
7. `ПересчитатьСтадииЗаказов` для заказа — стадия равна `РассчитатьСтадию`.
8. Удаление строк передачи без поступлений до пустой — пометка (отдельная передача).

Существующие сценарии `Переработка`, `СтадииЗаказа`, `АвтовыпускПриОтгрузке` не меняются и должны пройти.

## 8. Риски

- **Стадии существующих заказов меняются** обработчиком обновления: заказы с поступлениями из переработки получают долю
  выпуска и, возможно, более позднюю стадию. Это соответствует решению «стадия всегда равна расчёту»; «Что нового» об этом
  говорит.
- **Двойной счёт**: продукция одного заказа может прийти и выпуском, и поступлением из переработки — оба считаются, как два
  выпуска; ограничения нет (как выпуск сверх заказа).
- **Передача по выпуску полуфабриката** хранит заказ выпуска и считается к нему; передача и поступление без основания к
  заказу не относятся.
- **Размер модуля менеджера** растёт (~6300 строк); вынос движка строк в общий модуль — отдельной задачей после приёмки
  E12.3 (TECHDEBT), не в этой сборке: регресс четырёх закладок.
- **Правило порядка выпуска и отгрузки** остаётся только в рабочем месте.
- **Правка метаданных**: `HomePageWorkArea.hpwa`, форма рабочего места, индексы `Основание` документов переработки
  (реструктуризация индексов без изменения данных) — Refresh и проверка EDT у владельца.

## 9. Редакция 2 — изменения по ревью плана

Критик (`01-architecture-critic.md`): approve_with_changes, 2×P1, 6×P2, P3. astra (`02-plan-review-astra.md`):
approve_with_changes, 2×P2. Решения (правки §2–§6 выше и ниже имеют приоритет над текстом редакции 1):

| Находка | Источник | Решение |
|---|---|---|
| Поступление списывает партии чужих передач переработчика по FIFO: проверка «есть поступления по основанию» не защищает остаток | critic P1-1 | запрет правки, удаления, «В черновик», «Отменить» передачи — по движениям `ТоварыВПереработке`: есть расход с `ПередачаВПереработку = передача` от другого регистратора. Черновики поступлений движений не пишут и не запрещают: их проведение само проверит остаток у переработчика; колонка «Поступления» их показывает |
| Проверка черновиков под блокировкой остатков не защищена от параллельной записи черновика | astra P2-2 | снимается решением выше: запрет только по проведённым движениям, которые пишутся под блокировкой `ТоварыВПереработке` |
| Смена основания или переработчика передачи после поступлений в форме меняет счёт выпуска и остаток | critic P1-2 | `ПередачаВПереработку.ПередЗаписью`: отказ при смене `Основание` или `Контрагент` (сравнение с базой), если по партиям передачи есть расход других регистраторов; сообщение на четырёх языках. Сценарий проверяет |
| Связи «передача по выпуску» в данных нет | astra P2-1, critic P2-1 | ветки через выпуск и автовыпуск убраны; цепочка одна — поступление → (заказ \| передача → заказ) |
| Поступление с основанием — заказ | critic P2-2 | считается выпуском по этому заказу (§2, §3, обработчик) |
| Заполнение поступления копирует всю ожидаемую продукцию — частичное поступление завышает выпуск | critic P2-3 | `ПоступлениеИзПереработки.ЗаполнитьПоПередаче`: продукция — ожидаемая минус уже поступившая по этой передаче (проведённые непомеченные поступления), строки с нулём не попадают |
| Предблокировка `ТоварыВПереработке` до проведения передачи — обратный порядок | critic P2-4 | проверка расхода и запись проведённой передачи — в транзакции с предблокировкой тем же набором и в том же порядке, что `ОбработкаПроведения` передачи: `ТоварыВНаличии` склада, затем `ТоварыВПереработке` переработчика по материалам |
