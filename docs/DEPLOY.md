# Развёртывание базы без интерфейса

Как поднять базу maERP для клиента без единого интерактивного шага: создать базу из
CF, заполнить организацию и пользователей из JSON, дать клиенту ссылку и логин. Этот
документ — контракт между конфигурацией и скриптами на 1С-сервере; сами серверные
скрипты живут вне git (решение владельца 2026-09-06), их вызывает раннер хаба tinycio
по плану `../tinycio/docs/plans/feature-maerp-onboarding.md` (§5.3 — виды заданий,
§5.4 — контракт скрипта раннера).

## Зачем

Визард первого запуска (`ОбщаяФорма.ФормаПервогоЗапуска`) открывается, только если в
базе ноль организаций и ноль пользователей ИБ (`БрендированиеКлиент.ВызовПервогоЗапуска`).
Клиент, пришедший из хаба, должен попасть в готовую программу, поэтому организацию,
пользователей и служебного администратора заводит обработка `НачальноеЗаполнение` до
первого входа. Логика заполнения одна и та же для визарда и для headless-запуска —
общий модуль `НачальноеЗаполнениеВызовСервера`.

## Шаги на сервере

1. **База из CF.** `1cv8 CREATEINFOBASE ... /UseTemplate maERP-<версия>.cf` — образец
   для файловой базы `scripts/ib-create.sh`; для серверной базы — строка `Srvr=...;Ref=...`
   или `ibcmd`. Версию CF берёт скрипт `create_base`, файлы — из GitHub Releases.
2. **Начальное заполнение** (задание `initial_fill` хаба) — запуск тонкого клиента с
   параметром, описанным ниже. Пока в базе нет пользователей, вход идёт без `/N` и `/P`;
   после заполнения они обязательны.
3. **Публикация** веб-клиента (задание `publish_web`): `webinst`/vhost, HTTPS, язык
   интерфейса в `default.vrd` либо ключ `/L <код>` при запуске толстого/тонкого клиента —
   иначе платформенные строки выходят на языке ОС.
4. **Проверка** (`healthcheck`): HTTP-статус страницы входа.

## Запуск начального заполнения

```
1cv8c ENTERPRISE /F <база>  /C "НачальноеЗаполнение;<payload.json>;<result.json>[;<отчёт.txt>]" \
    /DisableStartupDialogs /DisableStartupMessages /Out <клиентский-лог>
```

- Только **тонкий клиент** (`1cv8c`): толстый компилирует общие модули «Сервер +
  Вызов сервера» дважды и падает на старте.
- Пути — абсолютные, без символа `;` (это разделитель параметра запуска).
- Отчёт хода по умолчанию — `<result.json>.report.txt`.
- Кодам возврата `1cv8` верить нельзя (на macOS обёртка падает сразу, работу делает
  дочерний процесс): успех определяется по строке `ИТОГ;Успех=1` в отчёте **и**
  наличию result-файла с `"success": true`. Образец ожидания — `scripts/run-lib.sh`.
- Перед заполнением клиент выполняет обычное обновление данных базы
  (`ОбновлениеПрограммыКлиент.ОбработатьНачалоРаботы`): версия в регистре
  `ВерсииПодсистем` поднимается, первый вход клиента обновления уже не требует.

Dev-обёртка для macOS: `scripts/initial-fill.sh <база> <payload.json> [result.json]`.
Серверный `initial-fill.sh` для раннера пишется по ней: читает `JOB_PAYLOAD`, кладёт его
во временный файл с правами 600, запускает клиент, переносит result в `JOB_RESULT_FILE`,
удаляет payload и завершается кодом ≠ 0 при любой ошибке. Пароли не печатать: ни в
stdout, ни в лог раннера, ни в аргументы `1cv8` (видны в `ps`).

## Формат payload

Образец — `scripts/initial-fill.example.json`. Лишние поля игнорируются; отсутствие
обязательных — ошибка с перечнем в отчёте и в result-файле.

| Поле | Обязательное | Как используется |
|---|---|---|
| `company.name` | да | наименование организации; по нему ищется существующая (идемпотентность) |
| `company.kind` | нет | вид организации: `legal_entity` (по умолчанию), `sole_proprietor`, `branch`, `individual` либо имя перечисления `ВидыКонтрагентов` |
| `company.prefix` | нет | префикс номеров документов |
| `company.currency` | нет | код (`MAD`, `EUR`, `USD`, `RUB`) или наименование валюты — константа `ВалютаРегламентированногоУчета`, только если она пуста |
| `company.country` | нет | код альфа-2 — константа `СтранаКалендаря` (праздники), только если она пуста |
| `company.language` | нет | язык интерфейса по умолчанию для пользователей: код `ru`/`fr`/`en`/`es` или имя языка конфигурации |
| `company.industry` | нет | отрасль: `trade` (по умолчанию), `construction` (строительство и недвижимость), `other`. Ставит константу «Отрасль»; для `construction` заводит дополнительные реквизиты номенклатуры (этаж, площадь, титр, признак объекта недвижимости) — см. раздел «Отрасль» |
| `owner.*` | нет | принимается, **не используется**: у организации и пользователя нет реквизитов для контактов (`docs/TECHDEBT.md`) |
| `users[]` | нет | пользователи ИБ; пустой список допустим, если пользователей заводит отдельное задание `create_users` |
| `users[].login` | да | имя пользователя ИБ и элемента справочника `Пользователи`; по нему ищется существующий |
| `users[].password` | да | пароль; у существующего пользователя не меняется |
| `users[].full_name` | нет | ФИО пользователя и физлица; пусто — логин |
| `users[].language` | нет | язык интерфейса пользователя; пусто — `company.language`, затем основной язык |
| `users[].roles[]` | нет | имена ролей конфигурации (`Администратор`, `МенеджерПоПродажам`, …); неизвестные пропускаются с предупреждением, роль `Клиент` не выдаётся, пустой список — `Администратор` |
| `users[].email` | нет | не используется (нет реквизита) |
| `support_admin` | нет | скрытый служебный администратор для поддержки; без объекта не создаётся |
| `support_admin.login` | нет | по умолчанию `tinycio-1c` |
| `support_admin.password` | да, если объект есть | пароль; **нигде не хранится и не печатается** — хаб генерирует его и отдаёт клиенту один раз |
| `tenant_id`, `base_name` | нет | не используются конфигурацией, служат скрипту |

Каждому созданному пользователю заводится элемент справочника `Пользователи`
(`Внешний`, вход разрешён, организация) и физлицо по ФИО — как в визарде.

Часовой пояс базы (константа «Часовой пояс базы», форма настроек «Общее», с 2.0.14.18)
через payload пока не задаётся — раннер ставит его администратором после первого входа
или дожидается поля `company.time_zone` (следующий шаг, `docs/ROADMAP.md`, блок 2).

## Формат result

```json
{
  "success": true,
  "organization_created": true,
  "organization": "Example SARL",
  "users": [{"login": "fatima", "created": true}, {"login": "youssef", "created": true}],
  "support_admin_created": true,
  "industry_attributes_created": 4,
  "organizations_total": 1,
  "users_total": 3,
  "warnings": []
}
```

При ошибке — `{"success": false, "error": "<текст>"}`. Паролей в result нет по построению.
`organizations_total` и `users_total` > 0 означают, что визард первого запуска больше
не откроется.

## Отчёт хода

```
СТАРТ;
ПРЕДУПРЕЖДЕНИЕ;роль не найдена, пропущена у youssef: Продавец
ИТОГ;Успех=1;организация создана;пользователей создано 2 из 2;служебный администратор создан;предупреждений 1
```

Строка `СТАРТ;` пишется до работы (признак, что клиент поднялся), `ИТОГ;Успех=0;<ошибка>`
— заполнение не выполнено. Файл начинается с BOM: искать маркеры `grep` без якоря `^`.

## Идемпотентность

Повторный запуск на заполненной базе завершается успехом и ничего не создаёт: организация
найдена по наименованию (`organization_created: false`), пользователи — по логину
(`created: false`), их пароли и роли не трогаются. Так раннер может безопасно повторить
задание после обрыва.

## Отрасль

Тот же выбор есть на первом шаге мастера первого запуска. Отрасль ничего не меняет в
метаданных: «Строительство» лишь заводит дополнительные реквизиты справочника «Номенклатура»
через механизм `УправлениеСвойствами` (план видов характеристик «Дополнительные реквизиты»,
поля появляются на закладке «Дополнительно» карточки). Повторное применение реквизиты не
дублирует; администратор может добавить свои в разделе «Сервис → Управление данными».

## Служебный администратор

Пароль `tinycio-1c` в конфигурации не зашит (развилка Р3 `docs/ROADMAP.md` закрыта
2026-09-06): в headless-режиме он приходит в `support_admin.password`, в визарде
генерируется случайно и показывается один раз на последнем шаге. Потерянный пароль
меняется администратором базы штатно (обработка `СменаПароля` или конфигуратор).

## Проверка

`scripts/initial-fill-test.sh <файл.cf>`: пустая база → заполнение → повтор → смок под
созданным администратором. Регламент — `docs/TESTING.md`, раздел «Headless-первый запуск».
