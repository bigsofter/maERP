> Постановка владельца 10.10.2026: у каждого продукта — версия, публичная история обновлений с датами на сайте
> (`tinycio.*/about/releases/maerp`, блок «Новое в продукте» на `/products/maerp`) и окно «Что нового» в программе.
> Общая постановка — `docs/ai/prompts/product-releases.md` репозитория tinycio; здесь — то, что нужно именно maERP
> (17.10.2026).

**Код в хабе:** `maerp` · **версия:** `2.0.X.Y` из `Configuration.mdo` (своя, вторую нумерацию не заводим) ·
**языки записей:** ru, fr, en, es

**Что уже есть.** Полный цикл с 26.08: макет «ОписаниеИзменений» ×4 → окно «Что нового» в 1С; при публикации CF
секции переезжают в `docs/CHANGELOG.md`; шаг 13 чек-листа `docs/RELEASING.md` — `scripts/push-release-to-hub.sh`
отправляет релиз в хаб. **Чего нет:** опубликованные релизы до сих пор не дошли до хаба — 17.10 публичная лента
`GET https://my.tinycio.com/api/public/product-hub/maerp/releases` отдаёт 404. Опубликованные релизы — теги
`v1.0.11.1` (25.08), `v2.0.12.18` (31.08), `v2.0.14.26` (08.09), `v2.0.15.71` (26.09). Свой скрипт берёт текст
из макета, а макет после публикации CF очищается, поэтому прошлые релизы им не отправить — нужен промпт ниже.

## Промпт 1 · Догрузить в хаб прошлые релизы (первое сообщение новой сессии в этом репозитории)

```text
Ты — релиз-менеджер maERP. Задача: опубликовать в TinyCIO Product Hub историю ВЫПУЩЕННЫХ релизов maERP, чтобы на
tinycio.*/about/releases/maerp и в блоке «Новое в продукте» на /products/maerp было видно, как продукт развивается.
Источник — docs/CHANGELOG.md (разделы «# Релиз X (дата)» и секции сборок внутри) и теги git v*. Ничего не
придумывай: нет в CHANGELOG — нет в записи.

Правила:
- одна запись хаба = один опубликованный релиз (тег), не сборка: version = версия релиза (2.0.15.71),
  released_at = дата из заголовка релиза / тега;
- текст — сводка всех сборок релиза для пользователя: 5–12 пунктов на релиз, сгруппированных по смыслу, без
  повторов и промежуточных исправлений того, что появилось в том же релизе; 1–2 предложения на пункт; без имён
  объектов метаданных, модулей и цен;
- kind: feature, если в релизе есть новые возможности; fix — если только исправления;
- языки ru, fr, en, es — из соответствующих блоков секций (### ru / ### fr / …), не переводи заново;
  нет языка в источнике — сообщи, не дописывай машинно.

Выход: build/releases-history.json — [{ "version", "released_at", "kind",
"changes": [{ "lang": "ru", "title": "...", "items": [...] }, ...] }, ...], старые сверху; и таблица в ответе
«версия · дата · одна строка · сколько сборок свернуто». В хаб НЕ публикуй.
Публикация после проверки владельцем — скриптом tinycio (ключ --from-json, своих скриптов не правь):
  TINYCIO_HUB_PRODUCT=maerp TINYCIO_HUB_SECRET=… <tinycio>/tools/push-release-to-hub.sh --from-json build/releases-history.json --dry-run
```
