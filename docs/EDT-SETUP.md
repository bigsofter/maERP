# Настройка среды разработки

Проверено на macOS (Apple M2 Pro, Darwin 25.5). Платформа 1С уже установлена
в `/opt/1cv8`, версии `8.3.25.1560` и `8.5.1.1150`. Проект ведём на `8.5.1.1150`.

## 1. Установить 1C:EDT

Сейчас установлен только лаунчер **1C:EDT Start 2025.2.3** и JDK 17, самой IDE нет.

```bash
open "/Applications/1C/1CE/components/1c-edt-start-0.9.0+229-x86_64/1cedtstart (0.9.0+229).app"
```

В окне лаунчера выбрать и установить версию EDT. **Ключевая проверка:** версия
EDT должна поддерживать платформу 8.5.1. Список поддерживаемых версий платформы
виден в мастере создания проекта — если 8.5.1 там нет, нужна более свежая EDT.

Компоненты EDT собраны под x86_64 и на Apple Silicon идут через Rosetta. Это
работает, но памяти EDT ест много: в `1cedt.ini` установленной сборки стоит
поднять `-Xmx` минимум до `4096m`, для крупной конфигурации — до `6144m`.

## 2. Воркспейс

Воркспейс EDT держим **вне репозитория**:

```
~/EDT/ws-maERP
```

Иначе служебные каталоги Eclipse (`.metadata`, индексы, логи) окажутся внутри
git и будут постоянно засорять историю.

## 3. Настройки EDT

Окно → Параметры:

- **Кодировка** — UTF-8 (General → Workspace → Text file encoding). Расходится с
  этим — получаем битую кириллицу в модулях.
- **Каталог платформы** — `/opt/1cv8`, версия по умолчанию `8.5.1.1150`.
- **Автоформатирование при сохранении — выключить.** Иначе EDT будет
  переформатировать модули, которые правил я, и диффы превратятся в шум.
- **Проверка модулей** — включить, это основной способ поймать мои ошибки до
  сборки.

## 4. Перенести конфигурацию из CF в EDT

EDT не умеет импортировать `.cf` напрямую. Промежуточное звено — база.

Создаём базу сборки из CF (скрипт создаёт чистую файловую базу и грузит в неё CF):

```bash
scripts/ib-create.sh /путь/к/конфигурации.cf
```

База появится в `build/ib`. Дальше в EDT:

1. Файл → Импорт → **Конфигурация 1С:Предприятие из информационной базы**.
2. Указать базу `build/ib` (файловая, путь к каталогу).
3. Имя проекта — `maERP`.
4. Снять галку «использовать расположение по умолчанию» и указать
   расположение проекта: `~/Documents/Dev/maERP/src/cf`.
5. Версия платформы проекта — `8.5.1`.

Импорт крупной конфигурации занимает от 20 минут до часа. По завершении в
`src/cf` появится дерево `.mdo` и `.bsl` — с этого момента я вижу код и могу
его править.

## 5. Обратное направление

Если правки делались в конфигураторе, а не в EDT, их надо втянуть обратно:

```bash
scripts/xml-dump.sh build/ib build/xml     # база -> XML конфигуратора
```

затем в EDT: Файл → Импорт → Конфигурация из файлов, указать `build/xml`.

## 6. Цикл разработки

1. Я правлю `.bsl` / `.mdo` в `src/cf` и коммичу.
2. Ты в EDT делаешь Refresh (F5) на проекте и смотришь проверку модулей.
3. Отладка — запуск конфигурации из EDT на базе разработки.
4. Сборка поставки — `scripts/dist-build.sh`, см. [RELEASE.md](RELEASE.md).

Конфигуратор для сборки не нужен: пакетный режим `1cv8 DESIGNER` работает
из терминала headless, это проверено.
