# E13: совместимость с базой drissotex перед публикацией CF

Этап **E13** волны «производственный контур 2mzl» (`docs/plans/production-2mzl.md`, раздел «E13. Совместимость с
базой drissotex», размер M). По плану волны E13 выполняется **после всех изменений метаданных** — волна
«многоуровневые техкарты и переработка» закрыта 2026-09-22 сборкой 2.0.15.49, значит очередь его.

Это проверочный этап: он не добавляет функционала, а отвечает на один вопрос — **сядет ли накопленное с последней
публикации CF на базу клиента без потери данных**. Сборка заводится только если проверка что-то найдёт.

## Объём (после ответов, по рекомендациям)

1. **Метаданные: ни один uuid не изменился и ни одна табличная часть не удалена.** Сверка XML-выгрузки
   конфигурации клиента (`build/drissotex/`) с текущей: список объектов и их uuid, реквизиты и табличные части
   общих объектов, смена типов. Скриптом (одноразовый в scratchpad) с нормализацией: в XML оставлять только `ru`
   в `v8:item`, иначе 90 % диффа — переводы. Результат — таблица «объект: было / стало / последствие».
2. **Реструктуризация на копии базы клиента.** Развернуть копию (`ib-restore.sh`), загрузить конфигурацию 2.0.15.49
   и применить **отдельной командой** `/UpdateDBCfg` (tiny1C `workflow-012`: в одной команде с загрузкой она не
   применяется). В журнале — только изменение типов реквизитов и создание объектов, никаких удалений данных.
   Время применения записать: владельцу нужно окно простоя.
3. **Первый вход после обновления** (шаг 7 чек-листа релиза): `ВерсииПодсистем` поднимается до 2.0.15.49,
   обработчики выполняются один раз, окно «Что нового» показывает секции всех сборок, в журнале регистрации по
   событию «Обновление программы» ошибок нет. Засечь время обработчиков.
4. **Смок и тесты документов на копии базы клиента** — данные клиента, а не наши фикстуры: `scripts/smoke.sh` и
   `scripts/doctests.sh` по каталогу копии.
5. **Перепроведение выпусков** по ответу 3: суммы прихода готовой продукции до и после — запросом к
   `ТоварыВНаличии` (и `СуммаНДС` отдельно), сравнение таблиц, расхождения — поимённо.
6. **Отчёт** `.ai/reports/production-2mzl-e13.md` и раздел «Совместимость 2.0.15.49» в `docs/MERGE-DRISSOTEX.md`:

## Ловушки, каждую проверить до работы

1. **Работаем только на копии.** База клиента и `build/ib` владельца — не трогать; каталог копии — в scratchpad
   сессии. Перед применением конфигурации — свой бэкап копии, иначе повтор проверки стоит ещё одного разворачивания.
2. **`/UpdateDBCfg` отдельной командой** (`workflow-012`), иначе «обновление прошло», а структура базы прежняя.
3. **Расширение клиента**: подключённое расширение может не пустить обновление. По ответу 2 — либо проверяем с ним,
   либо явно пишем в отчёте, что проверка шла без него.
4. **Сравнение XML** без нормализации языков бессмысленно (`project-state`): оставлять `ru`, остальное отбрасывать.
5. **Один тяжёлый процесс за раз**: разворачивание, `UpdateDBCfg`, смок и `doctests` — последовательно, не
   параллелить с субагентами и EDT (память `ai-backend-limits`, `edt-mdo-types`).
6. **Гонка выгрузки EDT** («feature with code "type"», «без родительского объекта») — повторить полное обновление,
   журнал `~/EDT/ws-maERP/.metadata/1cedtcli.log`.
7. **Лицензия платформы**: EDT врёт про неверный пароль, когда нет лицензии (`workflow-010`) — проверять
   конфигуратором напрямую.
8. **`СуммаНДС = 0` у исторических партий** — принятое ограничение волны 5, не новая находка.
9. **«ё» в новых именах файлов**: `git add -u`, `git show --stat` (`workflow-007`).

## Сценарии уровня 3

Новых сценариев этап не заводит: он проверяет данные клиента, а не правило. Исключение — если сверка найдёт дефект,
воспроизводимый на фикстурах: тогда сценарий заводится вместе с исправлением в сборке 2.0.15.50 и расширяет
существующий блок (`ТестыДокументов`), а не создаёт новый.

## Гейты

| Шаг | Гейт | Как закрывать |
|---|---|---|
| план | `ai-review-plan` | обязателен, если появятся правки метаданных или обработчик обновления; чистая проверка — по желанию |
| проверка | прогон на копии | `ib-restore.sh` → загрузка 2.0.15.49 → `/UpdateDBCfg` → первый вход → `smoke.sh`, `doctests.sh` |
| исправления | `ai-review` + `ai-database` | обязательны, если что-то правим: реструктуризация и данные клиента |
| сдача | `ai-final-check --db` | отчёт `.ai/reports/production-2mzl-e13.md` |

Codex в лимите — гейты субагентами Claude, в отчёте прямо писать, на каком бэкенде.
