# Режим «Товары» на закладке «Поступления» рабочего места закупок (2.0.16.108)

Задача владельца (клиент Drissotex). Решения 2026-10-27:

1. **Товары — любые.** Если у поставщика есть открытый заказ поставщику на этот товар, строка привязывается к строке
   заказа автоматически, иначе поступление без заказа.
2. **Документ создаётся при выходе из строки.** «Документ поступления создается в момент выхода из строки. В следующей
   строке я могу выбрать предыдущее поступление из выпадающего списка, которое сформировалось на первой строке. Если я
   не выбираю поступление, то создается новое». Это модель строки рабочего места производства.

Уровень по CLAUDE.md — существенный: запись и проведение документов из формы, новая точка входа в общий механизм строк.
План → `ai-review-plan` → код → `ai-review` → `ai-final-check`.

Редакция 6 — по кругу 5 (approve_with_changes: строки поступлений, оформивших ордер, — просмотр; открытые строки без
предела 500 с отбором заказа и кодов в запросе). Редакция 5 — по кругу 4 (reject: пустое основание любого типа, коды строк, уже представленные в документе). Редакция 4
— по кругу 3 (reject: открытые строки — расчётом «К поступлению» по регистру; права на строки поступлений и
ордеров раздельно). Редакция 3 — по кругу 2 (reject: гейт только для новой строки, документы с другим основанием только для просмотра,
склад пользователя, права на поступление). Редакция 2 — по кругу 1 `ai-review-plan` (reject, 4×P1): путь по заказу — адаптер нижней панели с заказом клиента,
путь без заказа — признак `БезЗаказаПоставщику` в механизме, смешанных документов нет, остаток — как на нижней панели.

## Что есть

- Закладка «Поступления» (`СтраницаСписокПоступлений`) — список документов: поступления и приходные ордера, страницы по
  отборам формы (`Обработки.АРМЗакупки.СтраницаПоступлений`).
- Общий механизм строк документов — `Обработки.АРМПроизводство.ЗаписатьСтрокуДокумента(ДанныеСтроки)` (вид
  «Поступление»):
  - новый документ — `НовыйДокументЗакупки`: по заказу поставщику — заполнение на основании, валюта заказа; без
    заказа — договор поставщика, основная валюта;
  - на ордерном складе — приходный ордер вместо поступления (`ОрдерВместоДокумента`);
  - проведение нового документа, отказ проведения — черновик;
  - защита оформленного ордера и зависимых документов, версия данных строки.
- Рабочее место закупок уже пишет им строки поступления заказа на нижней панели (`ЗаписатьСтрокуПоступления`,
  `КонтекстЗаказПоставщику = Истина`) — только по строкам заказа поставщику.
- Привязка поступления к заказу: шапка `Основание` = заказ поставщику (один заказ на документ), строка — `КодСтроки` =
  код строки заказа; у приходного ордера — `КодСтрокиЗаказа`. Остатки строк заказов — `ТекстЗапросаСтрокОснований`.

## Как будет

### Интерфейс

- На закладке «Поступления» — переключатель **«Документы / Товары»** (реквизит формы `РежимПоступлений`, сохраняется в
  настройках формы). «Документы» — нынешний список без изменений.
- «Товары» — таблица `ТоварыПоступлений` (реквизит формы — таблица значений) со строками документов **текущей страницы**
  списка (те же отборы и страницы: переключение режима не меняет набор документов). Колонки:
  - «Документ» — представление документа; выбор из списка: «Новое поступление» и сегодняшние непомеченные поступления
    и приходные ордера поставщика строки (свежие первыми). Двойной щелчок по колонке открывает документ;
  - «Поставщик» — у новой строки по умолчанию отбор формы или поставщик предыдущей строки; у строки записанного
    документа — только просмотр;
  - «Товар», «Характеристика», «Упаковка», «Количество», «Цена» (при праве видеть суммы), «Сумма» — только просмотр;
  - «Заказ поставщику» — только просмотр: к какому заказу привязалась строка;
  - «Склад» — только просмотр, склад документа.
- Порядок ввода — как в нижних таблицах рабочего места производства:
  - новая строка добавляется сверху;
  - запись строки — `ПриОкончанииРедактирования`, серверный вызов обработчиком ожидания (урок 2.0.16.106: не в самом
    событии, пока закрывается выпадающий список);
  - после успешной записи строки документа заменяются его актуальными строками (сумма, цена, номер строки,
    версия данных), позиция курсора — на записанной строке;
  - отказ — сообщение, строка перечитывается из базы, новая непрошедшая строка остаётся для правки.
- Удаление строк — тот же механизм, что у нижней таблицы (`ИтогУдаления` → `УдалитьСтрокиДокументов`): документ без
  строк помечается на удаление.
- Подменю и кнопка «Создать» на закладке не меняются (2.0.16.107).

### Запись строки — `Обработки.АРМЗакупки.ЗаписатьСтрокуТоваровПоступления(Строка)`

Редакция 2 (круг 1 `ai-review-plan`: 4×P1). Строка — Документ (пустой — новый), НомерСтроки (0 — новая), ВерсияДанных,
Поставщик, Номенклатура, Характеристика, Упаковка, КоличествоУпаковок, Цена/ЦенаИзменена.

**Документ поступления — либо по одному заказу поставщику, либо без заказа.** Смешанных документов нет: товар вне
заказа в поступление по заказу не добавляется (P1-2: механизм связывает все строки поступления с его основанием —
перечитывание, движения `ЗаказыПоставщикам`).

1. **Открытые строки заказов поставщика по товару** (редакция 4, P1 круга 3) — расчёт закладки «К поступлению»
   (`ТекстЗапросаКПоступлению`): остатки регистра `ЗаказыПоставщикам` (поступления, возвраты и переносы строк между
   заказами уже в нём) минус непроведённые непомеченные поступления и заказы, забирающие строку. Новая экспортная функция
   рабочего места закупок `ОткрытыеСтрокиЗаказовПоставщика(Поставщик, Номенклатура, Характеристика, ЗаказПоставщику,
   ЗанятыеКоды)` — тот же расчёт **без предела `ПЕРВЫЕ 500`** экранной таблицы (редакция 6, P2 круга 5); отбор заказа и
   исключение занятых кодов — в самом запросе, до выбора первой строки. Порядок — дата заказа, код строки. Её же
   вызывает гейт механизма (п. 3) — один расчёт для выбора и для запрета.
2. **Строка по заказу X** — данные строки собирает существующий адаптер нижней панели `ДанныеСтрокиЗаказа(X,
   ВидПоступление)`: `КонтекстЗаказПоставщику = Истина`, поставщик заказа, **заказ клиента из основания X** (P1-4),
   `ЗаказПоставщику = X`; затем `КодСтрокиОснования` — код выбранной строки X, товар, количество, документ. Это ровно
   путь `ЗаписатьСтрокуПоступления`, проверенный на нижней панели.
3. **Строка без заказа** — `КонтекстЗаказПоставщику = Истина` (производственные проверки пустого заказа клиента не
   выполняются — P1-1), `Заказ` и `ЗаказПоставщику` пусты, новый признак данных строки механизма
   **`БезЗаказаПоставщику = Истина`**. Гейт `ТекстЗапретаОснованияСтрокиПоступления` для такой строки не требует строки
   заказа, а проверяет обратное: у поставщика нет открытых строк по товару (функция п. 1). Есть — отказ «Товар есть в
   открытом заказе поставщику № …: выберите «Новое поступление» — оно оформится по заказу». Проверка — **только для новой
   строки** (НомерСтроки = 0), в механизме, после проверки «строка не изменилась» не зависит (редакция 3, P1-1): правка
   количества и цены записанной строки без заказа проходит, даже если заказ на этот товар оформлен позже.
4. **Выбор пути:**
   - новый документ: есть открытая строка — путь п. 2 по первой строке; нет — п. 3;
   - выбран документ по заказу X: у X есть открытая строка по товару — п. 2 по ней; нет — отказ «Поступление
     оформлено по заказу № …, товара в нём нет: выберите «Новое поступление»»;
   - выбран документ без заказа — п. 3 (гейт механизма откажет, если товар есть в открытом заказе);
   - механизм сам отказывает, если основание документа не совпадает с основанием строки
     (`ТекстЗапретаОснованияПоступления`) и если поставщик другой.
**Пустое основание (редакция 5, P1 круга 4).** `Основание` документа бывает `Неопределено` или пустой ссылкой любого
допустимого типа: всё это — «без заказа». В `ТекстЗапретаОснованияПоступления` механизма два незаполненных значения
считаются равными независимо от типа, заполненные сравниваются строго; так же классифицирует документы адаптер.

**Строка заказа, уже представленная в документе (редакция 5, P2 круга 4).** При добавлении в выбранный документ по
заказу X кандидаты — открытые строки X по товару **без кодов, уже имеющихся в строках документа**: механизм запрещает
повтор кода (`ТекстЗапретаПовтораСтрокиОснования`) и перепроверяет это при записи. Свободных нет — отказ «Строка
этого товара уже есть в поступлении: измените её количество».

**Документы с другим основанием (редакция 3, P1-2).** Поступление может быть введено и на основании заказа клиента
(прямое поступление, «Заполнить по заказу на производство») или реализации. Режим «Товары» правит только документы
двух видов: основание — заказ поставщику или пусто. Строки остальных показываются только для просмотра (признак строки
`ТолькоПросмотр`, клиент не начинает правку), в выбор документа они не попадают; правка — в форме документа.

5. **Изменение записанной строки** (НомерСтроки ≠ 0): путь по основанию документа — X (п. 2 с кодом строки из
   прочитанной строки) или без заказа (п. 3). Товар записанной строки не меняется — колонка «Товар» только для
   просмотра. Удаление — `ИтогУдаления` с тем же путём данных.
6. **Остаток строки заказа (P1-3).** Одиночная запись строки по заказу проверяет существование строки основания, но не
   остаток — так же, как нижняя панель «Поступления» заказа сегодня: поступление сверх заказа допустимо (пакет «К
   поступлению» с `НаОстаток = Ложь` тоже принимает сверхпоставку). Гонка двух пользователей по одной строке даёт
   поступление сверх заказа, как и ввод сверх заказа руками; ограничения остатком в одиночном пути не ввожу —
   поведение то же, что на нижней панели. Рассогласования данных нет: исполнение заказа считается по фактическим
   строкам поступлений.

Склад нового документа — склад поступлений пользователя по умолчанию (2.0.16.91) для обоих путей: у заказа поставщику
склада нет (редакция 3, P2-1). На ордерном складе механизм создаёт приходный ордер (`ОрдерВместоДокумента`):
по заказу — `КодСтрокиЗаказа`, без заказа — без основания.

### Строки страницы — `Обработки.АРМЗакупки.СтрокиТоваровПоступлений(Документы)`

Одним пакетом запросов по документам страницы: новая экспортная функция механизма
`СтрокиДокументовСписка(Документы)` — запросы строк `СтрокиДокументов` с условием отбора `Д.Ссылка В (&Документы)`
(сейчас она принимает заказ или один документ). Цикла запросов по документам нет. Права на поступления и на приходные
ордера проверяются **независимо**. Строки поступлений, оформивших приходный ордер (`Ордер` заполнен), в пакетное
чтение входят — только для просмотра, с колонкой «Ордер» (редакция 6, P2 круга 5): нижняя панель их по-прежнему
исключает. Права: в пакет входит часть, на которую есть чтение (редакция 4, P2 круга 3); пустой
результат — только без чтения обоих.

### Права

Ввод строк в режиме «Товары» — при праве добавления поступления (механизм проверяет право на поступление до выбора
ордера). Пользователь с правами только на приходные ордера видит строки только для просмотра и вводит ордера через
«Создать» (редакция 3, P2-2; TECHDEBT, если владельцу понадобится ввод ордеров кладовщиком в этом режиме). Колонки цены и суммы — по праву видеть
суммы (`ПоказыватьСуммы` механизма). Без права записи документа строки только для просмотра.

## Тесты (уровень 3)

Сценарий `ПоступленияТоварамиАРМ` (без отказов: проверки запрета — без записи, `ТекстЗапретаСтрокиДокумента`):
1. Заказ поставщику под заказ клиента (торговый) на товар А. Строка А без документа — новое поступление по заказу,
   строка с кодом строки заказа, остаток строки заказа уменьшился, `ЗаказыПоставщикам` — расход.
2. Строка товара Б (ни в одном заказе) без документа — новое поступление без основания, движений `ЗаказыПоставщикам`
   нет.
3. Вторая строка товара Б в документ п. 2 — тот же документ, две строки.
4. Изменение количества строки п. 1 и строки п. 2 — документы перепроведены, основания те же.
5. Проверки без записи: товар Б в документ п. 1 — запрет «товара в заказе нет»; товар А в документ п. 2 — запрет
   механизма «товар есть в открытом заказе».
6. `СтрокиТоваровПоступлений` по документам п. 1 и 2 — три строки, заказ — у первой.
7. Удаление строки п. 3 — документ остаётся с одной строкой.
8. Ордерный склад поступлений пользователя (опция включена) — новая строка товара А создаёт приходный ордер с
   `КодСтрокиЗаказа`, товара Б — приходный ордер без основания.

9. Поступление товара Б без заказа (п. 2), затем заказ поставщику на Б, затем правка количества строки п. 2 — проходит;
   новая строка Б в документ п. 2 — запрет «товар есть в открытом заказе».
10. Перенос строки заказа X в заказ Y (Y забрал строку): новая строка товара привязывается к Y, а не к X.
11. Заказ X с двумя строками товара А (коды 1 и 2), в документе уже строка по коду 1 — новая строка А в этот документ
    привязывается к коду 2; третья — отказ «строка уже есть».
12. Поступление и приходный ордер без заказа, созданные вручную (основание `Неопределено`), — добавление и правка
    строки проходят.
13. Поступление на основании заказа клиента (прямое) на странице — строка `ТолькоПросмотр`, в выборе документа его нет.

`ПоступленияТоварамиАРМПроизводство` — заказ поставщику под заказ на производство: строка по заказу проходит
производственные проверки заказа клиента (путь п. 2).

Форма (переключатель, выбор документа, двойной щелчок, порядок строк) — руками у владельца.

## Риски

- Привязка решается до блокировки: строку заказа между выбором и записью может закрыть другой пользователь — тогда
  поступление пройдёт сверх заказа (п. 6), как на нижней панели. Обратное — заказ на товар появился после проверки
  строки без заказа — механизм перепроверяет гейт п. 3 при записи; окно между гейтом и проведением такое же, как у
  ручного ввода поступления без заказа в форме документа.
- Документ из выпадающего списка — сегодняшние документы поставщика: вчерашний документ дописать нельзя (как в рабочем
  месте производства).
- Страница списка — до размера страницы документов. Строк может быть много (широкие поступления), таблица значений
  формы. Предел — размер страницы списка, как у «Документов».

## Не входит

- Номер и дата накладной поставщика в строке — вводятся в форме документа.
- Серии в строке — в форме документа.
- Смена склада и валюты нового документа из строки.
