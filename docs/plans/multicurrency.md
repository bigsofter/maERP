# Документы в валюте: «Поступление товаров» и «Реализация товаров»

Задача владельца 2026-10-06. Флажок «В валюте» на первой закладке, валюта и курс, заголовки
колонок «Цена (EUR)», «Сумма (EUR)» и колонка «Сумма (MAD)», пересчёт цен вида цен в валюту
документа, сумма в основной валюте во всех регистрах.

## Решения владельца (2026-10-06)

1. Курсы — новый периодический регистр сведений `КурсыВалют`, ввод вручную; в документ курс
   подставляется по дате и валюте и правится руками.
2. Основная валюта — существующая константа `ВалютаРегламентированногоУчета`, новой не заводим.
3. Взаиморасчёты с поставщиками и с покупателями, «Заказы поставщикам»: **«Сумма» всегда в
   основной валюте** (её читают ~80 мест: долги, просрочка, кредитный контроль, ведомости,
   дашборд — они остаются верными, оплата в MAD закрывает долг валютного документа). Новый
   ресурс `СуммаВВалюте` + `Валюта` хранят сумму в валюте объекта расчётов.
4. «Товары в наличии», «Дополнительные расходы», «Продажи» — без нового ресурса: их суммы и так в
   основной валюте (себестоимость партии, выручка − себестоимость); пересчёт по курсу доводится там,
   где его нет.

## Факты, на которые опирается план

- `ПоступлениеТоваровУслуг` уже имеет `Валюта` (по умолчанию MoroccanDirham) и `КурсВалюты`
  (15.4, по умолчанию 1); у `РеализацияТоваровУслуг` их нет.
- `СерииИРазмещение.ОбъединитьТоварыССериями` (Module.bsl:95–106) уже умножает суммы ТЧ на
  `КурсВалюты`, если `Валюта` заполнена и ≠ регл.; включится и для реализации, как только у неё
  появится реквизит (`ЕстьРеквизит`). → ТоварыВНаличии и Продажи (Себестоимость) уже в регл.
- `ДополнительныеРасходы.РаспределитьНаСебестоимость`: суммы `ТЧДополнительныеРасходы` берутся
  без курса — ошибка для валютного поступления.
- `ВзаиморасчётыСПоставщиками`: измерение `Валюта` есть; поступление пишет `ДокОбъект.Сумма` в
  валюте документа, оплаты — в регл. с `Валюта = регл.` — у валютного поступления сейчас долг и
  оплата расходятся по измерению и по валюте.
- `ВзаиморасчётыСПокупателями`: измерения `Валюта` нет; все движения через `Движение(...)`
  (ManagerModule.bsl:212). У поставщиков — тоже единый `Движение(...)` (:257).
- `ЗаказыПоставщикам`: заказ пишет приход в регл. (у `ЗаказПоставщику` валюты нет), поступление —
  расход `Стр.Сумма` без курса.
- `ВидыЦен` без валюты; `ЦеныНоменклатуры` — без валюты (цена в валюте своего вида цен).
  `ЦеныНоменклатурыПоставщиков` хранится в регл. (поступление пишет её через курс).
  `ЦеныПродажи`/`ЦеныЗакупки` (фиксированные цены контрагента) — без валюты, считаем регл.
- Единая точка подстановки цены строки — `ОбщегоНазначенияВызовСервера.ПолучитьЦенуНоменклатуры`
  (:308) через `ЦеныДляЗакупки`/`ЦеныДляПродажи`/`ДанныеЦенДляСписка`; массовая —
  `РаботаСДокументами.УстановитьЦеныВТабличнойЧасти` (:968).
- Описание валют = ISO-код (EUR, MAD, USD, RUR) — годится в заголовок колонки.

## Метаданные

1. **Регистр сведений `КурсыВалют`** — периодический (день), независимый. Измерение `Валюта`
   (СправочникСсылка.Валюты, ведущее нет). Ресурс `Курс` (Число 15.4) — сколько единиц основной
   валюты за 1 единицу валюты. Кратности нет (MAD/EUR/USD ей не пользуются; заведём, если
   понадобится). Основная форма списка; в подсистему `Казначейство/Справочники` рядом с `Валюты`.
   Права: чтение — всем ролям, у которых есть чтение `Валюты`; изменение — тем, у кого есть
   изменение `Валюты`/`ВидыЦен` (сверю по Rights.rights).
2. **`ВидыЦен.Валюта`** (СправочникСсылка.Валюты). Пусто = основная валюта. Поле в форме элемента.
3. **`ПоступлениеТоваровУслуг.ВВалюте`** (Булево).
4. **`РеализацияТоваровУслуг`**: `ВВалюте` (Булево), `Валюта` (Валюты), `КурсВалюты` (15.4,
   заполнение 1) — по образцу поступления; у валюты без значения заполнения (пусто = основная).
5. **ТЧ `ТЧТовары` и `ТЧУслуги` обоих документов: `СуммаРегл`** (ОпределяемыйТип.Сумма) —
   `Сумма × КурсВалюты` строки, только для показа и печати.
6. **Шапка обоих документов: `СуммаРегл`** (ОпределяемыйТип.Сумма) — итог `Сумма` документа ×
   курс, для взаиморасчётов и списков.
7. **`ВзаиморасчётыСПокупателями`**: измерение `Валюта` (последним), ресурс `СуммаВВалюте`.
   **`ВзаиморасчётыСПоставщиками`**: ресурс `СуммаВВалюте`. **`ЗаказыПоставщикам`**: ресурс
   `СуммаВВалюте` не нужен (заказ поставщику без валюты) — там только перевод суммы поступления
   в регл.

## Общий модуль `РаботаСВалютами` (Сервер) и `РаботаСВалютамиКлиентСервер`

- `КурсВалюты(Валюта, Дата) Экспорт` — срез последних `КурсыВалют`; основная или пустая валюта →
  1; нет курса → 0 (вызывающий решает, что сказать пользователю).
- `ВалютаИКурсДокумента(ДокОбъект) Экспорт` → Структура(Валюта, Курс, ВВалюте): у документа без
  реквизитов или со снятым флажком — основная и 1; пустая валюта → основная; курс 0 → 1.
  У `ВозвратПоставщику` (валюта есть, флажка нет) — валюта ≠ основной считается валютной.
- `ПересчитатьЦену(Цена, ВалютаЦены, ВалютаДокумента, КурсДокумента, Дата) Экспорт` — цена вида
  цен в валюте документа: `Цена × Курс(ВалютаЦены) / КурсДокумента`; курс валюты цены не задан —
  цена возвращается как есть + признак для сообщения.
- КлиентСервер: `СуммаРегл(Сумма, Курс)` = `Окр(Сумма × Курс, 2)`; `ЗаголовокСВалютой(Текст,
  Валюта)`.

## Формы документов

- Первая закладка («Основное» у поступления, «Операция» у реализации — она и есть «Общее»):
  флажок `ВВалюте`, рядом группа `Валюта` + `КурсВалюты`. Поля видимы всегда, доступны только при
  флажке. У поступления группа `ВалютаКурс` уже есть — флажок встаёт в неё первым.
- Флажок снят → `Валюта = основная`, `КурсВалюты = 1`. Флажок включён / сменилась валюта или дата
  → курс из `КурсыВалют` на дату документа; нет курса — сообщение «Курс EUR на дату не задан»,
  курс остаётся прежним.
- Смена валюты или курса при непустых ТЧ → вопрос «Пересчитать цены в новую валюту?»: `Цена ×
  СтарыйКурс / НовыйКурс`, затем `РассчитатьСтроку`. Отказ — цены не трогаем, пересчитываются
  только `СуммаРегл`.
- `ВВалюте` = Истина: заголовки `ТЧТоварыЦена`/`ТЧТоварыСумма` (и `ТЧУслуги…`) — «Цена (EUR)»,
  «Сумма (EUR)»; колонка `СуммаРегл` видима, заголовок «Сумма (MAD)», только просмотр. Снят —
  штатные заголовки, колонка скрыта. Устанавливается в `ПриСозданииНаСервере`/`ПриЧтенииНаСервере`
  и при смене флажка/валюты (`УстановитьВидимостьВалюты`). Шрифт шапки новой колонки — как у
  соседних (`colfont.py`).
- `СуммаРегл` строки: `ТЧТоварыПриОкончанииРедактирования` и после массовых операций (подбор,
  Excel, перезаполнение цен, смена курса) — серверный `ПересчитатьСуммыРегл`; в объекте —
  повторно в `ПередЗаписью` (истина там).
- Подвал реализации: оплата и долг (`СуммаОплаты`, `СуммаДолга`) читаются из регистра в регл. —
  у валютного документа подписываю их «(MAD)».

## Цены

- `ПреобразоватьСтрокуТаблицыВСтруктуру` / данные цен: передаю `Валюта`, `КурсВалюты` и `Дата`
  документа.
- `ПолучитьЦенуНоменклатуры` и `УстановитьЦеныВТабличнойЧасти`: цена из `ЦеныНоменклатуры`
  пересчитывается из `ВидЦены.Валюта` (пусто = основная) в валюту документа; цены поставщиков,
  `ЦеныПродажи`/`ЦеныЗакупки` и динамическая цена — из основной. В основной валюте документа
  без флажка поведение прежнее (курс 1, валюта цены = основная → без пересчёта), кроме вида цен в
  чужой валюте — он теперь тоже пересчитывается в основную.
- Справочные цены поступления (`ЦенаРозничная`, `ЦенаМинимальная`, `ЦенаПоТипуЦен`) не
  пересчитываю: они пишутся обратно в `ЦеныНоменклатуры` и должны остаться в валюте вида цен.
- Ввод на основании: реализация из заказа покупателя и поступление из заказа поставщику (оба в
  основной валюте) — документ создаётся без флажка, как сейчас.

## Проведение

Правило: в регистрах взаиморасчётов «Сумма» — основная валюта; `Валюта` + `СуммаВВалюте` —
валюта **объекта расчётов** и сумма в ней. Валюту определяет **сам `Движение(...)`** по
`ОбъектРасчётов`, а не вызывающий (ревью плана P1-2): любой документ — оплата, корректировка долга,
сертификат, зачёт аванса, налоговая накладная, возврат — пишет по валютному объекту ту же валюту, и
остаток по `(объект, валюта)` не дробится.

- Соглашение об основной валюте в измерении (P1-1): у `ВзаиморасчётыСПокупателями` основная =
  **пустая ссылка** (старые записи не трогаем, новых с константой не пишем); у
  `ВзаиморасчётыСПоставщиками` основная = значение константы (так пишется уже сейчас).
- `Движение(... Сумма ...)`: `Сумма` **всегда в основной валюте**. Внутри — `РаботаСВалютами.
  ВалютаИКурсОбъекта(ОбъектРасчётов)` (ЗначенияРеквизитовОбъекта для типов с реквизитом `Валюта`,
  привилегированно): валютный объект → `Валюта` объекта, `СуммаВВалюте = Окр(Сумма / Курс, 2)`;
  иначе основная и `СуммаВВалюте = Сумма`. Необязательный параметр `СуммаВВалюте` — точная сумма
  документа для движения на сам документ (без ошибки округления). Позиционный `Валюта` поставщиков
  остаётся для совместимости, для валютного объекта переопределяется.
- Документы со своей валютой переводят суммы в основную **до** вызова `Движение`, курсом своего
  документа (`ВалютаИКурсДокумента`): `ПоступлениеТоваровУслуг`, `РеализацияТоваровУслуг`,
  `ВозвратПоставщику`, `ВозвратПоставщикуНалоговый`, `НалоговаяНакладнаяПокупка` (P1-3, в т.ч.
  `ДанныеПоступлений`/`ДолгПоПоступлениям`/`ОплатыПоПоступлениям` — `Стр.Сумма × курс накладной`).
- Реализация/поступление: `СуммаРаспределения` = `СуммаРегл`; `ТЧЗачётАвансов.Сумма` — в основной
  (аванс — оплата в MAD); `ПроверитьСуммуАвансовТоварногоДокумента` сравнивает с `СуммаРегл`.
- `СформироватьПоДопРасходам`: доп. расходы поступления в валюте документа → `× курс`; объект
  расчётов — сам документ. У реализации — без изменений.
- `ДополнительныеРасходы.РаспределитьНаСебестоимость`: суммы `ТЧДополнительныеРасходы` × курс.
- `ЗаказыПоставщикам` при поступлении и при возврате поставщику: `Окр(Стр.Сумма × курс, 2)`.
- `Продажи`: `Выручка` и `НДС` = суммы ТЧ × курс реализации.
- Единый признак валютности (P2-5): `СерииИРазмещение.ОбъединитьТоварыССериями` и
  `ЦеныНоменклатурыПоставщиков` переходят на `ВалютаИКурсДокумента` (курс — из объекта).
- `ЗаполнитьИтогиДокумента` (общий, P2-4): `СуммаРегл` шапки и строк — только при `ЕстьРеквизит`,
  курс из `ВалютаИКурсДокумента`.
- `ПередЗаписью` обоих документов: флажок снят → `Валюта = основная`, `КурсВалюты = 1`.
- Запрет (P2-1): `ВозвратОтПокупателя` и `НалоговаяНакладная` (продажная) по валютной реализации —
  отказ в `ОбработкаПроверкиЗаполнения` (основание/отгрузки валютные), не только при вводе на основании.

   валютой ≠ основной (поступление, возврат, налоговая накладная покупки) → `СуммаВВалюте = Сумма`,
   `Сумма = Окр(Сумма × курс регистратора, 2)`; регистратор в основной (оплаты) → `СуммаВВалюте =
   Окр(Сумма / курс объекта, 2)`; `Валюта` = валюта объекта. Наборы по регистратору, `Загрузка`.
3. `ЗаказыПоставщикам` регистраторов из п.1 → `Сумма × курс`.
4. Остальные записи не трогаем: `СуммаВВалюте` новых ресурсов в старых записях = 0, читателей у неё в
   этой волне нет. Реструктуризация `ВзаиморасчётыСПокупателями` (новое измерение + ресурс) при
   обновлении перестраивает таблицы движений и итогов — время на крупной базе отметить в отчёте (P2-3).

## Печать (P2-2)

Подпись валюты (`Devise`) в печати реализации берётся из `Договор.ВалютаВзаиморасчётов` — меняю на
валюту документа при `ВВалюте`, иначе как было. Сумма прописью — в валюте документа.
Договор с валютой взаиморасчётов ≠ основной при выборе в документе включает флажок и ставит валюту.

## Права

`КурсыВалют`: чтение — всем ролям с чтением `Валюты` (в т.ч. казначейство, P3-3); в `Движение` курс читается привилегированно; изменение — по образцу
