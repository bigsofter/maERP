# Присоединённые файлы в документах

Запрос владельца 2026-11-10: «В документах возможность присоединения файлов типовым механизмом дополнительных файлов».
Сборка 2.0.17.9. Круг 3 плана (ревью круга 1: два P0, P1, P2; круга 2: два P0 — разобраны ниже, раздел «Ответ на ревью»).

## Что есть

- Регистр сведений `ПрисоединённыеФайлы` (измерения `Объект` — `ОпределяемыйТип.ВладельцыПрисоединенныхФайлов`,
  `Связь`, `ID`; ресурс `Данные` — хранилище; файл в базе или на диске по константе `ХранитьФайлыНаДиске`) и
  `ПрисоединённыеФайлыНаличие` (признак «есть файлы» по владельцу, тот же определяемый тип).
- Форма списка регистра: добавить файлы, открыть двойным щелчком, сохранить на диск, удалить. Владелец — из отбора
  `Объект`.
- Модули `ПрисоединённыеФайлыКлиент`, `ПрисоединённыеФайлыВызовСервера` (привилегированный), `ПраваНаФайлы`.
- Подключено к карточкам справочников и к КП (команда «Вложения» формы КП). Из документов в типе было 8, формы
  кроме КП команды не имели.

## Что делаю

1. **Определяемый тип** `ВладельцыПрисоединенныхФайлов` — ссылки всех документов, **кроме кадровых и зарплатных**
   (`КадровыйПриказ`, `НачислениеЗарплаты`, `ВыплатаЗарплаты`, `ПлатёжнаяВедомостьНаАванс`,
   `ТабельУчётаРабочегоВремени`, `ПриказНаНачислениеУдержание`): список файлов общий и без RLS по владельцу (Р13),
   имена и комментарии вложений к ним увидели бы все роли с правом на регистр. Итого 47 документов. Реструктуризация
   двух регистров — только расширение составного типа измерения.
2. **Общая команда** `ФайлыДокумента` («Файлы», `ПрикрепитьФайл24`, `FormCommandBarImportant`, `PictureAndText`),
   тип параметра — те же 47 документов без КП (у КП своя «Вложения»). Модуль команды:
   - параметр — ссылка или массив (первый элемент);
   - пустая ссылка — сообщение «Запишите документ, чтобы присоединить файлы», без автозаписи;
   - нет права просмотра регистра — сообщение (`ПрисоединённыеФайлыВызовСервера.ДоступенПросмотрФайлов()` →
     `ПраваНаФайлы.ПравоПросмотраФайлов()`, право по ролям пользователя явно, как в `ПравоНаВладельца`);
   - иначе форма списка регистра с отбором `Объект` = документ, владелец — форма-источник, ключ уникальности —
     документ (как у КП).
   **Подключение в формах.** Основные формы всех документов имеют `autoFill` у командной панели формы
   (проверено скриптом по `Form.form`: панель верхнего уровня). Без автозаполнения — только служебные формы
   (мобильные формы `ЗаданиеНаПересчет`, `ФормаДокументаECommerce` заказа покупателя — роль `ECommerce` прав на
   регистр не имеет, формы выбора и параметров). Формы списков — свои панели без автозаполнения: в списках команды
   нет, это не обещается.
   **Права на команду.** `View` выдаётся явно ролям, у которых есть `View` регистра файлов: `Оператор`, `Кладовщик`,
   `Логист`, `МенеджерПоПродажам`, `МенеджерПоЗакупкам`, `ОператорПроизводства`, `Казначей`, `БухгалтерПоЗарплате`,
   `PDV`. `Руководитель` (`setForNewObjects=true`, прав на регистр нет) — явный `View=false`, чтобы не видеть
   мёртвую кнопку. `ЛичныйКабинет`, `MobileClient` — без команды. `Администратор` — все права по умолчанию.
3. **Права изменения файлов.** `ПравоИзмененияВладельца` — для всех документов право «Изменение» документа (было
   только КП); справочники — прежнее поведение (TECHDEBT). Набор записей регистра проверяет это в `ПередЗаписью`,
   поэтому запрет действует и на форму записи, и на удаление в списке.
4. **Удаление файлов с диска по ключам** (закрывает пункт TECHDEBT «`УдалитьФайлыСДиска` удаляет пути, переданные с
   клиента»): `ПолучитьМассивУдаляемыхФайлов` и `УдалитьФайлыСДиска` удалены. Новая
   `ПрисоединённыеФайлыВызовСервера.УдалитьФайлыУдалённыхЗаписей(Ключи)`: принимает только
   `РегистрСведенийКлючЗаписи.ПрисоединённыеФайлы`, для каждого ключа проверяет право изменения владельца и то, что
   записи с этими `Объект` + `ID` в регистре **уже нет**, путь строит на сервере (`КаталогХраненияФайлов` \ UUID
   владельца, маска `<ID>.*`, каталог не создаётся; пустая константа — диск не трогается). «Записи нет» проверяется
   по `ID` у **любого** владельца: каталог — только UUID владельца, и ссылка другого типа с тем же UUID не выдаст
   файл живой записи за удалённый. Возвращает типы
   владельцев для оповещения. Форма списка запоминает ключи в `ПередУдалением` и зовёт функцию в `ПослеУдаления`;
   карточка номенклатуры — после записи пустого набора.
5. **Личный кабинет партнёра.** У роли `ЛичныйКабинет` был `View` регистра: после расширения он мог бы открыть
   список и увидеть имена файлов всех документов. Кабинету регистр нужен только программно — картинки товаров в
   `ЛичныйКабинетПартнера` (наборы записей с отбором по товару и навигационная ссылка на `Данные`). Поэтому:
   - `View` регистра у роли снимается (список и форма записи не открываются);
   - чтение регистра ограничивается RLS `ГДЕ Объект ССЫЛКА Справочник.Номенклатура`;
   - привилегированная выдача файла (`ПодготовитьФайлыДляПередачиНаКлиент`) требует новой
     `ПраваНаФайлы.ПравоЧтенияФайловВладельца`: у **одной роли** пользователя есть и `Чтение` владельца, и `Просмотр`
     регистра. Кабинет (чтение заказов есть, просмотра регистра нет) файлы документов не получает, хотя бы и знал
     ключ. Других вызовов выдачи нет: её зовут только формы списка и записи регистра, которым и так нужен
     `Просмотр`, — внутренние роли ничего не теряют.
6. **Тесты** (`ТестыДокументов`, рядом с правами файлов КП): каждый документ, кроме кадровых, — в типе владельцев
   и в типе параметра команды (кроме КП), кадровые — ни там, ни там; кладовщик (заказ покупателя только для
   чтения) файлы заказа не меняет и читает, оператор меняет; удаление по ключам пропускает живую запись и
   обрабатывает удалённую, подмена владельца ссылкой другого типа с тем же UUID при живой записи пропускается;
   кладовщик файл заказа получает, личный кабинет — нет. Реестр `docs/TESTS.xlsx` — ручной сценарий «Файлы из формы документа».
7. **Версия** 2.0.17.9, «Что нового» на четырёх языках, хаб.

## Не делаю

- Колонку «есть файлы» в списках документов, команду в формах списков.
- RLS регистра по правам на владельца для внутренних ролей (Р13). **Риск принят владельцем 2026-11-10** (после круга 3
  ревью плана): у внутренних ролей `Read` всего регистра без RLS — роль видит в общем списке «Файлы» имена файлов
  документов, которых сама не читает, и, зная ключ, может получить содержимое файла, хранящегося в базе, навигационной
  ссылкой на `Данные` (проверка выдачи в `ПодготовитьФайлыДляПередачиНаКлиент` защищает только этот путь). Поэтому
  кадровые документы исключены. Записано в TECHDEBT.
- Права ролей на сам регистр не расширяю.

## Ответ на ревью круга 1

- P0 удаление путей с клиента — п. 4.
- P0 раскрытие сведений о вложениях — кадровые и зарплатные исключены (п. 1), личный кабинет ограничен RLS (п. 5),
  остаток — TECHDEBT/Р13.
- P1 право на общую команду — п. 2, «Права на команду».
- P2 формы без автозаполнения — п. 2, «Подключение в формах»: основные формы заполняются, исключения перечислены.
- Круг 2, P0 привилегированная выдача в обход RLS кабинета — п. 5: `View` снят, выдача требует чтения владельца и
  просмотра регистра в одной роли.
- Круг 2, P0 подмена типа владельца при удалении — п. 4: проверка живой записи по `ID` у любого владельца.

## Проверить вживую (владелец)

- Личный кабинет партнёра: картинки товаров в каталоге и в истории показываются после снятия `View` регистра.
- Круг 3, P0 содержимое вложений в обход проверки выдачи — риск принят владельцем 2026-11-10 (раздел «Не делаю»).
- Круг 3, P0 перезапись дискового файла подменой владельца через `ПоместитьФайлВХранилище` — метод принимает только
  `РегистрСведенийМенеджерЗаписи.ПрисоединённыеФайлы` (структура с клиента — исключение) и отказывает, если запись с
  тем же `ID` есть у другого владельца.
