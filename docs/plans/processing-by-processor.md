# План: отчёт «Переработка по переработчикам»

Запрос владельца (2026-10-31): отчёт производства со статистикой переработки в разрезе переработчиков — передачи и
приёмы по заказам клиентов, по аналогии с отчётом прослеживаемости партий (`docs/plans/lot-traceability.md`), плюс
остатки у переработчиков в том же отчёте. Учёт времени — Drissotex. Отчёт тиражный: в конфигурации клиент не
упоминается.

## Поиск готового (по просьбе владельца)

- maERP: `Reports/ТоварыВПереработке` — остатки и обороты регистра `ТоварыВПереработке` таблицей (сырьё по
  переработчику, передаче, заказу), без документов приёма и продукции. Рабочее место производства, закладка
  «Переработка» — список передач со статусами, без приёмов и итогов.
- УНФ 3.0.14: `Reports/ЗапасыПереданные`, вариант «Запасы, переданные в переработку» — та же ведомость остатков и
  оборотов, без продукции и сроков.
- Готового отчёта «передачи + приёмы по заказам + остатки + срок» нет — делаем новый.

## Решения владельца (2026-10-31)

| Вопрос | Решение |
|---|---|
| Группировка | **Переработчик → заказ клиента**; передачи без заказа — группой «Без заказа» |
| Статистика в итогах | **Срок переработки, дней** (средний по принятому; старейшая незакрытая передача) |
| Учёт времени | Drissotex |

## Уровень изменения

Существенное (новый отчёт, права, меню). Без изменения проведения и хранимых данных. Порядок: план →
**`ai-review-plan`** → реализация → `ai-test` → **`ai-review`** → `ai-final-check` → отчёт
`.ai/reports/processing-by-processor.md`.

## Исходные данные (по `src/cf`)

Регистр `ТоварыВПереработке`: измерения `Контрагент` (переработчик), `Номенклатура`, `Характеристика`, `Серия`,
`Партия`, `ДатаПартии`, `ПередачаВПереработку`, `ЗаказПокупателя`; ресурсы `Количество`, `Сумма`, `СуммаНДС`. Приход —
передача (`Регистратор` = передача), расход — `ПоступлениеИзПереработки` (списание сырья по партиям передачи; измерение
`ПередачаВПереработку` расход копирует из партии).

Все документы отчёта — **проведённые** (у регистров — активные движения; у документов, взятых не из регистров, —
`Проведен`).

**Заказ группы — заказ передачи, а не измерение `ЗаказПокупателя` движения** (ревью плана, круг 1, P1): обработчик
обновления волны 12 (`ОбновлениеПрограммыОбработчики.ЗаполнитьЗаказВДвиженияхПереработки`) проставлял заказ по
основанию **регистратора**, поэтому у старого расхода заказ может не совпасть с заказом прихода той же партии
(`ТоварыВПереработке.ПодставитьОтборПоЗаказу` по той же причине отбирает по передаче). Группа движения и остатка =
`ВЫРАЗИТЬ(ПередачаВПереработку.Основание КАК Документ.ЗаказПокупателя)` — срез по `ПередачаВПереработку` сбалансирован
на любых данных. Пустая передача или передача без заказа — «Без заказа».

| Секция | Источник | Правило |
|---|---|---|
| **Передано** | приход `ТоварыВПереработке` с `Регистратор ССЫЛКА Документ.ПередачаВПереработку` в периоде | Строка: дата, № передачи, номенклатура (+характеристика), количество, единица. Группа — `Контрагент` × заказ передачи (см. выше) |
| **Принято** | расход `ТоварыВПереработке` с `Регистратор ССЫЛКА Документ.ПоступлениеИзПереработки` в периоде → переработчик и заказы **передач**, чьё сырьё списано; продукция — `ПоступлениеИзПереработки.ТЧГотоваяПродукция` | Поступление попадает в группу каждого заказа, сырьё которого оно списало. Продукция поступления одна на все строки сырья (связь «какое сырьё — какая продукция» не хранится), поэтому при списании сырья **нескольких заказов** строка продукции выводится полностью в каждой группе с пометкой «◐» (тот же принцип, что в прослеживаемости: долями не делим). Строка: дата, № поступления, продукция, количество, единица |
| **Хвосты** | **проведённые** `ПоступлениеИзПереработки` в периоде без расхода `ТоварыВПереработке` (приёмка хвоста продукции без сырья после дочистки; круг 2, P2 — черновики и отменённые не берутся) | **Входят в «Принято» и итоги** (круг 2, P1: продукция переработчика принята и оприходована — `ТоварыВНаличии.СформироватьОприходованиеПоПоступлениюИзПереработки`; отчёт считает принятое у переработчика, а не распределение по партиям). Строка помечается «хвост без сырья», группа — переработчик × заказ по `Основание` (заказ; передача — её заказ; иначе «Без заказа»); хвост сам образует группу, если других строк у неё нет. В **средний срок не входит** — передачи-источника нет |
| **Остаток у переработчика** | `ТоварыВПереработке.Остатки` на конец периода с измерением `ПередачаВПереработку` | Строка: номенклатура (+характеристика), количество, единица, старейшая передача остатка (дата, №). Группа — `Контрагент` × заказ передачи; остатки, сальдированные по передаче, асимметрией заказов не искажаются |

**Период.** Передано и принято — движения внутри периода; остаток — на конец периода (`Граница(Конец, Включая)`).
Группа выводится, если у неё есть хотя бы одна строка в любой секции (передача до периода с остатком на конец —
группа с одной секцией остатка).

### Срок переработки

- **Средний срок, дней** (по группе и по переработчику): по **различным парам «поступление — передача»** из расхода
  `ТоварыВПереработке` поступлениями в периоде — среднее `РАЗНОСТЬДАТ(Передача.Дата, Поступление.Дата, ДЕНЬ)` по парам,
  **без веса количеством** (ревью плана, круг 1, P2: количества сырья разных единиц складывать нельзя). Хвосты в срок не
  входят (сырья нет).
- **Старейшая незакрытая передача, дней**: по остатку на конец периода — максимум
  `РАЗНОСТЬДАТ(ПередачаВПереработку.Дата, КонецПериода, ДЕНЬ)` среди измерений `ПередачаВПереработку` с остатком > 0.
- Пусто, если данных нет (нет приёмов / нет остатка).

## 1. Отчёт `ПереработкаПоПереработчикам`

Синоним «Переработка по переработчикам» (fr «Sous-traitance par sous-traitant», en «Processing by processor», es
«Procesamiento por procesador»); основная форма — общая `ФормаОтчёта` (избранное, образ, варианты).

**Схема компоновки** — для настроек и отбора групп: набор «Группы переработки» — `Переработчик`, `Заказ` (заказ
передачи), `Клиент` (`Заказ.Контрагент`) из трёх источников, объединением с отбором различных: движения
`ТоварыВПереработке` в периоде, остатки на конец периода, хвостовые поступления в периоде. Параметры: `Период` (`СтандартныйПериод`, по умолчанию текущий месяц; значения `НачалоПериода`/`КонецПериода`
задаёт модуль, как в прослеживаемости — без выражений). Отборы пользователя: переработчик, клиент, заказ.

**Вывод — модуль объекта** `ПриКомпоновкеРезультата` (`СтандартнаяОбработка = Ложь`), по образцу
`ПрослеживаемостьПартий`:
1. группы — СКД в коллекцию значений по настройкам;
2. пакет запросов (временная таблица групп; передачи; приёмы с признаком «несколько заказов»; хвосты; остатки со
   старейшей передачей; сроки) — псевдонимы без ключевых слов (`В`, …), без соединений с вложенными запросами и
   виртуальными таблицами напрямую (сначала во временные таблицы), без `ИЛИ` в условиях соединения;
3. вывод: группа переработчика (шапка с итогами: передано / принято / остаток по единицам, средний срок, старейшая
   передача; **«Принято» переработчика — по различным поступлениям**: смешанное поступление, показанное полностью в
   нескольких группах заказов, в итог переработчика входит один раз — итоги групп заказов при «◐» неаддитивны, это
   сказано подписью под итогом переработчика; ревью плана, круг 1, P2), внутри — группы заказов (шапка: заказ, клиент, срок), три секции бок о бок: «Передано», «Принято»,
   «Остаток у переработчика»; итоги секций по единицам измерения; хвосты — строками «Принято» с пометкой «хвост без сырья», в итогах;
   расшифровка — ссылка на документ в ячейке номера.
4. Легенда «◐» внизу, если были смешанные приёмы.

## 2. Размещение и права

«Производство» → панель отчётов рядом с «Товарами в переработке»; функциональная опция `ИспользоватьПереработку`;
права `Use`/`View` — `Кладовщик` (как у `ТоварыВПереработке`), `Администратор`/`Руководитель` — автоматически.
`scripts/menucheck.py`.

## 3. Проверка

- `lint.sh` (ноль новых), `refcheck.py`, `queryfields.py`, `menucheck.py`; смок формирует варианты (66 → 67).
- Сценарий уровня 3 `ПереработкаПоПереработчикам`: переработчик П1 — две передачи по заказу A и одна по заказу B; одно
  поступление списывает сырьё обоих заказов (смешанное); второе поступление — только A; хвостовое поступление без
  сырья; переработчик П2 — передача без заказа с остатком. Проверки по тексту результата:
  - группы П1/A, П1/B, П2/«Без заказа»; передачи — в своих группах;
  - смешанное поступление — в A и в B с «◐», второе — только в A;
  - остаток П1/A и П2 — строками с датой старейшей передачи;
  - средний срок П1/A — среднее по парам «поступление — передача» без веса количеством (круг 2, P2), от дат сценария;
  - хвост — в «Принято» и в итоге переработчика с пометкой, в среднем сроке не участвует;
  - **итог «Принято» П1 численно** = смешанное поступление + второе поступление + хвост (каждое один раз), а не сумма
    итогов групп A и B (круг 3, P2);
  - отбор по переработчику П2 — только его группа.

## Риски

0. Ревью плана, круг 1 (reject): P1 заказ группы — по передаче, не по измерению движения; P2 хвосты — источник групп;
   P2 средний срок — по парам без веса количеством; P2 итог «Принято» переработчика — по различным поступлениям.
   Круг 2 (reject): хвосты — в «Принято» и итогах (это принятая продукция), вне среднего срока; только проведённые;
   критерий теста срока — без веса.
   Круг 3 — **approve_with_changes**: P2 — численная проверка итога переработчика добавлена в сценарий.

1. Количества сырья и продукции в разных единицах — итоги секций строго по единицам, «выход %» не считаем (не
   выбран владельцем).
2. Заказ группы — реквизит `Основание` передачи; передача, проведённая до заказа и переоснованная позже, попадёт в
   группу текущего основания.
3. Срок по документам с датой поступления раньше передачи (исправленные задним числом) — отрицательные дни не
   отбрасываем молча: берём как есть, они видны в среднем.
