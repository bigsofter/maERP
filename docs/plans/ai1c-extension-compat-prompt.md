# Промпт: maERP под расширение «TinyCIO ИИ-помощник» (Татьяна) без правок расширения

> Подготовлен 26.10.2026 в сессии tinycio (расширение 3.1.2). Запускать в репозитории maERP отдельной сессией.

## Задача

Доработать конфигурацию maERP так, чтобы в неё ставилось и работало расширение «TinyCIO ИИ-помощник» (ИИ-бухгалтер
Татьяна, файл `tinycio-ai-<версия>.cfe` из портала my.tinycio.com) **без единой правки расширения**. Расширение одно для
всех конфигураций заказчиков (БП 3.0, отраслевые, maERP): оно вызывает функции БСП 3.1 по их штатным именам и
сигнатурам, а конфигурация обязана их предоставить. Языки (ru/fr/en/es) расширение доработает само, их не трогать.

Сейчас расширение в maERP **не компилируется**: из 17 функций БСП, которые оно вызывает, в maERP есть 3 (и то
`ДлительныеОперацииКлиент` — старой редакции). Вызов несуществующего метода общего модуля — ошибка компиляции ВСЕГО
модуля расширения; `Попытка` её не ловит.

Работаем по правилам maERP (`CLAUDE.md`, `docs/UNF-ADOPTION.md` — механизмы УНФ как образец, `checklist` tiny1C перед
правкой метаданных, `docs/TESTING.md`, `docs/RELEASING.md`). Правим только EDT-проект `src/cf`.

## Источник реализации

Рекомендую не писать свои аналоги, а **перенести механизмы БСП 3.1 из УНФ** (`build/unf_14_123` — УНФ 3.0.14 с БСП
3.1.x, XML-выгрузка; образец переноса — `docs/UNF-ADOPTION.md`): подсистемы «Длительные операции», «Безопасное хранилище»
и нужные функции `ОбщегоНазначения`/`ОбщегоНазначенияКлиентСервер`/`СтандартныеПодсистемыСервер`/`Пользователи`.
Переносить точечно (только перечисленное ниже и его зависимости), не всю БСП. Если зависимость тянет за собой
половину БСП — свой минимальный аналог с ТЕМ ЖЕ именем, сигнатурой и формой результата.

## Контракт: что вызывает расширение (обязательно, все — `Экспорт`)

Имена модулей и методов — ровно такие. Формы структур — как в БСП 3.1 (расширение читает перечисленные поля).

### 1. Длительные операции (сервер)

| Вызов | Как используется в расширении |
|---|---|
| `ДлительныеОперации.ПараметрыВыполненияФункции(ИдентификаторФормы)` | → Структура; расширение присваивает `ОжидатьЗавершение = 0`, `КлючФоновогоЗадания`, `НаименованиеФоновогоЗадания`, `ЗапуститьВФоне = Истина` (если свойство есть) |
| `ДлительныеОперации.ВыполнитьФункцию(Параметры, ИмяФункции[, П1, П2])` | ИмяФункции — экспортная функция ОБЩЕГО МОДУЛЯ РАСШИРЕНИЯ (`"TinyCIO_Агент.ВыполнитьШаги"` и др.), выполняется в фоновом задании; → Структура `Статус` ("Выполняется"/"Выполнено"/"Ошибка"), `ИдентификаторЗадания`, `АдресРезультата` (результат функции во временном хранилище), `КраткоеПредставлениеОшибки`, `ПодробноеПредставлениеОшибки`, необязательно `ИнформацияОбОшибке`. Если задание с тем же ключом уже идёт — `Статус = "Ошибка"` с текстом платформы («…с таким значением ключа уже выполняется» / «…same key value is performed already»): расширение ловит его по тексту и повторяет |
| `ДлительныеОперации.СообщитьПрогресс(Процент, Текст)` | из фонового задания, `Процент` может быть пропущен; `Текст` — строка JSON до 20 000 символов (события хода). Вне фонового задания — не должно ломать (расширение оборачивает в `Попытка`) |
| `ДлительныеОперации.ОтменитьВыполнениеЗадания(ИдентификаторЗадания)` | «Остановить» хода |

### 2. Длительные операции (клиент)

| Вызов | Как используется |
|---|---|
| `ДлительныеОперацииКлиент.ПараметрыОжидания(ФормаВладелец)` | ФормаВладелец — форма или `Неопределено`; расширение присваивает `ВыводитьОкноОжидания = Ложь`, а при наличии свойств — `Интервал` (с), `ОповещениеОПрогрессеВыполнения`, `ОтменятьПриЗакрытииФормыВладельца = Ложь`, `ВыводитьСообщения = Ложь` |
| `ДлительныеОперацииКлиент.ОжидатьЗавершение(ДлительнаяОперация, ОповещениеОЗавершении, ПараметрыОжидания)` | ДлительнаяОперация — результат `ВыполнитьФункцию`. Оповещение о завершении получает `Неопределено` (задание отменено) или Структуру `Статус`, `АдресРезультата`, `КраткоеПредставлениеОшибки`. Оповещение о прогрессе получает Структуру состояния с полем `Прогресс` — Структура с `Текст` (строка из `СообщитьПрогресс`); расширение должно получать события в порядке отправки |

Старые клиентские `ОжидатьЗавершение`/`ПараметрыОжидания` maERP заменить версией БСП 3.1 и **проверить всех
собственных вызывающих maERP** (они могли рассчитывать на старую форму).

### 3. Безопасное хранилище

| Вызов | Как используется |
|---|---|
| `ОбщегоНазначения.ЗаписатьДанныеВБезопасноеХранилище(Владелец, Данные, Ключ)` | Владелец — СТРОКА `"ИИАссистент.TinyCIO"`, ключи `"BaseId"`, `"Secret"`, `"Url"`, данные — строки |
| `ОбщегоНазначения.ПрочитатьДанныеИзБезопасногоХранилища(Владелец, "BaseId, Secret, Url")` | → Структура с этими ключами (`Неопределено`, если значения нет) |
| `ОбщегоНазначения.УдалитьДанныеИзБезопасногоХранилища(Владелец, Ключ)` | сброс ключа подключения |

Расширение вызывает их в привилегированном режиме. Хранилище — как в БСП: отдельный регистр сведений, доступ только
в привилегированном режиме, строковый владелец поддержан. Это секрет подключения к сервису — в обычные регистры,
константы и хранилища настроек не класть.

### 4. ОбщегоНазначения / ОбщегоНазначенияКлиентСервер / Пользователи / СтандартныеПодсистемыСервер

| Вызов | Требование |
|---|---|
| `ОбщегоНазначения.ОбщийМодуль(Имя)` | модуль по имени; ОБЯЗАН находить и модули расширения (`TinyCIO_Сервер`, `TinyCIO_Инструменты`, `TinyCIO_Запросы`, `TinyCIO_Разметка`, `TinyCIO_КлиентСервер`, `TinyCIO_ПовтИсп`); нет модуля — исключение (вызовы в `Попытка`) |
| `ОбщегоНазначения.ПодсистемаСуществует(ПолноеИмя)` | `"СтандартныеПодсистемы.ВариантыОтчетов"`, `"СтандартныеПодсистемы.ДатыЗапретаИзменения"` — в maERP `Ложь` (если подсистем нет); не падать |
| `ОбщегоНазначения.ОбъектМетаданныхДоступенПоФункциональнымОпциям(ОбъектМетаданных)` | Булево; учитывать ФО maERP |
| `ОбщегоНазначения.ИдентификаторОбъектаМетаданных(ПолноеИмя)` | должна существовать (компиляция); зовётся только при наличии «Вариантов отчётов» |
| `ОбщегоНазначения.МестаИспользования(МассивСсылок)` | ТаблицаЗначений, колонки `Ссылка`, `Данные`, `Метаданные`; желательно `ЭтоСлужебныеДанные`, `ВспомогательныеДанные`. Поиск привилегированно ВНУТРИ функции (у пользователя может не быть прав на служебные таблицы) |
| `ОбщегоНазначенияКлиентСервер.СтруктураURI(Строка)` | Структура как в БСП; расширение читает `Схема`, `Хост` |
| `Пользователи.ЭтоСеансВнешнегоПользователя()` | **`Ложь` для всех пользователей maERP и никогда не падает**: при исключении расширение считает сеанс внешним и закрывает помощник |
| `СтандартныеПодсистемыСервер.ВерсияБиблиотеки()` | строка версии (перенесённой БСП или своя, напр. `"3.1.x-maERP"`); показывается помощнику как «версия БСП» |

### 5. Мягкие зависимости (не обязательны)

Вызываются через `ОбщийМодуль` в `Попытка`, отсутствие не ломает: `ОбщегоНазначения.РазрешенДоступКИнтернетСервисам`,
`ПолучениеФайловИзИнтернета.ПолучитьПрокси`, `ВариантыОтчетов.*`, `ДатыЗапретаИзменения.*`,
`БухгалтерскиеОтчетыВызовСервера.ПодготовитьОтчет`. Добавлять не нужно.

## Прочие требования к конфигурации

- Язык с именем **`Русский`** (код `ru`) — расширение заимствует его по имени; основной язык не менять. Режим
  совместимости ≥ 8.3.24 (сейчас 8.5.1 — ок).
- **Не заводить общие модули и глобальные имена, совпадающие с локальными переменными расширения** (ловушка 3.1.2 у
  Камцвета: общий модуль `ПолныеПрава` → «Поле объекта недоступно для записи»). Проверка — гейт расширения по списку
  общих модулей maERP (команда в «Приёмке»).
- Расширение приносит свои роли «TinyCIO ИИ-помощник: использование» и «…: настройка» и свои справочники/регистры.
  Проверить, что администратор maERP может выдать роли расширения пользователям в своём интерфейсе пользователей
  (если права выдаются только профилями maERP — дать способ). Описать в `docs/DEPLOY.md`.
- Расширение ходит в интернет (HTTPS к my.tinycio.com) из сервера 1С — ничего не блокировать.

## Приёмка

1. Все 17 вызовов существуют и экспортны — проверка из корня maERP (EDT-проект):

```bash
python3 - <<'PY'
import os,re
calls="""ДлительныеОперации.ВыполнитьФункцию ДлительныеОперации.ОтменитьВыполнениеЗадания ДлительныеОперации.ПараметрыВыполненияФункции
ДлительныеОперации.СообщитьПрогресс ДлительныеОперацииКлиент.ОжидатьЗавершение ДлительныеОперацииКлиент.ПараметрыОжидания
ОбщегоНазначения.ЗаписатьДанныеВБезопасноеХранилище ОбщегоНазначения.ИдентификаторОбъектаМетаданных ОбщегоНазначения.МестаИспользования
ОбщегоНазначения.ОбщийМодуль ОбщегоНазначения.ОбъектМетаданныхДоступенПоФункциональнымОпциям ОбщегоНазначения.ПодсистемаСуществует
ОбщегоНазначения.ПрочитатьДанныеИзБезопасногоХранилища ОбщегоНазначения.УдалитьДанныеИзБезопасногоХранилища
ОбщегоНазначенияКлиентСервер.СтруктураURI Пользователи.ЭтоСеансВнешнегоПользователя СтандартныеПодсистемыСервер.ВерсияБиблиотеки""".split()
bad=0
for c in calls:
    m,f=c.split('.'); p=f'src/cf/src/CommonModules/{m}/Module.bsl'
    ok=os.path.exists(p) and re.search(r'(?im)^\s*(Функция|Процедура)\s+'+f+r'\s*\([^)]*\)\s*Экспорт',open(p,encoding='utf-8-sig').read())
    print('ok ' if ok else 'НЕТ',c); bad+=not ok
raise SystemExit(bad)
PY
```

2. Нет конфликтов имён с переменными расширения — из репозитория tinycio (`services/ai1c-service/extension`):
   распаковать `.cfe` (`python3 -I tools/cfe_extract.py ../internal/extfile/TinyCIO-AI.cfe <каталог>`), подставить в
   копию `tools/readonly_names.json` поле `base_common_modules` = список общих модулей maERP, прогнать
   `python3 -I tools/check_readonly_props.py <каталог> --names <копия.json>` → `нарушений 0`.
   (На maERP 2.0.16.98 до доработки — 0 нарушений; новые модули проверить так же.)
3. Живая проверка на копии базы maERP (ставит владелец): «Расширения → Добавить из файла» `tinycio-ai-3.1.2.cfe`
   применяется без ошибок; «Конфигуратор → Проверка модулей» с расширением — без ошибок; окно чата открывается;
   «Подключить» сохраняет ключ, после перезапуска 1С ключ читается; вопрос «Какие организации есть в базе?» получает
   ответ с живыми событиями хода (прогресс); «Остановить» останавливает ход; второй вопрос подряд не падает на ключе
   задания.
4. Собственные сценарии maERP, затронутые заменой «Длительных операций», — по `docs/TESTING.md`.

## Что НЕ делать

- Не править расширение и не просить его поправить — оно общее для всех заказчиков.
- Не тянуть БСП целиком и не менять основной язык.
- Не класть секрет подключения вне безопасного хранилища.
