Реализуем фазу 3 проекта `docs/plans/branded-print.md` (maERP, 1С 8.5.1, EDT-проект `src/cf`, ветка `develop`).
Последняя сборка — 2.0.16.69 (фаза 2: КП из реализации по опции, коммит 313ef1c); эта — **2.0.16.70**. Содержание

## Уроки прошлых сборок (учесть сразу)

- Печать, которая пишет данные, — только в транзакции; смок формирует формы в транзакции с откатом (фаза 2).
- Адаптер выбирается **по типу ссылки**, а не по менеджеру печати: любые проверки доступа и опций — в самом адаптере.
  Привилегированное чтение — только после `ВЫБРАТЬ РАЗРЕШЕННЫЕ` с явными соединениями связанных справочников (RLS роли
  «Клиент» на контрагентов и договоры) и в той же транзакции, что проверка.
- Роль `ОператорПроизводства` не видит цены и суммы (`ОграничитьВидимостьРеквизитовПоТипу`) — печатные формы с
  ценами для неё — вопрос `ai-security`.
- Номер документа фиксированной длины дополнен пробелами (tiny1C bsl-026): номера сравнивать через `СокрЛП`.
- Опцию КП в тестах читать константой (bsl-023); сценарии ручных КП включают её константой в транзакции.
- `ib-sync.sh`: «Экспорт EDT не удался (rc=204)» и SIGSEGV загрузки — повторить; `src/cf` не трогать во время экспорта;
  ожидание фоновых прогонов — по процессу или свежему маркеру, а не по `rc=` из старого лога.
- Отчёты 1С — CRLF и BOM: `tr -d '\r'`; итог тестов — строка `ИТОГ;Сценариев=…`, а не `grep -c '^ОК;'`.
- Внешние обработки headless — `/DisableUnsafeActionProtection` с маской своей базы (workflow-015); два клиента на
  файловой базе стартуют с разносом 5 с.
- Отказ записи посреди сценария портит транзакцию — настоящий отказ только последним шагом.
- Циклы в shell — через `bash -c`; `rm` внутри `bash -c` блокируется проверкой безопасности — писать отчёты в новые
  файлы.
- `ai-review --verify` смотрит дельту: закрытое прошлым кругом может прийти «partially_fixed» — сверять с файлом.
