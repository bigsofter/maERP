# Учёт станков: выработка станка по номенклатуре (2.0.16.46, Drissotex)

Задача владельца 2026-10-09: «Возможность ввести производительность машины (кг/ч) в разрезе номенклатуры
(Оборудование + номенклатура + выработка) или в разрезе оборудования без номенклатуры (как сейчас)». Решения
владельца в тот же день: **только кг/ч** (без «в день»); номенклатура строки — **материал или продукция** (обе роли).

**Уровень — существенная**: новая табличная часть справочника (реструктуризация), смена правила расчёта, общего для
проведения требования, планировщика, автоплана и отчётов. Порядок: план → **`ai-review-plan` (обязателен)** →
реализация → `ai-test` → **`ai-review` (обязателен)** → `ai-database` (реструктуризация, чтение справочника внутри
транзакции проведения) → `ai-final-check` → отчёт `.ai/reports/machine-output-by-item.md`. `ai-security` не нужен:
права ролей не меняются (см. п. 1). Перед правкой `.mdo` и `Form.form` — `checklist` tiny1C по файлу (`core`,
`greenfield`).

## 2. Правило выбора выработки

Входные данные загрузки: станок `S`, продукция требования/строки заказа `P` (`ТребованиеНакладная.Номенклатура`,
`СтрокаПродукции.Номенклатура`), материалы `M_i` с весом `w_i` кг (как сейчас — `ВесНоменклатурыКг`; для нормы
отчётов — израсходованные), `W = Σ w_i`, переналадка `T` мин. `V(S)` — общая выработка, `V(S, X)` — строка ТЧ.

**Правило (одно, по приоритету):**

1. **Продукция.** Есть строка `V(S, P)` → `Часы = W / V(S, P) + T / 60`. Норма продукции описывает переработку всего
   её сырья на этом станке — материалы не смотрим.
2. **Материалы.** Строки для `P` нет, но хотя бы у одного материала есть `V(S, M_i)` → время складывается по
   материалам: `Часы = Σ_{i∈A} w_i / V(S, M_i) + W_ост / V(S) + T / 60`, где `A` — материалы со своей нормой,
   `W_ост = Σ_{i∉A} w_i` (суммой весов, а не вычитанием — без отрицательного остатка от округления). Если `W_ост > 0`,
   а `V(S)` не задана — ошибка «нет выработки для материалов …: время загрузки не посчитать» со списком материалов.
3. **Станок.** Ни продукции, ни материалов в ТЧ нет → `Часы = W / V(S) + T / 60` — **ровно как сейчас**; нет `V(S)` —
   прежний текст «У станка не задана выработка».

Округление — один раз в конце (`ОкруглитьЧасы`), переналадка входит один раз. Характеристика не учитывается (норма —
на номенклатуру).

Почему сумма времён, а не средняя выработка: кг/ч — скорость переработки килограмма; станок перерабатывает все
килограммы загрузки, время аддитивно, поэтому `Σ w_i / V_i` — точное время, а «взвешенная выработка» `W / Σ(w_i/V_i)`
даёт то же самое. Альтернатива «самый медленный материал задаёт темп всей загрузки» (`W / min V_i`) — вопрос
владельцу 2. Приоритет продукции над материалами — продукция конкретнее (норма для изделия уже учитывает его
состав) — вопрос владельцу 1.

**Вопросы владельцу** (реализация идёт по правилу выше, ответ меняет только функцию п. 3):
1. Есть строка и для продукции, и для её материала — берётся норма продукции. Так?
2. Материалы с разными нормами — время суммой по материалам (кг каждого / его норма), остальное — по общей выработке.
   Так, или вся загрузка по самому медленному материалу?
3. Подтвердить: изменение норм не пересчитывает уже запланированные требования (как и сейчас для общей выработки);
   пересчёт — повторным «Разместить»/переносом.
4. Нужна ли норма на группу номенклатуры (одна строка на группу материалов)? Сейчас — только элементы.

## 3. Единая функция и все места пересчёта

### 3.1 Чтение норм

`ЗагрузкаСтанков.ВыработкиСтанков(Станки) Экспорт` — **один пакетный запрос** по массиву станков:
шапка (`Выработка`, `ВремяНаСменуЗаказа`) + `Справочник.ПроизводственноеОборудование.ВыработкаПоНоменклатуре`
(`Ссылка В (&Станки)`). Возвращает `Соответствие`: станок → `Структура(Выработка, ВремяНаСменуЗаказа, ПоНоменклатуре)`,
`ПоНоменклатуре` — `Соответствие` номенклатура → выработка. Объём: станков единицы–десятки, строк — сотни.

### 3.2 Расчёт

`ДлительностьЗагрузки(Станок, Вес, Реквизиты = Неопределено, Состав = Неопределено) Экспорт` — **сигнатура
расширяется, а не заменяется** (вызовы с двумя параметрами и тест `ДлительностьЗагрузки(Станок, 600)` работают как
раньше — правило 3):
- `Реквизиты` — элемент `ВыработкиСтанков` (или прежняя структура/строка без `ПоНоменклатуре` — тогда только правило 3);
  `Неопределено` — читается `ВыработкиСтанков(Станок)`.
- `Состав` — `Структура(Продукция, ВесаПозиций)`: `ВесаПозиций` — `Соответствие` номенклатура → кг.
  `Неопределено` — только общая выработка.
- Возврат: `Часы`, `ТекстОшибки` + новое `Источник` (`"Продукция"`, `"Материалы"`, `"Станок"`) — для теста и
  возможной подсказки; потребители берут поля по имени.

`ВесНоменклатурыКг` дополняется полем `ВесаПозиций` (`Соответствие` номенклатура → кг до округления итога) —
аддитивно, существующие потребители читают `Вес`/`БезВеса`. `ВесМатериаловЗагрузки` пробрасывает его.
Комментарии экспортных методов обновить (назначение, параметры, возврат).

**Почему расчёт не в запросе.** Норма зависит от килограммов, а вес — единое правило `КгНаЕдиницу`/`ВесНоменклатурыКг`
(весовая единица, `ВесЗнаменатель`, позиции без веса). Перенос его в текст запроса дублирует правило веса во втором
месте. Запрос только приносит нормы (один дополнительный пакет на отчёт), формула — одна функция в BSL. Если позже
понадобится норма в СКД — колонка вычисляется тем же циклом до передачи во внешний набор.

### 3.4 Формы и печать

- Форма требования-накладной: поле «Длительность» показывает пересчитанное при записи значение — правок формы нет.
- Закладка «Станки», планировщик, «Готовы к запуску»: колонки «Вес», «Часы» прежние, значения — по новому правилу.
- Печатных форм с выработкой нет (`git grep` по макетам пуст) — не затрагиваются.

## 5. Тесты

`ТестыДокументов` — новый сценарий **`ВыработкаПоНоменклатуре`** (станок `НовыйСтанокСценария`: 120 кг/ч, 15 мин;
продукция P1, P2; материалы M1 и M2 с весом единицы 1 кг):
1. Состав ФО содержит ТЧ (дополнить проверку состава в `СтанкиИОбслуживание`).
2. Строки ТЧ: P1 → 200, M1 → 60. `ДлительностьЗагрузки` с составом:
   - P1, {M1: 60, M2: 540} → `600 / 200 + 0,25 = 3,25`, источник «Продукция»;
   - P2, {M1: 60, M2: 540} → `60 / 60 + 540 / 120 + 0,25 = 5,75`, источник «Материалы»;
   - P2, {M2: 600} → 5,25, источник «Станок» (как раньше); без состава → 5,25 (обратная совместимость).
3. Второй станок без общей выработки, строка M1 → 60: {M1: 60} → 1,25; {M1: 60, M2: 10} → текст ошибки с M2.
4. Требование P1 на станке 1 (материалы 600 кг): `Длительность = 3,25`, `ПланОкончание` по режиму; ручная длительность
   по-прежнему перекрывает.
5. `ГотовыеКЗапуску(Станок)` — строка заказа P1: часы по норме продукции; колонки `ВесаПозиций` в результате нет.
6. Автоплан: станок 2 с общей 120 и строкой P1 → 600 — черновик ставит P1 на станок 2 (раньше заканчивает).
7. Норма завершённого требования P2 (израсходовано M1 30 кг, M2 30 кг) → `30/60 + 30/120 + 0,25 = 1,00` в
   «Выработке станков»; требование станка 2 без нормы для материала → норма 0 и предупреждение OEE.
8. **Последним шагом — настоящий отказ:** запись станка с дублем номенклатуры в ТЧ и со строкой без выработки —
   `Записать()` отклонено проверкой заполнения.

Регрессия без ТЧ: `ОтчетыСтанков` (норма 0,75), `ЗакладкаСтанков` (1,25 ч), `АвтопланСтанков`, `РастяжениеСтанков`
должны пройти без правок ожиданий — это и есть проверка «пустая таблица = как сейчас».

Смок (`scripts/smoke.sh`) открывает форму элемента станка — новая таблица попадает в «открыть все формы».
Реестр: строка `ВыработкаПоНоменклатуре` в `docs/TESTS.xlsx` и таблице `docs/TESTING.md` (машина; человеку — ввод
нормы в карточке и сверка часов на закладке «Станки»).

## 6. Риски

- **Обратная совместимость.** Пустая ТЧ → правило 3, формула и тексты ошибок прежние; сигнатуры расширены
  необязательными параметрами; поля результатов добавлены, не переименованы. Проверяется регрессией п. 5.
- **Блокировки.** Новых управляемых блокировок нет: нормы читаются из справочника так же, как сейчас `Выработка`, —
  в том числе внутри транзакции проведения требования (под блокировкой «Загрузки станков»). Изменение карточки станка
  во время размещения даст ту же гонку, что сейчас с общей выработкой (длительность по прочитанному значению) —
  приемлемо, норма не участвует в остатках.
- **Производительность.** Один дополнительный пакет в `ЗавершенныеТребования` (ТЧ по станкам периода), одно чтение
  норм на вызов «Готовых» и автоплана (кэш по станкам), без запросов в цикле. `ДлительностьЗагрузки` без `Реквизитов`
  (запись одного требования) — один лёгкий запрос, как сейчас `ЗначенияРеквизитовОбъекта`.
- **Хранимые длительности** не пересчитываются при смене норм (вопрос 3) — как сейчас.
- **Реструктуризация** — только новая таблица ТЧ; данные существующих станков не конвертируются. Обновление базы
  клиента — обычное обновление CFU.
- **Семантика номенклатуры в двух ролях.** Одна позиция может быть продукцией одного требования и материалом
  другого — роль определяется контекстом расчёта, а не строкой ТЧ; конфликт «продукция и её материал оба с нормой»
  решает приоритет (вопрос 1).
- **Длина строк и BSL LS** — новые тексты на 4 языках переносом `|`, как в существующих `НСтр`.

## Не делаю

- Норма в «шт/ч» или «в день» (решение владельца — только кг/ч).
- Норма по характеристике и по группе номенклатуры (вопрос 4).
- Показ норм станков в карточке номенклатуры, периодическая история норм.
- Пересчёт уже запланированных требований при изменении норм.
