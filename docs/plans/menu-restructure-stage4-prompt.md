## Целевое меню (§3 плана, уточнить в плане этапа)

```
Склад
[В] Перемещения +   Товары в наличии
├─ Инвентаризация       (ФО ИспользоватьПересчеты) Задания на пересчёт + · Пересчёты · Отчёт по пересчётам
├─ Излишки и списания   Оприходования + · Списания + · Уценки (выровнять: список и «Создать» вместе)
├─ Комплектация         (ФО ИспользоватьКомплектацию) Акты разбора + · Пересортица +
├─ Товары               Товары (Номенклатура, отбор) · Характеристики · Серии · Упаковки · Наборы упаковок
│                       · Штрихкоды ⟵ · Виды свойств номенклатуры
├─ Хранение             Склады (Места хранения) · Ячейки (ФО ИспользоватьЯчейки) · Перевозчики ⟵ · Качество
└─ Отчёты (корень)      Товары в наличии · Ведомость по товарам · Стоимость склада · Движения товара ⟵
                        · Недостаточные запасы · Печать этикеток
```

Решения этапа (без владельца, с записью в план):
- **Отчёты-варианты (§4)**: «Товары в наличии», «Ведомость по товарам на складах», «Стоимость склада» — один отчёт с
  вариантами **только если** источники и модули позволяют без потери смысла (сверить запросы поле к полю, есть ли
  `ObjectModule`); иначе три отчёта под понятными именами, объединение — в TECHDEBT. «Стоимость склада» сейчас в двух
  разделах: оставить в одном (Склад или Бухгалтерия) — решить по правам ролей и правилу 3 §2.
- **«Движения товара»**: починить вариант «ОтчетПоСписанию» (поле «Склад» → место хранения нового регистра, сверить
  схему с запросом поле к полю, tiny1C query-006), снять пропуск смока и строку листа «Пропуски смока» `TESTS.xlsx`,
  вывести в меню — или оставить скрытым с записью, если вариант не спасти.
- **«Ведомость по поступлениям»** — закупочный отчёт: остаётся в «Складе» или уходит в «Закупки» (у кого из ролей
  права и View) — решить.
- **Штрихкоды** (`InformationRegister.ШтрихкодыНоменклатуры`) — вывести в «Товары» или оставить вне меню
  (как сейчас ведутся — из карточки номенклатуры?).
- **Группы под опции** (правило 8 §2): «Инвентаризация» — в `ИспользоватьПересчеты`, «Комплектация» — в
  `ИспользоватьКомплектацию`; ячейки — объект уже в своей ФО, группа «Хранение» не пустеет.
- **Перевозчики и Логист**: кому из ролей видеть «Перевозчиков» после переезда (Логист раздела не видит).
- **«Создать»**: перемещение, оприходование, списание, уценка, задание на пересчёт, акт разбора, пересортица;
  без справочников.

## Ловушки (из этапов 2–3 — не повторять)

1. **Ролевые фрагменты `.cmi`** (tiny1C mdo-007): до переписывания — `git grep -n '<role>' -- '*.cmi'` по подсистемам
   «Склада»; генератор пишет `<for><role>`.
2. **Вывод «объект не используется» — только полным поиском** (tiny1C workflow-013): `git grep -c <Имя> -- src` без
   `head`, отдельно тексты запросов, `registerRecords`, `content` опций. В этапе 3 так ошибочно назвали мёртвым регистр
   надбавок.
3. **Подсистемы** — шесть мест на переименование, uuid сохранять, `git mv`. `git mv` сразу стейджит — коммит плана
   делать до переименования. Сборку стейджить `git add -A`, после — `git show --stat` и проверка NFC/NFD (workflow-007).
4. **Новая команда справочника протекает во все разделы**, где лежит справочник: «Товары» скрыть в Закупках,
   Продажах, Производстве. `Catalog.Контрагенты` в составе «Склада» — скрыть `Покупатели`, `Поставщики`, `OpenList`,
   `Create`. `menucheck.py` — по всем разделам.
5. **Необъявленный параметр формы платформа отбрасывает**; параметры запроса ставить всегда (флаг `Ложь` вне режима).
   С отбором по сегментам `ТипыНоменклатуры` — свои параметры, не общие.
6. **Отчёт, скопированный с другого, / вариант со старого регистра** — поле к полю против источника; проверка схемы до
   базы (внешняя обработка `build/menu/run.sh` или сценарий через `СкомпоноватьРезультат`).
7. **Функция источника с несколькими вызывающими** — новое поведение только по необязательному ключу; остальные
   вызовы получают прежние строки (образец — `ТолькоПросроченные` этапа 3); формы, строящие вывод по настройкам схемы
   отчёта (как `ИнтерфейсКлиент`), проверить отдельно.
8. **Права**: перечислить, кто что **получает и теряет**, по матрице «View на объект × View на группу и корень»;
   права на данные не расширять.
9. **`build/ib` может держать EDT** — работать на копии (`cp -R build/ib build/ib-stage4`, `scripts/ib-sync.sh
   build/ib-stage4`, смок и doctests с тем же аргументом). CLI EDT может зависнуть на «Waiting for permission to
   execute operation 'External export'» (`~/EDT/ws-maERP/.metadata/.log`) — снять **свой** процесс по PID.
10. Значения ФО кэшируются на серверный вызов (bsl-023) — в сценарии не переключать опцию дважды.
11. Не трогать: Казначейство и Бухгалтерию сверх решения по «Стоимости склада» (этап 5), Производство и CRM (этап 6).
