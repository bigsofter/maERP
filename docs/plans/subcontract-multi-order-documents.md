# Закладка «Документы» рабочего места производства — сборки 3 и 4 плана subcontract-multi-order

Редакция плана перед сборкой 3: `docs/plans/subcontract-multi-order.md` («Закладка «Документы» (сборки 3 и 4)»)
требует отдельной редакции деталей интерфейса с повторным `ai-review-plan`. Решения владельца (2026-11-02, переписка):
верхняя закладка «Документы» с видами «Переработка», «Выпуски», «Требования-накладные»; режимы «Документы / Строки», у
переработки ещё «У подрядчиков» — сразу; суммы услуг — по праву видеть суммы; выпуски без заказа вводятся строкой;
требования-накладные — только просмотр и статус (ввод — в АРМ станков), вид показывается при выключенной константе
`ИспользоватьАвтовыпускПриОтгрузке`.

## Поиск готового

- Образец страницы со списком документов и пагинацией — АРМ закупок, `СтраницаСписокПоступлений`
  (`DataProcessors/АРМЗакупки/Forms/Форма`): список-таблица значений, пагинатор `ОбновитьПагинатор`, открытие документа
  двойным щелчком, `ГруппаВерхПриСменеСтраницы`.
- Пагинатор заказов АРМ производства: `СтраницаЗаказов(Отборы, НомерСтраницы, РазмерСтраницы)`, `РазмерСтраницыЗаказов()`.
- Строки передач и поступлений по заказам — `СтрокиПередач`, `СтрокиПоступленийИзПереработки` (отбор по заказу или
  массиву, сборка 2): в режиме «Строки» те же запросы по отбору документов, без нового текста.
- Остатки у переработчика — отчёт `ПереработкаПоПереработчикам` (`ВТ_ОстаткиВсе`) и `ТоварыВПереработке.Остатки`;
  ожидаемое к приёму — `Документы.ПоступлениеИзПереработки.ОжидаемаяПродукция(Передача)`.
- Выпуски — `СтрокиВыпусковИлиОтгрузок`, запись строки выпуска — `ПрименитьДанныеСтрокиВыпуска`; выпуск без заказа
  документ `ВыпускПродукции` допускает (основание необязательно).
- Требования-накладные — форма списка документа и АРМ станков (`DataProcessors/АРМСтанков`); статус — реквизит
  `ТребованиеНакладная.Статус`.

## Устройство

- `ГруппаВерх` — третья страница **«Документы»** (`СтраницаДокументыВерх`). Когда она текущая, `ГруппаНиз` и панель
  свойств скрыты (`ГруппаВерхПриСменеСтраницы`), под шапкой — одна таблица режима; при возврате на «Заказы»/«Продукцию»
  — как было.
- Шапка: «Вид» (переключатель: Переработка / Выпуски / Требования-накладные; последний виден только при выключенной
  константе), «Показать» (Документы / Строки / У подрядчиков — третий только у переработки), отборы: подрядчик (у
  переработки), склад, период (начало, конец; по умолчанию — текущий месяц), «Только незакрытые». Вид, режим и отборы —
  реквизиты формы с `savedData` (форма уже `autoSaveDataInSettings`).
- Данные — серверная функция менеджера `ДанныеЗакладкиДокументов(Параметры)` → Структура: Строки (массив структур
  колонок режима), ВсегоСтраниц. Размер страницы — 50 (как у заказов). Таблица формы — одна таблица значений
  `ДокументыВерх` с колонками-надмножеством; видимость колонок по виду и режиму (`ПрименитьКолонкиДокументов`). Без новых
  метаданных: реквизиты формы, колонки, команды.
- Права: каждый вид читается, только если есть право чтения его документов (как `СтрокиПередач`); суммы услуг и
  себестоимость — по `ПоказыватьСуммы()`; команды записи — по `ПраваРабочегоМеста()`.

## Сборка 3 — «Переработка»

- **Документы**: передачи и поступления из переработки периода (`РАЗРЕШЕННЫЕ`), непомеченные; колонки: Документ
  (представление «Передача №15 от 02.11» / «Поступление №…»), Дата, Подрядчик, Склад, Заказы («№ 12, Клиент; …» по
  заказам строк, у одного заказа — его), Осталось принять (у передачи — сумма количеств `ОжидаемаяПродукция`, у
  поступления — пусто), Услуги (у поступления, по праву), Статус (проведён / черновик). «Только незакрытые» — передачи с
  ожидаемой продукцией > 0 и черновики поступлений. Порядок — дата убыв. Пагинация (ревью плана, P2): без «Только
  незакрытые» — запросом по периоду (`ПЕРВЫЕ` и смещение, как `СтраницаЗаказов`), «Осталось принять» — по документам
  страницы; с «Только незакрытые» — сначала отбор всех передач периода с ожидаемой продукцией > 0 (расчёт по каждой
  передаче периода, период ограничивает объём; по умолчанию — месяц) и черновиков поступлений, затем страница из
  отобранных и ВсегоСтраниц по ним.
- **Строки**: строки сырья передач и продукции поступлений документов текущей страницы «Документов» (тот же отбор):
  Документ, Заказ, Клиент, Номенклатура, Характеристика, Количество, ПФ/ГП (у передачи); только просмотр.
- **У подрядчиков** — состояние **на сейчас**, период к режиму не применяется (ревью плана, P2: ожидаемая продукция
  считается только на текущий момент — `ОжидаемаяПродукция` вычитает все проведённые поступления и текущее выполнение
  заказа; смешивать её с историческими остатками нельзя): `ТоварыВПереработке.Остатки()` без даты по подрядчику
  (отбор) — Подрядчик, Передача, Заказ, Клиент, Материал, Характеристика, Количество, Сумма (по праву); ожидаемая
  продукция к приёму — отдельным блоком строк той же таблицы с видом строки «ожидается» (Продукция, Количество) по
  передачам с остатком сырья **и** по проведённым передачам периода отбора (ревью плана, круг 2, P2: без правил расхода
  поступление списывает весь остаток сырья при частичной приёмке, а непринятая продукция остаётся ожидаемой — набор
  передач только «с остатком» её теряет); ожидаемое считается на сейчас, период лишь ограничивает набор передач без
  остатка. Подпись режима — «У подрядчиков (на сейчас)».
- Команды: «Открыть» (двойной щелчок — форма документа), «Провести» / «Отменить проведение» (отмеченные документы:
  запись с проведением / отменой; запреты — проверки самих документов, текст отказа — в панель сообщений, как у
  «Статуса» нижних закладок), «Поступление из переработки» (по отмеченной проведённой передаче: форма нового поступления
  с `Основание`), «Акт» (печать акта передачи / приёмки отмеченных — подменю печати документа).

## Сборка 4 — «Выпуски» и «Требования-накладные»

- **Выпуски / Документы**: ручные выпуски и автовыпуски периода — Документ, Дата, Склад оприходования, Заказ
  (основание, у автовыпуска — заказ реализации), Продукция (первая строка и «+N»), Статус; «Только незакрытые» —
  черновики.
- **Выпуски / Строки**: строки готовой продукции; **новая строка без заказа** — вид «Выпуск» с пустым заказом:
  `ЗаписатьСтрокуДокумента` допускает пустой `Заказ` только для вида выпуска из этой закладки (признак
  `БезЗаказа` в данных строки), документ — новый выпуск без основания; правка и удаление строк — тем же путём, что на
  закладке «Выпуск» (запреты автовыпуска и порядка выпуска/отгрузки — прежние, у выпуска без заказа порядок не
  проверяется — заказа нет). Общий валидатор `ТекстЗапретаЗначенийСтрокиДокумента` требует продукцию в заказе
  (`СтрокаЗаказаПродукции`, `ПолуфабрикатыЗаказаКВыпуску`; ревью плана, круг 2, P1): при `БезЗаказа` у вида выпуска
  проверка наличия в заказе пропускается, остаются продукция, количество и владелец характеристики. `НовыйВыпуск` сейчас берёт организацию из заказа строки (ревью плана, P1): без заказа —
  организация из значений по умолчанию (`РаботаСДокументами.ЗаполнитьРеквизитыПоУмолчанию`, основная организация
  пользователя), её нет — отказ строки «Укажите основную организацию в настройках пользователя» до записи.
- **Требования-накладные / Документы**: требования периода — Документ, Станок, Заказ, Номенклатура, Количество,
  Статус, План/Факт; **Строки** — материалы требования; связанные выпуски — колонка «Выпуски». Только просмотр; команда
  «Статус» — тот же путь, что в АРМ станков (ревью плана, круги 1–2, P1): «Запустить», «Завершить», «Отменить» —
  `ЗагрузкаСтанков.ВыполнитьДействиеТребования(Требование, Действие, КоличествоФакт)`; «Завершить» сначала спрашивает
  выпущенное количество (`ПоказатьВводЧисла`, по умолчанию — количество требования, ноль и отказ — без действия;
  функция сама отказывает при факте ≤ 0, иначе `ПодготовитьЗавершение` подставил бы план), «Отменить» — вопрос Да/Нет;
  «Вернуть в работу» — `ТребованияНакладные.ВернутьВРаботу(Требование)` (право руководителя, отмена выпуска), исключение
  — в панель сообщений; своей записи статуса нет. Печать — подменю печати документа. Вид скрыт при включённой константе
  `ИспользоватьАвтовыпускПриОтгрузке`.

## Тесты

`ТестыДокументов`, новый сценарий `АРМЗакладкаДокументов`: «Переработка / Документы» — общая и одно-заказная передачи и
поступление: заказы в колонке, остаток к приёму, «Только незакрытые» и страницы по отобранным; «Строки» — заказ строки;
«У подрядчиков» — остаток по заказам и ожидаемое; суммы скрыты без права — настройкой пользователя «Видеть суммы
производства» (`ЗаписатьПравоСуммАРМ`, как сценарий прав сумм рабочего места; ревью плана, P2), функция данных читает
`ПоказыватьСуммы()` сама, параметра нет. Сборка 4: выпуск без заказа строкой — документ без основания, проведён,
продукция вне заказов допускается; требования — список, «Завершить» с фактом и отказ при нуле. Смок открывает форму (страница не текущая); вид страницы на клиенте — руками у владельца.

## Ревью плана

Круг 1 (`ai-review-plan`, reject, 5 находок): выпуск без заказа — организация (P1), статус требования — бизнес-операции
`ТребованияНакладные` (P1), «У подрядчиков» — только на сейчас (P2), пагинация «Только незакрытые» (P2), права сумм в
тесте — настройкой пользователя (P2). Все внесены выше.

Круг 2 (reject, 3 находки): валидатор строки выпуска требует продукцию в заказе (P1), «Завершить» требования — с
вводом факта через `ЗагрузкаСтанков.ВыполнитьДействиеТребования` (P1), ожидаемое у подрядчиков — не только по передачам
с остатком сырья (P2). Внесены выше.

Круг 3 — **approve_with_changes**, 3 P2: (1) старые передачи без остатка сырья вне периода в «У подрядчиков» не видны —
принято как ограничение, подпись режима говорит «передачи с остатком и передачи периода»; (2) `ВыполнитьДействиеТребования`
возвращает текст отказа, а не бросает исключение — текст выводится в панель сообщений, исключение ловится только у
`ВернутьВРаботу`; (3) «Только незакрытые» считает ожидаемое по каждой передаче периода — период больше трёх месяцев с
этим флажком отклоняется текстом «Сузьте период до трёх месяцев».

## Риски

- Объём формы: страница добавляется скриптом по образцу, проверки forms-012/018/021/022/025 (`colfont.py`, id и имена).
- Выпуск без заказа строкой — правка общего пути записи строк (`ТекстЗапретаЗаказовСтроки` требует заказ): допускается
  только при признаке `БезЗаказа` и виде выпуска, остальные виды — прежний отказ.
- Производительность: страницы по 50 документов, «Строки» и «Осталось принять» — по документам текущей страницы.

## Отклонения реализации от плана

- Сборки 3 и 4 сданы одной передачей на тест — версия 2.0.16.144 (решение владельца: «делай их сразу обе»).
- Пагинация: страница режется из списка ссылок периода, а не запросом `ПЕРВЫЕ` со смещением: документы двух видов
  (передачи и поступления) объединяются по дате в коде, период ограничивает объём. «Только незакрытые» у передач —
  отбор после запроса по ожидаемой продукции, как в плане.
- Колонки «Пометка» нет: документы для «Провести» берутся из выделенных строк, как на нижних закладках.
- «Провести»/«Отменить проведение» документа одного заказа и выпуска без заказа — путь «Статуса» нижних закладок
  (`ВыполнитьДействиеСтатусаДокумента` с заказом самого документа); документ нескольких заказов — отказ «проводится в форме
  документа» (как «Статус» сборки 2).
- «У подрядчиков» без отбора по складу: остатки у подрядчика склада не имеют.
- Строка выпуска правится на закладке, только если выпуск без основания, не автовыпуск и не по требованию.
