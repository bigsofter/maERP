# Сборка 2.0.17.10: отрасль «Телефоны и аксессуары», серийный учёт IMEI — основа (`industry-phones`)

Волна 4 мастер-плана `docs/plans/retail-chain.md`, сборка 4.1. Волна делится на сборки:

- **4.1 (эта)** — отрасль, флаг серийного учёта у номенклатуры, уникальность IMEI в базе, «один экземпляр» и запрет
  минуса для серийной номенклатуры на уровне регистра остатков, IMEI обязателен при оприходовании, ордерный склад.
- **4.2** — ввод и скан IMEI в документах и на кассе (поиск товара по IMEI, создание серии из скана), срок гарантии в
  чеке и накладной, возврат только по чеку продажи.
- **4.3** — протокол незавершённой продажи на кассе (требование 5 мастер-плана).

## Что есть сейчас

- `Отрасли`: Торговля, Строительство, Прочее, Ткани; `ПрименитьОтрасль` ставит константу и заводит отраслевые
  доп. реквизиты номенклатуры (`ОписаниеОтраслевогоРеквизита`, `ДобавитьОтраслевойРеквизит`, идемпотентно);
  `ОтрасльПоКоду` (код хаба) неизвестный код молча превращает в Торговлю.
- Серии: справочник `СерииНоменклатуры` (владелец — номенклатура), `ТЧСерии` у документов с `КодСтроки` и
  `УказаноНесколькоСерий`, `СерииИРазмещение.ОбъединитьТоварыССериями` раскладывает строки по сериям для движений;
  у перемещения, списания, оприходования, пересортицы серия — колонка `ТЧТовары`. Константа и ФО
  `ИспользоватьСерииНоменклатуры` есть, но ни одна форма и модуль их не читают (колонки серий видны всегда).
- `ТоварыВНаличии` — измерения Склад, Номенклатура, Характеристика, **Серия**, Партия; `СписатьНоменклатуру`
  по умолчанию отказывает при нехватке, но многие пути пишут движения без контроля (`РазрешитьНедостачи`, приход,
  «в пути», подчинённый склад, ордера). Модуль набора: `ПередЗаписью` (прежние позиции), `ПриЗаписи` (инвариант
  склада станка, оповещение о минимальном остатке); промежуточная очистка при перепроведении распознаётся
  (`Количество() = 0` и регистратор проведён, признак `ОчисткаПройдена`).
- `Номенклатура.Качество` — справочник `КачествоТоваров` (новый/б/у/восстановленный — значения справочника, нового
  реквизита не нужно).

## 1. Отрасль

- Значение `Отрасли.ТелефоныИАксессуары` (синонимы на 4 языках); `ОтрасльПоКоду` — коды `phones`, `телефоны`,
  `electronics`, `mobile`.
- `ПрименитьОтрасль` для телефонов: включает константу `ИспользоватьСерииНоменклатуры` и заводит доп. реквизиты
  номенклатуры **Модель** (строка 100), **Совместимость** (строка 250, для аксессуаров), **ГарантияМесяцев** (число 3,
  0), **Цвет** и **Память** (значения дополнительного справочника) — цвет и память не характеристики: у клиента их нет,
  ФО характеристик выключена, остатки по цвету не нужны.
- Мастер первого запуска и «Настройки программы» уже вызывают `ПрименитьОтрасль` — список отраслей берётся из
  перечисления.

## 2. Флаг серийного учёта

- `Номенклатура.УчетПоСерийнымНомерам` (Булево, «Учёт по серийным номерам (IMEI)»). **Только для типа «Товар»**,
  не участвующего в технологических картах (материалом или продукцией): производство и автовыпуск серийный товар
    не двигают, их каскады блокировок серийного учёта не касаются; проверка типа и техкарт — первым шагом включения,
  до любых блокировок остатков (отказ без ожиданий), и **повторно — после исключительной блокировки номенклатуры**;
  запись техкарты до чтения флагов берёт разделяемые блокировки номенклатуры всей своей продукции и материалов
  (пространство барьера) и удерживает их до конца транзакции — включение флага и добавление товара в техкарту
  сериализуются, успешна только одна операция; смена типа серийной позиции и добавление её в техкарту — отказ.
    **Без характеристик**: у товара с элементами `ХарактеристикиНоменклатуры` или движениями с характеристикой флаг не
  ставится; создание характеристики серийному товару и движение серийного товара с непустой характеристикой —
    отказ (характеристика вне ключа контроля экземпляра; цвет и память — доп. реквизиты, п. 1). Запись характеристики
  (создание и смена владельца) берёт разделяемую блокировку старого и нового владельца в пространстве
  `Справочник.Номенклатура` до чтения флага; включение флага повторяет проверку характеристик после исключительной
  блокировки товара. Не для комплектов: у
  номенклатуры типа «Комплект» флаг не ставится, смена типа серийной позиции на «Комплект» — отказ (списание
  раскладывает комплект на составляющие без серии — серия комплекта ушла бы из контроля). Комплект с серийными
  составляющими (серия составляющей при разложении не назначается) — проведение реализации такого комплекта отказывает
  до сборки с назначением серий составляющим (TECHDEBT). В карточке товара — флажок рядом с качеством;
  групповое изменение реквизитов ставит его группе. Видимость флажка — при константе серий.
- Переход остатков: флаг ставят, когда магазины готовы сканировать. **Остаток без серии**, набранный до флага,
  остаётся остатком с пустой серией; продаётся без IMEI только в его пределах (минус пустой серии запрещён, п. 4).
  Привязка IMEI к лежащему товару — пересортицей «без серии → серия» (`ПересортицаТоваров`, серия — колонка строки).

## 3. Уникальность IMEI в базе

- Регистр сведений `СерийныеНомера`: измерение `СерийныйНомер` (строка 150 — как наименование серии, без усечения), ресурсы `Серия`
  (`СерииНоменклатуры`), `Номенклатура`. Смена номера серии без движений освобождает прежний номер; номер серии с
  движениями не меняется (п. 4а). Запись — в модуле объекта `СерииНоменклатуры` (`ПередЗаписью`: если владелец
  с серийным учётом — нормализация наименования (без пробелов по краям), исключительная управляемая блокировка
  регистра по значению `СерийныйНомер`, проверка: номер занят другой серией → отказ «IMEI … уже зарегистрирован у …»;
  `ПриЗаписи` — запись регистра (смена номера — удаление прежней записи); `ПередУдалением` — удаление записи).
  Конкурентное создание двух серий с одним IMEI сериализуется блокировкой по значению — вторая видит запись первой.
- Серии, заведённые до флага, в регистр не попадают; при установке флага у номенклатуры её серии регистрируются
  (модуль объекта `Номенклатура`, `ПриЗаписи` при переходе флага Ложь → Истина; дубль — отказ записи номенклатуры с
  перечнем номеров).

## 4. Один экземпляр и запрет минуса — регистр `ТоварыВНаличии`

Проверка в модуле набора `ТоварыВНаличии`, для ключей набора с номенклатурой с серийным учётом (флаг читается одним
запросом по номенклатуре набора; у несерийной — ничего не делается):

- **Протокол блокировок** (единый порядок для всех операций с движениями товаров): **номенклатура → IMEI →
  документы-основания и покрывающие документы → склады**. Барьер по номенклатуре: `СерийныйУчет.
  ЗаблокироватьСерииДокумента` сначала берёт **разделяемую** управляемую блокировку `Справочник.Номенклатура` по
    товарам документа (новые строки и прежние движения, любой флаг, **включая составляющие комплектов** —
  `НоменклатураССоставляющими`; состав комплектов перечитывается под блокировкой, изменился — отказ «состав изменён,
  повторите») и только после неё читает флаг и блокирует IMEI;
  включение флага берёт исключительную блокировку той же ссылки (п. 4а) — документ либо видит включённый флаг до
  своих складских блокировок, либо включение ждёт его завершения. **Каскад платежа**: `ПередЗаписьюПлатежа` перед
  блокировками оснований вызывает `ЗаблокироватьСерииДокументов` для оснований и покрывающих налоговых документов,
  которые затем перепроводит `ПерепровестиПокрывающиеДокументы` (товары и IMEI — по их строкам и прежним движениям),
    поэтому перепроведение покрывающего документа новых ожиданий в пространстве IMEI не создаёт. То же **для любого
  документа на основаниях** (реализация, поступление и др., чьё проведение вызывает `ПерепровестиПокрывающиеДокументы`):
  `ЗаблокироватьСерииДокумента` собирает номенклатуру и IMEI **каскада** — текущий документ, его покрывающие налоговые
  документы и остальные основания этих покрывающих документов — и захватывает их одним упорядоченным набором до
  блокировок оснований; после захвата состав каскада перечитывается, изменился — отказ «документы изменены,
    повторите» (без добора ключей). **После** захвата блокировок оснований и покрывающих документов полный набор
  ссылок, номенклатуры и IMEI каскада проверяется ещё раз против предварительно захваченного: появился новый ключ
  (другой сеанс успел заменить серию) — отказ «документы изменены, повторите» до вложенного перепроведения, без
  добора блокировок; то же для платежей и остальных каскадных входов.
- **Получить отгрузку** (`ПотребностиТорговыхТочек.ПолучитьОтгрузку`): внутри транзакции до `ЗаблокироватьДокумент`
  собирает номенклатуру и IMEI списания-основания и существующего черновика получения, захватывает их
  (`ЗаблокироватьСерииДокументов`), затем блокирует документы и перечитывает исходные данные; набор ключей изменился —
  отказ без добора.
- **Остаточный риск взаимоблокировок**: вход записи движений, не охваченный предварительным захватом (новый код,
  внешние обработки), при встречном порядке блокировок получает от платформы ошибку взаимоблокировки — откатывается
  одна операция, пользователь повторяет её. Инварианты п. 4 при этом не нарушаются: проверки выполняются под
  блокировками в транзакции записи, откат не оставляет частичных данных. Новые входы записи движений подключаются к
  протоколу через `ЗаблокироватьСерииДокументов` (правило в комментарии модуля `СерийныйУчет`). Документы, которые в собственном `ПередЗаписью` уже блокируют основания или себя
  (возврат от покупателя — `ЗаблокироватьОснованияВозврата`, реализация — `НалоговыеДокументыНаОснованиях.
  ПередЗаписьюДокумента`, остальные регистраторы с блокировками в `ПередЗаписью`), первой строкой `ПередЗаписью`
  вызывают `СерийныйУчет.ЗаблокироватьСерииДокумента(ЭтотОбъект)` — раньше своих блокировок; пакетные входы рабочих
  мест захватывают IMEI всех документов пакета до любых других блокировок. Подписка (ниже) — для регистраторов без
  собственного `ПередЗаписью` и как страховка (повторная блокировка удержанных номеров ожиданий не создаёт).
- **Блокировка и её порядок**: IMEI блокируются **первыми**, до складских блокировок документа и до автоматической
  очистки движений при перепроведении — новой подпиской `ПередЗаписью` документов-регистраторов `ТоварыВНаличии`
    (при записи в режимах «Проведение» и «Отмена проведения», **независимо от константы серий** — по наличию серийной
  номенклатуры в новых данных документа или в прежних движениях регистратора; константа управляет только
  интерфейсом): номера IMEI серий серийной
  номенклатуры из реквизитов `Серия` всех табличных частей документа (новые) и из прежних движений `ТоварыВНаличии`
    этого регистратора (старые); «серии» — все реквизиты шапки и табличных частей документа типа
  `СправочникСсылка.СерииНоменклатуры` (в т. ч. `СерияОприходование` пересортицы с её `НоменклатураОприходование`) —
  исключительная управляемая блокировка регистра `СерийныеНомера` по значению
  `СерийныйНомер`, одним вызовом `Заблокировать`. `ПередЗаписью` документа выполняется до очистки движений и до
  `ОбработкаПроведения`, где документы берут складские блокировки, поэтому у всех путей проведения, перепроведения и
    отмены порядок один: IMEI → склад. **Внешние точки захвата складских блокировок** — процедуры документов
  `ЗаполнитьБлокировкуПроведения` (поступление, реализация, возвраты, поступление из переработки, выпуск, передача в
  переработку), которые рабочие места (`АРМПроизводство`, `ОрдераСклада`, `ЗагрузкаСтанков`, `ТребованияНакладные`)
  вызывают до записи документа, — первой строкой вызывают `СерийныйУчет.ЗаблокироватьСерииДокумента(ЭтотОбъект)`:
  немедленная блокировка номеров IMEI документа (новых и прежних движений) при активной транзакции, до того как
  вызывающий заблокирует склады. Рабочее место, собирающее блокировку нескольких документов, заполняет её по всем
    документам до `Заблокировать` — IMEI всех документов пакета захвачены раньше складов: пакет сначала вызывает
  `СерийныйУчет.ЗаблокироватьСерииДокументов(Документы)` — сбор новых и прежних IMEI всех документов, удаление дублей,
  **один** вызов `Заблокировать` с ключами, упорядоченными по номеру (единый порядок у всех сеансов); последующие
  вызовы по отдельным документам новых ожиданий не создают (номера уже удержаны). Модуль набора повторно блокирует номера своих записей (в той же транзакции —
    уже удержаны). **Прямая запись набора** без документного входа (корректировка регистров, обработки) в
  `ПередЗаписью` набора проходит тот же барьер: разделяемая блокировка номенклатуры новых и заменяемых движений →
  чтение флага → блокировка IMEI → остатки; флаг, прочитанный под барьером, не устаревает до записи (включение флага
  ждёт исключительно).
  Разные IMEI не конфликтуют; один IMEI — сериализуется.
- **Снимок прежних ключей**: в `ПередЗаписью` (при замещении) прежние записи регистратора по серийной номенклатуре —
  «склад, номенклатура, серия, вид движения, количество» — добавляются в снимок в `ДополнительныеСвойства` набора.
  Промежуточная очистка при перепроведении пишется **тем же** объектом набора (bsl-029), поэтому снимок, взятый при
  очистке, доживает до окончательной записи; проверка после окончательной записи идёт по объединению ключей снимка
  и нового набора (заменённый или удалённый проданный IMEI проверяется).
- **Промежуточная очистка** распознаётся только по явному контексту и только у регистраторов, у которых платформа
  её делает (`registerRecordsDeletion = AutoDelete`; у `AutoDeleteOnUnpost` и `AutoDeleteOff` — например,
  оприходование — промежуточной очистки нет, и первая запись набора при перепроведении проверяется как окончательная):
  подписка `ПередЗаписью` документа при перепроведении (документ уже проведён, режим «Проведение», режим удаления
  движений документа — автоудаление) ставит в `ДополнительныеСвойства` набора
  `ДокОбъект.Движения.ТоварыВНаличии` признак `ЭтапЗаписиДвижений = "Очистка"` (контекст сбрасывается при каждом
  вызове записи документа); набор, записанный пустым с этим признаком, проверку пропускает и переводит признак в
  «Запись». Пустая запись без контекста (отдельный набор с отбором по регистратору, отмена проведения) —
  проверяется по прежним ключам.
- **Физическое направление**: каждая запись серийной номенклатуры нормализуется — приход = «Приход» с положительным
  количеством или «Расход» с отрицательным; расход — наоборот. Все правила прихода, хронология и проверка
  исторических приходов при включении флага считают **физический приход** этой единой функцией (отрицательный расход
  без серии — приход, требует разрешения).
- **После записи** (`ПриЗаписи`), кроме промежуточной очистки, по объединённым ключам:
  - **владелец серии**: непустая серия принадлежит номенклатуре движения и зарегистрирована в `СерийныеНомера` за
    ней — иначе отказ;
      - **непустая серия**: остаток на каждом складе **строго 0 или 1** и сетевой остаток (сумма по всем складам) — 0 или
    1 (дробное количество серии — нарушение: экземпляр не делится между складами) — **по всей хронологии** движений
    IMEI (накопительно по моменту времени всех регистраторов, а не только конечный остаток): перенос даты прихода
    позже продажи, продажа датой раньше прихода дают промежуточный минус — отказ. Движений у одного IMEI единицы —
    расчёт в коде по выборке движений ключа; склад «в пути» — обычный склад,
    при перемещении сетевой итог не меняется;
            - **налоговая переклассификация**: пары движений регистратора на основаниях
    (`НалоговыеДокументыНаОснованиях.ЭтоРегистраторНаОснованиях`, `ПереклассифицироватьТовары`) с нулевым итогом по
    полному ключу «склад, номенклатура, серия» правилами прихода (разрешения, состояние экземпляра) не проверяются —
    это не физический приход; хронология и остатки 0/1 проверяются как обычно. Ненулевой итог такого регистратора —
    по общим правилам.
  - **состояние экземпляра (непустая серия)**: агрегированное количество прихода IMEI регистратором (сумма по всем
    строкам и складам набора) — не больше 1; приход допустим, если в снимке прежних записей этого регистратора есть
    приход этого IMEI и новое агрегированное количество не больше прежнего (перепроведение исходного документа, в т. ч.
    исправление цены после продажи; добавить вторую строку того же IMEI нельзя), либо у IMEI нет движений других
    регистраторов (первый приход), либо это перемещение (тот же набор списывает этот IMEI) или возврат от покупателя.
    Новый обычный приход уже поступавшего IMEI — отказ.
    - **отмена первичного прихода**: первичный приход — приход IMEI документом прихода (не перемещением и не возвратом
    от покупателя). Если запись такого регистратора убирает приход IMEI (снимок содержал приход, новый набор — нет:
    отмена проведения, перепроведение без строки, удаление), а у IMEI есть движения других регистраторов (зависимая
    история — продажа, возврат, перемещение, даже взаимно компенсированные), — отказ; повторное проведение после
    допустимой отмены — снова первый приход. Отмена приходной стороны перемещения или возврата от покупателя
    проверяется только остатками (по складам 0/1, сеть 0/1): предшествующие документы зависимыми не считаются.
  - **пустая серия**: остаток на каждом складе ≥ 0; **приход пустой серии** допустим только: историческим
    регистратором в пределах разрешения из регистра `ПереходныеПриходыБезСерии` (п. 4а: при включении учёта
    фиксируются регистратор, склад и количество его прихода без серии; разрешение не исчезает при распроведении, его
    можно отменить, исправить цену и провести снова, но не увеличить количество; новый документ «задним числом»
            разрешения не имеет), перемещением (тот же набор списывает пустую серию той же номенклатуры в том же количестве) и
    возвратом от покупателя по основанию (п. 4б).
    Любой другой приход без IMEI — отказ при любом пути проведения (без `ПроверитьЗаполнение`, приходный ордер,
    корректировка регистров);
  - **склады**: серийный товар не движется на складе, у которого указан подчинённый склад, на подчинённом складе
    (приход поступления дублируется на зеркало, расход его не списывает) и на складе, ордерном на дату движения
    (реализация не списывает до расходного ордера), — отказ.
  - Нарушение — отказ записи с текстом «IMEI … уже на складе …» / «IMEI … нет на складе …» / «нет остатка без IMEI» /
    «приход без IMEI запрещён» / «серия … принадлежит другому товару» / «серийный товар не учитывается на складе …».
- Отмена проведения (пустой набор, регистратор уже не проведён) — проверяется по снимку: отмена прихода проданного
  IMEI отклоняется.
- **Упаковки**: коэффициент упаковки в конфигурации всегда 1 (`РассчитатьКоэффициентЕдиницы`), количество серии в
  `ТЧСерии` равно количеству в базовых единицах; сетевая проверка «не больше 1 на IMEI» отклонит иное разворачивание.
- Это узкое исключение из политики отрицательных остатков (решение владельца 2026-11-09) — только для номенклатуры
  с серийным учётом; остальная номенклатура — как прежде.

- **Обычная запись проведённого документа** (режим «Запись» без перепроведения) с серийной номенклатурой в данных
  документа или его движениях — отказ подпиской `ПередЗаписью`: «проведённый документ с серийным товаром
  записывается только проведением» (строки и движения не должны расходиться — лимит возврата, история экземпляра).
- **Склады документа**: подпиской `ПередЗаписью` (режим «Проведение») — склады документа (реквизиты типа
  `СправочникСсылка.МестаХранения` шапки и строк серийного товара) для серийных строк не ордерные на дату документа,
    без подчинённого и не подчинённые — проверка **до** формирования движений (поступление на ордерный склад
  исключает свои движения `ИсключитьЗаписиОрдерногоСклада`, и набор их не увидит), выполняемая **после
  разделяемой блокировки `Справочник.МестаХранения`** по этим складам; блокировка удерживается до конца транзакции
  (порядок: номенклатура → IMEI → склады-справочник → основания → остатки). Запись склада (смена режима или связи)
  берёт исключительную блокировку той же ссылки — либо ждёт проведения и затем видит появившуюся историю, либо
  проведение видит новый режим и отказывает.
- **Полнота разложения по сериям**: подписка `ПередЗаписью` документа (режим «Проведение»), до формирования движений:
  у строки с серийным товаром и `УказаноНесколькоСерий` сумма количеств строк `ТЧСерии` с тем же `КодСтроки` равна
    количеству строки, у каждой непустой серии — 1 (строка пустой серии — переходный остаток — любое количество,
  достаточность — проверкой остатка пустой серии в наборе) (иначе `ОбъединитьТоварыССериями` молча теряет строку, и набор её не
  видит); у строки без признака — количество 1 при непустой серии. Нарушение — отказ проведения, независимо от
  `ПроверитьЗаполнение`.

## 4б. Возврат серийного товара

- Возврат от покупателя серийного товара — **только по основанию — документу физической продажи** (реализация, не
  налоговый документ на основаниях: у него искусственная пара «приход/расход» переклассификации, и второй возврат по
  нему дал бы второй лимит); без основания или по налоговому документу — отказ проведения
  строки серийного товара (интерфейс «возврат по чеку» — сборка 4.2).
- Строгое соответствие: строка возврата серийного товара сопоставляется со строками продажи по «номенклатура +
  характеристика + серия» (пустая серия — тоже ключ); поиск «только по номенклатуре» существующей проверки
  `ПроверкаСоответствияВозвратовРеализации` для серийной номенклатуры не применяется. Количество возврата по ключу —
  не больше проданного по нему **по движениям продажи** (расход реализации в `ТоварыВНаличии` по ключу, а не строки
  документа) за вычетом проведённых возвратов этой реализации. Продажа A → возврат без серии или с
  серией B — отказ.
- Конкурентность: проведение возврата серийного товара берёт исключительную управляемую блокировку
  реализации-основания (`Документ.РеализацияТоваровУслуг`, ссылка) до чтения проданного и возвращённого — два
  возврата одной продажи сериализуются; разные продажи не конфликтуют.
- **Отмена продажи** (отмена проведения, перепроведение с уменьшением или удалением строки серийного товара,
  удаление, **прямая запись набора** с отбором по реализации), по которой есть проведённые возвраты серийного товара,
    — отказ: сначала отменить возвраты. Проверка — в общем валидаторе набора (`ПриЗаписи`, окончательная запись): если
  регистратор — реализация, под блокировкой этой реализации (прямой вход берёт её в `ПередЗаписью` набора — после
  барьера номенклатуры и IMEI, до записи и блокировок остатков, в том же порядке, что возврат; документный вход —
  уже удерживает её своими блокировками) новый полный расход регистратора по ключу «номенклатура +
  характеристика + серия» не меньше проведённых возвратов по ней; промежуточная очистка документного перепроведения
  пропускается тем же контекстом.

## 4а. Включение флага, связи складов, владелец серии

- **Порядок блокировок флага и серий**: запись серии (`СерииНоменклатуры.ПередЗаписью`) берёт **разделяемую**
  управляемую блокировку `Справочник.Номенклатура` по ссылке владельца **до** чтения флага и держит её до конца
  транзакции; включение флага (`Номенклатура.ПередЗаписью`, Ложь → Истина) берёт **исключительную** блокировку той же
  ссылки до перечисления серий. Серия, создаваемая одновременно с включением флага, либо видна при перечислении,
  либо создаётся после и видит флаг — регистрируется в обоих случаях. Номера IMEI блокируются после номенклатуры
  (единый порядок).
- **Включение необратимо**: снять флаг после включения нельзя (в т. ч. групповым изменением — тот же модуль объекта),
  иначе цикл «выключить → приход без IMEI → включить» легализовал бы новый остаток; разрешения исторических приходов
  создаются только при этом единственном включении.
- **Включение флага**: в той же транзакции — разделяемая блокировка `ТоварыВНаличии` по номенклатуре (движения
  товара ждут) и проверка остатков: каждая непустая серия — сетевой остаток ≤ 1 и по складам ≥ 0; пустая серия —
      по складам ≥ 0;     **хронологический валидатор** непустых серий товара — тот же, что в п. 4 (остатки по складам 0/1 и сеть 0/1
  накопительно по всей истории; нарушение — отказ с первым нарушающим документом);
    **исторические приходы непустых серий**: агрегат **физического** прихода серии каждым регистратором (без нулевых пар
  налоговой переклассификации — та же функция, что в п. 4) — не больше 1 (иначе после
  включения исходный документ не перепровести: отказ с перечнем документов; историю исправляют до перехода —
  разделить приход на серии в самом документе, не пересортицей); все непустые серии в **истории движений товара**
  принадлежат ему, нормализованный номер
  регистрируется без дублей (чужая серия в историческом поступлении — отказ с перечнем документов для исправления
  до перехода); нет **ни остатков, ни истории движений** товара на складах с подчинённым, подчинённых и ордерных
  (исправление старых ордеров и документов на них после включения стало бы невозможным); нет дублей номеров (п. 3).
    Предикат непустой серии тот же, что в п. 4 (по складам строго 0 или 1, сеть 0 или 1). Нарушения — отказ записи
  номенклатуры с перечнем («серия S: 3 шт. на складе А — разделите экземпляры пересортицей     до включения учёта»; приход нескольких единиц одной серии исправляется в исходном документе). Регистрация номеров в `СерийныеНомера` и **разрешений исторических приходов** — там же
  (`ПриЗаписи`): регистр сведений `ПереходныеПриходыБезСерии` (измерения `ДокументПрихода` — любой документ,
    `Номенклатура`, `МестоХранения`; ресурсы `КоличествоБезСерии` и `КоличествоВсего`) получает приходы номенклатуры
  по регистраторам на момент включения: без серии и всех серий вместе. Исторический регистратор не может превысить
  ни лимит без серии, ни предел **общего количества** прихода (замена пустой серии на IMEI не освобождает место для
  новой штуки без серии; увеличение — отдельным документом с IMEI); ролям не выдаётся, как `СерийныеНомера`.
- **Связь складов**: запись склада, у которого задаётся или меняется подчинённый склад или который становится
  ордерным, при любых серийных движениях на нём или на подчинённом (не только остатке: связь не датирована, и
  отмена старой продажи после смены связи стала бы невозможной) — отказ с перечнем товаров. Гонка с первым
  серийным приходом: запись склада до проверки истории берёт исключительную блокировку `ТоварыВНаличии` по складу
  записываемого склада и его подчинённого — любая запись движений на эти склады (запись набора сама блокирует свои
  ключи) ждёт или опережает её; проверка набора читает режим и связь склада после своих блокировок и видит
  зафиксированное состояние.
- **Удаление серии** (`ПередУдалением`, непосредственное и программное): блокировки владельца и номера в общем
  порядке, при любой истории движений серии — отказ; номер освобождается только у серии без истории.
- **Владелец и номер серии**: запись серии блокирует **старый и новый номер** одним упорядоченным набором (и обе
  номенклатуры при смене владельца) до проверки истории и перечитывает серию после блокировок; проведение в
  `ПриЗаписи` набора сверяет, что актуальный номер серии совпадает с захваченным (иначе — «серия изменена,
  повторите»). Смена владельца или нормализованного номера серии, по которой есть движения, — отказ
  (модуль объекта `СерииНоменклатуры`); запись `СерийныеНомера` использованного номера не освобождается (номер
  проданного экземпляра не может получить новая серия). Исправление ошибочного IMEI — сборка 4.2 (контролируемая
  операция с историей номеров); до неё — только для серии без движений.
- **Удаление**: подписка `ПередУдалением` документов-регистраторов `ТоварыВНаличии` (подписка `ЗапретУдаленияСерийных`)
  — документ с движениями серийной номенклатуры (**независимо от признака «Проведён»**: непроводимая корректировка
  регистров тоже хранит движения) удалить нельзя, сначала штатная отмена проведения (для корректировки — запись
  пустого набора, проверяемая набором),
  проходящая инвариант п. 4 (непосредственное и программное `Удалить()` проходят мимо модуля набора, bsl-024). При
  `ОбменДанными.Загрузка` не действует.
- **Права регистра `СерийныеНомера`**: ролям не выдаётся (кроме администратора с полными правами); запись и чтение —
  только серверным кодом модулей серий, номенклатуры и набора остатков в привилегированном режиме **после** штатной
  проверки права изменения объекта (запись серии и номенклатуры сама требует права изменения у роли). Пользователь
  с ролью редактирования номенклатуры включает флаг и создаёт серии без прав на регистр; тест — под этой ролью
  (`ВыполнитьПодРолью`/живая проверка) — в регрессе человека, если автотест ролей невозможен.


## 5. Раннее сообщение и ордерный склад

- Проверка заполнения (раннее сообщение пользователю; инвариант — п. 4) — только для документов прихода
  (поступление, оприходование), не имеющих разрешения в `ПереходныеПриходыБезСерии` (исторические документы
  перепроводятся без требования IMEI). Расходные документы (реализация, возврат поставщику, списание, перемещение)
  IMEI не требуют: расход без серии допустим в пределах остатка без серии (переходный товар), п. 4:
  строка товара с серийным учётом — сумма количеств её серий равна количеству строки, количество каждой серии — 1.
  Возврат от покупателя — не требует IMEI (переходный остаток продавался без IMEI), но если IMEI указан — п. 4.
- Ордерный склад: серийная номенклатура на ордерных складах не учитывается (п. 4); реализация с ордерного склада
  товар не двигает, поэтому реализация серийного товара с ордерного склада отклоняется проведением самого документа
  (строка с серийным товаром при ордерном складе), чтобы продажа не прошла «до ордера».

## Тесты (`ТестыДокументов`)

1. `ОтрасльТелефоны`: применение отрасли — константа серий включена, пять доп. реквизитов, повтор не дублирует; код
   хаба `phones`.
2. `IMEIУникальность`: вторая серия с тем же IMEI (у другого товара) — отказ; смена номера освобождает прежний;
   установка флага у номенклатуры с двумя сериями одного номера — отказ.
3. `IMEIОдинЭкземпляр`: поступление IMEI на склад А; второе поступление того же IMEI на склад Б — отказ; реализация
   IMEI — остаток 0; вторая реализация — отказ; отмена проведения поступления проданного IMEI — отказ; перепроведение
      поступления (без изменений) — проходит; замена проданного IMEI в поступлении и удаление его строки при
   перепроведении — отказ; перемещение A → «в пути» → Б — проходит, списание с неверного склада — отказ; поступление с

регистрируются как отдельные сценарии `IMEI<Проверка>` (около 30), положительные цепочки — по одному сценарию на
цепочку; проверка «движения на месте после отказа» — сравнением, сделанным до отказа, и самим фактом отказа записи
(транзакция откатывается целиком).

## Порядок и проверки

Перечисление и отрасль → реквизит номенклатуры и форма → регистр и модуль серий → модуль набора остатков → проверки
документов → тесты → «Что нового» 2.0.17.10. lint, refcheck, listcheck, colfont, menucheck; `ib-sync`; смок; тесты;
`ai-review` → `ai-database` (регистр, блокировки, проверки набора) → `ai-security` → `ai-final-check --db` → отчёт.

## Риски

- Проверка в модуле набора добавляет запрос остатков по ключам серийной номенклатуры к каждой записи `ТоварыВНаличии`
  с такими ключами; для несерийной — только проверка флага пакетом по номенклатуре набора.
- Существующие базы: флаг по умолчанию снят — поведение не меняется, пока владелец не поставит флаг.
