## Что сделать (С2)

Налоговый документ на основании неналоговых — та же `РеализацияТоваровУслуг` (`ПоступлениеТоваровУслуг`) с
флажком «Налоговый» и табличной частью `Основания`:
- ТЧ `Основания` (основание, строка основания, покрытое количество); подбор неналоговых документов того же
  контрагента и организации; заполнение товаров по основаниям с правкой количества и цены.
- **Отдельная ветка проведения** при непустых основаниях: без складских ордеров, без списания партий заново, без
  зеркала; **переклассификация** по покрытым количествам с партиями оснований: у реализации приход `УУ = Истина` /
  расход `УУ = Ложь`, у поступления — наоборот; `Продажи` — построчно.
- Расчёты — **два действия**: перенос долга по строкам (денежная доля строки = сумма строки × доля покрытого
  количества строки; разница цен — отдельной суммой налогового долга) и перенос **уже распределённых оплат**
  оснований в `УУ = Ложь`.
- Подписка оплат: **дополнить** новыми документами (старые налоговые накладные обслуживаются до С5); прежние основания
  платежа запоминать в `ПередЗаписью` (`ДополнительныеСвойства`); перепроведение зависимых налоговых документов — в
  транзакции платежа без подавления исключения.
- Покрытие — под **исключительной блокировкой** оснований; одна действующая налоговая реализация на строку основания.
- **Защита оснований с момента покрытия**: покрытое основание нельзя распровести, удалить, пометить и изменить в
  покрытых строках и в реквизитах шапки (`УУ`, организация, контрагент, договор, склад, дата, валюта, курс) —
  `ПередЗаписью`, `ОбработкаУдаленияПроведения`, `ПередУдалением`, проверка под блокировкой.
- Возвраты: `Продажи.УменьшитьПрибыльПоВозврату` — отбор по `УУ` возвращаемого документа, без парных записей
  переклассификации.
- Списки реализаций и поступлений при опции `РаздельныйУчет`: закладки «Управленческие» и «Налоговые», колонки
  связи (основания ↔ налоговый на основании), команда «Создать налоговый документ» из отмеченных.
- Сценарии `ТестыДокументов`: частичное и полное покрытие, повторное покрытие — отказ, физический остаток после
  переклассификации не меняется, белый/чёрный — меняются, разные цены — разница отдельной суммой, оплата основания
  до и после налогового документа, перенос и удаление распределения платежа, распроведение покрытого основания —
  отказ, возврат по налоговой реализации.

`scripts/doctests.sh` и `scripts/smoke.sh` с тем же путём (скрипты — только под bash). Во время выгрузки EDT
(~4 мин) `src/cf` не править.

## Грабли, на которых уже спотыкались

- Псевдоним поля запроса не может быть зарезервированным словом (`Есть`, `Выбор`, …) — tiny1C query-001; в С1 это
  уронило сценарий.
- Значение функциональной опции запоминается на весь серверный вызов (tiny1C bsl-023): признак раздельного учёта
  читать через `НалоговыйУчет.РаздельныйУчетВключен()` (константа), а не `ПолучитьФункциональнуюОпцию`.
- Движения документа содержат только регистры из его метаданных — проверять `Метаданные().Движения.Содержит`.
- Деньги: банк всегда белый по типу `МестоХранения` (`БанковскиеСчета`), касса — по признаку документа;
  `ТипДенежныхСредств` — справочник `TypesDePayment`, не перечисление.
- Отказ записи внутри транзакции теста ломает всю транзакцию прогона: отказы проверять функциями, а не записью.
- Параметр или переменная с именем процедуры (`Провести`, `Строка`) затеняет её — tiny1C bsl-011.
- Выгрузка EDT иногда падает гонкой «feature with code "type"» — повторить синхронизацию (до трёх раз).
- `ai-review --verify` со второго круга сверяет находки полного круга только с последней дельтой: «not_fixed» у уже
  закрытых — артефакт; итог кругов — в `.ai/reviews/<slug>/03c-verify-note.md`, копию прежнего `03b` сохранять.
- Вставка в `Form.form` — по вложенности тегов `<items>`, а не по отступу (отступы в формах документов сбиты); id
  элементов и реквизитов формы — уникальные, `xmllint` после правки.
