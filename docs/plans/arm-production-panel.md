# Рабочее место производства: фильтры, пагинатор, легенда, право на суммы, колонки материалов

Сборка 2.0.16.14. Шесть замечаний владельца от 2026-10-05 по скриншоту `DataProcessor.АРМПроизводство`.
Решения владельца по развилкам (тот же день): тип заказа из фильтра убирается — рабочее место всегда
показывает только заказы на производство; право на суммы, не заданное пользователю, работает как раньше
по роли.

## Что меняется

### 1. Клиент и продукция в фильтре — справочники

Реквизиты формы `ОтборКлиент` (`String(100)` → `CatalogRef.Контрагенты`) и `ОтборПродукция`
(`String(100)` → `CatalogRef.Номенклатура`). Поиск по вхождению текста (решение 2026-09-15) отменяется:
поле справочника само даёт ввод по строке с подбором. Отбор — по равенству ссылки.

- Список заказов: условия `ДокументЗаказПокупателя.Контрагент = &Клиент` и
  `Ссылка В (ВЫБРАТЬ ТЧТовары.Ссылка ГДЕ Номенклатура = &Продукция)`, флаги `ЛюбойКлиент`/`ЛюбаяПродукция`
  по `ЗначениеЗаполнено`.
- «Продукция» (`ТекстЗапросаСтрокПродукции`): те же условия на ссылку, строки — только выбранной номенклатуры.
- `НовыеОтборы`: `Клиент`, `Продукция` — ссылки (пустые по умолчанию). `ШаблонВхождения` больше не нужен —
  удаляется вместе с его проверкой в тестах.
- Клиентская проверка `ВнеОтбора` после записи строки (`Module.bsl` ~1875) — сравнение ссылок вместо
  `СтрНайти` по представлению.
- Поле продукции в панели получает тот же отбор подбора, что колонка «Продукция» (готовая продукция и
  полуфабрикаты, S7), клиент — без ограничений.

Сохранённых значений нет (`savedData` у этих реквизитов не стоит) — смена типа данных не теряет.

### 2. Фильтр: убрать тип заказа, добавить стадию и дату отгрузки

- Реквизит `РежимОчереди` и поле-переключатель удаляются. Список и «Продукция» — всегда
  `ВидОперации = Производство` (параметр `ВсеЗаказы` из запроса списка и `НовыеОтборы` уходит;
  `УстановитьПараметрыОтборов` — только `Производство`). У реквизита был `savedData`: сохранённое значение
  платформа при загрузке настроек просто не найдёт — безопасно.
- `ОтборСтадия` — `EnumRef.СтатусыЗаказовПокупателя`, одно значение, пустое = любая. Условие — по
  `История.СтатусЗаказаПокупателя` (срез последних, уже соединён в обоих запросах). Заказ без записи в
  истории считается «Черновиком», как в `ТекстЗапросаСтрокПродукции` (`ЕСТЬNULL(..., Черновик)`).
- `ОтборДатаОтгрузки` — `StandardPeriod`, поле с выбором периода; условие
  `ДатаОтгрузки МЕЖДУ &НачалоОтгрузки И &КонецОтгрузки` при заполненной границе (открытая граница —
  без условия с этой стороны).
- Порядок в панели: Клиент, Продукция, Стадия, Дата отгрузки.

### 3. Наш пагинатор под списком заказов

Повторяю пагинатор списков документов (2.0.15.62–63): группа `ГруппаПагинация` под таблицей `Заказы`
(кнопки `◀◀ ◀ N / M ▶ ▶▶` + счётчик «1-50 из 124»), команды `СтраницаПервая/Назад/Вперед/Последняя`,
реквизиты `НомерСтраницы`, `ВсегоСтраниц`, у таблицы `viewStatusLocation=None` (убирает штатные стрелки
⏫▲▼⏬ — их же убирали в списках документов). Отрисовка — общий
`РаботаСДокументамиКлиентСервер.ОбновитьПагинатор`, выборка ссылок страницы —
`ПараметрыВыборкиСтраницы`, размер страницы 50.

Счёт и ссылки страницы — новая серверная функция менеджера `Обработки.АРМПроизводство.СтраницаЗаказов(Отборы,
НомерСтраницы, РазмерСтраницы)` → `Всего`, `ВсегоСтраниц`, `НомерСтраницы`, `Ссылки` (СписокЗначений,
пустой при одной странице). Условия текстом строятся **одной** функцией и для счёта, и для страницы —
это то же множество, что даёт запрос динамического списка (вид операции, клиент, продукция, стадия, дата
отгрузки). Список ограничивается элементом отбора `Ссылка В список` (как в формах списков); при одной
странице элемент выключается. Порядок резки — `Дата УБЫВ, Ссылка` (как сортировка списка по умолчанию).

Переход на первую страницу — при изменении любого отбора; «Обновить» пересчитывает текущую страницу
(новые заказы не попадают в ограниченный ссылками список сами — как в формах списков). Запросы —
`РАЗРЕШЕННЫЕ`, иначе счётчик посчитал бы недоступные по RLS заказы.

### 4. Легенда индикатора в строке пагинатора

Справа от счётчика — надпись `НадписьЛегенда` в одну строку:
«Кружки: материалы заказаны · материалы пришли · выпуск · отгрузка · оплата   ○ не начато ◐ частично ● полностью»
на четырёх языках. Текст — новая функция `ПроизводственныеЗаказы.ЛегендаИндикатораСтрокой()` рядом с
`ЛегендаИндикатора()` (подсказка у заголовка колонки остаётся — в ней ещё проценты текущего заказа).

### 5. Суммы — по праву пользователя

Новый предопределённый элемент ПВХ `ВидыНастроекПользователей` в группе `НастройкиДоступа`:
`ВидетьСуммыПроизводства`, тип `Boolean`, описание «Voir les montants (production)» (как соседи — описание
на французском), новый uuid. Значение хранится в `РегистрСведений.НастройкиПользователей` (измерения
Пользователь, Настройка) — там же, где «Кассир», «Редактировать завершённые документы»; редактируется
штатной формой регистра. Структура регистра не меняется, реструктуризации нет.

`Обработки.АРМПроизводство.ПоказыватьСуммы()`:
- есть запись у пользователя → её значение;
- записи нет → прежнее правило: `Не РольДоступна("ОператорПроизводства") Или РольДоступна("Администратор")`.

Для различения «нет записи» и «Ложь» в менеджер регистра добавляется экспортная
`ЗначениеНастройкиИлиНеопределено(Настройка)` (привилегированный режим, как `ПолучитьЗначениеНастройки`) и
`ВидетьСуммыПроизводства()` → Булево/Неопределено. Область действия — только рабочее место производства
(все места, где сейчас стоит `ПоказыватьСуммы()`: колонки Сумма/Цена во всех закладках, представление
заказа в выборе, услуги переработчика, запрет правки цены). Данные запросов не режутся, право роли на чтение
документа не меняется; на сервере то же право открывает правку цен (см. «Гейт плана»).

### 6. Колонки закладки «Материалы»

- Ширины задаются явно (`<width>`, `horizontalStretch=false` у числовых), короткие заголовки, полное имя —
  в подсказке колонки (`toolTip`), на четырёх языках:
  Материал · Продукция · Характ. · Состав · Нужно · Заказано · Пришло · Со склада · Дефицит · Ожидается · Способ.
- «Способ изготовления» (`МатериалыСпособИзготовления`) переносится в конец, заголовок «Способ».
- `МатериалыХарактеристика.Видимость` — по функциональной опции `ИспользоватьХарактеристикиНоменклатуры`, как
  уже сделано у «Продукции» и закладок документов. Опция уже выведена в настройки
  (`НастройкиПрограммы` → «Номенклатура»), новая опция не заводится.

## Чего не делаю

- Не трогаю права ролей и RLS (см. «Гейт плана»: дыра записи настроек — отдельной задачей).
- Не распространяю право на суммы за пределы рабочего места (документы, отчёты) — не просили.
- Не пагинирую закладку «Продукция» (у неё свой предел 300 заказов) и нижние таблицы.

## Риски

- Динамический список с `customQuery` + отбор по `Ссылка В` — та же схема, что в 42 формах списков.
- Счёт по `ИсторияЗаказовПокупателейПоСтатусам.СрезПоследних` при отборе стадии — срез с отбором по
  заказам отобранного вида операции, как в `ТекстЗапросаСтрокПродукции`.
- Предопределённый элемент ПВХ появляется у клиентов при обновлении конфигурации сам (платформа создаёт
  предопределённые). uuid новый, коллизий с drissotex нет (их ПВХ не переносится).

## Гейт плана и что изменилось после него

Codex в лимите до 2026-10-09 — гейт прошёл на субагенте `architecture-critic` (вердикт «approve_with_changes»).
Принято:

- **P1.** Страница пересчитывается после записи строк, смены статусов и документов строк, а не только по «Обновить»:
  клиентская `ОбновитьСтраницуЗаказов` зовёт сервер без контекста (`ДанныеСтраницыЗаказов`) и ставит отбор
  ссылок на клиенте — форма целиком на сервер не уходит.
- **P1.** Право на суммы — не только интерфейс: на сервере оно же открывает правку цен и услуг (так было и с ролью).
  Решение «Да» = видеть и править. Дыра «PDV пишет регистр настроек сам» — в `TECHDEBT.md` и `ROADMAP.md` 12.5a,
  вынесена владельцу.
- **P2.** Условия счётчика — по тексту запроса **списка** (без отсечения пометки и финальных стадий), один текст
  `ТекстУсловийОтборов` в модуле менеджера и копия в запросе динсписка; «Продукция» подставляет его вместо маркера.
- **P2.** Обособленное подразделение в отборе клиента заменяется головным контрагентом (заказы АРМ пишутся на
  головного); в продукции — выбор только элементов.
- **P2.** Границы периода — флагами `ЕстьНачалоОтгрузки`/`ЕстьКонецОтгрузки`; заказ без даты отгрузки в отбор по
  периоду не попадает ни с какой границей — одинаково в списке, счётчике и «Продукции».
- **P2.** Тест права на суммы сохраняет прежнюю запись пользователя прогона и восстанавливает её в `Исключение`.
- **P2.** После записи строки соседние строки заказа проверяются по продукции, клиенту и стадии.
- Отложено в `TECHDEBT.md`: пользовательские настройки списка вне счётчика, кеш права в форме, пустая «Продукция»
  при финальной стадии.

Дополнительно: регистр «Настройки пользователей» не был выведен ни в одно меню — добавлен в «Настройка →
Пользователи и права» (подсистема видна только администратору и руководителю), иначе право негде выставить.
Генератор формы догнан: `scripts/formgen/arm/gen9.py`.
