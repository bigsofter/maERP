# Сборка 2.0.17.7: универсальная загрузка из Excel (`excel-import-universal`)

Волна 3 мастер-плана `docs/plans/retail-chain.md`; этап У3 `docs/UNF-ADOPTION.md` (закрывается этой сборкой).

## Что есть сейчас

Обработка `ЗагрузкаИзExcel` (одна форма, 361 строка) читает xls/xlsx в табличный документ, колонки задаются номерами
жёстко (ИД, КодПоставщика, Товар, Количество, Категория, Марка, три цены), ищет товар по коду поставщика, артикулу и
точному наименованию, умеет создавать товары (флаг `СоздаватьТовары`) и возвращает форме документа массив структур
(`Номенклатура, Количество, КоличествоУпаковок, Цена, ЦенаРозничная, ЦенаМинимальная`). Шесть форм документов
(Реализация, Поступление, НН, НН покупки, Заказ поставщику, Предложение поставщика) заполняют `ТЧТовары` своими
копиями обработчика `ПослеЗакрытияФормыЗагрузки`. Изъяны: ошибка чтения файла проглатывается; пустой результат
очищает ТЧ; ненайденный товар даёт строку с пустой номенклатурой; `КодСтроки` не ставится; право на обработку есть
только у `МенеджерПоЗакупкам` — у остальных ролей кнопка в документе не открывает форму. Тестов загрузки нет.

## 1. Движок — общий модуль `ЗагрузкаИзФайла` (сервер)

- `ПрочитатьФайл(ДвоичныеДанные, Расширение)` → `ТабличныйДокумент`: xlsx/xls/ods — `ТабличныйДокумент.Прочитать`
  через временный файл **с исходным расширением**; csv/txt — разбор текста (UTF-8 с BOM или без, разделитель
  определяется по первой строке: `;`, табуляция, `,`; кавычки по RFC 4180). Ошибка чтения — исключение с понятным
  текстом, не пустая таблица. Временный файл удаляется в `Попытка … Исключение` с повторным вызовом исключения.
- `ОписаниеПриемника(ИмяДокумента, ИмяТЧ)` → допустимость ТЧ и колонки для загрузки.
  **Приёмник** в этой сборке — ТЧ документа с реквизитом `Номенклатура` одного из двух классов: **количественный**
  (есть `Количество`; товары, услуги, материалы, продукция) и **суммовой** (есть `Сумма` и `СтавкаНДС` в строке, нет
  `Количество` — например `ТЧДополнительныеРасходы`). ТЧ с обязательной ссылкой на документ в строке (не
  сопоставляется) — не приёмник: `ПоступлениеДополнительныхРасходов.ТЧТовары` (`ДокументПартии` — база распределения,
  ставка НДС в шапке) исключается явно и правилом «суммовой — только со ставкой в строке». Прочие ТЧ (сотрудники, основания платежей, табель, проводки) — не в этой сборке
  (TECHDEBT: у каждой свой расчёт строк). `АктРазбора.ТЧТовары` — не приёмник в этой сборке: доли себестоимости выходных товаров (`ДоляСтоимости`)
  рассчитывает только форма (`РассчитатьДолиСтоимости`), загруженные строки оприходовались бы с нулевой стоимостью —
  TECHDEBT (серверный адаптер распределения). `ПересортицаТоваров` — не приёмник в этой сборке: две номенклатурные группы в строке (списания и оприходования,
  `ХарактеристикаОприходование`, `СерияОприходование` подчинены `НоменклатураОприходование`) требуют отдельного
  разрешения владельцев — TECHDEBT. Правило «подчинённый справочник — в паре с товаром строки» действует только для
  реквизитов `Характеристика`, `Серия` при реквизите `Номенклатура` той же строки; иные реквизиты, подчинённые
  номенклатуре, делают ТЧ неприёмником (проверяется тестом-обходом метаданных). `ПересчётТоваров` — не приёмник в этой сборке:
  загрузка факта должна обновлять факт существующей строки по ключу «товар + характеристика + серия + упаковка»,
  сохраняя учётную пару, а не добавлять строку (иначе списание на основании считает отклонение построчно) — TECHDEBT
  «режим обновления факта». `ВыпускПродукции.ТЧГотоваяПродукция` — не приёмник: `ПередЗаписью` перестраивает её из
  шапки (`СинхронизироватьГотовуюПродукцию`), загруженные строки были бы потеряны. Документы-ордера склада
  (`ПриходныйОрдер`, `РасходныйОрдер`) — не приёмники:
  их строки привязаны к строкам заказов (`КодСтрокиЗаказа`) и вводятся на основании.
  **Подчинённые ТЧ** — явная карта в модуле (`ПодчиненныеТЧ()`): `ТЧСерии` любого документа → `ТЧТовары`,
  `ЗаказПокупателя.ТЧМатериалы` → `ТЧТовары` (по `КодСтрокиПродукции`, `КодСтрокиРодителя`, несмотря на собственный
  `КодСтроки`). Карта используется и для исключения приёмников, и для запрета замены (шаг 2 ниже). Внешние связи строк
  (`КодСтрокиПотребности` перемещения, `КодСтрокиЗаказа` ордеров) — отдельный перечень. Тест обходит метаданные: любой
  реквизит ТЧ `КодСтроки<Суффикс>` и любая ТЧ с «Серии» в имени должны быть либо в карте, либо во внешних связях —
  новая связь без решения роняет тест.
  Колонки: реквизиты простого типа (Число, Строка, Дата, Булево), перечисление, справочник (одиночный тип). Не
  загружаются: составные типы, ссылки на документы, `ХранилищеЗначения`, `КодСтроки` и `КодСтроки…`,
  `Идентификатор…`, `Ключ…`, служебные признаки строки — перечень
  `СлужебныеКолонки()` модуля, в нём `УказаноНесколькоСерий` (при истине штатное `ОбъединитьТоварыССериями` заменяет
  строку строками `ТЧСерии`, и товар без серий выпал бы из движений; новым строкам признак ставится `Ложь`); расчётные `СуммаНДС`, `СуммаСНДС`, `СуммаРегл…`, скидки (`ПроцентСкидки`,
  `СуммаСкидки`, `СкидкаНаЦену` — их взаимный расчёт зависит от того, что ввёл пользователь; TECHDEBT). Из
  `Цена`, `ЦенаSKU`, `Сумма` сопоставляется **не больше одной** (форма не даёт выбрать вторую).
- `ПреобразоватьСтроки(ТабДок, Настройка, ИмяДокумента, ИмяТЧ)` → таблица значений сопоставленных колонок +
  `НомерСтрокиФайла` + `Ошибки`; результат различает значения из колонок файла и полученные из
  идентификатора (штрихкода), в `Загрузка.Сопоставлено` попадают и те, и другие. Преобразование по типу: число (пробелы, неразрывные пробелы, запятая/точка), дата
  (`ДД.ММ.ГГГГ`, `ГГГГ-ММ-ДД`), булево (да/нет, 1/0, true/false, oui/non, sí/no), перечисление — по имени или синониму
  на любом языке, `Номенклатура` — по правилам поиска настройки в заданном порядке (штрихкод → регистр
  `ШтрихкодыНоменклатуры` — **вместе с характеристикой и серией**
  штрихкода, как штатный `ПолучитьНоменклатуруПоШтрихкоду`; они переносятся в строку, если в ТЧ есть такие
  реквизиты, и считаются сопоставленными до подбора цены; сопоставленная из файла характеристика или серия,
  противоречащая штрихкоду, — ошибка строки), артикул, код поставщика, код, наименование; группы не находятся; несколько совпадений —
  ошибка «неоднозначно»), характеристика — по наименованию среди характеристик найденного товара; **серия** (`СерииНоменклатуры`, подчинена
  номенклатуре, коды уникальны в пределах владельца) — отдельным правилом: по коду, затем точному наименованию
  **только среди серий найденного товара строки** (пакет по парам «товар + значение»); серия и характеристика из
  штрихкода проверяются на владельца; глобального поиска серий нет; прочие подчинённые номенклатуре справочники —
  тоже только в паре с товаром строки; прочие справочники
  — по коду, затем по точному наименованию (не группы; неоднозначно — ошибка). Поиск — **пакетом запросов по всем
  значениям колонки**, не запросом на строку. Строка без найденной номенклатуры или с ошибкой преобразования
  в загрузку не идёт.
- `ЗаполнитьТЧ(Объект, ИмяТЧ, Загрузка)` — сначала **сверяет `Загрузка.Сопоставлено` с допустимыми колонками
  приёмника** (`ОписаниеПриемника`): недопустимая колонка (служебная, `КодСтроки`, скидка) — ошибка, объект не
  меняется (режим формы передаёт структуру с клиента — ей не доверяем); из `Цена`, `ЦенаSKU`, `Сумма` сопоставлено больше
  одной — ошибка (тест прямого вызова с конфликтующими колонками, ТЧ не изменилась). Возвращает текст ошибок или пусто — **единственное заполнение** для обоих режимов
  (объект документа на сервере и данные формы в серверном вызове формы). `Загрузка` — структура `Строки` (массив
  структур только из сопоставленных колонок), `Сопоставлено` (имена), `Заменить`. **Атомарность**: результат строится
  в таблице значений — копии ТЧ (`Выгрузить()`; при «заменить» — пустая копия колонок); исходная ТЧ заменяется
  (`Загрузить`) только после того, как все строки рассчитаны без ошибок. Ошибка любой строки → ТЧ объекта или формы
  не изменена, прежние строки и их коды на месте. Порядок:
  1. Пустой набор пригодных строк → ошибка «нечего загружать» (проверка здесь, а не только в форме).
  2. `Заменить` и в документе есть непустая подчинённая ТЧ из карты (серии, материалы) → ошибка «в документе есть
     связанные строки (серии, материалы) — загрузите добавлением или очистите их».
  3. **Ценовой расчёт** у приёмника есть, только если в ТЧ есть `Цена` и `СтавкаНДС`; иначе (пересчёт, списание,
     материалы без денег) подготовка и подбор цен пропускаются целиком, значения по умолчанию применяются только к
     существующим реквизитам. **Вид цены строки** (если в ТЧ есть `ВидЦены` и он не сопоставлен) — тем же правилом,
     что форма документа при добавлении строки: `ВидЦен` шапки, пустой — `ОбщегоНазначенияВызовСервера.
     ВидЦеныПродажиПоУмолчанию(Контрагент, МестоХранения)`; в режиме формы вызывающая форма передаёт свой текущий
     вид цены в `Загрузка.ВидЦены`. Сопоставленный пустой вид цены сохраняется («произвольная цена»).
     **Направление подбора цены** — явной таблицей модуля `НаправлениеЦены(ИмяДокумента)`: закупка —
     `ПоступлениеТоваровУслуг`, `НалоговаяНакладнаяПокупка`, `ЗаказПоставщику`, `ВозвратПоставщику`,
     `ВозвратПоставщикуНалоговый` (поставщик — `Контрагент` шапки), `ПредложениеПоставщика` (реквизит шапки
     `Поставщик`); **закупка без поставщика** — `ОприходованиеТоваров` (свойство `Поставщик` = `Неопределено`, как ставит
     штатный преобразователь: закупочная ветка подбора); остальные приёмники с ценой — продажа по виду цены; продажа **без реквизита вида цены** в строке и шапке
     (`ВозвратОтПокупателя`, налоговый возврат) — штатное поведение `ЦеныДляПродажи` без свойства `ВидЦены`: розничный
     вид (он и так всегда в пакете среза цен). Перед вызовом ценового помощника структура
     строки нормализуется: у закупки в неё ставится `Поставщик` из реквизита шапки (штатный преобразователь делает это
     только при `НоменклатураКонтрагента` в строке), у закупки без поставщика — `Поставщик = Неопределено`, у продажи `Поставщик` отсутствует. Тест: каждый приёмник с ценой — в таблице закупки (с поставщиком или без) либо продажа (с реквизитом вида цены
     или без — розничная по умолчанию).
     **Дата цены** — одна на загрузку: `КонецДня(Объект.Дата)`, как ставит штатный преобразователь; она же — в
     структуре строки, в `ПоследнийПрайс` и в `ДанныеЦенДляСписка`.
     Данные по умолчанию — **пакетно** до цикла: реквизиты номенклатуры (ставка НДС, единица) одним запросом по
     уникальным товарам. Цена — **тем же путём, что форма документа**: структура строки — штатным
     `РаботаСДокументамиКлиентСервер.ПреобразоватьСтрокуТаблицыВСтруктуру(Стр, Объект)` (контекст документа:
     поставщик/покупатель, валюта и курс, дата цены, вид цены документа; для неполного приёмника — адаптер добавляет
     отсутствующие `Характеристика`, `Упаковка` пустыми во временную строку), затем
     `ОбщегоНазначенияВызовСервера.ПолучитьЦенуНоменклатуры`. Для продажи данные цен готовятся пакетно, как в
     `РаботаСДокументами.УстановитьЦеныВТабличнойЧасти`: `ЦеныНоменклатуры.ПоследнийПрайс(Дата, ВидыЦен)` по всем видам
     цен загрузки **плюс розничный** (`ЦеныДляПродажи` при отсутствии цены вида ищет резервную розничную только в
     переданном срезе — без неё пакет обнулил бы цену, которую ручной ввод находит) и `ДанныеЦенДляСписка` по товарам каждого вида цены (с `ВалютаДокумента`) — передаются в
     `ПолучитьЦенуНоменклатуры`; для закупки (ветка поставщика) пакетного помощника нет — вызов на уникальное
     сочетание с кешем. Ключ кеша — «товар + характеристика + упаковка + вид цены + ставка НДС» (контекст документа
     у загрузки один; цена прайса преобразуется по ставке строки, поэтому ставка — часть ключа).
  4. Для каждой строки: новая строка копии; **сначала все сопоставленные значения** (`ЗаполнитьЗначенияСвойств` по
     `Сопоставлено`, включая параметры цены — вид цены, характеристику, упаковку); затем **значения по умолчанию только
     для несопоставленных полей** из шага 3, рассчитанные с уже применёнными параметрами: упаковка, ставка НДС; цена —
     только если не сопоставлена ни одна из `Цена`, `ЦенаSKU`, `Сумма`. Упаковка и ставка из файла не перетираются
     карточкой; цена ищется по виду цены из файла.
  5. Количество (количественный класс): коэффициент — `ОбщегоНазначенияВызовСервера.РассчитатьКоэффициентЕдиницы`,
     как в формах документов. В maERP он сейчас всегда 1 (пересчёт по числителю/знаменателю отключён во всей
     конфигурации) — загрузка следует той же семантике, что ручной ввод: сопоставлено только `Количество` →
     `КоличествоУпаковок = Количество / К`; только `КоличествоУпаковок` → `Количество = КоличествоУпаковок × К`; оба и
     `Количество ≠ КоличествоУпаковок × К` → ошибка строки «количество не согласовано с упаковкой». Включение
     коэффициентов упаковок — не задача загрузки (существующий TECHDEBT/развилка; тест фиксирует текущее поведение).
     То же — **для каждой пары** `Количество<П>` / `КоличествоУпаковок<П>` ТЧ (постфиксы находятся по метаданным: «Факт»
     пересчёта, «Принято» и др.): согласование и `РассчитатьКоличество(Стр, П)`; сумма считается только от основной
     пары (без постфикса), как в формах.
  6. Сумма и цена: количественный класс — `РассчитатьСтроку(Стр, ЦенаВключаетНДСДокумента(Объект), Основа)`: `Цена`
     сопоставлена или подставлена по умолчанию → `"Цена"`; `Сумма` → `"Сумма"`; `ЦенаSKU` → `""`. Суммовой класс —
     сумма сохраняется, НДС `РассчитатьСуммуНДС(СтавкаНДС, Сумма, ЦенаВключаетНДС)` при наличии `СтавкаНДС` и
     `СуммаНДС`; `СуммаСНДС` (если есть) = `Сумма + НДС` при цене без НДС, иначе `Сумма`; `РассчитатьСтроку` не
     вызывается.
  7. `КодСтроки` (если есть в ТЧ) — новым строкам «максимум существующих + 1» по порядку; существующие коды не
     меняются; при «заменить» (подчинённых строк нет по шагу 2) — тоже от максимума прежних.
  Ограничение — 10 000 строк за загрузку (больше — ошибка до расчёта).
- `ЗагрузитьВДокумент(Ссылка, ИмяТЧ, Загрузка)` → текст ошибки или пусто. Обычная запись объекта под правами
  пользователя (не `ОбменДанными.Загрузка`, без привилегированного режима): в транзакции — исключительная блокировка
  документа, `ПолучитьОбъект`, отказ если документ проведён («отмените проведение — загрузка в проведённый документ
  запрещена»: перепроведение после массовой замены строк меняет движения без проверки человеком), помечен на
  удаление или `РаботаСДокументами.МожноРедактироватьДокумент` запрещает; `ЗаполнитьТЧ`; **`ПроверитьЗаполнение()`**
  (программная запись её не запускает: склад при товарах и т. п. проверяет `ОбработкаПроверкиЗаполнения`) — не прошла
  → откат, сообщения проверки пользователю; `Записать(Запись)`; ошибки
  записи и проверки заполнения — пользователю, транзакция откатывается. Расчёт (`ЗаполнитьТЧ`) выполняется **до**
  транзакции на прочитанном объекте; в транзакции — блокировка, повторное чтение, сверка `ВерсияДанных` с прочитанной
  (изменился — «документ изменён другим пользователем, повторите загрузку»), перенос рассчитанной ТЧ и запись — без
  долгих расчётов под исключительной блокировкой.
- `СоздатьНоменклатуру(Строки, Настройка)` — режим «создавать товары» прежней обработки (артикул, наименование,
  категория, бренд, штрихкод через `ШтрихкодыНоменклатуры.ЗанятьШтрихкод`) переносится в модуль; поля категории и
  бренда — дополнительные колонки сопоставления только в этом режиме; доступен при праве `Добавление` на
  `Номенклатура`. **Атомарно на товар**: транзакция — исключительная управляемая блокировка таблицы
  `Справочник.Номенклатура` (короткая, только на создание) и записи `ШтрихкодыНоменклатуры` по штрихкоду →
  повторный поиск по тем же правилам (найден после ожидания — используется, дубль не создаётся) → запись товара и
  бренда → `ЗанятьШтрихкод`; отказ занятия — исключение, транзакция откатывает товар и бренд.


## 2. Обработка `ЗагрузкаИзФайла` и форма

Новая обработка (форма «Загрузка из файла»): файл → лист → строка заголовка и первая строка данных → таблица
сопоставления «реквизит приёмника ↔ колонка файла» (автоматически — по совпадению заголовка с именем или синонимом
реквизита на любом языке, без регистра и пробелов; вручную — выбором из списка заголовков) → правила поиска
номенклатуры (флажки и порядок) → «Проверить» (предпросмотр в табличном документе: загружаемые значения и колонка
ошибок, строки с ошибками выделены, счётчик «к загрузке / с ошибками») → «Загрузить». Параметры открытия:

- `Документ` (ссылка) — режим общей команды: приёмник — допустимая ТЧ этого документа (по умолчанию `ТЧТовары`),
  флажок «Заменить строки» (по умолчанию — добавить), загрузка через `ЗагрузитьВДокумент`.
- `ИмяДокумента` + `ИмяТЧ` + `СоздаватьТовары` — режим формы документа (незаписанный объект): форма закрывается со
  структурой `Загрузка` (раздел 1). Прежние ключи результата не нужны: `ЦенаМинимальная` и `ЦенаРозничная` — реквизиты
  ТЧ поступления и НН покупки, сопоставляются как обычные колонки.

Обработка `ЗагрузкаИзExcel` удаляется: шесть форм документов открывают `ЗагрузкаИзФайла` во втором режиме, раздел
«Сервисные операции» и ссылка в «Настройках программы» ведут на новую обработку (без документа — с выбором документа,
открытием его формы не занимается: показывает «откройте документ и нажмите «Загрузить из файла»» и список
документов). Данных у обработки нет; права на неё — только в `МенеджерПоЗакупкам` (заменяются правами на новую).

Шесть форм документов: обработчик закрытия — результат `Неопределено` → ничего; иначе серверный вызов формы
`ЗагрузкаИзФайла.ЗаполнитьТЧ(Объект, "ТЧТовары", Загрузка)` (ошибка — сообщение, ТЧ не тронута), затем только
особенности формы (остатки строк, `ПересчитатьСуммыРегл`) — прежние циклы заполнения с безусловной заменой упаковки
и ставки удаляются. Выбор «заменить / добавить» — флажок в форме загрузки (как в режиме команды).

## 3. Настройки загрузки — справочник `НастройкиЗагрузкиИзФайла`

Реквизиты: `Приемник` (строка «Документ.Имя.ИмяТЧ»), `СтрокаЗаголовка`, `ПерваяСтрокаДанных` (Число), `Лист` (строка),
`ПорядокПоиска` (строка, например «Штрихкод,Артикул,КодПоставщика»), `Общая` (Булево), `Автор` (`Пользователи`,
заполняется при создании, недоступен в форме); ТЧ `Колонки` (`Реквизит` строка, `ЗаголовокКолонки` строка,
`НомерКолонки` число). В форме загрузки — поле выбора настройки с быстрым выбором **последних пяти** настроек
приёмника (список последних — в `ХранилищеОбщихНастроек` пользователя, а не в справочнике: общей настройкой
пользуются те, кто не может её менять), «Сохранить настройку» / «Сохранить как…».

RLS: чтение `ГДЕ Общая ИЛИ Автор = &Пользователь`, изменение и добавление `ГДЕ Автор = &Пользователь` (общую правит
только автор). Администратор — без ограничений. Удаление непосредственное — нет, только пометка.

## 4. Общая команда «Загрузить из файла»

`CommonCommands.ЗагрузитьИзФайла`, группа `FormCommandBarImportant`, тип параметра — перечень `DocumentRef.*`
документов, у которых есть хотя бы одна допустимая ТЧ (список строится скриптом при реализации и проверяется
тестом: каждая ссылка параметра имеет допустимую ТЧ). Обработчик: источник — форма объекта с изменёнными данными →
«Запишите документ перед загрузкой»; иначе открыть обработку с `Документ`, по закрытии с результатом «загружено» —
форма загрузки из формы объекта открывается с режимом
`БлокироватьОкноВладельца` (исходную форму нельзя менять, пока идёт загрузка); перед перечитыванием — повторная
проверка `Источник.Модифицированность` (изменена — `Прочитать()` не выполняется, пользователю: «документ загружен в
базе, форма содержит несохранённые изменения — закройте её без записи и откройте снова»); иначе для формы объекта —
`Источник.Прочитать()`, для формы списка — только `ОповеститьОбИзменении(Документ)` (список
обновится сам); тип источника проверяется (`ТипЗнч(Источник.Объект)` у формы объекта), не предполагается. Из списка документов команда тоже работает (по текущей
строке).

## 5. Права

Новая обработка (`Использование`, `Просмотр`) и справочник настроек (чтение/добавление/изменение/интерактивная
пометка с RLS из раздела 3) — ролям, которые вводят документы с ТЧ: `Руководитель`, `МенеджерПоПродажам`,
`МенеджерПоЗакупкам`, `Кладовщик`, `Оператор`, `Логист`, `СкладскиеОрдера`, `ОператорПроизводства`. Само право на
изменение документа проверяет платформа при записи (без привилегированного режима). Роли кассы (`PDV`), клиентов и
обмена не получают.

## Тесты (`ТестыДокументов`)

1. `ЗагрузкаИзФайлаЧтение`: CSV UTF-8 с `;` и кавычками → табличный документ; автосопоставление «Артикул; Кол-во;
   Цена» по синонимам; число «1 234,50» → 1234.5; булево и перечисление по синониму на fr.
2. `ЗагрузкаИзФайлаДокумент`: черновик поступления с одной строкой; файл — строки по штрихкоду, артикулу и
   наименованию и одна с неизвестным товаром → неизвестная не загружена; режим «добавить»: прежняя строка и её
   `КодСтроки` на месте, новые коды — max+1; файл только с `Количество` и `Цена` → количество, количество упаковок,
   цена из файла, сумма и НДС пересчитаны; упаковка и ставка НДС из файла не заменены карточкой; оба количества
   несогласованы во второй строке → ошибка, ТЧ (на объекте и на данных формы через `ЗаполнитьТЧ`) не изменилась;
   режим «заменить» — заменяет.
3. `ЗагрузкаИзФайлаКлассы`: реализация без колонки `ЦенаSKU`, `КоличествоУпаковок` 2 и `Цена` 100 → сумма 200;
   реализация с колонкой вида цены (розничная 100) без ценовой колонки, количество 2 → цена 100, сумма 200;
   две строки одного товара и вида цены с разными ставками НДС (документ без НДС в цене) — цена каждой по своей ставке,
   независимо от порядка строк; `ТЧУслуги` поступления загружается; `ТЧДополнительныеРасходы` (суммовой) — сумма
   100, НДС 20, сумма с НДС 120 при цене без НДС и 100 при цене с НДС; реализация в валюте (курс 10, прайс 100 в
   основной) без ценовой колонки → цена 10; реализация с розничным видом цен в шапке без колонок цены и вида цены,
   количество 2 → вид цены строки розничный, цена 100, сумма 200; списание товара без прайса — без
   исключения; поступление только с услугами без склада + загрузка товаров → отказ проверки заполнения, ТЧ на месте; `ПоступлениеДополнительныхРасходов` — не приёмник; оптовый вид цен без прайса
   товара, розничная 100 → цена 100 (как ручной ввод); `ТЧУслуги` поступления и `ПредложениеПоставщика` без ценовой
   колонки (закупочная цена поставщика 60, розничная 100) → 60; оприходование без ценовой колонки (последняя закупочная 60, розничная 100) → 60, как ручной выбор;
   `ПересортицаТоваров` и `АктРазбора` — не приёмники; возврат от покупателя без ценовой колонки (розничная 100) →
   100; реализация в 09:00, цена товара изменена в 12:00 того
   же дня → цена на конец дня, как ручной подбор; файл только со штрихкодом, зарегистрированным с
   характеристикой и серией, → строка с ними; пара с постфиксом (`КоличествоПринято`/`КоличествоУпаковокПринято`, где есть)
   согласуется; `ПересчётТоваров` и `ТЧГотоваяПродукция` выпуска — не приёмники; серии «Партия 001» с кодом 001 у
   товаров А и Б при поиске товаров по артикулу — каждая строка получает серию своего товара, серия только у Б —
   ошибка строки А; создание товара: повторная загрузка того же файла не создаёт дубль, штрихкод, занятый другим
   товаром, — отказ без созданного товара; `УказаноНесколькоСерий` во входной структуре — отказ без изменений, у загруженных строк признак
   `Ложь`, после проведения реализации товар есть в движениях; каждый
   класс приёмника заполняется без исключения.
4. `ЗагрузкаИзФайлаЗапреты`: проведённый документ — отказ, ТЧ не изменилась; все строки отклонены + «заменить» —
   ТЧ не изменилась; заказ покупателя: продукция А (`КодСтроки` 1) с материалами, «заменить» на Б → отказ, обе ТЧ на
   месте; документ изменён между расчётом и записью → отказ; обход метаданных: каждая связь `КодСтроки<Суффикс>` и
   ТЧ серий — в карте или во внешних связях; `ТЧСерии`, материалы и ордера не в приёмниках, `КодСтроки` и скидки не в
   колонках; каждый тип параметра общей команды имеет приёмник.
5. `ЗагрузкаИзФайлаНастройки`: сохранение и повторное применение настройки (колонки, порядок поиска).

Смок откроет форму обработки и справочника. Человек: файл xlsx поставщика, кнопка в шести документах, общая
команда из открытого документа, RLS личной настройки под двумя пользователями.

## Порядок и проверки

Модуль → обработка и форма → справочник → команда → шесть форм → права → удаление старой обработки → тесты;
«Что нового» 2.0.17.7; lint, refcheck, listcheck, colfont, menucheck; `ib-sync`; смок; тесты; `ai-review` →
`ai-security` (права, RLS, запись под пользователем) → `ai-final-check --db` → отчёт. У3 в `docs/UNF-ADOPTION.md` —
**частично**: поставлено — загрузка в ТЧ документов с номенклатурой, создание номенклатуры, настройки; остаток в
TECHDEBT и очереди У3 — приёмники-справочники, обновление существующих элементов, буфер обмена, ТЧ без номенклатуры,
скидки.

## Риски

- Удаление обработки: ссылки на неё в коде и правило tiny1C mdo-001 (образец) — refcheck и поиск по имени; правило
  в tiny1C не правлю (внешний набор), упоминание остаётся историческим.
- Большие файлы: пакетный поиск по колонке, предпросмотр — до первых 1000 строк, загрузка — всех.
- `ТабличныйДокумент.Прочитать` для xls под macOS/Linux — проверка человеком; csv — без зависимостей.

## Статус ревью плана

- Круг 1 — reject (2 P0, 4 P1): замена при связанных строках, пустой набор строк, количество при несопоставленных
  упаковках, цена против `ЦенаSKU`, упаковка и ставка из файла, неполные приёмники → единое заполнение
  `ЗаполнитьТЧ` (раздел 1), приёмники — только ТЧ с номенклатурой, скидки не загружаются.
- Круг 2 — reject (P0 материалы с собственным `КодСтроки`; P1 суммовые ТЧ, атомарность, коэффициент упаковки, вид
  цены до подбора цены; P2 запросы на строку) → явная карта подчинённых ТЧ с тестом-обходом, классы приёмников,
  расчёт в копии ТЧ, семантика коэффициента как у форм, параметры цены до значений по умолчанию, пакетные данные и
  расчёт вне транзакции со сверкой версии.
- Круг 3 — reject (3 P1): `СуммаСНДС` суммовых ТЧ, ставка НДС в ключе кеша цены, пары количеств с постфиксом
  (пересчёт «Факт») → внесены в шаги 3, 5, 6 и тест 3.
- Круг 4 — reject (2 P1, 2 P2): контекст цены документа (валюта, дата, контрагент) — через штатное
  `ПреобразоватьСтрокуТаблицыВСтруктуру`; `ПоступлениеДополнительныхРасходов.ТЧТовары` исключена; завершение команды
  из списка; пакетная подготовка цен продажи как в `УстановитьЦеныВТабличнойЧасти`.
- Круг 5 — reject (2 P1, P2): вид цены строки по правилу формы, ценовой расчёт только при `Цена` и `СтавкаНДС` в ТЧ,
  `ПроверитьЗаполнение()` перед записью → внесены.
- Круг 6 — reject (2 P1, P2): розничный вид цен в пакете резервных цен, характеристика и серия из штрихкода,
  У3 — частично с остатком в TECHDEBT → внесены.
- Круги 7–9 — по ошибке прогнаны на неизменённом плане (правки не применились); их находки: служебный
  `УказаноНесколькоСерий` и сверка колонок в `ЗаполнитьТЧ`, серия только среди серий товара, `ПересчётТоваров`
  исключён (TECHDEBT «режим обновления факта»), направление подбора цены и поставщик шапки, единая дата цены
  `КонецДня(Дата)`, атомарное создание товара → внесены в круге 10.
- Круг 10 — reject (P0 `УказаноНесколькоСерий`, P1 `ВыпускПродукции.ТЧГотоваяПродукция`, P2 серии) → внесены
  (выпуск исключён из приёмников).
- Круг 11 — reject (3 P1): оприходование — «закупка без поставщика», пересортица исключена (владельцы двух групп),
  блокировка окна владельца и проверка модифицированности перед `Прочитать()` → внесены.
- Круг 12 — reject (P0 акт разбора без долей стоимости, P2 продажа без вида цены) → акт разбора исключён (TECHDEBT),
  продажа без вида цены — розничная по умолчанию, тест полноты направлений уточнён.
- Круг 13 — **approve_with_changes** (P2: взаимоисключение ценовых колонок проверяется на сервере) → внесено.

## Отклонения при реализации

- Обработка `ЗагрузкаИзExcel` **переименована** в `ЗагрузкаИзФайла` (тот же uuid, форма переписана), а не удалена с
  созданием новой: данных у обработки нет, ссылки в подсистеме, правах и «Настройках программы» переехали
  переименованием.
- Без документа (из «Сервисных операций») форма даёт выбрать записанный документ и грузит в него — вместо
  подсказки «откройте документ».
- Автосопоставление: имя реквизита, синоним на языке сеанса и словарь частых заголовков на четырёх языках
  (синонимы метаданных на прочих языках платформа не отдаёт) — TECHDEBT.
- Второй реквизит типа «Номенклатура» в строке (`ЗаказПоставщику.ТЧТовары.Продукция`) приёмник не исключает:
  исключают только справочники, подчинённые номенклатуре, кроме характеристики и серии (пересортица исключена явно).
- Цены закупки берутся пакетом `ДанныеЦенДляСписка` по поставщику (а не вызовом на сочетание).
- Перечитывание формы-владельца после загрузки делает форма загрузки (блокирует окно владельца свойством формы), а не
  обработчик общей команды.
