# План: отчёт «Деньги и статусы заказов клиентов»

Запрос владельца (2026-11-01): отчёты руководителя «Деньги по заказам» и «Статусы заказов»: заказчик, долги, долги
по заказам, плановая отгрузка, процент отгруженного, сумма оплаченного, долг, себестоимость, маржинальность. Учёт
времени — Drissotex. Отчёт тиражный, без упоминания клиентов в конфигурации.

## Поиск готового

| Где | Что есть | Почему не подходит |
|---|---|---|
| maERP «Неотгруженные заказы» | заказано/отгружено по строкам заказа | нет денег, себестоимости, статуса |
| maERP «Ведомость по продажам» | выручка, себестоимость, прибыль по документам продажи | нет заказа, оплат, плановой отгрузки |
| maERP «Долги покупателей», «Расчёты с покупателями» | долг по контрагенту и объекту расчётов | нет заказа целиком, отгрузки, маржи |
| maERP список заказов клиентов | статус, картинки отгрузки/оплаты, долг объекта продажи | форма списка, без себестоимости и итогов |
| УНФ «Сводный анализ заказов покупателей» | сумма, оплачено, отгружено, осталось | нет себестоимости и маржи, другая модель регистров |

Готового нет — новый отчёт на схеме компоновки (чистая СКД, без своего вывода).

## Решения владельца (2026-11-01)

| Вопрос | Решение |
|---|---|
| Состав | **Один отчёт, два варианта**: «Деньги по заказам» и «Статусы заказов» |
| Долг по заказу | **Оба**: «Долг» = отгружено − оплачено (минус — аванс), «Осталось оплатить» = сумма заказа − оплачено; плюс общий долг заказчика |
| Какие заказы | **Незакрытые + созданные в периоде**, всё на конец периода |
| Учёт времени | Drissotex |

## Уровень изменения

Существенное: новый отчёт, права, меню. Только чтение данных. Порядок: план → **`ai-review-plan`** → реализация →
`ai-test` → **`ai-review`** → `ai-final-check` → отчёт `.ai/reports/order-money-status.md`.

## Показатели (на конец периода `К`, суммы — в валюте регламентированного учёта, из регистров)

**Связь с заказом — по регистрам, а не по суммам документов** (ревью плана, круг 1, P1 × 4): у безналичного поступления
нет реквизита шапки «Основание» с заказом; налоговая накладная и налоговая реализация на основаниях покрывают несколько
заказов и сторнируют продажи, себестоимость и расчёты исходных реализаций; возврат в валюте списка без пересчёта курса.
Регистры уже содержат суммы в основной валюте по курсу объекта.

**Физические таблицы регистров** (`ВзаиморасчётыСПокупателями` и др.) читаются **только активными движениями**
(`Активность`) и с периодом ≤ К — так же, как их видят виртуальные таблицы `Остатки`/`Обороты` (долг заказчика) и
`НалоговыеДокументыНаОснованиях.ПеренестиРасчеты` (круг 10, P1); иначе сальдо заказа разошлось бы с долгом заказчика.

**Объекты заказа** (`ОбъектРасчётов` / `ДокументПродажи` → заказ):
- `ЗаказПокупателя` — сам заказ;
- `ПриходныйКассовыйОрдер` — его `Основание` (тип `ЗаказПокупателя`);
- `РеализацияТоваровУслуг` **без строк табличной части `Основания`** (не налоговая на основаниях) — **её заказ** по
  правилу «Заказ реализации» ниже.

**Заказ реализации** — одно правило для всех мест отчёта (объекты расчётов, продажи, себестоимость, количества,
основания налоговых документов; круги 11–12, P1):
1. `Основание` реализации заполнено — этот заказ;
2. иначе — заказ, у которого `Основание` = эта реализация (заказ по совершившейся продаже,
   `ЗаказПокупателя.ЗаполнитьПоРеализации`), **если такой заказ ровно один** среди не помеченных на удаление **с `Дата` ≤ К** (поздняя копия не меняет прошлый
   период; круг 13, P1); копия заказа
   (`ПриКопировании` основание не очищает) даёт два — тогда
3. заказа нет: реализация к заказу не относится, её суммы — в «Не распределено по заказам».
Реализуется временной таблицей «Реализация → Заказ» в начале пакета, все остальные выборки соединяются с ней.
- налоговый документ, все основания которого ведут в один заказ, — этот заказ (см. ниже).
Всё прочее (налоговая накладная, налоговая реализация на основаниях, безналичное поступление и списание, РКО,
корректировка долга, сертификат) к заказу **не относится** — см. «Не распределено по заказам».

**Налоговые документы** (`НалоговаяНакладная`; `РеализацияТоваровУслуг` со строками `Основания`) переносят продажи,
себестоимость и расчёты исходных реализаций на себя; на них же пишутся последующие оплаты и возвраты (круги 1–3, P1).
**Заказы налогового документа** — через его основания: у налоговой реализации — `Основания.Основание` → «Заказ реализации», у
налоговой накладной — `ТЧТовары`/`ТЧУслуги.ОтгрузкаТовара` → «Заказ реализации».
- **Все основания ведут в один и тот же заказ** (у каждой строки основания заказ заполнен и совпадает; основание без
  заказа — допустимо, `КандидатыВОснования`, — делает документ общим; круг 4, P1) — налоговый документ сам становится
  **объектом этого заказа**: все его движения (перенос с
  исходной реализации, свои продажи и себестоимость, оплаты на него, возвраты по нему) входят в показатели заказа;
  перенос внутри заказа взаимно гасится, оплаченный через налоговый документ заказ закрывается.
- **Иначе (несколько заказов или основание без заказа)** — документ к заказу не относится: его движения переноса по объектам и продажам исходных
  реализаций **исключаются** (продажи и оплаты остаются за исходными заказами), а собственные движения (последующие
  оплаты) идут в «Не распределено по заказам» заказчика. **Исключение — регистраторы, которые сами ссылаются на конкретную
  реализацию** (круги 14–15, P1): `ВозвратОтПокупателя` (его `Основание`) и `СертификатНаОплату` (его `Реализация`)
  пишут уменьшение долга на покрывающую налоговую накладную (`НакладнаяПокрывающаяОснование`), но связь с заказом
  известна — их движения по объекту общего налогового документа относятся к **заказу этой реализации** (правило
  «Заказ реализации»): возврат — в отгрузку и долг, сертификат — в «Оплачено»; возврат — и в `Продажи`,
  `СебестоимостьПродаж`. Прочие регистраторы с объектом общего налогового документа (платежи без ссылки на реализацию)
  — в «Не распределено». Долями не делим — данных для этого нет (строки
  `Основания` не хранят номенклатуру, круг 3, P2).

| Показатель | Правило |
|---|---|
| Заказ, заказчик, менеджер, дата | `Документ.ЗаказПокупателя`: **не помечен на удаление**, **`Дата` ≤ К** (круг 1, P2). Условия «проведён» нет: заказ на продажу не проводится вовсе (`ЗаказПроводится(ВидОперации)`), проводятся только производственные (круг 7, P1) |
| Плановая отгрузка | `ДатаОтгрузки` |
| Статус | **текущий** статус (`ИсторияЗаказовПокупателейПоСтатусам.СрезПоследних` без даты) — период записи истории статусов — время сеанса, а не дата события (`РаботаСДокументами.ПериодЗаписиСтатусаЗаказа`), срез на К не дал бы состояния на К (круг 6, P1); колонка так и называется — «Статус сейчас» |
| Сумма заказа | `ВЫБОР ВВалюте ТОГДА СуммаРегл ИНАЧЕ Сумма` |
| Выручка (с НДС) | `Продажи.Обороты(, &ГраницаК)` — `ВыручкаОборот` по `ДокументПродажи` = объекты заказа; движения налоговых документов **на несколько заказов** исключаются. Возвраты регистр пишет минусом с пересчётом курса |
| Выручка без НДС | то же, `ВыручкаОборот − НДСОборот` |
| Себестоимость | `СебестоимостьПродаж.Обороты(, &ГраницаК)` — **`СуммаОборот − СуммаНДСОборот`** (ресурс `Сумма` себестоимости — с НДС: `ТоварыВНаличии` пишет `СуммаСНДС` в `Сумма`, `НоваяЗаписьСписания` переносит её как есть; круг 3, P1) по `ДокументПродажи` = объекты заказа; движения общих налоговых документов исключаются |
| Маржа, Маржинальность % | Выручка без НДС − Себестоимость; Маржа / Выручка без НДС × 100 — **при нулевой выручке без НДС маржинальность пуста** (круг 2, P2; как «Ведомость по продажам»), итоги — из сумм |
| % отгружено | по количеству (см. «Валюта»); при нулевом количестве заказа пусто; итоги — из сумм количеств |
| Оплачено (погашено долга) | `ВзаиморасчётыСПокупателями` (таблица движений, период ≤ К) по объектам заказа: **Σ сумм расхода (со знаком), регистратор — денежный документ** (`ПриходныйКассовыйОрдер`, `ПоступлениеБезналичныхДенежныхСредств`, `РасходныйКассовыйОрдер`, `СписаниеБезналичныхДенежныхСредств`, **`СертификатНаОплату`** — круг 6, P1), **реализация** (зачёт аванса) или **налоговый документ этого заказа**. Платёж гасит объект основания, остаток аванса — сам платёж (ПКО → его заказ); зачёт аванса реализацией пишет расход с минусом на объекте аванса и с плюсом на самой реализации — деньги переходят из заказа аванса в заказ продажи; возврат денег — расход с минусом |
| Долг по заказу | **сальдо движений** по объектам заказа (Σ приход − Σ расход, период ≤ К), без движений общих налоговых документов; тождественно = Отгружено (расчёты) − Оплачено − Корректировки |
| Отгружено (расчёты) | Σ приходов по объектам заказа (долг продаж, возвраты товара — приход с минусом), без общих налоговых документов — денежная колонка, согласованная с долгом |
| Корректировки | Σ расходов по объектам заказа с регистратором `КорректировкаДолга` (корректировка — не оплата; круг 5, P1) |
| Осталось оплатить | Сумма заказа − Оплачено (основная валюта; у валютного заказа — с курсовой разницей) |
| Долг заказчика | `ВзаиморасчётыСПокупателями.Остатки(&ГраницаК)` по `Контрагент` целиком; на группировке «Заказчик» — `Максимум` |
| Не распределено по заказам | на группировке «Заказчик»: Долг заказчика − Σ Долг по заказу **всех** его заказов на К (считается в запросе, до отборов пользователя; закрытые заказы долга не имеют) — оплаты и долги на объектах без заказа (общие налоговые документы, безнал без основания, продажи без заказа). Отбор по менеджеру или статусу его не меняет (ревью кода, P2) |
| Просрочка отгрузки, дней | **`ДатаОтгрузки` заполнена**, `ДатаОтгрузки` < К и % отгружено < 100 — дней от плановой даты до К; без плановой даты — пусто (реквизит не обязателен; круг 9, P2) |

**Валюта (круги 4–5, P1).** Все деньги отчёта — **в основной валюте** из регистров (`Сумма`), без `СуммаВВалюте`:
объекты расчётов одного заказа бывают в разных валютах (аванс на ПКО — в валюте кассы). Долг по заказу — **сальдо
движений** `ВзаиморасчётыСПокупателями` по объектам заказа: оплата закрывает объект **по курсу объекта**
(`РаботаСВалютами.СтрокаОплатыВРасчеты` пишет в движение сумму расчётов, курсовую разницу копит отдельно — для
регистра `Убытки`), поэтому полностью оплаченный валютный заказ даёт нулевое сальдо в основной валюте.
**«Оплачено» — это погашенный оплатами долг по курсу объектов, а не полученные деньги по курсу дня платежа** (круг 8,
P1): для заказа в основной валюте они совпадают, для валютного отличаются на курсовую разницу. Колонка называется
«Оплачено (погашено долга)», пояснение — в её подсказке; деньги по курсу платежа — отчёты по деньгам.

**% отгружено — по количеству**, тем же правилом, что механизм заказов (`ПроизводственныеЗаказы.ТекстЗапросаОтгрузок`,
круг 6, P1): строки реализаций заказа **с неордерных складов** (для ордерного склада с даты его ордерной схемы
реализация товар не отгружает; **строки услуг** — `ТипНоменклатуры` = `Услуга`, а также `ТЧУслуги`, — отгружает реализация
на любом складе: расходный ордер услуги не подбирает, `РасходныйОрдер.ManagerModule`, круг 16, P1) + строки проведённых
**расходных ордеров** с `Основание` = заказ − строки возвратов по
реализациям заказа и по его налоговому документу. **По позициям**, как `ПроизводственныеЗаказы.ДобавитьПоказателиСтрок`
(круг 7, P1): отгрузки группируются по номенклатуре и характеристике, зачтённое количество позиции ограничено
диапазоном [0; заказано позиции]; % отгружено = Σ зачтённого / Σ заказанного × 100 (перегруз одной позиции не
закрывает недогруз другой); **полностью отгружен** — каждая позиция зачтена целиком. При нулевом количестве заказа %
пусто. Курсы не участвуют.

**Какие заказы:** `Дата` ≤ К, не помечен на удаление, **и** (созданы в периоде **или** незакрыты на К). **Закрыт** —
одновременно: полностью отгружен по позициям (физически), **полностью реализован** по позициям (реализации заказа,
не налоговые, минус возвраты по ним и по налоговому документу заказа, тем же правилом позиций [0; заказано]) — иначе
заказ, отгруженный расходным ордером без реализации, долга ещё не имеет и выглядел бы закрытым (`ОрдераСклада.ПровестиОрдер`
расчётов не пишет; круг 9, P1), — **и** Долг по заказу = 0. Статус `Выполнен` закрытием не считается: его ставит только механизм стадий производственных заказов,
обычный заказ после реализации получает «Собран» и оплатой не меняется (круг 6, P1).

**Расхождение со списком заказов.** Список считает отгрузку суммами документов и сальдо по объектам с налоговой
накладной целиком в каждом заказе; отчёт — по регистрам, без двойного счёта. Отчёт точнее; выравнивание списка —
TECHDEBT.

## Схема компоновки

- Параметры: `Период` (`СтандартныйПериод`, по умолчанию текущий месяц); `НачалоПериода`, `КонецПериода`,
  `ГраницаКонца` — выражениями от `Период`, у всех `use = Always` и `availableAsField = false` (образец — «Остатки на
  складах»: без `Always` параметр виртуальной таблицы не передаётся, и запрос падает «несовместимость типов» — так было
  в «Переработке по переработчикам»).
- Один набор-запрос (временные таблицы во вложенных выборках не нужны: СКД сама соединяет), ресурсы с `totalField`,
  вычисляемые проценты — `totalField` из сумм.
- Варианты:
  - **«Деньги по заказам»**: группировка Заказчик (Долг заказчика, Не распределено) → Заказ; колонки Сумма заказа,
    Отгружено (расчёты), Оплачено, Корректировки, Долг по заказу, Осталось оплатить, Выручка без НДС, Себестоимость,
    Маржа, Маржинальность %.
  - **«Статусы заказов»**: таблица заказов: Заказчик, Заказ, Дата, Плановая отгрузка, Статус сейчас, Сумма заказа,
    % отгружено, Просрочка отгрузки; условное оформление — просроченные красным.
- Отборы пользователя: заказчик, менеджер, статус, заказ.

## Размещение и права

Раздел «Продажи» (отчёты), рядом с «Неотгруженными заказами».

**Права — только ролям, у которых есть чтение всех источников запроса** (круг 9, P1): `Документ.ЗаказПокупателя`,
`РеализацияТоваровУслуг` (с ТЧ `Основания`), `ВозвратОтПокупателя`, `РасходныйОрдер`, `НалоговаяНакладная`,
`ПриходныйКассовыйОрдер`, `СертификатНаОплату`, `Справочник.МестаХранения`, `Справочник.Номенклатура`
(тип номенклатуры для услуг), регистры `ВзаиморасчётыСПокупателями`, `Продажи`,
`СебестоимостьПродаж`, `ИсторияЗаказовПокупателейПоСтатусам`. Список ролей вычисляется скриптом по `Rights.rights` при
реализации (роль, которой не хватает хотя бы одного источника, отчёт не получает — иначе запрос упадёт на правах),
`Администратор`/`Руководитель` — автоматически (`setForNewObjects`). Сценарий уровня 3 проверяет по метаданным:
у каждой роли с `Просмотр` отчёта — `Чтение` всех источников.
