# Сортировка рабочих мест, сборка 3: «Источники» потребности (тикет 2605527, 2.0.17.34)

Продолжение `docs/plans/arm-sorting.md` (2.0.17.32) и `docs/plans/arm-sorting-2.md` (2.0.17.33). Решение владельца 17.11:
таблицы только для чтения — динамические списки, чтобы щелчок по заголовку сортировал; для таблиц со сложным расчётом —
«Переписать на запросы». 18.11: «Делай третью сборку». Последняя таблица — закупки `ИсточникиТовара` (нижняя закладка
«Источники» строки «Потребности»): сейчас `ТаблицаЗначений`, сортировка командами меню (вариант A).

## Почему не перенос расчёта в запрос списка

Строки источников считает `ИсточникиПотребности(Товары)`: пакет из 15+ временных таблиц (`ТекстЗапросаПотребности`) и
поправка дефицита переработчика кодом (`ПотребностиПроизводства.ПоправкиДефицитаПереработчика`). Тот же расчёт
используют «Потребность» (редактируемая, остаётся на значениях), заказ потребности, запрос предложений и перепроверка
дефицита под блокировкой. Динамический список не допускает временных таблиц; перенос пакета вложенными запросами дал бы
второй, независимый расчёт дефицита — риск расхождения с «Потребностью» и заказом, который владелец назвал при выборе, —
и пересчёт всей потребности по товару на каждый щелчок по заголовку.

**Решение:** расчёт не дублируется. Строки источников товара считаются как сейчас (`ДанныеСтрокиПотребности`, один раз на
смену строки «Потребности»), а динамический список показывает их **запросом без таблиц**: одна часть `ОБЪЕДИНИТЬ ВСЕ` на
строку источника, значения полей — параметрами списка. Сортировку, поиск и курсор делает платформа, как у остальных семи
списков; щелчок по заголовку ничего не пересчитывает (запрос из констант). Цифры совпадают с «Потребностью» по
построению — это те же значения.

Строк у товара немного: один заказ клиента в работе с этим товаром — одна строка, плюс пополнение склада.

## Поиск готового

- `ТекстЗаглушкиСписка`, `НастроитьДинамическиеСписки`, `УстановитьПараметрыСписка` (АРМЗакупки), генератор
  `Form.form` сборок 2.0.17.32–33, сценарий-образец `СпискиДокументовЗаказаАРМ` (`ПроверитьСписокКомпоновкой`,
  `ПроверитьУникальностьКлюча`) — берутся как есть.

## 1. Модуль менеджера `АРМЗакупки`

Новая экспортная `СписокИсточниковТовара(Источники)` → `Структура(Текст, Параметры)`:

- `Источники` — `ТаблицаЗначений` из `ДанныеСтрокиПотребности(...).Источники` (или пустая / `Неопределено`).
- Нет строк → `Текст = ТекстЗаглушкиСписка("ИсточникиТовара")` (новая ветка: те же поля, `ГДЕ ЛОЖЬ`), параметров нет.
- Иначе на строку `N` (с 1) — часть:

  ```
  ВЫБРАТЬ
  	ВЫРАЗИТЬ(&ИсточникN КАК Документ.ЗаказПокупателя) КАК Источник,
  	ВЫРАЗИТЬ(&ИсточникПредставлениеN КАК СТРОКА(150)) КАК ИсточникПредставление,
  	ВЫРАЗИТЬ(&НужноN КАК ЧИСЛО(15, 3)) КАК Нужно,
  	… Заказано, Пришло, СоСклада, НаСкладе, Дефицит — так же,
  	ВЫРАЗИТЬ(&ДатаОтгрузкиN КАК ДАТА) КАК ДатаОтгрузки
  ```

  части — через `ОБЪЕДИНИТЬ ВСЕ`. `СТРОКА(150)` — как у колонки реквизита сейчас; строка неограниченной длины не
  упорядочивается. Пустой источник (пополнение) передаётся `Документы.ЗаказПокупателя.ПустаяСсылка()`, а не
  `Неопределено`: ключ списка и `ВЫРАЗИТЬ` получают ссылку. Текст зависит только от числа строк, значения — в параметрах
  (имена из полей и номера, без данных в тексте).
- Типы точности чисел — как у колонок реквизита (`15, 3`); `Цена` в список не идёт (колонки нет; в режиме приёмки её
  обнуляет `ДанныеСтрокиПотребности`).

## 2. Форма `АРМЗакупки.Форма`

`Form.form` (генератором 2.0.17.33):

- реквизит `ИсточникиТовара` → `DynamicList`, `customQuery`, текст — заглушка; поля списка `Источник`,
  `ИсточникПредставление`, `Нужно`, `Заказано`, `Пришло`, `СоСклада`, `НаСкладе`, `Дефицит`, `ДатаОтгрузки`;
  `Источник` — в `notDefaultUseAlwaysAttributes` (его читает `ИсточникиТовараВыбор`);
- `ListSettings.dcss` — порядок `ДатаОтгрузки` по возрастанию (как сейчас: пакет упорядочен по дате отгрузки, пополнение
  в конце — `ДАТАВРЕМЯ(3999, 12, 31)`);
- пути колонок те же (`ИсточникиТовара.<Поле>`); кнопки контекстного меню `СортироватьПоВозрастанию/Убыванию` у таблицы
  снимаются; строка поиска — как у списков сборки 2.0.17.33.

Модуль формы:

- `НастроитьДинамическиеСписки`: `ИсточникиТовара` — ключ `Источник`, текст заглушки.
- `ЗагрузитьДанныеСтрокиПотребности`: вместо `Очистить` / заполнения / `ПрименитьПорядок` — новая
  `УстановитьСписокИсточников(Источники)`:
  1. запоминается ключ текущей строки (`Элементы.ИсточникиТовара.ТекущаяСтрока` — значение `Источник`);
  2. текст меняется, только если отличается (меняется лишь при другом числе строк); перед сменой запоминаются
     пользовательские настройки компоновщика (порядок по щелчку) и загружаются после неё — выбранная сортировка
     переживает смену строки «Потребности»;
  3. параметры — `УстановитьПараметрыСписка`; `Элементы.ИсточникиТовара.Обновить()`;
  4. если прежний источник есть среди новых строк — курсор на нём.
  Строки «Потребности» нет — пустая таблица → заглушка. `КлючиТекущихСтрок` для `ИсточникиТовара` снимается (если
  функция больше никем не используется — удаляется вместе с `ВернутьТекущиеСтроки`).
- `ИсточникиТовара` убирается из таблиц своей сортировки (`ПрименитьПорядок`).

Остальное не меняется: предложения и заказы товара по-прежнему берут заказы-источники из рассчитанной таблицы, не из
списка.

## 3. Тесты

Новый сценарий `СписокИсточниковТовараАРМ` (группа форм, `docs/TESTING.md`, `docs/TESTS.xlsx`):

- синтетика (не зависит от данных базы): таблица из трёх строк — два заказа клиента (последние в базе, если есть) и
  пополнение; текст и параметры выполняются запросом — строки и значения всех полей совпадают с таблицей, ключ уникален,
  пустой источник — пустая ссылка; компоновкой с порядком по каждому полю (`ПроверитьСписокКомпоновкой`) — то же число
  строк;
- данные базы: по товарам «Потребности» (до 20) — `ДанныеСтрокиПотребности(…, Истина)`, список выполняется запросом,
  поля и дефицит строк совпадают с рассчитанной таблицей по ключу `Источник`;
- пустая таблица и `Неопределено` → заглушка, те же поля, ни одной строки.

Прогоны: смок форм, сценарии `СписокИсточниковТовараАРМ`, `РабочееМестоЗакупок`, все тесты документов; lint против
baseline, refcheck, listcheck, colfont, queryfields.

## Риски

- Пользовательский порядок при смене текста запроса: сохраняется/загружается явно (п. 2); проверка — руками на клиенте
  (щелчок по «Дефициту», смена строки «Потребности» с другим числом источников — порядок остаётся).
- Много источников у одного товара (сотни заказов в работе на один материал) — длинный текст из констант; запрос без
  таблиц, СУБД не читается. Сценарий фиксирует максимум строк на товар в копии базы.
- Компоновка над запросом без `ИЗ` — проверяется сценарием (`ПроверитьСписокКомпоновкой`); если не пройдёт — части
  получают `ИЗ (ВЫБРАТЬ 1 КАК Поле) КАК Строка`, как у заглушки.

## Правки по ревью плана

Ревью плана — субагент Claude (Codex в лимите до 18.11 08:45), вердикт approve_with_changes, P0/P1 нет. Принято:

- **P2-1.** Курсор: `ТекущаяСтрока` списка с ключом по полю — `КлючСтрокиДинамическогоСписка`. Прежний источник читается
  `Ключ.Получить("Источник")` (при `ТипЗнч = КлючСтрокиДинамическогоСписка`), курсор ставится
  `Новый КлючСтрокиДинамическогоСписка(Новый Структура("Источник", Значение))`.
- **P2-2.** После каждой смены текста заново ставятся `ВидКлюча` и `ПоляКлюча`. Порядок: текст → ключ → загрузка
  пользовательских настроек → параметры → `Обновить()`.
- **P2-3.** Потолок — 100 строк (на MS SQL предел 2100 параметров на запрос). Остаются первые по `ДатаОтгрузки`,
  пополнение — всегда. Если строк было больше, заголовок закладки — «Источники (100 из N)».
- **P2-4.** Колонка «Источник» привязывается к ссылке `Источник`, а не к строке-представлению, поэтому сортирует по
  заказу, а не по тексту «Заказ покупателя …» (как вариант A, ревью arm-sorting P1-4). Для пустой ссылки (пополнение)
  текст «Пополнение склада» задаёт условное оформление формы: поле `Источник` не заполнено → «Текст». Поле
  `ИсточникПредставление` и его параметры не нужны.
- **P3-1.** Каждая часть объединения — `ИЗ (ВЫБРАТЬ 1 КАК Поле) КАК СтрокаN`, как у проверенной на клиенте заглушки.
- **P3-4.** Число частей округляется вверх до ступени 1, 2, 4, … 64, 100. Лишние части отсекает `ГДЕ &ЕстьN`
  (`Ложь`, поля — пустые значения), поэтому текст меняется редко. Параметров на строку — 9, при потолке не больше 900.
- **P3-2.** Тест дополнительно проверяет:
  - синтетику на 1 строку (без `ОБЪЕДИНИТЬ`);
  - порядок запроса по `ДатаОтгрузки`: пополнение последним;
  - одинаковый текст при числе строк одной ступени;
  - потолок: 150 синтетических строк дают 100, и пополнение среди них;
  - максимум строк на товар в копии базы — в итоге сценария.

  Сохранение настроек и курсор при смене текста — ручная проверка на клиенте.
- **P3-3.** `КлючиТекущихСтрок` и `ВернутьТекущиеСтроки` остаются: их вызывает `ЗагрузитьДанныеЗаказа`.
