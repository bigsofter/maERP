# Учёт станков: занятость сейчас и «когда освободится» (2.0.16.42, Drissotex)

Задача владельца 2026-10-09: «Отчёт по загруженности оборудования. Показывать загруженные и свободные машины +
период загруженности (когда освободится)». Решения владельца в тот же день: показывать **обе** даты — конец текущей
работы и первое свободное время после очереди плана; **новый отчёт + колонки на закладке «Станки»** АРМ производства.

## Что уже есть

- `ЗагрузкаСтанков.ЗанятостьСтанков` — записи «Загрузки станков» обоих слоёв (план/факт, работа/обслуживание),
  затянувшаяся загрузка продлена до момента + шаг (`Затянулась`).
- `ЗагрузкаСтанков.СостояниеСтанков` → закладка «Станки»: «Состояние сейчас» текстом (`ЗаполнитьСостояниеСейчас`),
  фонд, работа, % загрузки периода, ближайшее ТО. **Когда станок освободится — нигде не видно.**
- `БлижайшееОкно` / `ОкноВКонтексте` — первое свободное окно заданной длительности в рабочем времени (горизонт год).
- Отчёт «Загрузка станков» — распределение времени **за период**, не срез на момент.

Новых регистров, реквизитов и движений нет: только чтение существующих данных.

## Что делаю

### 1. `ЗагрузкаСтанков.ОсвобождениеСтанков(Станки, Момент = Неопределено) Экспорт` (новая)

Один раз читает `ИнтервалыРаботыСтанков` и `ЗанятостьСтанков` на горизонт `[Момент, Момент + ДнейГоризонтаОкончания)`
по всем станкам, дальше по станку — из массивов (`НайтиСтроки`). Возвращает ТаблицуЗначений:

| Колонка | Смысл |
|---|---|
| Станок | |
| Занят | Булево: момент накрыт хотя бы одной записью занятости (любой слой и вид) — то же правило, что у поиска окна; не зависит от текста состояния (ревью плана, круг 3) |
| Состояние | текст как на закладке (`ЗаполнитьСостояниеСейчас`), у затянувшейся — с хвостом «идёт дольше расчёта» |
| Документ | регистратор выбранной записи: требование или обслуживание |
| Заказ, Продукция | из выбранной записи (у обслуживания пусто) |
| Освободится | максимум окончаний **всех** записей, накрывающих момент (факт работы и ТО могут пересекаться — проверка пересечений ограничена одним видом записи), а не только выбранной; пусто — свободен или среди накрывающих есть затянувшаяся |
| Затянулась, РасчетноеОкончание | Затянулась — среди **всех** записей, накрывающих момент, есть затянувшаяся работа (даже если «Состояние» показывает фактическое ТО поверх неё); РасчетноеОкончание — её окончание до продления |
| СвободенС | начало **первого** свободного окна длиной в шаг планирования не раньше момента — то же правило, что «Разместить» (`ОкноВКонтексте`, округление до шага, сдвиг на смену, занято всё — оба слоя). Это «когда можно поставить новую работу»: окно может быть разрывом **внутри** очереди, позже в плане ещё есть загрузки — их конец показывает «Загружен до». Пусто — среди накрывающих момент записей есть затянувшаяся работа (конец неизвестен до «Завершить», продление на шаг — техническая граница планировщика, а не прогноз) или нет окна за год |
| ЗагруженДо | конец всей очереди: максимум окончаний записей «Загрузки станков» станка после момента (план и факт, работа и ТО) — **отдельным запросом без горизонта**; пусто — впереди ничего нет. Затянувшаяся работа в нём не участвует (её окончание неизвестно) |
| ЧасовРаботыВпереди | часы «Работы» (план ∪ факт, без двойного счёта) от момента в рабочем времени, в пределах горизонта года (подпись колонки — «Работы впереди (год), ч») — `ЧасыРаботыВРабочееВремя`; затянувшаяся считается до продления (момент + шаг) |

Решение владельца «обе колонки» трактуется так: «Освободится» — конец текущей работы, «Свободен с» — ближайшее свободное время, «Загружен до» — конец всей запланированной очереди (ревью плана Codex, P1-2: первое окно и конец очереди — разные даты, показываются обе).

Выбор записи «сейчас» — существующая `ЗаполнитьСостояниеСейчас`, переделанная в функцию, которая дополнительно
возвращает выбранную запись (приоритет прежний: факт ТО → факт работа → план ТО → нерабочее время → план работа →
свободен). В `ЗанятостьСтанков` добавляется колонка `РасчетноеОкончание` (окончание до продления; у прочих — равно
окончанию): потребители выгружают таблицу по именам колонок, лишняя колонка ничего не ломает.

### 2. `СостояниеСтанков` — через `ОсвобождениеСтанков`

Состояние/Требование берутся из `ОсвобождениеСтанков` (одна логика «сейчас» для отчёта и закладки), в таблицу
добавляются `Освободится`, `СвободенС` и `ЗагруженДо`. Два отдельных вызова `ЗанятостьСтанков`/`ИнтервалыРаботыСтанков` на `Момент`
уходят. Цена: чтение интервалов на год вперёд при обновлении списка закладки — цикл по дням × станки без запросов,
плюс один запрос занятости; у Drissotex станков единицы-десятки.

### 3. Закладка «Станки» АРМ производства

Реквизит `СтанкиСостояние`: колонки `Освободится`, `СвободенС`, `ЗагруженДо` (ДатаВремя). Колонки таблицы после «Состояние», формат
`ДФ='dd.MM.yyyy HH:mm'` (даты на год вперёд и дальше — с годом, ревью плана P2), шрифт шапки как у соседей (`colfont.py`), видимость `true` (урок edt-form-visible-default).

### 4. Отчёт «Занятость станков» (`Отчеты.ЗанятостьСтанков`, новый объект)

- Схема с внешним набором `Занятость` (как у отчётов сборки 4): поля таблицы п. 1 + `Занятость` (строка
  «Загружен»/«Свободен» на 4 языках для группировки и отбора).
- Параметр `Момент` (ДатаВремя), пусто — текущая дата сеанса.
- Вариант «Основной»: группировка `Занятость` → детальные `Станок`; колонки Состояние, Документ, Освободится,
  СвободенС, ЗагруженДо, ЧасовРаботыВпереди; порядок Занятость, Освободится. Отбор в быстрых настройках.
- `ManagerModule.ДанныеОтчета(Момент)` — станки: новая `ЗагрузкаСтанков.СтанкиЗанятости(Момент)` — не выведенные и не
  помеченные + станки с записью «Загрузки станков», кончающейся после момента, + с запущенным требованием (затянувшаяся),
  без горизонта; `СтанкиОтчетов` не подходит — тянет выведенные станки по завершённым требованиям (ревью плана, круг 3);
  предупреждение о пустом календаре — `ТекстПустогоКалендаря`. `ObjectModule.ПриКомпоновкеРезультата` —
  `ЗагрузкаСтанков.ВывестиОтчет`, как у «Загрузки станков».
- Регистрация: `Configuration.mdo`, подсистема «Производство» (content, видимость и порядок в «Отчётах» перед
  «Загрузкой станков»), ФО `ИспользоватьУчетСтанков`, роль `ОператорПроизводства` (Use, View — как у соседей).
  `menucheck.py` после правки.

### 5. Тесты

`ТестыДокументов.СценарийЗакладкаСтанков` (данные уже есть: ТО 8–10 по плану, загрузка 10:00–10:39, перенесённая
13:15–13:48, факт ремонта 15–16, затянувшаяся загрузка второго станка):
- на 8:30 первый станок: занят ТО по плану, освободится 10:00, свободен с 10:45 (первое окно после загрузки 10:39
  с шагом — разрыв внутри очереди), загружен до 16:00 (факт ремонта — конец очереди позже первого окна), работы
  впереди 1,2 ч;
- на 12:00 второй станок: затянулась, «Освободится» и «Свободен с» пусто, расчётное окончание 08:33; затем факт
  ремонта 11:30–13:00 поверх затянувшейся работы — «Состояние» про ремонт, но «Затянулась» и пустые даты остаются;
- запись станка за годовым горизонтом (ТО через 400 дней) попадает в «Загружен до» — горизонт его не обрезает;
- отчёт через `ДанныеОтчета` и компоновку с внешним набором — строка станка есть, схема собирается.
Реестр `docs/TESTS.xlsx` и `docs/TESTING.md` — дополнение сценария `ЗакладкаСтанков`.
