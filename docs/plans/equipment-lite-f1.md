# БПО-лайт, фаза 1 — устойчивое рабочее место (детальный план)

Общий план и причины — `docs/plans/equipment-lite.md`, раздел «Фаза 1». Здесь — раскладка по объектам и коду.
Сборка 2.0.16.95. Работает на текущей подсистеме `МенеджерОборудования*`, переносится в фазу 2 без изменений.
Открытые вопросы владельцу (поставка драйверов, обмен автономной кассы, модели, лицензия) фазу 1 не блокируют:
в автономной кассовой базе механизм тот же, справочник рабочих мест там свой.

## Метаданные

1. **Регистр сведений `ИдентификаторыРабочихМест`** (новый, независимый, непериодический, управляемые блокировки):
   - измерение `ИдентификаторКлиента` — Строка(50) (как `РабочиеМеста.Код`; идентификатор клиента — UUID 36 знаков
     или значение переопределения `ИдентификаторКлиентаДляРабочегоМеста`), ведущее нет, основной отбор;
   - ресурс `РабочееМесто` — СправочникСсылка.РабочиеМеста;
   - реквизиты `ИмяКомпьютера` — Строка(50), `ДатаПривязки` — Дата (дата и время), `Способ` — Строка(20)
     («Миграция», «Код», «Выбор», «Создание», «Объединение», «Перенос») — история для администратора.
   - Прямых прав ролям не даю (у `Администратор` `setForNewObjects` — права придут сами). Все чтения и записи —
     серверные функции менеджера `РабочиеМеста` в привилегированном режиме, с проверкой прав вызывающего там, где
     операция административная (ниже).
2. **`Справочник.РабочиеМеста`**: реквизит `ОбъединеноВ` — СправочникСсылка.РабочиеМеста (только чтение в формах).
   Добавление реквизита — реструктуризация без потерь.
3. Формы:
   - `ПодключаемоеОборудование.ФормаВыбораРабочегоМеста` — переделка: таблица кандидатов (реквизит формы
     ТаблицаЗначений: `Ссылка`, `Наименование`, `ИмяКомпьютера`, `ТожеИмяКомпьютера`, `Оборудование` — строка
     «N: устройство, устройство…»), сначала места с тем же именем компьютера; над таблицей — имя компьютера и
     пояснение; команды «Это рабочее место» (по умолчанию), «Создать новое», «Отмена». Результат закрытия —
     `Структура("РабочееМесто")` или `Неопределено`. Параметр `Кандидаты` — массив ссылок (форма сама читает
     описания с сервера), параметр `ИмяКомпьютера`.
   - `РабочиеМеста.ФормаЭлемента` — закладка «Идентификаторы» (таблица из регистра, только чтение) с командой
     «Перенести на другое рабочее место» и команда «Перенести оборудование с другого рабочего места» у списка
     оборудования; поле `ОбъединеноВ` (видно, только если заполнено).
   - `РабочиеМеста.ФормаСписка` — команда «Объединить с…» → новая форма `РабочиеМеста.ФормаОбъединения`.
   - `РабочиеМеста.ФормаОбъединения` (новая): источник (дубль) и приёмник; таблица оборудования обоих мест
     (`Оставить` — флажок, `Место`, `Наименование`, `Тип`, `Драйвер`, `Совпадает`); совпадающие строки подсвечены
     условным оформлением; по умолчанию из совпадающей пары оставлена запись приёмника. Текст-предупреждение
     «выполнять при закрытой 1С на этих кассах». Команда «Объединить».
   - `VentesEnDetail.Form` — `ПодключитьОборудование(УникальныйИдентификатор, Истина, Истина)` и кнопка общей
     команды `ВыбратьРМТекущегоСеанса` в командной панели.

## Сервер: модуль менеджера `Справочник.РабочиеМеста`

Все функции — `Экспорт`, привилегированный режим внутри, документированы. Клиент зовёт их через обёртки в
`МенеджерОборудованияВызовСервера` (модуль вызова сервера).

- `ОпределитьРабочееМесто(ИдентификаторКлиента, ИмяКомпьютера)` → `Структура`:
  `РабочееМесто` (ссылка или пустая), `Кандидаты` (массив ссылок, порядок — сначала то же имя компьютера),
  `Способ` («Регистр», «Код», «Выбор»).
  1. Запись регистра по идентификатору → место; если у места заполнено `ОбъединеноВ` — переход по цепочке (не
     глубже 10, цикл — стоп); итог не помечен и не объединён → он, без диалога и без записи.
     Итог помечен на удаление → запись пропускается, идём в п. 2.
  2. `Код = ИдентификаторКлиента` среди непомеченных и необъединённых мест: одно → привязка идентификатора
     (`ПривязатьИдентификатор`, способ «Код»), возвращается место; несколько → `Кандидаты` = эти места,
     `Способ = "Выбор"`.
  3. Нет — `Кандидаты` = все непомеченные необъединённые места (сначала с тем же `ИмяКомпьютера`), `Способ = "Выбор"`.
     Никогда ничего не создаёт.
- `ОписаниеКандидатов(Кандидаты, ИмяКомпьютера)` → массив структур для формы выбора (одним запросом: место +
  оборудование, помеченное оборудование не показывается).
- `ПривязатьИдентификатор(ИдентификаторКлиента, РабочееМесто, ИмяКомпьютера, Способ)` → `Структура("Успех, Текст")`.
  Протокол блокировок (общий): `НачатьТранзакцию`; исключительная блокировка элемента `Справочник.РабочиеМеста`
  по ссылке; исключительная блокировка `РегистрСведений.ИдентификаторыРабочихМест` по идентификатору; под
  блокировкой — место не помечено и не объединено; запись регистра по идентификатору: нет / указывает на это же
  место / указывает на помеченное или объединённое место → пишем; указывает на другое действующее место → отказ
  «идентификатор уже привязан к …». Логический отказ — `ЗафиксироватьТранзакцию` (ничего не записано) и возврат
  `Успех = Ложь`: так вызов внутри транзакции автотеста не ломает внешнюю транзакцию. Исключение —
  `ОтменитьТранзакцию` + `ВызватьИсключение`.
- `СоздатьРабочееМесто(ИдентификаторКлиента, ИмяКомпьютера)` → ссылка или исключение. Одна транзакция: под
  блокировкой идентификатора проверка, что он не привязан к действующему месту (иначе отказ — возвращается то
  место); элемент (`Код` = идентификатор — совместимость, `ИмяКомпьютера`, наименование как сейчас) и запись
  регистра (способ «Создание»).
- `ПеренестиИдентификатор(ИдентификаторКлиента, НовоеМесто)` — администратор. Блокировки: старое и новое место в
  порядке uuid, затем идентификатор; новое место — не помечено и не объединено; старое может быть помечено.
- `ПеренестиОборудование(Источник, Приемник, Оборудование)` — администратор. Блокировки: оба места в порядке uuid;
  приёмник — не помечен и не объединён; источник ≠ приёмник; каждое устройство принадлежит источнику (под
  блокировкой). Запись устройства — через объект (его `ПередЗаписью` возьмёт те же блокировки повторно).
- `ОбъединитьРабочиеМеста(Источник, Приемник, ОставитьОборудование)` — администратор. Блокировки: оба места в
  порядке uuid; под блокировкой: источник ≠ приёмник, источник не объединён (иначе отказ «уже объединено в …»),
  приёмник не помечен и не объединён. Далее под блокировками идентификаторов источника: записи регистра
  источника → приёмник (способ «Объединение»); оборудование источника из `ОставитьОборудование` → приёмник,
  остальное оборудование обоих мест, не вошедшее в `ОставитьОборудование`, — пометка удаления; у источника
  `ОбъединеноВ = Приемник`, пометка удаления. Встречное объединение B→A, начавшееся во время A→B, ждёт блокировку и
  получает отказ (A уже объединено). Запись источника — объектом в режиме, который не запускает переустановку
  параметра сеанса (см. `ObjectModule`).
- `ПроверитьПравоАдминистрирования()` — для трёх административных операций до включения привилегированного режима:
  `ПравоДоступа("Изменение", Метаданные.Справочники.РабочиеМеста)` и
  `ПравоДоступа("Изменение", Метаданные.Справочники.ПодключаемоеОборудование)`; нет — исключение с текстом.
  Привязка и создание доступны любому пользователю (как сейчас создание из клиента).
- `ПеренестиКодыВРегистр()` — для обработчика обновления (ниже).

`ПодключаемоеОборудование.ObjectModule.ПередЗаписью` (вне `ОбменДанными.Загрузка`): исключительная блокировка
места объекта и, если `РабочееМесто` изменено, — прежнего места из базы, в порядке uuid; отказ, если место объекта
помечено на удаление или объединено, кроме записи, которая только ставит пометку удаления самому устройству.
Источник переноса (прежнее место) может быть помечен.

`РабочиеМеста.ObjectModule`: `ПередЗаписью` как сейчас (сброс параметра сеанса при пометке текущего места).
`МенеджерОборудованияВызовСервера.НайтиРабочиеМестаПоИД` и `УстановитьПараметрыСеансаПодключаемогоОборудования`
переводятся на `ОпределитьРабочееМесто` (массив из 0 или 1 места — первый из нескольких больше не берётся);
`СоздатьРабочееМестоКлиента` удаляется (звал только клиент).

## Клиент

`МенеджерОборудованияКлиент`:
- `ОбновитьРабочееМестоКлиента()` — тот же контракт «Булево», новая суть: параметр сеанса заполнен → Истина; иначе
  тихий `ОпределитьРабочееМесто`; найдено → `УстановитьРабочееМесто` (без переподключения: ещё нечего
  переподключать) → Истина; не найдено → Ложь. Ничего не создаёт. После смены места на клиенте —
  `ОбновитьПовторноИспользуемыеЗначения()` (кэш `МенеджерОборудованияКлиентПовтИсп.ПолучитьРабочееМестоКлиента`
  клиентский, серверный сброс его не чистит).
- `ПриНачалеРаботыСистемы`: тихое определение места, затем `ПереустановитьПомеченныеДрайверы` берёт место из
  параметра сеанса (не определено — пропуск). Установка — `Асинх` с `Ждать УстановитьВнешнююКомпонентуАсинх(...)`
  в `Попытка`; признаки «требуется установка/переустановка» сбрасываются только при успехе; ошибка — в журнал и
  сообщение. Пока установка идёт, `глПодключаемоеОборудование.ИдётУстановкаДрайверов = Истина`, и подключения
  встают в очередь; по завершении очередь разбирается.
- Очередь и реестр в `глПодключаемоеОборудование` (`ПередНачаломРаботыСистемы`):
  `ЗапросыФорм` — массив `Структура("ИдентификаторФормы, ТипыПО, Оповещение")`, пополняется каждым
  `ОперацииСПодключаемымОборудованиемКлиент.ПодключитьОборудование`, чистится `ОтключитьОборудование` по форме;
  `ОтложенныеПодключения` — идентификаторы форм, ждущих рабочего места; `ВыборРабочегоМестаОткрыт`,
  `ОповещениеОНеопределённомМестеПоказано`.
- `ЗапроситьПодключение(Запрос, РазрешитьВыбор)`: место определено и установка не идёт → подключить; иначе — в
  `ОтложенныеПодключения`; `РазрешитьВыбор` → `ОткрытьВыборРабочегоМеста` (если ещё не открыт); не разрешён и в
  базе есть действующие сканеры у какого-либо места (иначе подключать нечего и сообщать незачем) → одно
  `ПоказатьОповещениеПользователя` за сеанс «Сканер не подключён: рабочее место не определено» с действием
  «выбрать рабочее место».
- `ОткрытьВыборРабочегоМеста(ОповещениеПослеВыбора = Неопределено)`: `ОпределитьРабочееМесто`; найдено →
  установить и разобрать очередь; иначе — форма выбора (немодально, `БлокироватьВесьИнтерфейс`) с
  `Кандидаты`/`ИмяКомпьютера`. Результат: место → `ПривязатьИдентификатор` (отказ — сообщение, форма снова);
  «Создать новое» → `СоздатьРабочееМесто`; затем `УстановитьРабочееМесто`. Закрыли без выбора — сообщение
  «Оборудование не подключено: выберите рабочее место (Настройка → Выбрать рабочее место)».
- `УстановитьРабочееМесто(Место)` (публичный контракт тот же): прежнее место ≠ новое → `НачатьОтключениеВсегоОборудования`
  (синхронно очищает реестр подключений), все `ЗапросыФорм` открытых форм — в очередь; параметр сеанса;
  сброс клиентских кэшей; `Оповестить("ИзмененоРабочееМестоТекущегоСеанса")`; разбор очереди.
- `РазобратьОчередьПодключений()`: открытые формы — `ПолучитьОкна()` → `Содержимое` → `УникальныйИдентификатор`;
  для каждой отложенной открытой формы — `НачатьПодключениеОборудованиеПоТипу` с её оповещением; закрытые формы
  из реестра и очереди удаляются.
- `ВыбратьРМТекущегоСеанса` (общая команда) → `ОткрытьВыборРабочегоМеста` с явным показом формы даже при
  определённом месте (смена места пользователем): в форму передаются все действующие места, текущее отмечено.
- Синхронные потребители (`ПодключитьОборудование` синхронный, `НачатьПодключениеОборудования`,
  `ПредложитьВыбратьУстройство`, `ПредложитьВыбратьСмену`, `ОткрытьРабочиеМеста/ПодключаемоеОборудование/Драйверы`)
  только читают: `ОбновитьРабочееМестоКлиента()` больше ничего не создаёт.

`ОперацииСПодключаемымОборудованиемКлиент.ПодключитьОборудование(УИД, СканерШК = Ложь, РазрешитьВыборРабочегоМеста = Ложь)`
→ `МенеджерОборудованияКлиент.ЗапроситьПодключение`. `ОтключитьОборудование` чистит реестр формы. ~20 форм не
меняются, РМК передаёт Истина.

## Обработчик обновления 2.0.16.95

`ОбновлениеПрограммыОбработчики.ПеренестиИдентификаторыРабочихМест` (монопольно) → `РабочиеМеста.ПеренестиКодыВРегистр()`:
- непомеченные места, `ВРег(СокрЛП(Код))` непустой, группировка по коду: в группе одно место и записи регистра по
  коду нет → запись (способ «Миграция», `ИмяКомпьютера` места); запись есть — пропуск (повтор безопасен);
  в группе больше одного места → не пишется, в журнал регистрации предупреждение: код, места, число устройств у
  каждого (дубли разбирает администратор командой «Объединить с…»).
- Ничего не удаляет и не сливает. Итог в журнал: перенесено / уже было / неоднозначных кодов.
- В начальном заполнении не нужен (новая база пустая).

## Автотесты (`ТестыДокументов`, уровень 3, транзакция с откатом)

Сценарий `РабочиеМеста` (одно имя — подсценарии внутри, общий набор мест), на уникальных идентификаторах вида
`ТЕСТ-<uuid>`, чтобы не задеть места базы клиента:
1. известный идентификатор (запись регистра) → место, `Способ = "Регистр"`;
2. новый идентификатор, одно место с тем же `ИмяКомпьютера` → `РабочееМесто` пусто, место первое в `Кандидаты`;
3. неоднозначный `Код` (два места) → пусто, кандидаты — оба; однозначный `Код` → место и появилась запись регистра;
4. привязка идентификатора, занятого другим действующим местом, → `Успех = Ложь`, запись не изменилась;
   привязка к помеченному месту → отказ; запись на помеченное место считается свободной;
5. объединение: оборудование и идентификаторы источника у приёмника, у источника `ОбъединеноВ` и пометка;
   определение по идентификатору источника → приёмник; повторное объединение и встречное (приёмник → источник) —
   отказ; совпадающее устройство, не отмеченное «оставить», помечено на удаление;
6. миграция: `ПеренестиКодыВРегистр` на двух местах с одинаковым кодом и одном однозначном — запись только для
   однозначного; повторный запуск ничего не меняет.
Административные операции в тесте вызываются под пользователем прогона (у него права администратора).

## Ручные проверки (уровень 4 нет — чек-лист в `docs/TESTING.md`, строки `TESTS.xlsx`)

Новый профиль 1С на кассе → форма выбора, а не новое место; РМК открыт до выбора → после выбора сканер подключён
без переоткрытия; две формы со сканером ждут выбора → обе подключены; выбор закрыт → сообщение и кнопка в РМК;
RDP: два сеанса одного сервера — разные идентификаторы, одно имя компьютера → оба видят подсказку, привязка у каждого
своя; смена места командой «Выбрать рабочее место» при открытом РМК — сканер нового места подключён.

чужих сеансов (ограничение платформы — предупреждение в форме объединения).

## Гейты

## Правки по ревью плана (Codex, 2026-10-18, `.ai/reviews/equipment-lite-f1/02-plan-review.json`, reject → правки)

- **P0, чужой идентификатор через привилегированный API.** Клиент идентификатор больше не передаёт. При старте
  `УстановитьПараметрыСеансаКлиента` кладёт в `ПараметрыКлиентаНаСервере` `ИдентификаторРабочегоМеста`
  (`ИдентификаторКлиентаДляРабочегоМеста`, с переопределением) и `ИмяКомпьютера`; сервер фиксирует их один раз за
  сеанс (повторный вызов установщика эти ключи не меняет). Функции менеджера `РабочиеМеста` с параметром
  идентификатора с клиента недоступны (модуль менеджера — только сервер); обёртки `МенеджерОборудованияВызовСервера`
  для пользователя — без идентификатора: `ОпределитьРабочееМестоСеанса()`, `ВыбратьРабочееМестоСеанса(Место)`,
  `СоздатьРабочееМестоСеанса()`. Операции над чужими идентификаторами — только административные
  (`ПеренестиИдентификатор`, `ОбъединитьРабочиеМеста`, право `Администрирование`). Автотест: обёртки не имеют
  параметра идентификатора (сверка сигнатур), административная функция без права — исключение (проверяется
  `ДоступноАдминистрирование`).
- **P1, смена места сеанса.** `ВыбратьРабочееМестоСеанса(Место)`: место действующее (иначе отказ); идентификатор
  свободен (нет записи или запись на недействующее место) → постоянная привязка; уже привязан к другому
  действующему месту → меняется только параметр сеанса, постоянная привязка остаётся, пользователь получает текст
  «до конца сеанса; закрепить за этим компьютером — администратор, карточка рабочего места → «Перенести на другое
  рабочее место»». Следующий вход — снова по записи регистра. Результат: `Структура("Успех, Текст, ТолькоСеанс")`.
- **P1, гонки отключения и подключения.** `глПодключаемоеОборудование.ПоколениеПодключений` (Число): растёт при
  каждой смене места; асинхронное подключение запоминает поколение в параметрах команды, завершение
  (`НачатьПодключениеОборудования_ПолучениеОбъектаДрайвераЗавершение`/`…_Завершение`) при устаревшем поколении
  не добавляет устройство в реестр, а отключает его и сообщает форме «отменено: рабочее место сменилось». Отключение
  при смене места — `ОтключитьВсёОборудованиеИПродолжить(Продолжение)`: синхронные драйверы сразу, асинхронные —
  счётчик ожидаемых завершений; очередь нового места разбирается только после последнего завершения
  (`ИдётОтключение` = Истина до тех пор).
- **P1, устаревший список объединения.** `ОбъединитьРабочиеМеста(Источник, Приемник, Оставить, Удалить)` — два явных
  списка. Под блокировками сервер перечитывает непомеченное оборудование обоих мест: множество должно совпасть с
  `Оставить ∪ Удалить` (без пересечения), иначе отказ «данные изменились, откройте объединение заново», ничего не
  записано. Помечаются только устройства из `Удалить`. `ПеренестиОборудование` — так же: сначала под блокировкой
  проверка, что все устройства у источника, затем запись (отказ без частичной записи).
- **P1, обход ожидания установки.** `РазобратьОчередьПодключений()` — единственная точка допуска: место определено,
  `ИдётУстановкаДрайверов` = Ложь, `ИдётОтключение` = Ложь; иначе ничего не делает, запросы остаются в очереди.
  Завершение установки и отключения вызывает разбор. `ОткрытьВыборРабочегоМеста` при определённом месте форму не
  открывает (кроме явной команды смены) и только зовёт разбор.
- **P2, поставка.** Версия `Configuration.mdo` → 2.0.16.95; секция `## 2.0.16.95` в `ОписаниеИзменений/Template.txt`
  на ru/fr/en/es; версия обработчика обновления = 2.0.16.95.

### Второй круг ревью плана (reject → правки)

- **P1, параллельные подключения одного устройства.** Очередь строго последовательная: запрос формы
  разворачивается в задания «форма × устройство» (список устройств места по типам — один серверный вызов на
  поколение и набор типов), задание выполняется `НачатьПодключениеОборудованиеПоИдентификатору` — для одного
  устройства оповещение приходит ровно один раз в любой ветке. Следующее задание стартует только из оповещения
  предыдущего (`ПодключениеВПроцессе`). Второе задание того же устройства застаёт его в реестре подключений и
  только добавляет форму в клиенты.
- **P1, барьер смены места.** Смена места: `ПоколениеПодключений` + 1, ожидаемое место запоминается; если идёт
  подключение — переход продолжается из его оповещения. Затем отключение всего оборудования с ожиданием каждого
  асинхронного завершения (счётчик), затем параметр сеанса, затем подготовка драйверов нового места, и только
  после этого открывается допуск очереди. Задание, завершившееся после смены поколения, своё устройство в форму не
  отдаёт: оно уже отключено общим отключением перехода (переход ждал это задание).
- **P2, установка драйверов после выбора места.** Подготовка драйверов (`ТребуетсяУстановка/Переустановка`) —
  шаг каждого перехода на место (старт сеанса, выбор, смена), а не только старта; общий план (`equipment-lite.md`)
  с этим согласован.
- **P2, права на команду выбора.** Общая команда `ВыбратьРМТекущегоСеанса` существующая; право `View` проверяется
  у всех пользовательских ролей с доступом к РМК и документам со сканером (см. отчёт), недостающие выдаются.
- Окна клиента (`ПолучитьОкна`) для отбора «открытых форм» не используются: проверить на живом клиенте 8.5 нельзя,
  а лишний клиент у подключения (закрытая форма) безвреден — события сканера идут глобальным оповещением. Реестр
  запросов — соответствие по идентификатору формы (повторное открытие не плодит записи), `ОтключитьОборудование`
  запись удаляет.
