# Налоговые документы не двигают товар

Решение владельца от 2026-09-28, версия 2.0.15.72. Первый шаг «белого» товарного
учёта (`docs/plans/belyi-tovarnyi-uchet.md`): налоговые документы не трогают
управленческий `ТоварыВНаличии`. Белый регистр количеств — позже, по плану.

## Повод

База 2MZL: реализации идут по изделиям собственного производства (автовыпуск),
налоговых поступлений нет, склад один. Налоговая накладная по такой реализации
списывала тот же товар второй раз из `ТоварыВНаличии` без права на недостачу —
отказ проведения, а при остатке — двойное списание реального склада. Налоговая
накладная покупки на том же складе оприходовала бы товар повторно поверх
поступления, налоговый возврат от покупателя — по цене продажи.

## Что сделано

1. `ТоварыВНаличии.СформироватьДвижения`: для `НалоговаяНакладная`,
   `НалоговаяНакладнаяПокупка`, `ВозвратОтПокупателяНалоговый`,
   `ВозвратПоставщикуНалоговый` (функция `ЭтоНалоговыйДокумент`) — только проверка
   `СкладНалоговый`. Списания, оприходования и распределения издержек нет.
2. В этих документах снята блокировка `УправляемыеБлокировки.ТоварыВНаличии`:
   остатки не читаются. Блокировки взаиморасчётов остались.
3. Перепроведение старого документа стирает прежние товарные движения
   (`УстановитьЗаписьВсехРегистров` + `AutoDelete`).

## Чего не делали и почему

- **Запасное заполнение организации и склада** из реализации для организации без
  основного учёта и без ведущей — отказались. При такой организации накладная
  задваивает оплаты в `ДенежныеСредстваОрганизаций` (перенос денег в ведущую
  организацию, которой нет) и не пишет `ВзаиморасчётыСПокупателямиНалоговый`. Для
  2MZL решено данными: у организации включён «Основной учёт», склад `Principal`
  помечен «Налоговый» (владелец, 2026-09-28).
- **Обработчик обновления** для уже проведённых налоговых документов не делается:
  у 2MZL их нет, данные drissotex в maERP ещё не перенесены. Хвост — в TECHDEBT.
- **Отчёты** `ПроданныйТоварБезНакладной` и `ОтчетПоНедостаткамТовара` читают
  `ТоварыВНаличии` налогового склада — до белого регистра записаны в TECHDEBT.

## Проверка

- Ревью плана: субагент Claude `architecture-critic` (Codex — сбой CLI без текста,
  OpenCode Zen — 402, нет кредитов). Находки P1-1 (возврат по накладной приходовал
  по цене продажи) и P2-1 (задвоение денег) закрыты решениями выше.
- Сценарий `ТестыДокументов` `НалоговыеДокументыБезТовара`; все 38 сценариев
  прошли на копии `build/ib` с конфигурацией 2.0.15.72.
