- Роли-допуски без прав на объекты уже есть (`ПродажаНижеМинимальнойЦены`, проверка в коде); роль с правами на один

## Фаза 5.1 — сборка 2.0.17.13

### 1. Показатели движения товаров

- Три значения `Перечисление.ПоказателиДвиженияТоваров` с uuid клиента (перечисление уже с тем же uuid):
  `Оприходовано` — `7a0d42c3-ce66-4f31-8eb1-ce3e4d6cb70b`, `ПеремещениеСписание` —
  `cec7d143-d1d4-4846-9fc0-4d54d2114445`, `ПеремещениеОприходование` — `58735bc9-b486-482b-94b7-938c66f9835b`;
  синонимы на четырёх языках. Новые значения — в конце списка (порядок существующих не меняется; значение по
  умолчанию перечисления — первое, оно прежнее).
- `Отчет.ДвиженияТовара`: оба источника схемы — `ТоварыВНаличии.Обороты` (поля `КоличествоОборот`, без вида
  движения строки). `ОприходованиеТоваров` → `Оприходовано` — новой веткой `ВЫБОР`. Для `ПеремещениеТоваров`
  **источник меняется**: регистратор-перемещение исключается из основной выборки и добавляется объединением двух
  выборок из того же `Обороты`: приход → `ПеремещениеОприходование`, расход → `ПеремещениеСписание`. Правила веток
  раздельные, как в действующей схеме: **количественные** выборки — количество = `КоличествоПриход` / −
  `КоличествоРасход`, вес — из этого количества, сумма = 0, нулевые отбрасываются по количеству; **суммовые** —
  сумма = `СуммаПриход` / − `СуммаРасход`, количество и вес = 0, нулевые отбрасываются по сумме. Остальные поля
  (склад, номенклатура, период) — как в действующих ветках. Перемещение пишет две стороны (разные склады) — каждая
  сторона даёт свою строку. Общие итоги по складу и товару не меняются; прежде эти документы шли в «Прочее» —
  итог «Прочее» уменьшается. Сверить тесты `ДвиженияТовара` (`ТестыДокументов`), где ожидается «Прочее».

### 2. Отчёт «Анализ инвентаризаций» (`Отчет.АнализИнвентаризаций`, uuid `9f3af05a-c945-4bae-ab03-b9156adceeb4`)

- Параметр — проведённый `ПересчётТоваров`. Корректировки инвентаризации — **только проведённые и не помеченные на
  удаление** `СписаниеТоваров`/`ОприходованиеТоваров` с основанием = этот пересчёт и тем же складом (своим запросом,
  не `ПолучитьДокументыПоИмениПоОснованию`: тот не фильтрует проведение и пометку). Черновик или распроведённая
  корректировка границы не меняет.
- **Сопоставимая предыдущая инвентаризация** — последний проведённый пересчёт того же склада с меньшим моментом
  времени, чей охват содержит охват текущего: полный пересчёт (пустая `ТоварнаяГруппа`) — граница для любого;
  пересчёт группы — только для пересчёта той же группы. Текущий полный, а последние — пересчёты групп: граница —
  последний полный. **Состав отчёта — сохранённые строки текущего пересчёта** (номенклатура, характеристика, серия),
  а не текущая товарная группа номенклатуры: перенос товара в другую группу после пересчёта строку не теряет.
- **Границы**: конец предыдущей — самый поздний момент её корректировок, без них — момент самого пересчёта.
  **Учётное количество и расхождение — сохранённые в строках пересчёта** (`Количество` и `КоличествоФакт`): по ним
  созданы корректировки (`СписаниеТоваров`/`ОприходованиеТоваров` берут сохранённые количества). Справочно —
  остаток на границу пересчёта по текущим движениям — `Документы.ПересчётТоваров.УчетныеОстатки` с новым
  необязательным параметром «набор номенклатуры» (строки пересчёта; при нём отбор по текущей группе не ставится,
  прежние вызовы без параметра работают как раньше) и
  колонка «Изменение истории» = текущий − сохранённый; ненулевая — предупреждение в шапке «Движения до пересчёта
  изменены после него». Остаток на начало — `Остатки(Граница(конец предыдущей, Включая))` (корректировки
  предыдущей уже в нём); обороты по показателям — с `Граница(конец предыдущей, Исключая)` по границу текущего
  пересчёта; движения между пересчётом и его корректировками в сравнение с фактом не входят (отдельная колонка
  «После пересчёта», справочно). Первая инвентаризация склада — остаток на начало ноль, обороты с начала учёта.
  Пересечение (конец предыдущей позже момента текущего пересчёта) — обороты пустые, остаток на начало = учётному,
  в шапке отчёта предупреждение «Инвентаризации пересекаются».
- Колонки по номенклатуре (характеристика, серия): остаток на начало, обороты по показателям движения (те же
  правила `ВЫБОР`, что в п. 1, — общий текст выражения в модуле отчёта, а не копия), учётный остаток на момент
  пересчёта, факт пересчёта (`КоличествоФакт`), расхождение. Регистр — `ТоварыВНаличии` (как `ДвиженияТовара`);
  на ордерном складе — тот же физический источник, что в `ДвиженияТовара`.
- СКД + модуль объекта (`ПриКомпоновкеРезультата` вычисляет даты периода запросом и ставит параметры). Команда
  «Анализ инвентаризации» в форме и списке `ПересчётТоваров` (параметризуемая, открывает отчёт по документу).
  Подсистема «Склад → Инвентаризация», роли: Кладовщик, Руководитель, Администратор (просмотр отчёта и чтение
  `ПересчётТоваров` у них уже есть).

### 3. Отчёт «Отгрузки с изменёнными ценами» (`Отчет.ОтгрузкиСИзмененнымиЦенами`, uuid `d5eeaffb-85aa-44dd-be91-ac090bd462fd`)

- Строки проведённых реализаций за период (склад, контрагент — отборы), у которых цена строки отличается от цены
  прайса **на момент реализации**. У клиента срез без даты (текущая цена) — после переоценки в отчёт попадали все
  прошлые продажи; здесь это исправлено.
- **Вид цены — исторический, из документа**: реквизит строки `ТЧТовары.ВидЦены` (касса записывает в него вид цены
  склада на момент продажи, `VentesEnDetail` `Module.bsl:1853-1863`; форма реализации — вид цены строки), пустой —
  реквизит шапки `ВидЦен`. Текущий вид склада не используется. Строки без вида цены не сравниваются: в отчёте —
  отдельной группой «Вид цены не задан» (без колонки отклонения), чтобы пропуск был виден.
- **Цена прайса = цена, которую взяла бы касса на момент продажи** — одно правило с кассой, прайс-чекером и
  сетками подбора (`Справочники.МестаХранения.ЦеныПродажиСклада`, `ManagerModule.bsl:213-227`): цена вида строки по
  номенклатуре и характеристике; нет её — цена «Розничной», если «Розничная» подходит складу (как у кассы); срез не
  уникален по измерению `ТоварнаяГруппа` — последний период пары, при нескольких записях периода — **максимум цены**;
  цена записи **как есть** (коэффициент упаковки в конфигурации сейчас 1 — `РассчитатьКоэффициентЕдиницы`; отдельной
  нормализации упаковок отчёт не вводит, чтобы цены отчёта и кассы не расходились; полноценные коэффициенты — во все
  пути сразу, отдельной задачей). **Переход к цене без характеристики** — как у строки кассы
  (`VentesEnDetail` `ЦенаПродажиСклада`, `Module.bsl:1619-1628`): `ЦеныПродажиСклада` даёт по паре (номенклатура,
  характеристика) цену вида, нет её — допустимую «Розничную»; затем поиск — точная характеристика, нет строки —
  пустая характеристика. Итоговый порядок: вид строки для характеристики или «Розничная» для характеристики (как
  объединяет `ЦеныПродажиСклада`) → вид строки или «Розничная» без характеристики. Правило (оба шага) оформляется
  одной серверной функцией цен на моменты строк, пары загружаются пакетно на тот же момент продажи; касса
  (`ЦенаПродажиСклада` формы и форма избранного) переводится на неё — её частный случай с одной датой, поведение не
  меняется; её же вызывают отчёт и прайс-чекер.
- Признак «Несколько цен в периоде» — справочная колонка, если у пары на последнем периоде записи разных товарных
  групп с разными ценами (сравнение точное, без округления): касса в этом случае тоже берёт максимум, строка
  сравнивается с ним. Записать в TECHDEBT неоднозначность прайса по товарной группе.
- **Режим НДС цены прайса — эффективный, как у кассы**: для кассовой реализации (заполнена `КассоваяСмена`) цена
  вида — цена с НДС независимо от признака `ЦенаВключаетНДС` вида (правило кассы,
  `МестаХранения.ВидЦеныДопустимДляСклада`); для прочих реализаций — по признаку вида, при отличии от режима строки —
  пересчёт по ставке НДС строки. Валюта — **эффективная валюта выбранной цены** (после выбора источника, включая
  откат на «Розничную»): пустая валюта вида = основная (так её допускает касса, `ВидЦеныДопустимДляСклада`);
  отличается от валюты документа — строка в группе «Не сравнивается: валюта».
- **Свойства вида цены (валюта, «цена включает НДС») — текущие** из справочника `ВидыЦен`: регистр цен их снимка не
  хранит, касса работает так же. Осознанное ограничение: смена свойств вида цены после продажи меняет сравнение
  прошлых продаж — в описании отчёта и в TECHDEBT. Сравнивается цена строки до скидки (`Цена`), скидка — отдельной
  колонкой. Строка отчёта = строка реализации (`КодСтроки` сохраняется), не размножается.
- **Пакетный расчёт** без запроса на строку: временная таблица строк (момент реализации, вид цены, номенклатура,
  характеристика, ключ строки); максимальный период активных записей ≤ секунде реализации по паре; цена — максимум по
  записям этого периода. Точное разрешение порядка внутри секунды (периодичность «по позиции регистратора»):
  (а) **период пары строго раньше секунды продажи и на нём записи нескольких регистраторов** — разрешается **один раз
  на период** (`СрезПоследних(Граница(период, Включая))` по набору пар этого периода), результат — всем строкам с этим
  периодом; (б) **период пары совпадает с секундой продажи** — строка в группе «Переоценка в секунду продажи» (не
  сравнивается, видна): касса брала цену на текущее время сеанса, а порядок документов внутри секунды определяется
  ссылками, а не фактическим порядком записи, — восстановить применённую кассой цену нельзя (ревью плана, круг 13).
  К результату (а) применяется то же правило «последний период пары, максимум цены». Число запросов: 1 + различные
  конфликтные периоды; не зависит от числа последующих продаж.
- Колонки: реализация, склад, номенклатура, количество, цена продажи, цена прайса на момент, отклонение (сумма и %),
  скидка строки, себестоимость единицы. **Себестоимость — действующим механизмом**
  `РегистрыНакопления.СебестоимостьПродаж.ТекстПродажССебестоимостью` (ресурс `Продажи.Себестоимость` для новых
  продаж не пишется): себестоимость и дополнительные расходы по реализации, номенклатуре и характеристике ÷
  количество — средняя единицы по документу (несколько строк одного товара получают одну среднюю; сказано в описании
  колонки); на ордерном складе — по тем же правилам. Себестоимость — только пользователю с правом видеть
  себестоимость по тем же правилам, что действующие отчёты продаж (поле не выводится, если права нет; образец —
  выписать при реализации). Актуальность — `РаботаСДокументами.ВывестиОтчетСАктуальностьюСебестоимости` из
  `ПриКомпоновкеРезультата`, как `ВедомостьПоПродажам`.
- Подсистема «Продажи → Отчёты»; роли: МенеджерПоПродажам, Руководитель, Администратор.

### 4. Прайс-чекер (`Обработка.ПроверкаЦен`, uuid `72c8792b-5553-4979-a17e-a44ab934d8c5`)

- Форма на весь экран: поле штрихкода (ввод вручную) и сканер (подключение оборудования как в формах документов,
  событие `ScanData`); поиск — новая серверная функция со статусом `НайденныйТоварПоШтрихкоду(Штрихкод)` →
  Структура (Статус: «Найден» / «НеНайден» / «Неоднозначен», Номенклатура, Характеристика, Серия, Упаковка): считает
  различные сочетания номенклатуры, характеристики, серии и **упаковки** среди совпадений штрихкодов и IMEI (IMEI — по правам на серии, как в
  2.0.17.11); больше одного — «Неоднозначен». `ПолучитьНоменклатуруПоШтрихкоду` и её вызывающие не меняются
  (новая функция — рядом, общая часть поиска выносится, поведение прежней сохраняется).
  Показывает наименование, характеристику (если есть), упаковку найденного штрихкода и цену — **той же функцией цен,
  что касса** (п. 3; цена записи как есть), по складу пользователя: вид цены склада пользователя
  (`СкладПользователя` → `ВидЦеныПродажи`), пустой склад или вид — вид цены по умолчанию. Не найдено — крупное
  сообщение «Товар не найден», неоднозначность — «Обратитесь к продавцу». Остаток не показывается.
- Подсистема «Продажи → Розничные продажи»; роли: PDV, МенеджерПоПродажам, Руководитель, Администратор (право
  «Использование» обработки; данные читаются серверными функциями с проверкой прав — новых прав на данные нет).

### 5. «Товары в наличии» — только свой склад

- Новый вид настройки пользователя `ТолькоСвойСклад` (Булево, группа «Склады» плана видов
  `ВидыНастроекПользователей`), функция `НастройкиПользователей.ТолькоСвойСклад()`. По умолчанию выключена —
  поведение прежнее.
- Включена — `Отчет.ТоварыВНаличии` в `ПриКомпоновкеРезультата` ставит **фиксированный** отбор
  `МестоХранения = СкладПользователя()` (в фиксированных настройках компоновщика — пользователь его не снимает);
  склад пользователя не задан — отбор по пустому складу (отчёт пуст) и сообщение «Не задан склад пользователя».
  Это отбор отчёта, а не ограничение доступа к данным: другие отчёты и формы остатков настройка не меняет (записать
  в описании настройки).
- Перенос с клиента (волна 7): настройка включается пользователям с ролью кассира клиента — пункт в плане волны 7.

### Тесты 5.1 (`ТестыДокументов`)

- `ПоказателиОприходованияИПеремещения`: оприходование и двухэтапное перемещение — показатели `Оприходовано`,
  `ПеремещениеСписание`/`ПеремещениеОприходование` в отчёте `ДвиженияТовара` (программной компоновкой); точные
  количество, вес и сумма по каждому складу (отправитель, «в пути», получатель) и обоим этапам; общие итоги по
  складу и товару равны итогам до изменения.
- `АнализИнвентаризации`: остаток, продажа, оприходование и перемещение между двумя пересчётами склада, списание
  по второму — начало, обороты по показателям, учёт, факт, расхождение; первая инвентаризация — с начала учёта;
  поздний черновик списания и распроведённое оприходование границы не меняют; пересечение — предупреждение;
  продажа между пересчётом и его списанием — учёт и расхождение на момент пересчёта, продажа — в «После пересчёта»;
  чередование групп A, B, A — граница третьего пересчёта — первый (группа A), а не второй; продажа задним числом
  после оформления корректировок — расхождение по сохранённому количеству не меняется, «Изменение истории» = −1 и
  предупреждение; перенос товара в другую товарную группу после пересчёта группы — строка, расхождение и нулевое
  «Изменение истории» сохраняются.
- `ОтгрузкиСИзмененнымиЦенами`: цена прайса до и после переоценки, две продажи (по старой и по новой цене) — в отчёт
  попадает только продажа с отклонением от цены на её момент; смена вида цены склада после продажи не меняет
  результат (вид из строки); вид строки без цены товара — сравнение с «Розничной», как у кассы; две характеристики;
  «Розничная» со снятым признаком НДС, ставка 20 %, продажа кассой без правки цены — строки нет в отклонениях;
  строка без вида цены — в группе «Вид цены не задан»; две установки в одну секунду и продажа между ними и после них
  — разрешение один раз на период; продажа в ту же секунду, что переоценка (в том числе при обратном порядке ссылок
  документов) — группа «Переоценка в секунду продажи»; вид цены с пустой валютой — строка сравнивается (основная
  валюта), отклонение видно;
  две товарные группы с ценами 6,00 и 6,01 на одном периоде — сравнение с 6,01 и признак «Несколько цен в периоде»;
  одна конфликтная пара установок и 30 последующих продаж — число запросов не растёт с числом продаж; цена отчёта =
  цене функции кассы для той же строки; нет цены характеристики — цена без характеристики; «Розничная» для точной
  характеристики против цены вида склада без характеристики — побеждает «Розничная» точной характеристики (порядок
  кассы); результат сверяется с функцией строки кассы на тех же данных; себестоимость новой продажи не нулевая (обычный и ордерный склад).
- `ПрайсЧекерЦена`: серверная функция обработки — цена по виду склада пользователя и по умолчанию, не найдено;
  неоднозначность: один штрихкод у двух товаров и штрихкод одного товара, равный IMEI другого — статус
  «Неоднозначен»; штрихкод коробки — название упаковки и цена, равная цене кассы для этого товара; один код у двух
  упаковок одного товара — «Неоднозначен»; цена прайс-чекера = цене строки кассы (та же функция) для склада
  пользователя; прежняя `ПолучитьНоменклатуруПоШтрихкоду` на тех же данных возвращает прежний
  результат.
- `ТоварыВНаличииСвойСклад`: настройка включена — в отчёте только склад пользователя, выключена — все склады;
  включена без склада — пусто.

## Фаза 5.2 — сборка 2.0.17.14

### 6. Перемещение товаров: заполнение остатками и себестоимость

- Команда «Заполнить остатками» на форме (закрывает TECHDEBT «`ПеремещениеТоваров.ФормаДокумента.ЗаполнитьНаСервере`
  мёртвый»): **только для операции `ПеремещениеСписание`** (первый этап — списание со склада-отправителя). Второй этап
  (`ПеремещениеОприходование`, форма создаёт его по первому, списание — со склада «в пути» `StockEnCoursDeRoute`,
  `ТоварыВНаличии/ManagerModule.bsl:65-67`) заполняется по основанию, как сейчас; команда в нём недоступна. Строки —
  положительные остатки `ТоварыВНаличии` склада-отправителя на дату документа (новый — на текущую) по номенклатуре,
  характеристике и серии, без партий; непустая таблица — вопрос «Заменить строки?».
  Серийный товар — строкой на серию с количеством остатка (серии — в `ТЧСерии` по правилам 2.0.17.10). Мёртвый
  `ЗаполнитьНаСервере` заменяется рабочим.
- Себестоимость в форме: колонки «Себестоимость» и «Сумма себестоимости» (единица и сумма по партиям **фактического
  склада списания операции** — отправителя для первого этапа, «в пути» для второго: для проведённого — по движениям
  документа, для непроведённого — оценка по остаткам склада списания),
  только просмотр; видны пользователю с правом видеть себестоимость (те же правила, что `СписаниеТоваров`,
  `Module.bsl:131-141` — образец), итог в подвале. Себестоимость неактуальна (`РаботаСДокументами.АктуальностьСебестоимости`
  раньше даты документа) — надпись над колонками «Себестоимость пересчитана по …» в форме и такая же строка в печати.
- Печать «Накладная на перемещение»: колонки цены и суммы по себестоимости и итог — при том же праве; без права —
  прежний макет без сумм. Правила фирменной печати (`ФирменнаяПечать.ЦеныСкрыты`) учитываются.

### 7. Макеты этикеток

- `Обработка.ПечатьЭтикеток`: макеты «60×40 с QR» (QR-код, артикул, наименование; цена — по константе
  `ПечататьЦенуНаЭтикетке`, как у действующего) и «Только наименование» (наименование крупно, без кода и цены);
  тексты макетов на четырёх языках. Содержимое QR — тот же штрихкод номенклатуры, что у действующей этикетки (без
  штрихкода — артикул). Поле «Тип этикетки» в форме (список: действующая, «60×40 с QR», «Только наименование»),
  запоминается в настройках формы; пустое — действующая.
- QR рисуется внешней компонентой `КомпонентаПечатиШтрихкодов`: при недоступности — этикетка без QR и сообщение
  (как сейчас у действующего макета).

### Тесты 5.2

- `ПеремещениеЗаполнитьОстатками`: две позиции и серийный товар на складе — строки и серии по остаткам, нулевой
  остаток не попадает; повтор с заменой; полное двухэтапное перемещение — второй этап по основанию при нулевом
  остатке отправителя, себестоимость второго этапа = себестоимости первого (склад «в пути»).
- `ПеремещениеСебестоимость`: себестоимость строк проведённого перемещения = себестоимости партий отправителя;
  печать с правом — колонки сумм, без права — нет; себестоимость неактуальна (граница пересчёта раньше документа)
  — надпись «пересчитана по» в данных формы и строке печати, после пересчёта — нет.
- `ЭтикеткиМакеты`: печать трёх типов на две позиции — табличные документы не пустые, у «Только наименование» нет
  области кода.

## Порядок и проверки

Каждая фаза: tiny1C `checklist` по `.mdo`/`Form.form`/запросам/макетам → реализация → `lint` (ноль новых),
`refcheck`, `listcheck`, `colfont`, `menucheck` → `ib-sync` → смок → `ТестыДокументов` → «Что нового» на четырёх
языках → `ai-review` → `ai-database` (5.1 — запросы отчётов; 5.2 — заполнение и себестоимость) / `ai-security`
(5.1 — себестоимость в отчёте и прайс-чекер; 5.3 — роли) → `ai-final-check --db` → отчёт
`.ai/reports/retail-tools-<фаза>.md` → коммит, push.

- Ветки `ВЫБОР` меняют разбивку «Прочее» в `ДвиженияТовара` у всех пользователей — отмечено в «Что нового».
