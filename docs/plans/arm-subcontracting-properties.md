# АРМ производства: «Передача в переработку», ПФ/ГП строки, свойства изделия, отрасль «Ткани»

Сборка 2.0.16.16. Семь замечаний владельца 2026-10-05 по скриншоту закладки «Переработка». Решения владельца в
тот же день: значения свойств хранятся **в карточке ПФ/ГП** (дополнительные реквизиты номенклатуры); количество
ПФ/ГП в поступлении из переработки — **по заказу** (текущее правило ожидаемой продукции).

## 3. Колонка ПФ/ГП в передаче в переработку

Решение владельца (повторный разбор после гейта): ПФ/ГП выбирается **только из заказа**.

- **Метаданные:** реквизит `Продукция` (`CatalogRef.Номенклатура`, необязательный, новый uuid) в
  `Документ.ПередачаВПереработку.ТЧТовары` — для какого ПФ/ГП передаётся материал. Реструктуризация — новая колонка
  табличной части, у старых строк пусто (= прежнее поведение); у drissotex документа нет.
- **Допустимые ПФ/ГП материала** — функция менеджера передачи `ДопустимаяПродукцияМатериала(Заказ, Материал)`:
  прямые родители материала в дереве материалов заказа (строки товаров или узлы `ТЧМатериалы`, чьим ребёнком материал
  стоит) — только у них материал входит в карту, и поступление спишет сырьё (гейт P1-3). Материала в дереве нет или
  дерева нет (плоский заказ) — номенклатура строк товаров заказа. Проверяется на сервере: запрет записи строки АРМ
  (`ТекстЗапретаЗначенийСтрокиПередачи`) и проверка заполнения передачи (`ОбработкаПроверкиЗаполнения`, ошибка у
  строки). Тот же список — выбор в колонке АРМ и в форме документа. **Без автоподстановки** (гейт P2-4).
- Колонка в форме документа передачи и в таблице `Переработки` АРМ после «Материала». Запись строки АРМ
  (`ПрименитьДанныеСтрокиПередачи`) пишет `Продукция`, чтение строк (`ТекстЗапросаСтрокПередач`) её отдаёт.
- **Ожидаемая продукция передачи** (`ОжидаемаяПродукцияПередачи`; зовут заполнение, форма и АРМ — проведение её не
  пересчитывает):
  - ни у одной строки ПФ/ГП нет — правило без изменений;
  - иначе для каждого указанного P: строки P из `ПродукцияПоДеревуЗаказа(Заказ, строки с Продукция = P)` — доля
    считается только по материалам, переданным под P, общий материал двух ПФ/ГП не засчитывается обоим (гейт P2-2);
    у плоского заказа — строки товаров заказа с номенклатурой P; все характеристики P (гейт P2-3);
  - строки без ПФ/ГП: если их нет — ничего; иначе прежнее правило по ним, минус номенклатура, уже указанная явно
    (слияние по ключу, без суммы; запасной путь «все товары заказа» явные ПФ/ГП не подменяет — гейт P2-1);
  - нулевых строк не бывает: ПФ/ГП только из заказа, количество есть всегда (гейт P1-1).
  - Инвариант с тестом: указан ровно тот прямой родитель, которого дало бы прежнее правило, — результат совпадает с
    прежним.

## 4–6. Свойства ПФ/ГП справа от таблицы передач

- Справа от таблицы `Переработки` — таблица `СвойстваПродукции` (Свойство, Заголовок, Значение составного типа ПВХ
  `ДополнительныеРеквизиты`, ТипЗначения): дополнительные реквизиты номенклатуры из колонки ПФ/ГП текущей строки.
  Пустая ПФ/ГП — пусто; у номенклатуры нет ни одного доп. реквизита в базе — панель скрыта.
- Поле значения: при начале редактирования строки — `ОграничениеТипа` по типу свойства и `ПараметрыВыбора`
  `Отбор.Владелец` = свойство для значений доп. справочника. Обработчики объявлены в `<handlers>` (forms-004).
- **Право — только свойства и только из АРМ** (решение владельца): функция менеджера АРМ
  `ЗаписатьСвойствоПродукции(Заказ, Продукция, Свойство, Значение)` проверяет: у пользователя право ввода передач
  (`МожноВводитьПереработку`), заказ — на производство, `Продукция` входит в ПФ/ГП заказа (товары + узлы дерева),
  свойство — дополнительный реквизит набора номенклатуры, значение подходит по типу (для значений доп. справочника —
  владелец = свойство). Затем запись в привилегированном режиме под блокировкой объекта номенклатуры: реквизит — ТЧ
  `ДополнительныеРеквизиты` карточки (`ОбменДанными.Загрузка` не ставится — проверки карточки работают), сведение —
  регистр `ДополнительныеСведения`. Обязательное свойство пустым значением не записывается. Остальная карточка
  оператору по-прежнему недоступна. Значения доп. справочников (цвета, материалы) оператор выбирает из готового списка;
  пополняет список администратор.
- Обновление таблицы — при активизации строки передачи и смене её ПФ/ГП, серверным вызовом без контекста.

## 5. Отрасль «Ткани» и её свойства

- Значение `Ткани` перечисления `Отрасли` (Tissus / Textiles / Textiles). Поле «Отрасль» в визарде и в «Настройках
  программы → Компания и учёт» — поле перечисления; подсказки с перечнем отраслей дополняются
  (`ФормаПервогоЗапуска/Module.bsl:19` и Form.form настроек). Код хаба `textile`/`ткани` в `ОтрасльПоКоду`; `docs/DEPLOY.md`
  — поле `industry` и итог `industry_attributes_created` (исправить расхождение с кодом).
- `ПрименитьОтрасль(Ткани)` при `ИспользоватьПроизводство` заводит дополнительные реквизиты номенклатуры:
  `Материал`, `Цвет`, `ТипОбработки` — `СправочникСсылка.ЗначенияДополнительныхРеквизитов`, `Ширина` — число 15,3.
  Без производства — ничего не создаёт и возвращает предупреждение (в `Результат.Предупреждения` заполнения базы и
  сообщением в настройках).
- **Порядок при заполнении базы:** `ПрименитьФункциональныеОпции` до `ПрименитьОтрасль`
  (`НачальноеЗаполнениеВызовСервера/Module.bsl:260`), иначе визард и хаб с «Ткани + производство» ничего не создадут
  (гейт P1-4). Тест на путь заполнения базы.
- В «Настройках программы → Компания и учёт» — кнопка «Создать свойства номенклатуры» (видна при отрасли «Ткани»):
  применяет отрасль повторно (идемпотентно).

## 7. Поступление из переработки по ПФ/ГП передачи

Заполнение поступления по передаче и выбор продукции в АРМ уже берут ожидаемую продукцию передачи
(`ОжидаемаяПродукция`), а она после п. 3 состоит из указанных ПФ/ГП с количеством по заказу. Нового кода в поступлении
не нужно — нужны тесты: передача с ПФ/ГП → заполненное поступление содержит ровно их; ПФ/ГП не указан — состав как
раньше и определяется в поступлении.

## Чего не делаю

- Свойства в строке документа (вариант изделия на передачу) — отклонено владельцем.
- ПФ/ГП вне заказа — отклонено владельцем.
- Списание сырья в поступлении не меняется — сырьё по техкартам, как сейчас.

## Риски

- Реструктуризация `ПередачаВПереработку.ТЧТовары` — добавление необязательной колонки.
- Привилегированная запись карточки номенклатуры из АРМ — узкая функция с проверками, `ai-security` обязателен.
- Ожидаемая продукция передачи влияет на заполнение поступления и запреты АРМ (`ТекстЗапретаКоличества…`,
  `ПередачиЗаказаДляВыбора`); при пустых ПФ/ГП — без изменений (тесты `АРМПереработка`, `АвтовыпускПриПередаче`).
- Форма АРМ — через генератор (`gen10.py` поверх `gen9.py`).

## Проверка

lint, refcheck, listcheck, menucheck, titlecheck; `ТестыДокументов`: ожидаемая продукция с ПФ/ГП (прямой родитель = прежнее
правило, общий материал двух ПФ/ГП, смешанные строки, плоский заказ), запрет ПФ/ГП не из заказа, запись ПФ/ГП строкой АРМ, заполнение поступления, `ЗаписатьСвойствоПродукции` (разрешено/запрещено),
`ПрименитьОтрасль(Ткани)` с производством и без, путь заполнения базы с «Ткани»; смок и тесты на копии базы; ai-review, ai-database (реструктуризация,
проведение), ai-security (запись справочника из АРМ, права); версия и «Что нового» на 4 языках.

## Гейт плана, редакция 1

`architecture-critic` (Codex в лимите): reject — P1: нули в ожидаемой продукции ломают проведение и поступление,
ПФ/ГП не прямой родитель не списывает сырьё, «Ткани» при заполнении базы применяется до опций, у оператора нет прав
на номенклатуру. Владелец 2026-10-05: ПФ/ГП только из заказа, оператор меняет только свойства из АРМ. Редакция 2
выше учитывает P1 и P2 полностью.

## Гейт плана, редакция 2 — правки, принятые без нового круга

approve_with_changes. Принято:
- **N1.** Ветка ожидаемой продукции для P выбирается по источнику допустимости: P — прямой родитель материала в
  дереве → по дереву (строки с Продукция = P); P из строк товаров заказа (дерева нет или материал вне дерева) → строки
  товаров заказа с номенклатурой P. Тест «дерево есть, материал вне дерева».
- **N2.** Формулировка сужена: общий материал двух **разных** ПФ/ГП не засчитывается обоим; одна номенклатура P
  несколькими узлами дерева (крой под A и под B) считается, как и раньше, по каждому узлу — в `TECHDEBT.md`.
- **N3.** Проверка `Продукция` при записи передачи — только у новых строк и строк, где `Продукция` изменилась
  относительно базы; старым строкам перепроведение не мешает. Основание не заказ — `Продукция` должна быть пустой.
- **N4.** `ЗаписатьСвойствоПродукции`: тип — `ТипЗначения.СодержитТип`, свойство без пометки и из набора номенклатуры,
  `ЗаблокироватьДанныеДляРедактирования` до чтения с понятным сообщением, сведения — под управляемой блокировкой,
  ПФ/ГП проверяется по заказу строки передачи.
- **N5.** Владельцу: свойство меняется в карточке глобально — видно во всех заказах и продажах этой номенклатуры.
