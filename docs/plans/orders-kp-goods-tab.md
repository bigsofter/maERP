# Закладка «Товары» в списках заказов клиента и КП (тикет 2605528, сборки 2.0.17.40–41)

## Задача

Проверяющий клиента 18.11 к закладке «Товары» списка реализаций (2.0.17.35, `docs/plans/sales-goods-tab.md`): «такая
же форма нужна для заказов клиента и КП». Решения владельца 19.11:

- колонки закладки — как у реализаций после 2.0.17.39: первой «Документ» со значком состояния строки, затем
  номенклатура, количество, сумма, клиент; остальные — после, поджатые; колонок «Дата» и «Статус» нет;
- **заказ клиента** — только заказ на куплю-продажу. Заказы на производство ведутся отдельным списком (общая команда
  «Заказы клиентов на производство») и в рабочих местах производства. Пункт меню «Заказы клиентов» открывает
  **отдельный список заказов-продаж**, в нём и закладка «Товары»;
- **КП** по умолчанию вводятся отдельно (настройка «Коммерческие предложения» включена), реализации делаются на их
  основании; режим «КП автоматически из реализации» (настройка выключена) — для простоты интерфейса и обратной
  совместимости. Закладка в списке КП нужна;
- номер документа и построчный ввод не меняются (как в реализациях).

Уровень — **существенный**: запись документов из формы списка, новый общий модуль. План → `ai-review-plan` → код →
`ai-test` → `ai-review` → `ai-security` → `ai-final-check`.

Редакция 2 — по кругу 1 `ai-review-plan` (reject: P0, P1, P2): внешние роли закладку не получают и сервер им
отказывает; отбор «только продажи» ставится явно и недоступен пользователю; перечень отборов закладки КП — явный.

Редакция 3 — по кругу 2 (reject: P1, P2): контракт общего модуля расширен строковой спецификой — вид цен новой
строки, запрет правки строки, дополнение новой строки; общий модуль не читает реквизитов, которых нет у заказа и КП
(`ВидЦен`, `МестоХранения` шапки, `Серия` строки); новая строка КП получает описание по умолчанию.

Редакция 4 — по кругу 3 (reject: P0, P1): защита цен КП без заверения (`ПересчитатьСуммыБезЗаверения`,
`ДобавитьОшибкиШапкиЦен`) — главная: историческая строка КП с нулевой `ЦенаSKU` закладкой не правится; новое КП без
права заверения — в основной валюте.

Редакция 5 — по кругу 4 (reject: P0): защита цен КП восстанавливает цены **всех** строк при записи — запрет
исторических строк и неоднозначных ключей переносится с уровня строки на уровень документа.

Редакция 6 — по кругу 5 (reject: P0, P1): КП с основанием на закладке не правится (цены восстанавливаются и из
основания); ключ сопоставления строк КП держится уникальным `КодСтроки`, а у записанной строки КП закладка меняет
только количество.

Редакция 7 — по кругу 6 (reject: P1): кнопки «Создать заказ» внутри таблицы списка КП переносятся в командную
панель формы до оборачивания списка в страницы (tiny1C forms-009, forms-008).

Редакция 8 — по кругу 7 (reject: P1): кнопки создания заказа в панели формы видны только на странице «Предложения».

Редакция 9 — по кругу 8 (`approve_with_changes`, P2): заказ в сохранённом статусе сборки/отгрузки/доставки/выполнения
на закладке только для просмотра — статус при правке строк не пересчитывается.

## Поиск готового

- Образец целиком — закладка «Товары» реализаций (2.0.17.35/39): `Документы.РеализацияТоваровУслуг` —
  `СтрокиТоваровСписка`, `ЗаписатьСтрокиТоваров`, `УдалитьСтрокиТоваров`, `ДокументыДляСтрокиТоваров`,
  `ШапкаДокументаСтрокиТоваров`, `ЗначенияНовойСтрокиТоваров`, механика пакета (`ЗаблокированныйДокумент`,
  `ПрименитьСтроку`, `ЗаполнитьЦенуСтроки`, `ПрименитьРучнуюЦену`, `ЗаписатьДокумент`, `УдалитьСтрокиДокумента`,
  `ПометитьДокумент`, тексты); клиентская часть формы списка (очередь записи, незаписанные правки, курсор,
  сортировка, печать, закрытие). Все P0–P2 десяти кругов ревью того плана — в силе и здесь.
- Хелперы строки уже работают у форм заказа и КП: `РаботаСДокументамиКлиентСервер.УстановитьПараметрыНоменклатуры`,
  `УстановитьЦенуНоменклатуры`, `РассчитатьСтроку` (ЗП ФормаДокумента :325/:359/:370, КП :185/:207/:217).
- Вид цен нового документа — как форма документа `УстановитьВидЦеныПоДоговору` (ЗП :450, КП :305): тип цены
  контрагента, иначе розничная; `ЦенаВключаетНДС` — по виду цен.
- Значок состояния — общая картинка `СостоянияОбъекта` (как 2.0.17.39).

## Общий серверный модуль — `СтрокиТоваровСписков`

Механика пакета у реализации, заказа и КП одна; разница — шапка нового документа, правила правки и режим записи.
Третья копия ~700 строк (реализация, рабочее место производства уже держат свои) — повод вынести общее.

Новый общий модуль `СтрокиТоваровСписков` (Сервер, не глобальный, без вызова сервера, не привилегированный):
результат пакета и тексты (`НовыйРезультат`, `ТекстСообщений`, `ТекстНеЗаписано`, `ТекстДокументИзменен`,
`ТекстНеверныеДанные`), проверки типов и данных строки, `ВерсияПакета`, `ЗаблокированныйДокумент`, `ПрименитьСтроку`
с ценой, скидкой и ручной ценой, `ЗаписатьСтроки` (пакет одного документа), `УдалитьСтроки` с пометкой последнего,
`СтрокаБезИзменений`. Документная часть передаётся **именем документа**: модуль вызывает экспортные функции менеджера
`Документы[Имя]` с фиксированными именами:

| Функция менеджера | Назначение |
|---|---|
| `ТекстЗапретаПравкиСтрокТоваров(ДокОбъект)` | правила правки по объекту под блокировкой; пусто — можно |
| `ЗаполнитьНовыйДокументСтрокТоваров(ДокОбъект, Строка)` | шапка нового документа; отказ — текст |
| `РежимЗаписиСтрокТоваров(ДокОбъект, НовыйДокумент)` | `Запись` / `Проведение` |
| `МожноВводитьСтрокиТоваров()` | права на ввод |
| `ВидЦеныНовойСтрокиТоваров(ДокОбъект)` | вид цен новой строки в существующем и новом документе |
| `ТекстЗапретаСтрокиТоваров(СтрокаТоваров)` | запрет правки и удаления конкретной строки; пусто — можно |
| `ДополнитьНовуюСтрокуТоваров(ДокОбъект, СтрокаТоваров)` | документные поля новой строки после данных номенклатуры |

**Общий модуль читает только общие реквизиты** (P1 круга 2): шапка — `ЦенаВключаетНДС`, валюта через
`РаботаСВалютами.ВалютаИКурсДокумента`, `ТЧТовары`, `ВерсияДанных`, `ПометкаУдаления`; строка — `КодСтроки`,
`Номенклатура`, `Характеристика`, `Упаковка`, `КоличествоУпаковок`, `Количество`, `ВидЦены`, `ЦенаSKU`, `Цена`,
`ПроцентСкидки`, `СкидкаНаЦену` и расчётные поля `РассчитатьСтроку`. Всё, что у реализации было в
`ПрименитьСтроку`/`ЗаписаннаяСтрокаТоваров`/`НомераУдаляемыхСтрок` про шапку (`ВидЦен`, `МестоХранения`) и серии, —
уходит в функции менеджера:
- `ВидЦеныНовойСтрокиТоваров` у ЗП и КП — как `УстановитьВидЦеныПоДоговору` форм (ЗП :450, КП :305): тип цены
  контрагента документа, иначе розничная. **Режим НДС существующего документа не меняется** (форма при открытии
  переставляет `ЦенаВключаетНДС` по виду цен — закладка этого не делает, прежние строки не переоцениваются; как у
  реализаций, P1 круга 3 того плана). У нового документа `ЦенаВключаетНДС` — по этому виду цен (в шапке).
- `ТекстЗапретаСтрокиТоваров`: ЗП — у строки заполнена `Техкарта` (производство); КП — пусто: запрет КП —
  документный (правило 5 «Правил правки КП»), потому что `ПередЗаписью` восстанавливает цены всех строк сразу.
- Исторические строки КП (P0 круга 3 — `ПередЗаписью` КП без права заверения восстанавливает цены из версии в базе и
  при другом количестве считает `РассчитатьСтроку` от нулевой `ЦенаSKU`, `ВосстановитьЦеныСтроки` :704, — расчёт от
  цены с сохранением скидки закладки был бы отменён) — см. правило 5. Тот же пересчёт у формы документа КП — запись в TECHDEBT («КП без заверения цен: строка без цены
  базовой единицы при смене количества получает цену из нулевой ЦенаSKU»), не правится в этой волне.
- `ДополнитьНовуюСтрокуТоваров`: КП — `Описание = Документы.КоммерческоеПредложение.ОписаниеСтрокиПоУмолчанию(Номенклатура)`
  (P2 круга 2: форма документа делает это после `УстановитьПараметрыНоменклатуры`, печать КП берёт сохранённое
  описание); ЗП — ничего. Правка записанной строки описание не трогает (как подбор в форме).
Тесты: новая строка КП — описание по умолчанию из карточки; новая строка в существующий заказ с
`ЦенаВключаетНДС`, отличным от вида цен клиента, — режим документа прежний, цена прайса пересчитана по режиму документа.

Модуль проверяет имя по белому списку (`ЗаказПокупателя`, `КоммерческоеПредложение`) — имя приходит из формы.
**Реализация в этой волне не переводится** на общий модуль: её код прошёл десять кругов ревью и тест сценария;
перевод — отдельной сборкой (TECHDEBT «Закладка «Товары» реализаций на общем модуле»), чтобы не смешивать с новым.

Клиентская часть (очередь записи, незаписанные правки, курсор, сортировка, вопросы при закрытии и «Обновить»)
привязана к элементам формы — **копируется** в формы списков ЗП и КП с заменой специфики (нет склада, своё
представление нового документа «Новый заказ» / «Новое предложение»).

## 1. Заказы клиента (2.0.17.40)

### Список заказов-продаж

`Документ.ЗаказПокупателя.ФормаСписка` сейчас — все заказы с тумблером вида операции «Все / Продажа / Производство»
(тумблер виден при учёте производства); общая команда «Заказы клиентов на производство» открывает её с фиксированным
отбором `ВидОперации = Производство` и скрытым тумблером.

Изменение `НастроитьВидОперации`: открытие **без** отбора вида операции (пункт меню «Заказы клиентов», переходы из
карточек и отчётов) — тумблер ставится на «Продажа» и скрывается; заголовок «Заказы клиентов». Присваивание позиции
тумблера отбор не ставит (P1 круга 1: `УстановитьОтборВидаОперации` зовётся только из `ПрименитьОтборы` при изменении
поля панели) — поэтому `ПриСозданииНаСервере` после `НастроитьВидОперации` **явно** вызывает
`УстановитьОтборВидаОперации()`: элемент отбора `ВидОперации НеРавно Производство` (заказ с пустым видом — продажа, как
сейчас) с `РежимОтображения = Недоступный` — пользователь не снимает его настройками списка. Тест: форма, созданная
без параметров (`ПолучитьФорму`), — в отборе списка есть этот элемент, тумблер скрыт. Открытие с отбором «Производство» — как сейчас. Команды
проведения — по тому же правилу, что сейчас (`НастроитьКомандыПроведения`): в списке продаж скрыты.

Риск: переход «Заказы» из карточки контрагента и подобные открывают тот же список — производственные заказы клиента в
нём больше не видны. По решению владельца они ведутся в своём списке; проверить перечень мест открытия (`grep` по
`ЗаказПокупателя.ФормаСписка` и `OpenList`) и описать в «Что нового».

### Закладка

Список заказов уже лежит в группе страниц `ГруппаСтраницыДокументов` (страницы `СтраницаЗаказы`,
`СтраницаКоммерческиеПредложения`) — страница `СтраницаТовары` добавляется в неё третьей. Видна только в списке
продаж (в режиме «Производство» скрыта). Правая панель — общая. Отборы закладки (по шапке заказа в запросе строк):
клиент, организация, ответственный, сумма с условием, товар (только строки товара). **Не действуют** на закладку
вычисляемые отборы списка — оплата, отгрузка, долг: их состояние считает запрос динамического списка, дублировать его
не стоит. Если хоть один из них задан, над таблицей закладки — надпись «Отборы оплаты, отгрузки и долга на закладку
не действуют» (на 4 языках), рядом с надписью о пределе 200 документов.

Колонки: Документ (значок: 2 — записан, 1 — помечен на удаление; заказ-продажа не проводится), Номенклатура,
Количество, Сумма, Клиент, Характеристика, Упаковка, Цена, Валюта, Организация. Склада у заказа нет.

### Правила правки заказа (`ТекстЗапретаПравкиСтрокТоваров`)

Строка правится, если:
0. `ВидОперации` — продажа (пустой — продажа);
1. `ТЧМатериалы` пуст, у строк нет `Техкарта` (материалы и техкарты — заказ на производство);
2. не помечен на удаление;
3. дата не в закрытом периоде — `РаботаСДокументами.МожноРедактироватьДокумент` (запись всё равно проверит);
4. права «Добавление» и «Изменение» `ЗаказПокупателя`.

5. последний статус продажи (`ИсторияЗаказовПокупателейПоСтатусам`, срез последних без индикатора — как
   `ЗаписатьСтатусПродажи`) не из «Собран», «Отгружен», «Доставлен», «Выполнен» (P2 круга 8: эти статусы запись заказа
   сохраняет как есть, не пересчитывая по изменённому количеству; список показывает сохранённый статус). Такой заказ на
   закладке — только просмотр, «правьте заказ в форме документа». Тест — заказ со статусом «Отгружен» в истории:
   строки только просмотр, запись отказана.

### Новый заказ (`ЗаполнитьНовыйДокументСтрокТоваров`)

`СоздатьДокумент()` → `Заполнить(Неопределено)` (`ОбработкаЗаполнения`: реквизиты по умолчанию, `ЦенаВключаетНДС`,
`ДатаОтгрузки`) → `ВидОперации = Продажа`, `Организация` (строки, иначе по умолчанию), данные клиента —
`ОбщегоНазначенияВызовСервера.ПолучитьДанныеКонтрагента` (головной контрагент, договор, менеджер, как
`ЗаполнитьДанныеПоТорговойТочке`), валюта — по договору (`ТекстКурсНеЗадан` при отсутствии курса), вид цен строк и
`ЦенаВключаетНДС` — как `УстановитьВидЦеныПоДоговору` формы. Запрет отгрузок клиенту форма заказа не проверяет —
закладка тоже нет. Запись — `РежимЗаписиДокумента.Запись` (заказ-продажа не проводится).

Выбор документа новой строки — «Новый заказ» + сегодняшние заказы-продажи клиента в той же организации, проходящие
правила правки (как у реализаций).

### Печать

Подменю «Печать» по `ПечатныеФормы.ДоступныеКомандыПечатиОбъекта("Документ.ЗаказПокупателя")` — как у реализаций.

## 2. КП (2.0.17.41)

### Список

Форма списка КП без закладок: `ГруппаГлавная` → `ГруппаЛевая` со `Список` и правая панель. `ГруппаЛевая`
оборачивается в группу страниц `ГруппаЗакладкиСписков` со страницами «Предложения» (текущий список) и «Товары».
**До оборачивания** (P1 круга 6): кнопки `КнопкаСоздатьЗаказ` и `КнопкаСоздатьЗаказНаПроизводство` из командной
панели таблицы `Список` (`placementArea=UserCmds`, Form.form :666–718) переносятся в командную панель формы с теми же
командами — кнопка внутри таблицы динамического списка на закладке роняет клиент 8.5.1 (tiny1C forms-009); у
`Список` не должно остаться `userSettingsGroup` (forms-008). Проверка: в Form.form КП нет `<items xsi:type="form:Button">`
внутри `Список`, кнопки видны в панели формы и работают по текущей строке списка (команды формы с текущими данными
`Элементы.Список`). **Видимость** (P1 круга 7): кнопки создания заказа показываются только на странице
«Предложения» — обработчик смены страницы `ГруппаЗакладкиСписковПриСменеСтраницы` (в `extInfo` группы страниц,
tiny1C forms-030) переключает их `Видимость`; кроме того `СоздатьЗаказПоПредложению` первой строкой выходит, если
текущая страница — не «Предложения» (команда может прийти горячей клавишей). На странице «Товары» заказ по строке не
создаётся. Список заказов клиента — то же правило для страницы «Товары» (там список уже на странице и работает).
Ручная проверка у владельца — открытие списка КП в клиенте 8.5.1 (смок открывает форму, но краш на стороне
отрисовки — тоже ловит падением клиента). Панель — общая. Все отборы панели КП — реквизиты шапки (P2 круга 1: перечень явный) и действуют на закладку
в запросе строк: клиент (`Контрагент`), организация, ответственный, менеджер, договор, сумма с условием, дата отгрузки,
статус (та же позиция тумблера, что `ЗначениеФильтраСтатуса`), товар (только строки товара). Тест — каждый отбор
сужает строки.

Колонки: Документ (значок: записан / помечен), Номенклатура, Количество, Сумма, Клиент, Характеристика, Упаковка, Цена,
Валюта, Организация.

### Правила правки КП

0. `КПВводятсяВручную()` (настройка «Коммерческие предложения» включена) — иначе вся закладка только для просмотра;
1. не `Автосинхронизация` (авто-КП реализации);
2. не помечено на удаление;
3. закрытый период — как запись;
4. права «Добавление» и «Изменение» `КоммерческоеПредложение`;
5. **цены документа восстанавливаются однозначно** (P0 кругов 3–5). `ПередЗаписью` КП без права заверения
   (`ПересчитатьСуммыБезЗаверения` :342) восстанавливает цены **всех** строк из источника — строки той же версии в базе
   (`ПрежняяСтрокаЦен` :422, ключ `КодСтроки + Номенклатура + Характеристика + Упаковка`, первое совпадение), иначе
   строки реализации-основания (`СтрокаОснованияЦен` :597, `ИсточникЦенСтроки` :629). Чтобы правка одной строки не
   меняла цены других, документ правится на закладке только если:
   - `Основание` не заполнено (КП на основании реализации — только просмотр: цены и его новых строк сопоставляются с
     основанием по товару, P0 круга 5);
   - `КодСтроки` всех строк заполнены и **уникальны** в документе (тогда ключ версии однозначен и после правки);
   - нет строк с `ЦенаSKU = 0` и `Цена <> 0` (исторические, P0 круга 3).
   Иначе весь документ на закладке — только просмотр, «правьте КП в форме документа». Правило проверяется всегда (не
   только без заверения), при загрузке, выборе документа и под блокировкой.
6. **Записанная строка КП**: закладка меняет только количество; характеристика и упаковка у записанной строки КП —
   только просмотр (P1 круга 5: их смена сохраняла бы `КодСтроки` при другом ключе сопоставления). Другая упаковка
   или характеристика — новой строкой (новый уникальный `КодСтроки` — `ПолучитьСледующийКодСтроки`), старая
   удаляется. Сервер проверяет то же: у записанной строки КП отличие характеристики или упаковки — отказ пакета.
   Для этого в контракт — `ПоляПравкиЗаписаннойСтроки()` менеджера: РТУ/ЗП — «Характеристика, Упаковка,
   КоличествоУпаковок, Цена», КП — «КоличествоУпаковок, Цена»; форма списка КП делает колонки характеристики и
   упаковки только для просмотра у записанных строк.
   Тесты: КП с основанием, КП с дублем `КодСтроки`, КП с исторической строкой — строки только просмотр, запись и
   удаление отказаны, документ не изменён; смена упаковки записанной строки КП — отказ; правка количества
   отправленного КП — новая редакция, цены остальных строк прежние.

Статус не ограничивает: правка отправленного КП сама заводит новую редакцию (`ОпределитьРедакцию` объекта) — как при
записи из формы документа. «Выигран»/«Проигран» — по тому же правилу, что форма документа (проверить: форма их не
запирает — закладка тоже).

### Новое КП

`СоздатьДокумент()` → `Заполнить(Неопределено)` → `Статус = Черновик`, организация, данные клиента, вид цен — как у
заказа (форма КП `УстановитьВидЦеныПоДоговору` :305). **Валюта** (P1 круга 3): сервер КП без права «Заверение цен»
допускает у нового предложения без основания только основную валюту и `ЦенаВключаетНДС` из {Истина, по виду цен}
(`ДобавитьОшибкиШапкиЦен` :826). Поэтому: с правом заверения — валюта договора (как у заказа); без права — основная
валюта (`ВВалюте = Ложь`), `ЦенаВключаетНДС` — по виду цен; цена прайса пересчитывается в основную валюту. Колонка
«Валюта» новой строки показывает именно её (`ЗначенияНовойСтрокиТоваров` возвращает валюту по тому же правилу).
Серверную проверку КП не меняем. Тест: пользователь без заверения не воспроизводится автотестом под администратором —
модульно функция выбора валюты по признаку права (параметром), ручной сценарий у владельца. Запись — `Запись`
(КП не проводится).

### Печать

`ПечатныеФормы.ДоступныеКомандыПечатиОбъекта("Документ.КоммерческоеПредложение")`.

## Права

**Внешние роли** (P0 круга 1): у роли «Клиент» (и ЛичныйКабинет, ECommerce, ОбменМобильнаяДоставка, MobileClient —
`NAV_EXTERNAL_ROLES` rolecheck) есть чтение, добавление и изменение заказов **без** ограничения по контрагенту, а
форма списка заказов не ставит обязательного отбора своего клиента. Закладка этим ролям **не даётся**: страница
скрыта при создании формы, а серверные функции общего модуля и менеджеров (`СтрокиТоваровСписка`, `ЗаписатьСтроки`,
`УдалитьСтроки`, `ДокументыДляСтрокиТоваров`, `ШапкаДокументаСтрокиТоваров`) первым делом проверяют
`ЕстьВнешняяРоль()` (любая из перечисленных ролей у пользователя, `РольДоступна`) и отдают пусто/отказ. Тест —
модульно: функция проверки ролей и отказ записи при её истине (подмена через параметр нельзя — проверка под
пользователем теста-администратора даёт Ложь; ручной сценарий владельца — пользователь с ролью «Клиент»).

Внутренние роли: ввод — при праве «Добавление» и «Изменение» документа; иначе только просмотр (менеджер по продажам: чтение ЗП и КП —
ввода нет, как сейчас в формах). Цена — по «Заверению цен»; сервер КП дополнительно проверяет цены без заверения
(`ОшибкиЦенБезЗаверения`).

## Тесты

Сценарии `ЗаказыТоварамиСписка` и `КПТоварамиСписка` в `ТестыДокументов`, по образцу `РеализацииТоварамиСписка`:
новая строка → новый документ (шапка, вид цен, цена прайса, сумма; заказ — `ВидОперации = Продажа`, не проведён; КП —
черновик); вторая строка в тот же документ; правка количества (цена прежняя); конфликт версии; удаление строки и
последней строки (пометка); отборы клиента и товара; запреты: заказ на производство и заказ с материалами — только
просмотр, запись отказана; КП в режиме авто-КП и `Автосинхронизация` — отказ; отправленное КП → новая редакция после
правки строки; упаковка с коэффициентом; ручная цена в другой валюте — отказ. Список заказов без отбора — только
продажи (запрос формы с отбором тумблера). `docs/TESTING.md`, `docs/TESTS.xlsx`.
