# Режим «Товары» на «Поступлениях» рабочего места закупок: правка записанных строк, статус, порядок (2.0.16.115)

Задача владельца (клиент Drissotex), 2026-10-28:

1. «В режиме «Товары» в АРМ Закупки надо создавать новый элемент сверху и сортировать по дате и моменту времени
   создания».
2. «Надо сделать редактирование и изменение статуса с черновика на проведён по аналогии с АРМ Производство, когда
   вводим заказ товарами».

Отзыв пользователя: «после окончания редактирования строку больше нельзя отредактировать. Двойной клик открывает
форму документа, после закрытия которого переходит в самый верх списка. Только количество можно через кнопку ввести.
Если не выходить из режима редактирования, то всё вводится».

Редакция 12 — по кругу 11 (reject: P0): версии строк очереди не подменяются — вторая строка того же документа
отклоняется по версии и возвращается к базе.
Редакция 11 — по кругу 10 (reject: 2×P1): версия документа для следующей строки очереди того же документа;
обработчик ожидания не перечитывает при пустой очереди и во время ввода строки.
Редакция 10 — по кругу 9 (reject: 2×P1): назначенные записи — список в реквизите формы; удачно записанная строка
удаляется из таблицы формы сразу.
Редакция 9 — по кругу 8 (reject: P1, P2): назначенная запись — в начале верхнего загрузчика, до отбора страницы,
единственный вход загрузки; ручная проверка ввода с немедленным перечитыванием.
Редакция 8 — по кругу 7 (reject: 3×P1): идентификатор назначенной записи — реквизит формы; защита — в нижнем загрузчике
строк; удачно записанная новая строка не остаётся среди незаписанных.
Редакция 7 — по кругу 6 (reject: 1×P1): назначенная запись строки выполняется перед любым перечитыванием страницы —
на сервере, в единой точке загрузки, а не только перед статусом.
Редакция 6 — по кругу 5 (reject: P0, 2×P1 — перенос правок поверх перечитанных строк): вместо признака и переноса —
исходное правило: отказ записи записанной строки возвращает её к значениям базы.
Редакция 5 — по кругу 4 (reject: 1×P1): перечитывание после записи строки сохраняет строки с незаписанной правкой.
Редакция 4 — по кругу 3 (reject: 1×P1, 1×P2): признак незаписанной правки строки — статус не меняется, пока он есть;
копия цену не переносит.
Редакция 3 — по кругу 2 (reject: 1×P1, 2×P2): команда статуса сначала записывает ожидающую строку; копия переносит
цену с признаком «цена изменена»; курсор после формы документа — с откатом на первую строку документа.
Редакция 2 — по кругу 1 `ai-review-plan` (reject: 1×P1, 3×P2): единица нового товара при смене товара записанной
строки; версия данных при смене статуса не сверяется — сказано прямо; порядок строк — порядок документов страницы,
«момент создания» — дата документа.

Уровень по CLAUDE.md — существенный: проведение и отмена проведения документов из формы. План → `ai-review-plan` →
код → `ai-test` → `ai-review` → `ai-final-check`.

## Причины (разбор кода 2.0.16.114)

- `ТоварыПоступленийВыбор` → `ОткрытьДокументСтроки` ставит `СтандартнаяОбработка = Ложь` и открывает документ по
  **любой** колонке. Двойной щелчок по ячейке записанной строки не начинает правку, а открывает форму документа. В
  рабочем месте производства (`АРМПроизводство`, `ОткрытьДокументСтроки`) документ открывается только по колонкам
  «Статус» и «Документ» и у строк только для просмотра; по прочим колонкам — стандартная обработка, то есть правка.
- `ПослеЗакрытияДокумента` перечитывает страницу без текущего документа: курсор уходит на первую строку.
- `ТоварыПоступленийПередНачаломДобавления` не отменяет стандартное добавление: платформа вставляет строку после
  текущей, а не в начало. В производстве `ПередДобавлениемСтрокиДокумента` отменяет добавление, вставляет строку
  индексом 0 и начинает её ввод обработчиком ожидания.
- Строки страницы идут в порядке пакета: сначала все поступления, затем все приходные ордера, внутри — по запросу.
  Порядка по дате нет.
- Статуса документов в режиме «Товары» нет: меню «Статус» есть только у закладки «Заказы».

## Как будет

### 1. Новая строка — сверху

`ТоварыПоступленийПередНачаломДобавления`: `Отказ = Истина`; строка вставляется `ТоварыПоступлений.Вставить(0)`,
заполняется как сейчас в `ТоварыПоступленийПриНачалеРедактирования` для новой строки (вынести в процедуру
`ПодготовитьНовуюСтрокуТоваров(СтрокаТаблицы, Копирование, Исходная)`), курсор — на неё, ввод — обработчиком ожидания
`НачатьВводВставленнойСтрокиТоваров` (`Элементы.ТоварыПоступлений.ИзменитьСтроку()`), как в производстве.
Копирование (F9) — та же вставка в начало с полями исходной строки (документ, поставщик, склад, накладная, товар,
характеристика, упаковка). **Цена не копируется** (редакция 4, P2 круга 3): копия — новая строка, её цена — по правилам
новой строки механизма (источник цены, право изменения); пользователь с правом вводит цену сам, и тогда
`ЦенаИзменена` ставит обработчик колонки «Цена». Отмена ввода вставленной незаписанной строки удаляет её из таблицы
(`ПриОкончанииРедактирования` с `ОтменаРедактирования`), как в производстве.

### 2. Порядок строк

`Обработки.АРМЗакупки.СтрокиТоваровПоступлений` сортирует строки: документы — **в порядке документов страницы**
(`СписокДокументов` приходит из `СтраницаПоступлений`: `Дата УБЫВ, Ссылка` — тот же порядок, что у пагинации и режима
«Документы», свежие первыми), строки документа — по номеру строки убыванием (последняя добавленная — первой). Без
дополнительного запроса: ранг документа — его индекс в переданном массиве. «Дата и момент времени создания» владельца —
дата документа с временем: новый документ рабочего места получает её текущим моментом сеанса при создании. Документ,
дату которого поправили руками, встаёт по своей дате — так же, как в режиме «Документы»; два документа одной секунды
упорядочиваются ссылкой, как в списке (редакция 2, P2 круга 1). Незаписанные
строки формы остаются над записанными (как сейчас в `ЗагрузитьТоварыПоступленийНаСервере`). Записанная новая строка в
новом документе — свежий документ первой страницы — оказывается первой; строка, добавленная в выбранный сегодняшний
документ, — первой среди строк своего документа.

### 3. Правка записанной строки — как в производстве

- Двойной щелчок: документ открывается по колонкам «Документ» и «Статус» и у строк `ТолькоПросмотр`; по остальным
  колонкам — стандартная обработка (правка).
- После закрытия формы документа страница перечитывается с курсором на той же строке: документ и номер строки
  запоминаются перед открытием. Если в форме документа строки удалили или переставили и строки с этим номером нет —
  курсор на первой строке того же документа (редакция 3, P2 круга 2: номер строки — не идентичность; другой
  идентичности у строки поступления нет — `КодСтроки` поступления по заказу совпадает с кодом строки заказа). Курсор —
  удобство, данные от него не зависят: правка строки идёт по документу, номеру и версии данных, и механизм отказывает
  при изменённом документе.
- Смена товара или характеристики записанной строки подставляет в «Упак.» единицу нового товара (редакция 2, P1
  круга 1): сейчас `ОбновитьДанныеТовараНовойСтроки` для записанной строки ничего не делает, и непустая упаковка
  прежнего товара ушла бы в механизм (`ПрименитьДанныеСтрокиЗакупки` сохраняет переданную упаковку). Для записанной
  строки берётся только единица (`ДанныеТовараНовойСтроки(...).Упаковка`); представление заказа не меняется — привязка
  записанной строки прежняя.
- Колонки записанной строки: только для просмотра остаются колонки шапки документа и привязки — «Документ»,
  «Поставщик», «Склад», «№ накл.», «Дата накл.», «Заказ поставщику». Правятся «Товар», «Характеристика», «Упак.»,
  «Кол-во», «Цена» — набор производства (`УстановитьОформлениеЗакупок("Поступления", …)`).
- **Смена товара записанной строки.** Путь записи — по основанию документа, как сейчас; товар (и характеристика)
  читается из строки документа:
  - документ по заказу поставщику — строка привязана кодом к строке заказа; механизм и сейчас отказывает, если товар не
    совпадает со строкой заказа (`ТекстЗапретаСтрокиОснования`), а код строки поступления при правке не меняется.
    Поэтому смена товара такой строки — отказ до механизма с понятным текстом: «Строка оформлена по строке заказа
    поставщику: другой товар вводится новой строкой, эту — удалите или измените количество». Так же в производстве;
  - документ без заказа — правка проходит; если новый товар (характеристика) есть в открытом заказе поставщика —
    отказ тем же текстом, что для новой строки (`ОткрытыеСтрокиЗаказовПоставщика` — тот же расчёт). Сейчас гейт
    механизма `ТекстЗапретаПоступленияБезЗаказа` пропускает записанную строку целиком: правка количества записанной
    строки без заказа после оформления заказа на товар допустима (редакция 3 плана arm-purchasing-receipt-lines), а
    смена товара — это новая позиция, и для неё правило новой строки. Проверка — в `ПутьСтрокиТоваров` рабочего места
    закупок (товар строки документа читается там же), механизм не меняется.

### 4. «Статус» в режиме «Товары»

- Подменю «Статус» в командной панели `ТоварыПоступлений` — «Провести», «В черновик», «Отменить» (пометить на
  удаление), как «Статус» нижних закладок производства и закладки «Заказы» закупок.
- Документы — уникальные документы выделенных строк (`ВыделенныеСтроки`), только записанные строки. Серверный путь —
  существующий `Обработки.АРМПроизводство.ИзменитьСтатусДокументовСтрок(Документы, Действие, Неопределено)`:
  закупочный контекст, поступления и приходные ордера любого заказа клиента; права, объектная блокировка, запреты
  (оформленный ордер, автовыпуск) — его. «Отменить» — с вопросом, как у заказов.
- **Версия данных при смене статуса не сверяется** (редакция 2, P2 круга 1): путь передаёт ссылки, и
  `ВыполнитьДействиеСтатусаДокумента` вызывает `ЗаблокированныйДокументСтроки` с пустой версией — так сегодня работают
  «Статус» заказов закупок и нижних закладок производства. Статус не меняет содержимое документа: проводится или
  распроводится то, что лежит в базе под блокировкой, со всеми проверками проведения; после действия страница
  перечитывается, и пользователь видит актуальные строки. Сверку версии для всех путей статуса не ввожу в этой сборке —
  пункт в TECHDEBT («Статус» по версиям показанных документов), чтобы поведение путей не разошлось.
- **Назначенные записи строк выполняются перед любым перечитыванием** (редакции 3, 7–10; P1 кругов 2, 6–9).
  - Окончание редактирования назначает запись обработчиком ожидания (урок 2.0.16.106). Назначенные строки хранятся в
    **реквизите формы** `СтрокиТоваровКЗаписи` (СписокЗначений из Число — идентификаторы строк, без повторов, в порядке
    окончания правки) вместо клиентской переменной: его видит сервер, и вторая правка не перетирает первую.
  - Единственный вход загрузки — `ЗагрузитьПоступленияНаСервере`: переключатель режима и
    `ПриЗагрузкеДанныхИзНастроекНаСервере` вызывают его вместо прямого `ЗагрузитьТоварыПоступленийНаСервере`, нижний
    загрузчик становится его внутренней частью. **Первый шаг**, до отбора страницы: `ВыполнитьНазначенныеЗаписи()` —
    забрать и очистить список, затем по порядку записать каждую ещё существующую строку
    (`Обработки.АРМЗакупки.ЗаписатьСтрокуТоваровПоступления` + сообщение). Версии строк очереди **не подменяются** (редакция 12,
    P0 круга 11): вторая строка того же документа после записи первой отклоняется механизмом по версии и возвращается
    к базе с сообщением «значения возвращены» — правка не теряется молча и чужие изменения не перекрываются.
    Очередь из двух строк одного документа возникает, только если две правки закончились в одни 0,1 секунды.
  - Удачная запись строки — **строка формы удаляется сразу** (новая и записанная одинаково): её место займёт строка из
    базы при загрузке, в незаписанные она не попадёт ни в одном режиме, задвоения нет. Документ и номер строки
    последнего удачного результата становятся курсором этой загрузки, если вызывающий не задал свой; новый документ —
    страница первая (он самый свежий), как у нынешней записи.
  - Отказ по записанной строке — строка формы тоже удаляется и придёт из базы (см. ниже, «возвращает к базе»), к
    сообщению механизма — «Правка строки не записана: значения возвращены». Отказ по новой строке — она остаётся среди
    незаписанных для правки.
  - Клиентский обработчик ожидания: список пуст (записи уже выполнила другая загрузка) — **ничего не делает**; таблица
    в режиме ввода другой строки (признак формы `ИдётВводСтроки`: ставится в `ПриНачалеРедактирования`, снимается в
    `ПриОкончанииРедактирования`) — тоже ничего: назначенные записи выполнит обработчик, который назначит окончание
    этой правки, — перечитывание не сотрёт строку под вводом (редакция 11, P1 круга 10). Иначе — загрузка
    (`ЗагрузитьПоступленияНаСервере` с текущими отборами): запись и перечитывание — один серверный вызов. Прочие
    перечитывания (пагинация, «Обновить», отборы, переключатель, статус, закрытие документа) начинаются с действия
    пользователя вне таблицы: платформа к этому моменту заканчивает ввод строки, и её правка уже в очереди.
  - Закрытие рабочего места (`ПередЗакрытием`) с непустым списком выполняет записи серверным вызовом.
  - Команда статуса: `ЗакончитьРедактированиеСтроки()`, если таблица в режиме ввода; серверная часть начинается с
    `ВыполнитьНазначенныеЗаписи()`; была отклонена хоть одна — статус не меняется, сообщение. Незаписанные новые строки
    (`НомерСтроки = 0`) в статус не входят и при перечитывании остаются, как сейчас.
- **Отказ записи записанной строки возвращает её к базе** (редакция 6, круги 3–5). Исходное правило плана 2.0.16.108
  («отказ — сообщение, строка перечитывается из базы, новая непрошедшая строка остаётся для правки»): сейчас код его
  не выполняет — при отказе записанная строка остаётся на экране с правкой, а следующее перечитывание стирает её молча.
  Теперь отказ по записанной строке (`НомерСтроки <> 0`) удаляет её строку формы, и загрузка читает строку из базы с
  курсором на ней; к сообщению механизма добавляется «Правка строки не записана: значения возвращены». Новая строка при отказе остаётся для правки, как сейчас. Так у записанных строк незаписанных правок
  не бывает: перечитывание после статуса, после записи другой строки, при смене страницы и после закрытия формы
  документа ничего не теряет молча, версия данных строки — всегда версия из базы. Признаков правки и переноса правок
  поверх перечитанных строк нет (редакции 4–5 отменены: P0 и 2×P1 круга 5).
- Итоги — в панель сообщений (как `ИзменитьСтатусНаСервере` заказов); после — перечитывание страницы с курсором на
  текущей строке.
- Строки `ТолькоПросмотр` (документ на другом основании) в статус входят: статус меняет документ целиком, его
  содержимое не правится; запреты механизма те же, что в производстве.
- Видимость подменю — при праве проведения поступления или приходного ордера; без права — скрыто.

## Остаточный риск (круг 12 `ai-review-plan`, P1)

Правка строки A и начало ввода строки B того же документа в пределах 0,1 секунды: запись A откладывается до конца
ввода B, после записи A строка B отклоняется по версии документа и возвращается к базе с сообщением «значения
возвращены» — пользователь вводит правку B повторно. Молча правка не теряется, чужие изменения не перекрываются.
Устранение требует записи без перечитывания во время ввода другой строки (обновление версий строк формы на месте) —
отдельная доработка общего механизма отложенной записи, тот же порядок и в рабочем месте производства. Решение о
принятии риска — за владельцем; при принятии — пункт в TECHDEBT.

## Что не меняется

- Серверная запись строки (`ЗаписатьСтрокуТоваровПоступления` → `ЗаписатьСтрокуДокумента`), удаление строк, выбор
  документа и склада, накладная новой строки.
- Режим «Документы».

## Тесты (уровень 3)

`ПоступленияТоварамиАРМ` дополняется (без отказов проведения — проверки запрета без записи):
1. `СтрокиТоваровПоступлений` двух документов разного момента — строки свежего документа первыми, внутри документа —
   по номеру строки убыванием.
2. Смена товара записанной строки документа по заказу — отказ `ЗаписатьСтрокуТоваровПоступления` с текстом про новую
   строку, документ не изменён.
3. Смена товара записанной строки документа без заказа на товар без открытых заказов — записано, товар строки новый;
   на товар с открытым заказом — отказ.
4. `ИзменитьСтатусДокументовСтрок` с `Неопределено` по поступлению режима «Товары»: «В черновик» — не проведён,
   «Провести» — проведён.
