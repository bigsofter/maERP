# Промпт: бухгалтерский контур Марокко, Ф1 С2б — списки и создание налогового документа из отмеченных

Выполни сборку **С2б** детального плана `docs/plans/accounting-morocco-f1.md` (раздел «Сборки → С2», пункт
«Списки»). Предыдущая сборка С2а — 2.0.16.97 (коммит `c61a1b4`), дельта-план `docs/plans/accounting-morocco-f1-s2.md`,
отчёт `.ai/reports/accounting-morocco-f1-s2.md`.

## Объём: что входит и что нет

Остаток С2 из `docs/ROADMAP.md` (блок 3) и `docs/TECHDEBT.md` («Ф1 С2а») делится на две сборки по риску:

- **С2б (эта сборка, M)** — интерфейс над готовой механикой С2а, без новых веток проведения и без реструктуризации:
  - закладки «Управленческие» / «Налоговые» в списках реализаций и поступлений;
  - колонки связи;
  - команда «Создать налоговый документ» из отмеченных.
- **С2в (следующая, L, своё ревью плана)** — расширение механики, каждое снимает ограничение С2а:
  - частичное покрытие: часть строк или количества, серии и партии покрытой части, знаменатели доли;
  - покрытие услуг (`ТЧУслуги`);
  - помесячная фактура: основания разных дней, с распределением прямых оплат по основаниям;
  - основание с возвратом, корректировкой или сертификатом до покрытия;
  - возвраты, корректировки и сертификаты частично покрытого основания, контроль кредита по двум объектам.

  В С2б этого **не делать**: ограничения С2а остаются отказами с текстом.

## Что сделать (С2б)

- **Закладки списка.** Над списком — переключатель «Все / Управленческие / Налоговые» (отбор по `УУ`). Видимость — только
  при `РаздельныйУчетВключен()`. Выбранная закладка запоминается в настройках формы. Отбор пользователя по `УУ` в
  настройках списка закладка не ломает.
- **Колонки связи.**
  - «Налоговый документ» у неналогового: номер и дата покрывающего проведённого документа, пусто — не покрыт.
  - «Основания» у налогового: число оснований или номер единственного.

  Поля — в произвольном запросе списка левым соединением с ТЧ `Основания`, сгруппированным так, чтобы строки
  документа не размножались. Без обращения к БД на каждую строку списка. Сверка — `listcheck.py`. Отбор по колонке
  «не покрыт» — для бухгалтера, который ищет неналоговые без налогового.
- **Команда «Создать налоговый документ»** в списке (у реализации и поступления):
  - по отмеченным неналоговым проведённым документам;
  - группирует их по ключу ограничений С2а: организация, контрагент, договор, день, валюта;
  - на каждую группу открывает **форму нового документа**, заполненную через
    `ЗаполнитьПоДаннымЗаполнения(Структура("ОснованияНалоговогоДокумента", …))`;
  - документы не записывает: пользователь проверяет цены и проводит сам.

  Покрытые, налоговые, непроведённые и не проходящие `ТекстОшибокДокумента` документы в группы не идут — сводное
  сообщение со списком пропущенных и причиной. Больше пяти групп — вопрос пользователю перед открытием форм.
  Видимость команды — по `РаздельныйУчетВключен()`; `menucheck.py` после правки командного интерфейса.
- **Сценарии `ТестыДокументов`** (машинная часть): функции группировки отмеченных и сводного отказа покрываются
  сценарием без открытия форм. Проверить: две группы по разным дням; покрытый документ пропущен с причиной; налоговый
  пропущен; данные заполнения группы дают документ с теми же основаниями, что ручной подбор. Отказы — функциями, не
  записью. Ручная часть — чек-лист в `docs/TESTING.md`: закладки, колонки, команда, видимость при выключенной опции.

## Порядок и гейты

Изменение среднее: формы, запросы списков, команда без проведения. Если в ходе работы понадобится трогать проведение,
блокировки или метаданные (новый реквизит, ТЧ), оно становится существенным: остановись, допиши дельта-план и пройди
`ai-review-plan`.

1. Короткая дельта-раскладка в `docs/plans/accounting-morocco-f1-s2.md`, раздел «С2б»: какие формы, какие поля
   запроса, ключ группировки.
2. Реализация.
3. `scripts/lint.sh` (ноль новых замечаний против `build/bsl-json-baseline.json`), `refcheck.py`, `listcheck.py`,
   `colfont.py`, `menucheck.py`.
4. **`ai-review`** → фиксы → `ai-review --verify --tier codex`.
5. `ai-final-check` (с `--db` на копии).
6. Отчёт `.ai/reports/accounting-morocco-f1-s2b.md`.

Уровни 1–3 — на **копии** базы: `build/ib` держит EDT.

- Синхронизация: `bash -c 'scripts/ib-sync.sh $PWD/build/ib-kp'`.
- Затем `scripts/doctests.sh` и `scripts/smoke.sh` с тем же путём, только под bash.
- Смок обязан открыть обе формы списка с новыми полями запроса.
- Во время выгрузки EDT (~4 мин) `src/cf` не править.

## Грабли, на которых уже спотыкались (С1–С2а)

- **Имена в коде:**
  - зарезервированные слова — не имена переменных и не псевдонимы полей запроса (`Возврат`, `Новый`, `Есть`,
    `Выбор`; tiny1C query-001);
  - `Документы` — имя глобального контекста;
  - параметр с именем процедуры затеняет её (bsl-011).
- **Платформенные функции:** `ЗначениеВМассиве` принимает одно значение, `СвернутьМассив` не существует — свои
  помощники.
- **Функциональная опция** запоминается на серверный вызов (bsl-023): признак раздельного учёта — только через
  `НалоговыйУчет.РаздельныйУчетВключен()`.
- **Запросы:**
  - двусмысленный псевдоним при соединении с ТЧ (`Основания.Ссылка`) роняет запрос — всегда полные псевдонимы;
  - `listcheck.py` сверяет колонки с текстом запроса, но не ловит размножение строк — проверить руками на документе с
    двумя основаниями.
- **Form.form:**
  - элемент без `<visible>true</visible>` скрыт;
  - обработчик без `<handlers>` не вызывается;
  - вставка — по вложенности `<items>`, а не по отступу;
  - id уникальны, после правки — `xmllint`;
  - шапка колонки — со шрифтом (`colfont.py`).
- **Прогоны:**
  - перед запуском тестов проверь, что на копии не висит прежний `doctests.sh`: он держит базу;
  - не жди окончания циклом `pgrep -f` по шаблону, который совпадает с самим циклом;
  - выгрузка EDT иногда падает гонкой «feature with code "type"» — повтори синхронизацию, до трёх раз.
- **Ревью:**
  - `ai-review --verify` со второго круга: «not_fixed» у уже закрытых находок — артефакт;
  - итог — в `.ai/reviews/<slug>/03c-verify-note.md`, копию прежнего `03b` сохраняй;
  - находку, опровергнутую прогоном на базе, отклоняй с доказательством.
