## Что видит пользователь

**Колонка продукции** (рабочее место «Продукция», заказ на производство `ТЧТовары`), кнопка выбора «…» /F4:

```
Изделие А — создано 21.09.2026
Изделие Б — создано 20.09.2026
…                                  (до 10 последних созданных ГП и ПФ)
Выбрать из справочника: Продукция, Полуфабрикат…
```
Последний пункт открывает стандартную форму выбора номенклатуры с отбором по типу, списком без групп. Ввод текстом
(автоподбор) предлагает только ГП и ПФ. Позицию другого типа выбрать нельзя — сначала тип в карточке.

**Колонка материала** (рабочее место «Заказы поставщику», «Поступления», «Переработка»):

```
Ткань синяя — дефицит 12,5          (материалы текущего заказа; у поступлений — «к поступлению»,
Нитки — дефицит 0                    у переработки — «потребность»)
Выбрать из справочника: Сырье, Полуфабрикат, Товар…
Выбрать из всей номенклатуры…
```
Выбор материала заказа подставляет и характеристику; дальше — как при вводе руками (поставщик, количество, строка
заказа поставщику). Ввод текстом отбора не имеет (мягкий отбор).

**Заказ на производство, `ТЧМатериалы`**: те же два пункта справочника (материалы заказа здесь и есть сама таблица).

У заказа с видом операции «Продажа» ничего не меняется: стандартный выбор без отбора по типу.

## Реализация

### 1. Правило и данные подбора — `Справочники.Номенклатура` (модуль менеджера, серверный)

Новая область `ПодборНоменклатуры`, экспортные:
- `НазначениеПодбораПродукция()`, `НазначениеПодбораМатериалы()` — строки-константы назначения колонки.
- `ТипыПодбора(Назначение)` → `ФиксированныйМассив` типов; неизвестное назначение — исключение (ошибка разработчика).
- `ПоследниеСозданные(Типы, Количество)` → `СписокЗначений`: значение — `Структура("Номенклатура, Характеристика")`,
  представление «наименование — создано дд.ММ.гггг». Запрос: не группа, не помеченная, тип в `&Типы`,
  `ДатаСоздания` заполнена (у старых позиций без даты порядок бессмыслен), `УПОРЯДОЧИТЬ ПО ДатаСоздания УБЫВ,
  Наименование`, `ПЕРВЫЕ` по параметру — через `СтрЗаменить` числа в тексте.
- `ДанныеПодбора(Назначение)` → `Структура("Типы, Пункты, Мягкий")`: продукция — типы + последние 10, жёсткий;
  материалы — типы, пустые пункты, мягкий. Один серверный вызов на нажатие выбора.

### 2. Показ подбора — `РаботаСДокументамиКлиент` (общий клиентский модуль)

`ПоказатьПодборНоменклатуры(Элемент, ДанныеПодбора, ОповещениеОВыборе)`:
- список = пункты + «Выбрать из справочника: <типы>…» + (мягкий) «Выбрать из всей номенклатуры…»;
- пунктов нет и отбор жёсткий — форма выбора открывается сразу;
- `ПоказатьВыборИзСписка` → выбран пункт с `Структура` → `ВыполнитьОбработкуОповещения(ОповещениеОВыборе, значение)`;
- выбран пункт справочника → `ОткрытьФорму("Справочник.Номенклатура.ФормаВыбора", РежимВыбора + Отбор.ТипНоменклатуры,
  Элемент)`: владелец — **само поле**, выбор обрабатывает платформа как при штатной кнопке «…» (значение в поле,
  `ПриИзменении` колонки), поэтому существующие обработчики смены позиции срабатывают без дублирования.
Представления пунктов — `НСтр` на ru/fr/en/es, имена типов — из синонимов перечисления.

### 3. Форма выбора номенклатуры

`ФормаВыбора.ПриСозданииНаСервере` (привязан, пуст): если в `Параметры.Отбор` есть `ТипНоменклатуры` — список
плоский (`ОтображениеТаблицы.Список`). У групп тип не заполнен (реквизит только для элементов): в иерархическом виде
отбор спрятал бы группы вместе с содержимым. То же делает `УстановитьПараметрыСписка` формы списка при отметке типа.
Штатный F4 из поля с `ПараметрыВыбора` передаёт тот же `Отбор` — тоже плоский список.

### 4. Рабочее место (`Form.form` не меняется)

- `НастроитьЭлементы`: `ПродукцияНоменклатура.ПараметрыВыбора = Отбор.ТипНоменклатуры` (типы продукции — жёстко,
  действует и на автоподбор) ; `УстановитьДействие("НачалоВыбора", "Подключаемый_…")` для `ПродукцияНоменклатура`,
  `ЗаказыПоставщикуМатериал`, `ПоступленияМатериал`, `ПереработкиМатериал`. Префикс `Подключаемый_` — соглашение
  для обработчиков, привязанных кодом (BSL LS не считает их неиспользуемыми).
- Колонки «Выпуск», «Отгрузки», «Поступления из переработки» — уже списком заказа/передачи, не трогаются.
- Продукция: `Подключаемый_ПродукцияНоменклатураНачалоВыбора` → `ДанныеПодбора(Продукция)` → показ; выбор из
  списка → `ПослеСменыНоменклатурыПродукции(СтрокаТаблицы)` (выделено из `ПродукцияНоменклатураПриИзменении`).
- Материалы: `Подключаемый_ЗакупкиМатериалНачалоВыбора` → пункты = материалы текущего заказа из дерева `Материалы`
  (клиент, без сервера): уникальные пары материал+характеристика, количество по колонке таблицы (`Дефицит` /
  `КПоступлению` / `Потребность` — как `ЗакупкиМатериалПриИзменении`) суммой по дереву (`КоличествоМатериала`);
  выбор → `ПослеСменыМатериала(ИмяТаблицы, СтрокаТаблицы, Характеристика)` — выделено из
  `ЗакупкиМатериалПриИзменении`, который теперь его и вызывает (характеристика ставится до подсчёта количества).
- Строка только для чтения / без права ввода — `НачалоВыбора` не показывает подбор (поле недоступно и так; проверка
  `ТекущиеДанные = Неопределено`).

### 5. Заказ на производство (`Documents/ЗаказПокупателя/Forms/ФормаДокумента`)

Форма не генерируется — `<handlers>` `StartChoice` в `Form.form` для `ТЧТоварыНоменклатура` и
`ТЧМатериалыНоменклатура`.
- `НастроитьМатериалы` (вызывается при создании, записи и смене вида операции): у заказа на производство
  `Элементы.ТЧТоварыНоменклатура.ПараметрыВыбора` = `Отбор.ТипНоменклатуры` продукции, иначе — пустой массив
  (у продажи отбора нет). Автоподбор (`ТЧТоварыНоменклатураАвтоПодбор` → `ОбработкаПолученияДанныхВыбора` с
  `ПодменаАвтоподбора`) уже фильтрует по `Параметры.Отбор.ТипНоменклатуры`, который приходит из `ПараметрыВыбора`
  поля.
- `ТЧТоварыНоменклатураНачалоВыбора`: только при `ЭтоЗаказНаПроизводство`, иначе штатная обработка. Выбор из списка
  → номенклатура в строку + та же обработка, что в `ТЧТоварыНоменклатураПриИзменении` (параметры номенклатуры,
  последние цены). Пересчёт материалов — как сейчас, по окончании редактирования строки (`НоменклатураДоРедактирования`).
- `ТЧМатериалыНоменклатураНачалоВыбора`: мягкий подбор материалов (два пункта справочника).
- Мёртвый параметр выбора `Отбор.ВидНоменклатуры` у `ТЧТовары.Номенклатура` в `.mdo` (реквизита `ВидНоменклатуры`
  у номенклатуры нет) — не трогаю: правка метаданных вне объёма, пишу в TECHDEBT.

### 6. Тесты уровня 3 — расширение сценария `АРМПроизводство`

`ПроверитьПодборНоменклатурыАРМ(Контекст)`:
- `ТипыПодбора`: продукция = {Продукция, Полуфабрикат}, материалы = {Сырье, Полуфабрикат, Товар}; услуга и комплект
  не входят ни в один; неизвестное назначение — исключение;
- `ПоследниеСозданные`: три ГП с `ДатаСоздания` в будущем (+1…+3 ч, чтобы обогнать базу), помеченная ГП (+4 ч) и
  сырьё (+5 ч); при `Количество = 2` — ровно две самые новые ГП в порядке убывания, помеченной и сырья нет;
- `ДанныеПодбора`: продукция — жёсткий с пунктами, материалы — мягкий без пунктов.

Интерфейс (список, форма выбора, автоподбор, группы) — ручная приёмка на клиенте, `docs/TESTING.md` «Проверка S7».

## Риски

- **Данные клиентов**: жёсткий отбор продукции спрячет ГП с неверным типом — выход один: тип в карточке; «Что нового»
  говорит это прямо. У материалов отбор мягкий. Уже введённые строки не проверяются (решение 6).
- **Форма выбора открыта из обработчика списка, а не штатно**: владелец — поле; если на клиенте поле к этому моменту
  вышло из редактирования, значение не встанет — проверка на ручной приёмке, запасной путь — оповещение о закрытии.
- `ТипНоменклатуры` в запросе формы выбора есть (`customQuery`), отбор платформы накладывается на него.

## Разбор плана (2026-09-22, `architecture-critic`, Codex в лимите до 26.09)

Approve with changes, блокирующего нет. Принято:
- P2-1: форма выбора, открытая кодом, не получает параметров выбора реквизита — `Отбор.ПометкаУдаления = Ложь` явно
  в `ОткрытьВыборНоменклатуры`; в заказе он же — в `ПараметрыВыбора` поля рядом с отбором по типу;
- P2-2: подстановка из списка в заказе ставит `Модифицированность` и характеристику;
- P2-3: плоский список формы выбора включается и в документах, где `Отбор.ТипНоменклатуры` был в `.mdo` раньше
  (выпуск, поступления, реализация и др.) — назван в «Что нового» и в ручной приёмке;
- P3-2: `ЗакрыватьПриВыборе` передаётся явно; `БлокироватьОкноВладельца` в 8.5 устарел (BSL LS) — режим окна
  остаётся свойством формы выбора;
- P3-3: сортировка по неиндексированной `ДатаСоздания` — TECHDEBT (индекс — правка метаданных).

Не принято: P3-1 (подбор в записанной строке) — кнопка выбора ячейки доступна только в режиме редактирования, а его
для записанных строк уже отменяют `ПередНачаломИзменения`; P3-4 (тестовые позиции с будущей датой) — сценарий идёт
в транзакции с откатом.

## Реализация: отклонения от плана

- `РаботаСДокументамиКлиент.ПоказатьПодборНоменклатуры` принимает форму первым параметром: `ПоказатьВыборИзСписка` —
  метод формы, в общем модуле без квалификатора не компилируется (поймал CheckConfig смока, правило tiny1C `bsl-020`).
- Форма выбора встаёт на текущую позицию поля (`ТекущаяСтрока`) — ревью кода, P3-1.
