# План: консоль отчётов в «Главном» (избранное с образами + «Все отчёты»)

Задача владельца (2026-10-31). Дословно по смыслу:

1. Консоль, на которой собираются **избранные отчёты** пользователя.
2. Отдельно — механизм **«Все отчёты»**: все отчёты и их варианты таблицей, быстрый поиск
   отчёта и варианта.
3. Любой вариант можно сделать **избранным** — он попадает на панель избранного.
4. В идеале одна форма; к полному списку переходят отдельно, там открывают, настраивают свои
   варианты и сохраняют в избранное.
5. Избранное — **образы отчётов** (как в УНФ): представление отчёта видно сразу на форме,
   по щелчку отчёт разворачивается.
6. Форма — в разделе **«Главное»**.

Это этап **У6** из `docs/UNF-ADOPTION.md` («Варианты отчётов и панель отчётов с поиском»),
расширенный избранным с образами. Вторая волна — отчёт прослеживаемости партий
(`docs/plans/lot-traceability.md`, пишется после этой волны) — станет первым «избранным».

## Решения владельца (2026-10-31)

| Развилка | Решение |
|---|---|
| Образ на плитке | **Снимок + обновить**: плитка показывает последний сформированный результат с датой; обновление кнопкой и фоном при открытии формы |
| Кому консоль | **Всем ролям**; избранное у каждого пользователя своё; в «Все отчёты» — только отчёты, доступные по правам |
| Порядок работ | **Две волны**: сначала консоль, затем отчёт по партиям |
| Учёт времени | TinyCIO |
| 12 отчётов со своими формами | **Ярлык + TECHDEBT** (ответ владельца 2026-10-31 после 6-го круга ревью): в «Все отчёты» — одной строкой без вариантов, в избранном — плитка-ярлык без образа; варианты и образы для них — отдельной задачей |

## Уровень изменения

Существенное: новая обработка, новый регистр сведений, права всех рабочих ролей, правка
основного раздела «Главное» и общей формы отчёта. Порядок: план → **`ai-review-plan`** →
реализация → `ai-test` → **`ai-review`** → `ai-database` (новый регистр) → `ai-security` (привилегированный модуль) →
`ai-final-check` → отчёт `.ai/reports/reports-console.md`.

## Исходное состояние (проверено)

- 65 отчётов, все на СКД; 53 открываются общей формой `CommonForm.ФормаОтчёта`

  `КарточкаСчета`, `КарточкаСубконто`, `АнализСубконто`, `ОборотноСальдоваяВедомость*`,

- Предопределённые варианты — в схемах (`<settingsVariant>`, у трёх отчётов по два).
- `reportsVariantsStorage` в `Configuration.mdo` не задан — пользовательские варианты
  платформа хранит в стандартном хранилище вариантов отчётов.

  мобильного режима, не наш случай.

## Проверено по модели типов 8.5.1 (jar EDT)

- `ПолеТабличногоДокумента` **не масштабируется** программно: есть только
  `РежимМасштабированияПросмотра` (Авто/Крупный/Обычный). Миниатюру им не построить.
- `ТабличныйДокумент.Записать(..., ТипФайлаТабличногоДокумента.HTML5)` есть.
- `СтандартноеХранилищеНастроекМенеджер.ПолучитьСписок(КлючОбъекта, ИмяПользователя)`,

Отсюда конструкция образа: **снимок = HTML5 верхней части результата**, на плитке —
`ПолеHTMLДокумента` с CSS-уменьшением (`zoom`/`transform: scale`) обёрткой вокруг HTML.

## 1. Хранение избранного

Новый регистр сведений **`ИзбранныеОтчеты`** (свой uuid; у клиентов объекта нет).

| Свойство | Значение |
|---|---|
| Режим записи | Независимый, непериодический |
| `useStandardCommands` | **false** (см. `rmk-izbrannoe.md`: иначе ведущее измерение тянет команды в меню) |
| Измерение `ПользовательИБ` | УникальныйИдентификатор — `ПользователиИнформационнойБазы.ТекущийПользователь().УникальныйИдентификатор` (ревью плана, круг 6, P0: `ПараметрыСеанса.Пользователь` у рабочих ролей `МенеджерПоПродажам`, `Казначей`, `Клиент` доступен на установку — подмена дала бы чужое избранное через привилегированный модуль; идентификатор пользователя ИБ из кода не подменяется). Не ведущее — ссылок нет |
| Измерение `Идентификатор` | Строка(36) — `Новый УникальныйИдентификатор`, один пользователь может держать два избранных одного варианта с разными настройками |
| Ресурс `Порядок` | Число(5,0) |
| Реквизит `ПолноеИмяОтчета` | Строка(255), `Отчет.<Имя>` |
| Реквизит `КлючВарианта` | Строка(255) |
| Реквизит `Наименование` | Строка(150) — заголовок плитки, пользователь правит |
| Реквизит `Настройки` | ХранилищеЗначения — **полные** `НастройкиКомпоновкиДанных` на момент добавления (структура, изменённая без сохранения варианта, не теряется) |
| Реквизит `ПользовательскиеНастройки` | ХранилищеЗначения (`ПользовательскиеНастройкиКомпоновкиДанных`) |
| Реквизит `Снимок` | Строка неогр. — HTML образа |
| Реквизит `ДатаСнимка` | Дата (дата и время) — для показа |
| Реквизит `МоментСнимка` | Число(15,0) — `ТекущаяУниверсальнаяДатаВМиллисекундах()` **начала** формирования |
| Реквизит `ОтпечатокПрав` | Строка(64) — SHA-256 от отсортированного списка ролей пользователя + `Метаданные.Версия` на момент формирования |
| Реквизит `ОшибкаСнимка` | Строка неогр. — краткое представление ошибки последнего формирования |

Почему регистр, а не справочник: тот же довод, что у `ИзбраннаяНоменклатураРМК` — личный
список, без ссылок на него, без реструктуризации существующих таблиц. Обработчик
обновления **не нужен**: таблица новая.

Запись — менеджером записи по полному ключу (`ПользовательИБ` + `Идентификатор`): две сессии
одного пользователя не затирают друг друга.

**Конкурентность (ревью плана, P2).** Каждая запись в регистр (снимок, переименование,
порядок, удаление) — в транзакции с **исключительной управляемой блокировкой**
`РегистрСведений.ИзбранныеОтчеты` по `ПользовательИБ` + `Идентификатор` (режим блокировок
конфигурации — `Managed`): блокировка → чтение менеджером → проверка `Выбран()` → правка
только своих реквизитов → запись → фиксация. Снимок пишет только `Снимок`, `ДатаСнимка`,
`ОшибкаСнимка`, `МоментСнимка`, `ОтпечатокПрав` (ревью плана, круг 4, P2); переименование — только `Наименование`; перестановка — только `Порядок`.
Запись не найдена под блокировкой (плитку убрали, пока шло формирование) — снимок
отбрасывается, запись не воскрешается. **Старый результат не затирает новый** (ревью плана,
круг 2, P2): снимок пишется, только если `МоментСнимка` в записи меньше момента начала этого
формирования; иначе результат отбрасывается — его уже обогнало более позднее формирование.

**Перестановка плиток** («Выше»/«Ниже», ревью плана, круг 5, P2) меняет `Порядок` у двух
записей — блокируется **весь набор пользователя** (исключительная блокировка по одному
измерению `ПользовательИБ`), обе записи читаются и пишутся в одной транзакции. Добавление
(`Порядок = max + 1`) — под той же блокировкой набора, иначе две сессии получат одинаковый
порядок. Формирование отчёта идёт **вне** транзакции, под
блокировкой — только короткая запись результата.

### Права (ревью плана, круг 2, P0)

**Роли прав на регистр не получают вовсе.** Прямые `Read`/`Update` без RLS дали бы любой
рабочей роли программно читать и менять чужое избранное (обработка, консоль запросов); отбор в
форме и `useStandardCommands = false` этого не закрывают, а RLS в проекте нет.

Доступ к регистру — только через новый серверный общий модуль **`ИзбранныеОтчетыПолныеПрава`**
(`Сервер`, **`Привилегированный`**, без `ВызовСервера`: зовут его только серверные процедуры форм и `ПанельОтчетов`). Каждый его экспортный метод сам берёт
идентификатор `ПользователиИнформационнойБазы.ТекущийПользователь()` (параметр «пользователь» снаружи не принимает; `ПараметрыСеанса.Пользователь` не используется — его можно установить) и работает
только с записями этого пользователя: список плиток, добавить, переименовать, переставить,
удалить, записать снимок. Этот модуль **не формирует отчёты** — формирование идёт в
непривилегированном `ПанельОтчетов` с правами пользователя (раздел 2.2), привилегированный
модуль только хранит результат. Изменение трогает привилегированный режим → обязателен
`ai-security`.

`setForNewObjects = true` — у ролей **`Администратор`** и **`Руководитель`** (ревью плана,
круг 3, P0): обе получили бы права на регистр автоматически. `Администратор` оставляем — он и
так управляет всеми данными. У `Руководитель` в `Rights.rights` объект
`InformationRegister.ИзбранныеОтчеты` записывается **явно со всеми правами `false`**. Проверка
после реализации — `ПравоДоступа("Чтение", Метаданные.РегистрыСведений.ИзбранныеОтчеты,
Роль)` по всем ролям: `Истина` только у `Администратор` — строкой сценария уровня 3.

**Отзыв права (ревью плана, круги 1 и 2, P0).** Право на отчёт проверяется **при каждой выдаче снимка**,
а не только при формировании: серверная функция, отдающая форме плитки, по каждой записи
проверяет `ПравоДоступа("Просмотр", Метаданные.Отчеты[Имя])` и видимость отчёта по
функциональным опциям. Нет права или отчёт удалён из конфигурации — `Снимок` на клиент **не
передаётся**, плитка показывает «Нет доступа к отчёту» и предлагает убрать её из избранного;
сам снимок при этом стирается (запись по правилу конкурентности выше). Фоновое
формирование делает ту же проверку перед построением отчёта.

Право на сам отчёт не покрывает права на **данные**, из которых собран снимок. В maERP права
на данные задаются только ролями (RLS нет), поэтому при формировании в запись кладётся
`ОтпечатокПрав` — хеш отсортированных имён ролей пользователя и версии конфигурации (в новой
версии права ролей могли поменяться). При выдаче отпечаток пересчитывается: не совпал — снимок
не отдаётся (плитка «Обновляется…»), стирается и ставится в фоновое формирование, которое
построит его уже с текущими правами.

## 2. Обработка `КонсольОтчетов`

Новая обработка, `useStandardCommands` по `mdo-001`. Две формы, две команды.

### 2.1. Форма `ИзбранныеОтчеты` (основная)

- Сетка плиток, по умолчанию 2 колонки (группа «Горизонтальная если возможно» —
  `ГруппировкаПодчиненныхЭлементовФормы.ГоризонтальнаяЕслиВозможно`, проверено в РМК).
- Плитка строится программно (`Элементы.Добавить`) по записям регистра, порядок —
  `Порядок, Наименование`. Состав плитки:
  - заголовок-гиперссылка: наименование отчёта/варианта; щелчок — открыть отчёт;
  - строка состояния: «Обновлено 31.10 14:05» / «Формируется…» / «Ошибка: …»;
  - `ПолеHTMLДокумента` высотой ~10 строк, без полос прокрутки, только просмотр — образ;
    щелчок по полю (`ПриНажатии`, `СтандартнаяОбработка = Ложь`) — открыть отчёт;
  - гиперссылки-значки в шапке плитки (при реализации вместо контекстного меню — видны сразу):
    «Обновить», «Переименовать», «Выше», «Ниже», «Убрать из
    избранного» (декорация, не кнопка — у кнопки контекстного меню нет, см. РМК).
- Командная панель формы: «Все отчёты», «Обновить все».
- Пустое избранное — надпись «Добавьте отчёты в избранное из списка всех отчётов или из
  открытого отчёта» с гиперссылкой «Все отчёты».
- **Открытие отчёта**: `ОткрытьФорму(ПолноеИмяОтчета + ".Форма", Новый Структура(
  "КлючВарианта, ПользовательскиеНастройки, ИдентификаторИзбранного, СформироватьПриОткрытии",
  …, …, Идентификатор, Истина), , Идентификатор)` — `ИдентификаторИзбранного` передаётся
  **в структуре параметров** (ревью плана, круг 3, P1: аргумент уникальности его в форму не
  передаёт), 4-й аргумент — только уникальность окна — уникальность по идентификатору избранного, чтобы два избранных одного
  отчёта открывались двумя окнами. Для 12 отчётов со своими формами — тот же вызов
  (`.Форма` = основная форма отчёта); если форма не принимает варианты — открывается с
  настройками по умолчанию (фиксируем в TECHDEBT, если так).
- **Фоновое обновление при открытии**: снимки старше **1 часа** (константа модуля, без
  настройки) обновляются одним фоновым заданием через `ДлительныеОперации.ВыполнитьВФоне`;
  форма ждёт его `ДлительныеОперацииКлиент`-ожиданием и перерисовывает плитки по завершении.
  Форма открывается сразу со старыми снимками — открытие «Главного» не тормозит.

### 2.2. Формирование снимка (серверный общий модуль `ПанельОтчетов`)

Экспортные (с комментариями по правилу CLAUDE.md):

- `СформироватьСнимки(Параметры, АдресРезультата)` — процедура фонового задания, сигнатура
  по контракту `ДлительныеОперации.ВыполнитьВФоне` (ревью плана, P1: механизм всегда
  передаёт параметры процедуры и адрес результата, `ДлительныеОперации/Module.bsl:299–302`);
  `Параметры.Идентификаторы` — массив; в `АдресРезультата` — массив обновлённых
  идентификаторов. По каждому:
  1. `Отчет = Отчеты[Имя].Создать()`;
  2. настройки: сохранённые полные `Настройки` записи, если заполнены; иначе вариант — предопределённый — `Отчет.СхемаКомпоновкиДанных.ВариантыНастроек
     [КлючВарианта].Настройки`, пользовательский — `ХранилищеВариантовОтчетов.Загрузить(
     ПолноеИмяОтчета, КлючВарианта)`; не найден — ошибка снимка «Вариант удалён»;
  3. `Отчет.КомпоновщикНастроек.ЗагрузитьНастройки`, затем `ЗагрузитьПользовательскиеНастройки`;
  4. `Отчет.СкомпоноватьРезультат(ТабДок, Расшифровка)` — так отрабатывает
     `ПриКомпоновкеРезультата` модуля отчёта, если он есть;
  5. верх результата: `ТабДок.ПолучитьОбласть(1, 1, Мин(40, ТабДок.ВысотаТаблицы),
     ТабДок.ШиринаТаблицы)` → во временный файл HTML5 → текст; лимит 300 КБ — больше
     обрезаем снимок до «нет образа, откройте отчёт»;
  6. запись снимка менеджером записи (см. раздел 1); исключение отчёта — в `ОшибкаСнимка`
     `КраткоеПредставлениеОшибки`, полное — в журнал регистрации, остальные плитки
     продолжают формироваться.
- **Образ строится только у отчётов на общей форме `CommonForm.ФормаОтчёта`** (53 отчёта;
  ревью плана, P1). У 12 отчётов со своими формами результат собирает форма: «Анализ счёта» и
  прочие бухгалтерские готовят схему и параметры в `СформироватьОтчетНаСервере` формы и
  вызывают `БухгалтерскиеОтчетыВызовСервера`, `ДвиженияДокумента` и `ЗарплатаСотрудника` — на
  макете. Универсальный `Создать → ЗагрузитьНастройки → СкомпоноватьРезультат` их не
  воспроизводит. Такие отчёты в избранное добавляются **ярлыком отчёта целиком**: без
  варианта и без настроек (ревью плана, круг 4, P1: открыть их с сохранённым вариантом
  универсально нельзя — схему и настройки грузит `БухгалтерскиеОтчетыВызовСервера.
  ИнициализацияКомпоновщикаНастроек`, `КлючВарианта` его не заменяет). В «Все отчёты» у них
  команда «В избранное» доступна только на строке отчёта, на строках вариантов — недоступна
  с подсказкой; кнопки «В избранное» в их формах нет. Плитка без образа («Отчёт открывается
  по щелчку»), фоновое формирование их пропускает. Сужение требования «любой вариант» **принято владельцем
  2026-10-31** («Ярлык + TECHDEBT»); полноценные варианты в избранном для
  этих 12 отчётов — пункт TECHDEBT (доработка каждой формы под параметр
  `ИдентификаторИзбранного`). Признак —
  `Метаданные.Отчеты[Имя].ОсновнаяФорма = Метаданные.ОбщиеФормы.ФормаОтчёта`, вычисляется,
  а не хранится. Образ для своих форм — в TECHDEBT.
- Права: задание выполняется под тем же пользователем, без привилегированного режима —
  отчёт формируется с правами пользователя, ровно как при ручном открытии.

### 2.3. Форма `ВсеОтчеты`

- Дерево значений: **Раздел → Отчёт → Вариант**. Раздел — подсистема верхнего уровня,
  в состав которой входит отчёт (отчёт в нескольких разделах — в каждом); не входящие ни в
  один — раздел «Прочие».
- Отбор по правам: `ПравоДоступа("Просмотр", Метаданные.Отчеты[Имя])` и видимость по
  функциональным опциям (`ОбщегоНазначения`-проверка, если такая есть; иначе
  `ПолучитьФункциональнуюОпцию` по опциям из состава) — недоступное не показывается.
- У 12 отчётов со своими формами **варианты в дереве не показываются** (ревью плана, круг 5,
  P1): одна строка отчёта, «Открыть» — форма отчёта как из меню раздела, без `КлючВарианта`.
  Свои варианты внутри их форм работают штатно, как сейчас.
- Варианты остальных отчётов: предопределённые (из схемы) + пользовательские текущего пользователя
  (`ХранилищеВариантовОтчетов.ПолучитьСписок(ПолноеИмяОтчета)`), пометкой «мой».
  **Ключ объекта стандартного хранилища для вариантов проверяется на базе до реализации
  списка** (эксперимент: сохранить вариант в форме отчёта, прочитать `ПолучитьСписок` под
  разными ключами). Если ключ не `Отчет.<Имя>` — правим здесь.
- Строка поиска: по подстроке без учёта регистра в наименовании раздела, отчёта, варианта и
  описании отчёта (`Метаданные.Отчеты[Имя].Пояснение`); найденное раскрывается.
- Команды: «Открыть» (двойной щелчок), «В избранное» (вариант или отчёт — тогда вариант
  по умолчанию), «Удалить вариант» — только своего (`ХранилищеВариантовОтчетов.Удалить`),
  с вопросом.
- Пометка «★» у вариантов, уже лежащих в избранном.

### 2.4. «В избранное» из открытого отчёта

В общую форму `ФормаОтчёта` — команда «В избранное» в командную панель формы: берёт
`ПолноеИмяОтчета` (имя формы-владельца отчёта), `КлючТекущегоВарианта` (свойство расширения формы отчёта, модель 8.5.1; ревью плана, круг 7, P2), **полные текущие
`Отчет.КомпоновщикНастроек.Настройки`** и `ПользовательскиеНастройки`; наименование —
`Заголовок` формы (ревью плана, круг 2, P1: одних ключа варианта и пользовательских
настроек мало — изменённая в отчёте структура без сохранения варианта потерялась бы).

Обратная сторона — открытие из избранного. `ФормаОтчёта` получает обработчик
`ПриЗагрузкеВариантаНаСервере(Настройки)`: если в параметрах формы передан ключ избранного
(`ИдентификаторИзбранного`) **и он ещё не применён** — реквизит формы `ИзбранноеПрименено`
(Булево) ложь, ставится в истину сразу после загрузки (ревью плана, круг 3, P2: иначе
последующий выбор другого варианта пользователем подменялся бы избранным), — настройки берутся из записи (через `ИзбранныеОтчетыПолныеПрава`, только
своя запись) и грузятся `Отчет.КомпоновщикНастроек.ЗагрузитьНастройки`, затем
`ЗагрузитьПользовательскиеНастройки`. Фоновое формирование снимка грузит те же полные
`Настройки`, а не исходный вариант схемы; ключ варианта остаётся для заголовка и для случая,
когда `Настройки` пусты (добавлено из «Все отчёты» — тогда берётся вариант). Это
закрывает «настроить свой вариант и сохранить в избранное» для 53 отчётов. Для 12 отчётов со
своими формами — только из «Все отчёты»; доводка их форм — в TECHDEBT.

Сохранение пользовательских вариантов — **штатное** платформенное («Сохранить вариант…» в
меню «Ещё» формы отчёта), своего механизма не пишем.

## Отклонения при реализации (2026-10-31)

- Обработка названа **`КонсольОтчетов`**, а не `ПанельОтчетов`: так не путается с общим модулем
  `ПанельОтчетов`. Привилегированный модуль — **`ИзбранныеОтчетыПолныеПрава`** (сервер,
  привилегированный, без вызова сервера; имя — по правилу BSL LS для модулей полных прав).
- Действия плитки — гиперссылки-значки в шапке (⟳ ✎ ↑ ↓ ✕) с подсказками, а не контекстное меню.
- У общей формы отчёта **штатные команды вариантов отключены** (`excludedCommands`: `SaveVariant`,
  `LoadVariant`, `ChangeVariant`, `ReportSettings`) — так было до этой волны. Пользователь
  настраивает отчёт и сохраняет пользовательские настройки; кнопка «В избранное» снимает
  **полные настройки и пользовательские настройки** — это и есть «свой вариант в избранном».
  Список пользовательских вариантов в «Все отчёты» поэтому почти всегда пуст; эксперимент с
  ключом хранилища вариантов не понадобился для сдачи и не проводился. Включать штатные
  варианты — решение владельца (TECHDEBT).
