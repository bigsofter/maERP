# Окно печати у ролей и «Печать» в панели отмеченных строк — 2.0.17.26

Тикет 2605475 (Drissotex, приёмка 01.11): у оператора производства на закладках «Передача в переработку» и
«Поступления из переработки» рабочего места производства:

1. «Печать» нажимается и падает: «Недостаточно прав для просмотра».
2. После отметки строки флажком «Печать» пропадает из панели отмеченных строк, остаётся только в «⋮».

## Причина

**1 — права на окно печати.** Печать открывает `ОбщаяФорма.ПечатьДокументов` (`ПечатныеФормыКлиент.ВыполнитьКомандуПечати`).
Её завели 26.08 (2.0.12.9) вместо удалённой `ОбщаяФорма.ПредварительныйПросмотр`, а права в ролях остались на старом
имени: 12 ролей держат `CommonForm.ПредварительныйПросмотр` (View) — объекта нет, право висит. «Просмотр»
на `ПечатьДокументов` есть только у ролей с правами на новые объекты по умолчанию (Администратор, Руководитель).
Значит, окно печати не открывается ни у одной другой роли — у кладовщика, менеджеров, кассира, оператора
производства и т. д. Сборки 2.0.16.135/136 выдали права на команды печати (меню появилось), но окно они не открывают.

Воспроизведено вживую 2026-11-15: копия базы `build/ib-sf-live` → `build/ib-arm-print`, пользователь `op-test`
(только «Оператор производства»), запуск `/C "ОткрытьФорму;ОбщаяФорма.ПечатьДокументов"` — в журнале регистрации
`_$Access$_.AccessDenied`, право «Просмотр», объект `ОбщаяФорма.ПечатьДокументов`, ошибка «Недостаточно прав для
просмотра» (`НарушениеПравДоступа`). `ПравоДоступа("Просмотр", Метаданные.ОбщиеФормы.ПечатьДокументов, op-test)` = Ложь.

**2 — панель отмеченных строк.** Команды «Печать» таблиц рабочего места создаются кодом
(`РазместитьКомандыПечатиСтрок`) без «Использование выделенных строк» и «Используемая таблица». Клиент 8.5 в панели
отмеченных строк показывает только команды с `ИспользованиеВыделенныхСтрок = Использует` и связанной таблицей
(tiny1C forms-031). Статические команды той же панели («Статус», «Поступление из переработки») их имеют.

## Изменения

1. **Права ролей** (`src/cf/src/Roles/*/Rights.rights`):
   - у каждой роли вне `EXTERNAL_ROLES` (`scripts/rolecheck.py`: Клиент, ECommerce, ОбменМобильнаяДоставка), у которой
     есть «Просмотр» хотя бы одной команды печати документа, — `CommonForm.ПечатьДокументов` View = true. Это 10 ролей
     с прежним `ПредварительныйПросмотр` (ЛичныйКабинет, БухгалтерПоЗарплате, Казначей, Логист, МенеджерПоПродажам,
     ОператорПроизводства, Оператор, Кладовщик, МенеджерПоЗакупкам, PDV) и роли-допуски с командами печати
     (РедактированиеТабеляУчетаРабочегоВремени, РеализацииИзменениеПроведенных, СкладскиеОрдера,
     РедактированиеПоступлениеТоваровУслуг) — они работают в паре с базовой ролью, но проверка единая;
   - висячие записи `CommonForm.ПредварительныйПросмотр` удаляются из всех ролей (в т. ч. Клиент и ECommerce — им окно
     не выдаётся: печать внешних ролей — отдельное решение владельца, как в rolecheck).
   - Безопасность: окно только вызывает `ПечатныеФормы.СформироватьПечатныеФормы`, модуль менеджера `Печать`
     выполняется с правами пользователя (не привилегированно); запрет печати с ценами для роли без цен
     (`ПроверитьПечатьБезЦен`) остаётся на сервере. Новых данных роли не видят — только то, что уже читают.
2. **Рабочее место производства** (`DataProcessors/АРМПроизводство/Forms/Форма/Module.bsl`):
   - `РазместитьКомандыПечатиСтрок`: командам печати таблицы — `ИспользованиеВыделенныхСтрок =
     ИспользованиеВыделенныхСтрок.Использует`, `ИспользуемаяТаблица = Элементы[ИмяТаблицы]` (свойства проверены по модели
     типов 8.5.1: `FormCommand.SelectedRowsUse`/`AssociatedTable`, запись на сервере);
   - `Подключаемый_ПечатьДокументаСтроки`: печатаются документы отмеченных строк (записанные, нужного типа, без
     повторов) одним окном; нет отмеченных — как раньше, документ текущей строки.
3. **Проверки**: `scripts/rolecheck.py` — третья проверка: роль вне EXTERNAL_ROLES с командой печати без View на
   `CommonForm.ПечатьДокументов`; четвёртая — право в роли на `CommonForm.<Имя>`, которого нет в `CommonForms`.
   `ТестыДокументов`: сценарий `ОкноПечатиРолей` — `ПравоДоступа("Просмотр", ОбщаяФорма.ПечатьДокументов, Роль)` у
   каждой роли, видящей хоть одну команду печати документа (кроме внешних); `ПечатьПереработкиОператора` дополнен
   той же проверкой для оператора.
4. Версия 2.0.17.26 (2.0.17.25 занята планом commerce-two-orgs), «Что нового» ×4 языка, TESTING.md / TESTS.xlsx.

## Не входит

- Печать у внешних ролей (Клиент, ECommerce) — решение владельца, в TECHDEBT не новое.
- Живая проверка исправления вживую — повтор запуска под `op-test` на обновлённой копии, если хватит времени; иначе
  — сценарий тестов и rolecheck.

## Риски

- Роли получают окно печати впервые с 26.08: могут всплыть отказы чтения данных внутри конкретных печатных форм
  (фирменная печать читает подписантов организации). Это уже покрыто правилом EXTERNAL_ROLES и сценариями печати
  ролей; новые отказы будут видны пользователю сообщением, не порчей данных.

## По ревью плана (approve_with_changes, 2 × P2)

- Ревью кода (P2): отмеченные строки есть, подходящих нет — печать текущей строки не подменяет их, панель просит отметить записанные строки.
- Видимость пунктов «Печати» по-прежнему по виду документа текущей строки; отмеченные строки другого вида (в
  «Поступлениях», «Отгрузках», «Документах» виды смешаны) не печатаются молча — панель сообщает, сколько строк другого
  вида пропущено.
- Живая проверка исправления прав — обязательна: копия базы с новой конфигурацией, `op-test` открывает
  `ОбщаяФорма.ПечатьДокументов`, в журнале регистрации нет `AccessDenied`. Панель отмеченных строк и печать по
  отмеченным строкам headless не проверяются (нужны щелчки в окне клиента) — проверка владельца, так и сказано в сдаче.

## Найдено живой проверкой (2026-11-15)

После исправления окна печати повтор под `op-test` на копии с конфигурацией ветки: отказа на
`ОбщаяФорма.ПечатьДокументов` нет, но рабочее место производства при открытии падает «Нарушение прав доступа» —
`Обработка.АРМПроизводство.ВидТребованийДоступен` (2.0.16.144) читает `Константы.ИспользоватьАвтовыпускПриОтгрузке`,
а у роли «Оператор производства» нет права «Чтение» на неё (журнал: `_$Access$_.AccessDenied`, «Чтение»,
`Константа.ИспользоватьАвтовыпускПриОтгрузке`). Других ролей без прав по умолчанию с доступом к рабочему месту
производства нет. Исправление: право «Чтение» константы роли; проверка — в сценарии `ПечатьПереработкиОператора`.
