# Бриф: материалы в заказе клиента на производство (E5)

## Задача

Заказ клиента с видом операции «Производство» (E4) получает состав материалов: табличную часть
`ТЧМатериалы`, связанную со строками товаров, заполнение по действующим технологическим картам и
пересчёт при изменении количества продукции. Это данные, на которые опираются E6 (проведение и
регистрация техкарты заказа), E7 (потребности) и E9 (списание при автовыпуске). Сам E5 движений и
проведения не добавляет — только состав, его заполнение и форму.

Что появляется:

- **табличная часть `ЗаказПокупателя.ТЧМатериалы`** — колонки `КодСтроки` (`DefinedType.КодСтроки`),
  `КодСтрокиПродукции` (тот же тип — ссылка на `ТЧТовары.КодСтроки`), `Номенклатура`, `Характеристика`,
  `Упаковка`, `Количество`, `КоличествоНаЕдиницу`, `Комментарий`. Типы — по образцу
  `ТехнологическаяКарта.ТЧМатериалы` и `ВыпускПродукции.ТЧТовары` (`КоличествоЗаЕдиницу`); новые uuid
  (у drissotex и Rayssouni такой табличной части нет — проверить по `build/drissotex` перед созданием).
  В функциональной опции «Производство»;
- **реквизит `ТЧТовары.Техкарта`** (`DocumentRef.ТехнологическаяКарта`) — версия карты, по которой
  заполнены материалы строки. Колонка в форме скрыта, включается пользователем через «Ещё → Изменить
  форму». Регистрацию новой версии по составу заказа делает E6, в E5 колонка только заполняется;
- **таблица материалов на странице «Товары» формы документа под таблицей товаров**, видна только у
  заказа на производство (`Объект.ВидОперации = Производство`) и при опции «Производство»;
  переключение видимости при смене вида операции — без перезаписи документа;
- **отбор строк материалов по текущей строке товаров** — через `ОтборСтрок` таблицы по
  `КодСтрокиПродукции`, с переключателем «Все материалы / по строке» (по умолчанию — по строке);
- **команды «Заполнить по техкарте»** в командной панели таблицы материалов: для текущей строки
  товаров и для всех строк. Состав берётся `ТехнологическиеКарты.СоставТехкарт(Продукция, Объект.Дата)` —
  у неё есть продукция и регистратор, в отличие от `ЗаполнитьМатериалыПоТехкартам`, которая сводит
  материалы всех позиций в одну строку. Прежние материалы заполняемой строки заменяются;
  `Техкарта` строки товаров = регистратор; позиция без карты — сообщение, материалы строки пусты;
- **количество**: `КоличествоНаЕдиницу` из карты, `Количество = КоличествоНаЕдиницу × Количество
  продукции` (в единицах хранения, как в выпуске); `Упаковка` — только при опции «Использовать
  упаковку», как делает фасад (E1, 722618a);
- **пересчёт** материалов строки при изменении количества продукции; **очистка** материалов строки и
  `Техкарта` при смене номенклатуры продукции и при удалении строки товаров; новый `КодСтроки`
  продукции у скопированной строки получает копию её материалов;
- **заполнение при вводе на основании КП**: если заказ по КП получил «Производство» (E4), материалы
  заполняются по техкартам сразу — серверной процедурой объекта, общей с командой формы;
- **сценарий уровня 3 `МатериалыЗаказа`** в `ТестыДокументов` и строки в `docs/TESTING.md` и
  `docs/TESTS.xlsx`.

## Почему сейчас

E4 разделил заказы на продажи и производство. Без состава материалов E6 нечего проводить и
регистрировать как техкарту заказа, а E7 не из чего строить потребности. Порядок и основание —
`docs/plans/production-2mzl.md`, этап E5.

## Границы (чего НЕ делать)

- **Проведения и движений нет** — E6. Регистрацию техкарты по составу заказа и отказ при разных
  составах одной продукции — тоже E6.
- **Регистр потребностей, заказ поставщику «по потребности» — E7**; стадии — E8.
- **Справочник, техкарты и фасад не менять**, если без этого можно обойтись; если фасаду нужна новая
  функция — экспортная, с описанием, и в отчёте отдельной строкой.
- **Продажи не трогать**: у заказа «Продажа» материалов нет, таблица скрыта, поведение формы прежнее.
- **ECommerce-форму заказа не менять.**
- Попутно найденное — в `docs/TECHDEBT.md`, не в этот коммит.

## Уроки последних сборок — обязательны

- **Элементы Form.form копировать с работающего образца целиком**: `visible`, `enabled`,
  `userVisible`, `extendedTooltip` (tiny1C forms-012: без `<visible>` элемент скрыт, E3 дал пустой
  список заказов). После правки — скрипт-аудит новых элементов без `<visible>`.
- **У каждой новой колонки и команды — заголовки на ru/fr/en/es**; у колонки вычисляемого поля без
  реквизита — обязательно свой `<title>` (forms-013).
- **Запросы**: псевдоним таблицы не совпадает с именем поля соседней таблицы (query-003 — в E4 это
  сломало ввод заказа по КП); разыменование через точку заменять соединением осторожно.
- **Реквизиты формы и элементы — разные пространства id** (forms-001).
- **Видимость по функциональной опции — в `ПриСозданииНаСервере`**, не на клиенте (bsl-009).
- **Смок форму не рисует**: пустую или сломанную раскладку видит только владелец — в отчёте явный
  список «что посмотреть глазами».
- **Проверка на базе — сам**: копия `build/ib` (`cp build/ib/1Cv8.1CD build/ib-check/`), `scripts/smoke.sh`
  и `scripts/doctests.sh` на копии; шаг 1б смока ложно срабатывает (TECHDEBT 2026-09-13) — шаг 2
  запускать отдельно.
