# План: «Ввод по строке» во всех ролях (2.0.16.134)

Сообщение владельца (2026-11-01, Drissotex): у производственника в рабочем месте производства, закладка «Продукция»,
поле «Клиент» и поле «Продукция» не подбирают значение по набранному тексту. Выпадает только история выбора и
«Показать все». У администратора подбор работает.

## Причина

Роль «Оператор производства» даёт на `Catalog.Контрагенты` и `Catalog.Номенклатура` права `Read` и `View`, но не
`InputByString`. Платформа без этого права не ищет по строке, а в выпадающем списке показывает только историю выбора.
У администратора все права стоят по умолчанию (`setForNewObjects=true`), поэтому ошибка у него не воспроизводится.

Сверка по всем ролям показала, что правило «есть View — есть InputByString» нарушено массово: всего 265 пар (без объектов-исключений — 243)
«роль — объект», в 18 ролях. У оператора производства таких 22: Контрагенты, Номенклатура, Характеристики, Серии,
Упаковки, Места хранения, Организации и другие.

## Решение

1. В каждой роли, где права не стоят по умолчанию, у объектов ссылочных видов с `View=true` и без записи
   `InputByString` добавляется `InputByString=true`. Ссылочные виды: справочник, документ, ПВХ, план счетов, план обмена,
   бизнес-процесс, задача, ПВР. Запись вставляется сразу после `View`. Вставку делает скрипт, вручную ничего не правится.
2. Не трогаются:
   - роли со всеми правами по умолчанию: «Администратор» и «Руководитель»;
   - объекты, где у «Администратора» явно стоит `InputByString=false`: `ChartOfAccounts.Хозрасчетный` и ПВХ
     `ВидыНастроекПользователей`, `ВидыРеквизитовКонтрагентов`, `ВидыСубконтоХозрасчетные`. Это эталон, и другие роли
     его не расширяют: при совмещении ролей права складываются. В этой правке право на них не добавляется. Где оно уже
     было в HEAD (PDV, Клиент), его не трогаю: это отдельный вопрос, вне правки. Исключения rolecheck и сценарий
     берут из роли «Администратор», списка имён в них нет;
   - других исключений нет. Роль без своего права на клиент тоже проверяется: она работает в паре с другой, как
     «Складские ордера» с «Оператором производства». `ECommerce`, `MobileClient` и `ОбменМобильнаяДоставка`
     исправляются вместе со всеми.
   - явных `InputByString=false` в ролях без прав по умолчанию нет. Если такой запрет появится, rolecheck сочтёт его
     расхождением.
3. Новых прав на данные правка не даёт. Ввод по строке ищет только среди объектов, которые роль и так читает (`Read`)
   и видит (`View`). Ограничения на уровне записей (RLS) в конфигурации есть: у роли «Клиент» на Контрагентов —
   `Ссылка В(&Контрагенты)`, на договоры — `Контрагент В(&Контрагенты)`; у PDV — `Пользователь = &Пользователь`.
   Платформа выполняет ввод по строке запросом к данным с ограничениями права `Read`. Поэтому у «Клиента» подбор
   по строке находит только его контрагентов: те же записи, что он уже видит в форме выбора. Сценарий
   `ПравоДоступа` состав записей не проверяет, он проверяет только наличие права. Отдельная проверка RLS в эту
   правку не входит.
4. Защита от регресса:
   - `scripts/rolecheck.py` в `scripts/lint.sh`: View без InputByString, в том числе с явным `false`, валит линт;
   - сценарий `ВводПоСтрокеРолей` в `ТестыДокументов`: `ПравоДоступа("ВводПоСтроке", Объект, Роль)` по
     загруженной конфигурации, с тем же списком исключений, плюс отдельная проверка Контрагентов и Номенклатуры у
     оператора производства.

## Риски

- Справочник `Пользователи`, физлица и прочие объекты с `View` теперь подбираются по строке там, где роль их уже видит.
  Объём видимых данных не меняется.
- Структуры базы правка не меняет: это только права ролей.

## Проверка

- `scripts/lint.sh` (с rolecheck) и ноль новых замечаний BSL LS;
- `scripts/refcheck.py`;
- doctests на копии `build/ib-kp`, включая новый сценарий;
- оба поля из сообщения:
  - «Клиент» — стандартный ввод по строке справочника Контрагенты;
  - «Продукция» — стандартный ввод по строке Номенклатуры с параметром выбора `Отбор.ТипНоменклатуры`. Свой
    обработчик `Подключаемый_ПродукцияНоменклатураНачалоВыбора` срабатывает только на кнопку выбора, не на набор
    текста. `ОбработкаПолученияДанныхВыбора` менеджера без параметра `ПодменаАвтоподбора` отдаёт обработку платформе.
  Поэтому оба поля упираются в одно и то же право;
- живая проверка набора текста в обоих полях под пользователем «Оператор производства». Урезанная роль не открывает
  внешнюю обработку, поэтому проверить это можно только через интерфейс. Окно 1С активирую только с разрешения
  владельца. Без разрешения в отчёте прямо пишу, что живьём подбор не проверен и проверка остаётся за владельцем.
