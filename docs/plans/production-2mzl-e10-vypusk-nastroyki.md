# Бриф: самостоятельный выпуск и настройки (E10)

## Задача

Довести ручной («самостоятельный») выпуск продукции до чистого состояния после E1–E9 и закрыть развилку **Р10** в части
констант выпуска. Основание — `docs/plans/production-2mzl.md`, этап E10, и обязательства E9 (сдан в 2.0.15.22, проверен на
базе, отчёт `.ai/reports/production-2mzl-e9.md`).

Что уже сделано раньше и в E10 не переделывается:

- заполнение материалов ручного выпуска по техкарте идёт через фасад — `ФормаДокумента.ЗаполнитьТехкартуНаСервере` вызывает
  `ТехнологическиеКарты.ЗаполнитьМатериалыПоТехкартам` (E1); проверить, что других путей заполнения мимо фасада нет;
- константа «Автоматический выпуск при продаже» (`ИспользоватьВыпускПродукцииПриПродаже`) наполнена поведением и вынесена
  на форму настроек «Производство» (E9).

Что делается:

- **чистка формы ручного выпуска** `Documents/ВыпускПродукции/Forms/ФормаДокумента` — мёртвый код предка:
  - `РассчитатьДолиСтоимости` — тело целиком закомментировано, вызовы тоже;
  - `УстановитьЦенуНоменклатуры` — тело закомментировано, но процедура `&НаСервере` **вызывается в цикле по строкам**
    `ЗаполнитьТехкарту` и из `ТЧТоварыНоменклатураОбработкаВыбора`/`ПриИзменении` — пустой серверный вызов на строку;
  - `ВесСоответствуетИсходному`, `ПослеЗакрытияВопросаОНесоответствииВеса`, переменная `ЗакрытиеФормы`, закомментированное
    тело `ПередЗаписью` — «проверка веса» без вызовов;
  - закомментированные `РассчитатьДолиСтоимости()` в `ПриОткрытии`/`ПослеЗаписи`;
  - элементы формы `ТЧТоварыГруппаДоляСтоимости`/`ТЧТоварыДоляСтоимостиПроцент` (путь данных на реквизит, которого у
    `ТЧТовары` нет) — сверить с `.mdo` и EDT, убрать мёртвые; колонку «Цена» — решение 3;
- **удаление константы** `ИспользоватьУпрощенныйВыпускГП` («Упрощённый выпуск ГП», код её не читает — TECHDEBT «Константы,
  которые не читает ни одна строка кода»): `.mdo`, `Configuration.mdo`, право `Read` у роли `Кладовщик`
  (`Roles/Кладовщик/Rights.rights`), упоминания в документах — по решению 1;
- **бухгалтерские проводки выпуска**: процедура `Хозрасчетный.ДвижениеВыпускПродукции` готова, но диспетчер
  `РегистрыБухгалтерии.Хозрасчетный.СформироватьДвижения` целиком закомментирован — развилка **Р1**, в E10 только запись в
  `docs/TECHDEBT.md` и `docs/ROADMAP.md` (блок 3), код не трогается;
- **хвосты E9 про ручной выпуск** (TECHDEBT «Найдено в E9»): `ТехнологическиеКарты.ЕстьВыпускиПослеДаты` при смене карты
  советует «перезаполнить выпуски» и для автовыпусков, которые вручную не правятся, — исключить автовыпуски из совета (или
  сказать о них отдельно) по решению 4;
- **Р10**: в `docs/ROADMAP.md` закрыть в части двух констант выпуска; остальные четыре (`ДатаДемоРежима`,
  `ИспользоватьСинхронизацию`, `ЕдиницаИзмеренияДлины`, `ЕдиницаИзмеренияОбъема`) — по решению 2;
- сценарий уровня 3 — дополнить `ВыпускПродукции` (или новый `РучнойВыпуск`): заполнение по техкарте через фасад на дату
  документа, мультивыпуск, `ЕстьВыпускиПослеДаты` без автовыпусков; строки в `docs/TESTING.md`, `docs/TESTS.xlsx`.

## Почему сейчас

E9 закрыл автоматический путь выпуска; ручной остаётся рабочим путём для заказов без автовыпуска и для производства на
склад. E11 (демо-данные контура) и E12 (АРМ производства) опираются на чистую форму ручного выпуска и на закрытую Р10:
демо-набор не должен показывать переключатели, которые ничего не делают, а АРМ — вести в форму с пустыми серверными вызовами.

## Границы (чего НЕ делать)

- **Проводки выпуска** (`Хозрасчетный`) не подключать и диспетчер не раскомментировать — развилка Р1.
- **Механизм проведения выпуска** (`ТоварыВНаличии.СписатьНоменклатуру`, `РаспределитьСебестоимостьНаПродукцию`, веса
  техкарт) и автовыпуск E9 (`CommonModules/Производство`) не менять.
- **Табличную часть техкарты в справочнике номенклатуры не удалять** (обязательство волны: отдельный поздний релиз).
- Константу `ИспользоватьВыпускПродукцииПриПродаже` не трогать — E9.
- Раскладку формы по `docs/FORMS-STYLE.md` не переделывать: только мёртвые элементы; состав живых полей и их порядок — как есть.
- Uuid существующих объектов не менять. Попутно найденное — в `docs/TECHDEBT.md`, не в этот коммит.

## Уроки последних сборок — обязательны

- **Удаление объекта метаданных — реструктуризация**: полное обновление `build/ib` владельцем (урок E4), права ролей на
  удаляемый объект убрать в том же коммите, иначе EDT не загрузит конфигурацию; сверить `refcheck` (строковые имена
  констант) и поиск по `scripts/`, `docs/hub/`, начальному заполнению.
- **Совместимость с drissotex (E13)**: константа есть в составе подсистемы «Производство» базы клиента
  (`docs/drissotex-analysis/production.md`) — при слиянии объект с другим uuid; удаление у нас не должно сломать перенос
  данных клиента (значение константы клиента теряется — оно ни на что не влияло).
- **Имена переменных** — не имена свойств глобального контекста и общих модулей (tiny1C `bsl-011`, E9: `Документы`,
  `Производство`); линтер гонять по всей конфигурации, а не только по изменённым модулям.
- **Формы:** удаляя элемент `Form.form`, удалить и его обработчики в `<handlers>` и в модуле (forms-004); элементы без
  `<visible>true</visible>` скрыты — не путать «мёртвый» и «скрытый намеренно»; дифф всей `Form.form` (workflow-009);
  `listcheck.py`.
- **Переменная модуля объекта с именем реквизита** — это реквизит (bsl-010); псевдонимы запросов не ключевые слова (query-001).
- **Проверка на базе — сам**, после полного обновления владельцем: копия `build/ib`, `scripts/doctests.sh` и
  `scripts/smoke.sh` на копии; шаг 1б смока ложно срабатывает — сверять с нормализацией BOM/Unicode, шаг 2 отдельно.
  Исправления по прогону можно проверить до следующего обновления частичной загрузкой модуля в копию
  (`/LoadConfigFromFiles -files` + `/UpdateDBCfg`), `build/ib` не трогая.
- **Выпуск по техкарте у заказа на производство** срабатывает только для непроведённого заказа (E6 + умолчания E2) — в
  сценарии ручного выпуска на это не опираться.
- **Оркестрация:** обязательные гейты — Codex; пока нет доступа к основному аккаунту — модель Codex через OpenCode
  (`opencode/gpt-6-astra`), промпт с запретом выходить за репозиторий, `TINY1C_HOME` на копию правил внутри `.ai/state`
  (грабли E9); ревью данных и безопасности — дополнительно субагенты Claude.

## Порядок работы

Изменение **существенное** (удаление объекта метаданных, реструктуризация, права роли) — порядок по `.ai/README.md`:
исследование → план → `architecture-critic` → **`ai-review-plan`** → реализация → lint/refcheck/listcheck → `ai-test` →
**`ai-review`** → **`ai-database`** (удаление константы, данные клиентов) → **`ai-security`** (права роли) →
`ai-review --verify` → `ai-final-check` → прогон на копии обновлённой базы → отчёт `.ai/reports/production-2mzl-e10.md`.

## Вопросы владельцу

1. **Константа «Упрощённый выпуск ГП».** Удалить объект метаданных (реструктуризация при обновлении, значение в базах
   клиентов теряется — ни на что не влияло) или оставить с префиксом «Удалить…» до E13? Предлагается — удалить: план волны
   так и говорит, код её не читает с 2.0.14.19.
2. **Остальные четыре константы Р10** (`ДатаДемоРежима`, `ИспользоватьСинхронизацию`, `ЕдиницаИзмеренияДлины`,
   `ЕдиницаИзмеренияОбъема`). Закрыть в E10 заодно (удалить) или оставить Р10 открытой в их части? Предлагается — оставить:
   они не про производство, E10 закрывает Р10 только в части выпуска.
3. **Колонка «Цена» в материалах ручного выпуска.** Цена заполнялась из плановых цен закупки (код закомментирован), при
   проведении не используется — себестоимость берётся из партий. Убрать колонку с формы или оставить для ручного ввода
   справочно? Предлагается — оставить колонку, убрать только пустой вызов `УстановитьЦенуНоменклатуры`.
4. **Совет «перезаполнить выпуски» при смене техкарты.** Не учитывать автовыпуски вовсе или показывать отдельной строкой
   «перепроведите реализации»? Предлагается — не учитывать: автовыпуск перезаполняется перепроведением реализации, а
   карта дня регистрируется проведением заказа.
5. **Размер этапа.** Одной сборкой (этап S) — предлагается одной.
