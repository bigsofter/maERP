## Открытые вопросы владельцу — задать ДО плана

1. **Где живут строки.** а) **новая нижняя закладка «Поступления из переработки»** рядом с «Переработкой» —
   своя таблица, как у выпусков и отгрузок (рекомендация); б) строки поступлений внутри закладки
   «Переработка» под своими передачами — дерево на форме, где сейчас плоская таблица.
2. **Что такое строка.** Рекомендация: строка = строка **продукции** поступления (`ТЧГотоваяПродукция`):
   передача-основание (переработчик и склад берутся из неё), продукция, характеристика, количество, процент
   потерь (подставляется из карты, правится). **Сырьё в рабочем месте не показывается и не правится** — оно
   пересчитывается сервером по строкам продукции (`ЗаполнитьСырье`). Кому нужно поправить сырьё руками —
   открывает документ. Подтвердить или назвать, что ещё нужно видеть в строке.
3. **Стоимость услуг переработчика.** Это шапка документа (`СтоимостьУслуг`), не строка. Варианты: а) не
   вводится в рабочем месте — только в документе (рекомендация: поступление без услуг проводится, если есть
   сырьё); б) колонка при включённых суммах (`ПоказыватьСуммы`) — но она общая на документ, и правка в одной
   строке меняет итог всех строк.
4. **Правка строки у поступления, сырьё которого правили руками** (п. 5 состояния). Варианты: а) **строка
   рабочего места всегда пересчитывает сырьё документа** — ручная правка сырья затирается, пользователь
   предупреждён в подсказке; б) **заводить реквизит документа «сырьё правилось вручную»** и запрещать правку
   строки такого документа в рабочем месте с текстом «откройте документ» — это новый реквизит (реструктуризация)
   и правка формы документа; в) запрещать правку строк проведённого поступления в рабочем месте вообще
   (только новые строки и удаление непроведённых). Рекомендация — б, если ручная правка сырья бывает на деле;
   иначе а.
5. **Кнопка `ПереработкиСоздатьПоступление`.** Оставить как есть (открывает документ — путь для ручного
   сырья) или заменить переходом на новую закладку с новой строкой по отмеченной передаче. Рекомендация —
   оставить и добавить рядом переход.
6. **Генератор формы.** а) S6 правит `Form.form` руками и пишет в README, что отставание выросло до трёх
   сборок (рекомендация — дёшево, риск откатки уже записан); б) S6 начинается с `gen8.py`, догоняющего
   генератор до формы (способ изготовления, дерево материалов), и новая закладка — уже в `gen8.py`.

## Ловушки, каждую проверить чтением кода до правки

1. **Form.form — самая большая форма конфигурации.** Правка точечно по имени элемента (`workflow-009`),
   `git diff -w` по всей форме: посторонние блоки = откат чужой правки. У каждого нового элемента
   `<visible>true</visible>` (память проекта: без него закладка пустая, смок не ловит) и объявленные
   `<handlers>`. Свой диапазон id для реквизитов и элементов формы (`forms-001`).
2. **Кнопка внутри таблицы на закладке и `userSettingsGroup` роняют клиента 8.5** (`forms-008`, `forms-009`) —
   команды строк держать в панели отмеченных строк, как у существующих закладок.
3. **Поле в `ТекущиеДанные` — только через видимую колонку** (`forms-011`).
4. **Генератор** (п. 6 состояния): не запускать `gen7.py` поверх формы.
5. **Проведение поступления — деньги**: себестоимость принятого, списание сырья у переработчика, порог
   дочистки. Новый путь проведения обязан давать те же движения, что форма документа: сверить сценарием
   движения поступления, введённого строкой, с поступлением, введённым через документ на тех же данных.
6. **Блокировки**: порядок поступления `ТоварыВНаличии` → `ТоварыВПереработке` развёрнут в S4-B; правка строки
   существующего поступления под транзакцией — по образцу зависимых документов `ЗаписатьСтрокуДокумента`
   (`:955-968`: отказ фиксирует пустую транзакцию, откат вложенной испортил бы внешнюю).
7. **Повторное проведение того же экземпляра удваивает движения** (`bsl-018`, у поступления починено в S5-A) —
   строка рабочего места перепроводит документ: проверить сценарием остаток у переработчика после двух
   правок одной строки.
8. **«ё» в новых именах не использовать** (`YoLetterUsage`); `git add -u` + `git show --stat` для путей с «ё»
   (`workflow-007`).
9. **Headless**: `ib-sync.sh`, по одному тяжёлому процессу, не параллелить с субагентами. `build/ib` может
   держать EDT владельца — тогда копия базы (см. п. 1 состояния). Исключение экспорта «External property
   manager … is not active» — транзиентное, повторить.

## Сценарии уровня 3

Расширить `АРМПереработка` (новых сценариев не заводить):
- новая строка поступления по проведённой передаче → проведённый документ, основание — передача, продукция и
  процент потерь из строки, сырьё посчитано сервером; «Выпущено» и стадия заказа;
- **движения поступления строкой совпадают с поступлением через документ** на тех же данных (себестоимость,
  списание у переработчика);
- правка количества строки → сырьё пересчитано, остаток у переработчика не задвоен (ловушка 7);
- вторая строка в тот же документ; устаревшая версия — отказ с перечитыванием;
- запреты: непроведённая передача, продукция не из ожидаемой, количество сверх ожидаемого, чужой заказ;
- удаление строк — документ без строк помечен на удаление;
- поведение по ответу 4 (ручное сырьё);
- права: `Кладовщик` — строка записывается, но документ не проводится (или запрет — по ответу).
Один отказ проведения на сценарий, и он последний (`docs/TESTING.md`, п. 3).
