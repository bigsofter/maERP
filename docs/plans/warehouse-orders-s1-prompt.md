# Промпт: ордерные склады — фаза 1 (2.0.16.76): количественный регистр ТоварыНаСкладах без видимых изменений

Реализуем фазу 1 проекта `docs/plans/warehouse-orders.md` (maERP, 1С 8.5.1, EDT-проект `src/cf`, ветка `develop`).
План одобрен Codex на редакции 20 (коммит 9eb8342). Последняя сборка — 2.0.16.75 (фирменная печать, фаза 7); эта —
**2.0.16.76**. Содержание — строка 1 таблицы «Фазы»: рядом с `ТоварыВНаличии` (партии и стоимость) появляется
количественный регистр `ТоварыНаСкладах`, его заполняет зеркало, история переносится копией, физические читатели
(место A) переключаются на него. **Ордерных складов, ордеров и `ТоварыКОформлению` в этой фазе нет.** Для пользователя
ничего не меняется: на неордерном складе регистры равны, и инвариант равенства — главная проверка фазы.

Главный риск — **данные клиентов**: обработчик обновления переписывает историю склада в новый регистр на каждой
базе, а ошибка зеркала тихо разведёт физический остаток с партиями. Новый регистр, обработчик обновления, права
ролей, блокировки → **существенная правка: план фазы и `ai-review-plan` обязательны**, `ai-database` обязателен,
`ai-security` — права ролей.

Часы — клиент **Drissotex**: `~/Downloads/Drissotex — Ордерные склады (фаза 1).xlsx` (лист «Отчёт», колонки Подзадача

## Шаг 1. Реализация

(`УстановитьЗаписьВсехРегистров`, `КорректировкаРегистров`) → блокировки → минимальный остаток → обработчик →
переключение мест A → права. После каждого блока — `git grep` по именам и `refcheck.py`.

## Шаг 2. Тесты (`ТестыДокументов`, реестр)

- **Инвариант**: после каждого существующего сценария, двигающего склад, остатки `ТоварыНаСкладах` = остатки
  `ТоварыВНаличии`, свёрнутые по физическим измерениям, — общей проверкой-помощником, а не копией в каждом сценарии.
- Отдельно: требование-накладная в обоих режимах (перемещение сохранено / набор очищен); `Замещение = Ложь`;
  неактивные движения (`КорректировкаРегистров` с выключенной активностью — регистр физики её тоже не видит);
  отмена проведения — оба набора пусты; реализация комплекта — физика по составляющим; зеркало поступления в
  `ПодчиненныйСклад`.
- Обработчик: на копии базы — повторный запуск даёт тот же результат; инвариант на каждую дату (выборочно по
  месяцам) и на текущий момент.
- Минимальный остаток: оповещение приходит один раз (не дважды) при списании ниже минимума.
- Переключённые места A: те же значения, что до фазы (снимок до/после на `build/ib-kp` — в отчёт).
- Тест 13599 — зелёный, и понятно почему.
- `docs/TESTING.md` («Проверка 2.0.16.76»), строки `docs/TESTS.xlsx`.

## Уроки прошлых сборок (учесть сразу)

- Модель типов платформы 8.5.1 (свойства, события, перечисления) — по jar EDT в `~/.p2`, не угадывать.
- `<handlers>` в `Form.form` обязателен; элемент без `<visible>true</visible>` скрыт; шрифт шапки у каждой колонки
  (`colfont.py`); смок не ловит ни пустую форму, ни неверный источник количества — проверка значений своя.
- Агент final-validator правит файлы вопреки «read-only» — сверять `git diff` после каждого прогона.
- Гонка выгрузки EDT («feature with code "type"», «без родительского объекта») — повторить полное обновление; во
  время экспорта `src/cf` не трогать.
- `ib-sync.sh` / `doctests.sh` / `smoke.sh` — через `bash -c`; rc=141 без строк и rc=134 JVM EDT — повтор; итог
  тестов — `ИТОГ;Сценариев=…`, отчёт перечитывать после завершения; отчёты 1С — CRLF и BOM (`tr -d '\r'`); на одной
  базе не запускать внешние обработки во время синхронизации.
- Отрицательные остатки не запрещают проведение (решение владельца): находки ревью «можно уйти в минус» по
  `ТоварыНаСкладах` снимать со ссылкой на правило, контроль остатков по новому регистру не добавлять.
- Пути с «ё» в git — только NFC; `sort`/`uniq` по кириллице — только `LC_ALL=C`; зависшие процессы 1С снимать по
  PID, а не `pkill` по шаблону.
- В роли `Rights.rights` до сих пор висят права на удалённую `CommonForm.ПредварительныйПросмотр` (12 предупреждений
  при загрузке XML) — не путать с ошибками фазы; чистка — отдельной правкой, если владелец скажет.
