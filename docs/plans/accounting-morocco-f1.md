# Бухгалтерский контур Марокко, Ф1 — налоговый учёт документов (детальный план)

Генеральный план — `docs/plans/accounting-morocco.md`, раздел «Решения владельца по налоговым документам» (три
круга решений 2026-10-18). Здесь — раскладка Ф1 по объектам и сборкам. Опись мест записи и чтения регистров —
исследование 2026-10-18 (ниже по разделам).

## Главное правило измерения `УУ`

- `УУ` (Булево) — новое измерение регистров накопления `ТоварыВНаличии`, `ВзаиморасчётыСПокупателями`,
  `ВзаиморасчётыСПоставщиками`, `ДенежныеСредстваОрганизаций`, `ДвиженияДенежныхСредств`, `Продажи`.
  Истина — только управленческое («чёрное») движение, Ложь — белое. Старые записи после реструктуризации — Ложь
  (белые), переписывания нет.
- **В документе хранится тот же признак `УУ`** (Булево, Ложь = налоговый), а в форме показывается флажок
  «Налоговый» = `Не УУ` (реквизит формы и обработчик изменения). Новый реквизит у всех существующих документов
  получает Ложь, то есть «налоговый», — так же, как их движения; массового переписывания документов нет.
- **Пишут** все движения с `УУ` документа (у документов без реквизита и при выключенной опции `РаздельныйУчет` —
  Ложь).
- **Внутренние операции без флажка** (перемещение, пересортица, производство, переработка, требования, обычная
  комплектация) пишут обе стороны с `УУ = Ложь`. Это свойство модели, а не ошибка: белый учёт не ведётся по складам
  (решение 3), белые итоги по организации перемещение не меняет; производство из сырья, купленного в чёрную, даёт
  белый выпуск и **отрицательный белый остаток сырья** — это и есть потребность в белых закупках (С3). Белый
  остаток в разрезе склада поэтому не показатель; отчёты «Учёт = налоговый» по товарам — без разреза склада по
  умолчанию. Осознанное превращение чёрного товара в белый — `НалоговаяКомплектация`.
- **Деньги — по виду денежных средств каждого движения, а не по виду документа**: безналичные движения — всегда
  `УУ = Ложь`; наличные — по признаку документа. Инкассация (`ПоступлениеБезналичныхДенежныхСредств`, операция
  «Инкассация», расход кассы с типом Cash в `ДенежныеСредстваОрганизаций.ПараметрыДвиженийДокумента`): у
  документа появляется флажок «Налоговый» только для этой операции — он задаёт признак расходуемой наличности
  (из какой кассы ушли деньги), банковская часть белая.
- **Читают** операционные места (проверка и отказ по остатку, списание партий `СписатьНоменклатуру`,
  себестоимость, распределение оплат, панели, рабочие места производства и закупок, дашборды) — **без отбора и без
  группировки по `УУ`**: физическая картина. Белый остаток партии и чёрный расход той же партии в сумме дают
  реальный остаток. Каждое такое место проверяется, что оно не группирует по всем измерениям регистра
  (`Выгрузить` без явного состава полей, `СгруппироватьПо` по всем измерениям): иначе одна партия разойдётся на
  две строки.
- **Белая картина** (`УУ = Ложь`) нужна только отчётам с параметром «Учёт = налоговый», АРМ бухгалтера и, на
  уровнях 2–3, отражению в бухучёте.
- Белый остаток товара может быть отрицательным (белая продажа раньше белой покупки) — отказа по нему нет:
  отказ по остатку проверяет только физическую картину, как сейчас.

- Умолчания пользователя — `НастройкиПользователей`, образец `РаботаСДокументами` (стр. 15, склад по умолчанию).
- Нумерация восьми документов — строка 11, периодичность «год», `checkUnique`, префикс организации в подписке
  `ПриУстановкеНовогоНомера`.

## Сборки

### С1 — измерение, флажок и запись признака

- Опция `РаздельныйУчет` (константа, функциональная опция, настройки «Бухгалтерия», мастер первого запуска;
  серверная проверка: выключение запрещено при записях `УУ = Истина` в любом из шести регистров).
- Реквизит `Налоговый` (Булево) у `РеализацияТоваровУслуг`, `ПоступлениеТоваровУслуг`, `ВозвратОтПокупателя`,
  `ВозвратПоставщику`, `ПриходныйКассовыйОрдер`, `РасходныйКассовыйОрдер`, `СписаниеТоваров` (списание по
  бухучёту), `ПоступлениеБезналичныхДенежныхСредств` (только операция «Инкассация») — реквизит `УУ`, в формах
  флажок «Налоговый» под опцией; при выключенной опции флажок скрыт, `УУ = Ложь`. Умолчание при создании —
  `НастройкиПользователей` «Налоговый по умолчанию» (Истина, если не задано).
- Измерение `УУ` в шести регистрах; все писатели передают признак документа (`СформироватьДвижения` по ветке
  документа, `Движение` денежных регистров — по виду документа: безналичные Ложь, кассовые — по флажку).
- Ревизия 26 мест чтения остатков и запросов взаиморасчётов, денег, продаж: подтвердить, что читают без `УУ` и не
  группируют по всем измерениям (список с результатом — в отчёте сборки).
- `СкладНалоговый` (отказ по складу без признака «Налоговый учёт») к новым флажковым документам не применяется:
  налоговость задаёт документ, а не склад (решение 3).
- РМК: флажок у чека (по умолчанию из настроек пользователя), деньги чека — касса с тем же признаком.
- Сценарии `ТестыДокументов`: белая и чёрная продажа одной партии — физический остаток верен, белый остаток
  расходится; отказ по остатку — по физическому; банк всегда белый; касса по флажку; выключение опции при чёрных
  движениях — отказ; реструктуризация не меняет старые остатки.
- Размер L. Гейты: `ai-review-plan` этого раздела, `ai-database` (реструктуризация шести регистров с данными,
  замер обновления на копии базы 2MZL), смок и тесты на копии.

### С2 — налоговый документ на основании и списки

- Табличная часть `Основания` у реализации и поступления (основание, строка основания, количество покрытия);
  подбор неналоговых документов того же контрагента и организации; заполнение товаров по основаниям с правкой.
- **Отдельная ветка жизненного цикла** документа на основании (непустая табличная часть `Основания`): он не
  оформляет складские ордера (`ПроверитьОформление`, `СформироватьДвиженияОформления`, `ТоварыКОформлению` не
  вызываются — товар уже отгружен основаниями), не списывает партии заново, не пишет зеркало.
- Переклассификация (генеральный план, решения второго круга п. 3): реализация — приход `УУ = Истина`, расход
  `УУ = Ложь` по покрытым количествам с партиями оснований; поступление — наоборот; `Продажи` — построчно.
- Возвраты по налоговой реализации на основании и по её основаниям: `Продажи.УменьшитьПрибыльПоВозврату` (читает
  все записи регистратора и сопоставляет по товару и партии) — отбор по `УУ` возвращаемого документа и
  исключение парных записей переклассификации; сценарий возврата обоих видов.
- Расчёты — два действия, как в нынешнем `СформироватьПоНалоговойНакладной`: перенос долга
  (`ДолгПоОтгрузкам`, построчно, разница цен отдельной суммой налогового долга) и перенос **уже распределённых
  оплат** оснований (`ОплатыПоОтгрузкам`, `ОплатыВалютныхОтгрузок`) в признак `УУ = Ложь`. Сопровождение будущих
  оплат оснований — подписка оплат в С2 **дополняется** новыми документами на основании, старые налоговые
  накладные она обслуживает по-прежнему до С5.
  - Подписка собирает основания **и до, и после** изменения платежа: прежние основания запоминаются в
    `ПередЗаписью` (`ДополнительныеСвойства`) — перенос или удаление распределения обновляет налоговые документы
    прежнего основания.
  - Перепроведение зависимых налоговых документов — в транзакции платежа, без подавления исключения: ошибка
    перепроведения отменяет запись платежа с текстом пользователю (сейчас подписка глушит ошибку и пишет только
    журнал — для новых документов так нельзя, для старых поведение не меняется до С5).
- Покрытие основания — под исключительной блокировкой оснований; одна действующая налоговая реализация на строку
  основания.
- **Защита оснований с момента покрытия**, а не выдачи: основание, покрытое проведённым налоговым документом,
  нельзя распровести, удалить, пометить и изменить в покрытых строках и в реквизитах шапки, от которых зависят
  движения (`УУ`, организация, контрагент, договор, склад, дата, валюта и курс) (`ПередЗаписью`,
  `ОбработкаУдаленияПроведения`, `ПередУдалением` реализации и поступления; проверка под блокировкой). Сначала
  распроводится или исправляется налоговый документ (до выдачи) либо Avoir-аннулирование (после выдачи, Ф2).
- Списки: закладки «Управленческие» и «Налоговые», колонки связи, «Создать налоговый документ» из отмеченных.
- Сценарии: покрытие частичное и полное, повторное покрытие — отказ, переклассификация не меняет физический
  остаток, разные цены — разница отдельной суммой.
- Размер L.

### С3 — отчёты УУ/БУ, АРМ бухгалтера, списание по бухучёту

- Параметр «Учёт» (фактический / налоговый) в отчётах по остаткам, долгам, деньгам, продажам, закупкам.
- АРМ бухгалтера (первая версия): неналоговые без налогового, потребность в белых поступлениях по датам,
  поставщики для запроса налоговой накладной, расхождения белого и управленческого остатка со списанием по
  бухучёту, белая и чёрная касса, налоговые долги.
- **Списание по бухучёту** — вид операции `СписаниеТоваров` «Списание по бухучёту»: товар физически уже ушёл
  (продан в чёрную), поэтому документ **не списывает партии и не уменьшает физический остаток** — это
  переклассификация расход `УУ = Ложь` / приход `УУ = Истина` по выбранным количествам (из отчёта расхождений), без
  `Убытки` управленческого учёта; на уровнях 2–3 — расход в бухучёте (недостача). Обычное списание (бой, порча)
  — как сейчас, с признаком документа.
- Опция `НалоговаяКомплектация`: комплектация с флажком — расход управленческого товара (`УУ = Истина`
  компоненты), приход налогового набора.
- Размер L.

### С4 — нумерация

- Регистр сведений `НастройкиНумерации` (вид документа, вид операции, серия налоговый/неналоговый, организация —
  необязательно; префикс, год в номере, перенумерация при смене операции), начальное заполнение префиксов.
- Собственный нумератор (регистр счётчиков: серия, организация, год; исключительная блокировка), снятие
  `checkUnique` у восьми документов, номер в документе без префикса, на печать — `Префикс-Год-Номер`.
- `НомерФактуры`/`ДатаФактуры` — серия фактур организации, присваивается при выдаче (Ф2, выдача — при первой
  печати).
- Существующие номера не меняются; счётчики начального года — от максимального существующего номера серии.
- Размер M.

### С5 — переход существующих баз и старые налоговые документы

- Обработчик обновления (генеральный план, решения второго круга п. 5 и круги ревью 10–11): классификация
  реализаций и поступлений, генерация налоговых документов на основании из старых накладных с другим составом,
  ценами, НДС или датой, перенос налоговых возвратов, перенос долгов из отдельных налоговых регистров в
  измерение, деньги (банк белый, кассовые по правилу В8), **замена всех входящих ссылок** на старые документы,
  включение `РаздельныйУчет` в базах со старыми налоговыми документами.
- **Движения старых налоговых документов в общих регистрах** (`ВзаиморасчётыСПокупателями`,
  `ВзаиморасчётыСПоставщиками`, деньги, `ТоварыВНаличии` до 2.0.16.1) снимаются: старый документ распроводится
  в режиме перехода (его движения во всех регистрах удаляются), а его эффект — перенос долга и оплат — заново
  формирует сгенерированный документ на основании или флажок основания; итоги взаиморасчётов, денег и товаров по
  контрагентам до и после перехода сверяются обработчиком (расхождение — откат перехода базы с текстом).
- Префикс `Удалить` у четырёх документов, двух регистров, подсистемы и команд; подписка оплат больше не
  обслуживает старые документы; печать, отчёты и тесты — на новые документы.
- Обработчик идемпотентен; повтор на копии базы 2MZL ничего не меняет. Отчёт перехода в журнал регистрации:
  сколько реализаций налоговые, неналоговые, сколько сгенерировано налоговых документов, какие ссылки заменены.
- Удаление объектов `Удалить…` — следующий релиз, отдельным планом (CFU только из версий после перехода).
- Размер L. Гейты: `ai-database` и проверка обновления на копии базы 2MZL с замером времени.

## Порядок

С1 → С2 → С3; С4 параллельно С2–С3; С5 последней, но до включения раздельного учёта у клиентов с налоговыми
накладными: до С5 опция `РаздельныйУчет` в таких базах не включается (новые флажки ничего не ломают — старые
налоговые накладные работают как сейчас). Каждая сборка — версия `2.0.16.Y`, «Что нового» на четырёх языках, хаб,
статья базы знаний к концу Ф1 (Ф6).

## Ревью плана

Круг 1 (Codex, 2026-10-18, reject, 6): реквизит документа `УУ` с флажком «Налоговый» в форме (старые документы —
налоговые без переписывания), признак денег по виду средств каждого движения и флажок инкассации, отдельная ветка
документа на основании без складских ордеров, перенос распределённых оплат и подписка оплат в С2, защита оснований
с момента покрытия, списание по бухучёту как переклассификация без физического расхода — приняты.
Круг 2 (reject, 7): подписка оплат дополняется (старые накладные до С5), прежние основания платежа, атомарность
перепроведения, снятие движений старых документов при переходе со сверкой итогов, возвраты и парные записи,
защита реквизитов шапки — приняты; внутренние операции без флажка пишут белое — записано как свойство модели
(решение 3), а не исправлено; **подтверждено владельцем 2026-10-18**.
