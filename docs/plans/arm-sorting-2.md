# Сортировка рабочих мест, сборка 2: оплаты, документы, документы заказа (тикет 2605527, 2.0.17.33)

Продолжение `docs/plans/arm-sorting.md` (2.0.17.32). Решение владельца 17.11: таблицы, которые только показывают
данные, переводятся на динамические списки, чтобы сортировка работала щелчком по заголовку. Для трёх таблиц со сложным
расчётом — «Переписать на запросы». «Делай следующие сборки» — 17.11. В 2.0.17.32 эти таблицы сортируются своей
сортировкой (команды меню, вариант A). В этой сборке они переходят на динамические списки (вариант B), команды
меню у них снимаются.

Объём:

| Форма | Таблица | Сейчас |
|---|---|---|
| АРМЗакупки | `Оплаты` | `ТаблицаЗначений` из `ЗапросОплат` → `ТекстЗапросаПлатежей` (ВТПлатежи) |
| АРМЗакупки | `Документы` | `ТаблицаЗначений` из `ТекстЗапросаДокументов` (ВТНакладные, ВТПлатежи); «Вид», «Статус» — в коде |
| АРМПроизводство | `ДокументыЗаказа` | `ТаблицаЗначений` из `ДокументыЗаказа(Заказ)`: объединение частей по правам, дедупликация `Найти`, движение `ЗаполнитьДвижениеДокументов` вторым запросом, строки «+N/−N», подвал |

`ИсточникиТовара` — следующая сборка, свой план (пакет потребности из 15+ ВТ и поправка дефицита переработчика в коде).

## Поиск готового

- Общее устройство динсписка рабочего места, заглушки по правам, `ПараметрыСтатусаДокумента`,
  `ТекстЗаглушкиСписка`, `НастроитьДинамическиеСписки`, генерация `Form.form` (скрипт сборки 2.0.17.32) — берутся
  как есть.
- Цвет движения — уже условным оформлением (`УстановитьЦветДвижения`); туда же добавляется формат «+».

## 1. Закупки: `Оплаты`

Новая экспортная `ТекстСпискаОплат()` — один запрос без ВТ, параметр `&Заказ`:

```
ВЫБРАТЬ Касса.Регистратор КАК Документ, Касса.Период КАК Дата, Касса.ДокументПродажи КАК Основание,
	СУММА(ВЫБОР КОГДА ТипДвижения = Поступление ТОГДА -СуммаОборот ИНАЧЕ СуммаОборот КОНЕЦ) КАК Сумма
ИЗ РегистрНакопления.ДвиженияПоКассе.Обороты(, , Регистратор, ДокументПродажи В (<ОбъектыОплат>)) КАК Касса
СГРУППИРОВАТЬ ПО Касса.Регистратор, Касса.Период, Касса.ДокументПродажи
```

`<ОбъектыОплат>` — то же множество, что ВТОбъектыОплат: проведённые поступления заказа (`Основание = &Заказ И
Проведен`) плюс проведённые налоговые накладные покупки, у которых в `ТЧТовары` или `ТЧУслуги` есть строка с таким
поступлением (соединением, без разыменования). Группировка нужна, чтобы ключ (`Документ`, `Основание`) был уникален:
сейчас строка одна на регистратор, основание и тип движения.

Ключ — `Документ, Основание`. «Использовать всегда» — `Документ`, `Основание` (`ОткрытьДокументСтроки`).

## 2. Закупки: `Документы`

Новая экспортная `ТекстСпискаДокументов()` — объединение частей `ТекстЗапросаДокументов` с теми же условиями.
`ВТНакладные` заменяется подзапросом накладных из п. 1, `ВТПлатежи` — подзапросом регистраторов
`ДвиженияПоКассе.Обороты` с тем же условием. Добавляются поля:
- `Вид` — у каждой части свой параметр (`&ВидЗаказПоставщику`, `&ВидПоступлениеТоваровУслуг`, …). Значения —
  `Метаданные.Документы.<Имя>.Синоним`, как сейчас в коде. Функция `ПараметрыВидовДокументов()` отдаёт их по
  списку имён частей.
- `Статус` — `ВЫБОР` по `ПометкаУдаления`/`Проведен` с параметрами `ПараметрыСтатусаДокумента()`.

Документ входит в цепочку одной частью: у каждой части свой тип документа. Ключ — `Документ`.

## 3. Закупки: общее

- `ТекстЗапросаПлатежей` и `ТекстЗапросаДокументов` удаляются. `ДанныеЗаказа` выполняет `ТекстСпискаОплат` и
  `ТекстСпискаДокументов` с `УПОРЯДОЧИТЬ ПО Дата`, параметры — `ПараметрыСпискаЗаказа(Заказ)` (Заказ, виды, статусы).
  Колонки результата прежние, плюс `Вид` и `Статус` из запроса; цикл дозаполнения «Вид/Статус» у `Документы`
  снимается. Тесты `ПроверитьДанныеЗаказаРабочегоМеста` (2 платежа, документы цепочки) сверяют новый текст со старым
  поведением.
- `ЗапросОплат` (кружки оплаты `ОплатыЗаказов`, сальдо) не меняется. `ТекстыЗапросовОплат` возвращает новые тексты
  вместо удалённых: сценарий сверки `ОбъектыОплат` с текстами остаётся.
- Без `ОплатыДоступны()` текст обоих списков — заглушка (`ТекстЗаглушкиСписка("Оплаты"/"Документы")`, те же поля и
  типы). Закладки и сейчас скрыты. Режим приёмки — то же самое, оплаты и сейчас не читаются.
- Форма: реквизиты `Оплаты`, `Документы` → `DynamicList` (тот же скрипт, что в 2.0.17.32). `Form.form` хранит полный
  текст, код ставит текст из менеджера в `НастроитьДинамическиеСписки`. Ключи — там же. `ListSettings.dcss`:
  порядок `Дата` по возрастанию (сейчас `УПОРЯДОЧИТЬ ПО Дата`).
- `ЗагрузитьДанныеЗаказа`: вместо `Загрузить` — параметр `Заказ` обоих списков (пустая ссылка без заказа) и
  `Обновить()`. «Оплаты»/«Документы» убираются из `КлючиТекущихСтрок` и `ПрименитьПорядок`.
- Кнопки «Сортировать по возрастанию/убыванию» из контекстного меню `Оплаты`, `Документы` снимаются. У
  динсписка сортировка — стандартная, по щелчку.
- Колонки сумм скрываются, как сейчас (`НастроитьВидимостьДенегИПриемки`): невидимую колонку динсписок не читает.

## 4. Производство: `ДокументыЗаказа`

Новая экспортная `ТекстСпискаДокументовЗаказа()` на тех же частях, что `ТекстЗапросаДокументовЗаказа` (по правам,
первый и второй уровень, автовыпуски, ордера):

```
ВЫБРАТЬ РАЗРЕШЕННЫЕ Д.Документ, Д.Вид, Д.Номер, Д.Дата, Д.Контрагент, Д.Через, Д.Сумма,
	<Статус по Проведен/ПометкаУдаления> + ВЫБОР КОГДА Д.Автовыпуск = 1 ТОГДА &ПометкаАвтовыпуска ИНАЧЕ "" КОНЕЦ КАК Статус,
	ВЫБОР КОГДА Д.Проведен И НЕ Д.ПометкаУдаления ТОГДА ЕСТЬNULL(Д2.ПродукцияЧисло, 0) ИНАЧЕ 0 КОНЕЦ КАК ПродукцияЧисло,
	… МатериалыЧисло
ИЗ (ВЫБРАТЬ Ч.Документ, МАКСИМУМ(Ч.Через) КАК Через, МАКСИМУМ(Ч.Автовыпуск) КАК Автовыпуск, <остальные поля в группировке>
	ИЗ (<части объединения>) КАК Ч СГРУППИРОВАТЬ ПО …) КАК Д
	ЛЕВОЕ СОЕДИНЕНИЕ (ВЫБРАТЬ М.Документ, СУММА(М.ПродукцияЧисло), СУММА(М.МатериалыЧисло)
		ИЗ (<части движения>) КАК М СГРУППИРОВАТЬ ПО М.Документ) КАК Д2
	ПО Д.Документ = Д2.Документ
```

- **Дедупликация** — группировкой по документу вместо `Найти`. Ключ динсписка `Документ` обязан быть уникален.
  «Через» и «Автовыпуск» — `МАКСИМУМ`, `Автовыпуск` — число 1/0. Сейчас дубль даёт первое попавшееся «Через».
- **Вид** — параметр на часть (`&Вид<Имя>`, `Метаданные.Документы[Имя].Представление()`, как сейчас).
- **Сумма** — `ВЫБОР КОГДА &СуммыВидны ТОГДА Т.Сумма ИНАЧЕ 0 КОНЕЦ`, как сейчас: при `ПоказыватьСуммы() = Ложь`
  форма получает нули, а не только скрытую колонку.
- **Движение** — части по `ПарыДвиженияДокументов()` (права те же). Вместо `Т.Ссылка В (&Документы)` —
  `Т.Ссылка В (ВЫБРАТЬ Д.Ссылка ИЗ Документ.<Имя> КАК Д ГДЕ <условия всех частей этого типа документа>)`. Условие
  ордера и услуги — как в `ТекстЗапросаДвиженияДокументов`. Знак и колонка (`ПродукцияЧисло`/`МатериалыЧисло`) —
  константы части. Проведён и не помечен — `ВЫБОР` во внешнем запросе, как сейчас (движение только у
  проведённых непомеченных).
- Части документов и движения строятся одной функцией по описанию частей (тип, основание, условие с псевдонимом),
  чтобы условие типа в движении было тем же, что в списке.
- `ДокументыЗаказа(Заказ)` (подвал, подсказка индикатора, тесты) выполняет этот же текст с `УПОРЯДОЧИТЬ ПО Дата`.
  Колонки прежние, строковые `Продукция`/`Материалы` снимаются (их читала только форма). `ДобавитьДокументЗаказа`,
  `ЗаполнитьДвижениеДокументов`, `ТекстЗапросаДвиженияДокументов`, `ТекстЗапросаДокументовЗаказа`,
  `ПредставлениеДвижения` удаляются, если вне них не используются.
- Нет ни одной части (нет прав ни на один тип) — текст-заглушка с теми же полями.
- Форма: реквизит `ДокументыЗаказа` → `DynamicList`. Колонки «Продукция», «Материалы» — на `ПродукцияЧисло`,
  `МатериалыЧисло`, имена элементов прежние. Условное оформление `УстановитьЦветДвижения`: у прихода к цвету
  добавляется `Формат` = `ЧФ='+Ч'; ЧГ=0`, у расхода — `ЧГ=0`. Нулевое движение — пустая ячейка (`ЧН=`) форматом
  колонки. Отбор оформления — по полю списка `ДокументыЗаказа.ПродукцияЧисло` (у динсписка путь тот же).
  Сортировка по колонке — числовая.
- `ЗагрузитьДанныеЗаказа`: параметры `Заказ`, `СуммыВидны`, виды, статусы — в `ПриСозданииНаСервере` (пустой заказ).
  При смене заказа меняется `Заказ`, затем `Обновить()`. Курсор держит ключ, `КлючТекущейСтроки` и
  `ВернутьТекущуюСтроку` для этой таблицы снимаются. `ПрименитьПорядок` и кнопки меню снимаются.
- Подвал (`ОбновитьИтогиДвижения`) и счётчик закладки «Документы (N)» считаются по `Данные.Документы` — той же
  функции, тем же текстом. Счётчик — новый числовой реквизит `КоличествоДокументовЗаказа`.
  `ОбновитьЗаголовкиЗакладок` берёт его вместо `Количество()` у этой страницы.
- `ДокументыЗаказаВыбор` читает `ТекущиеДанные.Документ` — `Документ` в «использовать всегда».
- `ListSettings.dcss`: порядок `Дата` по возрастанию (как `Результат.Сортировать("Дата")`).

## Проверки

- `ТестыДокументов`:
  - существующие сценарии движения документов заказа (`ПродукцияЧисло`, `МатериалыЧисло`, автовыпуск, ордера) и
    данных заказа закупок проходят на новом тексте — это сверка со старым расчётом;
  - новый сценарий `СпискиДокументовЗаказа` выполняет `ТекстСписка…` трёх списков обычным запросом с параметрами
    формы на заказах базы (до 20 заказов каждого вида):
    - каждое поле колонок и «использовать всегда» есть в результате;
    - `Документ` (у оплат — `Документ`+`Основание`) уникален;
    - строки и суммы совпадают с `ДанныеЗаказа`/`ДокументыЗаказа`;
    - заглушки без прав имеют те же поля.
  - Строка в `docs/TESTS.xlsx`.
- Разовая сверка на копии базы до удаления старых функций: старый `ДокументыЗаказа` и старые
  `Оплаты`/`Документы` против новых на всех заказах базы — число строк, документы, движение, суммы. Расхождения —
  разбираются до сдачи.
- `scripts/lint.sh`, `refcheck.py`, `listcheck.py`, `colfont.py`, `queryfields.py`; смок форм и тесты документов на
  `build/ib-kp`.
- Ручная проверка владельцем: щелчок по заголовку «Оплат», «Документов» закупок и «Документов» заказа в
  производстве; «+» и цвет движения; подвал и счётчик закладки после смены заказа.

## Риски

- Подзапрос в параметре виртуальной таблицы `Обороты` внутри динсписка. Обычный запрос это допускает, сценарий
  выполняет текст. Динсписок проверяется на клиенте. Если платформа откажет — физическая таблица регистра с
  `Активность` и группировкой.
- Формат «+» условным оформлением в таблице динсписка — проверка на клиенте. Запасной вариант — число без «+», знак
  только у расхода, цвет как сейчас.
- Производительность: части движения повторяют условия частей документов (до 10 подзапросов по одному заказу).
  Условия те же, что сейчас выполняются двумя запросами; индексы по `Основание` те же.
- Два запроса на смену заказа в производстве: список и `ДокументыЗаказа` (подвал, индикатор) — так же, как сейчас
  (сейчас один, но с дозапросом движения).

## Правки по ревью плана (17.11, субагент Claude architecture-critic — Codex в лимите до 18.11)

Отчёт: `.ai/reviews/arm-sorting-2/02-plan-review-claude.md`. Вердикт REVISE (одна P1), второй круг не требовался.
Принято:

- **P1-1.** Параметр `&ЕстьЗаказ` во всех частях трёх текстов, в частях движения, в объектах оплат и в отборе
  виртуальной таблицы `ДвиженияПоКассе.Обороты`. Без заказа список пуст и таблицы не читаются: условия
  `Основание = &Заказ` с пустой ссылкой совпали бы с документами без основания. Сценарий проверяет пустой список.
- **P2-1.** Список «Документы» производства перечитывается (`Обновить()`) при каждом `ОбновитьТекущийЗаказНаСервере`,
  и при том же заказе тоже.
- **P2-2.** Одна часть движения на пару «документ — табличная часть». Условие `В (…)` объединяет через ИЛИ условия всех
  частей этого типа, поэтому дубль `ПоступлениеИзПереработки` не удваивает количество. «Через» пусто, если документ
  найден и первым уровнем: `ВЫБОР КОГДА МАКСИМУМ(ПервыйУровень) = 1`. Так же работал прежний выбор первой найденной
  строки.
- **P2-3.** «Оплаты» группируются по `Регистратор, ДокументПродажи`, дата — `МАКСИМУМ(Период)`. Накладные в
  «Документах» отбираются через `В (подзапрос)`.
- **P2-4.** Платежи в «Документах» — одной частью: обороты кассы читаются один раз, документ платежа — левым
  соединением с четырьмя видами. Форма вызывает `ДанныеЗаказа(Заказ, , Ложь)`, тексты списков не выполняются
  дважды. Индекс `ДокументПродажи` — пункт TECHDEBT (реструктуризация, отдельной сборкой).
- **P3-1.** `ТекстЗаглушкиСписка` — явная ветка на каждое имя, на неизвестное имя — исключение.
- **P3-2.** `ТекстыЗапросовОплат` отдаёт полные тексты независимо от прав (`ПолныйТекстСписка…`).
- **P3-5.** «Через» — `ВЫРАЗИТЬ(Т.Основание КАК Документ.<Основание>)`.
- **P3-6.** Сверка со старым расчётом сделана разово, до удаления старых функций. Выгрузка на копии базы по всем
  заказам — 13 заказов клиентов, 7 заказов поставщику; номера сравнивались после `СокрЛП`. Результат совпал
  построчно: документы, «Через», статус, вид, сумма, движение. Оплат в копии базы нет: их сверяют сценарии
  `РабочееМестоЗакупок` (два платежа, доля накладной) и `АРМПроизводство` (движение, автовыпуск).
- **P3-7.** Временный сценарий выгрузки удалён до коммита.
- **P3-8.** Формат прихода `ЧФ='+Ч'; ЧГ=0` задан в условном оформлении, у колонки — `ЧН=; ЧГ=0`.

Не принято:

- **P3-3** — подзапрос объектов оплат для `ЗапросОплат`. Пакет кружков оплаты не меняется, общий подзапрос — только у
  двух списков.
- **P3-4** — обнуление сумм оплат в режиме приёмки. Поведение то же, что в 2.0.17.32: колонки сумм скрыты по
  `СуммыВидны`, закладки — по `ОплатыДоступны`.
