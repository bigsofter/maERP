## Задача

Распространить механизм автовыпуска на `ПередачаВПереработку`: полуфабрикат, который отдают
переработчику, выпускается автоматически по своей технологической карте, списывая листья её состава.

Объём и решения — в плане, разделы B.1–B.7. Здесь только то, что ломается тише всего.

## Четыре P1 Codex — это и есть содержание сборки

Разбор целиком — `.ai/reviews/production-subcontracting-s4/02-plan-review-codex.md`, сырые находки —
`02-plan-review.json`.

**P1-1. Остаток самого полуфабриката обязан участвовать в расчёте.** Прежняя арифметика считала «потребность
минус ранее выпущенное по этому заказу», то есть читала документы выпуска; `ОстаткиМатериалов` (`:1499`)
читает только материалы автовыпуска. Остаток ПФ, попавший на склад иначе, не учитывался — а сценарий
требует «ПФ есть на складе → автовыпуска нет» и «частичный остаток → выпускается разница». Считать
доступный остаток на складе передачи по характеристике и серии **под блокировкой**, исключая собственные
движения при перепроведении.

**P1-2. Баланс у отгрузки и у передачи — общий.** Два независимых баланса выдают один свободный ручной
выпуск дважды. Прежнее возражение «номенклатура ПФ и ГП разная» **неверно**: план сам разрешает передачу
готовой продукции переработчику и заказ самого ПФ строкой товаров. Сопоставлять по номенклатуре,
характеристике **и серии**, исключая текущий комплект документов.

**P1-3. Запрет ручного выпуска расширить на основание-передачу.** `ПроверитьПравкуАвтовыпуска` (`:268`)
сегодня держится на признаке и основании-реализации. Отсутствие `basedOn` и ограничение выбора на форме —
это интерфейс, а не объектный инвариант, а поиск автовыпусков идёт только по основанию: дыра ведёт прямо
к дублю.

**P1-4. Расход материалов ПФ связать с ключами обеспечения верхнего уровня.** `ПотребностьЗаказаКлиента`
пишет листья под `Продукция` из `ТЧТовары` заказа, а `РаспределитьМатериалы` (`:1367`) формирует
`ИзОстатка` только при `ПоЗаказу` и переносит `Продукция` прямо из нормы. Нормы карты ПФ такой связи не
содержат — движения потребностей легли бы не под те ключи, и `ДефицитЗаказа` поехал бы.

## Ловушки, названные ранними кругами разбора

1. **Собственный автовыпуск передачи не должен попадать в «выпущено ранее».** Путь реализации защищён
   двумя барьерами (`ВыпущеноИОтгруженоРанее`, `:1078`); у передачи оба исчезают: основание автовыпуска —
   эта же передача, а его дата на секунду раньше. Без исключения `Основание <> &Передача` перепроведение
   любой передачи с автовыпуском ломается **со стопроцентной вероятностью**: к выпуску выходит ноль,
   выпуск распроводится и помечается на удаление, передача отказывает по нехватке.
2. **`ПроизводственныеЗаказы.ЗаказОснованияДокумента` (`Module.bsl:370`)** для выпуска разворачивает
   только реализацию. С основанием-передачей вернёт саму передачу, она молча отсеется, и стадии заказа по
   ПФ-автовыпуску не пересчитаются. Образец ветки — `ПоступлениеИзПереработки` в той же функции.
3. **`ПередачаВПереработку.ЗаполнитьПоВыпускуПродукции` (`ObjectModule.bsl:95`)** уже переведена на признак
   в сборке A, но при расширении типа основания её ветку перепроверить: `basedOn` у передачи содержит
   `ВыпускПродукции`, а её `Основание` типизирован только заказом.
4. **У `ПередачаВПереработку` нет ни одного вызова `ПроизводственныеЗаказы.*`** — единственный документ
   контура без них. Без `ЗапомнитьЗаказыДокумента` вызов `ОтменитьПроведениеДокумента`
   (`ПроизводственныеЗаказы/Module.bsl:76`) возвращается сразу, и отмена проведения пойдёт порядком,
   запрещённым уроком E8.
5. **Встречная пара блокировок — не реализация, а поступление.**
   `ПоступлениеИзПереработки.ЗаполнитьБлокировкуПроведения` (`ObjectModule.bsl:48`) берёт
   `ТоварыВПереработке` → `ТоварыВНаличии`, то есть в обратном порядке к передаче. Инверсия есть уже
   сегодня, но сборка B кратно расширяет элемент `ТоварыВНаличии` передачи. Именной вопрос в `ai-database`.
6. **Литерал `ЧИСЛО(15, 3)` в запросе — только как образец подстановки.**
   `ТехнологическиеКарты.ТекстСПриведениемКоличества` (`:752`) **требует** его наличия в тексте и иначе
   бросает исключение; готовый запрос обязан пройти через неё.
7. **`ИмяСвойстваЗаписи()` (`:402`) возвращает `"ЗаписьАвтовыпускаРеализации"`** — после обобщения имя врёт.

## Уроки прошлой сборки, которые дешевле не повторять

- **`ЗначениеЗаполнено` к Булеву неприменима**: на `Ложь` она отвечает `Истина`. Правило tiny1C `bsl-017`.
  Замечание линтера `CompareWithBoolean` на `= Истина` — **не повод** менять конструкцию на другую по
  семантике. Читать булево из запроса через `Производство.ЭтоИстина` (`:1644`).
- **`Структура.Свойство()` при отсутствии ключа присваивает `Неопределено`**, а не оставляет переменную
  прежней.
- **Шаг сценария с настоящим отказом проведения — последний**: отказ отравляет транзакцию, и следующий
  запрос падает с «в этой транзакции уже были ошибки», а виновным выглядит не тот шаг. Регламент —
  `docs/TESTING.md`, п. 3. Новый шаг дописывать **перед** отказом.
- **Статика и смок эти три ошибки не ловят.** Уровни 1–3 прогонять до сдачи, а не после.

## Что этап НЕ делает

Порядок обеспечения из трёх ступеней (S9) — **кроме** остатка передаваемой позиции, который вносит P1-1;
отбор списания из переработки по заказу, процент и порог потерь, себестоимость по новой базе (S5);
переименование константы (S8); закладка поступлений и подборы номенклатуры (S6, S7).

**Главное ограничение, которое пишется владельцу первой строкой отчёта:** цепочка «передали ПФ → получили
обратно → отгрузили ГП» полностью заработает только с S9. Автовыпуск при отгрузке разворачивает состав до
листьев, и после того как ПФ выпущен и передан, его сырья на складе уже нет. S4-B чинит только вход в эту
цепочку.

## Открытые вопросы владельцу

1. **Сценарий `НастройкиПрограммы` падает по часовому поясу окружения** и держит `doctests.sh` красным
   независимо от работы. Чинить список часовых поясов (UTC в нём нет), чинить сценарий или оставить как
   есть и разбирать построчно каждый раз.

   лишь частично: ручной выпуск по-прежнему заполняется одноуровневым `ЗаполнитьМатериалыПоТехкартам`.
   Сводить его с автовыпуском в этой сборке или отдельной задачей.
