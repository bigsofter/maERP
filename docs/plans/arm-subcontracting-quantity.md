# АРМ производства: количество ПФ/ГП в передаче, штатные стрелки, легенда, выбор без «Показать все»

Сборка 2.0.16.17. Замечания владельца 2026-10-06 по скриншоту 2.0.16.16. Решения владельца в тот же день:
количество ПФ/ГП подставляется **по норме заказа и правится**; при нескольких материалах под один ПФ/ГП ожидается
по самому дефицитному; разрядку шрифта заголовков владелец проверяет повторным полным обновлением базы (в коде шрифты
не менялись: `NormalTextFont = Arial` из 2.0.15.53 на месте, в выгрузке EDT есть).

## 1. Штатные стрелки под списком заказов

У таблицы `Заказы` (динамический список) нет явных дополнений `searchStringAddition`, `viewStatusAddition`,
`searchControlAddition` — у форм списков документов они есть, и там `viewStatusLocation=None` убирает штатную
навигацию (2.0.15.62). Добавляю дополнения по образцу `ЗаказПокупателя.ФормаСписка` (фрагмент генератора `gen11`).
Если и после этого стрелки останутся — это прокрутка самой таблицы 8.5, проверяется глазами у владельца.

## 2. Легенда в одну строку

Короче, без слова «Кружки»: «заказ матер. · приход матер. · выпуск · отгрузка · оплата: ○ нет ◐ частично ● да»
на четырёх языках (`ПроизводственныеЗаказы.ЛегендаИндикатораСтрокой`).

## 3. Выбор в колонках «Материал» и «ПФ/ГП» сразу из отобранного

Выпадающий список «Введите строку для поиска / Показать все» — это кнопка выпадающего списка поля ввода по строке; наш
отбор открывает только «Показать все» (событие НачалоВыбора). У колонок `ЗаказыПоставщикуМатериал`,
`ПоступленияМатериал`, `ПереработкиМатериал`, `ПереработкиПродукция` и `ТЧТоварыПродукция` формы передачи —
`dropListButton=false`, `choiceButton=true`: кнопка выбора сразу открывает отобранные значения. Ввод по строке остаётся.

## 4. Количество ПФ/ГП в передаче

- **Метаданные:** `Документ.ПередачаВПереработку.ТЧТовары.КоличествоПродукции` — число по определяемому типу
  количества (как `Количество`), необязательное, базовые единицы ПФ/ГП. Реструктуризация — новая колонка, у старых
  строк 0 (= прежнее правило).
- **Норма:** `Документы.ПередачаВПереработку.КоличествоПродукцииПоНорме(Заказ, Материал, Характеристика, Количество,
  Продукция)` — доля строки по дереву заказа (`ПродукцияПоДеревуЗаказа` по одной строке, строки P); у плоского заказа —
  0 (нормы нет, вводит пользователь). Подставляется при выборе ПФ/ГП и при смене материала или его количества в строке;
  после этого правится.
- **Ожидаемая продукция по P** (`ОжидаемаяПродукцияПередачи`, ветка указанных ПФ/ГП): если у строк P есть
  `КоличествоПродукции > 0` — итог P = минимум по материалам строк P из суммы `КоличествоПродукции` строк этого
  материала (строки с нулём материал не ограничивают); строки P по прежнему правилу (характеристики, упаковка)
  масштабируются под этот итог; нет таких строк — одна строка P с характеристикой пустой и упаковкой = единица.
  Все `КоличествоПродукции = 0` — как в 2.0.16.16.
- **АРМ:** колонка `Переработки.КоличествоПродукции`, порядок колонок закладки: Материал, Кол-во, Упак., Характ.,
  ПФ/ГП, Кол-во ПФ/ГП, … (замечание владельца). Ключ данных строки `КоличествоПродукции` (тип проверяется), запись в
  `ПрименитьДанныеСтрокиПередачи`, чтение в `ТекстЗапросаСтрокПередач`, сравнение «строка не изменилась», запрет
  отрицательного. Подстановка нормы — клиент после выбора ПФ/ГП и смены количества.
- **Форма документа передачи:** колонки «ПФ/ГП» и «Кол-во ПФ/ГП» после «Количества» материала, количество материала —
  после материала (перестановка элементов таблицы `ТЧТовары`); подстановка нормы там же.
- Смена `КоличествоПродукции` после поступления — запрет, как у `Продукция` (`ПроверитьСменуПродукцииПриПоступлениях`).

## Гейт плана — принятые правки (architecture-critic, Codex в лимите)

approve_with_changes. Внесено в реализацию:
- в правило минимума идут только строки с материалом и `Количество > 0` (удаляемая строка не считается); ключ
  материала — номенклатура + характеристика;
- норма не затирает ручное значение: при выборе ПФ/ГП ставится всегда (если > 0), при смене материала или его
  количества — только если количество ПФ/ГП пустое; очистка ПФ/ГП обнуляет его количество;
- запрета менять количество ПФ/ГП после поступления нет (оно не ломает сопоставление по номенклатуре; поступление и так
  режет остатком заказа);
- реквизит — `DefinedType.КоличествоНеотрицательное` **без** проверки заполнения;
- норма делит переданный материал на суммарную потребность всех узлов этого ПФ/ГП (крой под A и под B не удваивается);
- строка «без строк по правилу» берёт характеристику и упаковку ПФ/ГП из первого вхождения в дереве или товарах заказа;
- масштабирование: защита от нуля, остаток на последнюю строку, `КоличествоУпаковок` тем же коэффициентом;
- `ТЗТовары` без колонки `КоличествоПродукции` — прежняя ветка;
- норма считается на сервере (в АРМ — в записи строки и отдельной функцией для формы), вызывается и после выбора из
  списка; у колонки формы документа — обработчик OnChange;
- у таблицы `Заказы` вместе с дополнениями — `searchControlLocation=None`.
Явное количество больше заказанного — разрешено, поступление режет остатком заказа (сказать владельцу).
