## Открытые вопросы владельцу — задать ДО плана

1. **Нужна ли константа порога потерь после S5-B.** Варианты:
   а) **не нужна** — порог по проценту карты остаётся единственным правилом, пункт волны закрыть; S8
   сводится к константе автовыпуска;
   б) **константа как значение по умолчанию**, когда процент потерь в карте пуст: закрывает дыру «без
   процента в карте дочистки нет», не меняет документы, где процент задан;
   в) **константа как исходное правило третьей итерации** — «остаток / переданное по заказу < порога → в
   списание» — вторым условием поверх процента карты. Два правила дочистки сразу: нужно решить, какое
   сильнее, и это меняет суммы уже сданного S5-B.
   Рекомендация — а или б; в — только если владелец видит случай, который процент карты не покрывает.
2. **Переименовывать ли ИМЯ константы или только её название.** Пользователь видит синоним; имя
   `ИспользоватьВыпускПродукцииПриПродаже` видно только в коде. Варианты:
   а) **только синоним и подсказка** — ноль риска, комментарий `Производство/Module.bsl:512` переписать;
   б) **и имя** (например, `ИспользоватьАвтовыпускПриОтгрузке`) — uuid сохраняется, значение в базах
   клиентов не теряется, но правка идёт по пяти модулям, правам роли, тестам, `docs/`, и **её ловит только
   CheckConfig** (ловушка 3). Рекомендация — а.
3. **Текст названия.** План волны: «Автоматическое создание выпусков при отгрузке», в подсказке —
   «отгрузка — это и расходные накладные, и передачи в переработку». Подтвердить формулировку и дать
   добро на переводы fr/en/es (предложить их в плане, а не придумывать молча).

## Ловушки, каждую проверить чтением до правки

1. **Форму правим точечно по имени элемента**, а не перегенерацией (`workflow-009`), смотрим `git diff -w`.
   У нового элемента формы обязательны `<visible>true</visible>` и `<handlers>` (память проекта: без
   `visible` элемент скрыт, смок это не ловит).
2. **Синоним — это заголовок элемента формы**: своего `<title>` у элемента нет. После правки открыть форму
   настроек глазами (скриншот развёрнутого окна — для базы знаний tinycio, по закладке).
3. **Переименование имени ловит только CheckConfig** (`workflow-011`): ни линтер, ни `refcheck.py` строки
   `Константы.<Имя>` внутри модулей и имя в `Блокировка.Добавить("Константа.<Имя>")` (`ТестовыеДанные:155`)
   не видят. Grep по всему `src/cf` и `scripts/`, затем `ib-sync.sh` и CheckConfig.
4. **Новая константа — новый объект метаданных**: регламент «существенная правка» — план →
   `ai-review-plan` обязателен → реализация → `ai-review` обязателен. Права: роль, проводящая поступление из
   переработки, обязана читать константу (или чтение — в привилегированном режиме, тогда обязателен
   `ai-security`). Значение по умолчанию обязано сохранять поведение S5-B.
5. **Порог меняет деньги поступления из переработки** (варианты 1б, 1в): именной вопрос `ai-database` —
   что происходит с себестоимостью уже проведённых поступлений при перепроведении.
6. **«ё» в новых именах не использовать** (`YoLetterUsage`). `git add -u` для путей с «ё», после коммита —
   `git show --stat` (`workflow-007`).
7. **Headless EDT**: `scripts/ib-sync.sh`, по одному тяжёлому процессу за раз, не параллелить с
   субагентами. Экспорт с исключением «External property manager … is not active» — транзиентный, повторить.
