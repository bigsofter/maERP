# Закладка «Товары» в списке расходных накладных (тикет 2605528, сборка 2.0.17.35)

## Задача

Клиент (2MZL): в списке документов продаж хочется сразу видеть товарный состав, не открывая документ и не щёлкая
по строкам правой панели. Решение владельца 18.11 (вместо колонки-описания из тикета): **отдельная закладка
«Товары» в списке расходных накладных**, по аналогии с рабочими местами производства и закупок. На ней
работают со строками товаров прямо в таблице — создают, печатают, ищут; расходные накладные формируются
автоматически. Кто привык к документам — работает на первой закладке; кому нужно больше полей — открывает
документ двойным щелчком. Поля — минимально необходимые из расходной накладной. Кнопка печати обязательна.

Редакция 2 — по кругу 1 `ai-review-plan` (reject: 2×P0, 2×P1, 2×P2): документы с услугами, доп. расходами и
авансами не правятся; пометка последней строки — по праву интерактивной пометки на перечитанном объекте; правки
строк одного документа из очереди пишутся пакетом; колонка валюты; тест отката проведения — отказом внутри
проведения.

Редакция 3 — по кругу 2 (reject: 3×P1, 2×P2): упаковка восстанавливается после заполнения данных номенклатуры и цена
считается `УстановитьЦенуНоменклатуры` с ней; налоговая накладная проверяется узкой привилегированной функцией
независимо от права её чтения; валюта новой строки — валюта выбранного документа; отказ пакета (не конфликт) не
теряет правки; тест отката — правкой документа в закрытом периоде.

Редакция 4 — по кругу 3 (reject: 2×P1, 2×P2): пустой вид цен документа — вид цен по умолчанию клиента и склада для
новой строки; закрытие формы и печать не теряют и не обходят незаписанные правки; тест права пометки — две ветки.

Редакция 5 — по кругу 4 (reject: 2×P1, P2): удаление строк документа с незаписанными правками запрещено до их
записи или отмены; смена товара, характеристики и упаковки сбрасывает ручную цену; поставка сборки — версия и
«Что нового».

Редакция 6 — по кругу 5 (reject: 2×P1): нет курса валюты прайса — отказ пакета; незаписанные правки переживают
любое перечитывание таблицы, в том числе смену отборов и предел 200 документов.

Редакция 7 — по кругу 6 (reject: P1): смена организации тоже сбрасывает ручную цену; валюта, в которой введена
ручная цена, передаётся в пакете и сверяется на сервере с фактической валютой документа.

Редакция 8 — по кругу 7 (reject: 2×P1, P2): запрет отгрузки — по итоговому контрагенту документа (головной у
обособленного подразделения) после заполнения шапки и под блокировкой существующего документа; правка только
количества сохраняет цену упаковки; выбор документа — тем же полным набором правил правки (включая п. 0).

Редакция 9 — по кругу 8 (reject: P1, P2): вид цен новой реализации — по итоговому контрагенту документа; тест
отказа в закрытом периоде — ручной сценарий владельца (настройка «Редактировать в закрытом периоде» пользователя
автотестом не управляется надёжно).

Редакция 10 — по кругу 9 (reject: P1): расчёт от цены упаковки (историческая строка с нулевой `ЦенаSKU`, ручная
цена) сохраняет процент скидки полным алгоритмом рабочего места производства.

Редакция 11 — по кругу 10 (approve_with_changes, 2×P2): выбор документа — по головному контрагенту подразделения;
сегодняшние документы — полуинтервал [начало дня; начало следующего дня).

Уровень по CLAUDE.md — **существенный**: запись и проведение документов из формы списка. План →
`ai-review-plan` → код → `ai-test` → `ai-review` → `ai-final-check`.

## Поиск готового

- Образец модели ввода — режим «Товары» закладки «Поступления» рабочего места закупок (2.0.16.108–115,
  `docs/plans/arm-purchasing-receipt-lines.md`): таблица значений строк документов, новая строка сверху, запись
  при выходе из строки обработчиком ожидания через очередь `СтрокиТоваровКЗаписи`, выбор документа из списка
  «Новый документ» + сегодняшние документы контрагента, удаление строк с пометкой пустого документа,
  перечитывание после записи с курсором на записанной строке, двойной щелчок по колонке «Документ» открывает
  документ. Клиентская часть переносится почти дословно.
- Серверный механизм строк рабочего места производства (`Обработки.АРМПроизводство.ЗаписатьСтрокуДокумента`,
  вид «Отгрузка» = реализация) **не подходит**: строка реализации там всегда привязана к строке заказа клиента
  (`ПрименитьДанныеСтрокиОтгрузки` берёт товар, цену, ставку НДС из строки заказа и отказывает без неё).
  Встраивать «реализацию без заказа» в 13-тысячестрочный механизм ради одной закладки — риск для производства.
  Свой узкий путь в модуле менеджера реализации; заполнение шапки и строки — **существующими** функциями,
  которыми пользуется форма документа (см. «Запись строки»).
- Печать — образец 2.0.16.100: меню из `ПечатныеФормы.ДоступныеКомандыПечатиОбъекта("Документ.РеализацияТоваровУслуг")`
  (с отбором по правам роли на команду), печать — `ПечатныеФормыКлиент.ВыполнитьКомандуПечати`.
- Сортировка щелчком — `СортировкаТаблицФормы` (2.0.17.32, `docs/plans/arm-sorting.md`, вариант A для
  редактируемых таблиц): команды «Сортировать по возрастанию/убыванию» в контекстном меню, `ПрименитьПорядок`
  после каждого перезаполнения, незаписанные строки — сверху.

## Как будет

### Интерфейс

- В группе закладок списка (`ГруппаЗакладкиСписков`) третья закладка **«Товары»** (`СтраницаТовары`) после
  «Реализаций» и «Заказов к отгрузке». Правая панель (фильтры, клиент, детали) остаётся общей.
- Таблица `Товары` (реквизит формы — таблица значений, в настройки не сохраняется). Колонки:
  | Колонка | Ввод |
  |---|---|
  | Дата | просмотр — дата документа |
  | Документ | новая строка: выбор из списка «Новая реализация» + сегодняшние редактируемые реализации клиента строки на её складе и организации (свежие первыми); записанная — просмотр, двойной щелчок открывает документ |
  | Статус | просмотр: «Проведён» / «Черновик» / «Помечен на удаление» |
  | Клиент | новая строка (по умолчанию — отбор панели, иначе клиент ближайшей строки); записанная — просмотр |
  | Организация | новая строка (по умолчанию — отбор панели, иначе организация по умолчанию); записанная — просмотр |
  | Склад | новая строка (по умолчанию — отбор панели, иначе склад пользователя); записанная — просмотр |
  | Товар | новая строка; у записанной — просмотр (другой товар — новой строкой, как в АРМ) |
  | Характеристика | по функциональной опции характеристик, связь выбора с товаром |
  | Упаковка | ввод; по умолчанию — единица товара |
  | Количество | ввод (количество упаковок) |
  | Валюта | просмотр: валюта документа; у новой строки «Новая реализация» — валюта договора клиента, у новой строки в выбранный документ — **фактическая валюта этого документа** (P1 круга 2); цена вводится в ней. Смена документа, клиента, организации, склада, товара, характеристики или упаковки сбрасывает ручную цену (`ЦенаИзменена = Ложь`, P1 круга 4) — цену подставит прайс в валюте документа и для новой упаковки; ручной ввод после этого снова ставит признак |
  | Цена | ввод только при праве «Заверение цен» (как в форме документа: `НастройкиПользователей.ЗаверениеЦен`); без права — просмотр, цена из прайса |
  | Сумма | просмотр |
- Строки, которые закладка не правит (см. «Какие документы правятся»), показываются с признаком `ТолькоПросмотр`:
  попытка правки — сообщение «Эта строка правится в форме документа», двойной щелчок открывает документ.
- Команды таблицы: «Добавить» (новая строка сверху), «Скопировать» (в тот же документ, без цены), «Удалить»,
  «Обновить», «Найти» (штатный поиск таблицы), подменю **«Печать»**, «Сортировать по возрастанию/убыванию»
  в контекстном меню.
- Без права добавления/изменения/проведения реализации таблица только для просмотра; печать и поиск доступны.

### Какие строки показываются

Новая функция модуля менеджера `Документы.РеализацияТоваровУслуг.СтрокиТоваровСписка(Отборы)` — один запрос:

- документы — по тем же отборам, что и список «Реализаций»: тумблер операции, клиент, организация, склад,
  ответственный, сумма и долг с условием, роль PDV — склад пользователя; отбор «Товар» — **только строки этого
  товара** (на закладке строк это и есть поиск по товару);
- непомеченные и помеченные на удаление (помеченные — с этим статусом, только просмотр), порядок — дата документа
  убыв., номер строки;
- предел — строки **последних 200 документов** (как `ПределЗаказовПродукции` в АРМ производства): документов
  больше — над таблицей надпись «Показаны строки последних 200 накладных: уточните отборы на панели».
- права: `ВЫБРАТЬ РАЗРЕШЕННЫЕ`; без права чтения реализаций закладки нет.

Загрузка — при переходе на закладку и при смене отборов панели, если закладка открыта (ленивая: «Реализации»
закладку не тормозят). Перед каждой загрузкой — назначенные записи очереди (как `ЗагрузитьПоступленияНаСервере`).

### Какие документы правятся

Строка редактируема, только если документ — простая реализация, которую закладка умеет вести целиком:

0. в документе нет услуг, доп. расходов и зачёта авансов (`ТЧУслуги`, `ТЧДополнительныеРасходы`, `ТЧЗачётАвансов`
   пусты) — закладка показывает только товары, и удаление последнего товара не должно снимать невидимые строки
   (P0 круга 1; то же правило у рабочего места производства — `ТекстЗапретаРеализацииОбъекта`);
1. `Основание` не заполнено (не по заказу, не по поступлению, не на основаниях налоговых документов —
   `НалоговыеДокументыНаОснованиях.ЭтоДокументНаОснованиях` = Ложь);
2. `КассоваяСмена` пуста (кассовые продажи — только в РМК);
3. в документе нет строк с `Ордер` (оформлено ордерами склада) и у строки нет серий (`Серия`,
   `УказаноНесколькоСерий`);
4. по документу нет налоговой накладной (форма документа в этом случае тоже только для просмотра);
5. документ не помечен на удаление;
6. у пользователя есть право изменения и проведения реализации.

Иначе — `ТолькоПросмотр`. Те же правила — при загрузке строк, выборе документа, записи и удалении под блокировкой
(клиентскому признаку не доверяем). Налоговая накладная проверяется **независимо от права её чтения** (P1 круга 2: защита налоговых
оснований документа ищет другие связи): узкая серверная функция `РеализацииСНалоговойНакладной(Документы)` в
привилегированном режиме возвращает только подмножество переданных реализаций, по которым есть непомеченная
налоговая накладная (`ТЧТовары/ТЧУслуги.ОтгрузкаТовара`), — ни реквизитов, ни ссылок накладных наружу не уходит;
вызывается после того, как реализации прочитаны с правами пользователя (`РАЗРЕШЕННЫЕ`, объект под блокировкой).
Уровень — `ai-security` по привилегированному режиму.

### Запись строк — `Документы.РеализацияТоваровУслуг.ЗаписатьСтрокиТоваров(Строки)`

**Пакет по документу (P1 круга 1).** Очередь записи на клиенте копит правки; перед записью они группируются: все
правки строк одного записанного документа уходят **одним вызовом** — одна блокировка, одна проверка исходной
версии данных (общей для строк пакета: они прочитаны одной загрузкой), применение всех правок и одна запись или
проведение. **Политика отказа (P2 круга 2):** документ в базе не меняется (исключение откатывает запись), а
правки пакета **остаются в таблице** с признаком `Изменена` и сообщением — пользователь исправляет одну строку и
пакет уходит снова. **При любом перечитывании** (после записи, «Обновить», смена отборов панели, переход на
закладку — P1 круга 5) все строки с `Изменена` и все новые строки (`НомерСтроки = 0`) сохраняются **до** очистки
таблицы и возвращаются наверх **независимо** от результата запроса (даже если их документ вне отборов или за
пределом 200); записанные строки из базы с тем же «документ + номер строки», что у сохранённой изменённой,
отбрасываются. Новые строки ключа не имеют и возвращаются все. Сбросить правки — только «Обновить» с вопросом. Только конфликт версии (документ изменил другой пользователь, строки больше нет) возвращает строки
пакета к базе. Каждая новая строка без документа — свой вызов (свой новый документ); новая строка, добавленная в
записанный документ, входит в его пакет. Отказ пакета — правки остаются в таблице незаписанными
(признак `Изменена`) с сообщением, строки записанные возвращаются к базе только при конфликте версии
(документ изменил другой пользователь: «Документ изменён другим пользователем: строки перечитаны»).

Строка — Документ (пустой — новый), НомерСтроки (0 — новая), ВерсияДанных, Клиент, Организация, Склад, Номенклатура,
Характеристика, Упаковка, КоличествоУпаковок, Цена, ЦенаИзменена, Валюта (в которой введена цена). Результат — Успех, Текст, Документ, НомерСтроки (последней записанной строки пакета).

1. **Проверки до записи:** права (добавление/изменение/проведение); типы и заполненность (клиент, склад, товар,
   количество > 0); **серийный товар**
   (`СерийныйУчет.ЭтоСерийнаяНоменклатура`) — отказ «Товар с IMEI/серийными номерами вводится в форме документа»
   (серия обязательна, в строке её нет); **ордерный склад** на сегодня (`Справочники.МестаХранения.ОрдерныйСклад`) —
   отказ «Склад ордерный: отгрузка оформляется расходным ордером» для новой строки (ОбработкаПроверкиЗаполнения
   иначе всё равно откажет — `ОрдераСклада.ПроверитьОформление`); **запрет отгрузки клиенту** — проверяется
   **после** заполнения шапки по `ДокОбъект.Контрагент` (P1 круга 7: `ПолучитьДанныеКонтрагента` заменяет обособленное
   подразделение головным контрагентом, как `ЗаполнитьДанныеПоТорговойТочке` формы) и у существующего документа — под
   блокировкой по его шапке (как `ПередЗаписью` формы документа при каждой записи) → отказ тем же текстом, что форма.
2. **Новый документ:** `СоздатьДокумент()` → `Заполнить(Неопределено)` (ОбработкаЗаполнения: реквизиты по
   умолчанию, `ЦенаВключаетНДС`) → `Дата = ТекущаяДатаСеанса()`, `ХозяйственнаяОперация = РеализацияКлиенту`,
   `Организация` (строки, иначе по умолчанию), `МестоХранения`; данные клиента (контрагент — головной у обособленного подразделения, договор, менеджер) —
   `ОбщегоНазначенияВызовСервера.ПолучитьДанныеКонтрагента(Клиент, Организация, СПокупателем, Дата)` (договор и
   прочее, как `ЗаполнитьДанныеПоТорговойТочке` формы); `ВидЦен = ВидЦеныПродажиПоУмолчанию(ДокОбъект.Контрагент, Склад)` — по итоговому контрагенту после замены
   подразделения головным (P1 круга 8),
   `ЦенаВключаетНДС = ЦенаВключаетНДСПоВидуЦен(ВидЦен)` (как `УстановитьВидЦеныПоДоговору` формы); валюта —
   по договору, как `ЗаполнитьВалютуПоДоговору` формы (валюта договора не основная → `ВВалюте`, курс на дату через
   `РаботаСВалютами.КурсВалюты`; курса нет — отказ `ТекстКурсНеЗадан`). Общая серверная процедура
   `ЗаполнитьШапкуНовойРеализации(ДокОбъект, Клиент, Организация, Склад)` в модуле менеджера.
3. **Существующий документ:** `ЗаблокироватьДанныеДляРедактирования` + управляемая блокировка документа в
   транзакции; `ВерсияДанных` не совпала — отказ «Документ изменён другим пользователем: строки перечитаны»;
   повторно — правила «Какие документы правятся» по объекту; клиент/склад/организация строки должны совпасть с
   шапкой (выбор документа это гарантирует, сервер перепроверяет).
4. **Строка:** новая — `ТЧТовары.Добавить()`, `КодСтроки = ПолучитьСледующийКодСтроки`; товар, характеристика,
   `ВидЦены = ДокОбъект.ВидЦен`, а пустой `ВидЦен` у существующего документа — `ВидЦеныПродажиПоУмолчанию(Контрагент,
   МестоХранения)` документа (как форма при открытии такого документа, P1 круга 3; валюта и режим НДС документа не
   меняются, прежние строки не переоцениваются); данные номенклатуры и ставка НДС —
   `РаботаСДокументамиКлиентСервер.УстановитьПараметрыНоменклатуры(Строка, ДокОбъект)` — та же функция, что
   у формы при выборе товара; она ставит упаковкой единицу товара, поэтому **после неё** восстанавливаются
   выбранная упаковка и количество упаковок и цена с количеством считаются
   `УстановитьЦенуНоменклатуры(Строка, ДокОбъект)` — как форма при смене упаковки (P1 круга 2). Записанная строка
   (по `НомерСтроки`, товар совпадает) — смена упаковки или характеристики → `УстановитьЦенуНоменклатуры`
   (цена заново, как в форме), только количество — цена упаковки прежняя (историческая строка с нулевой `ЦенаSKU` и ненулевой ценой
   пересчитывается от цены с **сохранением процента скидки** полным алгоритмом `ПрименитьДанныеСтрокиОтгрузки` рабочего
   места производства: процент запоминается, скидка на цену считается от него, расчёт от цены, процент восстанавливается,
   строка досчитывается — P1 кругов 7 и 9; так же считается строка с ручной ценой), количество
   (`РассчитатьСтроку(..., "Количество")`, цена прежняя). `ЦенаИзменена` и право «Заверение цен» — цена строки
   из таблицы, `РассчитатьСтроку(..., "Цена")`; без права введённая цена игнорируется.
   **Валюта ручной цены (P1 круга 6).** Ручная цена (`ЦенаИзменена` при праве заверения) применяется, только если
   `Валюта` строки совпадает с фактической валютой документа (новой реализации — после заполнения шапки по
   договору); иначе отказ пакета «Валюта накладной — …: введите цену заново», правки остаются в таблице.
   **Курс валюты прайса (P1 круга 5).** Подстановка цены при отсутствии курса валюты прайса только сообщает об
   этом (`ПересчитатьЦенуВВалютуДокумента`) и оставляет цену непересчитанной. Поэтому сообщения пользователю,
   накопленные **во время подстановки цены** (единственное сообщение этого пути — `ТекстКурсНеЗадан`), считаются
   отказом пакета: «Цена не подставлена: …», документ не пишется, правки остаются в таблице.
5. **Запись:** новый документ и проведённый — `Записать(Проведение)`; непроведённый (черновик) —
   `Записать(Запись)`. Отказ проведения **нового** документа (например, контроль минимальной цены) — документ
   не создаётся, отказ с текстом сообщений проведения (не плодим пустые черновики; строка остаётся для правки).
   Отказ записи существующего — запись откатывается, правки пакета остаются в таблице (политика отказа выше).
   Политика отрицательных остатков проекта: проведение из-за минуса не запрещается — это делает сам документ.
6. Ошибки записи — `ИнформацияОбОшибке` в краткое представление, транзакция откатывается, `Успех = Ложь`.

### Закрытие формы (P1 круга 3)

`ПередЗакрытием`: заканчивается ввод строки, выполняется очередь записи. Остались строки с `Изменена` (отказ записи)
— закрытие отменяется и задаётся вопрос «Правки N строк не записаны. Закрыть без сохранения?»; «Да» — форма
закрывается (признак подтверждённого закрытия), «Нет» — остаётся с правками. При завершении работы программы
(`ЗавершениеРаботы`) вопрос не задаётся — платформе возвращается текст предупреждения о незаписанных правках.

### Удаление — `Документы.РеализацияТоваровУслуг.УдалитьСтрокиТоваров(Строки)`

**Незаписанные правки (P1 круга 4).** Перед удалением на клиенте выполняется очередь записи; если у документа
удаляемых строк после неё остались строки с `Изменена` (отказ записи), удаление этого документа не выполняется —
сообщение «Сначала исправьте или отмените незаписанные правки накладной № …» (иначе своё удаление перенумеровало бы
строки и правки потерялись бы как чужой конфликт). Отмена правок — команда «Обновить»: при наличии строк с
`Изменена` она спрашивает «Отменить незаписанные правки N строк?» и перечитывает таблицу из базы.

Строки группируются по документу; по каждому — блокировка, версия, правила правки; строки удаляются по номерам
(с конца). Остались строки — перепроведение/запись в прежнем режиме. Не осталось — документ **помечается на
удаление** как в рабочем месте производства (`ПометитьДокументСтроки`, P0/P1 круга 1): сначала проверка права
`ИнтерактивнаяПометкаУдаления` (платформе хватает «Изменения», форма списка требует интерактивную пометку; нет
права — отказ «удалите строки в форме документа», документ не меняется); пометку ставит **заново полученный**
неизменённый объект (`Ссылка.ПолучитьОбъект()`) в той же транзакции под той же блокировкой — изменённый объект
платформа пометить не даёт; строки остаются в помеченном документе. Отказ по одному
документу не мешает остальным; итог — сообщения по документам.

### Выбор документа — `Документы.РеализацияТоваровУслуг.ДокументыДляСтрокиТоваров(Клиент, Организация, Склад)`

Сегодняшние (`Дата >= НачалоДня(ТекущаяДатаСеанса())`) непомеченные реализации клиента на складе и организации,
отвечающие **всем** правилам «Какие документы правятся» 0–5 (та же функция запретов, что при загрузке; P2 круга 7), свежие первыми; представление — «№ … от … (N поз., сумма)».
Первым пунктом — «Новая реализация». Смена клиента/склада/организации новой строки сбрасывает выбранный документ.

### Печать

Подменю «Печать» в командной панели таблицы `Товары`, собранное кодом при создании формы из
`ПечатныеФормы.ДоступныеКомандыПечатиОбъекта("Документ.РеализацияТоваровУслуг")` (одна форма — кнопка, нет —
ничего). Печатаются **документы выделенных записанных строк** (без повторов) целиком — тот же вызов
`ПечатныеФормыКлиент.ВыполнитьКомандуПечати("Документ.РеализацияТоваровУслуг", ИмяМакета, Документы, ЭтотОбъект)`.
Перед сбором документов заканчивается ввод строки и выполняется очередь записи (новый документ печатается сразу).
Документ, у которого после очереди остались строки с `Изменена` (отказ записи), **не печатается** — сообщение
«Правки строк накладной № … не записаны: исправьте их и повторите печать» (P2 круга 3: печать разошлась бы с
таблицей). Нет записанных строк — сообщение «Выделите строки записанных накладных».

### Права

Закладка видна при праве чтения реализаций. Ввод — при праве «Добавление», «Изменение» и «Проведение»
`РеализацияТоваровУслуг`; иначе таблица только для просмотра. Цена — по «Заверению цен». Роль PDV — склад
новой строки и отбор строк — склад пользователя (как отбор списка).

## Тесты

Уровень 3, сценарий `РеализацииТоварамиСписка` в `ТестыДокументов` (неордерный склад, товар без серий, прайс):
1. Новая строка без документа → новая проведённая реализация, клиент/склад/организация из строки, вид цен по
   умолчанию, цена = прайс, сумма = цена × количество, `ХозяйственнаяОперация` = реализация клиенту.
2. Вторая строка в документ п. 1 → тот же документ, две строки, перепроведён.
3. Правка количества строки п. 1 → сумма пересчитана, цена прежняя; документ проведён.
4. Правка с устаревшей версией данных → отказ, документ не изменён.
5. `СтрокиТоваровСписка` с отбором клиента → строки п. 1–2, редактируемые; отбор товара → одна строка.
6. Реализация на основании заказа клиента → её строки `ТолькоПросмотр`; запись строки в неё → отказ;
   в `ДокументыДляСтрокиТоваров` её нет.
7. Серийный товар → отказ; ордерный склад (опция включена) → отказ, документ не создан.
8. Удаление одной строки из двух → документ с одной строкой проведён; удаление последней → документ помечен на
   удаление и не проведён.
9. Запрет отгрузки клиенту (признак `ЗапретОтгрузок`) → отказ предварительной проверки, документа нет.
10. (Ручной сценарий у владельца, P2 круга 8: пользователь без права «Редактировать документы в закрытом
    периоде».) Отказ **внутри записи** существующего документа (P2 кругов 1–2; контроль минимальной цены под администратором
    не срабатывает — допуск роли): дата запрета изменения организации ставится на сегодня (тест возвращает прежнюю)
    → правка количества строки п. 1 отказана в `ПередЗаписью` документа, `Успех = Ложь`, `Конфликт = Ложь`,
    строки и движения документа прежние. Отказ проведения **нового** документа автоматикой не воспроизводится
    под администратором — путь тот же (`ЗаписатьДокумент`), проверка — руками у владельца пользователем без
    допуска продажи ниже минимальной цены.
14. Упаковка с коэффициентом ≠ 1 (2 коробки по 12): новая строка → `Количество` = 24, цена — за коробку; смена
    упаковки записанной строки на штуку → количество и цена пересчитаны; движения `ТоварыВНаличии` — 24.
15. Новая строка в существующий документ в валюте (договор клиента после создания документа переведён в основную
    валюту) → `ШапкаДокументаСтрокиТоваров` возвращает валюту документа; цена строки — в валюте документа.
16. Налоговая накладная по реализации → `РеализацииСНалоговойНакладной` её находит (под администратором; проверка
    без права чтения накладных — модульно: функция в привилегированном режиме).
11. Смешанная реализация (товар + услуга) → строки `ТолькоПросмотр`, удаление её строки → отказ, документ не
    изменён и не помечен.
12. Две правки строк одного документа одним пакетом → обе записаны, документ проведён один раз.
13. Удаление последней строки **с правом** интерактивной пометки (администратор) → документ помечен на удаление,
    проведение снято. **Без права** (P2 круга 3) → отказ «нет права помечать», пометки нет, строки и движения
    прежние — обязательный ручной сценарий у владельца пользователем роли без интерактивной пометки (тестовый контур
    пользователя не меняет); в автотесте — модульная проверка текста отказа функции пометки нет.
17. Существующий документ с пустым `ВидЦен` и розничным прайсом → новая строка получает цену прайса, прежние строки
    не переоценены.
19. Отказ правки второй строки → удаление первой строки того же документа отказано, правка второй сохранена
    (клиентская логика — руками у владельца; серверная часть — версия пакета проверяется).
23. Ручная цена → смена организации (договоры в разных валютах) → признак сброшен, цена прайса; ручная цена с
    валютой, отличной от валюты документа, → отказ пакета.
24. Обособленное подразделение, головному контрагенту запрещена отгрузка → отказ, документа нет.
25. Историческая строка с `ЦенаSKU = 0`, ценой 100 и скидкой 10 % → правка количества до 2: цена 100, процент 10,
    сумма со скидкой 180, долг клиента по документу — 180.
21. Прайс в иностранной валюте без курса, документ в основной валюте → отказ «Цена не подставлена», документа нет.
22. Отказ записи → смена отбора клиента → изменённая строка остаётся в таблице → возврат отбора → повтор записи
    проходит (клиентская логика — руками у владельца).
20. Ручная цена → смена упаковки → цена прайса для новой упаковки (признак сброшен на клиенте; сервер применяет
    ручную цену только с признаком).
18. Отказ записи правки (закрытый период, п. 10) → строка таблицы сохраняет введённое количество с `Изменена`;
    печать этого документа не выполняется; после снятия запрета повтор записи проходит. Закрытие формы с
    незаписанной правкой — вопрос (руками у владельца).

Смок «открыть все формы» открывает форму списка; закладка, ввод, печать — руками у владельца.
`docs/TESTING.md` и `docs/TESTS.xlsx` — новая строка сценария.

## Риски

- Цена строки зависит от прайса и вида цен клиента так же, как в форме документа: расхождение с формой возможно
  только если форма заполняет что-то при открытии, чего нет в `ЗаполнитьШапкуНовойРеализации` (срок оплаты —
  только реквизит формы; куратор — `ПередЗаписью` документа сам). Сверка в тесте п. 1 с документом,
  созданным формой, — руками у владельца.
- Предел 200 документов: при больших объёмах работа идёт через отборы панели (клиент, товар, склад).
- Таблица значений не обновляется сама при правке документа в другом окне: перечитывание — после закрытия
  открытого документа, кнопкой «Обновить», при смене отборов и после каждой записи.

## Не входит

- Ввод на ордерном складе (расходные ордера) и серий/IMEI — в форме документа.
- Скидки, услуги, доп. расходы, комментарий, валюта вручную — в форме документа.
- Колонка «описание состава» из исходного тикета — заменена этой закладкой по решению владельца.
