# План: отчёт «Прослеживаемость партий материала» (Drissotex)

Волна 2 консоли отчётов (`docs/plans/reports-console.md`). Отчёт сделан **для Drissotex** (образец — их бумажный
отчёт «Partie Usine / Partie Peinture / Partie Fini»), но живёт в тиражной конфигурации: схема «материал → выпуск ПФ →
передача в переработку → отгрузка» есть у любого клиента с переработкой. Пометка «для Drissotex» — в комментарии
`.mdo`, в этом плане и в ROADMAP; в интерфейсе — нейтральное имя.

## Задача владельца (2026-10-31)

По каждой партии материала увидеть, куда она ушла. Решения владельца:

| Вопрос | Решение |
|---|---|
| Лот | **Номер документа поставщика** (`ПоступлениеТоваровУслуг.НомерВходящегоДокумента`) |
| Связь партии материала с отгрузками | **Через заказ на производство** (`ЗаказПокупателя`, вид «Производство») |
| Группировка | **Материал + дата прихода (партия)**, внутри — таблицы движений |
| Таблицы | **Четыре независимые колонки-таблицы**: Партия материала → Выпуск ПФ → Передача в переработку → Отгрузка заказчику. Строки соседних таблиц не сопоставляются построчно |
| Полнота воронки | Все выпуски из партии — в «Выпуске ПФ»; все партии ПФ этих выпусков — в «Передаче»; все заказы и партии из передачи — в «Отгрузке» |
| Учёт времени | Drissotex |

Таблица «Выпуск ПФ» — новая относительно бумажного образца (у клиента её не хватало: «что передано в производство»).

## Уровень изменения

Существенное: новый объект метаданных (отчёт), права ролей, раздел меню. Без реструктуризации и без изменения
проведения. Порядок: план → **`ai-review-plan`** → реализация → `ai-test` → **`ai-review`** → `ai-final-check` → отчёт
`.ai/reports/lot-traceability.md`. `ai-database`/`ai-security` — не нужны (только чтение данных, без привилегий), если
ревью плана не решит иначе.

## Исходные данные (проверено по `src/cf`)

Ключ партии материала — **`Номенклатура` + `Характеристика` + `Партия`** (ревью плана, круг 1, P1: партия — ссылка
на документ, одно поступление несёт несколько материалов). Ниже «расход партии» = расход `ТоварыВНаличии` по этому
ключу.

| Звено | Источник | Правило |
|---|---|---|
| Партия материала (первичный приход) | приход `ТоварыВНаличии`, у которого **`Регистратор = Партия`**, `Партия ССЫЛКА Документ.ПоступлениеТоваровУслуг` или `Документ.ПриходныйОрдер` и **`МестоХранения` = склад самого документа прихода** — так отсекается только зеркальная копия, которую поступление пишет на `ПодчиненныйСклад` (круги 4–5, P1); склад целиком не исключается | Перемещения и требования-накладные пишут приход с прежней партией, но регистратор у них другой (круг 1, P1). Дата прихода — `ДатаПартии`; «Приход» — сумма первичных движений. «Остаток» — остаток по ключу партии на конец периода по всем складам, **кроме складов, на которые легла зеркальная копия этого прихода** — они берутся из самих движений: `Регистратор = Партия` и `МестоХранения` ≠ склад документа (круг 6, P1: история, а не текущая настройка `ПодчиненныйСклад`). Ограничение: если партию потом переместили на такой склад, этот остаток в «Остаток» не войдёт — пометка в описании колонки |
| Лот | партия-поступление — его `НомерВходящегоДокумента`. Партия-приходный ордер — номера поступлений, оформивших **строки этого материала** (ключ партии): «документ первый» — `ПриходныйОрдер.ТЧТовары.ДокументИсточник` строк с той же `Номенклатура`/`Характеристика`; «ордер первый» — `ТоварыКОформлению` с `Источник` = ордер, той же `Номенклатура`/`Характеристика` и `Регистратор ССЫЛКА Документ.ПоступлениеТоваровУслуг` (круг 2, P1: по ордеру целиком номера чужих материалов прилипли бы к партии) | Номера через запятую; не оформлен — «ордер №… (не оформлен)» |
| Выпуск ПФ | расход партии материала с `Регистратор ССЫЛКА Документ.ВыпускПродукции`; ПФ и количество — `ВыпускПродукции.ТЧГотоваяПродукция` | Партия ПФ = сам выпуск |
| Заказ выпуска | **`ВЫБОР`** по типу `ВыпускПродукции.Основание`: `ЗаказПокупателя` — он; `РеализацияТоваровУслуг`, `ПередачаВПереработку`, `РасходныйОрдер` — их `Основание`, если это заказ (автовыпуск хранит документ-основание, круг 1, P1). Клиент — `Контрагент` заказа | Нет заказа — клиент пуст |
| Передача в переработку | расход `ТоварыВНаличии` с `Регистратор ССЫЛКА Документ.ПередачаВПереработку`, `Номенклатура` = ПФ выпуска и `Партия` ∈ выпуски таблицы 2; переработчик — `Контрагент`, заказ — `Основание` (тип только `ЗаказПокупателя`) | |
| Продукция переработки | расход `РегистрНакопления.ТоварыВПереработке` с `Регистратор ССЫЛКА Документ.ПоступлениеИзПереработки`, **`ПередачаВПереработку` ∈ передачи таблицы 3, `Номенклатура`/`Характеристика` = ПФ и `Партия` ∈ выпуски таблицы 2** (круги 2–3, P1). **Хвостовые поступления без списания сырья** (приёмка хвоста продукции после дочистки остатка, `ПоступлениеИзПереработки.ПроверитьСписаниеБезПрихода`) **в воронку не входят** (круг 11, P1): проведение не связывает их ни с одной передачей, а любое правило «подходящих передач» — догадка. В секции «Передача» под строками переработчика выводится справочная строка «Хвост без сырья: поступление №… от … , продукция, количество — связь с партией не подтверждена» для поступлений этого переработчика без расхода сырья, у которых `Основание` — передача из таблицы 3 или её заказ, датой после передачи. Строка не входит в итоги, её продукция не попадает в «Отгрузку» и «На складе». Партия ГП — сам документ поступления | для отгрузок и «на складе» |
| Отгрузка заказчику | **Только физическая отгрузка партии ГП**: расход `ТоварыВНаличии` по партиям ГП из поступлений из переработки (предыдущая строка) с регистратором `РеализацияТоваровУслуг` (обычный склад) или `РасходныйОрдер` (ордерный склад). Количество — **нетто по документу из закрытого списка типов** (круг 13, P1): отгрузка — расход партий ГП этих поступлений регистратором `РеализацияТоваровУслуг` или `РасходныйОрдер`; возврат — приход этих партий регистратором `ВозвратОтПокупателя` или `ПриходныйОрдер` (кроме первичного прихода, `Регистратор` ≠ `Партия`). Прочие выбытия партий ГП (`СписаниеТоваров`, `ВыпускПродукции`, `ПередачаВПереработку`, …) — **отдельными строками «Прочее выбытие: <вид документа> №…»** с отдельным итогом, не отгрузкой; перемещения и требования-накладные (расход и приход одним документом) нетто дают ноль и не выводятся (круг 12, P1: возврат покупателя восстанавливает исходную партию ГП — `ТоварыВНаличии.СформироватьОприходованиеПоРеализации`, — и без этого возвращённое считалось бы и отгруженным, и лежащим на складе). Возврат даёт строку «Возврат» с минусом; секция сходится: «отгружено − возвращено + прочее выбытие + на складе» = поступило. Документ строки — регистратор движения. Расходный ордер реализацией **не подменяется** (круги 2–3, P1: оформление построчное и количественное); справочная колонка «Оформлено» не выводится (круг 5, P2: для комплектов физические строки ордера и строки оформления различаются; в образце клиента такой колонки нет). **Ветки «по заказу» нет** (круг 3, P1: реализация «документ первый» на ордерном складе до расходного ордера товар не списала — показывать её отгрузкой нельзя). Связь «через заказ», о которой говорит владелец, держится цепочкой партий: заказ выпуска → передача → поступление → отгрузка; заказ и клиент показываются в каждой секции | Клиент — `Контрагент` документа; у расходного ордера — его собственный `Контрагент` (ордер может быть без основания, круг 5, P2) |
| «На складе» | остаток `ТоварыВНаличии` по партиям ГП из поступлений из переработки этих передач **на конец периода** | строка «На складе», как «EN STOCK» |

**Количества — без долей (круги 4–5, P1).** Выпуск — одна партия ПФ на все использованные материалы, поступление из
переработки — одна партия ГП на все строки продукции (`РаспределитьСебестоимостьНаПродукцию`): какой материал стал каким
ПФ и какой ПФ — какой продукцией, система не хранит. Делить количества долями значит выдумывать точность. Поэтому секции
показывают **полные количества документов**, связанных с партией, как бумажный отчёт клиента, и **помечают смешение**:
- выпуск, списавший больше одной партии материала (по ключу партии), — пометка «◐» и подсказка «выпуск из нескольких
  партий материала» в строке выпуска и в строках передач его ПФ;
- поступление из переработки смешанное, если в расходе `ТоварыВПереработке` у него **больше одной партии сырья любого
  вида** (выпуски, покупной ПФ, материал — круг 7, P1) **или хотя бы одна из его партий ПФ — смешанный выпуск**
  (пометка наследуется по цепочке, круг 6, P1) — та же пометка в строках отгрузок его продукции и в «На складе»;
  хвостовые поступления в воронку не входят (см. «Продукция переработки»).
Итоги секций 2–4 — **по единицам измерения** (`Номенклатура.Единица`): строка итога на каждую единицу («Итого, кг:
2 060,700», «Итого, шт: 12»), разные номенклатуры одной единицы складываются, разные единицы — нет (круг 7, P2). При
смешении итоги относятся ко всем партиям группы сразу — это пишется под итогом («есть смешанные документы»), а не
скрывается.

**Период (круг 3, P2).** Период отчёта ограничивает первичный приход партий (§1). Движения воронки (выпуски,
передачи, поступления, отгрузки) берутся **с начала периода по его конец** — та же граница, что у остатков «Остаток» и
«На складе» (на конец периода). Всё, что случилось после конца периода, в отчёт не попадает: история и остатки
согласованы на одну дату.

Почему по регистру, а не по `ТЧТовары.Партия` документов: при списании FIFO колонка `Партия` в документе может быть
пустой, а движения регистра партию несут всегда.

## 1. Отчёт `ПрослеживаемостьПартий`

Новый отчёт (свой uuid, без префикса), синоним «Прослеживаемость партий материала» (fr «Traçabilité des lots de
matière», en «Material lot traceability», es «Trazabilidad de lotes de material»). Комментарий `.mdo`: «Сделан для
Drissotex: Partie Usine / Peinture / Fini». Основная форма — **общая `ФормаОтчёта`**: так работают избранное с образом,
именованные варианты и «Все отчёты» (волна 1).

### Схема компоновки (для настроек и отбора партий)

Основная СКД — набор «Партии материала» (первичный приход партии в периоде — правило таблицы выше):

- поля: `Номенклатура` (материал), `Характеристика`, `Партия`, `ДатаПартии` (дата прихода), `Поставщик`, `Приход` (количество
  прихода партии), `Остаток` (остаток на конец периода), `МестоХранения` первичного прихода; лот вычисляется модулем
  после отбора (номера поступлений через запятую в запросе СКД не собрать) и в отбор СКД не входит — поиск по лоту —
  параметром `Лот` (подстрока), применяется модулем;
- параметры: `Период` (`СтандартныйПериод`, по умолчанию — текущий месяц), `ДатаОстатка` = конец периода;
- отборы пользователя СКД: материал, поставщик, склад; параметры, применяемые модулем: `Лот` (подстрока номера) и
  `Клиент` — применяется **в каждой секции к её собственному клиенту** (круг 6, P2): выпуски — по клиенту заказа выпуска,
  передачи — по клиенту заказа передачи, отгрузки — по `Контрагент` документа отгрузки; воронка при этом строится по
  полной цепочке партий, отбор только скрывает строки. Строка «На складе» клиента не имеет — **при отборе по клиенту
  она не выводится и в итоги не входит** (круг 11, P2). Партия без единой строки клиента в секциях 2–4 скрывается.

### Вывод — модуль объекта, `ПриКомпоновкеРезультата` (`СтандартнаяОбработка = Ложь`)

1. Партии материала — СКД в коллекцию значений по настройкам пользователя (отборы и период работают как в любом отчёте).
2. Три пакетных запроса по списку партий (временная таблица партий): выпуски, передачи, отгрузки и остатки «на
   складе» — правилами полноты из таблицы выше.
3. Макет `МакетОформления` (табличный документ): шапка отчёта, шапка группы «Материал · характеристика · лот · дата прихода» (характеристика входит в ключ партии — без неё разные партии неразличимы, круг 8, P2), четыре
   секции-колонки с собственными шапками и строками, итоги количества под секциями 2–4.
4. Для каждой партии: строки секций выводятся бок о бок — по индексу строки `i` до максимума из четырёх: область строки
   секции или пустая область той же ширины (`Присоединить`). Секции не сопоставляются по смыслу — только по позиции.
5. Расшифровка: ячейки документов (выпуск, передача, реализация) открывают документ (`Расшифровка` = ссылка).

Колонки секций (по образцу клиента + выпуск):

| Секция | Колонки |
|---|---|
| Партия материала (Partie Usine) | Дата прихода, Материал, Характеристика, Лот, Поставщик, Приход, Остаток |
| Выпуск ПФ | Дата, № выпуска, ПФ, Кол-во ПФ, Списано материала из партии, Клиент |
| Передача в переработку (Partie Peinture) | Дата, № накладной, ПФ, Кол-во, Переработчик, Клиент |
| Отгрузка заказчику (Partie Fini) | Дата, № документа, Продукция, Кол-во, Клиент; строка «На складе» с остатком |

Языки: заголовки — `НСтр` на ru/fr/en/es.

### Почему не чистая СКД

Четыре независимых списка бок о бок под одной группировкой СКД не выводит: её группировки — это одна таблица или
вложенность, а нужна «воронка» колонками разной длины, как у клиента. Отбор и период при этом остаются настройками
СКД — вариант, избранное и образ работают как у остальных отчётов (образ строится `Отчет.СкомпоноватьРезультат`, а он
вызывает `ПриКомпоновкеРезультата` модуля объекта).

## 2. Размещение и права

- Подсистема «Производство» (и вложенная «Переработка», если отчёты переработки там) — команда отчёта в панели
  «Отчёты», сверка `scripts/menucheck.py`.
- Права `Use`/`View` на отчёт — ролям, у которых есть отчёт `ТоварыВПереработке` (те же читатели данных); список — по
  факту `Rights.rights` при реализации. `Администратор`/`Руководитель` — автоматически.
- Функциональная опция — та же, что у `ТоварыВПереработке` (`ИспользоватьПереработку`): без переработки отчёт не нужен.

## 3. Проверка

- `lint.sh`, `refcheck.py`, `menucheck.py`; смок формирует все варианты отчётов (65 → 66).
- Сценарий уровня 3 `ПрослеживаемостьПартий`: два поступления материала с разными номерами поставщика; выпуск ПФ по
  заказу клиента A из партии 1 (и частично из партии 2); второй выпуск по заказу клиента B; передача ПФ переработчику
  по обоим заказам; поступление из переработки; реализация клиенту A (часть). Проверки по результату отчёта
  (через `ПриКомпоновкеРезультата` во временный табличный документ + выгрузка текста):
  - группа партии 1 — лот = номер поставщика, приход и остаток;
  - «Выпуск ПФ» партии 1 — оба выпуска, списано материала = движения регистра;
  - «Передача» — все передачи партий ПФ этих выпусков, переработчик и клиент;
  - «Отгрузка» — реализация клиенту A и строка «На складе» с остатком;
  - партия 2 видит только свой выпуск; отбор по клиенту B скрывает реализацию A;
  - ордерный склад: партия — приходный ордер, лот — номер поступления-источника;
  - выпуск из двух партий материала — пометка смешения в выпуске, передаче его ПФ и отгрузке продукции (наследование);
  - возврат покупателя части отгрузки — строка «Возврат» с минусом, «На складе» включает возвращённое, сверка секции
    «отгружено − возвращено + прочее выбытие + на складе = поступило»;
  - списание части продукции — строка «Прочее выбытие», не отгрузка;
  - хвостовое поступление без сырья — справочная строка в «Передаче», его продукция не в «Отгрузке» и не в итогах;
