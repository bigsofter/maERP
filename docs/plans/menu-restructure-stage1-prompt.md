## Ловушки (найдены гейтом плана — не повторять)

1. **`НачальноеЗаполнение` — фильтр, а не «ещё и»** (`CommonModules/ОбновлениеПрограммы/Module.bsl:358-367`).
   `ВключитьНовыеФункциональныеОпции` регистрировать **дважды**: версия сборки 1б с `Ложь`
   (существующие базы, ветка `ВерсияБазы < Версия <= ВерсияПрограммы`) и с `Истина` (пустая база).
   Это первый обработчик начального заполнения в проекте — сверить, как его исполняет `ВыполнитьОбновление`.
2. **`ИспользоватьРегламентированныйУчет`** в существующих базах = `Константы.Бухгалтерия`, в новых — `Истина`.
   Остальные новые константы — `Истина`. Существующие ФО (`Бухгалтерия`, `Зарплата`, `Производство`,
   характеристики/серии/упаковки/партии, тендеры) обработчик не трогает.
3. **`Document.ЗаказПокупателя` — в двух ФО**: `ИспользоватьЗаказыПокупателей` и `Производство` (заказ на
   производство — тот же документ). **`ЗаявкаНаПоискТовара`** — в `ИспользоватьЗаявкиНаПоискТовара` и
   `ИспользоватьЛичныйКабинет`. Объект виден, если включена любая.
4. **`ПоступлениеДополнительныхРасходов` — вне ФО «Импорт».**
5. **Скрытое обязательное поле**: `Catalogs/СерииНоменклатуры/ObjectModule.bsl:7-8` — проверку
   `СтранаПроисхождения` обернуть в `ПолучитьФункциональнуюОпцию("ИспользоватьИмпорт")`. Для **каждой**
   строки таблицы 1.2 — grep `ПроверкаЗаполнения`/`fillChecking` по реквизитам из состава.
6. **Смок не выполняет обработчики** (`ManagedApplicationModule.bsl:36-40` выходит раньше
   `ОбработатьНачалоРаботы`). Перед смоком — `ОбновлениеПрограммы.ВыполнитьОбновление()` внешней
   обработкой через `build/menu/run.sh` (модуль без внешнего соединения), иначе смок пройдёт в профиле
   «всё выключено». Профиль «всё выключено» — отдельным прогоном с явной записью констант.
7. Имена без «ё» (BSLLS YoLetterUsage): `ИспользоватьРегламентированныйУчет`, `ИспользоватьПересчеты`.
   ФО производства называется `Производство`, константа — `ИспользоватьПроизводство`.
8. Формы: значения ФО для зависимых флажков — на сервере, не `ПолучитьФункциональнуюОпцию` в клиентском
   коде (tiny1C bsl-009); новые группы `Form.form` — с `<visible>true</visible>`, команды — с
   `<handlers>` (forms-004, память `edt-form-visible-default`).
9. Ключ `ФункциональныеОпции` в `НачальноеЗаполнениеВызовСервера.ПараметрыЗаполнения()` — пустое
   Соответствие по умолчанию; `ЗаполнитьБазу` при пустом ключе ничего не пишет (путь хаба сохраняет
   значения обработчика).
10. Начальная страница: `HomePageWorkArea.hpwa:136` (РМК) и `:193` (ЛКП) — формы объектов под новыми ФО;
    проверить на базе в профиле «всё выключено» под ролями `PDV` и `ЛичныйКабинет`.
11. Перед правкой `.mdo`, `Form.form`, `.dcs` — `checklist` tiny1C по файлу (направления `core`, `greenfield`).
12. Подсистемы в этапе 1 **не переносятся и не переименовываются** (кроме синонима
    `Сервис/НастройкиПрограммы` → «Параметры»): права ролей не меняются. Перестройка групп разделов —
    этапы 2–6.
