# Номер заказа клиента в заказе покупателя

Запрос клиента через владельца 2026-11-10: «В документе Заказ покупателя нужен реквизит с номером заказа клиента».
Ответы владельца: печатать — да; переносить в реализацию — нет, брать из основания. Сборка 2.0.17.10.

## Что есть

- `Документ.ЗаказПокупателя` уже имеет реквизиты `НомерВходящегоДокументаЭлектронногоОбмена` (синоним «Номер (вх)»,
  Строка(10)) и `ДатаВходящегоДокументаЭлектронногоОбмена` (Дата). Ни один модуль их не пишет и не читает; в формах их
  нет — только в тексте запроса динамического списка `ФормаСписка` без колонок. Папок ExchangePlans / HTTPServices /
  WebServices в конфигурации нет.
- Фирменная печать (`ФирменнаяПечать.СведенияДокумента`) печатает строкой сведений `Шапка.Основание` + договор +
  комментарий во всех товарных формах. Реализация уже кладёт туда «Заказ № N от D» по `Реализация.Основание`
  (`Документы.РеализацияТоваровУслуг.ДанныеФирменнойПечати`), заказ (проформа, бланк заказа, счёт без реализаций) —
  ничего (`Документы.ЗаказПокупателя.ДанныеФирменнойПечати`). Счёт из заказа с реализациями печатается адаптером
  реализации.

## Что делаю

1. **Реквизиты.** Имена и uuid не меняю (данные клиентов сохраняются; внешние интеграции по имени, если есть, не
   ломаются). Синонимы: «Номер заказа клиента» / «Дата заказа клиента» на ru/fr/en/es, подсказки. Длина номера
   10 → 50 (номера вида «PO-2026-001234»; реструктуризация — только расширение строки, данные не теряются).
   Комментарий в mdo: реквизиты — номер и дата заказа клиента, имена исторические.
2. **Карточка** `ФормаДокумента`: в `ГруппаШапкаПравая` после `Договор` горизонтальная группа `ГруппаЗаказКлиента`
   (заголовок не показывается): поле номера с заголовком «Заказ клиента №» и поле даты с заголовком «от», формат даты
   без времени. По `docs/FORMS-STYLE.md`; `<visible>true</visible>` у всех элементов. Форма e-commerce — без
   изменений.
3. **Список** `ФормаСписка`: колонка «Заказ клиента» (номер) после «Клиент»; шрифт шапки по `colfont.py`; поиск по
   строке поиска работает по колонке.
4. **Печать** (строка сведений, формат данных печати не меняется — ключ `Основание` уже есть, это строка):
   - заказ (проформа, бланк заказа, счёт без реализаций): `Шапка.Основание` = «Ваш заказ № X от D» на языке печати
     (дата пустая — «Ваш заказ № X»), если номер заполнен;
   - реализация (Facture, BL, счёт, проформа реализации): к «Заказ № N от D» через «; » добавляется «Ваш заказ № X
     от D» из заказа-основания (тот же ЛЕВОЕ СОЕДИНЕНИЕ `Заказы` по `Реализация.Основание`, два поля в запрос). Акт —
     как был (основание не печатает).
   - Шаблон — новая функция `ФирменнаяПечать.ПредставлениеЗаказаКлиента(Номер, Дата, КодЯзыка)`.
   Налоговые накладные, возвраты — не трогаю (основание у них — реализация / свой документ).
4а. **Копирование** (ревью плана, P2): `ПриКопировании` очищает номер и дату заказа клиента — иначе копия
   печатала бы чужой заказ клиента.
5. **Тесты** `ТестыДокументов`: данные фирменной печати реализации по заказу с номером клиента — `Шапка.Основание`
   содержит «Заказ № …» и номер клиента на ru/fr; заказ без номера — основание реализации прежнее; проформа заказа с
   номером — номер клиента в основании; длина реквизита ≥ 50 по метаданным; копия заказа — без номера и даты клиента. Смок открывает обе формы.
6. **Версия** 2.0.17.10, «Что нового» на четырёх языках, хаб.
