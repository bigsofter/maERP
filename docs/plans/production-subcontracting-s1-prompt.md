# S1: способ изготовления и процент потерь в технологической карте

Промпт этапа. Общий промпт волны — `docs/plans/production-subcontracting-prompt.md`, план —
`docs/plans/production-subcontracting.md` (редакция 6). Читать оба перед началом, плюс `CLAUDE.md` и
разборы плана в `.ai/reviews/production-subcontracting/`.

Сборка: `2.0.15.Y` (следующая свободная). Один коммит, одна передача на тест.

## Что делаем

У технологической карты появляются два свойства строки состава:

1. **Способ изготовления** — новое перечисление: переработчик / наше производство / оба.
2. **Процент потерь** — число, **значение по умолчанию**; фактический процент указывается позже в
   поступлении из переработки (этап S5) и правится там.

Оба видны и правятся в трёх местах: табличная часть документа `ТехнологическаяКарта`, закладка
«Техкарта» карточки номенклатуры, закладка «Материалы» рабочего места производства (только показ).

## Где именно править

| Объект | Что |
|---|---|
| `Enums/СпособыИзготовления` (новое) | переработчик / наше производство / оба, синонимы на четырёх языках |
| `InformationRegisters/СоставТехКарты` | два **ресурса**: `СпособИзготовления`, `ПроцентПотерь` |
| `Documents/ТехнологическаяКарта` | две колонки в `ТЧМатериалы`, форма документа |
| `Catalogs/Номенклатура/Forms/ФормаЭлемента` | две колонки на закладке «Техкарта» (`ТЗТехкарта`) |
| `DataProcessors/АРМПроизводство` | колонка способа изготовления на закладке «Материалы» |
| `CommonModules/ОбновлениеПрограммыОбработчики` | обработчик для существующих карт |
| `Roles/*` | права на новое перечисление |

## Четыре пути записи состава — главная ловушка этапа

Разбор плана нашёл, что новый ресурс теряется молча. Пройти **все четыре**:

1. **`ТехнологическиеКарты/Module.bsl:653`** (`ЗаписатьДокументТехкарты`) —
   `ЗаполнитьЗначенияСвойств(..., "Номенклатура, Характеристика, Упаковка, Количество")`, список
   фиксированный. **Список не расширять**: источником бывает строка `ТЧМатериалы` заказа, где новых
   полей нет, — получим «Поле объекта не обнаружено» прямо в проведении заказа. Значения новых
   ресурсов брать только когда источник — строка документа карты.
2. **`Documents/ТехнологическаяКарта/ObjectModule.bsl:88`** (`СвёрнутыйСостав`) —
   `ТЗ.Свернуть("Номенклатура, Характеристика, Упаковка", "Количество")`. Процент в ресурсы
   `Свернуть` класть **нельзя** — просуммируется (5 % + 5 % = 10 %); не перечислить — колонка
   исчезнет. Правило слияния: значения берутся из первой строки группы. Плюс проверка заполнения:
   две строки одного материала с разным способом или процентом — отказ с внятным текстом.
3. **`ТехнологическиеКарты/Module.bsl:704`** (`КлючСостава`) — новые ресурсы в ключ **не добавлять**.
   Функция общая: её зовёт и `СоставОтличается`, и публичная `КлючСоставаСтрок`, которую вызывает
   заказ по своим строкам. Добавишь — ключ заказа не совпадёт никогда, каждое проведение заведёт
   новую версию карты, а перенос состава новые колонки не захватит: способ и процент будут
   обнуляться у карты клиента ежедневно и молча.
   «Сменился только способ или процент» сверяется **отдельной** функцией, вызываемой из карточки
   номенклатуры и формы документа карты.
4. **Обработчик обновления** — правит и записи регистра, и табличную часть документов карт. Только
   регистр недостаточно: первое же перепроведение старой карты перезапишет движения из `ТЧМатериалы`
   документа с пустым значением. Образец — `ПеренестиТехнологическиеКарты` в
   `ОбновлениеПрограммыОбработчики`. Значение для существующих карт — **«наше производство»**,
   процент потерь — **0**.

## Проверка

- `scripts/lint.sh`, `scripts/refcheck.py`, `scripts/listcheck.py`, `scripts/menucheck.py` — чисто
  относительно базовой линии;
- **новый сценарий уровня 3**: запись карты со способом и процентом, свёртка двух строк одного
  материала, отказ при разных значениях в одной карте, сохранение значений при повторной записи
  карты **через проведение заказа** (ключевая проверка: значения не должны обнуляться), обработчик
  обновления на карте без значений;
- **ревизия существующих сценариев**: плоский состав и прежние ожидания зашиты в
  `DataProcessors/ТестыДокументов/ManagerModule.bsl` в блоках около строк 760–813, 1346–1508,
  3823–3888, 6436 — пройти и поправить, а не только добавить новый;
- смок на обновлённой из EDT `build/ib`;
- подъём версии и секция «Что нового» на ru/fr/en/es.

(S5), порядка обеспечения (S9), констант настроек (S8), закладки поступлений (S6), подборов (S7).

в S2 как правило остановки.
