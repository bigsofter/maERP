# Приёмка E1: технологические карты, 2.0.15.5

Реализация дополнена 2026-09-11. **E1 ещё не принят:** проверка конфигурации
и сценарии на свежей базе требуют Refresh и обновления из EDT владельцем.
Результаты прежних прогонов на `build/ib` не подтверждают эту сборку.

## Что входит

- Регистр состава, документ-версия, фасад и чтение рецептуры на дату документа.
- Карточка номенклатуры с историей, датой действия и отменой состава; единая форма
  для всех ролей, переводы, видимость характеристик и упаковки по настройкам.
- Монопольный обработчик `ПеренестиТехнологическиеКарты`, зарегистрированный на
  версии 2.0.15.2. Переносит каждую непустую старую карту с датой создания
  номенклатуры, иначе 01.01.2000; ЕИ становится упаковкой, характеристика пуста.
  Повторяющиеся материалы сворачиваются при проведении, исходная ТЧ остаётся.
- Перенос пропускает продукцию с любой записью регистра (включая будущую версию
  и маркер отмены) либо с существующим документом карты (включая черновик и
  помеченный на удаление документ). Это сохраняет уже введённые пользователем карты.
- Дата версии без времени, выбор новой или существующей карты по дню, запрет
  даты раньше последней версии (в том числе будущей), предупреждение о выпусках.
- Цены и суммы материалов, плановая себестоимость единицы, доступный выпуск по
  остаткам всех складов и потенциальная маржа по последней фактической продаже.
  При неполных закупочных ценах себестоимость и маржа не рассчитываются.
- Пять сценариев уровня 3, перечисленных в `docs/TESTING.md` и `docs/TESTS.xlsx`.

## Подготовка и машинный прогон

1. В EDT выполнить Refresh (F5) проекта `src/cf`, проверить модули и конфигурацию.
2. Обновить конфигурацию `build/ib` с реструктуризацией. Версия — **2.0.15.5**.
   Закрыть сеанс базы и агент EDT перед прогоном.
3. Выполнить `scripts/smoke.sh`, затем `scripts/doctests.sh`.
4. В `build/doctests-report.txt` должно быть **15 сценариев**, включая строки
   `ОК;ТехнологическиеКарты`, `ОК;ПереносТехнологическихКарт`,
   `ОК;СебестоимостьТехкарт`, `ОК;ДатыТехкарты`, `ОК;ПоказателиТехкарты`.
   Для проверки себестоимости включить «Производство»;
   пропуск этого сценария не закрывает производственную приёмку.

Сценарии переноса вызывают полный обработчик внутри транзакции с откатом.
Документы и движения не остаются; информационные записи журнала могут остаться.
Поэтому сценарий также выявит ошибки переноса имеющихся старых данных базы.

## Проверка обновления на копии базы клиента

1. До обновления сохранить состав нескольких старых карт, их даты создания и
   движения по стоимости у соответствующих выпусков, включая мультивыпуск.
2. Обновить **копию** базы до 2.0.15.5 и войти администратором обычным запуском:
   тестовый запуск по `/C` пропускает обычную инициализацию, поэтому один лишь
   прогон тестов не проверяет запуск обработчика механизмом обновления.
3. Проверить версию данных в `ВерсииПодсистем` и журнал «Обновление программы»:
   обработчик завершён, есть число созданных документов, ошибок нет.
4. Открыть карточки номенклатуры: прежний состав виден, дата версии соответствует
   дате создания товара (либо 01.01.2000). Старые строки ТЧ в данных сохранены.
5. Проверить заранее созданные новые карты, будущие версии, отмены и черновики:
   обновление не меняет их состав и не восстанавливает старую карту.
6. Повторный вход не создаёт новые документы. Идемпотентность самого обработчика
   дополнительно проверяется двукратным вызовом в сценарии уровня 3.
7. Заполнить материалы выпуска по перенесённой карте. Перепровести выбранные
   старые выпуски на копии и сравнить суммы с сохранёнными до обновления.
   Расхождение — ошибка переноса в конкретной базе, а не ожидаемое изменение.

## Проверка карточки и истории

- Открыть номенклатуру из списка: карточка открывается закладкой, список остаётся доступен.
- Под таблицей состава видны дата версии, ссылка на документ и кнопка истории.
  Ссылка открывает выбранную техкарту, история отбирается по текущей продукции.
  На узком окне нижняя строка переносится; блок показателей не скрыт родительской группой.

- Создать карту с двумя материалами, затем с более поздней датой оставить один:
  выпуск на старую дату содержит два материала, на новую — один.
- Сохранить карточку без правки состава: новая версия не создаётся.
- Исправить состав в тот же день: перезаписывается документ этого дня.
- Очистить состав с новой датой и сохранить: карта отменена, прежний материал
  не возвращается; история и старые выпуски продолжают видеть старый состав.
- Проверить страницу под ролью ECommerce и обычной ролью, с включённым
  производством для продукции и полуфабриката.
- Проверить выключенную и включённую опцию упаковки, аналогично характеристики.
- Открыть вчерашнюю карту и начать правку состава: дата переключается на сегодня.
  Войти в ячейку, отменить правку и сохранить карточку: новая версия не появляется.
- Выбрать дату последней карты: отображается её номер и состав; выбрать дату
  раньше неё: показана ошибка, предложен следующий день после последней версии
  либо сегодня, если оно позже. Повторить при наличии будущей карты.
- Если с выбранного дня есть проведённые выпуски, отображается предупреждение
  о ручном перезаполнении; состав уже записанных выпусков автоматически не меняется.
- Изменить материал, характеристику, количество; добавить и удалить строки:
  цены, суммы, итоги и статистика пересчитываются. Единица материала доступна
  только для просмотра. Нулевые показатели скрыты, отрицательная маржа видна.
- Проверить материал без закупочной цены: показано предупреждение, неполная
  себестоимость и маржа не выдаются за полные. Расчёты — в валюте учёта с НДС,
  без дополнительных производственных расходов; упаковки не меняют единицу нормы.

## Результаты

- Статические проверки исходников: BSL LS без новых замечаний относительно
  базовой линии; `refcheck.py` и `listcheck.py` без новых расхождений;
  `git diff --check` пройден. Согласованность версии, регистрации обработчика,
  четырёх языков описания изменений и реестра 13 сценариев проверена.
- CheckConfig, смок и 13 сценариев на 2.0.15.2: **ожидают обновления базы из EDT**.
- Обновление копии базы клиента и сверка исторических сумм: **ожидают приёмки**.
- Старую ТЧ в этом релизе не удалять; ограничение записано в `docs/RELEASING.md`
  и `docs/TECHDEBT.md`.
