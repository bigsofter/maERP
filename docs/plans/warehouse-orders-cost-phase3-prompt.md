# Промпт: ордерные склады v2 — фаза 3 (ордер — носитель партии, ордер первый)

Реализуем фазу 3 волны `docs/plans/warehouse-orders-cost.md` (maERP, 1С 8.5.1, EDT-проект `src/cf`, ветка `develop`).
Последняя сборка — 2.0.16.121 (фаза 2: регистр `СебестоимостьПродаж`, перенос истории, возврат из нового регистра).
Решения владельца В1–В7 — в плане, не переоткрывать; вопросы к ним — владельцу.

Фаза 3 закрывает **жалобу клиента**: приходный ордер создаёт партию, и выпуск списывает материал сразу после приёмки,
до оформления поступления (стоимость партии до оформления — 0, В2). Расходный ордер списывает партии, реализация на
ордерном складе получает себестоимость из списания ордеров по парам оформления. Схема «ордер первый» — на приходе и
расходе; «документ первый» — фаза 4.

Главные риски — **данные и порядок блокировок**: реструктуризация самого большого регистра `ТоварыВНаличии` (реквизит
`КодСтроки`, тип партии), двусторонний `ТоварыКОформлению` (новые измерения, без переноса — В7), ближний пересчёт пишет
движения чужого документа, нулевая стоимость не должна попасть в базы цен. Изменение существенное: `ai-review-plan`,
`ai-review`, `ai-database` и `ai-security` — обязательны.

Часы — клиент **Drissotex**: `~/Downloads/Drissotex — Ордерные склады v2: ордер — носитель партии (фаза 3).xlsx` (лист
«Отчёт», колонки Подзадача | Бизнес-польза | Техническое описание | Часы).

## Шаг 1. Детальный план фазы 3

Дописать в план раздел «Фаза 3 — детальный план» и прогнать через `.ai/bin/ai-review-plan` (обязателен) до `approve`
или `approve_with_changes`; ответ на каждый круг — таблицей «Ответ на разбор (фаза 3, круг N)» в конце плана; файлы
кругов — `.ai/reviews/warehouse-orders-cost-f3/02-plan-review-rN.json`. Если ревью уходит в фазы 4–5 — рамка круга:
готовность фазы 3 и отсутствие тупика дальше. `BACKEND_UNAVAILABLE` — результат не симулировать, остановиться и сообщить
владельцу.

Сначала — **замер** (только чтение, копии): объём `ТоварыВНаличии` и `ДополнительныеРасходы` на 2MZL и Drissotex,
число ордеров и записей `ТоварыКОформлению` на Drissotex (В7: данных ордерной схемы нет — подтвердить), время
реструктуризации `ТоварыВНаличии` на копии Drissotex.

План фазы обязан ответить:

- **метаданные**: тип `ПриходныйДокументПартии` + `ПриходныйОрдер` — каждое место типа партии; реквизит `КодСтроки` у
  `ТоварыВНаличии` и `ДополнительныеРасходы` (кто заполняет, 0 у прочих); `ТоварыКОформлению` — `Источник`,
  `КлючСтрокиИсточника`, без `Составляющая`, реквизит `КодСтрокиРегистратора`; что с текущими записями регистра (В7 —
  без переноса, но обновление не должно упасть на старых данных); `СебестоимостьПродаж.ДокументОтгрузки` +
  `РасходныйОрдер`; uuid новых объектов уникальны (tiny1C mdo-009);
- **приходный ордер**: приход партии (`Партия` = ордер, `ДатаПартии` = дата ордера, `КодСтроки`), сумма = сумма
  оформленных пар, неоформленная часть — 0; зеркало `ТоварыНаСкладах` вместо прямой физической записи;
  `ЗаказыПоставщикам`/`ПотребностиПроизводства` как сейчас; в последовательности `Основная`;
- **расходный ордер**: списание `СписатьНоменклатуру` (FIFO, комплекты по снимку, `КодСтроки`); нехватка — отказ (Р1,
  подтвердить у владельца, если меняется); автовыпуск — как сейчас; в `Основная`;
- **поступление и реализация на ордерном складе**: только финансы; пары оформления (`ТоварыКОформлению.ПарыОформления`);
  реализация — `СебестоимостьПродаж` по парам (доля строки ордера q/Q_k, целевая сумма оформленной части, остаток
  округления последней паре — Редакции 4, 7); строка без пары — «себестоимость не определена»;
- **ближний пересчёт**: поступление перезаписывает стоимостные наборы своих ордеров, расходный ордер —
  `СебестоимостьПродаж` реализаций всех затронутых строк; запись и сдвиг границы только при изменении наборов (Редакция
  5, нет цикла при восстановлении); граница — строго раньше самого раннего проведённого возврата прежней реализации
  (Редакция 11); привилегированный режим и права (кладовщик переписывает себестоимость чужой реализации);
- **блокировки**: единый порядок `МестаХранения → ТоварыВНаличии → ДополнительныеРасходы → ТоварыНаСкладах →
  ТоварыКОформлению → СебестоимостьПродаж`; ключи носителя и зеркала — в объекте блокировки источника; состав пар до
  блокировки и перепроверка после; двухсеансовая проверка параллельного проведения источника и носителя на копии;
- **допрасходы**: деление по количеству при нулевой сумме партии (и в `РаспределитьПоПозициям`); поступление допрасходов
  на поступление ордерного склада — раскладка на партии-ордера по парам; нераспределённый остаток с периодом поздней
  приёмки (Редакция 6); сдвиг границы на документы допрасходов при изменении пар;
- **защиты нулевой стоимости**: защита 1 (базы цен без неподтверждённых партий) и минимальная пометка «стоимость не
  подтверждена»; механизм неподтверждённости по зависимостям (выпуск, перемещение, передача, списавшие такую партию)
  — признак в записях или вычисление по цепочке, с тестом «до поступления → после → после восстановления»;
- **возврат от покупателя по реализации ордерного склада**: только отгруженное количество на дату возврата (ДокументОтгрузки
  = расходный ордер, момент отгрузки не позже возврата); полная защита «возвращено ≤ отгружено» при отмене ордера — фаза 4,
  явно указать границу;
- **закупочная сторона заморозки** налоговым документом (Ф2.4): закрыть с партией = ордер или оставить с причиной;
- **первая установка**: обработчик обновления (если нужен) — монопольно, в группе с нужным режимом; что видит Drissotex
  после обновления (пересчёт должен пройти выпуск 07.10 при перепроведении приходных ордеров 25.10/28.10 — или объяснить,
  почему нет и что делает владелец);
- **тесты**: сценарий `ОрдерныйСкладПартии` (раздел плана «Тесты», фаза 3) + обратный порядок реализаций, смена даты,
  отмена пары, три частичных оформления с возвратом между ними, допрасход при нулевой партии, база цен; инвариант
  `ТоварыНаСкладах` = свёртка `ТоварыВНаличии` (ордера теперь зеркалятся); реестр `docs/TESTS.xlsx`.
