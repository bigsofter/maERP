# Прибыль по продажам: из документа в аналитику, единое определение без НДС (тикет 2606233)

## Проблема

Тикет 2606233 (14.11): в документе продажи просят построчно себестоимость без НДС, прибыль без НДС и процент
прибыли, по фактической себестоимости: клиенты с минимальной наценкой продают в минус, когда первая партия по ФИФО
дороже последней закупки.

Решения владельца 2026-11-22:
- итоговые финансовые показатели на уровне документа не показывать, переход к аналитике - отчётом;
- команда - в подменю «Отчёты» шапки списка и документа; вход ещё с дашборда и из раздела «Продажи»;
- итог прибыли внизу формы убрать; при вводе подсвечивать строку с ценой ниже себестоимости;
- **единое определение прибыли без НДС везде**: выручка без НДС минус себестоимость без НДС.

## Что есть (разведка 2026-11-22)

- Отчёт `ВедомостьПоПродажам` уже считает по `Продажи` и `СебестоимостьПродаж` выручку, себестоимость, издержки,
  «валовую прибыль», «чистую прибыль», наценку, рентабельность; один вариант «Основной». Свой текст запроса в схеме.
- Определения расходятся. Документ (`РаботаСДокументамиВызовСервера.ЗаполнитьФинРезультат`): выручка без НДС минус
  `СуммаОборот`. Единая формула `РегистрыНакопления.СебестоимостьПродаж.ТекстПродажССебестоимостью`, отчёт, дашборд:
  выручка с НДС минус `СуммаОборот`.
- Себестоимость партий хранится с НДС: `ТоварыВНаличии.ManagerModule` (строки 12-14) переименовывает колонку
  `СуммаСНДС` строк поступления в `Сумма`; НДС партии ведётся отдельным ресурсом `СуммаНДС` и переносится в
  `СебестоимостьПродаж.СуммаНДС` при списании. Значит, себестоимость без НДС = `Сумма - СуммаНДС`, данные есть,
  реструктуризация не нужна.
- Потребители единой формулы и оборотов себестоимости: `Продажи.ManagerModule` (показатели продаж, планы),
  `Убытки.ManagerModule` (финансовый результат, EBITDA), `Дашборд`, отчёты `ВедомостьПоПродажам`,
  `ПроданныйТоварБезНакладной`, `ФинансовыйРезультат`, `ABCАнализПродаж`, `ДеньгиИСтатусыЗаказов`,
  `ОтгрузкиСИзмененнымиЦенами`, тесты `ТестыДокументов`.

## Поиск готового

Новый отчёт не нужен: `ВедомостьПоПродажам` покрывает показатели, нужны варианты настроек. Группа команд `Отчёты`
(категория «командная панель формы») есть; команды с параметром-документом в ней ещё нет, образец с
параметром-документом - `Отчеты.АнализИнвентаризаций`, с группой - `Отчеты.ТоварыВНаличии`. Плитки дашборда с
переходом в отчёт нет; ближайший образец - гиперссылка «Пересчитать» (`ДобавитьКарточкуАктуальностиСебестоимости`).
Контроль цены продажи ниже себестоимости партий склада - общий модуль `КонтрольЦенПродажи` (при проведении).

## Решение

Решение владельца 2026-11-22 после двух кругов ревью плана: **две сборки**.

- **Сборка А (этот план, 2.0.18.4):** аналитика вместо итога в документе. Расчёты, регистры и данные не меняются.
  Прибыль - в определении, которое сейчас показывает документ: выручка без НДС минус себестоимость, как она записана
  в `СебестоимостьПродаж` (поле отчёта `ЧистаяПрибыль`). Цифра отчёта по документу равна прежнему итогу формы.
- **Сборка Б (отдельный тикет, отдельный план):** единое определение «без НДС» - НДС в поправках, переносах и
  себестоимости услуг (сейчас не пишется: `ЗаписатьПеренос`, `ДобавитьПоправку`, `ДобавитьСебестоимостьУслуг`),
  обработчик обновления с пересчётом истории, перевод потребителей (`ТекстПродажССебестоимостью`, финансовый
  результат, планы продаж, ABC, дашборд), учёт неплательщиков НДС через механизм зон НДС. Запись в
  `docs/TECHDEBT.md` и `docs/ROADMAP.md`.

### А1. Варианты отчёта

В схему `ВедомостьПоПродажам` добавляются:
- вычисляемое поле `НаценкаБезНДС` = `ЧистаяПрибыль / СебестоимостьФактическая * 100` с защитой от нулевой
  себестоимости в поле и в ресурсе (как у существующего поля `Наценка`, строки 646-673: при нуле - 0; нулевая
  себестоимость допустима, например услуга без закупочной цены); ресурс - по суммам; заголовок
  «Наценка, %» в новых вариантах; существующие поля и вариант «Основной» не меняются;
- вариант «Прибыль по документам»: группировка `ДокументПродажи` - `Номенклатура`, `Характеристика`; поля -
  количество, выручка без НДС, себестоимость фактическая, прибыль (`ЧистаяПрибыль`, заголовок «Прибыль»), наценка;
  отбор `ДокументПродажи` (в списке) с пользовательской настройкой;
- вариант «Продажи в минус»: те же группировки и поля, отбор группировки нижнего уровня (документ продажи - товар -
  характеристика) `ЧистаяПрибыль < 0 И Количество > 0`, условное оформление отрицательной прибыли. Условие по
  количеству отделяет продажу ниже себестоимости от возврата: возврат пишет в `Продажи` отрицательные количество и
  выручку по исходному документу продажи (`УменьшитьВыручкуПоВозврату`) и сторнирует себестоимость; если в период
  попал только возврат, количество по товару документа не положительно и строка в вариант не попадает. Сценарий
  теста: возврат прибыльной продажи в другом периоде в «Продажи в минус» не попадает.

Детальность - товар и характеристика внутри документа, а не строка табличной части: регистр `Продажи` сворачивает
строки (`Продажи.ДанныеРеализации`), номер строки не хранится. Один товар двумя строками по разным ценам - одна
строка отчёта; ограничение - в приёмку и «Что нового». Выручка и себестоимость приходят разными записями
объединения, поэтому отбор «в минус» - на группировке по ресурсу, не на детальных записях. Поле «Валовая прибыль»
(с НДС) в новые варианты не выводится.

### А2. Команда в подменю «Отчёты»

Команда отчёта `ПрибыльПоДокументам`: группа `CommandGroup.Отчёты`, параметр - `ДокументСсылка.РеализацияТоваровУслуг`,
`ДокументСсылка.НалоговаяНакладная`, режим `Multiple`. Модуль команды: серверная функция возвращает документы
продажи (для налоговой накладной - основание и отгрузки строк; логика `ДокументыПродажиДляФинРезультата` выносится в
экспортную функцию общего модуля `РаботаСДокументамиВызовСервера`), затем открывается форма отчёта с вариантом
«Прибыль по документам», отбором по документам продажи, периодом без границ, формированием при открытии и
уникальностью по источнику. Способ передать вариант (`КлючВарианта` или готовые настройки) выбирается пробой на
клиенте - зафиксировать в плане после пробы. Права на команду - ролям, у которых есть и отчёт, и чтение
`СебестоимостьПродаж` (МенеджерПоПродажам, МенеджерПоЗакупкам); `rolecheck.py` и `menucheck.py` - без новых
расхождений.

### А3. Формы документов

Из форм документа `РеализацияТоваровУслуг` и `НалоговаяНакладная` удаляются группа `ГруппаФинРезультат` с четырьмя
полями, реквизиты формы `Себестоимость`, `Выручка`, `Прибыль`, `Наценка`, вызовы и обёртки `ЗаполнитьФинРезультат`,
сама процедура общего модуля (её тело заменяет экспортная функция документов продажи из А2). Колонки последних цен
строк остаются.

### А4. Подсветка строки ниже порога склада

Порог - тот же, что при проведении (`КонтрольЦенПродажи`): режим склада «не ниже себестоимости» или «не ниже вида
цен». Новая экспортная функция `КонтрольЦенПродажи.НомераСтрокНижеПорога(ДокОбъект)` по образцу
`ПорогиЦеныЕдиницы` (её до проведения уже вызывает редактор строки кассы). Параметр - объект документа, который
форма получает `РеквизитФормыВЗначение("Объект")`: у него текущие несохранённые данные формы, все реквизиты шапки
(в том числе `ВВалюте`, валюта, курс, кратность - сценарий теста на валютную реализацию) и ссылка записанного
документа, поэтому `МоментВремени()` и граница остатков те же, что при проведении (у нового документа - его дата).
Объект не записывается. Функция берёт `СтрокиДокумента` и `ПорогиСклада`, сравнивает `СравнитьСПорогами` только по жёстким
порогам и возвращает номера строк с нарушением. Ничего не пишет; наборы движений объекта не формирует и не читает (путь с парами расходных ордеров, которому они нужны, отсекается условием `ТолькоПоказ` до расчёта). Возвращает
пустой массив: контроль склада выключен; пользователь не видит суммы (`ПоказыватьСуммыПользователю`); ордерный склад
в режиме себестоимости (порог зависит от пар с ордерами - `ТолькоПоказ`); документ на основаниях; ошибка настройки
склада. Комплекты не подсвечиваются (контроль их пропускает) - ограничение в приёмку.

Форма реализации: реквизит строки `НижеПорога` (Булево, не хранится - колонка реквизита формы), условное оформление
полей цены и суммы строки. Пересчёт - одна процедура формы `ОбновитьСтрокиНижеПорога`, один серверный вызов; точки вызова: создание формы на
сервере, после записи; обработчики, пересчитывающие сумму строки (товар, количество, упаковка, цена, скидка, сумма,
ставка НДС, процент наценки), удаление строки; смена склада, даты, валюты, признака `ВВалюте`, курса
(`КурсВалютыПриИзменении`) и признака цены с НДС; программное изменение строк - после загрузки из Excel
(`ПослеЗакрытияФормыЗагрузки`), пересчёта валютных цен (`ПослеВопросаОПересчетеЦен`), заполнения цен и подбора.
Полный перечень точек составляется поиском всех мест модуля формы, меняющих `Объект.ТЧТовары` или реквизиты шапки
из списка, и сверяется в приёмке. Проведение не запрещается и не меняется.

### А5. Дашборд

Карточка «Продажи в минус за 7 дней» (число позиций «документ продажи - товар - характеристика» с тем же условием,
что отбор варианта: прибыль < 0 и количество > 0, и сумма их убытка - определение одно с отчётом, сценарий теста
сверяет число и сумму карточки с итогом варианта за тот же период) в
стоковом дашборде и дашборде продаж; расчёт - запросом по тем же регистрам с той же формулой, что вариант отчёта
(выручка без НДС минус `СуммаОборот`), одной экспортной функцией. Гиперссылка карточки открывает вариант «Продажи в
минус» за тот же период. Без права чтения `СебестоимостьПродаж` - прочерк, ссылки нет.

## Риски

- Определение прибыли остаётся смешанным (выручка без НДС, себестоимость с НДС) до сборки Б - в «Что нового»
  формулировка «прибыль, как раньше в документе», без слов «без НДС» про себестоимость.
- Отбор группировки по ресурсу при объединении запросов - проверяется сценарием: прибыльный товар в «Продажи в минус»
  не попадает, убыточный попадает.
- Вид группы «Отчёты» в командной панели, размещение команды с параметром-документом, открытие варианта - только
  исполнением на клиенте.
- Удаление реквизитов формы: поиск всех обращений по `src/cf` и тестам до удаления.

## Проверка

Тесты документов: сценарий отчёта - прибыль варианта «Прибыль по документам» по документу равна выручке без НДС
минус обороту себестоимости; убыточная продажа попадает в «Продажи в минус», прибыльная - нет; документы продажи
налоговой накладной; `НомераСтрокНижеПорога` - строка ниже себестоимости склада с контролем, выключенный контроль,
ордерный склад, комплект. Смок вариантов отчёта (порог `ВариантовОтчетов` +2). Тесты интерфейса: обход форм документа
и списка реализации и налоговой накладной; `видно=` - полей итога нет, команда «Прибыль по документам» есть; снимок
командной панели списка и отчёта, открытого командой. Приёмка - `.ai/reports/sales-profit-analytics-acceptance.md`.

## Принято по итогам ревью плана (круг 5, approve_with_changes)

- Доступ: итог в форме видели все роли с чтением `СебестоимостьПродаж` при включённом заверении цен (в том числе
  оператор, кладовщик, логист, казначей). Команду и отчёт получают только роли, у которых отчёт уже есть (менеджер
  по продажам, менеджер по закупкам); остальным прибыль больше не показывается. У PDV есть право просмотра прежней
  команды отчёта, но нет права использования самого отчёта, у мобильного клиента нет командной панели списка - им
  команда не выдаётся - это следует
  из решения владельца убрать финансовый результат с уровня документа. Права ролей не расширяются; в «Что нового» и в
  отчёте владельцу - явной строкой, решение о выдаче отчёта другим ролям - за владельцем.
- Подсветка и «Продажи в минус» - разные показатели: подсветка сравнивает цену строки с порогом склада (как
  проведение), отчёт считает фактически списанную себестоимость после проведения. Это пишется в подсказке признака
  строки и в «Что нового».
