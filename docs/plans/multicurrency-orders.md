# Заказы, КП и предложения поставщиков в валюте (2.0.16.24)

Третья часть валютного контура (2.0.16.22 — поступление и реализация, docs/plans/multicurrency.md;
2.0.16.23 — оплаты, docs/plans/multicurrency-payments.md). Решение владельца 2026-10-06: «делай во всех
перечисленных», работа сборками; эта — заказ покупателя, заказ поставщику, коммерческое предложение,
предложение поставщика.

## Модель — как у реализации

- Реквизиты: `ВВалюте`, `Валюта`, `КурсВалюты` (15.4, заполнение 1), `СуммаРегл`; `ТЧТовары.СуммаРегл`.
  Флажок «В валюте» на первой закладке (у предложения поставщика закладок нет — в правой группе шапки) рядом
  с «Цена включает НДС», поля валюты и курса доступны только при флажке, курс по дате из `КурсыВалют`, валюта
  договора у нового документа без строк, заголовки «Цена (EUR)»/«Сумма (EUR)», колонка «Сумма (MAD)», вопрос о
  пересчёте цен при смене валюты, без курса не записывается (`ПроверитьВалютуДокумента`).
- Общий клиент-серверный `ПересчитатьСуммыРегл` — с проверкой наличия `ТЧУслуги` (у этих документов её нет).
- Цены: построчная подстановка уже учитывает валюту (`ПреобразоватьСтрокуТаблицыВСтруктуру`); массовое
  перезаполнение (`УстановитьЦеныНаСервере` заказа покупателя и КП) получает `ВалютаДокумента`.

## Взаиморасчёты: заказ — объект в основной валюте

`ЗаказПокупателя` — объект расчётов авансов. Валютный заказ **не** становится валютным объектом расчётов:
аванс по заказу зачитывается реализацией в основной валюте (`ТЧЗачётАвансов`, 2.0.16.22), иначе остаток
аванса разошёлся бы по измерению «Валюта». Новая функция `РаботаСВалютами.ВалютаОбъектаРасчетов` (заказ
покупателя — основная валюта, остальное — `ВалютаИКурсОбъекта`) — в `Движение` обоих регистров и в
`РасчетСтрокиОплаты`. `ВалютаИКурсОбъекта` по-прежнему отдаёт валюту документа — для заполнения оплаты по
заказу (сумма заказа в валюте → валюта кассы) и печати. `ЗаказПоставщику` объектом расчётов не бывает.

## Движения

- `ЗаказыПоставщикам`, ветка `ЗаказПоставщику`: `Сумма = СуммаСНДС × курс заказа` (параметр запроса).
- `ПотребностиПроизводства`, `ИсторияЗаказовПокупателейПоСтатусам` — без сумм, не меняются.

## Ввод на основании — валюта переносится (`ЗаполнитьВалютуПоОснованию`)

- Реализация из заказа покупателя; поступление из заказа поставщику; заказ покупателя из КП и из
  реализации; заказ поставщику из предложения поставщика (цены копируются); КП из реализации.
- Заказ поставщику из заказа покупателя / по потребности и предложение поставщика из заказа покупателя
  берут цены из прайса поставщиков (основная валюта) — документ создаётся в основной валюте, как сейчас.
- Реализация «Перезаполнить цены по заказу» (обе формы): цена заказа переводится из валюты заказа в валюту
  реализации по их курсам (одна валюта — как есть).

## Печать

Заказ покупателя и КП печатаются функциями реализации (`PrintDevis*`) — подпись валюты и сумма прописью
уже берут `ВалютаИКурсОбъекта(Док)`. Заказ поставщику и запрос цен валюту не печатают — без изменений
(TECHDEBT).

## Формы-исключения

Форма заказа покупателя для интернет-магазина (`ФормаДокументаECommerce`) валюты не знает: валютный заказ
открывается в ней только для просмотра.

## Правки по ревью плана (01-plan-review-claude.md)

- P1-1/2: стадия и доля оплаты заказа (`ПроизводственныеЗаказы` 136–142, 632–722, 1001–1010; запрос списка
  заказов; блок остатков в форме заказа) сравнивают суммы в основной валюте: сумма документа —
  `ВЫБОР КОГДА ВВалюте ТОГДА СуммаРегл ИНАЧЕ Сумма КОНЕЦ` (у старых документов флажка нет).
- P1-3: тендер предложений поставщиков сортирует по сумме в основной валюте, в тексте — сумма с валютой.
- P1-4: последние цены закупки и продажи (`РаботаСДокументами.ЗаполнитьПоследниеЦены*`) переводятся в
  валюту документа — закрывает и заказ, и реализацию 2.0.16.22 (наценка в процентах).
- P2-5: ввод на основании переносит валюту, курс — на дату нового документа (нет курса — курс основания).
- P2-6: `ЗаказыПоставщикам` — приход по курсу заказа, расход по курсу поступления: остаток суммы может не
  обнулиться; регистр читает количества — записать в TECHDEBT.
- P2-7: аванс по заказу — заказ в строке оснований ПКО/поступления безналичных; тест — такой.
- P3: поступление на основании заказа покупателя — в основной валюте; печать предложения поставщика через
  `PrintDevisA4` — подпись валюты берётся сама; ECommerce-форма — копия валютного заказа сбрасывает валюту;
  колонка «Сумма (MAD)» без итога в подвале.

## Вне сборки (TECHDEBT)

Суммы заказов в валюте документа: АРМПроизводство, история ЛКП, отбор по сумме в списке, отчёт ИсторияТовара; печать заказа поставщику без валюты; остаток суммы `ЗаказыПоставщикам` при разных курсах.

## Тесты

`ЗаказыВВалюте`: заказ покупателя в EUR → реализация на основании: валюта, курс и цены перенесены;
заказ поставщику в EUR → `ЗаказыПоставщикам.Сумма` в основной валюте; поступление на основании — валюта;
ПКО на основании валютного заказа — сумма в основной валюте по курсу, аванс по заказу без валюты.
