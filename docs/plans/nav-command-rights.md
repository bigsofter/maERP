# Права ролей на команды навигации объектов — 2.0.17.38

Тикет 2605465 (Drissotex). Проверяющий 18.11: пользователю с ролями «Оператор производства» + «Складские ордера» в
разделе «Производство» не видны ни «Рабочее место производства», ни «Рабочее место закупок». В конфигураторе у ролей
нет права «Просмотр» на команды `DataProcessor.АРМЗакупки.Command.АРМЗакупки` и
`DataProcessor.АРМПроизводство.Command.АРМПроизводство`.

## Причина

Роли maERP заведены без «Устанавливать права для новых объектов» и без «Независимых прав подчинённых объектов»
(`setForNewObjects=false`, `independentRightsOfChildObjects=false`). Флажок «Права на реквизиты и табличные части по
умолчанию» распространяется только на реквизиты и ТЧ. Право «Просмотр» на **команду объекта** — отдельная запись
`<object><name>Вид.Имя.Command.Команда</name>`: без неё команда не попадает в меню раздела, в панель «Перейти» формы
и в группы «Отчёты» командной панели, даже если на сам объект у роли «Просмотр»/«Использование» есть.

Сейчас такие права выданы только командам печати (rolecheck п. 2, 2.0.16.135/136) и отдельным командам
(VentesEnDetail, РегистрацияИзменений…). Команды навигации у внутренних ролей видны только полноправным ролям
(Администратор, Руководитель — `setForNewObjects=true`).

## Почему не поймали

- 2.0.16.133: живая проверка роли «Складские ордера» смотрела открытие АРМ закупок при запуске — это `ОткрытьФорму`,
  права на команду ей не нужно. Меню раздела «Производство» под урезанным пользователем не открывали.
- `scripts/rolecheck.py` проверял только команды печати, `scripts/menucheck.py` строит меню раздела по метаданным
  без учёта ролей.
- Разбор 18.11 вывел «доработка не нужна» по метаданным, без живой проверки меню.

## Безопасность

Только «Просмотр» команд объектов, на которые у роли уже есть «Просмотр»/«Использование»: доступ к данным не
расширяется, команды открывают те же формы, что роль уже открывает. Проверить по ревью:
- ОператорПроизводства (суммы скрыты): `Report.ТоварыВНаличии` — отчёт роли уже доступен (View), команда в группе
  «Отчёты» карточки номенклатуры только открывает его; суммы в нём под теми же правами. АРМ закупок оператор
  получает только в паре со «Складскими ордерами» (режим приёмки без цен — 2.0.16.133).
- Казначей: `Хозрасчетный.ДвиженияДокументаБУ` — регистр Казначею уже доступен на чтение.
- Действия (EMail, Принять/Отклонить/Закрыть потребности) не выдаются.
- **Дашборд** (ai-security, круг 1, P0: команда `БазовыйДашборд` у роли без чтения `Продажи`, показатели продаж
  читаются привилегированно). Новой выдачи данных команда не даёт: форма `Обработка.Дашборд.Форма.БазовыйДашборд`
  уже стоит на начальной странице (`Configuration/HomePageWorkArea.hpwa`, видимость `common=true`, скрыта только
  для `ОператорПроизводства`) и открывается у всех этих ролей при каждом запуске с теми же закладками. Оператору
  производства форма показывает только производственную закладку (`РольДоступна("ОператорПроизводства")`). Сам
  привилегированный путь показателей продаж — существовавший до сборки, записан в TECHDEBT («Дашборд показывает
  продажи ролям без чтения регистра Продажи»), решение о нём — у владельца.

## Не делаем

- Внешние роли (Клиент, ECommerce, ОбменМобильнаяДоставка, ЛичныйКабинет, MobileClient) — их меню отдельное
  решение владельца; запись в TECHDEBT.
- `CommandGroup.EMail` у Казначея/Кладовщика (заказ поставщику), у менеджеров (сверка) — TECHDEBT с вопросом
  владельцу.
