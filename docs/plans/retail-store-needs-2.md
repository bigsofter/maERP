# Сборка 2.0.17.5: потребности точек — список с исполнением и «Заполнить по анализу» (`retail-store-needs-2`)

Волна 2 мастер-плана `docs/plans/retail-chain.md`, сборка 2.2 (2.1 — `docs/plans/retail-store-needs.md`, 2.0.17.4).
Сборка 2.3 (2.0.17.6, свой план) — строка «Пополнение точек» в АРМ закупок, оповещения и получатели по складу,
история системных сообщений.

## 1. Список потребностей — рабочее место склада и точки

Собственная форма списка `Документ.ПотребностьТорговойТочки.ФормаСписка` (вместо автоформы): динамический список с
произвольным запросом — шапка документа и итоги регистра `ПотребностиТорговыхТочек` по потребности:

- колонки: дата, номер, точка, склад снабжения, статус, **состояние исполнения**, запрошено, принято, отгружено,
  получено, желаемая дата, **просрочена**, ответственный, комментарий;
- состояние — то же правило, что `ПотребностиТорговыхТочек.СостояниеИсполнения` (выражение ВЫБОР в запросе:
  у «Принята»/«Закрыта» с отгрузкой — частично отгружена / отгружена / получена; иначе статус);
- просрочена — желаемая дата **заполнена** и раньше начала текущего дня (параметр `НачалоДня`, ставится при
  создании формы и при каждом обновлении списка командой «Обновить» — `ПриАктивизации`/оповещение не нужны: форма,
  оставленная открытой на ночь, обновится по команде) у отправленной или принятой потребности с неотгруженным
  остатком (у отправленной — весь запрошенный, у принятой — принято больше отгруженного);
- «запрошено» — сумма `Количество` строк документа (регистр хранит запрошенное только у проведённых статусов:
  черновик и отклонённая движений не имеют); принято, отгружено, получено — итоги регистра;
- итоги регистра — подзапрос остатков, сгруппированный по `Потребность` (как список `ПриходныйОрдер` с
  `ТоварыКОформлению`); `listcheck.py`.
- Команды документа (отправить, принять, отклонить, закрыть, вернуть в черновик, получить отгрузку, история
  статусов) и «Создать на основании → Перемещение» — в командной панели списка, как в автоформе; после команды
  список обновляется оповещением (`ОповеститьОбИзменении` уже есть).
- Права: точка видит только свои потребности (RLS документа, 2.0.17.4); роль точки получает чтение регистра
  `ПотребностиТорговыхТочек` **с тем же ограничением** по измерению `Точка` (иначе соединение в запросе списка
  падает «недостаточно прав»), склад — без ограничения.

## 2. «Заполнить по анализу»

Команда документа `ЗаполнитьПоАнализу` (только «Черновик», своя точка или доверенный — те же проверки записи):
заменяет строки рекомендациями. Серверная функция `ПотребностиТорговыхТочек.РекомендацииТочки(Точка,
ИсключитьПотребность)` → таблица `Номенклатура, Характеристика, Количество` + справочные колонки
(продажи в день, остаток, в пути, открыто, минимум, максимум) — для протокола в комментарии не пишутся.

- **Права**: рекомендации читают продажи, остатки, нормативы и регистр потребностей, на которые у роли точки и у
  `Кладовщик` прав может не быть: `РекомендацииТочки` проверяет `ПотребностиТорговыхТочек.СвояТочка(Точка)` и
  после этого читает данные **привилегированно** (только чтение, результат — количества товаров своей точки).
- Позиции: товары с продажами точки за период анализа (`РегистрНакопления.Продажи.Обороты`, `МестоХранения` =
  точка, операции продажи и возврата — как отчёт `ТоварыДляЗаказа`) и товары с минимальным остатком точки
  (`МинимальныйОстатокПоСкладам`); услуги и комплекты не берутся.
- Продажи в день = количество продаж за период / дней периода (а не средняя цена — ошибка клиента не переносится).
- Остаток точки — `ТоварыВНаличии.Остатки` по точке; в пути — `Отгружено − Получено` регистра потребностей по
  точке; открыто — по другим потребностям этой точки: отправленные — запрошено, принятые — принято − отгружено
  (текущий документ исключается).
- **Расчёт по строкам «товар + характеристика»** (продажи, остаток, в пути, открыто — в этом разрезе):
  потребность строки = Макс(0, продажи в день × дней запаса − остаток − в пути − открыто), округление вверх до целого.
- **Нормативы — на товар целиком** (`МинимальныйОстатокПоСкладам` без характеристики), применяются к сумме по
  товару, а не к каждой характеристике: покрытие товара = Σ остаток + Σ в пути + Σ открыто + Σ потребность строк.
  Норматив 0 — не задан (`ЗаписатьМинимумыПоСкладам` пишет 0 для пустого): минимум 0 не добавляет, максимум 0 не
  ограничивает. Минимум: если покрытие меньше минимума, недостача добавляется к строке товара с наибольшими
  продажами (её характеристика точная). Товар без продаж — строкой с пустой характеристикой, **только если у него
  нет характеристик** (`ХарактеристикиНоменклатуры` с этим владельцем, не помеченные); товар с характеристиками без
  продаж в строки не попадает — команда сообщает их список («укажите характеристику вручную»): пустая
  характеристика не совпала бы с перемещением, а у принятой строку не поправить. Максимум: если покрытие больше
  максимума, превышение снимается со строк товара, начиная с наименьших продаж, не ниже 0. Так норматив не
  размножается по характеристикам. Недостача добавляется округлённой вверх, превышение снимается округлённым вниз —
  количества строк остаются целыми.
- Строки с потребностью 0 не попадают. В документ строка пишется с `Количество` и `КоличествоУпаковок` = рекомендации
  (упаковка пустая, коэффициент 1 — TECHDEBT 2.0.17.1), коды строк — `ЗаполнитьКодыСтрок`.
- Настройки точки — новые реквизиты `МестаХранения`: `ДнейЗапаса` (Число 3,0; 0 — 14) и `ДнейАнализаПродаж`
  (Число 3,0; 0 — 30), в форме склада — группа «Снабжение» рядом со складом снабжения.
- Запрос — пакетом с временными таблицами (позиции, продажи, остатки, в пути, открыто), без запросов в цикле.

## Тесты (`ТестыДокументов`)

1. `ПотребностиСписок`: запрос формы списка (тот же текст — функция модуля менеджера `ТекстЗапросаСписка`)
   по потребности из основного пути — запрошено / принято / отгружено / получено и состояние совпадают с
   `СостояниеИсполнения`; просроченная — признак.
2. `ПотребностиАнализ`: точка с продажами 30 единиц за 30 дней (реализации с точки), остаток 5, дней запаса 14,
   открытая потребность 3 → 14 − 5 − 3 = 6; тот же товар с минимумом 20 → недостача 20 − (5 + 3 + 6) = 6 добавлена →
   12; с максимумом 10 → превышение снято → 2; товар без продаж с минимумом 4 и остатком 0 → 4 (пустая
   характеристика); заполнение черновика серверной функцией команды (`ПотребностиТорговыхТочек.ЗаполнитьПоАнализу`)
   — строки с `Количество` = `КоличествоУпаковок`. Клиентская команда — регресс человека (кнопка на черновике).

Человек: список склада — колонки исполнения, отбор по точке и состоянию; точка видит только свои потребности.

## Риски

- Динамический список с подзапросом остатков регистра — на больших объёмах; итоги регистра по `Потребность`
  (измерение индексировано).

## Статус ревью плана

- Круг 1 — reject: рекомендации — после проверки своей точки, чтение привилегированно; нормативы — на товар
  целиком (недостача к строке с наибольшими продажами, превышение — со строк с наименьшими); количество упаковок в
  строках; просрочка — по заполненной дате и началу дня.
- Круг 2 — reject: норматив 0 — не задан; товар с характеристиками без продаж не получает строку с пустой
  характеристикой (сообщение); «запрошено» — из строк документа.
- Круг 3 — approve_with_changes: целые количества после нормативов; клиентская команда — регресс человека. Внесено.
