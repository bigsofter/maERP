# Варианты технической интеграции независимого ERP-вендора во французскую экосистему электронных счетов (состояние на 15.10.2026)

Контекст терминов. PA — Plateforme Agréée (бывш. PDP, переименование июль 2025). PPF — Portail Public de Facturation (государственная платформа, с 2024 г. сведена к аннуаиру и концентратору данных). «Solution compatible» (SC) — официальный ярлык DGFiP для ПО, которое само не иммматрикулировано и работает через PA; в быту это и есть бывший «Opérateur de Dématérialisation» (OD). Сроки реформы: с 01.09.2026 все компании обязаны принимать счета через PA, крупные и ETI — выставлять; PME/микро — выставлять с 01.09.2027 — [peppol.org, профиль Франции](https://peppol.org/learn-more/country-profiles/france/); [impots.gouv.fr, Partenaires](https://www.impots.gouv.fr/facturation-electronique-et-plateformes-partenaires).

Собственный расчёт по официальным файлам (см. ниже): на 13.10.2026 в списке DGFiP 155 иммматрикулированных PA + 11 с полным досье, ожидающих тестов интероперабельности.

## Вопрос 1. Вариант A — самому стать Plateforme Agréée: требования, сроки, стоимость, реалистичность

### Takeaway
Иммматрикуляция открыта и продолжает выдаваться (последняя дата в официальном списке — 28.08.2026), но обязательными являются действующий сертификат ISO/IEC 27001 на весь контур выставления/приёма счетов, хостинг и персонал в ЕС (SecNumCloud у хостера, если хостинг внешний), тесты интероперабельности с PPF и с другой PA за 3 месяца, аудит соответствия за 1 год, надзорный аудит за 2 года, продление каждые 3 года; плюс де-факто членство в OpenPeppol и сертифицированный Access Point. Для команды из нескольких разработчиков это проект на 9–18 месяцев и десятки тысяч евро только на ISO 27001, не считая эксплуатации — путь нереалистичен без выделенного бюджета на compliance.

### Cited Findings
- Подача заявки — онлайн на demarche.numerique.gouv.fr (`/commencer/immatpdp`); инструкцию ведёт «Service d'immatriculation des plateformes agréées» (SIM, Лилль), контакт immat.pdp@dgfip.finances.gouv.fr; документы-основания: décret n° 2022-1299 (07.10.2022) и décret n° 2024-266 (25.03.2024) — [Guide utilisateur DGFiP, MAJ 10/12/2025 (PDF)](https://www.impots.gouv.fr/sites/default/files/media/1_metier/2_professionnel/EV/2_gestion/290_facturation_electronique/guide_utilisateur_fe_ds_immatriculation_pdp.pdf).
- Перечень пьес досье (гид, стр. 9): SIREN + Kbis < 3 мес.; документ о мерах защиты персональных данных (ст. 32 RGPD); «attestation de certification ISO/IEC 27001 en cours de validité»; декларация об эксплуатации ИС из ЕС без трансфера данных за пределы ЕС; при внешнем хостинге — решение ANSSI о квалификации SecNumCloud хостера; обязательство обновлять данные в центральном аннуаире (ст. 289 bis III CGI); отчёт аудита соответствия (в течение года); техописание процесса отправки/приёма счетов и данных e-reporting; описание аутентификации пользователей; описание извлечения и передачи данных в сроки администрации; защищённый протокол связи; отчёты тестов интероперабельности с PPF и с другой PA — «dans un second temps après validation du dossier» — [тот же гид](https://www.impots.gouv.fr/sites/default/files/media/1_metier/2_professionnel/EV/2_gestion/290_facturation_electronique/guide_utilisateur_fe_ds_immatriculation_pdp.pdf).
- ISO 27001 (гид, стр. 15): сертификат должен покрывать «l'ensemble des infrastructures, outils, services et éléments d'organisation informatique» для выставления/передачи/приёма счетов и передачи данных; «doit avoir une validité de 3 ans. Une certification en cours de réalisation n'est pas recevable, de même que toute certification autre que la certification ISO 27001 (certification BSI…) qui entraînera le rejet» — [гид DGFiP](https://www.impots.gouv.fr/sites/default/files/media/1_metier/2_professionnel/EV/2_gestion/290_facturation_electronique/guide_utilisateur_fe_ds_immatriculation_pdp.pdf).
- Локализация (гид, стр. 16–17): письмо-обязательство об эксплуатации ИС с территории ЕС + подтверждения: расположение серверов (кроме случая SecNumCloud-хостера), расположение персонала и подрядчиков, механизмы запрета доступа из третьих стран. Если SecNumCloud хостера ещё в процессе — приложить письмо ANSSI (jalon J0), саму квалификацию можно предоставить не позднее сдачи аудиторского отчёта — [гид DGFiP](https://www.impots.gouv.fr/sites/default/files/media/1_metier/2_professionnel/EV/2_gestion/290_facturation_electronique/guide_utilisateur_fe_ds_immatriculation_pdp.pdf).
- Все пьесы — на французском (или с заверенным переводом) и в формате подписанного PDF «niveau avancé 2 minimum» — [гид DGFiP](https://www.impots.gouv.fr/sites/default/files/media/1_metier/2_professionnel/EV/2_gestion/290_facturation_electronique/guide_utilisateur_fe_ds_immatriculation_pdp.pdf).
- Тесты интероперабельности (гид, стр. 21): после валидации досье — «émission, réception et transmission de factures avec le portail public» и обмен с другой PA «via une convention bilatérale ou un protocole d'échange en réseau»; срок 3 месяца с даты валидации досье или с даты открытия тестовой среды PPF — [гид DGFiP](https://www.impots.gouv.fr/sites/default/files/media/1_metier/2_professionnel/EV/2_gestion/290_facturation_electronique/guide_utilisateur_fe_ds_immatriculation_pdp.pdf).
- Аудит соответствия — не позднее 1 года с уведомления о выдаче номера, независимым органом/лицом, по перечню пунктов arrêté от 07.10.2022; номер выдаётся на 3 года с продлением, досье на продление — за 5 месяцев до истечения (art. 242 nonies C annexe II CGI) — [гид DGFiP](https://www.impots.gouv.fr/sites/default/files/media/1_metier/2_professionnel/EV/2_gestion/290_facturation_electronique/guide_utilisateur_fe_ds_immatriculation_pdp.pdf).
- Marque blanche / grise (гид, стр. 20): если кандидат использует целиком решение уже иммматрикулированной PA (cas n°1) — к досье прилагаются договор с издателем PA, расположение серверов кандидата, описание связки SI↔PA, и «ATTENTION, la certification ISO27001 en cours de validité de la PDP candidate est demandée»; cas n°2 (свой портал/аутентификация поверх чужой PA) — свой описатель аутентификации, ISO 27001 поддерживающей PA, RGPD-документ, SecNumCloud для облачной аутентификации. Вне этих двух случаев — «processus d'immatriculation dit classique», поставщик части решения считается субподрядчиком — [гид DGFiP](https://www.impots.gouv.fr/sites/default/files/media/1_metier/2_professionnel/EV/2_gestion/290_facturation_electronique/guide_utilisateur_fe_ds_immatriculation_pdp.pdf).
- Décret n° 2026-677 от 27.07.2026 (JO 28.07.2026, в силе 29.07.2026): уточняет тип сертификации в досье, добавляет обязательство «produire un rapport d'audit de surveillance dans les deux ans suivant la délivrance de son numéro d'immatriculation», «informer sans délai l'administration de tout changement substantiel», «communiquer l'identité des personnes qui la contrôlent»; PPF «n'est plus présenté comme une plateforme gratuite d'émission et de réception de factures», а как инструмент аннуаира и передачи данных — [LégiFiscal, 06.08.2026](https://www.legifiscal.fr/actualites-fiscales/4580-facturation-electronique-decret-27-juillet-2026.html); PA, зарегистрированные до 29.07.2026, для продления должны подать надзорный аудит со второго года и подтвердить уведомление о контролирующих лицах в 2 месяца — [сводка поиска по LexisVeille / Lemag-juridique](https://www.lexisveille.fr/facturation-electronique-le-cadre-reglementaire-de-la-generalisation-est-precise); Sovos описывает это как «formal abolition of the PPF and the shift to a fully PA-centric ecosystem» и новый «mid-cycle audit» — [Sovos](https://sovos.com/regulatory-updates/global-vat/france-e-invoicing-final-decree-sept-2026/). Текст декрета на Légifrance (JORFTEXT000054499487) мне открыть не удалось (403).
- Официальный список PA (страница изменена 13/10/2026) разбит на два файла: «Liste des opérateurs satisfaisant à l'ensemble des conditions, incluant les tests d'interopérabilité» (файл `liste_pa_attente_rapport_audit.xlsx`) и список с полным досье, ожидающих тестов (`liste_pa_attente_test_interop.xlsx`) — [impots.gouv.fr, список PA](https://www.impots.gouv.fr/je-consulte-la-liste-des-plateformes-agreees); файлы: [xlsx 1](https://www.impots.gouv.fr/sites/default/files/media/1_metier/2_professionnel/EV/2_gestion/290_facturation_electronique/listes_plateformes_agreees/liste_pa_attente_rapport_audit.xlsx), [xlsx 2](https://www.impots.gouv.fr/sites/default/files/media/1_metier/2_professionnel/EV/2_gestion/290_facturation_electronique/listes_plateformes_agreees/liste_pa_attente_test_interop.xlsx). - Госпошлины за иммматрикуляцию в гиде и на странице Partenaires не упоминаются — [impots.gouv.fr, Partenaires](https://www.impots.gouv.fr/facturation-electronique-et-plateformes-partenaires).

### Inferences
- Для 1C-вендора с несколькими разработчиками путь A означает: ISO 27001 на всю инфраструктуру (включая хостинг во Франции/ЕС с SecNumCloud-провайдером), собственный Peppol AP/SMP (без него другие PA вправе отказать в прямом подключении), ежедневная реплика аннуаира, e-reporting в PPF, три аудита за цикл. Минимальный бюджет — порядка нескольких десятков тысяч евро на старте и столько же ежегодно; срок — не менее года.
- Вариант «marque blanche» (cas n°1 гида) снижает технический объём, но не снимает требований по ISO 27001 (нужен сертификат поддерживающей PA и своё досье), поэтому «стать PA на чужом движке» всё равно означает отдельную иммматрикуляцию.
- Регистрация не закрыта: номера выдаются ежемесячно и после 01.09.2026 (6 в августе 2026).

### Gaps
- Не найден официальный перечень «points de conformité» аудита (arrêté 07.10.2022) и типовая стоимость аудита соответствия PA.
- Полный текст décret 2026-677 не прочитан (Légifrance отдаёт 403); детали «нового типа сертификации» и Peppol-обязанностей известны только из вторичных источников.
- Размер взноса OpenPeppol за членство не подтверждён источником.
- Государственная пошлина за иммматрикуляцию: явного упоминания нет — вероятно, отсутствует, но это не подтверждено.

## Вопрос 2. Вариант B — «Solution compatible» (бывш. OD): ERP, подключённый к одной или нескольким PA по их API

### Takeaway
Это основной и официально предусмотренный путь для ПО: DGFiP с сентября 2025 выдаёт ярлык «Solution compatible – Facturation électronique» для ПО, раккордированного к PA. Для ISV существуют минимум четыре публично открытых варианта: Pennylane (бесплатно для издателей, «API REST AFNOR», marque grise, 120+ издателей), iopole (API-first, B2B2B, sandbox, цены по запросу), SuperPDP (публичный прайс 0,01→0,0025 € за счёт, OAuth2 client credentials, marque grise) и международные Peppol-провайдеры с открытой документацией (B2Brouter, Storecove). У крупных «закрытых» PA (Cegid/EBP, Qonto, Tiime, Odoo) публичной ISV-API не найдено.

### Cited Findings
**Регуляторная рамка «solution compatible»**
- Ярлык DGFiP (сентябрь 2025): «la solution compatible n'est pas immatriculée par l'administration. Elle ne peut donc ni transmettre les factures directement à l'administration fiscale, ni agir en tant qu'intermédiaire officiel… Elle doit obligatoirement être raccordée à une plateforme agréée pour pouvoir utiliser ce label» — [DGFiP, Présentation des labels (PDF)](https://www.impots.gouv.fr/sites/default/files/media/1_metier/2_professionnel/EV/2_gestion/290_facturation_electronique/fe_presentation-des-labels.pdf); хартия логотипа «solution compatible» и règlement d'usage марки PA — на странице [Partenaires](https://www.impots.gouv.fr/facturation-electronique-et-plateformes-partenaires).
- «Une solution compatible, anciennement opérateur de dématérialisation, n'est pas immatriculée. Elle prépare les factures mais s'appuie sur une plateforme agréée partenaire pour la transmission» — [blog Tiime](https://blog.tiime.fr/api-facturation-electronique-gestion).
- Три канала подключения ERP→PA, которые встречаются на рынке: SFTP (асинхронный файловый обмен), проприетарное REST API (один коннектор на PA), API AFNOR XP Z12-013 (общая грамматика, но частичное покрытие); до подписания — получить письменное подтверждение доступных каналов — [ma-facture-electronique.org, API PA](https://ma-facture-electronique.org/formats-normes/api-plateforme-agreee/) (сайт с партнёрскими ссылками Pennylane/Indy).

**Pennylane (PA с 11.12.2025 по официальному списку)**
- Программа «Solution Compatible PA»: «+120 éditeurs» подключены; «API REST AFNOR» для отправки/приёма; конвертация Factur-X/EDI/PDF signé/UBL/CII; выделенная тестовая среда (sandbox); «0€: aucun frais de licence ou d'usage pour votre solution»; онбординг 3 шага, «2 à 4 semaines en moyenne»; партнёрский договор с клаузой о non-sollicitation; только marque grise (Pennylane остаётся идентифицирована как PA, не marque blanche); PA только для французских клиентов, для международных — Peppol; заявка — Typeform «Devenez partenaire gratuitement» — [pennylane.com/fr/facture-electronique-scpa](https://www.pennylane.com/fr/facture-electronique-scpa).
- Публичная документация API: эндпоинт `POST /api/external/v2/e-invoices/imports` (multipart: `file`, `type` = customer|supplier; scope `e_invoices:all`; статус BETA) — импорт e-счёта в Pennylane, не отправка через PA — [pennylane.readme.io changelog](https://pennylane.readme.io/changelog/v2-e-invoices-import-endpoint); на форуме докуменации есть вопрос об отсутствии в публичном API вызовов для работы с PA без официального ответа — [pennylane.readme.io/discuss](https://pennylane.readme.io/discuss) (тред по ссылке из поиска открывался с 404). Т.е. «API REST AFNOR» для партнёров выдаётся по договору, а не как публичная документация.

- Ярлык «Solution compatible» получается не аудитом, а фактом раккордирования к PA + соблюдением хартии логотипа — административно дёшев.

## Вопрос 3. Вариант C — Peppol: свой Access Point или использование чужого; роль норм AFNOR; open-source стеки

### Takeaway
Peppol во Франции — транспорт между PA, а не канал для ERP: PASR France требует, чтобы сервис-провайдер Peppol был иммматрикулированной PA, а XP Z12-013 — это API «предприятие↔PA», не Peppol. Нет пути «ERP → Peppol → PA получателя» в обход своей PA. Open-source AS4-стеки (Oxalis, phase4/phoss-ap, Domibus, Holodeck B2B, phoss-SMP) существуют, но полезны только тому, кто идёт по варианту A.

### Cited Findings
- «La DGFiP est devenue Autorité Peppol pour la France» (с 08.07.2025); PASR France — пример требования: «l'obligation d'être immatriculée en tant que plateforme agréée»; процесс для провайдера: членство OpenPeppol → конвенция с Peppol France → тесты с PKI-сертификатами OpenPeppol → продуктив; «L'autorité Peppol France n'est pas compétente pour la gestion des certificats PKI» — [impots.gouv.fr, Rejoindre le réseau Peppol](https://www.impots.gouv.fr/rejoindre-le-reseau-peppol).
- Форматы B2B через Peppol AP во Франции (с середины 2025): Factur-X (PDF/A-3), UBL EN16931 France CIUS и EXTENDED-CTC-FR, UN/CEFACT CII France CIUS и EXTENDED-CTC-FR, CDAR (статусы), Peppol BIS 3.0, Peppol Invoice Message Response; PASR — на вики OpenPeppol — [peppol.org, France](https://peppol.org/learn-more/country-profiles/france/); в списке PASR Франция с датой утверждения 2026.02.25 — [OpenPeppol wiki, PASR](https://openpeppol.atlassian.net/wiki/spaces/AF/pages/2889318401/Peppol+Authority+Specific+Requirements) (страница сама по себе не отдаёт текст через fetch).
- Обязательные capability в SMP для членов Peppol (FNFE, июль 2026): Factur-X (BASIC WL, EN16931, EXTENDED), UBL Invoice/CreditNote EN16931 и EXTENDED-CTC-FR, CII EN16931 и EXTENDED-CTC-FR, CDAR, UBL PEPPOLBIS3 Invoice/CreditNote («obligatoire dans le réseau Peppol»); синхронизация адресов аннуаира PPF с SML/SMP; статусы возвращаются на адрес C1 в SBDH — [FNFE-MPE Check-List (PDF)](https://fnfe-mpe.org/wp-content/uploads/2026/09/2026-09-07-RFE-Check-List-Demarrage-Volet-B-VF.pdf).
- Декрет 07.10.2022 допускает два пути интероперабельности PA↔PA: двусторонняя конвенция или сетевой протокол; при 149 PA (22.09.2026) это 11 026 возможных пар, поэтому сеть (Peppol, AS4) стала фактическим «transport backbone»; «Companies connect only through a PA… Non-PA tools can instead be a Solution Compatible (interfacing with a PA via XP Z12-013) or an Opérateur de Dématérialisation» — [ma-facture-electronique.org, interopérabilité](https://ma-facture-electronique.org/plateforme-agreee/interoperabilite/).
- Разделение норм: XP Z12-012 — форматы и профили сообщений Facture и статусов; XP Z12-013 — API SI предприятий ↔ PA; XP Z12-014 — cas d'usage B2B (44 сценария) — [impots.gouv.fr, spécifications externes](https://www.impots.gouv.fr/portail/specifications-externes-b2b); [ma-facture-electronique.org](https://ma-facture-electronique.org/plateforme-agreee/interoperabilite/). Ни один источник не описывает XP Z12-013 как «PA-PA на базе Peppol» — формулировка в задании неточна: PA-PA идёт по Peppol/PASR + XP Z12-012/014, а Z12-013 — это ERP↔PA.
- Open-source AS4 Access Point: Domibus, Holodeck B2B, Oxalis, phase4; SMP: phoss-SMP; «The software has not been accredited by OpenPeppol» — [peppol.org, Links to Software](https://peppol.org/tools-support/links-to-software/). Oxalis 6.0.0-RC3 поддерживает «France Peppol POC», требует Java 11; с ноября 2020 сопровождается NorStella Oxalis Community — [GitHub Oxalis release](https://github.com/OxalisCommunity/oxalis/releases/tag/v6.0.0-RC3); phase4 — встраиваемая Java-библиотека AS4 с поддержкой Peppol, standalone — phoss-ap — [GitHub phax/phase4](https://github.com/phax/phase4).
- По датасету FNAE 131 из 158 PA сертифицированы как Peppol AP, 82 — как SMP (04.08.2026) — [data.gouv.fr](https://www.data.gouv.fr/datasets/liste-des-plateformes-agreees-pour-la-facturation-electronique).

### Inferences
- Для ERP-вендора Peppol имеет смысл только через PA/провайдера с API (Storecove, B2Brouter, iopole, SuperPDP — все четыре сертифицированы как AP). Собственный AP на Oxalis/phase4 оправдан лишь внутри варианта A.
- Генерировать в ERP стоит UBL EN16931 (универсален в Peppol) и/или Factur-X; формат доставки получателю всё равно конвертирует PA.

### Gaps
- Текст PASR France (версия 2026.02.25) не прочитан — неизвестны точные схемы идентификаторов (SIREN/SIRET) и требования к безопасности.
- Не найдено, допускает ли PASR участие «Peppol-only» провайдера, не являющегося PA, для нерегламентированных потоков.

## Вопрос 4. API PPF (аннуаир, концентратор): кому доступны, есть ли публичный поиск PA по SIREN/SIRET, тестовая среда

### Takeaway
Прямого API PPF для ERP нет: запись в аннуаир делают только PA, программная консультация идёт через API PA (XP Z12-013 покрывает «consultation de l'annuaire»), а тестовая среда PPF открывается кандидатам в PA в рамках иммматрикуляции. Публично существуют веб-консультация аннуаира (с 18.09.2025) и спецификации/Swagger PPF (v3.2 от 30.04.2026) для изучения.

### Cited Findings
- Аннуаир открыт 18.09.2025; «permet d'identifier les entreprises ayant déjà sélectionné leur plateforme agréée, avec la plateforme retenue et l'adresse de facturation»; доступен «en accès libre»; пишут в него только PA — [economie.gouv.fr](https://www.economie.gouv.fr/actualites/facturation-electronique-ouverture-de-lannuaire-dedie); [LégiFiscal](https://www.legifiscal.fr/actualites-fiscales/4240-facturation-electronique-lancement-annuaire-dedie.html).
- Ещё в октябре 2024 решено: «aucune entreprise ne peut s'inscrire directement dans l'annuaire de l'AIFE. Les données transitent par les plateformes agréées, qui les envoient à l'AIFE via une API dédiée» — [ma-facture-electronique.org, annuaire](https://ma-facture-electronique.org/portail-public-facturation/annuaire/); с 03.03.2025 аннуаир был в пилоте для PDP — [Dext](https://dext.com/fr/ressources/blog-actualite-comptable/annuaire-ppf-comment-ca-marche).
- Spécifications externes B2B: v3.2 — 30/04/2026 (zip с аннексами, примерами, XSD и «swaggers»), предыдущие v3.1 (31/10/2025), v3.0 (18/12/2024), v2.4 (19/06/2024, есть англ. версия); контакт AIFE — форма `aife.economie.gouv.fr/formulaire-de-contact-ppf` — [impots.gouv.fr, spécifications externes](https://www.impots.gouv.fr/portail/specifications-externes-b2b).
- PA обязаны использовать аннуаир PPF как «source de vérité», держать ежедневно синхронизируемую реплику в своей ИС и «très fortement recommandé» давать клиентам консультацию публичных данных аннуаира — [FNFE-MPE Check-List (PDF)](https://fnfe-mpe.org/wp-content/uploads/2026/09/2026-09-07-RFE-Check-List-Demarrage-Volet-B-VF.pdf).
- Упоминание сервиса консультации (середина июня 2026) с пакетной проверкой до 5 000 SIRET за запрос; более 200 000 активных адресов в аннуаире на начало 2026 — [ma-facture-electronique.org, interopérabilité](https://ma-facture-electronique.org/plateforme-agreee/interoperabilite/), [API PA](https://ma-facture-electronique.org/formats-normes/api-plateforme-agreee/) (вторичный источник).
- Тестовая среда PPF: срок на тесты интероперабельности для кандидата отсчитывается «de la date d'ouverture de l'environnement de tests du portail public» — т.е. среда даётся в рамках иммматрикуляции — [гид DGFiP](https://www.impots.gouv.fr/sites/default/files/media/1_metier/2_professionnel/EV/2_gestion/290_facturation_electronique/guide_utilisateur_fe_ds_immatriculation_pdp.pdf). По сводке поиска, PPF открыл тестовую среду 14.10.2025, дедлайн сдачи отчётов — 14.01.2026 (источник из выдачи, напр. [mon-expert-en-gestion.com](https://www.mon-expert-en-gestion.com/ressources/ressources-plateforme-agreee-pa/); не верифицировано).
- Бесплатные сторонние проверки готовности получателя: «Info Annuaire» у SuperPDP — [superpdp.tech](https://www.superpdp.tech/); B2Brouter Lookup API (асинхронный) — [developer.b2brouter.net](https://developer.b2brouter.net/); Storecove `POST /discovery/receives` (Peppol-участник, не аннуаир PPF) — [storecove.com/docs](https://www.storecove.com/docs/).

### Inferences
- В ERP функцию «найти PA клиента по SIREN» нужно проектировать как вызов API выбранной PA (lookup/annuaire endpoint), с кэшем результата и обработкой «не найден/не assujetti».
- Swagger из zip спецификаций v3.2 полезен для понимания модели данных аннуаира (поля адреса маршрутизации) и форматов flux 1/2/10, даже без доступа к среде.

### Gaps
- Не подтверждено существование публичного (без статуса PA) программного API к аннуаиру PPF — все источники говорят только о доступе PA; веб-консультация «accès libre» — для людей.
- Не найден публичный «bac à sable» PPF для не-PA.

## Вопрос 5. Open-source и библиотеки: Factur-X, валидаторы, Schematron, бесплатные онлайн-инструменты

### Takeaway
Эталонный стек: Python `factur-x` (Akretion, BSD, v7.7 от 14.10.2026, Factur-X 1.0.9, XSD + Schematron через Saxon-сервер, CLI и REST-сервис), Java Mustangproject (Apache-2.0, v2.25.0, включает бывший валидатор ZUV), .NET `ZUGFeRD-csharp` 11.0.0, официальные Schematron CEN (EUPL 1.2, v1.3.16 от 10.04.2026), конфигурация KoSIT. Бесплатный валидатор FNFE-MPE (services.fnfe-mpe.org, v1.6.3) покрывает Factur-X/CII/UBL/CDAR/Order-X; FNFE публикует schematron'ы для EXTENDED-CTC-FR.

### Inferences
- Для 1С (встроенного Java/Python нет) практичны три подхода к Factur-X: (1) формировать только CII/UBL XML средствами 1С и отдавать PA, которая сама собирает Factur-X (Pennylane декларирует конвертацию, iopole — генерацию); (2) вызывать внешний микросервис `facturx-webservice` (Flask) или Mustang-CLI на сервере приложений; (3) использовать .NET `ZUGFeRD-csharp` через внешнюю компоненту. Валидацию перед отправкой — через Schematron CEN/FNFE во внешнем сервисе или валидатор PA.
- Рекомендованным FNFE-MPE считается его собственный бесплатный сервис; «официального» списка рекомендованных сторонних валидаторов не найдено.

### Gaps
- Прямая ссылка на репозиторий Schematron FNFE для EXTENDED-CTC-FR не найдена (упоминается в чек-листе без URL).
- Не подтверждено наличие API у валидатора FNFE-MPE.

## Вопрос 8. Коммерческие условия PA для ISV: типовые цены за счёт / в месяц

### Takeaway
Диапазон огромный: от 0 € для издателя (Pennylane, marque grise) и 0,0025–0,01 € HT за счёт оптом (SuperPDP) до «sur devis» (iopole, Seqino, Sage, B2Brouter API); розничные цены для конечных компаний — 0,30–1,50 € за счёт или 0–30 €/мес в подписках. Для стартовых объёмов малого ERP стоимость PA-канала пренебрежимо мала; основная цена — интеграция и соответствие.

### Cited Findings
- Pennylane: «0€: aucun frais de licence ou d'usage pour votre solution», «L'utilisation de la PA Pennylane est gratuite pour les éditeurs» — [pennylane.com](https://www.pennylane.com/fr/facture-electronique-scpa).
- SuperPDP (публичные тарифы, июль 2026): API 0,01 € HT/счёт (до 10 000/мес), 0,005 € (10 000–100 000), 0,0025 € (>100 000); аккаунт без API — бесплатно до 1 000 счетов/мес; KYC/KYB 2 € HT; минимум 10 € HT/год; оптовая цена для издателей в marque grise — [superpdp.tech/tarifs](https://www.superpdp.tech/tarifs); [comparateur-efacturation.fr](https://comparateur-efacturation.fr/plateforme/superpdp).

- B2Brouter: веб-планы 0 / 110 / 300 € в год; API и white-label — по запросу — [b2brouter.net/fr/tarifs](https://www.b2brouter.net/fr/tarifs/).
- Розница для конечных компаний: «0,30 € à 1,50 € par facture»; микро 0–15 €/мес, TPE 15–50 €/мес, PME 50–250 €/мес, ETI — devis; оценки DGFiP затрат на внедрение: микро/TPE 0–300 €, PME 1 000–1 500 €, крупные >50 000 € (статья 18.08.2026) — [tool-advisor.fr](https://tool-advisor.fr/logiciel-facturation/prix-plateforme-agreee/).

- Для клиента maERP с 500 счетами/мес через SuperPDP канал стоит ~5 €/мес; через Pennylane — 0 € (но клиент становится пользователем PA Pennylane в marque grise). Экономика позволяет держать два адаптера одновременно.

- Данные Tiime «<20 счетов/мес бесплатно» — из вторичного источника, не подтверждены на сайте Tiime.

## Сводка для выбора пути (на основе приведённых источников)

- **Вариант A (своя PA)** — технически открыт (номера выдаются по сей день), но требует действующего ISO 27001 на весь контур, хостинга в ЕС (SecNumCloud у хостера), Peppol AP/SMP, трёх аудитов за 3-летний цикл. Для команды из нескольких разработчиков — не раньше чем через год и при бюджете на compliance; ценность для продукта сомнительна, пока нет SaaS-инфраструктуры.
- **Вариант B (Solution compatible)** — основной: официальный ярлык DGFiP, 155 PA на выбор, минимум четыре с открытыми ISV-условиями (Pennylane 0 €, SuperPDP публичный прайс + OAuth2, iopole API-first B2B2B, Storecove/B2Brouter — международный Peppol с OpenAPI). Нужно предусмотреть несколько адаптеров, т.к. API AFNOR XP Z12-013 добровольна.
- **Вариант C (Peppol напрямую)** — для ERP закрыт: сервис-провайдер Peppol во Франции обязан быть PA (PASR). Peppol получаем «в комплекте» с любой из выбранных PA (все четыре названные — сертифицированные AP).
- **PPF** — ни API, ни sandbox для не-PA; аннуаир запрашивается через API PA.
- **Форматы/библиотеки** — генерировать CII (как Dolibarr) и/или UBL EN16931 в 1С; Factur-X (PDF/A-3) — через PA или внешний сервис (akretion/factur-x, Mustang); валидация — Schematron CEN + FNFE (EXTENDED-CTC-FR), бесплатный валидатор FNFE-MPE.
- **1С-прецедентов нет** — реализация будет первой; ориентир по структуре — модуль Dolibarr EInvoicing.
