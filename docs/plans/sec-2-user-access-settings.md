# SEC-2: дополнительные права пользователя пишет только администратор

Сборка 2.0.16.15. Решение владельца 2026-10-05 («делай») по ROADMAP 12.5a / TECHDEBT 2.0.16.14.

## Проблема

`РегистрСведений.НастройкиПользователей` (измерения Пользователь, Настройка — ПВХ `ВидыНастроекПользователей`)
хранит и бытовые настройки (принтеры, касса, склад), и права группы `НастройкиДоступа` («Кассир», «Редактировать
документы в закрытом периоде», «Редактировать завершённые документы», «Не контролировать запрет отгрузок»,
«Заверение цен», «Видеть суммы (производство)»). Писать регистр могут:

- `PDV` — `Update` без RLS: любые строки, в том числе чужие;
- `ОбменМобильнаяДоставка` — `Update`/`Edit` своей строки плюс `ExternalConnection`: через COM выдаёт себе право.

ПВХ на запись не открыт никому, кроме администратора и руководителя (проверено по `Rights.rights`) — переложить
право в другую группу нельзя.

## Что делаю

1. **Модуль набора записей** `InformationRegisters/НастройкиПользователей/RecordSetModule.bsl`, `ПередЗаписью`:
   если в записываемых строках **или в замещаемых** (строки базы по отбору набора — удаление/перезапись тоже
   меняет право) есть вид настройки из группы `НастройкиДоступа` (`Настройка.Родитель =
   ВидыНастроекПользователей.НастройкиДоступа`), а пользователь не администратор — `Отказ` с сообщением на
   четырёх языках.
   - «Администратор» = у пользователя ИБ есть роль `Администратор` или `Руководитель` (раздел «Пользователи и
     права» виден именно им), проверка через `ПользователиИнформационнойБазы.ТекущийПользователь().Роли.Содержит`,
     а не `РольДоступна`: в привилегированном режиме `РольДоступна` отвечает «Истина» на любую роль, а
     привилегированный режим доступен коду внешнего соединения. Список пользователей ИБ пуст (вход без
     авторизации) — разрешено, это и есть полные права.
   - `ОбменДанными.Загрузка` проверку **не** отключает: через COM её может выставить кто угодно, планов обмена с
     этим регистром нет (проверено).
   - Замещаемые строки читаются запросом в привилегированном режиме внутри проверки — это не расширяет права
     пишущего, только даёт увидеть, что он затирает.
   - Проверка — функция модуля менеджера `ЗаписьПравЗапрещена(Набор)` экспортная, чтобы её проверял тест.
2. **RLS у PDV** на `Update`: `ГДЕ Пользователь = &Пользователь` — как у `ОбменМобильнаяДоставка` (параметр сеанса
   `Пользователь` уже используется в RLS). Чужие бытовые настройки PDV больше не пишет.
3. Тест в `ТестыДокументов` — см. «Гейт плана».

## Чего не делаю

- Не ограничиваю чтение регистра: данные не чувствительные (вывод ревью безопасности 2026-10-05).
- Не трогаю `Read` у ролей и формы регистра.

## Риски

- Код, который пишет регистр от имени не-администратора, получит отказ. Такого кода нет: регистр пишут только
  тесты (`git grep НастройкиПользователей` по `.bsl`).
- RLS на PDV: если кто-то из PDV-пользователей заводил настройки другим — теперь не сможет. Так и задумано.
- Rights.rights правится руками — сверить формат с ролью `ОбменМобильнаяДоставка`, refcheck, смок.

## Проверка

lint, refcheck, listcheck, `ai-test`, смок и тесты документов на копии базы, `ai-security` (обязателен —
права ролей), версия 2.0.16.15 и «Что нового» на четырёх языках, закрыть пункты в TECHDEBT и ROADMAP 12.5a.

## Гейт плана и что изменилось после него

Codex в лимите — гейт прошёл на субагенте `architecture-critic` (approve_with_changes). Принято:

- **P1.** COM-пользователь сам включает привилегированный режим и обходит любую проверку в коде (может дописать себе
  роль). Решение владельца 2026-10-05: снять `ExternalConnection` с роли `ОбменМобильнаяДоставка` — в коде она через
  COM не используется.
- **P2.** Интерактивный путь — форма записи у `ОбменМобильнаяДоставка` (есть `Edit`), не PDV (у PDV нет `Edit`).
  Ручная приёмка — под этой ролью: свой «Кассир» — отказ, своя «Касса» — запись.
- **P2.** Пустое имя пользователя ИБ — разрешено только при пустом списке пользователей (читается в
  привилегированном режиме). Регламентное задание без пользователя права записать не сможет — таких нет.
- **P2.** Отказ — только если права до и после записи различаются (а не при любом касании строк прав); набор без
  отбора берёт все строки; группа — `В ИЕРАРХИИ`; родитель вида читается запросом.
- **P2.** Функции: `ИзменяютсяПраваДоступа(Набор, Замещение)` и `ЭтоАдминистраторНастроек()` — первая проверяется
  тестом без смены пользователя, тест права на суммы сначала проверяет, что пользователь прогона — администратор.
- P3 отложено в `TECHDEBT.md`: «Касса»/«Склад» вне группы доступа, разное понимание «администратора» в
  `АРМПроизводство`.
