## Сборка 2.0.16.29 — ввод

1. **Общий путь ввода — обобщение функций `Обработки.АРМПроизводство`** (не копия): контекст «заказ поставщику»
   (`КонтекстЗаказПоставщику`), `Заказ` (заказ клиента) необязателен для видов `ВидЗаказПоставщику`/`ВидПоступление`;
   производственные проверки — только если основание проводится (`Документы.ЗаказПокупателя.ЗаказПроводится`).
   Сценарий `АРМЗакупки` (регресс АРМ производства) обязан пройти без изменения своих шагов.
2. **Пакетная запись поступления** `ЗаписатьСтрокиПоступления(Строки, Накладная)`: одно поступление на заказ
   поставщику, одна транзакция и одна запись; черновик при отказе — только после `ОтменитьТранзакцию`.
3. **Валюта**: поступление от заказа поставщику — `ВВалюте`/`Валюта` заказа, курс на дату поступления
   (`РаботаСВалютами.ЗаполнитьВалютуПоОснованию`); убрать сброс в `НовыйДокументЗакупки` (~4366) — это исправляет
   и АРМ производства (пункт «Что нового»). Цена прайса (`ЦеныНоменклатурыПоставщиков`, основная валюта) —
   в валюту документа до упаковки и НДС.
4. **Политика цен по контексту**: в закупочном — по праву изменения заказа/поступления, в производственном —
   как сейчас (`ПоказыватьСуммы()`).
5. **Блокировка `ЗаказыПоставщикам`**: новая `УправляемыеБлокировки.ЗаказыПоставщикам` (исключительная по
   `ЗаказПоставщику`) в `ЗаполнитьБлокировкуПроведения` поступления (по `Основание`), возврата поставщику (по
   заказу-родителю), заказа поставщику (своя ссылка и все `ТЧТовары.ЗаказПоставщику`); АРМ берёт тот же набор в том
   же порядке. Защита перенесённых строк (зависимые заказы поставщику) под той же блокировкой.
6. **Строки любой даты** в выбранный заказ поставщику (в производственном контексте — по-прежнему «за сегодня»);
   заказ, забравший строки другого заказа, в АРМ только читается.
7. **Форма**: ввод строк в «Товары» и «Поступления» (по образцу таблиц АРМ производства), «Изменить статус ▾»
   (В работу / В черновик / Отменить), закладка **«К поступлению»** (строки проведённых заказов с остатком > 0;
   отметить строки одного поставщика → номер и дата накладной → по поступлению на каждый заказ). Склада в
   «К поступлению» нет (решение владельца). Генератор — `scripts/formgen/zakupki/gen.py` (дописать, сверять с формой).

## Сборка 2.0.16.30 — «Потребность»: анализ по потребностям

Решение владельца 2026-10-07: по потребностям нужно **анализировать** закупку — что нужно, под что, что уже заказано,
пришло, взято со склада, где дефицит, кому заказано и по какой цене. Перед кодом — дописать раздел плана и пройти
`ai-review-plan`.

Что есть в конфигурации (сверить, не верить на слово):
- регистр `ПотребностиПроизводства` (Заказ клиента, Продукция, Материал, Характеристика; Потребность, Заказано,
  Пришло, ИзОстатка) и отчёт `ПотребностиПроизводства`;
- обработка `ФормированиеЗаказовПоставщику` — заполнение по остаткам и оборотам и по группе товаров, создание заказов
  (пополнение запаса; минимальный остаток — проверить, где задаётся);
- отчёт `ПланированиеЗакупок`; документ `ЗаявкаНаПоискТовара` (товар, которого нет в справочнике/у поставщиков).

Состав для плана (уточнить у владельца развилки ниже):
- верхняя закладка «Потребность» слева от «Заказов поставщикам»: строки потребности с колонками нужно / заказано /
  пришло / со склада / дефицит, основной поставщик, последняя цена закупки, связанные заказы поставщикам и
  предложения; отборы — товар, заказ клиента, клиент, поставщик, период потребности, «только с дефицитом»;
- переключатель группировки: по товару (сводно по всем заказам) / по заказу клиента / по поставщику — для анализа;
- нижние закладки по строке: заказы клиентов, из которых потребность; заказы поставщикам и поступления по ней;
  предложения поставщиков; остатки по складам;
- действие: отметить строки → заказ поставщику (по поставщику строки) общим путём ввода сборки 2.0.16.29.

Развилки владельцу — спросить **до** плана (AskUserQuestion, с рекомендацией):
1. Источники потребности: только заказы клиентов на производство (регистр) или ещё торговые заказы клиентов
   (их регистр не ведёт) и пополнение до минимального остатка?
2. Единица анализа по умолчанию: по товару сводно или по заказу клиента?
3. Нужна ли выгрузка анализа в отчёт/Excel или достаточно экрана АРМ?

## Сборка 2.0.16.31 — тендеры

Что есть: документ `ПредложениеПоставщика` (Заказ клиента, Поставщик, Договор, Дата и срок поставки в днях, валюта,
`Победитель`, строки с ценой и сроком); `Документы.ПредложениеПоставщика` уже отдаёт предложения по заказу клиента,
отсортированные по сумме в основной валюте, и снимает «Победитель» с остальных; заказ поставщику вводится на
основании предложения. Перед кодом — раздел плана и `ai-review-plan`.

Состав для плана:
- из строк «Потребности» — «Запросить предложения»: черновики предложений нескольким поставщикам (по основному и
  выбранным) с количествами потребности;
- сравнение по строке/товару: цена в основной валюте, срок поставки, сумма, кто дешевле/быстрее; выбор победителя
  (по строке или по предложению целиком — развилка);
- «Заказать у победителя» — заказ поставщику на основании предложения общим путём ввода; статус потребности
  учитывает «предложения запрошены / победитель выбран».

Развилки владельцу: тендер по заказу клиента (как сейчас устроен документ) или по сводной потребности товара без
заказа клиента (документ придётся расширять — тогда это реструктуризация); победитель по строке или по документу;
обязателен ли тендер перед заказом.
