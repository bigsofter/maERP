# Сортировка в рабочих местах производства и закупок (тикет 2605527, сборка 2.0.17.32)

## Проблема

Замечание клиента 16.11 после 2.0.17.22: в рабочем месте производства сортировка кликом по колонке работает только
на первой закладке, в рабочем месте закупок — ни на одной. Сборка 2.0.17.8 в релизе есть; причина в другом.

- Клик по шапке сортирует только динамический список (платформа меняет порядок в пользовательских настройках).
  Единственный динамический список рабочих мест — «Заказы» производства, поэтому работает только он.
- Остальные таблицы — реквизиты типа ТаблицаЗначений/ДеревоЗначений, их заполняет код. По модели типов 8.5.1
  (`FormTable.type`) у таблицы формы нет события щелчка по шапке и нет свойства сортировки кликом; есть только
  `ChangeRowOrder` («Изменять порядок строк»). 2.0.17.8 включила его, предположив, что оно включает сортировку
  кликом, — на клиенте это не подтвердилось.

## Решение владельца (17.11)

- Таблицы **только для чтения** — перевести на динамические списки: сортировку кликом даёт платформа (вариант B).
- Таблицы **с редактированием** (ввод строкой, флажок отметки) — своя сортировка (вариант A).
- Дерево «Материалы» — своя сортировка внутри каждого уровня.

## Поиск готового

В maERP и УНФ своей сортировки таблиц на значениях нет: УНФ для табличных частей полагается на штатные команды
«Сортировать по возрастанию/убыванию» (они не переживают перезаполнение таблицы кодом — а в рабочих местах таблицы
перечитываются при каждой смене заказа и после каждой записи строки). Образец динсписка в форме обработки с
`ListSettings.dcss` — реквизит `Заказы` рабочего места производства (2.0.17.8).

## Вариант A: своя сортировка редактируемых таблиц

Таблицы:
- производство: `Продукция`, `ДокументыВерх`, `ЗаказыПоставщику`, `Поступления`, `Выпуски`, `Переработки`,
  `ПоступленияПереработки`, `Отгрузки`, `СвойстваПродукции`; дерево `Материалы`;
- закупки: `Потребность`, `Заказы` (флажок «Пометка»), `Товары`, `Поступления`, `ТоварыПоступлений`;
- до перевода на динсписок в следующих сборках (см. вариант B): закупки `Оплаты`, `Документы`, `ИсточникиТовара`,
  производство `ДокументыЗаказа`.
- Не трогаются: `Сообщения` (панель сообщений формы).

Устройство:
1. Общий модуль `СортировкаТаблицФормы` (сервер, не глобальный, без вызова сервера). Экспорт:
   - `УстановитьПорядок(Форма, ИмяТаблицы, ИмяПоля, Убывание)` — запоминает порядок таблицы и применяет его;
   - `ПрименитьПорядок(Форма, ИмяТаблицы)` — после каждого перезаполнения таблицы кодом; порядка нет — ничего
     не делает.
2. Порядок хранится в реквизите формы `ПорядокТаблиц` (Строка, неограниченная): записи `Таблица|Колонка|0/1`
   через `;`. В настройки формы не сохраняется: при новом открытии — порядок по умолчанию.
3. Колонка — последний сегмент `ПутьКДанным` текущего поля таблицы. Проверяется по `Форма.ПолучитьРеквизиты(Имя)`:
   колонки нет (поле-картинка без данных, группа) — сообщение «Колонку нельзя отсортировать», порядок не меняется.
4. Сортировка — на сервере, `ДанныеФормыКоллекция.Сортировать("Колонка [Убыв]", Новый СравнениеЗначений)`:
   ссылки — по представлению: ключ-ссылка заменяется строкой (документ — датой и номером); `СравнениеЗначений` сравнивает ссылки по идентификатору — это поймал сценарий `СортировкаТаблицАРМ`. Дерево — `РеквизитФормыВЗначение` →
   `Строки.Сортировать(..., Истина, Новый СравнениеЗначений)` (каждый уровень отдельно) → `ЗначениеВРеквизитФормы`.
   Сравнение ссылок по представлению проверяется прогоном на копии базы до реализации (внешняя обработка).
5. Незаписанные строки после сортировки сдвигаются в начало в прежнем порядке — так их держит и текущий код
   (`ЗагрузитьСтрокиДокументов`, загрузка «Продукции», `ЗагрузитьТоварыПоступленийНаСервере`). Признак передаётся
   параметром `ПрименитьПорядок(Форма, ИмяТаблицы, ОтборНезаписанных = Неопределено)`: у таблиц документов
   производства `Записана` = Ложь, у «Товаров поступлений» `НомерСтроки` = 0, у «Продукции» тоже `Записана` = Ложь.
6. Шапка: у поля отсортированной колонки к заголовку добавляется « ▲»/« ▼», у остальных полей таблицы суффикс
   снимается. Пустой `Заголовок` поля — берётся заголовок реквизита.
7. Команды формы `СортироватьПоВозрастанию`/`СортироватьПоУбыванию` (заголовки и подсказки на ru/fr/en/es,
   `currentRowUse` Auto, без связанной таблицы — одна пара на все таблицы) — кнопками в начало контекстного меню
   каждой таблицы варианта A. Обработчик на клиенте: `ТекущийЭлемент` формы — таблица, её `ТекущийЭлемент` —
   поле; дальше серверный вызов формы `УстановитьПорядокНаСервере(ИмяТаблицы, ИмяПоля, Убывание)`. Курсор после
   сортировки остаётся на той же строке (ключ — идентификатор строки до сортировки у таблиц; у дерева — по ключу
   текущей строки, если он есть).
8. Точки вызова `ПрименитьПорядок` — сразу после заполнения таблицы и ДО возврата курсора по ключу:
   - производство: загрузка `Продукции` (до вставки незаписанных строк), `ДокументыВерх`, общая
     `ЗагрузитьСтрокиДокументов` (все нижние таблицы документов), `Материалы`, `СвойстваПродукции`;
   - закупки: `ЗагрузитьЗаказыНаСервере`, `ЗагрузитьДанныеЗаказа` (`Товары`, `Поступления`),
     `ЗагрузитьПотребностьНаСервере`, загрузка `ТоварыПоступлений`.
   Точечная вставка строки после записи (`Продукция.Вставить(Позиция)`) порядок не пересчитывает: строка остаётся,
   где её правили, до следующего перечитывания.
9. `changeRowOrder` = true, включённое 2.0.17.8 на всех таблицах обоих рабочих мест, снимается: сортировки кликом
   оно не дало, а штатные «Сортировать»/«Переместить» в контекстном меню дублировали бы свои команды и не
   переживали бы перезаполнение.

## Вариант B: динамические списки для таблиц только для чтения

Восемь таблиц. Разведка (17.11): пять собираются одним запросом без временных таблиц сразу; «Оплаты», «Документы
заказа» (производство) и «Источники» потребности требуют переписать расчёт одним запросом. Владелец выбрал переписать
все восемь (17.11). Порядок — тремя сборками, чтобы исправление дошло до клиента раньше:

| Сборка | Таблицы |
|---|---|
| 2.0.17.32 (эта) | вариант A целиком; B: закупки `СписокПоступлений`, `ЗаказыТовара`, `ОстаткиТовара`, `ПредложенияТовара` |
| следующая | закупки `Оплаты` и `Документы` (обе стоят на `ЗапросОплат` — ВТПлатежи/ВТНакладные), производство `ДокументыЗаказа` (движение «+N/−N», дедупликация, подвал) — свой план |
| за ней | закупки `ИсточникиТовара` (пакет потребности > 15 ВТ, поправка дефицита переработчика в коде) — свой план |

До перевода оставшиеся четыре таблицы сортируются вариантом A (те же команды меню), чтобы сортировка была везде уже в
этой сборке.

### Общее устройство динсписка в рабочем месте

- Реквизит формы `DynamicList`, `customQuery` = true, без `mainTable` (запросы с ОБЪЕДИНИТЬ и группировкой),
  `autoSaveUserSettings` = false (порядок по клику живёт до закрытия формы, как у варианта A),
  `ListSettings.dcss` с `userSettingID` у `order` и порядком по умолчанию `OrderItemField` (урок 2.0.17.8:
  без файла настроек клику некуда писать порядок; порядок не через `Список.Порядок` в коде).
- Текст запроса — функция модуля менеджера (`ТекстЗапросаСписка…`), ставится в `ПриСозданииНаСервере`
  (`Список.ТекстЗапроса = …`): части по правам и режиму приёмки собираются, как сейчас. Ключ:
  `ВидКлюча = ВидКлючаДинамическогоСписка.ЗначениеПоля`, `ПоляКлюча` — ссылка строки (`Документ`, `Склад`,
  `Предложение`), чтобы `Элементы.<Таблица>.ТекущаяСтрока` было ссылкой и курсор ставился присваиванием ссылки.
- Параметры — `Список.Параметры.УстановитьЗначениеПараметра` в тех же точках, где сейчас заполняется таблица.
  Перечитывание после записи документа — `Элементы.<Таблица>.Обновить()` там, где сейчас перезаполнение.
- Строковые колонки «Статус», «Вид» — в запросе `ВЫБОР … ТОГДА &СтатусПроведен …` с параметрами из `НСтр` (сортируются
  по тексту). Колонки с форматом даты/числа в строке («№ … от …», «N из M») — поле запроса-заглушка + заполнение в
  `ПриПолученииДанныхНаСервере` (`&НаСервереБезКонтекста`); сортировка по ним — по исходному полю (дате заказа /
  числу покрытых).
- Поля, которые код читает из `ТекущиеДанные`, но колонкой не выведены (`Документ`, `ЗаказПоставщику`), —
  в `notDefaultUseAlwaysAttributes` (урок forms-011). Вычисляемым колонкам — `<title>` на четырёх языках (forms-013).
- В таблицы динсписков на закладках не кладутся кнопки и `userSettingsGroup` (уроки forms-008/009).
- `changeRowOrder` у них снимается, `readOnly` остаётся.

### Таблицы этой сборки

1. **`СписокПоступлений`** (закладка «Поступления», режим «Документы»). Запрос — поступления ОБЪЕДИНИТЬ ВСЕ ордера
   без `ПОМЕСТИТЬ` (`ТекстЗапросаСпискаДокументовПоступления` даёт обе части, сейчас — с `ВТСписок`). Отборы панели
   (поставщик, ответственный, товар) — сейчас подставляются в текст условием только при заполненном отборе; в
   динсписке — параметрами вида `(&ЛюбойПоставщик ИЛИ Док.Контрагент = &Поставщик)`, как у «Заказов» производства.
   Ключ — `Документ`. «Заказ» («№ … от …») — в `ПриПолученииДанныхНаСервере`, сортировка — по дате заказа.
   Режим «Товары» (`ЗагрузитьТоварыПоступленийНаСервере`) берёт документы не из таблицы, а запросом с теми же
   отборами (`Обработки.АРМЗакупки.ДокументыПоступлений(Отборы)` — новая функция на том же тексте).
   Курсор (`КурсорПоступлений`, `ЗагрузитьПоступленияНаСервере`) — ссылкой в `ТекущаяСтрока`.
   `СписокПоступленийВыбор` — `Документ` и `ЗаказПоставщику` в «использовать всегда».
2. **`ЗаказыТовара`** (нижняя закладка «Потребности»). ВТОсталось → вложенный запрос в соединении; `ПЕРВЫЕ 100`
   снимается (динсписок читает порциями). Параметры `Номенклатура`, `Характеристика` — по текущей строке
   «Потребности» в `ЗагрузитьДанныеСтрокиПотребности`. Ключ — `Документ`. «Статус» — `ВЫБОР` по `Проведен`.
3. **`ОстаткиТовара`**. ВТЗакреплено → вложенный запрос внутри объединения. Параметры те же. Ключ — `Склад`.
4. **`ПредложенияТовара`** (тендеры). ВТДефициты/ВТПокрытие/ВТВсегоДефицитов → вложенные запросы (дефициты
   повторяются в двух подзапросах). Параметры `Заказы` (массив заказов-источников строки), `Номенклатура`,
   `Характеристика`; без тендеров или в режиме приёмки — параметр `ТендерыДоступны` = Ложь в условии (пустой список).
   «Покрытие» («N из M») — в `ПриПолученииДанныхНаСервере`, сортировка по `Покрыто`. Ключ — `Предложение`.
   Цена и сумма скрываются колонками без права видеть суммы (`НастроитьВидимостьДенегИПриемки`), как сейчас;
   невидимые колонки динсписок не читает.

Тексты запросов `ТекстЗапросаЗаказовТовара`, `ТекстЗапросаОстатковТовара`, `ТекстЗапросаПредложенийТовара` и
списка поступлений переписываются в один запрос без ВТ и остаются единственными: ими же пользуются функции менеджера
`ДанныеСтрокиПотребности`, `ПредложенияТовара`, `ДанныеПоступлений` (тесты `ТестыДокументов` проверяют их — значит,
и запрос динсписка). Параметры, которые динсписок задаёт условием «любой» (`ЛюбойПоставщик` и т. п.), функции
менеджера ставят так же.

Курсор нижних таблиц потребности сейчас возвращается по ключу (`КлючиТекущихСтрок` / `ВернутьТекущиеСтроки`) —
для динсписков он сохраняется сам (ключ — значение поля), эти таблицы из ключей убираются.

## Проверки

- `scripts/lint.sh`, `refcheck.py`, `listcheck.py`, `colfont.py`; смок открытия форм и тесты документов на копии базы.
- `ТестыДокументов`: сценарий сортировки — `СортировкаТаблицФормы` на форме рабочего места закупок: порядок
  по ссылке-поставщику (по представлению), повторное применение после перезаполнения, незаписанная строка
  остаётся первой; дерево — порядок на каждом уровне.
- Ручная проверка владельцем на клиенте: клик по шапке у каждой таблицы варианта B, команды меню у таблиц A.

## Риски

- Сортировка ссылок без `СравнениеЗначений` шла бы по внутреннему идентификатору — проверяется прогоном.
- Таблица в режиме редактирования строки: команда из контекстного меню завершает редактирование до вызова.
- Код, полагающийся на порядок строк (`Продукция[0]` — первая строка по умолчанию) — первая строка теперь
  первая в выбранном порядке, это ожидаемо.

## Правки по ревью плана (17.11, субагент Claude architecture-critic — Codex в лимите до 18.11)

Отчёт: `.ai/reviews/arm-sorting/02-plan-review-claude.md`. Принято:

- **P1-1.** Параметры всех динсписков (`Номенклатура`, `Характеристика`, `Заказы`, `ЕстьСтрока` = Ложь, отборы
  поступлений) задаются в `ПриСозданииНаСервере` до любых ранних выходов; ранний выход `ЗагрузитьДанныеСтрокиПотребности`
  и режим приёмки сбрасывают их в пустое состояние (`ЕстьСтрока` = Ложь).
- **P1-2.** Права — по таблицам запроса: без права (`ТендерыВключены` ложно; нет чтения регистра заказов поставщикам,
  станков) текст списка — заглушка без таблиц (`ВЫБРАТЬ … ГДЕ ЛОЖЬ` с теми же полями и типами). Параметра-переключателя
  в условии нет.
- **P1-3.** В Form.form — полный текст запроса (все части, все поля); код ставит текст из функции менеджера только при
  урезанных правах/режиме. Сценарий `ТестыДокументов`: тексты `ТекстЗапросаСписка…` во всех вариантах (обычный,
  приёмка, без тендеров, заглушки) выполняются запросом с параметрами, каждое поле колонок и «использовать всегда»
  есть в результате. Строка в `docs/TESTS.xlsx`.
- **P1-4.** Текстовые колонки не сортируются по тексту:
  - B: «Заказ» у поступлений — колонка на ссылке `ЗаказПоставщику` (ссылка на документ упорядочивается по дате),
    «Покрытие» у предложений — две числовые колонки «Покрыто» и «Всего дефицитов» вместо строки «N из M».
    `ПриПолученииДанныхНаСервере` не нужен.
  - A: ключ сортировки строится в `СортировкаТаблицФормы`: колонка `XПредставление` при наличии колонки `X` —
    по `X`; строковая `X` при наличии `XЧисло` — по `XЧисло`; ссылка на документ — по дате и номеру документа
    (запрос по типам), прочая ссылка — по представлению, примитив — по значению.
- **P2-1.** После записи строки «Продукции» (`ЗаменитьСтрокиЗаказа`) — `ПрименитьПорядок`.
- **P2-2.** Подстановка документа в новую строку и сейчас перебирает все строки ниже новой (новая — первая), меняется
  только выбор среди нескольких подходящих сегодняшних документов: берётся первый в видимом порядке. Принято как есть.
- **P2-3.** Стрелка в шапке ставится после `ПрименитьКолонкиДокументов`; порядок по колонке, скрытой в новом режиме
  `ДокументыВерх`, сбрасывается.
- **P2-4.** Дерево «Материалы»: при обновлении заказа сортируется `ДеревоЗначений` до `ЗначениеВРеквизитФормы`;
  по команде — обратный путь с поиском текущей строки по (Материал, Характеристика, Уровень, Продукция);
  развёрнутость узлов после команды не восстанавливается (принято).
