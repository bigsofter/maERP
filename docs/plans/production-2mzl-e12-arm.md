# Бриф: рабочее место производства (E12)

## Задача

Превратить обработку `АРМПроизводство` из справочного окна (заказы, состав, связанные документы — только чтение) в рабочее
место, где весь производственный контур ведётся **от заказа клиента на производство и прямо в таблицах**: строка продукции
создаёт заказ-черновик, строки материалов, поступлений, передач, выпусков и отгрузок создают и правят свои документы без
открытия форм. Основание — `docs/plans/production-2mzl.md`, этап E12; обязательства E8 (очередь по стадиям и индикатору),
E9 (автовыпуск не виден через критерий `СвязанныеДокументы`) и E10 (форма ручного выпуска без пустых вызовов).

## Что взято из расширения drissotex (`build/Extension_Drissotex_14092026.cfe`)

Расширение `Extension_Drissotex` (префикс `Ext1_`) распаковано 2026-09-15 во временную базу и выгружено в XML. Состав:

Что в расширении **не нужно maERP**: заимствованные элементы стиля и картинки (не используются формой), закомментированный
`BeforeWriteAtServer` однострочной формы, запросы динамических списков с полями через точку без отбора — у нас списки
по выбранному заказу.

## Решения владельца (2026-09-15)

1. **Очередь заказов** — по умолчанию заказы на производство, тумблер «Все» показывает все заказы клиентов (в базе
   drissotex после E4 старые заказы имеют вид «Продажа»); выбор запоминается.
2. **Строки документов** — нижние закладки по **выбранному заказу**, с документами второго уровня цепочки: поступление через
   заказ поставщику, возврат из переработки через передачу, автовыпуск через реализацию. Сумм нет у тех, кому они не видны.
3. **Всё работает от заказа, ввод прямо в табличных частях.** После окончания редактирования строки документ создаётся или
   корректируется. Верхняя таблица — две закладки: «Заказы» и «Продукция». В «Продукции» первая строка клиента создаёт
   заказ-черновик; у следующих строк колонка «Заказ на производство» выбирается из **черновиков того же клиента**. На каждой
   нижней закладке товар добавляется строкой, документ формируется так же: закладка «Поступления» пишет поступление по
   заказу на производство сверху и связанному заказу поставщику; заказов поставщику несколько — колонка выбора в строке.
4. **Кнопки ввода на основании остаются** для быстрого создания документов: «Заказ поставщику», «Поступление», «Передача в
   переработку», «Выпуск по заказу», «Отгрузка», отчёт «Потребности производства» с отбором по заказу.
5. **В каждой таблице с товарами или материалами** видны номер, документ, контрагент созданного документа, его реквизиты и
   **статус**.
6. **Выбор из списков — человеческим представлением.** Колонка называется «Заказ на производство», в списке —
   «№11111 от 12.03 {контрагент} на {сумма/количество}», а не «Заказ клиента на производство №11111 от 12.03.27».
7. **Подчинённый документ** (любая нижняя закладка) создаётся **только у проведённого заказа**.
8. **Кнопка «Статус» по выделенным строкам** — действия, стадия по-прежнему считается расчётом (решение E8 не меняется):
   «В работу» — провести, «В черновик» — отменить проведение, «Отменить» — пометить на удаление. Дальше стадия (потребность,
   заказ поставщику, производство, отгрузка…) меняется сама от документов, введённых в АРМ.
9. **Подчинённые документы проводятся сразу** после окончания редактирования строки. Отказ проведения (нехватка материалов,
   закрытый период) — документ записывается непроведённым, в строке статус «Не проведён» и причина; кнопка «Статус»
   проводит повторно.
10. **Новая строка нижней закладки** попадает в документ предыдущей строки с тем же контрагентом; колонка «Документ» даёт
    выбрать документ этого заказа за сегодня или «Новый».
11. **Правка проведённых документов в АРМ разрешена**: правка строки перепроводит документ, удаление убирает строку,
    документ без строк помечается на удаление (не удаляется). **Автовыпуски и проведённые заказы — только чтение.**
12. **Три сборки**, каждая — на тест своей версией: E12.1, E12.2, E12.3 (ниже).

## Раскладка формы

```
┌ Показывать: (•) Производство ( ) Все        [Статус ▾] [Заказ поставщику] [Поступление] [Передача] [Выпуск] [Отгрузка] [Потребности]
├─ Заказы ─┬─ Продукция ─────────────────────────────────────────────────────────────────────────────────────────
│ Заказ на производство │ Клиент │ Стадия │ ●◐○○○ │ Обесп.% │ Пришло% │ Выпуск% │ Отгр.% │ Оплата% │ Отгрузка │ Сумма* │ Менеджер
│ …                                                                                   (* — только ролям с суммами)
├─ Материалы ─┬─ Документы ─┬─ Заказы поставщику ─┬─ Поступления ─┬─ Переработка ─┬─ Выпуск ─┬─ Отгрузки ────────────
│ (строки выбранного заказа; у каждой — документ, номер, дата, контрагент, реквизиты и статус документа)
```

- **Заказы** — динамический список (только чтение, множественный выбор), стадия и доли — из среза последних
  `ИсторияЗаказовПокупателейПоСтатусам` (E8). Доли показываются процентами: суммировать количества разных материалов в
  разных единицах бессмысленно, а доли уже посчитаны расчётом стадии.
- **Продукция** — таблица значений формы: строки товаров заказов очереди (заказ, клиент, номенклатура, характеристика,
  количество, упаковка, цена и сумма ролям с суммами, дата отгрузки, стадия, статус документа). Ввод строки черновика
  пишет заказ; строки проведённых заказов и продаж — только чтение.
- **Нижние закладки** — по текущему заказу верхней таблицы (в «Продукции» — по заказу текущей строки).

## Сборки

### E12.1 — заказы и продукция (2.0.15.29)

- Форма декларативно в `Form.form` (сейчас таблицы строятся кодом — `listcheck` их не видит, TECHDEBT 2026-09-09).
- Закладка «Заказы»: динамический список с отбором по виду операции (тумблер, решение 1), колонки стадии, индикатора и
  пяти долей, суммы по праву просмотра, как сейчас (`ПоказыватьСуммы`).
- Закладка «Продукция»: таблица значений; загрузка — строки не выполненных и не помеченных заказов очереди. Окончание
  редактирования строки → сервер модуля менеджера обработки: найти или создать черновик (`ВидОперации` = Производство,
  реквизиты по умолчанию и договор клиента, как у заказа из формы), записать строку (`УстановитьПараметрыНоменклатуры`,
  `РассчитатьСтроку`, `КодСтроки`), заполнить материалы строки по техкарте (`Документы.ЗаказПокупателя.
  ЗаполнитьМатериалыПоТехкартам(..., Строки)`), записать заказ в режиме «Запись». Документ блокируется объектной
  блокировкой, версия данных строки сверяется — чужая правка не затирается, таблица перечитывается с сообщением.
  Удаление строки — строка уходит из заказа; черновик без строк — пометка удаления.
- Колонка «Заказ на производство»: список выбора — черновики того же клиента (не проведены, не помечены, вид операции
  «Производство») плюс «Новый заказ»; по умолчанию — черновик предыдущей строки того же клиента.
- Представление в списках выбора (решение 6): функция модуля менеджера обработки, «№ номер от дд.ММ контрагент на сумма»
  или «на количество ед.» у ролей без сумм.
- Кнопка «Статус» (подменю) по выделенным строкам обеих закладок: провести, отменить проведение, пометить на удаление;
  отказ по одному заказу не прерывает остальные, сообщения с представлением заказа.
- Нижние закладки «Материалы» (материалы заказа и остатки `ПотребностиПроизводства`: потребность, заказано, пришло, из
  остатка, дефицит) и «Документы» (цепочка второго уровня: закупки через заказ поставщику, возврат из переработки через
  передачу, автовыпуски через реализации) — только чтение; ввод в них — E12.2 и E12.3.
- Кнопки ввода на основании: «Заказ поставщику», «Поступление», «Передача в переработку», «Отгрузка», «Потребности
  производства»; доступны у проведённого заказа на производство и по правам роли на добавление документа.
- Сценарий уровня 3 `АРМПроизводство`: черновик первой строкой, вторая строка в тот же черновик, выбор другого черновика,
  удаление последней строки → пометка, «В работу»/«В черновик», отказ правки строки проведённого заказа, список выбора
  только черновиков клиента, представление, цепочка документов второго уровня.

## Границы (чего НЕ делать)

- Расчёт стадий E8 и ручную установку статусов не трогать: «Статус» — только проведение, отмена, пометка.
- Проведение заказа (E6), потребности (E7), автовыпуск (E9) не менять; АРМ пишет документы их обычной записью, без
  привилегированного режима и без режима загрузки.
- Права ролей в E12.1 не менять. Новых объектов метаданных, кроме модуля менеджера обработки, в E12.1 нет.
- Формы документов не открывать для ввода строк (решение 3); форма документа — двойным щелчком по строке, как сейчас.
- Uuid существующих объектов не менять; обработка `АРМПроизводствоDrissotex` в maERP не переносится — при слиянии с
  базой drissotex расширение отключается, данных у него нет.

## Уроки последних сборок — обязательны

- **Ключ строки динамического списка** — `ТекущаяСтрока`, а не `ТекущиеДанные.Ссылка` (TECHDEBT 2026-09-09).
- **Формы:** `<handlers>` в `Form.form` обязательны (edt-form-handlers); без `<visible>true</visible>` элемент скрыт
  (E3 дал пустую форму, смок не ловит); у таблицы на закладке не задавать группу пользовательских настроек и не класть
  кнопку внутрь таблицы (forms-008, forms-009); тумблер — представления на четырёх языках (forms-010); `listcheck.py`.
- **Проводимый документ и стандартные команды** — `WriteAndClose` у проводимого документа не грузился (E6, 2.0.15.16).
- **Имена переменных** — не свойства глобального контекста и не общие модули (`Документы`, `Производство`, bsl-011);
  переменная модуля объекта с именем реквизита — реквизит (bsl-010); псевдонимы запросов — не ключевые слова (query-001).
- **Проверка на базе — сам**, после полного обновления `build/ib` владельцем: копия, `doctests.sh` и `smoke.sh`; сценарий
  уровня 3 — в транзакции с откатом, шаг две секунды между документами.
- **Оркестрация:** обязательные гейты — модель Codex через OpenCode (`opencode/gpt-6-astra`) временно, промпт «только
  внутри репозитория», `TINY1C_HOME` на копию правил в `.ai/state`; данные и безопасность — дополнительно субагенты Claude.
