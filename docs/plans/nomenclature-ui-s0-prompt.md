## Этап 0 (2.0.16.59) — ошибки данных и общий модуль отборов

План, раздел 6, п. 0–3, и раздел 3 «одна семантика значения свойства». Порядок:
1. **Сначала сценарий, потом исправление.** Новый сценарий `ТестыДокументов` `КарточкаНоменклатуры` (2099 год,
   транзакция с откатом, настоящий отказ — последним шагом). Первым прогоном на текущем коде подтвердить или
   опровергнуть пустую номенклатуру в `МинимальныйОстатокПоСкладам` у нового товара (если сценарием через объект не
   воспроизводится — записать это честно в отчёт).
2. **Штрихкоды (P0).** `РегистрыСведений.ШтрихкодыНоменклатуры.ЗанятьШтрихкод(Штрихкод, Номенклатура, Серия)` —
   транзакция, исключительная блокировка по ключу `Штрихкод`; нет записи — пишет; своя (та же номенклатура, при
   серии — и та же серия) — не трогает; чужая — текст отказа. Все пути: карточка (артикул, параметр `Штрихкод`),
   `ЗагрузкаИзExcel` (два места, отказы — в отчёт загрузки), `СерииНоменклатуры` (занятый EAN-13 — сгенерировать
   заново). Перед правкой — повторный полный поиск `ШтрихкодыНоменклатуры.СоздатьМенеджерЗаписи`.
3. **Минимумы (P1).** Таблица — в `ТекущийОбъект.ДополнительныеСвойства` из `ПередЗаписьюНаСервере`; объект в
   `ПриЗаписи` пишет строки, отличающиеся от регистра или отсутствующие, набором с отбором по **обоим** измерениям;
   `Объект.Ссылка` формы в обработчиках записи заменить на `ТекущийОбъект.Ссылка` везде.
4. **Свойства.** `УправлениеСвойствами.УстановитьЗначениеСвойстваВОбъекте` — одна строка на свойство, остальные
   удаляются; через неё — карточка, `ЗаписатьЗначениеСвойства` (АРМ производства), `ГрупповоеИзменениеРеквизитов`;
   `ЗначенияСвойствОбъекта` — `УПОРЯДОЧИТЬ ПО НомерСтроки`. Полный поиск путей записи ТЧ `ДополнительныеРеквизиты`
   перед правкой.
5. Проверка дублей артикула — `ОбработкаПроверкиЗаполнения` объекта, только при новом товаре или смене артикула;
   «наименование ↔ полное» — `ПередЗаписью` объекта (заполнять пустое). Документ установки цен и запись техкарты из
   формы — в модуль менеджера, одной транзакцией с товаром (если транзакционность ломает текущий сценарий техкарт —
   отдельным шагом и вопросом владельцу, не молча).
6. **Общий модуль `ОтборыСписков`**: отбор в именованной группе (`Иерархия` / `Панель`), явные «не заполнено» и
   «в списке», снятие отбора; 43 формы документов не переводить (отдельная задача, запись в TECHDEBT).

Гейты этапа 0: код → lint/refcheck/queryfields → `ai-review` и **`ai-database`** (Codex) → фиксы → `--verify` →

## Уроки прошлых сборок (учесть сразу)

- Параметр, который метод переприсваивает, — `Знач` (bsl-025).
- Правки скриптом — `encoding='utf-8'`, без BOM; блок Form.form искать по **началу строки** и после найденного
  `<type>` — подстрока `</extInfo>` вложенного элемента совпадает с внешней (ошибка 2.0.16.56).
- Имя встроенной функции — по образцу из конфигурации: `СтрНачинаетсяС`, не `СтрНачинается` — BSL LS не ловит,
  ловит только CheckConfig (2.0.16.56).
- Ограничение поля СКД `useRestriction/condition` не убирает поле из доступных отборов (tiny1C query-009).
- `СтандартныйПериод` с датой окончания внутри дня в тестах ведёт себя как конец дня — интервалы через полночь.
- Отказ записи посреди сценария портит транзакцию — настоящий отказ только последним шагом; проверки «без записи» —
  функциями модуля.
- Не трогать `src/cf`, пока идёт выгрузка `ib-sync.sh` (~4 мин), иначе в базу уйдёт смесь; прогон старой версии —
  останавливать по id задачи, а не `pkill`.
- `ai-review --verify` смотрит дельту: закрытое прошлым кругом он может пометить «not_fixed» — сверить с файлом.
- Новые права ролей и привилегии — `ai-security` обязателен.
