# План: рабочие места при запуске и роль «Складские ордера»

Запрос владельца (2026-11-01). У производственника на главной — рабочее место производства, рабочее место закупок не
открывается. Нужно:

1. **Открывать формы при запуске.** Флажок «Открывать при запуске» в самом рабочем месте (кнопка настроек) и список
   таких форм в карточке пользователя — таблица на отдельной закладке с удалением строк. При запуске программы
   отмеченные рабочие места открываются сами.
2. **Роль «Складские ордера».** «Менеджер по закупкам» не подходит: даёт документы с ценами. Новая роль вместе с
   «Оператором производства» открывает рабочее место закупок в части приёмки.

Учёт времени — Drissotex. Конфигурация тиражная, клиент в ней не упоминается.

## Решения владельца (2026-11-01)

| Вопрос | Решение |
|---|---|
| Что делает производственник в АРМ закупок | **Приёмка по заказам**: видит заказы поставщикам и их строки **без цен и сумм**, оформляет приходные (и расходные) ордера. Не создаёт заказы, не меняет статусы, не видит оплаты, тендеры, закладку «Документы» с суммами |
| Хранение списка «при запуске» | **Регистр `НастройкиПользователей`**, как склады пользователя (закладка «Склады» карточки) |
| Флажок | И в самом АРМ (быстро), и таблица в карточке пользователя (видеть и удалять) |

## Уровень изменения

Существенное: новая роль и права, привилегированный модуль, новые предопределённые виды настроек (ПВХ), правка форм
трёх рабочих мест и карточки пользователя. Порядок: план → **`ai-review-plan`** → реализация → `ai-test` →
**`ai-review`** → **`ai-security`** (роль, привилегированная запись) → `ai-final-check` → отчёт
`.ai/reports/startup-forms-warehouse-role.md`. Версия — следующая сборка `2.0.16.133`.

## Поиск готового

- Платформа: начальная страница (`Configuration/HomePageWorkArea.hpwa`) — формы по ролям, пользователь включает их в
  «Настройке начальной страницы» только из этого списка; два АРМ в колонках главной тесны, отдельной вкладкой их
  платформа не откроет. Своего «открывать при запуске» у платформы нет.
- БСП в maERP нет. Образец хранения пользовательской настройки со списком значений в карточке — закладка «Склады»
  (`Catalogs/Пользователи/Forms/ФормаЭлемента/Module.bsl`: `ВидыНастроекСкладов`, `ПрочитатьСкладыПользователя`,
  `ЗаписатьСкладыПользователя`).
- Образец привилегированного модуля «своя запись текущего пользователя» — `CommonModules/ИзбранныеОтчетыПолныеПрава`
  (ключ — текущий пользователь, блокировка набора).

## Часть 1. Открытие форм при запуске

### Данные

- ПВХ `ВидыНастроекПользователей`: новая группа предопределённых **`ФормыПриЗапуске`** с булевыми видами
  `ОткрыватьАРМПроизводство`, `ОткрыватьАРМЗакупки`, `ОткрыватьАРМУправлениеСтанками`. Группа **не** входит в
  «Настройки доступа» — проверка `ПередЗаписью` набора (`ИзменяютсяПраваДоступа`) её не касается и не меняется.
- Запись: `Пользователь` = текущий пользователь (по пользователю ИБ, см. ниже), `Настройка` = вид, `Значение` =
  Истина. Снятый флажок — **удаление записи** (нет записи = не открывать), чтобы в регистре не копились «Ложь».
- Соответствие «вид настройки → обработка» — одна функция в модуле менеджера регистра `НастройкиПользователей`:
  `ФормыПриЗапуске()` → ТаблицаЗначений (`Настройка`, `ИмяОбработки`, `ИмяФормы` = `Обработка.<Имя>.Форма`). Это
  же белый список: других форм механизм не открывает и не записывает. Представление строки в карточке —
  `Метаданные.Обработки[Имя].Представление()` (синоним на языке сеанса).

### Серверный интерфейс

Новый общий модуль **`ФормыПриЗапускеВызовСервера`** (сервер, вызов сервера, **привилегированный**): пользователи
не имеют права записи в `НастройкиПользователей` (у большинства ролей только чтение), а флажок ставит сам
пользователь.

- `ОткрыватьПриЗапуске(ИмяОбработки) Экспорт` → Булево — состояние флажка текущего пользователя.
- `УстановитьОткрытиеПриЗапуске(ИмяОбработки, Открывать) Экспорт`:
  - `ИмяОбработки` должно быть в `ФормыПриЗапуске()`, иначе исключение (не пишем произвольный вид настройки);
  - пользователь — **только текущий**, параметра «пользователь» нет. Определяется **не** по
    `ПараметрыСеанса.Пользователь`: у «Оператора производства» и «Менеджера по закупкам» есть право `Set` на этот
    параметр сеанса (ревью плана, круг 3, P0; так же предупреждает `ИзбранныеОтчетыПолныеПрава`). Пользователь
    справочника ищется запросом по `ИдентификаторПользователяИБ = ПользователиИнформационнойБазы.ТекущийПользователь()
    .УникальныйИдентификатор`. Не найден (сеанс без карточки: `SessionModule` это допускает, первый запуск до мастера)
    — в `УстановитьОткрытиеПриЗапуске` исключение, записи нет; `ОткрыватьПриЗапуске` отвечает Ложь,
    `ФормыДляОткрытия` — пустой массив, без исключения (круг 5, P1);
  - право текущего пользователя на обработку проверяется `ПравоДоступа("Использование", <обработка>,
    ПользователиИнформационнойБазы.ТекущийПользователь())` — с **явным** пользователем ИБ, потому что в
    привилегированном модуле проверка без пользователя может отвечать за привилегированный режим (проверить на
    базе: сценарий с ролью без права должен получить отказ);
  - явная транзакция (`НачатьТранзакцию` → управляемая исключительная блокировка `РегистрСведений.НастройкиПользователей`
    по (`Пользователь`, `Настройка`) → запись набора с отбором по этим измерениям → `ЗафиксироватьТранзакцию`; в
    `Исключение` — `ОтменитьТранзакцию` и проброс), как `ИзбранныеОтчетыПолныеПрава.Добавить` (ревью плана, круг 2,
    P1); `Открывать = Ложь` — пустой набор. То же — `УдалитьФормыПриЗапуске` карточки.
- `ФормыДляОткрытия() Экспорт` → Массив из Строка — полные имена форм с записанным Истина у текущего пользователя
  **и** правом на обработку (роль отобрали — форма не открывается и ошибки при запуске нет). Порядок — порядок
  `ФормыПриЗапуске()`.

Чтение/запись для карточки пользователя (администратор, любой пользователь) — в модуле менеджера регистра,
не в привилегированном модуле: `ФормыПриЗапускеПользователя(Пользователь)` → таблица (`Настройка`,
`Представление`), `УдалитьФормыПриЗапуске(Пользователь, Настройки)` — удаляет записи **только переданных видов**
(тех, что пользователь удалил в карточке). Не «всё, чего нет в таблице»: снимок формы мог устареть, пока карточка была
открыта, а флажок в АРМ за это время добавил вид — его не трогаем (ревью плана, круг 1, P2). Пишет карточка под правами
того, кто её редактирует (администратор), как склады.

### Клиент

- `Configuration/ManagedApplicationModule.bsl`, `ПриНачалеРаботыСистемы`: после `НастроитьПанели()` и
  `ОбновитьИнтерфейс()` — `ОткрытьФормыПриЗапуске()` (новая клиентская процедура в существующем клиентском общем
  модуле запуска либо в модуле приложения): `ОткрытьФорму(Имя)` по каждой форме из `ФормыДляОткрытия()`. Ветки
  автотестов, обновления базы и headless-заполнения уже выходят раньше — там формы не открываются. При первом
  запуске (мастер `БрендированиеКлиент.ВызовПервогоЗапуска`) формы открываются после — порядок проверить.
- Ошибка не мешает запуску: `Попытка` и вокруг серверного вызова `ФормыДляОткрытия`, и вокруг каждого
  `ОткрытьФорму`, с записью в журнал регистрации. Если мастер первого запуска открыт (`ВызовПервогоЗапуска`
  асинхронный), формы не открываются: пользователей ещё нет, `ФормыДляОткрытия` вернёт пустой массив.
- Повтор с начальной страницей: АРМ производства у оператора производства уже на главной; если отметить и его,
  будет вторая копия во вкладке. Принимаем: флажок ставит сам пользователь. В подсказке флажка АРМ производства —
  фраза «если рабочее место уже на начальной странице, отмечать не нужно».

### Рабочие места (АРМ производства, закупок, управления станками)

- В командной панели формы — подменю **«Настройки»** (картинка-шестерёнка) с командой формы
  **«Открывать при запуске»** (кнопка-флажок, `Пометка`). При создании формы — `Пометка = ОткрыватьПриЗапуске(...)`,
  нажатие — `УстановитьОткрытиеПриЗапуске(...)` и смена пометки. Тексты на 4 языках.
- Видимость — всем, кто открыл форму (право на обработку уже есть).

### Карточка пользователя

- Новая закладка **«При запуске»** (`Catalogs/Пользователи/Forms/ФормаЭлемента`): таблица значений-реквизит формы
  `ФормыПриЗапуске` (`Представление`, `Настройка` скрытая), только просмотр строк, **удаление разрешено, добавление
  нет** (добавляют флажком в АРМ). Чтение — `ПриСозданииНаСервере` (как `ПрочитатьСкладыПользователя`). Удалённые
  строки собираются в реквизит формы `УдаленныеФормыПриЗапуске` (`ПередУдалением` таблицы), в
  `ПослеЗаписиНаСервере` удаляются только они (`УдалитьФормыПриЗапуске`), затем список удалённых **очищается** и
  таблица перечитывается — повторная запись открытой карточки не применяет удаление второй раз (круг 4, P2).
- Оформление — `docs/FORMS-STYLE.md`, шрифт шапок колонок (`colfont.py`).

## Часть 2. Роль «Складские ордера» и режим приёмки АРМ закупок

### Почему сейчас не открывается

Право `Use/View` на `DataProcessor.АРМЗакупки` есть только у роли «Менеджер по закупкам». Даже с правом на
обработку у оператора производства форма упадёт при открытии: `ЗагрузитьДанныеЗаказа` → `ЗапросОплат`
(`DataProcessors/АРМЗакупки/ManagerModule.bsl` ~4330, `НалоговаяНакладнаяПокупка`) и `ТекстЗапросаДокументов`
(~4662: кассовые ордера, банковские поступления и списания, налоговые накладные) читают документы, на которые у
роли нет права, без проверки `ПравоДоступа` — «Нарушение прав доступа». При включённых тендерах то же с
`ПредложениеПоставщика`.

### Роль `СкладскиеОрдера`

Новая роль (`Roles/СкладскиеОрдера`), синонимы на 4 языках, без ограничений записей (RLS в ролях не используется).
Предназначена **в паре с «Оператором производства»**; сама по себе даёт:

| Объект | Права |
|---|---|
| `DataProcessor.АРМЗакупки` | Use, View |
| `Subsystem.Закупки` | View (иначе раздела и команды АРМ нет в интерфейсе; остальное в разделе видно по своим правам) |
| `Document.ЗаказПоставщику` | Read (без View, Insert, Update — форму документа с ценами не открыть) |
| `AccumulationRegister.ЗаказыПоставщикам` | Read |
| `Document.ПриходныйОрдер`, `Document.РасходныйОрдер` | как у «Оператора производства» (полные интерактивные), плюс команды печати ордеров (View) |

Прочее, что читает видимая часть АРМ (номенклатура, контрагенты, склады, `ТоварыВНаличии`), у «Оператора
производства» есть; роль это не дублирует — состав сверяется сценарием (см. «Проверка»).

### Режим приёмки в АРМ закупок

Признак формы **`РежимПриёмки = Не ПравоДоступа("Изменение", Метаданные.Документы.ЗаказПоставщику)`** — по правам,
а не по имени роли: менеджер по закупкам и администратор видят АРМ как раньше.

В режиме приёмки:
- скрыты: верхняя закладка «Потребность» с заказом потребности и тендером; команды «Создать» заказ, подменю
  статусов заказа; нижние закладки «Оплаты» и «Документы», «Предложения товара»; открытие формы заказа из списка
  (двойной щелчок по заказу не открывает документ с ценами);
- текущая верхняя закладка — «Заказы», нижняя — «Поступления»;
- **нижняя таблица «Поступления» выбранного заказа** (`ДанныеЗаказа.Поступления`, `ТекстЗапросаПоступлений`) сейчас
  читает только ПТУ и его `ТЧТовары`. В режиме приёмки её источник — **приходные ордера** заказа
  (`Документ.ПриходныйОрдер` и `ТЧТовары` с `Основание = &Заказ`), с теми же колонками: номер и дата накладной —
  пустые, `Сумма` — 0 (колонка скрыта). `ТекстЗапросаПоступлений(РежимПриёмки)`; вне режима — как сейчас
  (круг 5, P1). Обработчик открытия строки нижней таблицы открывает документ строки — в режиме приёмки это ордер.
  Тип колонки `Поступления.Документ` реквизита формы (`Form.form` ~10662) расширяется до
  `DocumentRef.ПоступлениеТоваровУслуг` + `DocumentRef.ПриходныйОрдер` (круг 6, P1);
- **приёмка по заказу** (круг 7, P1): существующая кнопка «Создать приходный ордер» открывает пустую форму ордера и
  заказ не передаёт — для приёмки она не годится. Путь приёмки выбранных заказов — «Создать поступление»
  (`СоздатьПоступлениеПоЗаказам` → `Обработки.АРМЗакупки.ПринятьЗаказы` → `АРМПроизводство.ЗаписатьСтрокиПоступления`):
  на складе, ордерном на сегодня, он уже создаёт **приходный ордер** с кодами строк заказа
  (`АРМПроизводство.НовыйДокументСтроки` → `ОрдерВместоДокумента`), на неордерном — ПТУ. В режиме приёмки этот путь
  остаётся, но **только с ордером**: в данные строк передаётся признак `ТолькоОрдер`, и
  `АРМПроизводство.ЗаписатьСтрокиПоступления`/`ЗаписатьСтрокуДокумента` отказывают (результат `Успех = Ложь` с
  текстом «Склад не ордерный: поступление оформляет менеджер по закупкам»), если **итоговый документ** записи — не
  `ПриходныйОрдер`: проверка стоит после получения объекта документа в обоих путях — нового (`НовыйДокументСтроки`)
  и существующего (`ДокументИСтрокаДокумента` → `ЗаблокированныйДокументСтроки`, круг 8, P2), до изменения строк. Признак ставит **сервер** АРМ закупок (`ПринятьЗаказы`, `ЗаписатьСтрокуПоступления`) по своему
  `РежимПриёмки()` (права текущего пользователя), а не клиент — серверный API не обходится вызовом с клиента
  (круг 7, P2: сейчас `ЗаписатьСтрокуПоступления` идёт прямо в `ЗаписатьСтрокуДокумента` без проверок);
- нижняя таблица «Поступления» в режиме приёмки — только просмотр (ввод строк — путь выше), обработчики добавления
  строк не вызываются; серверная защита — тот же `ТолькоОрдер`;
- **поступления с ценами недоступны из АРМ** (ревью плана, круг 1, P1): в верхнем списке поступлений (оба режима —
  «Документы» и «Товары») показываются только приходные ордера; `ПоступленияВыбор`, `СписокПоступленийВыбор`,
  `ТоварыПоступленийВыбор` открывают только `ПриходныйОрдер`; `СоздатьПоступление` и «Создать поступление» создают
  только приходный ордер — на неордерном складе кнопка недоступна с подсказкой «Поступление на этот склад оформляет
  менеджер по закупкам». Запись строк поступления в режиме «Товары» (механизм ПТУ) — только просмотр.
  Права «Оператора производства» на ПТУ остаются (рабочее место производства) — АРМ закупок к ним просто не ведёт.

**Независимо от режима** — защита запросов правами (то, что сейчас роняет форму у любой урезанной роли). Пакеты не
дробятся по ветвям `ОБЪЕДИНИТЬ`: в пакете оплат налоговые накладные участвуют и соединением при создании `ВТНакладные`,
и в зависимой цепочке временных таблиц (ревью плана, круг 1, P1). Поэтому:
- функция `ОплатыДоступны()` (модуль менеджера АРМ закупок) — `Чтение` на **все объекты метаданных** пакетов оплат,
  документов цепочки и сальдо: документы (`НалоговаяНакладнаяПокупка`, кассовые ордера, банковские поступления и
  списания, возвраты поставщику, ПТУ) **и регистры** (`ДвиженияПоКассе`, `ВзаиморасчётыСПоставщиками`) — ревью
  плана, круг 2, P2. Список — константой рядом с текстами запросов; сценарий разбирает тексты `ЗапросОплат`,
  `ТекстЗапросаДокументов`, `ТекстЗапросаСальдо` и сверяет: каждый `Документ.<Имя>`, `РегистрНакопления.<Имя>`,
  `РегистрСведений.<Имя>` есть в списке;
- без доступа `ДанныеЗаказа` **выполняется**, но не выполняет запрос оплат и запрос документов цепочки: свойства
  `Оплаты` и `Документы` результата — пустые коллекции той же структуры, `Товары`, `Поступления`, `Шапка` — как
  сейчас (ревью плана, круг 3, P1). `ОплатыЗаказов` и запрос сальдо при этом не выполняются; закладки «Оплаты» и
  «Документы» скрыты, колонки оплат и сальдо в списке заказов пусты и скрыты. Признак доступа передаётся в
  `ДанныеЗаказа`/`ОплатыЗаказов` параметром (по умолчанию — `ОплатыДоступны()`), чтобы сценарий проверил ветку
  «без доступа» под администратором;
- тендерные запросы (`ЗаполнитьТендерСтрок`, `ПредложенияТовара`) — при отсутствии права чтения
  `ПредложениеПоставщика` не выполняются.

### Цены и суммы

- `Обработки.АРМПроизводство.ПоказыватьСуммы()` **не меняется** (ревью плана, круг 2, P2: правило по роли задело
  бы менеджера по закупкам с ролью «Складские ордера» и АРМ производства).
- В АРМ закупок видимость денег — `СуммыВидны = Не РежимПриёмки И ПоказыватьСуммы()`: тот же признак по правам, что и
  режим приёмки, плюс прежняя настройка «Видеть суммы». `СуммыВидны = Ложь` скрывает **все** денежные колонки: `ЗаказыСумма`, `ПотребностьЦена`,
  `ТоварыЦена`/`ТоварыСумма`, `СписокПоступленийСумма`, `ПоступленияСумма`, `ОплатыСумма`, `ДокументыСумма`,
  `ПредложенияТовараЦена`/`СуммаРегл` (сейчас только `ТоварыПоступленийЦена`/`Сумма`), и **надпись сальдо**
  `НадписьСальдо` — `ЗагрузитьДанныеЗаказа` пишет в неё сальдо независимо от колонок (круг 8, P2): при
  `СуммыВидны = Ложь` надпись скрыта, а сальдо не запрашивается (оно и так не выполняется без `ОплатыДоступны`).
- Ограничение интерфейсное: данные заказов с ценами у «Оператора производства» читаются и сейчас (Read на
  `ЗаказПоставщику`, полные права на ПТУ). Ограничение полей ролью — вне объёма; фиксируется в `docs/TECHDEBT.md`.

## Проверка

Раннер `ТестыДокументов` работает под администратором, поэтому права роли проверяются явно:

1. **Сценарий «ФормыПриЗапуске»** (`ТестыДокументов`): установка и снятие флажка текущему пользователю
   (`ОткрыватьПриЗапуске` отвечает, запись «Ложь» не остаётся), `ФормыДляОткрытия` — порядок и состав, имя вне
   белого списка — исключение, `УдалитьФормыПриЗапуске` удаляет только переданные виды: вид, добавленный после
   чтения таблицы, остаётся; виды других групп (склады, «Видеть суммы») не тронуты.
1а. **Сценарий режима приёмки АРМ закупок**: `ОплатыДоступны()` по роли (`Ложь` для «Оператор производства» +
   «Складские ордера»); список документов пакетов совпадает с `Документ.<Имя>` в текстах запросов; функции
   данных заказа при недоступных оплатах возвращают пустые оплаты и документы без исключения.
2. **Сценарий «РольСкладскиеОрдера»**: `ПравоДоступа(…, Метаданные.Роли.СкладскиеОрдера)` — Use на АРМ, View на
   подсистему, Read без View/Insert/Update на заказ поставщику, нет прав на кассовые и банковские документы;
   у «Оператора производства» + «Складских ордеров» нет `Изменение` заказа поставщику (режим приёмки) и нет `Чтение`
   хотя бы одного объекта `ОплатыДоступны` (оплаты скрыты).
3. **Живая проверка под пользователем с ролями «Оператор производства» + «Складские ордера»** на копии базы
   (`build/ib-kp`; раннер `ТестыДокументов` работает под администратором, поэтому права проверяются только так —
   круг 4, P2). Завести пользователя (заранее, под администратором, на копии) и:
   - открыть АРМ закупок `scripts/openform.sh` под ним — форма открывается без «Нарушения прав доступа»;
   - внешней обработкой под ним (раннер `1cv8c /Execute`, как для баз клиентов): `ОплатыДоступны() = Ложь`,
     `ДанныеЗаказа` по заказу поставщику возвращает товары и поступления без исключения, создание приходного ордера
     по заказу той же серверной функцией, что кнопка АРМ, — ордер записан и проведён; `УстановитьОткрытиеПриЗапуске`
     пишет запись **его** пользователя, а после `ПараметрыСеанса.Пользователь = <другой>` (право `Set` у роли есть)
     — всё равно его, не другого;
   - пользователь без права на АРМ получает отказ `УстановитьОткрытиеПриЗапуске`;
   - перезапуск клиента под ним — отмеченный АРМ открылся.
4. Смок, тесты документов, `lint`/`refcheck`/`listcheck`/`colfont`/`menucheck`, реестр `docs/TESTS.xlsx`.

## Риски

- Привилегированная запись в регистр настроек: только текущий пользователь, только белый список, только группа
  `ФормыПриЗапуске` — ревью безопасности обязательно.
- `ПравоДоступа` в привилегированном модуле — проверить на базе (п. 3), не полагаться на память.
- Формы трёх АРМ большие: правка `Form.form` — по чек-листу tiny1C (`workflow-004`, `workflow-009`: дифф всей формы),
  `<visible>true</visible>` у новых элементов.
- Новые предопределённые элементы ПВХ появляются в базе при обновлении конфигурации; обработчик обновления не нужен
  (нет записи = не открывать).
- Ограничение цен интерфейсное (см. выше) — в TECHDEBT.

## Ревью плана

`ai-review-plan`, 8 кругов, итог — **approve_with_changes** (два P2 последнего круга внесены выше). Закрыты: пакет
оплат целиком, а не по ветвям; поступления с ценами из АРМ; удаление только явно удалённых строк карточки и очистка
их списка; явная транзакция записи; регистры в проверке доступа; суммы — по режиму приёмки, а не по роли глобально;
пользователь — по пользователю ИБ, а не по параметру сеанса (P0); сеанс без карточки; источник и тип нижней таблицы
поступлений; путь приёмки через `ПринятьЗаказы` с серверным признаком «только ордер»; проверка роли живым
пользователем. Отчёты — `.ai/reviews/startup-forms-warehouse-role/`.

## Порядок работ

1. ПВХ, регистр (функции менеджера), модуль `ФормыПриЗапускеВызовСервера`, запуск в модуле приложения.

5. Сценарии, прогон на копии базы, живая проверка под пользователем, «Что нового» на 4 языках, версия 2.0.16.133.
