# 12.1. Движения и партии — план (редакция 2, 2026-10-03)

Источник — промпт `docs/plans/production-stock-postings-prompt.md` (решения владельца 2026-09-23) и ответы владельца
2026-10-03 на четыре открытых вопроса — все по рекомендации:

1. **История не пересчитывается**: правила действуют на новые проведения, старые документы перепроводятся по
   требованию. Обработчика обновления нет.
2. **Отказ при уводе партии в минус — с обходом у администратора**: у пользователя с правом «Администрирование»
   вместо отказа — предупреждение, проведение проходит.
3. **Отказ в любом складском документе**, а не только в производственном контуре: правило одно.
4. **`AutoDelete` — только складским документам**, кассовые и прочие не трогаем.

Редакция 2 — по гейту плана (`.ai/reviews/production-stock-postings/01-plan-review-claude.md`, вердикт на
редакцию 1 — reject: обход открыт всем в привилегированном режиме, снимок не доходит до проверки, `AutoDelete` не
очищает наборы в памяти и ломает чтение своих движений в двух документах).

Состояние сверено на 2.0.16.11: `ТоварыВНаличии` пишут 17 документов, `AutoDelete` — у четырёх
(`ПередачаВПереработку`, `ПоступлениеИзПереработки`, `РеализацияТоваровУслуг`, `НалоговаяНакладная`).

Задача делится на две сборки: 2.0.16.12 (разделы C и B) и 2.0.16.13 (раздел A — потребности, права ролей).

## Сборка 2.0.16.12

### Порядок событий — сначала опыт

До правок — опыт на копии базы: журнал событий документа в `ДополнительныеСвойства` (ПередЗаписью, ПриЗаписи,
ОбработкаПроведения, ОбработкаУдаленияПроведения, момент удаления прежних движений по `AutoDelete` — видно запросом
движений регистратора в каждом событии), для проведения, перепроведения, отмены проведения и пометки удаления.
По знанию платформы: проведение — ПередЗаписью → запись объекта (удаление прежних движений по `AutoDelete`) →
ПриЗаписи → ОбработкаПроведения → запись наборов; отмена — ПередЗаписью → ПриЗаписи → ОбработкаУдаленияПроведения →
удаление движений платформой. Результат опыта — в редакцию 3 плана, если он расходится с этим.

### C. Удаление прежних движений

**Девять документов** получают `registerRecordsDeletion = AutoDelete`: `ВыпускПродукции`, `ПоступлениеТоваровУслуг`,
`ОприходованиеТоваров`, `СписаниеТоваров`, `ПеремещениеТоваров`, `ПересортицаТоваров`, `АктРазбора`,
`ВозвратОтПокупателя`, `ВозвратПоставщику`.

Не получают (сужение решения 4 — сказать владельцу):
- `КорректировкаРегистров` — `posting = Deny`, движения пишет форма с замещением: свойство ничего не делает;
- налоговые `НалоговаяНакладнаяПокупка`, `ВозвратПоставщикуНалоговый`, `ВозвратОтПокупателяНалоговый` — с 2.0.16.1
  товар не двигают (`СкладНалоговый`), пользы нет, а их проведение читает свои прежние записи денежных регистров
  (`ДенежныеСредстваОрганизаций.ПолучитьОплаты`).

Что даёт `AutoDelete`: прежние движения удаляются в базе **до** `ОбработкаПроведения`, и документ при перепроведении
читает остатки без своих старых движений — сдвиг даты вперёд больше не вычитает его дважды (TECHDEBT S4-B).

Чего `AutoDelete` не даёт: наборы в памяти не очищаются. Поэтому всем девяти — в начало `ОбработкаПроведения` явная
очистка наборов `Движения` (общая процедура `РаботаСДокументами.ОчиститьДвижения(Движения)`: `Очистить()` и
`Записывать = Истина` по каждому набору, по образцу `ПередачаВПереработку` / `ПоступлениеИзПереработки`). Это
чинит программное повторное «Провести» того же объекта (управляемая форма каждый раз собирает объект заново —
там задвоения не было).

Чтение своих прежних движений в проведении (ловушка 4):
- `УправляемыеБлокировки.ПотребностиПроизводстваЗакупки` (`CommonModules/УправляемыеБлокировки/Module.bsl:74`,
  зовут `ПоступлениеТоваровУслуг` и `ВозвратПоставщику` из `ОбработкаПроведения`) читает `ЗаказыДвиженийДокумента`
  — с `AutoDelete` движения к этому моменту удалены, прежний заказ выпадает из блокировки при смене основания.
  Список прежних заказов снимается в `ПередЗаписью` в `ДополнительныеСвойства`, блокировка берёт его оттуда.
- Остальные места проверены гейтом и безопасны: `ПроизводственныеЗаказы.ЗапомнитьЗаказыДокумента` вызывается в
  `ПередЗаписью`; запросы `ПотребностиПроизводства` с `Регистратор <> &Ссылка` самосогласованы.

Блокировки: `AutoDelete` удаляет движения до `Блокировка.Заблокировать()` и берёт неявные блокировки итогов в
обратном порядке (TECHDEBT, раздел S4-B) — теперь у девяти документов, включая массовые поступление и перемещение.
Окно взаимоблокировок шире; оценка — `ai-database`, пункт TECHDEBT расширяется.

### B. Отказ при уводе партии в минус

**Место — общая процедура проведения, а не модуль набора**: `РегистрыНакопления.ТоварыВНаличии.ПроверитьПартии(ДокОбъект,
Отказ)`. Вызов:
- в `ОбработкаПроведения` всех 17 документов — после `Движения.Записать()` (у документов, которые наборы явно не
  пишут, — добавить явную запись перед проверкой);
- в `ОбработкаУдаленияПроведения` всех 17 — после явной очистки и записи наборов (сейчас движения при отмене удаляет
  платформа после события, кроме документов с заказами на производство — у них уже есть явная очистка);
- пометка удаления проведённого документа идёт через отмену проведения — тем же путём.

Снимок `A0` — в `ПередЗаписью` документа (до записи объекта, до удаления по `AutoDelete`): итоговые остатки ключей
его текущих движений `ТоварыВНаличии` → `ДополнительныеСвойства` документа; после проверки снимок удаляется.
Подписка на 17 документов (`ПередЗаписью`, режимы проведения и отмены проведения) — одно место, без правки 17 модулей.

Ключ партии — все измерения регистра: `МестоХранения, Номенклатура, Характеристика, Серия, Партия, ДатаПартии`.

Правило: для ключей, которые документ трогает (старые ∪ новые), итоговый остаток после записи `A` (запрос
`Остатки()` без периода по ключам документа) сравнивается со снимком `A0`; для ключа без старых движений
`A0 = A − собственный оборот документа по ключу`. **Отказ, если `A < 0` и `A < A0`** — документ ухудшил партию.
Исторический минус, который документ не ухудшил, проходит (решение 1).

Отказ — через `Отказ` документа и `СообщитьОбОшибкеСписания` (канал `ДополнительныеСвойства.ТекстОшибки` — доходит
до интерфейса продавца и фоновых заданий), а не исключением из записи набора.

**Обход** — только по пользователю ИБ: `ПравоДоступа("Администрирование", Метаданные,
ПользователиИнформационнойБазы.ТекущийПользователь())`. Без пользователя `ПравоДоступа` в привилегированном режиме
(`postInPrivilegedMode` у всех 17 и `УстановитьПривилегированныйРежим(Истина)`) даёт Истина всем — урок проекта
(`production-2mzl-e7-potrebnosti.md`, `-e9-avtovypusk.md`). У администратора — то же сообщение предупреждением.
При групповом перепроведении предупреждения не дублируются по ключу.

Текст (`НСтр` ×4): позиция, партия (документ-приход), итоговый минус, что делать — перепровести поздние документы-
расходчики по датам или сторнировать; фоновое перепроведение последовательности `Основная` выпуск, передачу и
поступление из переработки не включает.

Не проверяется: `ОбменДанными.Загрузка`; `КорректировкаРегистров` (технический инструмент, движения пишет форма с
замещением — снимок «было» по её прежним записям возможен, но отдельной задачей: TECHDEBT, сказать владельцу).

Гонка: снимок и итог читаются без блокировки ключей, которые документ уменьшает задним числом (приход): параллельный
расход может проскочить — пропуск минуса, не взаимоблокировка. TECHDEBT.

### Проверка (2.0.16.12)

Опыт порядка событий (выше). Уровень 3 — каждый настоящий отказ последним шагом своего сценария (отказ портит
транзакцию теста):
- обход: функция признака обхода под `УстановитьПривилегированныйРежим(Истина)` для роли без «Администрирования»
  (проверка по роли, как в `ТестыДокументов` у прав) — Ложь; у администратора — Истина;
- сдвиг даты `ВыпускПродукции` вперёд и перепроведение — движения не вычитаются дважды; программное повторное
  «Провести» того же объекта — движений столько же;
- перепроведение поступления, чью партию частично израсходовали, без изменений — проходит;
- исторический минус, не ухудшенный, — проходит;
- перепроведение поступления со сменой заказа-основания — прежний заказ в блокировке и потребность пересчитана;
- уменьшение продукции проведённого поступления из переработки, партию которого отгрузили, — у администратора
  предупреждение и проведение; правило без обхода — отказ (последний шаг);
- отмена проведения `ОприходованиеТоваров`, партию которого израсходовали, — отказ правила (последний шаг).
Смок, doctests, BSL LS, refcheck. Версия 2.0.16.12, «Что нового» ×4.
