`docs/plans/industry-phones.md` (сборка 2.0.17.10: флаг учёта, регистры, модуль `СерийныйУчет`, валидатор набора).

## Что есть сейчас

- IMEI = элемент `СерииНоменклатуры` (владелец — товар с `УчетПоСерийнымНомерам`, наименование — номер); регистр
  `СерийныеНомера` держит уникальность номера; валидатор набора `ТоварыВНаличии` и подписки — инварианты экземпляра.
- Штрихкоды: регистр `ШтрихкодыНоменклатуры` (измерение `Штрихкод`, ресурсы Номенклатура, Характеристика, Упаковка,
  Серия). Серия при записи получает сгенерированный EAN-13 (`СерииНоменклатуры.ПриЗаписи → ЗанятьНовыйШтрихкод`).
  Поиск по штрихкоду в документах — `ОбщегоНазначенияВызовСервера.ПолучитьНоменклатуруПоШтрихкоду` (Номенклатура,
  Характеристика, Серия), добавление строки — `РаботаСДокументамиКлиентСервер.ДобавитьНоменклатуруПоШтрихкоду`: строка с
  тем же товаром, характеристикой и **серией** получает +1 к количеству. Касса `VentesEnDetail`: скан — тот же помощник,
  ручной ввод штрихкода — `StructureProductByBarCode` (по остаткам, с серией), повторный ввод той же серии ничего не
  добавляет.
- Сканирование есть в формах поступления, реализации, перемещения, оприходования; в возврате от покупателя нет.
  Перемещение и оприходование — одна серия на строку (`ТЧТовары.Серия`, без `ТЧСерии`).
- Возврат на кассе — только по выбранному чеку (`СоздатьВозвратНаСервере(Док)` + `Заполнить(Док)`); для серийного
  товара сборка 2.0.17.10 требует основание-продажу и сверяет ключ «товар + характеристика + серия» в документе и наборе.
- Чек (`РеализацияТоваровУслуг.PrintTicket`, макет `Чек`, области Шапка/Строка/Подвал) — строки по `ТЧТовары` без
  серии. Накладная BL (фирменная печать, `ФирменнаяПечать.ДанныеСтрокДокументов` с `ЯзыкСвойств`) уже печатает под
  строкой заполненные дополнительные реквизиты товара — значит, **гарантия (`ГарантияМесяцев`) в BL уже выводится**;
  серии в строках фирменной печати нет.
- Серия с движениями не переименовывается (2.0.17.10) — ошибочно введённый IMEI исправить нечем (TECHDEBT 2.0.17.10).

## 1. Скан IMEI — через закрытый регистр номеров

**Изменение после ревью безопасности реализации (круг 3, P0):** IMEI **не копируется** в регистр
`ШтрихкодыНоменклатуры` — его читают роли без права чтения серий (например, «ОбменМобильнаяДоставка»), и копия
раскрыла бы номера мимо прав. Скан находит серию через регистр `СерийныеНомера` (закрыт для ролей с 2.0.17.10).

- **Поиск по штрихкоду сверяет номер IMEI.** `ОбщегоНазначенияВызовСервера.ПолучитьНоменклатуруПоШтрихкоду` (его же
  теперь вызывает поиск кассы `StructureProductByBarCode`) ищет значение в `ШтрихкодыНоменклатуры` и через
  `СерийныйУчет.ТоварПоНомеру(Номер)` в `СерийныеНомера`: нашлось одно — возвращается оно; штрихкод другого товара и
  IMEI серийного товара одновременно — **неоднозначность**: товар не подбирается, сообщение «выберите товар вручную».
- `ТоварПоНомеру` — только точное совпадение одного номера, ссылки товара и серии, **только пользователю с правом
  чтения серий и номенклатуры** (проверка до привилегированного режима; иначе — «не найдено»). Поиск по штрихкоду
  без права чтения серий не возвращает серию, без права чтения номенклатуры — ничего.
- Проверка «номер не занят штрихкодом» берёт **исключительную блокировку ключа `ШтрихкодыНоменклатуры.Штрихкод`** (ту
  же, что `ЗанятьШтрихкод`) до чтения — проверка и занятие штрихкода другим сеансом сериализуются; порядок: номенклатура
  → номера IMEI → штрихкоды.
- Номер новой серии серийного товара, совпадающий со штрихкодом другого товара или серии, — отказ записи серии
  (неоднозначность не заводится); включение учёта у товара, номер серии которого совпадает с чужим штрихкодом, —
  отказ со списком.
- Перенос серии к другому владельцу (без движений): все записи `ШтрихкодыНоменклатуры` с этой серией (сгенерированный
  EAN) переписываются на нового владельца под исключительной блокировкой — поиск возвращает номенклатуру записи.
- Карточка серии: штрихкод из 13 знаков рисуется EAN-13, прочие — Code128.
- **Обработчик обновления 2.0.17.11** (`ОбновлениеПрограммыОбработчики.ПерейтиНаВозвратПоПродаже`, оперативный):
  в базе отрасли «Телефоны и аксессуары» включает константу `ВозвратТолькоПоПродаже` (п. 5) и пишет в журнал
  регистрации предупреждения о строках серийных товаров с неоднозначным кодом (п. 3). Штрихкоды не меняет.
- Признак «серия серийного товара» для клиента (`СерийныйУчетВызовСервера.ЭтоСерияСерийногоТовара`) — только при
  праве чтения серий; номера IMEI в печати (`СерииСтрокДокументов`) — только при праве чтения серий.

## 2. Правило скана для серийного товара

- `ДобавитьНоменклатуруПоШтрихкоду`: новой строке табличной части с колонкой `КодСтроки` присваивается код
  «максимум + 1» (сейчас скан оставляет 0) — разложение по `ТЧСерии`, проверки и печать опираются на код строки.
- `ДобавитьНоменклатуруПоШтрихкоду`: если найдена **серия серийного товара** и она уже есть в документе — в строке
  `ТЧТовары` (колонка `Серия`) **или в `ТЧСерии`** (распределение строки по `КодСтроки`, у документов, где эта ТЧ
  есть), — строка не увеличивается и новая не добавляется, кассиру/кладовщику сообщение «IMEI уже в документе». Признак серийности — серверной функцией
  `СерийныйУчетВызовСервера.СерийнаяСерия(Серия)` только когда серия заполнена (один вызов на скан серии).
- Касса, ручной ввод (`AfterInputBarcode`): повторный ввод той же серии — то же сообщение (сейчас молча ничего).
- Возврат от покупателя: обработчик скана не добавляется (возврат заполняется по документу продажи; лишние строки —
  отказ валидатора). Отказ сканирования в возврате — без изменений.
- Новая строка по скану IMEI серийного товара: **упаковка — пустая (базовая единица), количество и количество
  упаковок — 1** независимо от упаковки по умолчанию (существующий помощник ставит одну упаковку, а коэффициент
  упаковки может быть больше 1).
- Перемещение и оприходование: скан IMEI добавляет строку с серией и количеством 1; ТЧ серий этим документам не
  добавляется (одна серия на строку достаточна для IMEI; реструктуризации нет).

## 3. Гарантия и IMEI в печати

- **Чек** (`PrintTicket`): под строкой серийного товара — строка «IMEI: <номера>; гарантия: N мес.» (номера — серия
  строки или серии `ТЧСерии` по `КодСтроки`; гарантия — доп. реквизит `ГарантияМесяцев` товара, если заполнен).
  Вывод — в параметр описания той же области `Строка` (`Descriptif` + перенос строки), без правки макета; у
  несерийного товара с гарантией — только гарантия.
- **Накладная BL и фактура** (фирменная печать): в `ДанныеСтрокДокументов` — колонки `Серия` (представление серии
  строки, пусто, где колонки нет), `КодСтроки` и `УказаноНесколькоСерий` (константы, где нет). Номера IMEI строки:
  без признака нескольких серий — серия самой строки; с признаком — серии `ТЧСерии` этой строки по `КодСтроки`
  (функция `СерийныйУчет.СерииСтрокДокументов(ИмяДокумента, Ссылки)` → «ссылка|код строки» → номера; строки с
  признаком и нулевым или повторяющимся кодом у серийного товара не встречаются — см. п. 3 ниже). Только для серийной номенклатуры.
- Проверка разложения по сериям (подписка, `ПроверитьРазложениеПоСериям`) дополняется: у строк серийного товара с признаком нескольких серий код строки должен быть **больше нуля и уникален** в
  документе — иначе отказ проведения (перенос серий в налоговый документ `СинхронизироватьСерии` и связь возвратов
  с продажей опираются на код строки). Автонумерации нет: коды присваивают формы и скан.
- **Исторических нулевых кодов у серийного товара нет по построению**: включение учёта (`ПроверитьИсториюВключения`)
  дополнительно отказывает, если у товара есть документы (реализации, поступления, возвраты, налоговые документы на
  основаниях) со строкой этого товара с признаком нескольких серий и нулевым или повторяющимся кодом строки — с
  перечнем документов (представление — по правилу 2.0.17.10 для закрытых пользователю документов). Пока флаг не
  включён, история товара живёт по прежним правилам; после включения все его документы уже с корректными кодами,
  и возвраты, копирующие строки продажи, и перенос серий в налоговый документ работают без изменений.
- **Товары, включённые в 2.0.17.10** (сборка не опубликована — флаг стоит только в тестовых базах): обработчик
  обновления 2.0.17.11 (п. 1) проверяет их документы тем же запросом и пишет в журнал регистрации предупреждение с
  перечнем документов, у которых строка серийного товара с несколькими сериями имеет нулевой или повторяющийся код.
  Автоматически коды не меняются (связь с возвратами и налоговыми документами неоднозначна); такой документ при перепроведении получает отказ с текстом «у строки N с несколькими сериями нет уникального кода
  строки: удалите строку и добавьте её заново». Поля кода строки в форме нет — новая строка получает код
  обработчиком формы, серии строки вводятся заново формой «Указать серии» (связанные строки `ТЧСерии` удаляются вместе
  со строкой). Затрагивает только тестовые базы с флагом из 2.0.17.10. Гарантия в BL уже
  печатается свойствами; в фактуре свойства не печатаются — добавить только IMEI.
- Функция чтения гарантии — `СерийныйУчет.ГарантияМесяцев(Товары)` → соответствие товар → число (пакетом через
  `УправлениеСвойствами.ЗаполненныеСвойстваОбъектов` / значение свойства по имени).

## 4. Исправление IMEI

- Серверная функция `СерийныйУчет.ИсправитьНомерСерии(Серия, НовыйНомер)` (экспорт, в модуле с вызовом сервера
  `СерийныйУчетВызовСервера.ИсправитьНомерСерии`): только пользователю с правом изменения серий **и** ролью «Руководитель»
  или полными правами; в транзакции — блокировка номенклатуры владельца, старого и нового номеров, проверка свободы
  нового номера (регистр номеров и штрихкодов), переименование серии со служебным признаком
  `ДополнительныеСвойства.ИсправлениеIMEI` (снимает запрет переименования серии с движениями только для смены
  номера; владелец не меняется), перерегистрация номера и штрихкода, запись в журнал регистрации (старый → новый
  номер, пользователь). Движения не меняются: серия — та же ссылка.
- Команда формы серии «Исправить IMEI» (видна при серийном владельце): запрос нового номера, вызов сервера.
- Признак `ИсправлениеIMEI` ставится только этой функцией (серверный код; клиент не передаёт ДополнительныеСвойства
  в запись справочника).

## 5. Возврат только по чеку

- Новая константа `ВозвратТолькоПоПродаже` (Булево, «Возврат от покупателя только по документу продажи»): флажок в
  «Настройках программы» (форма «Номенклатура», рядом с сериями), включается отраслью «Телефоны и аксессуары» и
  обработчиком обновления в базах, где эта отрасль уже выбрана. **Чтение в проверках — привилегированно**
  (`СерийныйУчет.ВозвратТолькоПоПродаже()`): роли кладовщика и кассира прав на константу не получают и не нуждаются
  в них; право изменения — только у роли с правом «Настроек программы» (как у соседних констант формы).
- `СерийныйУчет.ПередЗаписьюДокумента`: ранний выход «нет серийной номенклатуры» не применяется к
  `ВозвратОтПокупателя` и `РеализацияТоваровУслуг` при включённой константе — проверки возврата и продажи выполняются
  и для несерийных документов. Без константы — как в 2.0.17.10 (только серийные строки).
- **Основание возврата** (при константе — для всех строк, без неё — для серийных): заполнено, **проведено** (признак
  `Проведен` основания читается под его блокировкой) и является физической реализацией **или** налоговым документом
  на основаниях (действующее правило `ТекстЗапретаДокументаПоОснованию` возвращает покрытую продажу только по
  налоговому документу — это же исправляет отказ серийного возврата по налоговому основанию в 2.0.17.10).
  Блокировка основания (и покрытых продаж налогового документа) — протоколом `ЗаблокироватьОснованияВозврата`,
  который вызывается в `ВозвратОтПокупателя.ПередЗаписью` раньше подписки.
- **Единственный расчёт «доступно к возврату» — по строкам документов**, `СерийныйУчет.ДоступноКВозвратуПоСтрокам(
  Основание, ИсключитьВозврат)`: продано = строки основания (`СерииИРазмещение.ОбъединитьТоварыССериями` объекта:
  строка с несколькими сериями раскладывается по `ТЧСерии`) по ключу «товар + характеристика + серия»; возвращено =
  строки проведённых возвратов с этим основанием (кроме текущего), тем же разложением. Движения не используются
  нигде: реализация с ордерного склада сама не списывает остаток, комплект в движениях разложен на составляющие,
  у налогового документа физический итог нулевой — по строкам ключи совпадают во всех случаях. Функция 2.0.17.10
  `ДоступноКВозврату` (по движениям) удаляется; её три потребителя переходят на расчёт по строкам:
  1. проверка возврата в документе — количество возврата по ключу ≤ доступного; для **серийного товара по
     физической продаже** «продано» = **минимум** из строк продажи и её фактического физического расхода в
     движениях (серийный товар не бывает комплектом и не лежит на ордерном складе — у корректной продажи они
     равны; минимум не даёт вернуть экземпляр, который продажа уже не списывает после изменения её движений); у налогового основания — **минимум** из его строк и физического расхода его покрытых продаж по ключу (покрытая
     продажа заморожена покрытием, но прямая запись её набора проверяется тем же правилом);
  2. проверка набора возврата серийного товара (`ПроверитьНаборВозврата`) — физический приход набора по ключу ≤
     доступного **по тому же определению, что п. 1**: продано = минимум из строк основания и физического расхода
     (продажи или покрытых продаж налогового документа), возвращено другими возвратами = максимум из их строк и
     физического прихода их движений. Для серийного товара — одна функция
     `СерийныйУчет.ДоступноКВозвратуСерийного(Основание, ИсключитьВозврат)` для документа, набора и проверки продажи;
     для несерийного при константе — только строки (уровень документа);
  3. проверка продажи с возвратами в наборе серийного товара (`ПроверитьВозвратыПродажи`): у **физической
     продажи** — её новый физический расход в движениях по ключу ≥ возвращённого (тот же максимум) — движения
     проверяются, как в 2.0.17.10, потому что прямая запись набора меняет движения, не строки; дополнительно
     строки продажи ≥ возвращённого. У **налогового документа на основаниях** (физический итог движений нулевой)
     — только строки. Проверка «продано» в документе возврата и в наборе возврата (п. 1–2) — по строкам основания.
- **Продажа с проведёнными возвратами при константе заморожена по товарам и шапке**: реквизиты шапки, от которых
  зависят возвраты и учёт продажи (дата, организация, контрагент, договор, склад, валюта, хозяйственная операция,
  признак раздельного учёта `УУ`, «цена включает НДС»), не меняются — иначе отказ; товарные строки: перепроведение, меняющее **любую** колонку товарных строк — сравниваются прежние (из базы) и новые `ТЧТовары` и
  `ТЧСерии` целиком, по всем реквизитам строк (номенклатура, характеристика, серия, упаковка, количества, признак
  нескольких серий, код строки, склад строки и прочие, кроме номера строки), — отказ «по продаже есть возвраты:
  сначала отмените их». Так построчная проверка возвратов (по кодам строк продажи) и агрегат не
  расходятся: строки продажи, на которые ссылаются возвраты, не меняются. Без константы — прежнее поведение плюс
  серийный агрегат 2.0.17.10.
- Отмена проведения и удаление реализации с проведёнными возвратами — отказ (подписки `СерийныйУчетПередЗаписью` и
  `ЗапретУдаленияСерийных`; вторая проверяет и этот случай при константе). Возвраты блокируют продажу исключительно,
  запись продажи держит её собственную блокировку — проверки сериализуются.
- **Только при проведении**: все проверки основания и количества возврата (документ, подписка) выполняются в режиме
  `РежимЗаписиДокумента.Проведение`; отмена проведения и обычная запись непроведённого возврата **новыми проверками** не проверяются (отмена возврата
  уменьшает возвращённое и инварианты не нарушает; серийный набор при отмене проверяется валидатором 2.0.17.10,
  которому основание не нужно). Действующая `ПроверкаСоответствияВозвратовРеализации` вызывается и при отмене
  проведения — её поведение этой сборкой не меняется (вне объёма; отказы, которые она даёт сегодня, остаются).
- **Порядок в `ВозвратОтПокупателя.ПередЗаписью`**: проверка основания (заполнено, проведено, допустимого вида —
  при константе для всех строк, без неё при серийных строках) переносится в начало, **до** действующей
  `ПроверкаСоответствияВозвратовРеализации`: пустое или недопустимое основание — отказ сразу, действующая проверка
  (она на пустом основании падает исключением при разборе строк основания) вызывается только с заполненным
  основанием. Подписка повторяет проверку основания под блокировкой (вход мимо модуля объекта).
- **Согласование с действующей проверкой** `РаботаСДокументами.ПроверкаСоответствияВозвратовРеализации` (вызывается из
  `ВозвратОтПокупателя.ПередЗаписью`, построчная, с кодом строки): остаётся без изменений и срабатывает первой. Новая —
  агрегат по ключу: возврат, прошедший построчную проверку, проходит и агрегат (сумма по строкам = агрегат);
  новая добавляет требование проведённого основания, налоговое основание и набор серийного товара.
- Касса и так возвращает по выбранному чеку; константа закрывает ручной возврат из документа. Набор движений
  проверяется только для серийного товара (инвариант экземпляра); для несерийного правило — уровень документа.

## Тесты (`ТестыДокументов`, каждый отказ — последний шаг своего сценария)

1. `IMEIШтрихкодСерии`: номер серии серийного товара не копируется в штрихкоды, `ПолучитьНоменклатуруПоШтрихкоду(номер)`
   → товар и серия; у несерийной серии — EAN как прежде.
2. `IMEIШтрихкодЗанят`: номер серии совпадает со штрихкодом другого товара — отказ записи серии.
3. `IMEIСменаНомераШтрихкод`: смена номера серии без движений — новый номер находит серию, прежний — нет.
4. `IMEIВключениеШтрихкоды`: включение учёта у товара с сериями — номера находятся сканом.
5. `IMEIПовторныйСкан`: `ДобавитьНоменклатуруПоШтрихкоду` на табличной части объекта (серверная обёртка) — повтор
   IMEI не увеличивает количество; повтор несерийного штрихкода увеличивает.
6. `IMEIИсправление`: приход и продажа IMEI → исправление номера — серия та же, номер и штрихкод новые, остатки не
   изменились, старый номер свободен.
7. `IMEIИсправлениеЗанятый`: исправление на занятый номер — отказ.
8. `IMEIИсправлениеБезПрав`: признак исправления без служебной функции (обычная запись серии с движениями) — отказ
   (2.0.17.10 сохраняется).
9. `IMEIПечатьЧека` и `IMEIПечатьНакладной`: в чеке и BL продажи серийного товара с гарантией 12 — строка с IMEI и
   «12».
10. `IMEIПовторныйСканТЧСерии`: серия уже в `ТЧСерии` строки — повторный скан не добавляет строку.
11. `IMEIПереносСерииШтрихкоды`: перенос серии без движений к другому товару — все её штрихкоды на новом владельце.
12. `IMEIОбработчикОбновления`: база отрасли телефонов — обработчик включает правило возврата, повтор безопасен.
13. `ВозвратТолькоПоПродаже`: константа включена — возврат несерийного товара без основания — отказ (отдельный
    сценарий); возврат сверх проданного по продаже — отказ (отдельный); в пределах — проходит; отрасль включает
    константу; уменьшение количества продажи ниже возвращённого — отказ, отмена проведения продажи с возвратом —
    отказ, удаление — отказ (отдельные сценарии).
14. `IMEIПоискПоНомеру`: номер IMEI, не ставший штрихкодом, — поиск возвращает серийный товар и серию; номер,
    совпавший со штрихкодом другого товара, — не подбирается ничего (неоднозначность).
15. `IMEIВозвратПоНалоговому`: продажа IMEI покрыта налоговым документом — возврат по налоговому документу
    проходит, сверх его строк — отказ.
16. `IMEIКодСтрокиСкана`: скан добавляет строку с кодом max + 1.

**Граница автотестов**: сканирование проверяется на табличной части объекта документа — тот же клиент-серверный
помощник работает с данными формы теми же методами коллекции (`НайтиСтроки`, `Добавить`); форма и касса — регресс
человека. Отказ `ИсправитьНомерСерии` пользователю без роли — живая проверка на копии базы под пользователем роли
«Кладовщик» (каркас тестов работает под администратором), автотест проверяет отказ при занятом номере и запрет
обычной записи.

## Порядок и проверки

Модуль `СерийныйУчетВызовСервера` → штрихкоды в `СерийныйУчет` → правило скана → печать → исправление IMEI и команда
формы серии → тесты → «Что нового» 2.0.17.11 (4 языка). lint, refcheck, listcheck, colfont, menucheck; `ib-sync`;
смок; тесты; `ai-review` → `ai-security` (привилегированное исправление, права) → `ai-final-check --db` → отчёт.

## Риски

- Регистрация IMEI штрихкодом у существующих серий при включении учёта: номер серии мог совпасть с чужим штрихкодом —
  отказ включения с перечнем (владелец исправляет серии).
- Печать чека меняет содержимое строки — смок печати проверяет вывод без ошибок; вид проверяет владелец.
