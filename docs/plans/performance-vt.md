## 1. Перенос отбора в параметры виртуальной таблицы (18 мест)

Правило эквивалентности: для `Остатки`/`Обороты` отбор по **измерениям** в условии виртуальной таблицы даёт тот же
результат, что `ГДЕ`/соединение после неё (и считается до группировки); по ресурсам — не переносится. Для
`СрезПоследних` условие по **измерениям** эквивалентно (последняя запись внутри каждого набора измерений не меняется);

## 2. Ошибки смысла, найденные разбором (исправляются в этой сборке)

Уценка и табель из этой сборки выведены (круги 1–2 ревью плана): под каждой ошибкой — дефекты документа целиком, см. п. 4.
В них — только перенос отбора (п. 1), результат запросов не меняется.

2.1. **«Формирование заказов поставщику», «Заказано» завышено.** К `ЗаказыПоставщикам.Остатки` левым соединением
приклеены `Обороты(, , Регистратор, )` по одному `ЗаказПоставщику`, поля оборотов не выбираются: строка остатка
множится на число поступлений по заказу, внешняя `СУММА` завышает «Заказано» — дозаказ меньше нужного именно у частично
поступивших заказов. Соединение удаляется.

2.3. **Кредитный контроль без контрагента берёт все объекты расчётов.** Условие виртуальной таблицы
`(Реализация ИЛИ НалоговаяНакладная) И Контрагент = &К ИЛИ &К = Пустая` по приоритету И/ИЛИ при пустом контрагенте
(регламентное `ЗапретОтгрузок`) снимает отбор по типу объекта. Скобки: `(…) И (Контрагент = &К ИЛИ &К = Пустая)`.

## 4. Вынесено владельцу (не в этой сборке)

Документ «Уценка товаров» (`ДополнительныеРасходы.РаспределитьНаСебестоимость`, ветка уценки):
- сумма уценки считается по декартову произведению остатков партий и строк доп. расходов (неверная сумма при двух и
  более партиях или статьях);
- распределение по партиям — по номенклатуре и характеристике, без серии и без цены: уценка одной серии ложится и на
  другую; две строки одной позиции с разной новой ценой распределяются на одни партии;
- повторное проведение не очищает наборы (`РаспределитьПоПозициям` добавляет к существующим записям);
- остатки читаются без управляемой блокировки.

Кадры и табель:
- автозаполнение табеля берёт сотрудников, уволенных до начала месяца;
- `КадровыйПриказ` при увольнении пишет в `ТарифныеСтавки` пустой график и нулевой оклад — табель уволенного в этом
  месяце заполняется с пустым графиком.

Ценообразование:

- ЦеныНоменклатуры: измерение `ТоварнаяГруппа` — у товара, переведённого в другую группу, срез даёт две цены одного
  вида; запросы, соединяющие срез по номенклатуре (продажи — закупочная цена в себестоимости услуг, розница,
  автоподбор), удваивают строки. В продажах — удвоение строки движения.
- `ПравилаЦенообразования.СформироватьБазовыеЦены`: цены поставщиков — строка на поставщика, блок «последней цены»
  закомментирован — дубли строк базовых цен, победитель не определён.
- Форма установки цен: `МАКСИМУМ(Период)` цен поставщиков без ограничения датой документа.
- Регламентное `ОбновлениеРозничныхЦен`: группы — из всего среза, `СформироватьБазовыеЦены` вызывается на каждую группу
  по всему каталогу.
