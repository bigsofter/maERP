# Формы и закладки дашборда при запуске — настройка пользователя (2.0.17.30)

Тикет 2606229 (TinyCIO, FlyCDI): у пользователя с ролью PDV на начальной странице дашборд, а должна открываться касса.
Решение владельца 2026-11-15: настройка пользователя «При запуске» — какие рабочие места открываются и какие закладки
дашборда показываются; у PDV — флажок на кассе, дашборд снят.

## Решения владельца

1. Дашборд остаётся на начальной странице; показывается по флажкам пользователя.
2. Без настройки дашборд **не** показывается.
3. Настраивает администратор в карточке пользователя; текущим пользователям настройки заполняет обработчик обновления.
4. Каждая закладка дашборда (Сток, Продажи, Производство) — отдельный флажок; первая отмеченная открыта при входе.

## Как сейчас

- `НастройкиПользователей.ФормыПриЗапуске()` — белый список: АРМ производства, АРМ закупок, АРМ станков; виды настроек
  — предопределённые булевы ПВХ `ВидыНастроекПользователей` в группе `ФормыПриЗапуске`. Флажок ставит сам пользователь
  в АРМ (`ФормыПриЗапускеПолныеПрава`, привилегированно, только свои настройки). Открывает
  `МодульУправляемогоПриложения` по `ФормыПриЗапускеВызовСервера.ФормыДляОткрытия()`.
- Карточка пользователя, закладка «При запуске»: только просмотр и удаление отмеченных (`ПередНачаломДобавления` — отказ).
- `HomePageWorkArea`: `Обработка.Дашборд.Форма.БазовыйДашборд` видна всем, кроме роли ОператорПроизводства. Закладки
  дашборд строит сам по ролям: коммерческие (Сток, Продажи) — администратору и всем, кроме оператора производства;
  производство — администратору и оператору.

## Изменения

1. **ПВХ `ВидыНастроекПользователей`**, группа `ФормыПриЗапуске`, четыре новых предопределённых булевых вида (новые uuid):
   `ОткрыватьРабочееМестоКассира`, `ПоказыватьДашбордСток`, `ПоказыватьДашбордПродажи`, `ПоказыватьДашбордПроизводство`.
   Реструктуризации нет: предопределённые элементы, регистр `НастройкиПользователей` не меняется.
2. **`НастройкиПользователей` (модуль менеджера)**: в `ФормыПриЗапуске()` — касса (`VentesEnDetail`, форма `Form`);
   новая `ЗакладкиДашборда()` — три вида в порядке Сток, Продажи, Производство с именами страниц; `ВсеНастройкиПриЗапуске()`
   — оба списка с представлениями на языке сеанса для карточки; `ЗаписатьНастройкиПриЗапуске(Пользователь, Отмеченные)`
   — ставит Истина отмеченным и удаляет записи снятых (только виды из белых списков).
3. **Карточка пользователя**, закладка «При запуске»: таблица всех пунктов (рабочие места + закладки дашборда) с
   флажком; запись — в `ПослеЗаписиНаСервере` через п. 2. Права — как у записи карточки сейчас (администратор);
   прежнее «удалить строку» заменяет снятие флажка.
4. **`ФормыПриЗапускеПолныеПрава`**: новая `ЗакладкиДашбордаТекущегоПользователя()` — отмеченные закладки текущего
   пользователя ИБ (тот же поиск пользователя по идентификатору ИБ); `ФормыДляОткрытия` — касса по праву на обработку.
5. **`БазовыйДашборд.ПриСозданииНаСервере`**: страницы = отмеченные ∩ разрешённые ролями (прежняя логика сохраняется),
   порядок Сток → Продажи → Производство, первая отмеченная — текущая; ни одной — `Отказ = Истина` (на начальной
   странице формы нет). Проверить вживую, что отказ формы начальной страницы просто убирает её.
6. **Обработчик обновления 2.0.17.30** (`ОбновлениеПрограммыОбработчики`, монопольно не нужен, идемпотентный):
   каждому пользователю справочника с пользователем ИБ — флажки, повторяющие то, что он видит сейчас:
   - роль PDV → `ОткрыватьРабочееМестоКассира`, закладки дашборда не ставятся (дефект тикета);
   - иначе, если дашборд ему виден сейчас (есть роль, кроме ОператорПроизводства, или полные права) → закладки,
     разрешённые его ролями по логике п. 5;
   - уже существующие записи этих видов не трогаются (повторный запуск ничего не меняет).
7. **Тесты** (`ТестыДокументов`): сценарий `НастройкиПриЗапуске` — запись/чтение флажков, белый список не пропускает
   чужой вид, закладки дашборда по ролям и порядку, обработчик обновления на тестовых пользователях с PDV и без.
   Реестр TESTS.xlsx, TESTING.md.
8. Версия 2.0.17.30, «Что нового» ×4.

## Риски

- Пользователи, заведённые после обновления, дашборда не видят, пока администратор не отметит (решение 2) — сказать в
  «Что нового».
- Отказ формы начальной страницы — проверка вживую на копии базы.
- Привилегированный модуль — ai-security.

## По ревью плана (субагент Claude, approve_with_changes; Codex в лимите до 18.11)

- Флажки фильтруют закладки только на начальной странице: команда «Дашборд» раздела «Главное» передаёт параметр
  `ВсеЗакладки` — показываются все закладки, разрешённые ролями, `Отказ` не ставится.
- Карточка пишет только пункты, изменённые на закладке (снимок флажков при чтении → разница при записи): флажок,
  поставленный пользователем в АРМ после открытия карточки, не снимается (как в круге 4 прежнего плана).
- Обработчик обновления: роли — `ПользователиИнформационнойБазы.НайтиПоУникальномуИдентификатору(...).Роли`, не
  `РольДоступна`. PDV без дашборда — только если у пользователя нет ролей сверх PDV, кроме допусков
  (`ПродажаНижеМинимальнойЦены`, `РеализацииИзменениеПроведенных` и т. п.); иначе — закладки по его ролям.
  Обработчик ставит недостающие флажки один раз на версию (повтор после ручного снятия вернул бы их — допустимо).
- Вход без пользователей ИБ — все разрешённые закладки. Первый администратор начального заполнения получает флажки
  всех закладок.
- `HomePageWorkArea`: исключение для роли ОператорПроизводства у дашборда снимается — видимостью управляют флажки.
- Флажки управляют интерфейсом, доступ к данным не ограничивают (суммы на закладках — по ролям, как сейчас).
- Смок: пользователь прогона (администратор) получает флажки обработчиком; сценарий `НастройкиПриЗапуске` проверяет,
  что форма дашборда создаётся с флажками и не создаётся без них.
