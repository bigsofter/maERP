# Учёт станков: аналитика загрузки для планирования (ожидаемо 2.0.16.52, 2MZL)

Слаг: `machines-analytics`. Задача владельца 2026-10-09: «на закладках обработки станков сделай аналитику онлайн по
загрузке, облегчающую планирование, и какие-то отчёты по загрузке». База — АРМ «Управление станками»
(`docs/plans/arm-machines.md`, сборка 2.0.16.49): таблица `СтанкиСостояние` с командной панелью, поле `НеделяСтанков`,
планировщик, закладки `ГруппаСтанкиНиз` «Готовы к запуску» / «Требования» / «Автоплан». Этот план начинается после
её сдачи и правит её файлы.

**Уровень — существенная**: новый объект (отчёт) — права роли, меню, ФО; новая экспортная логика в
`ЗагрузкаСтанков`. Порядок: план → **`ai-review-plan` (обязателен)** → реализация → `ai-test` → **`ai-review`
(обязателен)** → `ai-security` (одна строка роли, по образцу соседних отчётов — можно пропустить с обоснованием в
отчёте, как в `machines-occupancy.md`) → `ai-final-check` → отчёт `.ai/reports/machines-analytics.md`. `ai-database`
не нужен: регистров, реквизитов, движений, блокировок и реструктуризации нет — только чтение. Перед правкой `.mdo`,
`Form.form`, `.dcs` — `checklist` tiny1C по файлу (`core`, `greenfield`).

## Что уже есть (не дублирую)

| Функция `ЗагрузкаСтанков` | Что даёт аналитике |
|---|---|
| `ИнтервалыРаботыСтанков(Станки, Начало, Окончание)` | рабочие интервалы по режиму и производственному календарю, смены через полночь — **фонд** |
| `ЧасыИнтервалов`, `ЧасыВРабочееВремя` | часы интервалов / часы отрезка внутри рабочего времени |
| `ЗанятостьСтанков(Станки, Начало, Окончание, Момент)` | записи «Загрузки станков» обоих слоёв (план/факт), обоих видов (работа/обслуживание), затянувшиеся продлены — **план и ТО** |
| `ЧасыРаботыВРабочееВремя` (служебная, ~3206) | объединение интервалов «Работы» без двойного счёта плана и факта в рабочем времени |
| `ОкноВКонтексте` + контекст `Станок, Момент, Горизонт, Интервалы, Занятость` | первое свободное окно заданной длины — то же правило, что «Разместить» и автоплан |
| `ПредложениеАвтоплана(Момент, Склад, Заказы)` | очередь «Готовых к запуску» по дате отгрузки на станок с самым ранним окончанием, нормы 2.0.16.46 (`ДлительностьЗагрузки`, `ВыработкиСтанков`), `Просрочен` |
| `СостояниеСтанков` | Фонд / Работа / Загрузка % недели для таблицы станков — остаётся как есть |

Отчёты станков — все с внешним набором и `CommonForm.ФормаОтчёта`, поле `Станок` есть у всех; параметры:
`ЗагрузкаСтанков` — `Период`; `ПростоиСтанков` — `Период`, `ВключатьПлан`; `ЗанятостьСтанков` — `Момент`;
`ВыработкаСтанков`, `ЭффективностьСтанков`, `ДеньгиПоСтанкам` — `Период`; `МатериалыНаСтанках` — `НаДату`. Все,
кроме «Занятости», ретроспективные (факт до момента), разбивки по дням нет ни у одного.

## Решения

1. **Горизонт аналитики — две недели от `НеделяСтанков`** (неделя планировщика + следующая): планировать нужно дальше
   показанной недели; стрелки недели двигают и аналитику. Не настраивается (14 фиксированных колонок, п. 3).
2. **Тепловая карта — таблица значений формы с 14 фиксированными колонками дней**, не динамические колонки и не
   `ПолеДиаграммы`. Проверено по модели типов 8.5.1 (`com._1c.g5.v8.dt.platform_v8.5.1_*.jar`): у колонки (`FormField`)
   есть `ШрифтЗаголовка`, `ТекстПодвала`/`ПутьКДаннымПодвала`, у таблицы — `Подвал`; цвета `WebЦвета.СветлоЗеленый`,
   `СветлоЖелтый`, `СветлоРозовый`, `СветлоСерый` существуют. Почему не динамика (`ИзменитьРеквизиты` +
   `Элементы.Добавить`): колонки вне XML не видят `colfont.py` и `listcheck.py`, `titleFont` пришлось бы ставить кодом,
   смок не проверит состав. Почему не диаграмма (прецедент — только `Дашборд`, поле создаётся кодом): нет условного
   оформления по ячейке, нет выбора строки → станка, шрифты легенды на macOS не проверены. Заголовки колонок дней
   («Пн 12.10») ставятся кодом при заполнении.
3. **«Под риском срыва» — «опаздывает в текущем черновике автоплана»**, а не по «Готовым к запуску»: `Просрочен` у
   «Готовых» считается на одном выбранном станке без очереди, а черновик ставит всю очередь по дате отгрузки на станок
   с самым ранним окончанием мимо занятости. Черновик жадный (ревью плана, P2-5): размещение предыдущих строк не
   пересматривается, станок под продукцию с единственным допустимым станком не резервируется — опоздание в черновике
   **не доказывает** неизбежного срыва (контрпример: X допускает A 2 ч или B 3 ч, Y — только A 7 ч, по 8 ч до срока;
   черновик ставит X на A и объявляет Y просроченной, хотя X на B и Y на A успевают). Поэтому формулировки в
   интерфейсе и отчёте — «опаздывает по черновику автоплана», подсказка страницы и варианта отчёта это объясняет;
   оптимизация размещения — отдельная задача, если владелец потребует доказуемой выполнимости. Плюс уже
   запланированные работы, чьё **эффективное** окончание (с продлением затянувшихся, как в `ЗанятостьСтанков`) позже
   дня отгрузки заказа.
4. **Дефицит мощности — по датам отгрузки, нарастающим итогом, по всем строкам черновика**: потребность — сумма
   часов **всех** строк черновика с отгрузкой не позже даты D (и вовремя, и опаздывающих — все расходуют мощность;
   ревью плана, P1-2), мощность — свободные часы станков от момента до конца дня D. Это агрегат без допустимых станков
   (подпись «оценка по всем станкам»); по строке — п. 3, тоже оценка.
5. **Новый отчёт один — «План загрузки станков»** с двумя вариантами («По дням» и «Заказы под риском»), а не
   расширение существующих: у «Загрузки станков» данные из `КатегорииВремени` (по документам, без дня, общая с OEE,
   «Деньгами» и «Выработкой» через `ЧасыРаботыТребований`) — разбивка по дням меняла бы общую функцию трёх отчётов;
   «Занятость станков» — срез на момент, без периода. Два отчёта вместо двух вариантов — два объекта в правах и
   меню без выигрыша.

## 1. Общий модуль `ЗагрузкаСтанков` (новое, экспортное)

### `АналитикаЗагрузки(Станки, Начало, Окончание, ЧасовОкна, Момент = Неопределено) Экспорт`

Один вызов `ИнтервалыРаботыСтанков` и один `ЗанятостьСтанков` на `[Начало, Окончание)`, дальше — в памяти:
`НайтиСтроки` по станку, дни — циклом по 14 дням без запросов. Возвращает Структуру:

- `Станки` — ТаблицаЗначений, строка на станок в порядке массива:

| Колонка | Расчёт |
|---|---|
| `Фонд` | `ЧасыИнтервалов` рабочих интервалов периода |
| `Работа` | часы «Работы» плана ∪ факта в рабочем времени — `ЧасыРаботыВРабочееВремя` |
| `Обслуживание` | то же для вида «Обслуживание» |
| `Занято` | объединение **всех** записей (работа ∪ ТО, план ∪ факт) в рабочем времени — ТО поверх работы не считается дважды |
| `Свободно` | `Фонд` − `Занято`, но только от `Макс(Начало, Момент)`: прошлое свободное время для планирования бесполезно |
| `Процент` | `Окр(Занято / Фонд × 100, 0)`; фонд 0 — 0 |
| `ОкноС`, `ОкноПо` | первое окно ≥ `ЧасовОкна` от `Макс(Начало, Момент)` — `ОкноВКонтексте` на контексте из уже прочитанных интервалов и занятости с `Горизонт = Окончание`; нет окна в горизонте — пусто |
| `УзкоеМесто` | `Процент` ≥ `ПорогУзкогоМеста()` (90 — служебная функция-константа) |

- `Дни` — ТаблицаЗначений `Станок, День, Фонд, Занято, Свободно, Процент` по **всем** календарным суткам
  `[Начало, Окончание)` (ревью плана, P2-3: функция общая для закладки и отчёта, фиксированных 14 дней в ней нет);
  день — `[День, День + СекундВСутках())`, первый и последний обрезаются границами периода, смена через полночь делится
  по суткам, сумма дней = фонд периода; `Свободно` дня до момента — 0, текущего дня — от момента. Ограничения длины —
  у потребителей: 14 колонок — в форме АРМ (`Окончание = НеделяСтанков + 14 суток`), 93 дня — в менеджере отчёта.
- `Предупреждение` — `ТекстПустогоКалендаря(Станки, Начало, Окончание)`.
- Выведенный станок (круг 7, P1-1): фонд, свободное время и окно — 0 / пусто (интервалы его режима не читаются),
  работа и обслуживание — по факту записей; в форме и отчёте строка помечена «выведен». Иначе будущие часы
  выведенного станка выглядели бы свободными.

Обобщение без дублирования: служебная `ЧасыРаботыВРабочееВремя(Записи, Интервалы, Начало, Окончание)` получает
необязательный параметр `ВидЗаписи` (Неопределено — все виды); прежние вызовы передают `Работа` (поведение
`СостояниеСтанков` и `ОсвобождениеСтанков` не меняется, проверяют их сценарии `ЗакладкаСтанков` и
`ОтчетыСтанков`). Контекст окна собирается из прочитанного — так уже делает `ОсвобождениеСтанков`, отдельная
`КонтекстОкна` (с запросом на станок) не вызывается.

### `РискиСрыва(Станки, Момент = Неопределено, Склад = Неопределено, Заказы = Неопределено, Предложение = Неопределено) Экспорт`

Возвращает Структуру:

- `Предложение` — полный черновик автоплана (все строки, и вовремя, и опаздывающие): по нему считается `Дефицит`.
- `Заказы` — ТаблицаЗначений `Источник` («Запланировано» / «Очередь» — строка на 4 языках), `Заказ`, `НомерЗаказа`,
  `Клиент`, `ДатаОтгрузки`, `Номенклатура`, `Количество`, `Станок`, `Начало`, `Окончание`, `Часы`, `ОпозданиеДней`
  (`(НачалоДня(Окончание) − НачалоДня(ДатаОтгрузки)) / сутки`), `ТекстОшибки`, `Документ` (требование у
  «Запланировано»):
  - «Очередь» — строки черновика `ПредложениеАвтоплана(Момент, Склад, Заказы)` с `Просрочен` или с `ТекстОшибки`
    (не посчитать — тоже риск, с причиной). Если передан готовый `Предложение` (черновик закладки «Автоплан» того же
    момента) — пересчёта нет;
  - «Запланировано» — по **эффективному** окончанию (ревью плана, P1-1): `ЗанятостьСтанков(Станки, Момент,
    КонецГоризонта, Момент)` уже продлевает затянувшиеся (запущенное требование, факт, расчётное окончание ≤ момента →
    `Окончание` = момент + шаг, `Затянулась`); продление живёт только в возвращаемой таблице, поэтому сравнивать с
    сохранённым `Окончание` регистра запросом нельзя. Из таблицы берутся записи вида «Работа» с `Заказ`; по требованию —
    позднейшая (план или факт); даты отгрузки и клиенты — **один запрос** по массиву заказов. Риск — эффективное
    `Окончание > КонецДня(ДатаОтгрузки)` **только при заполненной дате отгрузки** (как `Просрочен` автоплана; ревью
    плана круга 2, P2-2); без даты строка в риски не попадает. `ОпозданиеДней` — от эффективного окончания.
    `КонецГоризонта` — `ДнейГоризонтаОкончания` от момента (как у автоплана). Пример, который ловит отбор по
    сохранённому окончанию: отгрузка Пн, расчётное окончание Пн 18:00, во Вт 10:00 требование ещё запущено — в рисках,
    опоздание 1 день.
  - **Незапущенный план, старт которого уже прошёл** (ревью плана кругов 2–3): `ЗанятостьСтанков` сохраняет исходное
    окончание незапущенного плана, а «Готовые к запуску» вычитают требования «Запланировано» — сорванный старт выпадал
    из обеих веток. Отбор — по **началу**, а не по окончанию (круг 3, P1-1): записи слоя «План» вида «Работа» станков
    `Станки` с `Начало <= &Момент` у проведённых требований со статусом «Запланировано» — отдельная часть того же
    запроса дат отгрузки (с `Длительность` требования). Эффективное окончание (круг 3, P1-2) — по **рабочему времени**,
    а не календарной разностью: `НачалоСменыСоШагом(Интервалы, Момент)` и `РазложитьЧасы(Интервалы, Начало,
    Длительность требования × 3600)` по интервалам станка, уже прочитанным для мощности (`ИнтервалыРаботыСтанков`
    один раз на `[Момент, КонецГоризонта)`, без запросов в цикле) — то же правило, что `ОкончаниеПоРежиму` и
    `ИнтервалЗагрузки`. Чужая занятость не учитывается — это нижняя оценка, так и подписано. Не уложилось в
    горизонт — окончание пусто, строка в рисках с текстом «нет рабочего времени в горизонте». Источник —
    «Запланировано, не запущено вовремя», признак `НеЗапущено`. Дальше — то же сравнение с днём отгрузки. Перенос
    записи в будущее «Разместить» уберёт её из этой части. По требованию в `Заказы` — **одна** строка: незапущенное
    с сорванным стартом вытесняет запись того же требования из `ЗанятостьСтанков` (там плановое окончание ещё может быть
    впереди), чтобы требование не попало в риски дважды.
  - **Выведенный станок** (`Станки.Выведен`, как в `СтанкиАвтоплана`; ревью плана кругов 6–7) — общее правило для
    рисков и мощности: (1) **любая** незапущенная работа («Запланировано», в любом времени — и с сорванным стартом,
    и будущая) на выведенном станке попадает в риски с пустым окончанием и `ТекстОшибки` «станок выведен из работы —
    перепланировать», окончание по его сохранённому режиму не считается, длительность — в потребности дефицита;
    станки таких работ берутся запросом **без** отбора по `Выведен`; (2) выведенный станок **мощности не даёт**:
    его интервалы в `Мощность` не входят. Запущенная работа на выведенном станке идёт как есть (ветка «Запланировано»
    через `ЗанятостьСтанков`).
- `Дефицит` — ТаблицаЗначений `ДатаОтгрузки, Потребность, Мощность, Дефицит` по различным датам отгрузки
  **полного черновика** `Предложение` **и незапущенных с сорванным стартом** (ревью плана круга 4, P1-1: их
  трудоёмкость не входит ни в черновик — «Готовые» вычитают требования «Запланировано», — ни в будущую занятость —
  `ЗанятостьСтанков` не переносит истёкшие интервалы; часы — `Длительность` требования, дата — отгрузка его заказа,
  **в том числе при `ТекстОшибки`** «нет рабочего времени в горизонте» — длительность известна; ревью плана круга 5,
  P2-2). Строки черновика с `ТекстОшибки` входят, **если часы известны** (ревью плана круга 8, P1-1: `ПредложитьСтроку`
  считает длительность до `ОкноВКонтексте`, но пишет её в строку только при успешном размещении — правка: строка без
  окна получает `Часы` = **минимальная** длительность по всем станкам-кандидатам цикла (нижняя оценка, не зависит от
  порядка станков по наименованию; ревью плана круга 9, P2-1), строка с окном — как сейчас, длительность выбранного
  станка; «нет окна» — это как раз исчерпанная
  мощность, и её потребность терять нельзя). Не входят строки без даты и строки, где длительность не посчитана (нет
  нормы выработки и т. п. — `Часы` = 0). Отбор `Просрочен`/`ТекстОшибки` применяется только к `Заказы`.
  **Горизонт** (круги 8–9): в таблицу `Дефицит` входят только даты, у которых `КонецДня(ДатаОтгрузки) <
  Момент + ДнейГоризонтаОкончания() × сутки` — мощность каждой из них прочитана до конца дня; интервалы читаются до
  `КонецДня` наибольшей такой даты. Остальные даты — за горизонтом, их строки остаются в `Заказы`. **Без двойного счёта** (круг 5, P1-1): плановые интервалы незапущенных с сорванным
  стартом исключаются из занятости, по которой считается `Мощность` (их ещё не истёкший остаток вернул бы
  `ЗанятостьСтанков`), — вся их длительность уже в потребности. `Потребность` — нарастающая сумма `Часы`; `Мощность` — свободные
  часы `Станки` от момента до конца дня (интервалы и занятость читаются **один раз** до максимальной даты, не дальше
  `ДнейГоризонтаОкончания`); `Дефицит = Макс(0, Потребность − Мощность)`. Показываются все даты, дефицитные — красным.

Цена: `ПредложениеАвтоплана` заполняет требование по каждой строке очереди (`ЗаполнитьПоСтрокеЗаказа` — запросы
внутри, путь сознательно общий с «Разместить», ревью плана волны 5 P2-7). Поэтому риски считаются **не** при каждом
`ЗаполнитьСтанки`, а лениво (п. 2) и переиспользуют черновик автоплана. Новый код запросов в цикле не содержит.

## 2. Форма `DataProcessor.АРМУправлениеСтанками.Форма`

### Раскладка (без вертикальной прокрутки: высота формы не растёт)

```
[таблица «Станки», 4 строки]                         — без изменений
[Неделя: __]  [Окно не короче, ч: __]                — новая группа ГруппаНеделя (HorizontalIfPossible, без рамки и
                                                        заголовка): НеделяСтанков + новое поле ЧасовОкна
[планировщик, 6]                                     — без изменений
[Готовы к запуску | Требования | Автоплан | Загрузка | Под риском]  — 2 новые страницы ГруппаСтанкиНиз, 4 строки
```

- **«Загрузка»** (`СтраницаЗагрузка`): таблица `ЗагрузкаПоДням` (реквизит — ТаблицаЗначений) на всю страницу,
  `heightInTableRows` 4 (как соседние), растягивается, только просмотр, `footer` = true. Колонки: `Станок`, `Фонд`,
  `Занято`, `Обслуживание`, `Свободно`, `Процент` («Занято, %»), `ОкноС` (`ДФ='dd.MM HH:mm'`; пустая дата — окна нет
  в горизонте, сказано в подсказке колонки), затем `День1`…`День14` (Число 3,0 — % занятости дня, ширина 4). Скрытые колонки-данные `Фонд1…14` не нужны: выходной (фонд 0) — по скрытой булевой
  колонке `Выходной1…14`, свободные часы дня — `Свободно1…14` (скрытые, для подвала). Подвал: у `Свободно` — сумма, у
  `ДеньN` — `ТекстПодвала` «своб. 12,5» (сумма свободных часов дня по станкам, ставится кодом — прецедент
  `ДокументыЗаказа…ТекстПодвала` АРМ производства).
  Командная панель таблицы (`autoCommandBar`): «Обновить» (та же команда `СтанкиОбновить`), подменю «Отчёты» (`Popup`,
  как `ПродукцияПодменюСтатус`) — п. 3. Выбор строки — текущей строкой `СтанкиСостояние` становится этот станок
  (планировщик и «Готовые» пересчитываются как при активизации строки станков).
- **«Под риском»** (`СтраницаРиски`): горизонтальная группа (без рамки), слева таблица `РискиСрыва` (растягивается):
  `Источник`, `НомерЗаказа`, `Клиент`, `ДатаОтгрузки`, `Номенклатура`, `Количество`, `Станок`, `Окончание`,
  `ОпозданиеДней`, `ТекстОшибки`; справа узкая `ДефицитМощности`: `ДатаОтгрузки`, `Потребность`, `Мощность`,
  `Дефицит`. Обе — 4 строки. Панель `РискиСрыва`: «Пересчитать» (команда `СтанкиПересчитатьРиски`), «Отчёт» (вариант
  «Заказы под риском»). Выбор строки — открыть требование (`Документ`) или заказ.
- Заголовки страниц с числом: «Под риском (3)» — кодом после расчёта; «Загрузка» без числа.
- Колонки всех новых таблиц — `titleFont` = `Style.NormalTextFont` (`colfont.py`), `<visible>true</visible>` у
  каждого элемента (урок edt-form-visible-default), заголовки колонок — `<title>` на 4 языках (реквизиты формы,
  FORMS-STYLE п. 9). Кнопки — **только** в `autoCommandBar` таблиц, без своего `font`, без `UsualButton` и отдельных
  `CommandBar` (решение владельца; урок forms-009 — кнопку не класть элементом внутрь таблицы).
- Видимость: страницы скрываются вместе с `ГруппаСтанкиНиз` при `МожноВидетьСтанки = Ложь` — отдельного кода не
  нужно; кнопка «Отчёты» — по праву `ПравоДоступа("Просмотр", Метаданные.Отчеты.<…>)` на каждый пункт.

### Реквизиты и условное оформление

- `ЧасовОкна` (Число 5,2, по умолчанию — 4 ч, **не меньше шага планирования 0,25 ч** — `minValue` поля и проверка
  `Макс(ЧасовОкна, ШагПланированияМинут() / 60)` перед расчётом: `ОкноВКонтексте` при нуле окна не находит; ревью
  плана круга 8, P2-3; `savedData` + сохранение в настройках формы), при
  изменении — пересчёт только колонок окна (`ЗаполнитьАналитику`).
- `ЗагрузкаПоДням`, `РискиСрыва`, `ДефицитМощности` (ТаблицыЗначений), `РискиРассчитаны` (Булево).
- Условное оформление — кодом в `НастроитьФорму` (как красные строки «Готовых»), циклом по N = 1…14 для поля
  `ЗагрузкаПоДнямДеньN`, отбор по `ЗагрузкаПоДням.ДеньN`: ≥ 100 — фон `WebЦвета.СветлоРозовый`; 85…99 —
  `СветлоЖелтый`; > 0 и < 85 — `СветлоЗеленый`; `ВыходнойN` — фон `СветлоСерый`, текст «—». Весь ряд станка с
  `УзкоеМесто` — полужирный шрифт колонки `Станок` (шрифт стиля, а не новый). `Дефицит > 0` и строки «Под риском» —
  `ЦветаСтиля.Цвет_Красный`. Прошедшие дни недели — текст `ЦветаСтиля.Цвет_ПоясняющийТекст`.

### Обновление

- `ЗаполнитьСтанки()` (зовут «Обновить», стрелки и поле недели, все действия) дополнительно вызывает
  `ЗаполнитьАналитику(Станки, Начало)` — `АналитикаЗагрузки(Станки, НеделяСтанков, НеделяСтанков + 14 суток,
  ЧасовОкна)`, перекладка `Дни` в колонки `ДеньN` (без запросов), заголовки колонок дней, подвал. Станки — те же
  `ДействующиеСтанки()`, что у таблицы станков.
- Риски: `ЗаполнитьСтанки(ПересчитатьРиски = Истина)` сбрасывает `РискиРассчитаны` и, **если текущая страница
  `ГруппаСтанкиНиз` — «Под риском» и `ПересчитатьРиски`, сразу пересчитывает** их. Команда «Автоплан» зовёт
  `ЗаполнитьСтанки(Ложь)` и затем считает риски по своему готовому черновику — дорогой автоплан не считается дважды
  (ревью плана круга 4, P2-2). «Принять» автоплана черновик **не** переиспользует (круг 6, P1-2: после принятия он не
  соответствует очереди и занятости, принятие частичное) — обычный `ЗаполнитьСтанки()` со свежим расчётом, если
  открыта страница рисков (ревью плана, P2-4: события смены страницы при оставшейся странице нет — без этого
  «Обновить» и стрелки недели оставляли пустые таблицы); на других страницах таблицы очищаются и считаются лениво — при
  переходе на «Под риском» (`ГруппаСтанкиНизПриСменеСтраницы`, если не рассчитаны). Ещё — по «Пересчитать» и сразу
  после «Автоплан» с готовым черновиком (`Предложение = Автоплан`, без второго расчёта). Заголовок страницы «Под
  риском (N)» обновляется в той же процедуре, что заполняет таблицы, и при очистке (без числа). От недели риски не
  зависят (от момента до дат отгрузки), но «Обновить» берёт новый момент.

## 3. Отчёты

### С закладки (подменю «Отчёты» таблицы «Загрузка»)

Открываются только **планировочные** отчёты — с периодом/моментом закладки и станком текущей строки:

| Пункт | Форма и параметры `ОткрытьФорму` |
|---|---|
| План загрузки по дням (новый) | `Отчет.ПланЗагрузкиСтанков.Форма`, `КлючВарианта` = «ПоДням», `Отбор` = `Новый Структура("Период, Станок", Период2Недели, Станок)`, `СформироватьПриОткрытии` = Истина |
| Загрузка станков | `Отчет.ЗагрузкаСтанков.Форма`, `Отбор` = `Период` (горизонт закладки) + `Станок` — слой «План» есть |
| Простои станков (с планом ТО) | `Отчет.ПростоиСтанков.Форма`, `Отбор` = `Период`, `ВключатьПлан` = Истина, `Станок` |
| Занятость станков | `Отчет.ЗанятостьСтанков.Форма`, без периода (момент — сейчас), `Отбор` = `Станок` |

`Период` — `СтандартныйПериод` с вариантом `Произвольный` (`НеделяСтанков` … конец второй недели). Образец вызова —
`АРМПроизводство` (`ПотребностиПроизводства`: `Отбор` + `СформироватьПриОткрытии`). Ключ `Отбор`, совпадающий с
именем параметра данных, стандартная форма отчёта ставит в параметр — **проверить на базе первым шагом реализации**
(ручной прогон: открыть «Загрузку станков» с закладки, период в шапке = горизонт). Если параметр не подставится —
запасной путь: серверная функция формы собирает `ПользовательскиеНастройки` из
`Отчеты[Имя].Создать().КомпоновщикНастроек` с установленным параметром (у параметров `Период` есть `userSettingID`).
Ретроспективные «Выработка», «Эффективность», «Деньги», «Материалы на станках» — не планирование, остаются в меню
группы «Станки», в подменю не попадают.

### Новый отчёт `Отчеты.ПланЗагрузкиСтанков` — «План загрузки станков»

fr «Plan de charge des machines», en «Machine load plan», es «Plan de carga de máquinas». Устроен как
`ЗанятостьСтанков`: `CommonForm.ФормаОтчёта`, схема `ОсновнаяСхемаКомпоновкиДанных`, внешние наборы, `ObjectModule.
ПриКомпоновкеРезультата` → `ЗагрузкаСтанков.ВывестиОтчет`.

- `ManagerModule.ДанныеОтчета(Период, Момент = Неопределено, ВидДанных = "Дни") Экспорт` — станки
  `СтанкиОтчетов(Начало, Окончание)` (как у остальных отчётов станков: выведенный станок с данными внутри прошлого
  периода не теряется; ревью плана круга 2, P2-3); «Дни» — `АналитикаЗагрузки(...).Дни` за весь период
  (ограничение 93 дня — здесь, в менеджере: длиннее — обрезка с предупреждением, цикл дней × станки); «Риски» —
  `РискиСрыва(Неопределено, Момент).Заказы` — для рисков список станков от периода не зависит (ревью плана круга 5,
  P2-3): `Станки = Неопределено` в `РискиСрыва` означает `СтанкиЗанятости(Момент)` (действующие и с занятостью после
  момента) плюс станки записей незапущенных требований с сорванным стартом — второй запрос, без цикла.
  Считается только нужный вариант: служебный параметр схемы `ВидДанных` (строка, не в пользовательских настройках),
  значение задано в каждом варианте; читается `ЗначениеПараметраОтчета`.
- Наборы: `Дни` (`Станок, День, Фонд, Занято, Свободно`; вычисляемый ресурс `Процент` =
  `Выбор Когда Сумма(Фонд) > 0 Тогда Окр(Сумма(Занято) / Сумма(Фонд) * 100, 0) Иначе 0 Конец`) и `Риски` (колонки
  п. 1). Наборы не связаны; каждый вариант выбирает поля только своего набора.
- Вариант **«По дням»** (`ПоДням`, по умолчанию): таблица — строки `Станок`, колонки `День` (`ДФ='ddd dd.MM'`),
  ресурсы `Процент`, `Свободно`; условное оформление варианта — те же пороги 85/100; параметр `Период`
  (по умолчанию `ЭтаНеделя`) в быстрых настройках, отбор `Станок`.
- Вариант **«Заказы под риском»** (`ЗаказыПодРиском`): группировка `Источник` → детальные записи, порядок
  `ДатаОтгрузки`; параметр `Момент` (пусто — сейчас) в быстрых настройках.
- Предупреждение — пустой календарь (`ТекстПустогоКалендаря`).
- Регистрация: `Configuration.mdo` `<reports>`; ФО `ИспользоватьУчетСтанков` — `<content>Report.ПланЗагрузкиСтанков`;
  подсистема `Производство.Станки` — `content`, видимость `StandardCommand.Open` (true), порядок в
  `NavigationPanelOrdinary` и `ActionsPanel…` (обе секции, где сейчас стоят отчёты станков) после
  `Report.ЗанятостьСтанков`; роль `ОператорПроизводства` — Use, View (как `Report.ЗанятостьСтанков`); `Администратор`,
  `Руководитель` — `setForNewObjects`. `menucheck.py` — без новых расхождений.

   черновику» — фиксирует известное поведение, а не доказательство срыва; текст источника — «опаздывает по черновику».
4а. Период длиннее 14 дней (P2-3): `АналитикаЗагрузки` за 31 день с работой на 20-й день — строка дня есть, сумма
   дневных фондов = фонд периода; периоды 7 и 14 дней — то же равенство.
4. Отчёт: `Отчеты.ПланЗагрузкиСтанков.ДанныеОтчета` — строка станка есть; компоновка обоих вариантов с внешними
   наборами собирается (`СтрокаОтчетаСтанков` по `Дни`: Фонд 136); вариант «Заказы под риском» — строка заказа C.

Регрессия: `ЗакладкаСтанков` и `ОтчетыСтанков` (обобщение `ЧасыРаботыВРабочееВремя`), `АвтопланСтанков`.
`СтанкиИОбслуживание` — отчёт в составе ФО и в группе «Станки». Смок открывает форму АРМ (новые страницы) и форму
отчёта. Реестр: строка `АналитикаЗагрузкиСтанков` в `docs/TESTING.md` и `docs/TESTS.xlsx`; человеку — тепловая карта
читается, подменю «Отчёты» подставляет период и станок, форма без прокрутки на 1440×900 (macOS) и 1920×1080.

## 5. Риски

- **Производительность.** Аналитика — +1 запрос занятости и цикл 14 дней × станки на каждое `ЗаполнитьСтанки`
  (десятки станков — миллисекунды). Риски — дорогие (автоплан), поэтому ленивые и с переиспользованием черновика. Если
  на базе 2MZL/Drissotex «Под риском» > 2 с — запись в `TECHDEBT.md` (вес очереди из `СтрокиГотовых` вместо
  заполнения требования).
- **ФО.** Без `ИспользоватьУчетСтанков` обработка и отчёт не видны в меню; форма без права показывает надпись
  (`arm-machines` §4). Своей проверки прав в отчёте нет — доступ даёт роль, как у соседних отчётов станков.
- **Отбор как параметр отчёта** — п. 3, проверка первым шагом и запасной путь.
- **Ширина таблицы «Загрузка»**: 7 + 14 колонок — горизонтальная прокрутка таблицы допустима (`AutoUse`), колонка
  `Станок` — `fixingInTable` слева.
- **Смысл «Занято, %»** отличается от «Загрузка, %» таблицы станков (там работа / фонд недели): подсказки колонок на
  4 языках («работа и обслуживание / фонд»), разные заголовки.
- **Сохранённые настройки формы**: новый `ЧасовОкна` сохраняется; страницы — новые, старым настройкам не мешают.
