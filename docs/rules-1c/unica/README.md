## Зачем взято

Наш MCP-сервер правил обслуживает не только maERP: разработка ведётся и на
8.3. Собственные `lessons/` выведены из ошибок 8.5.1 в EDT-проекте, а этот
корпус закрывает 8.3 и платформенный XML — формат, в котором лежат
конфигурации, выгруженные конфигуратором, и внешние обработки.

## Границы применимости

1. **Платформа 8.3.27, формат выгрузки 2.20.** Для 8.5 состав свойств шире:
   `PaletteColor`, часть свойств стиля и элементов формы там своя (см. урок
   `../lessons/mdo-004.md`). Расхождение с проверенным поведением 8.5
   решается в пользу поведения, а не этих текстов.
2. **Платформенный XML, не EDT.** Пути вида
   `src/Documents/X/Forms/Y/Ext/Form.xml` и структура `<Form>` относятся к
   выгрузке конфигуратора. Источник правды maERP — EDT-проект (`.mdo`,
   `Form.form`), там имена тегов и раскладка файлов другие; совпадают
   перечни свойств и их допустимые значения — ради них корпус и взят.
3. **Тексты написаны под инструменты Unica.** Ссылки на `unica.*`,
   `SKILL.md` и их скрипты читать как «сделай то же самое своим
   инструментом» — так же, как в основном каталоге правил.
4. Собственные уроки maERP старше: при конфликте выигрывает `../lessons/`,
   затем `CLAUDE.md`, затем этот корпус.
