# Кнопка внутри таблицы динамического списка на закладке роняет клиент 8.5 (SIGSEGV)

## Симптом

Клиент падает по SIGSEGV при открытии формы списка; CheckConfig молчит, EDT
импортирует форму без замечаний. В смок-прогоне отчёт обрывается на строке
«СТАРТ», ошибок не пишется - падает процесс целиком.

## Причина

Кнопка (`<items xsi:type="form:Button">` с `placementArea` = `UserCmds`),
помещённая ВНУТРЬ таблицы динамического списка, который лежит на странице
(`Pages` → `Page`), при отрисовке роняет клиент. Тот же приём в форме,
собранной руками в EDT, работает - воспроизводится на формах, собранных
внешним скриптом.

## Правило

1. Кнопку рядом со списком класть **на страницу**, соседним элементом перед
   таблицей, а не в её состав.
2. У кнопки заполнять `title` на все языки, `representation` = `Auto` и
   `buttonImportance`: кнопка без заголовка с `representation` = `Text` не
   рисуется и мешает диагностике.
3. После сборки формы скриптом - обязательный смок-прогон. CheckConfig такие
   дефекты не ловит.

## Как искать виновника

Смок пишет отчёт в конце прогона, поэтому при падении клиента он пуст. Трасса:
в модуль формы обработки СмокТест добавить запись имени формы в файл
`<отчёт>.trace` ДО открытия, открывая и закрывая файл на каждой строке
(`Новый ЗаписьТекста(Путь, КодировкаТекста.UTF8, , Истина)` + `Закрыть()`):
без закрытия буфер при SIGSEGV теряется. Дальше - бисекция на стенде:
копия базы (`cp build/ib/1Cv8.1CD build/ib-smoke/`), правка XML-дампа и
частичная загрузка `/LoadConfigFromFiles <дамп> -files "Documents/<Имя>.xml"
-updateConfigDumpInfo /UpdateDBCfg`. Путь в `-files` - именно файл `.xml`
объекта, каталог не принимается.

## История

2026-09-02. Волна 2 (закупки): в список поступления добавлена закладка «Заказы
поставщикам» с кнопкой «Оформить поступление» внутри таблицы. Смок падал на
`Документ.ПоступлениеТоваровУслуг.Форма.ФормаСписка`. Проверены и отвергнуты:
`userSettingsGroup` (урок forms-008 - снят у всех новых форм, не помогло),
запрос списка с СГРУППИРОВАТЬ/ИМЕЮЩИЕ (переписан на подзапрос - не помогло),
`dynamicDataRead` (отключение не помогло), отсутствие заголовка у кнопки.
Виновником оказалось само размещение кнопки в составе таблицы: вынос на
страницу дал зелёный прогон (383 формы, 105 образцов, 53 печати, 0 ошибок).
