# Уроки maERP: правила, выведенные из реальных ошибок

Дополнение к базе `docs/rules-1c/` (подмножество comol/ai_rules_1c). Та база —
общие стандарты разработки; эта — правила, каждое из которых родилось из ошибки,
реально пойманной в работе над maERP: линтером, CheckConfig, смок-прогоном или
владельцем на живой базе. У каждого правила есть раздел «История» с датой и
обстоятельствами — он объясняет, почему правило именно такое.

## Формат: готов под MCP-сервер

Одно правило — один файл `<id>.md` с YAML-фронтматтером:

```yaml
---
id: forms-001            # стабильный идентификатор, не переименовывать
категория: формы-xml     # запросы | модули | формы-xml | метаданные | макеты | процесс
серьёзность: критично    # критично | важно | справка
заголовок: "..."
ключи: [id, attributes, нумерация]   # для поиска по симптому
---
```

`rules.json` — машинный манифест: список всех правил с метаданными,
генерируется из фронтматтеров. Будущий MCP-сервер строится поверх без
переделки базы:

- **tool `lookup_rule(запрос)`** — поиск по `ключи` + `заголовок` манифеста,
  возврат тела найденных `.md`;
- **tool `rules_by_category(категория)`** — выдача правил категории
  (например, все «формы-xml» перед правкой Form.form);
- **tool `checklist(файл)`** — по расширению правимого файла (`.bsl`, `.form`,
  `.mdo`, `.mxlx`) вернуть применимые правила с серьёзностью «критично»;
- **resource** `rules://manifest` — сам `rules.json`.

Серверу достаточно читать каталог; состояния нет, индексация — по манифесту.

## Категории

| Категория | Про что | Чем ловится |
|---|---|---|
| `запросы` | язык запросов: псевдонимы, ИТОГИ | только выполнение на базе |
| `модули` | BSL: директивы, глобальный контекст, API метаданных | CheckConfig, база |
| `формы-xml` | сериализация Form.form в EDT: id, пути, вставка | EDT при импорте |
| `метаданные` | .mdo: флаги, размещение в интерфейсе, стиль | глазами на клиенте |
| `макеты` | .mxlx: заполнение ячеек, форматы | прогон печати |
| `процесс` | EDT/скрипты/тесты: Refresh, BOM, чек-листы | дисциплина |

## Правило пополнения

Новая ошибка того же класса, что уже описана, — дополняет «Историю»
существующего правила. Новый класс ошибки — новый файл + перегенерация
`rules.json`. Правило без реальной истории сюда не попадает: для общих
стандартов есть основная база уровнем выше.
