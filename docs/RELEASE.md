# Выпуск версии

maERP — тиражное решение, поэтому поставка состоит из двух файлов: полного
дистрибутива `.cf` и файла обновления `.cfu`, позволяющего клиентам обновиться
с предыдущих версий без потери их доработок.

## Версионирование

Схема — `2.0.X.Y`, единственное описание правила в `docs/RELEASING.md`
(«Версионирование»): `X` растёт при публикации CF, `Y` — при каждой передаче
владельцу на тест, и каждая сборка обязана иметь свою секцию в макете
`ОписаниеИзменений`.

## Сборка

```bash
scripts/edt-export.sh                    # EDT-проект -> build/xml
scripts/xml-load.sh                      # build/xml  -> база сборки
scripts/dist-build.sh 1.1.0 \
  build/dist/maERP-1.0.0.cf \
  build/dist/maERP-1.0.1.cf              # CF + CFU с указанных версий
```

Предыдущие релизы, перечисленные последними аргументами, попадают в CFU как
поддерживаемые исходные версии обновления. Их надо хранить — не в git
(бинарники), а в GitHub Releases соответствующих тегов.

## Порядок выпуска

1. Прогнать `scripts/lint.sh`, разобрать замечания.
2. Поднять версию в свойствах конфигурации, закоммитить.
3. Собрать CF и CFU.
4. Проверить обновление на копии базы с предыдущей версией.
5. Поставить тег `vX.Y.Z`, создать GitHub Release и приложить CF и CFU.

## Поставка с поддержкой

Тиражное решение поставляется клиентам на поддержке, чтобы их доработки
переживали обновления. Правила поставки задаются в конфигураторе один раз
(Конфигурация → Поставка конфигурации → Настройка поставки) и хранятся в
конфигурации.
