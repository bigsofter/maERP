## Проект тендера поставщиков (согласован 2026-08-24)

Решения владельца: оценка КП — **по цене** (ручной оценки нет, предложения
сравниваются по сумме, лучшее — наименьшая); имя документа —
**`ПредложениеПоставщика`**; заказ поставщику **можно** создавать и мимо
тендера (отказа проведения нет); весь тендер — под **константой и
функциональной опцией `ТендерыПоставщиков`** (новые, свои uuid): документ,
команды и элементы форм видны только при включённой опции (флажок в общей
форме «Параметры», как `ВыборПартииПриПродаже` в волне 9).

Модель:

- Документ **`ПредложениеПоставщика`** (непроводимый): Организация,
  `ЗаказПокупателя` (основание, обязательный), Поставщик (Контрагент),
  Договор, ДатаПредложения, СрокПоставкиДней, `ЦенаВключаетНДС`,
  `Победитель` (Булево), Комментарий, Ответственный; ТЧТовары: Номенклатура,
  Характеристика, Упаковка, КоличествоУпаковок, Количество, Цена, Сумма,
  СтавкаНДС, СуммаНДС, СуммаСНДС, СрокПоставкиДней. Ввод на основании
  `ЗаказПокупателя` (состав из заказа, цены — последний прайс поставщика).
  Шапки Сумма/СуммаНДС/СуммаБезНДС — через
  `РаботаСДокументами.ЗаполнитьИтогиДокумента`.
- Список предложений по заказу: критерий отбора `СвязанныеДокументы`;
  `ФормаСписка` с колонками Сумма/СрокПоставкиДней/Победитель,
  сортировка по сумме (лучшее сверху); в форме заказа покупателя — команда
  «Предложения поставщиков» (список с отбором по заказу) и декорация
  «Тендер: N предложений, победитель — <поставщик>» (при включённой опции).
- Команда **«Выбрать победителя»** в форме предложения: ставит
  `Победитель = Истина` себе и снимает у остальных предложений этого заказа
  (одна транзакция); по умолчанию предлагается предложение с наименьшей
  суммой. После выбора — предложение создать `ЗаказПоставщику` на основании
  выигравшего КП: контрагент, договор, цены и состав — из предложения,
  `Основание` (существующий реквизит) — заказ покупателя.
- Закрытие цепочки: новых статусов не вводить — у `ЗаказаПокупателя` есть
  `СтатусыЗаказовПокупателя`/`ИсторияЗаказовПокупателейПоСтатусам`; ПТУ по
  заказу поставщику приходует товар, резерв/отгрузка штатно.

### 10.1. Кредиты и запрет отгрузок (R3) — M

- `Контрагенты`: `КонтрольКредита` (выключатель), `СуммаКредита`,
  `СрокОплаты`, `СпособРасчётаОтсрочки` (uuid Rayssouni) — как **умолчания**
  при пустых значениях договора; страница «Кредит» в карточке (поля доступны
  при включённом контроле).
- `ВзаиморасчётыСПокупателями.ПолучитьПросроченнуюЗадолженность`: оставить
  расчёт по договору, но `ЕСТЬNULL(Договор.X, Контрагент.X)`; `СрокОплаты=0`
  → 365 дней; менеджер — куратор договора, иначе ответственный контрагента;
  вместо «−1000000 дней» — отдельный параметр «без ограничения».
- `РаботаСДокументамиВызовСервера.КлиентуЗапрещеноОтгружать`: если
  `КонтрольКредита` выключен — только ручной `ЗапретОтгрузок` (как сейчас);
  включён — ручной запрет ИЛИ дата запрета наступила ИЛИ долг сверх
  `СуммаКредита`. Настройка пользователя `НеКонтролироватьЗапретОтгрузок`
  (предопределёнка есть) отключает проверку. Клиентская проверка при смене
  контрагента и записи заказа/РТУ уже есть (`КлиентуЗапрещеноОтгружать` в
  формах) — не дублировать, только починить очистку: очищать контрагента,
  не трогая организацию/договор.
- Регламентное задание `ЗапретОтгрузок` (uuid Rayssouni, Use=false по
  умолчанию): раз в день `СистемныеОповещения` менеджерам «клиенту запрещено
  отгружать» / «будет запрещено через N дн.» (константа
  `ОповещатьЗаКолДнейДоЗапретаОтгрузок`). Опечатку Rayssouni в имени
  константы и сломанные вложенные `НСтр` — не воспроизводить: имена чистые,
  `НСтр` ru/fr/en/es.

### 10.2. Комплекты (R4) — M

- `ТипыНоменклатуры.Комплект` (uuid), ТЧ `Номенклатура.СоставКомплекта`
  (Номенклатура с отбором «Товар», Количество; uuid их); страница «Комплект»
  в карточке вместо «Хранения» для типа Комплект; состав блокировать, если
  комплект есть в проведённых документах (запрос ПЕРВЫЕ 1, кэшировать в
  реквизит формы — § 3.14).
- Реквизит `Комплект` в `ТоварыВНаличии` и `ДополнительныеРасходы` (uuid);
  `ТоварыВНаличии.РазложитьКомплектыНаСоставляющие(ТЗ)` перед
  `СписатьНоменклатуру` (наш пакет с партиями/сериями; составляющие без
  характеристики/серии/партии, `ЕстьПартия = Ложь`), `ДобавитьРасход` с
  комплектом; при возврате от покупателя комплект приходуется как товар
  (ограничение Rayssouni — принять, зафиксировать в TECHDEBT).
- `Продажи.СформироватьДанные`: свёртка составляющих обратно в комплект
  (`ВЫБОР КОГДА Комплект пусто…`), выручка по партиям пропорционально
  себестоимости с **защитой от деления на ноль** (нулевая себестоимость —
  делить поровну по количеству), остаток на последнюю строку (§ 3.6).
- Последние цены: закупочная комплекта — сумма по составу (в
  `РаботаСДокументами.ЗаполнитьПоследниеЦены`, без обращений по ссылке в
  цикле — состав одним запросом).
- Проверить отборы `ТипНоменклатуры` в ТЧ документов продаж (Комплект должен
  выбираться в РТУ/заказе/КП, но не в ПТУ/производстве).

### 10.3. ОбъектРасчётов и «Главная книга» (R15) — S

- Измерение `ОбъектРасчётов` (uuid Rayssouni, составной тип: накладная |
  основание | платёжный документ) в `ВзаиморасчётыСПокупателямиНалоговый` и
  `ВзаиморасчётыСПоcтавщикамиНалоговый`; заполнять во всех наших движениях
  (менеджеры регистров, налоговые документы, платёжные документы волны 5) —
  регистратором-основанием, для оплат — платёжным документом.
- Отчёт `ГлавнаяКнига` (uuid Rayssouni): по образцу нашего
  `РасчетыСПокупателями` + группировка по `ОбъектРасчётов`; схему Rayssouni
  не копировать, собрать на наших регистрах; 4 языка, `CommonForm.ФормаОтчёта`.

### 10.4. Статус оплаты накладных (R16) — S

Вычисляемое поле в динамических списках `НалоговаяНакладная` и
`НалоговаяНакладнаяПокупка` по образцу `НомерКартинкиОплаты` списка РТУ:
остаток по налоговому регистру взаиморасчётов (0 — не оплачена, частично,
оплачена), пиктограмма `СостояниеЗаказа`. Без регистра
`СтатусыОплатыДокументов` и подписок Rayssouni.

### 10.5. Тендер поставщиков (R12 по-нашему) — M

По согласованному проекту (см. выше), под константой и ФО
`ТендерыПоставщиков`. Печать предложения — вариантом `ВывестиDevisBL`
(«Demande de prix» / КП поставщика), без клона макета. Права:
МенеджерПоЗакупкам — полные, МенеджерПоПродажам/Казначей — чтение.
Подсистема Закупки. В `СвязанныеДокументы` и `ДвиженияДокумента` не
забыть новый документ.
