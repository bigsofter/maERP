# Производство, переработка, партии и склад — анализ ветки drissotex

Пути ниже — относительно выгрузки drissotex (`scratchpad/drissotex/...`), диффы — в `scratchpad/diffs/`.
Важное методическое замечание: `build/xml` (предок) старше нашего src (в нём нет `ЗаполнитьТехкарту`,
команд `Сырье/Полуфабрикаты/ГотоваяПродукция`, которые в нашем src есть с первого коммита 226e95d),
поэтому для файлов категории `both` сравнение делалось напрямую с `build/xml-current`.

## 1. Краткое резюме

В drissotex вокруг существующего документа `ВыпускПродукции` начали строить контур давальческой
переработки и партионного учёта, но довели его только до «каркаса»:

- Добавлены документы `ПередачаВПереработку` и `ПоступлениеИзПереработки`, регистр `ТоварыВПереработке`,
  справочник `ПроизводственноеОборудование`, роль `ОператорПроизводства`, подсистема `Производство` с
  подчинёнными `ПроизводственныеОперации`/`Справочники`. **Проведение новых документов не реализовано**:
  регистр `ТоварыВПереработке` никто не заполняет, его модуль менеджера — побайтовая копия модуля
  `ТоварыВНаличии`, а `ТоварыВНаличии.СформироватьДвижения` не знает эти типы документов, поэтому
  проведение всегда даёт `Отказ = Истина`.
- Реально работающая часть — **явный выбор партии при списании**: реквизит `Партия` в `ТЧТовары`
  `ВыпускПродукции`, форма `ВыборПартииПоОстаткам`, модуль `ПартииИРазмещениеКлиент`, колонки
  `Партия/ЕстьПартия` в `СерииИРазмещение.ОбъединитьТоварыССериями` и списание по конкретной партии в
  `ТоварыВНаличии.СписатьНоменклатуру` с контролем остатка по партии.
- **Ресурс `СуммаНДС`** в регистрах `ТоварыВНаличии` и `ДополнительныеРасходы`, протянут через
  `ДобавитьПриход/ДобавитьРасход/РаспределитьНаСебестоимость` и оприходование выпуска.
- `ВыпускПродукции` расширен: `Оборудование`, `Оператор`, `Основание` (ЗаказПокупателя), табличная часть
  `ТЧГотоваяПродукция` с переключателем «несколько строк ГП», услуги включаются в себестоимость выпуска,
  убрана запись розничной цены при проведении.
- Склад: `МестаХранения.Налоговый` и условия по нему в диспетчере `ТоварыВНаличии`; закомментировано
  дублирование движений ПТУ на `ПодчиненныйСклад`; новые значения `ПоказателиДвиженияТоваров`.
- Наши правки этапа 1 (удаление `СформироватьТаблицуКритическихОстатков`, веток `ЗаданиеНаПеревозку`)
  и ce16379 (ветка `ВыпускПродукции` в диспетчере) пересекаются с их кодом — конфликты описаны ниже.

## 2. Функциональные изменения

### 2.1. Документы переработки: ПередачаВПереработку, ПоступлениеИзПереработки

**Что даёт пользователю.** Оформление передачи сырья/полуфабрикатов переработчику и получения готовой
продукции. Оба документа — шапка `Организация, МестоХранения, Контрагент, Основание (ЗаказПокупателя),
Ответственный, Комментарий`, ТЧ `ТЧТовары` и `ТЧГотоваяПродукция` (одинаковый состав: КодСтроки,
Номенклатура, Характеристика, Упаковка, Серия, КоличествоУпаковок, Количество). Ввод на основании:
`ПередачаВПереработку` — из `ЗаказПокупателя` (продукция из ТЧТовары заказа → ТЧГотоваяПродукция) и из
`ВыпускПродукции` (полуфабрикат из шапки выпуска → ТЧТовары); `ПоступлениеИзПереработки` — из
`ПоступлениеТоваровУслуг` (хотя в ОбработкаЗаполнения обрабатывается ещё и `ПересчётТоваров`, которого
нет в BasedOn). Есть печатная форма «Акт списания» (копия из СписаниеТоваров).

**Файлы.** `Documents/ПередачаВПереработку.xml` (+ Forms/ФормаДокумента, ФормаСписка, Ext/ObjectModule.bsl,
Ext/ManagerModule.bsl, Commands/ПечатьАктСписанияТоваров, Templates/АктСписанияТоваров),
то же для `Documents/ПоступлениеИзПереработки`; `Subsystems/Производство/Subsystems/ПроизводственныеОперации*`;
`DefinedTypes/ПриходныйДокументПартии.xml` (+ `ПоступлениеИзПереработки` как приходный документ партии);
`FilterCriteria/СвязанныеДокументы.xml`, `Reports/ДвиженияДокумента.xml` (включены новые типы).

**Направление.** Их добавление (новые uuid, ссылки на `ТоварыВПереработке`).

**Зависимости.** `AccumulationRegisters/ТоварыВПереработке`, `Catalogs/ПроизводственноеОборудование`
(только через подсистему), `DefinedTypes/ПриходныйДокументПартии`, `Documents/ВыпускПродукции`
(BasedOn), `РегистрыНакопления.Убытки.СформироватьДвижения`, `УправляемыеБлокировки.ТоварыВНаличии`.

**Состояние кода — незавершённый клон `СписаниеТоваров`:**
- `ОбработкаПроведения` обоих документов вызывает `РегистрыНакопления.ТоварыВНаличии.СформироватьДвижения`,
  где нет ветки для этих типов → функция вернёт `Ложь`, `Отказ = Истина`, документы **не проводятся**.
  Та же ошибка, что мы чинили для ВыпускПродукции в ce16379.
- В `RegisterRecords` указаны `Убытки, ДополнительныеРасходы, Хозрасчетный, ТоварыВПереработке,
  ТоварыВНаличии`, но `Убытки.СформироватьДвижения` и `Хозрасчетный.СформироватьДвижения` эти типы не
  обрабатывают; `ТоварыВПереработке` в коде не упоминается вообще.
- `ManagerModule.ПечатьАктСписанияТоваров` обоих документов читает `Документ.СписаниеТоваров.ТЧТовары`
  и макет `Документы.СписаниеТоваров.ПолучитьМакет("АктСписанияТоваров")`; командный модуль печати
  вызывает `Документы.СписаниеТоваров.ПечатьАктСписанияТоваров(Док, Таб)` — печать для документа
  переработки выведет пустой акт. Собственный макет `АктСписанияТоваров` в документах не используется.
- Модули форм обоих документов идентичны модулю формы СписаниеТоваров: `ПоказатьСебестоимость` берёт
  себестоимость из `ТоварыВНаличии.ПолучитьСебестоимостьПоДокументу`, обработчики ТЧГотоваяПродукция
  в ПоступлениеИзПереработки объявлены, но на форме ПоступлениеИзПереработки таблицы ТЧГотоваяПродукция
  нет (в отличие от ПередачаВПереработку, где форма двухстраничная).
- В `ПередачаВПереработку.ОбработкаЗаполнения` по `ЗаказПокупателя`: `ЗаполнитьЗначенияСвойств(НС, Стр)`
  без `КодСтроки`, перебор `ДанныеЗаполнения.ТЧТовары` с обращением к `Стр.Номенклатура.ТипНоменклатуры`
  — запрос в цикле по ссылке.
- Реквизит `Контрагент` в ПоступлениеИзПереработки есть, `Основание` типизирован только ЗаказПокупателя,
  хотя заполняется из ПоступлениеТоваровУслуг/ПересчётТоваров (присвоение не сработает — тип не войдёт).
- Ни одна роль drissotex не даёт прав на новые документы (в т.ч. `ОператорПроизводства`).

**Конфликт с нашими правками.** Нет (новые объекты). Подсистема `Производство` — см. 2.6.

**Рекомендация.** Решение владельца. Переносить как есть — нельзя: это нерабочий каркас. Если
функционал нужен, переносить только метаданные (документы, регистр, тип) и **писать проведение заново**:
ветки в диспетчере `ТоварыВНаличии` (списание у нас, приход на `ТоварыВПереработке`), обратное движение
при поступлении, расчёт себестоимости ГП. Трудоёмкость переноса «как есть» — M (метаданные + формы),
доведение до работающего состояния — L. Порядок: 2.3 (партии) → 2.4 (СуммаНДС) → 2.2 (регистр) → 2.1.

### 2.3. Явный выбор партии при списании (ВыпускПродукции, СписатьНоменклатуру)

**Что даёт.** В строке `ТЧТовары` документа `ВыпускПродукции` можно указать конкретную партию
(реквизит `Партия`, тип `ПриходныйДокументПартии`), выбрав её из остатков по складу/номенклатуре/
характеристике (форма показывает ДатаПартии, Поставщика, Количество, ЦенаЗакупки без НДС). При проведении
строка с партией списывается именно с неё с отдельным контролем «Недостаточно … по партии»; строки без
партии — по FIFO, как раньше. `ВыпускПродукции` добавлен в `ПриходныйДокументПартии`, т.е. выпущенная
продукция становится партией-регистратором.

**Файлы.**
- `Documents/ПоступлениеТоваровУслуг/Forms/ВыборПартииПоОстаткам/*` (новая форма, динамический список по
  `РегистрНакопления.ТоварыВНаличии.Остатки`, в запросе используется `СуммаНДСОстаток` → зависит от 2.4);
- `CommonModules/ПартииИРазмещениеКлиент/*` (новый, `ВыбратьПартиюПоОстаткам` + оповещение
  `ПослеЗакрытияФормыВыбораПартии`, заполняет `ДанныеСтроки.Партия`);
- `CommonModules/СерииИРазмещение/Ext/Module.bsl` — в `ОбъединитьТоварыССериями` добавляются колонки
  `Партия` (если нет) и `ЕстьПартия`;
- `AccumulationRegisters/ТоварыВНаличии/Ext/ManagerModule.bsl` — `СписатьНоменклатуру`: в пакете запросов
  появилась ВТ `ВТТовары` с Партия/ЕстьПартия и `ВТТоварыБезПартии` (индексы `Результат[4..7]` вместо
  `[3..6]`), отбор партий `Новый Структура("Номенклатура, Характеристика, Серия, Партия")` при
  `Стр.ЕстьПартия`, блок «проверим остаток по заполненным партиям»;
- `Documents/ВыпускПродукции.xml` (реквизит `ТЧТовары.Партия`), форма документа (колонка, событие
  `ТЧТоварыПартияНачалоВыбора`), `DefinedTypes/ПриходныйДокументПартии.xml` (+ВыпускПродукции).

**Направление.** Их добавление (новая форма/модуль, ссылки на `ЕстьПартия`, которых у нас нет).

**Зависимости.** 2.4 (`СуммаНДСОстаток` в запросе формы выбора и в `СписатьНоменклатуру`) — без
переноса 2.4 запросы нужно править.

**Конфликт с нашими правками.** Да, в `ТоварыВНаличии/ManagerModule.bsl`: тот же файл, где мы в ce16379

### 2.4. Ресурс СуммаНДС в ТоварыВНаличии и ДополнительныеРасходы

**Что даёт.** Себестоимость в регистрах хранится с выделенным НДС: приход и расход партий и издержек
переносят `СуммаНДС` пропорционально количеству; при выпуске продукции `СебестоимостьНДС` ГП =
сумма НДС списанных компонентов и издержек. Позволяет показывать цену закупки без НДС
(форма выбора партии) и корректно считать налоговые документы.

**Файлы.** `AccumulationRegisters/ТоварыВНаличии.xml` (ресурс `СуммаНДС`, uuid 9e2e3c53…),
`AccumulationRegisters/ДополнительныеРасходы.xml` (ресурс `СуммаНДС`, uuid ed3eb41d…),
`ДополнительныеРасходы/Ext/ManagerModule.bsl` (`ДобавитьРасход(..., Сумма, СуммаНДС = 0)`),
`ТоварыВНаличии/Ext/ManagerModule.bsl` (`ДобавитьПриход/ДобавитьРасход(..., СуммаНДС = 0)`,
`СписатьНоменклатуру`: `СуммаНДСОстаток` в запросе, `СуммаНДС` и `СуммаНДСДополнительногоРасхода` при
списании, `СтрПартия.СуммаНДС = СтрПартия.СуммаНДС - СуммаНДС`).

**Направление.** Их добавление (у нас в `ТоварыВНаличии.xml` ресурсы только Количество и Сумма).

**Зависимости.** `ТЗТоварыССериями` должна содержать `СуммаНДС` — в `СерииИРазмещение.ОбъединитьТоварыССериями`
колонка есть (SuммаНДС/СуммаСНДС уже считаются), а в `СформироватьДвижения` для ПТУ выполняется
`Движения.ТоварыВНаличии.Загрузить(ТЗТоварыССериями)` — значит СуммаНДС прихода загрузится автоматически.
Требует проверки, что `ДобавитьДанныеОприходования` и `РаспределитьНаСебестоимость` заполняют СуммаНДС
для всех приходных веток (ОприходованиеТоваров, ВозвратОтПокупателя и т.п.), иначе по части партий
НДС будет 0 — не ошибка, но неполнота.

**Конфликт.** Тот же файл `ТоварыВНаличии/ManagerModule.bsl` — см. 2.3; по метаданным конфликтов нет.

**Рекомендация.** Перенести (фундамент для 2.3 и для налогового контура). M. Переносить первым из
изменений диспетчера. После переноса — перепроведение/пересчёт остатков регистра (исторические записи
получат СуммаНДС = 0).

### 2.5. Расширение документа ВыпускПродукции

**Что даёт.**
- Шапка: `Оборудование` (ПроизводственноеОборудование), `Оператор` (ФизическиеЛица), `Основание`
  (ЗаказПокупателя, с ограничением выбора по Договор/Контрагент/Организация). В форме списка — колонки
  Основание, Основание.Контрагент, Оборудование, Оператор; колонка ХозяйственнаяОперация скрыта.
- ТЧ `ТЧГотоваяПродукция` (КодСтроки, Номенклатура, Характеристика, Упаковка, Серия, КоличествоУпаковок,
  Количество) и флаг формы `НесколькоСтрокГП`: при одном изделии поля шапки `Номенклатура/Характеристика/
  Серия/КоличествоУпаковок/Упаковка` на форме **привязаны к `Объект.ТЧГотоваяПродукция[0].*`**, при
  нескольких — показывается страница с таблицей (`НастроитьФорму`). Группа «Комплектующие» превращена в
  страницу.
- Тип номенклатуры в `ТЧТовары`: параметр выбора расширен с `Товар` до `Товар, Продукция, Полуфабрикат,
  Сырье` (то же сделано в `ПересортицаТоваров`).
- `ТЧТовары.КоличествоЗаЕдиницу` — тип `DefinedType.Количество` (у нас `xs:decimal`).
- Проведение (ветка в `ТоварыВНаличии.СформироватьДвижения`): после `СписатьНоменклатуру` запросом по
  `ТЗТоварыССериями` выбираются строки с `ТипНоменклатуры = Услуга` и их `Себестоимость` добавляется к
  себестоимости ГП; приход ГП с `СебестоимостьНДС`. Старая процедура
  `СформироватьОприходованиеПоВыпускуПродукции` (с несуществующей `ТЧИнгредиенты`) оставлена мёртвой.
- `ОбработкаПроведения` документа: **удалена** запись в `ЦеныНоменклатуры` по `ЦенаРозничная` (реквизит
  в метаданных остался, регистр в `RegisterRecords` остался).

8. Форма `ВыпускПродукции`: поля шапки привязаны к `Объект.ТЧГотоваяПродукция[0].*` — при пустой ТЧ
