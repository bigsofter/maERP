# Волна 8: проверка закрытия переноса на данных (`build/ib`)

Обновление `build/ib` из EDT headless недоступно (1cedtcli без JVM) —
проверку выполняет владелец.

## 1. Обновить конфигурацию

EDT → Refresh, синтаксический контроль: `ОбщегоНазначения`,
`ОбщегоНазначенияКлиентСервер`, `ГрупповоеИзменениеРеквизитов/Форма`,
`ТоварыВНаличии`, `ДополнительныеРасходы`, `ТоварыВПереработке`,
`ДенежныеСредстваОрганизаций`, `РаботаСДокументами`, менеджеры
`ПередачаВПереработку`/`ПоступлениеИзПереработки`, `ФормаПервогоЗапуска`,
`Номенклатура/ФормаСписка`. Реструктуризация при обновлении БД:

- ресурс `СуммаНДС` в `ТоварыВНаличии`, `ДополнительныеРасходы`,
  `ТоварыВПереработке` (исторические записи получают 0);
- удалён документ `Взаимодействие` (данных у клиентов нет — проверить
  запросом до обновления: `ВЫБРАТЬ КОЛИЧЕСТВО(*) ИЗ Документ.Взаимодействие`);
- `Пользователи.ФизическоеЛицо` — проверка заполнения;
- поля `ОперацияБух` удалены только в форме.

## 2. СуммаНДС в партиях (решение № 12)

До перепроведения все партии с НДС = 0:

```
ВЫБРАТЬ СУММА(О.СуммаОстаток) КАК Сумма, СУММА(О.СуммаНДСОстаток) КАК НДС
ИЗ РегистрНакопления.ТоварыВНаличии.Остатки КАК О
```

1. **ПТУ** с НДС (цена не включает НДС): провести/перепровести → движение
   прихода: `Сумма` = сумма с НДС, `СуммаНДС` = НДС строки.
   ```
   ВЫБРАТЬ Д.Номенклатура, Д.Количество, Д.Сумма, Д.СуммаНДС
   ИЗ РегистрНакопления.ТоварыВНаличии КАК Д ГДЕ Д.Регистратор = &Док
   ```
2. **Реализация** части партии: расход `СуммаНДС` = НДС партии × (сумма
   списания / сумма партии); остаток НДС партии уменьшился на ту же
   величину; при полном списании НДС партии обнулён (без копеечного
   хвоста).
3. **Поступление доп. расходов** на партию → приход `ДополнительныеРасходы`
   с `СуммаНДС` = НДС строки; следующая реализация списывает издержки с
   НДС пропорционально.
4. **Возврат от покупателя** по реализации: приход партии с НДС партии
   реализации; без основания — НДС из ТЧ возврата.
5. **Выпуск продукции**: НДС прихода ГП = сумма НДС списанных компонентов
   и издержек. **Акт разбора**: НДС делится по доле стоимости, сумма по
   строкам = НДС списанного. **Пересортица**: НДС переносится с списанной
   партии; при оприходовании по цене — 0.
6. **Переработка**: передача — у переработчика `СуммаНДС` партии = НДС
   списанной партии (+ НДС издержек); поступление — НДС ГП = НДС списанного
   сырья, делится как себестоимость.
7. Форма выбора партии (выпуск, передача): колонка «Цена без НДС» =
   (сумма − НДС) / количество.
8. **Перепроведение истории**: групповое перепроведение складских документов
   за период (ПТУ → реализации) — после него запрос п. 2 показывает НДС > 0;
   сверить `Сумма` до и после — себестоимость измениться не должна.

## 3. Роли (решение № 10)

- Пользователь с ролью **Оператор**: создаёт и проводит перемещение,
  списание, оприходование, ПТУ.
- **Кладовщик**: документ «Отгрузка товара» недоступен (нет в интерфейсе,
  открытие по ссылке — отказ в доступе).
- Новый пользователь через карточку без физлица — ошибка заполнения;
  первый запуск на чистой базе создаёт физлица по ФИО.

## 4. Список номенклатуры (решение № 5)

Колонки «Цена закупки» (по основному поставщику, цена единицы хранения) и
«Розничная цена» (вид цены «Розничная», без характеристики и товарной
группы); «Продано» на месте. Открытие списка на большой базе — время
сопоставимо с прежним (срез цен соединением, без ВТ).

## 5. Остальное

- Форматы: чек ПКО/РКО, акт сверки, отчёты «Кассовая книга», «Ведомость по
  товарам на складах» — даты `dd.MM.yyyy`, числа с двумя знаками во всех
  языках интерфейса (fr/en/es).
- Заголовки «Наименование» в плане счетов, регламентных заданиях,
  классификаторе единиц.
- Акты передачи/приёмки из переработки печатаются, суммы прописью в валюте
  учёта на языке сеанса.
- `ИнтерфейсКлиент` (ЛКП) открывается; ПКО с несколькими ставками НДС —
  ставки читаются из расшифровки.
- Серия готовой продукции в поступлении из переработки выбирается из
  справочника.
