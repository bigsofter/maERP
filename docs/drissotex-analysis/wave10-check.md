# Волна 10 — порядок проверки

Проверка в тестовой базе после реструктуризации (EDT: Refresh, синтакс-контроль,
обновление конфигурации БД). Реструктуризация затрагивает: справочник
`Контрагенты` (4 реквизита кредита), `Номенклатура` (ТЧ `СоставКомплекта`),
регистры `ТоварыВНаличии` и `ДополнительныеРасходы` (реквизит `Комплект`),
налоговые регистры взаиморасчётов (измерение `ОбъектРасчётов`), новый документ
`ПредложениеПоставщика`, константы `ОповещатьЗаКолДнейДоЗапретаОтгрузок` и
`ТендерыПоставщиков`.

## 1. Кредиты и запрет отгрузок (R3)

1. Карточка контрагента-покупателя: страница «Кредит» видна, поля СуммаКредита /
   СрокОплаты / СпособРасчёта доступны только при включённом «Контроль кредита».
2. Договор с заполненными условиями кредита: расчёт идёт по договору
   (`ПолучитьПросроченнуюЗадолженность`), при пустых значениях договора — по
   контрагенту; при нулевом сроке оплаты — 365 дней.
3. Отгрузка клиенту с включённым контролем и долгом сверх суммы кредита: при
   выборе контрагента в заказе/реализации — предупреждение, контрагент
   очищается (организация и договор остаются). Ручной «Запрет отгрузок»
   работает как раньше при выключенном контроле.
4. Настройка пользователя «Не контролировать запрет отгрузок» отключает проверку.
5. Регламентное задание «Запрет отгрузок» (по умолчанию выключено): включить,
   задать константу «Оповещать за кол. дней…», проверить оповещения менеджерам
   «запрещено отгружать» и «будет запрещено» (менеджер — куратор договора, иначе
   ответственный контрагента; оповещение приходит пользователю этого физлица).

## 2. Комплекты (R4)

1. Карточка номенклатуры: тип «Комплект» в тумблере, страница «Комплект» вместо
   «Хранения», состав с отбором «Товар» и количеством.
2. Продажа комплекта (РТУ): комплект в одной строке, при проведении списываются
   составляющие (FIFO, без характеристики/серии/партии), движения `ТоварыВНаличии`
   и `ДополнительныеРасходы` — с реквизитом `Комплект`.
3. Регистр «Продажи»: строки свёрнуты в комплект, выручка и НДС распределены по
   партиям пропорционально себестоимости (при нулевой — поровну по количеству),
   итог по документу сходится копейка в копейку.
4. Комплект с нулевой себестоимостью составляющих (новый товар без партий) —
   проведение не падает, деления на ноль нет.
5. Состав комплекта блокируется после первого проведённого документа с ним.
6. Последние цены в РТУ/заказе: закупочная комплекта = сумма последних
   закупочных цен состава.
7. Возврат от покупателя: комплект приходуется как товар (принятое ограничение),
   остаток комплекта на складе виден в ведомости.
8. Отчёт «Ведомость по товарам на складах»: после продажи комплекта остатки
   уменьшены по составляющим.

## 3. ОбъектРасчётов и «Главная книга» (R15)

1. Перепровести налоговую накладную (продажа и покупка) и платёжный документ по
   налоговому контуру: в движениях налоговых регистров заполнено измерение
   `ОбъектРасчётов` (равно документу движения).
2. Отчёт «Главная книга» (подсистема Бухгалтерия): организация обязательна,
   отбор по контрагенту, группировка контрагент → объект расчётов, обороты и
   остатки сходятся с отчётом «Расчеты с покупателями».
3. Исторические движения налоговых регистров получат пустой `ОбъектРасчётов` —
   при необходимости групповое перепроведение налоговых документов.

## 4. Статус оплаты накладных (R16)

1. Списки «Налоговая накладная» и «Налоговая накладная покупка»: пиктограмма
   оплаты (не проведена — пусто, не оплачена, частично, оплачена) и колонка Долг.
2. Оплатить накладную частично и полностью, перепровести накладную — статус
   меняется. Внимание: оплата, проведённая после накладной, отражается в статусе
   после перепроведения накладной (особенность модели волны 5).

## 5. Тендер поставщиков (R12 по-нашему)

0. Включить флажок «Тендеры поставщиков» в общих параметрах (константа + ФО);
   до включения документ и команды не видны.
1. Заказ покупателя → «Создать на основании» → «Предложение поставщика»: состав
   и количества из заказа, цены — последний прайс. Ввести 2–3 предложения от
   разных поставщиков с разными ценами и сроками.
2. Форма заказа: декорация «Тендер: N предложений…», команда «Предложения
   поставщиков» открывает список с отбором по заказу, сортировка по сумме
   (лучшее сверху).
3. В предложении команда «Выбрать победителя»: если предложение не самое
   дешёвое — предупреждение; флаг победителя ставится ему и снимается у
   остальных (транзакция); далее — вопрос о создании заказа поставщику.
4. Заказ поставщику по выигравшему предложению: поставщик, договор, состав и
   цены из предложения, `Основание` — заказ покупателя.
5. Цикл до конца: ПТУ по заказу поставщику, отгрузка заказа покупателя, статусы
   заказа штатные. Заказ поставщику мимо тендера создаётся свободно.
6. Печать «Demande de prix» из предложения (команда в меню Печать).
7. Права: МенеджерПоЗакупкам создаёт и редактирует предложения,
   МенеджерПоПродажам и Казначей видят их только на чтение.

## 6. Регрессия

1. Продажа обычного товара несколькими партиями: выручка в «Продажах»
   распределяется по себестоимости партий, итоги прежние.
2. Печать Devis/BL/Facture по РТУ и заказу — без изменений.
3. Ведомости расчётов и отчёты по продажам — без изменений.
