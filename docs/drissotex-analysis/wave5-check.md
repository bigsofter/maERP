JVM), поэтому проверку выполняет владелец. Порядок:

## 2. Обновить конфигурацию

EDT → обновить конфигурацию БД `build/ib`. Реструктуризация:
`МестаХранения` (реквизит `Налоговый`), `ТоварыВНаличии`, `Продажи`,
`ДополнительныеРасходы` (тип измерения `Партия`), состав регистраторов
`ВзаиморасчётыСПокупателямиНалоговый`, `ВзаиморасчётыСПоcтавщикамиНалоговый`,
`ТоварыВНаличии`, `ВзаиморасчётыСПоставщиками` (`НалоговаяНакладнаяПокупка`
исключена — её старые записи в этом регистре удалятся).

## 3. Пометить налоговые склады

`МестаХранения` → у складов, по которым проводились налоговые накладные,
включить «Налоговый учёт». Какие это склады:

```
ВЫБРАТЬ РАЗЛИЧНЫЕ Д.МестоХранения ИЗ Документ.НалоговаяНакладная КАК Д ГДЕ Д.Проведен
ОБЪЕДИНИТЬ ВЫБРАТЬ РАЗЛИЧНЫЕ Д.МестоХранения ИЗ Документ.НалоговаяНакладнаяПокупка КАК Д ГДЕ Д.Проведен
ОБЪЕДИНИТЬ ВЫБРАТЬ РАЗЛИЧНЫЕ Д.МестоХранения ИЗ Документ.ВозвратОтПокупателяНалоговый КАК Д ГДЕ Д.Проведен
```

Без флага налоговые документы при перепроведении дадут отказ с сообщением
(так задумано: у drissotex они молча оставались без движений).

## 4. Перепровести за весь период

Стандартная обработка «Проведение документов» (или `Документы.X.Выбрать()`
в консоли кода), по видам в порядке дат: `НалоговаяНакладнаяПокупка`,
`НалоговаяНакладная`, `ВозвратОтПокупателяНалоговый`, затем
`ПриходныйКассовыйОрдер`, `РасходныйКассовыйОрдер`,
`ПоступлениеБезналичныхДенежныхСредств`, `СписаниеБезналичныхДенежныхСредств`.
Документы с отказом — в список для разбора.

## 5. После — повторить запросы из п. 1 и сравнить

Ожидаемо:
- `ВзаиморасчётыСПокупателями`: остаток по контрагенту уменьшился на сумму
  его НН минус возвраты НН минус оплаты с основанием НН; ровно эта величина
  появилась в `ВзаиморасчётыСПокупателямиНалоговый`.
- `ВзаиморасчётыСПоставщиками` / `…СПоcтавщикамиНалоговый` — то же по ННП.
- `ДенежныеСредстваОрганизаций`: итоги по кассам/счетам не изменились,
  кроме ПКО с типом оплаты «Чек» (теперь дают приход чеком в кассу) и
  документов обналичивания чека; задвоений по ПКО с несколькими
  основаниями нет (сумма движений = сумма документа).
- `ТоварыВНаличии` по налоговым складам: приход по ННП с партией = ННП.

## 6. Функциональные сценарии

- ПБДС «Обналичивание чека»: чек списан из кассы (`ОплатыЧеками` расход,
  `ДенежныеСредстваОрганизаций` расход Cheque), приход на счёт.
- ПКО с основанием НН и РКО/СБДС с основанием ННП: долг закрывается в
  налоговом регистре, обычный не трогается.
- Новая ННП на основании ПТУ: договор поставщика, входящие номер/дата
  перенесены; по нескольким ПТУ с разными входящими — пусто и сообщение.
- Отчёты расчётов: с отбором по контрагенту и без (группировка по
  контрагентам), логотип в шапке.
