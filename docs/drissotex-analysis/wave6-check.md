# Волна 6: проверка на данных drissotex (`build/ib`)

Обновление `build/ib` из EDT-проекта headless недоступно (1cedtcli без
JVM), поэтому проверку выполняет владелец. Порядок:

## 1. До обновления конфигурации — снять контрольные суммы

Премии по плановой модели считаются только в документе `НачислениеЗарплаты`
(в предке вызов `РассчитатьПремию` был закомментирован, поэтому в базе
drissotex премий «по плану» нет — проверить):

```
ВЫБРАТЬ НАЧАЛОПЕРИОДА(Д.Дата, МЕСЯЦ) КАК Месяц, ТЧ.Сотрудник, ТЧ.Оклад, ТЧ.Премия, ТЧ.Сумма
ИЗ Документ.НачислениеЗарплаты.ТЧСотрудники КАК ТЧ
	ЛЕВОЕ СОЕДИНЕНИЕ Документ.НачислениеЗарплаты КАК Д ПО ТЧ.Ссылка = Д.Ссылка
ГДЕ Д.Проведен
УПОРЯДОЧИТЬ ПО Месяц, ТЧ.Сотрудник
```

Месяцы, за которые есть плановые показатели и постоянные настройки премий:

```
ВЫБРАТЬ "План" КАК Источник, П.Период КАК Период, П.Сотрудник, П.Показатель, П.Стоимость КАК Сумма
ИЗ РегистрСведений.ПлановыеПоказатели КАК П
ОБЪЕДИНИТЬ ВСЕ
ВЫБРАТЬ "Настройка", Н.Период, Н.Сотрудник, Н.ВидПремии, Н.Премия
ИЗ РегистрСведений.ПремииСотрудников КАК Н
УПОРЯДОЧИТЬ ПО Источник, Период, Сотрудник
```

Остаток регистра `Зарплата` по сотрудникам и статьям:

```
ВЫБРАТЬ Ост.Сотрудник, Ост.СтатьяЗатрат, Ост.СуммаОстаток
ИЗ РегистрНакопления.Зарплата.Остатки КАК Ост
УПОРЯДОЧИТЬ ПО Сотрудник, СтатьяЗатрат
```

Затраты регистра `Убытки` (для показателя «Чистая прибыль»):

```
ВЫБРАТЬ НАЧАЛОПЕРИОДА(О.Период, МЕСЯЦ) КАК Месяц, О.МестоХранения, СУММА(О.Сумма) КАК Сумма
ИЗ РегистрНакопления.Убытки КАК О
СГРУППИРОВАТЬ ПО НАЧАЛОПЕРИОДА(О.Период, МЕСЯЦ), О.МестоХранения
```

## 2. Обновить конфигурацию

EDT → обновить конфигурацию БД `build/ib`. Реструктуризация:
`ПоказателиРасчётаПремий` (предопределённые элементы `ПремияПоПлану`,
`ФиксированнаяПремия`, `ПроцентОтПродажСотрудника`,
`ПроцентОтОбщегоОбъема`, `ПроцентОтПродажПодразделения`), константа
`СтранаКалендаря`, общий макет `ПраздничныеДни`, тип реквизита
`СформироватьДля` отчёта «Зарплата сотрудника» (`СтруктураПредприятия` →
`МестаХранения`). Предопределённые элементы платформа создаёт при первом
запуске; их реквизиты анализа продаж подставляются расчётом по умолчанию
(`ЗначенияПоУмолчаниюПредопределенного`) и записываются при первом
сохранении элемента.

## 3. Настроить премии

- `ПремииСотрудников`: для сотрудника A — `ФиксированнаяПремия`, сумма;
  для сотрудника B — `ПроцентОтПродажСотрудника`, процент; для C —
  `ПроцентОтОбщегоОбъема`, процент.
- `УстановкаПлановыхПоказателей` за тот же месяц для сотрудника D с любым
  видом премии (плановая модель).
- Месяц с продажами; у документов продажи заполнены `Менеджер` или
  `Ответственный` с физлицом (продавец = менеджер, при его отсутствии -
  физлицо ответственного).

## 4. Сверка

- `НачислениеЗарплаты` → «Заполнить»: колонка «Премия» видна и заполнена.
  A — сумма из настройки (при `ПоОтработаннымДням` — пропорционально
  табелю); B — `процент × выручка продавца B` (проверить запросом ниже);
  C — `процент × выручка всей организации`; D — как давал старый расчёт
  по плану (сумма по `ПлановыеПоказатели` с коэффициентами).
- Выручка продавца за месяц:

```
ВЫБРАТЬ ВЫБОР КОГДА О.Сотрудник = ЗНАЧЕНИЕ(Справочник.ФизическиеЛица.ПустаяСсылка)
		ТОГДА П.ФизическоеЛицо ИНАЧЕ О.Сотрудник КОНЕЦ КАК Продавец,
	СУММА(О.ВыручкаОборот) КАК Выручка, СУММА(О.ВаловаяПрибыльОборот) КАК Прибыль
ИЗ РегистрНакопления.Продажи.Обороты(&НачалоМесяца, &КонецМесяца, , ) КАК О
	ЛЕВОЕ СОЕДИНЕНИЕ Справочник.Пользователи КАК П ПО О.Ответственный = П.Ссылка
СГРУППИРОВАТЬ ПО ВЫБОР КОГДА О.Сотрудник = ЗНАЧЕНИЕ(Справочник.ФизическиеЛица.ПустаяСсылка)
		ТОГДА П.ФизическоеЛицо ИНАЧЕ О.Сотрудник КОНЕЦ
```

- Регрессия плановой модели: для D сумма премии после волны равна сумме
  до волны (если до волны премии не считались — равна ручному расчёту по
  `ПлановыеПоказатели`: стоимость показателя × процент выполнения в зачёт).
- Один и тот же вид премии у D и в плане, и в настройках — в расшифровке
  отчёта одна строка «По плану: …», строки «По настройке» по этому виду нет.
- Проведение `НачислениеЗарплаты`: в `Зарплата` две записи на сотрудника -
  оклад по статье `НачислениеПоТабелю`, премия по статье `Премия`; остаток
  по сотруднику (п. 1) не изменился, если документ не перезаполнялся.
- Отчёт «Зарплата сотрудника» по сотруднику и по месту хранения: разделы
  «Премии» с пояснениями «По плану» / «По настройке», «Штрафы», валюта из
  `ВалютаРегламентированногоУчета`, период без «г.».
- Производственный календарь: страна `MA` → «Заполнить по умолчанию» даёт
  субботы, воскресенья и 10 праздников (01.01, 11.01, 14.01, 01.05, 30.07,
  14.08, 20.08, 21.08, 06.11, 18.11); `RU` — 14 праздников. Смена страны
  в форме сохраняется в константу.

## 5. Не проверено автоматически

- Показатель «Чистая прибыль» — `Убытки.ПолучитьЗатраты` написан без
  прогона на данных; сверить с п. 1 (затраты по месту хранения).
- Количество запросов к `Продажи` при заполнении документа: один на вид
  премии (вариант «по сотруднику» — суммы по продавцам одним запросом),
  а не на сотрудника; проверить замером в консоли (технологический журнал
  или `ОценкаПроизводительности`).
