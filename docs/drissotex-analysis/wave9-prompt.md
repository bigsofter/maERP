## Решения владельца (2026-08-23)

- **R13 — режим «цена без НДС» — берём, но не по Rayssouni:**
  - константы `ЦенаВключаетНДС` **нет**; режим определяется видом цен
    (`ВидыЦен.ЦенаВключаетНДС` уже есть);
  - в документах продаж — реквизит `ЦенаВключаетНДС` («цена с НДС
    сверху/снизу»), заполняется по виду цен документа при выборе вида цен
    и контрагента (`ПолучитьЦенуНоменклатуры`/`ПолучитьДанныеКонтрагента`
    уже возвращают признак по типу цены контрагента); у документов закупок
    реквизит уже есть (`ПоступлениеТоваровУслуг`, `ЗаказПоставщику`,
    `ВозвратПоставщику`, налоговая покупка, доп. расходы);
  - в регистрах цен колонки `ЦенаБезНДС` **нет**: `Цена` вида цен «НДС
    сверху» и есть цена без НДС;
  - `Контрагенты.ОсвобожденОтНДС` **не переносится**: плательщик НДС всегда
    выставляет НДС;
  - умолчание `РассчитатьСтроку(…, ЦенаВключаетНДС = Истина)` **не менять**
    (у Rayssouni перевёрнуто — сломает вызовы без параметра).
- **R12 — коммерческое предложение.** Перепроверено: у Rayssouni
  `КоммерческоеПредложение` — это **предложение клиенту** (Devis с НДС / HT /
  без цен, вводится по реализации, по нему вводится заказ покупателя).
  Процесс, описанный владельцем, — **тендер поставщиков**: заказ клиента →
  по нему КП от поставщиков → оценка каждого КП → выбор победителя → заказ
  поставщику по выигравшему → закрытие на заказ покупателя. У Rayssouni
  такого нет — это новая разработка, вынесена в **волну 10** (см. ниже) с
  проектом на согласование. Печать Devis клиенту остаётся из
  `ЗаказПокупателя`; документ КП Rayssouni как «предложение клиенту» в этой
  волне не переносится (если нужен и он — сказать).
- **R14 — печатные формы HT / без цен, проформа, Bon de commande — делаем.**
- **R15, R16 — `ОбъектРасчётов` в налоговых регистрах, «Главная книга»,
  статус оплаты накладных вычисляемым полем — делаем** (волна 10, рядом с
  кредитами).
- **Кредиты (R3) — нужны, отдельным блоком** (волна 10).
- **Не брать (3)** подтверждено: налоговый контур Rayssouni, нумерация с
  годом, роли «всё, кроме», точность 15,4, логотип/слоган клиента.
- Приоритет 1 из § 4 (R1, R2, R4–R11, R17) — брать; в этой волне всё, кроме
  комплектов (R4) и кредитов (R3) — они в волне 10.

## Задача

Перенести сервисные доработки, ценообразование, режим «цена без НДС» по
решению владельца и печатные формы HT. Порядок:

9.1 → 9.2 → 9.3 → 9.4 → 9.5 → 9.6 → 9.7 (проверка).

Каждый пункт — отдельный коммит; после каждого `scripts/lint.sh` (база —
текущий `build/bsl-json.json`, пересоздать `build/bsl-json-baseline.json`
перед началом; сравнение по парам (файл, код); `YoLetterUsage` на именах
метаданных с «ё» — в базу) и XML-проверка правленых `.mdo`/`.form`/`.mxlx`.

## Правила

- Объекты, переносимые из Rayssouni, создаём с их uuid (реквизиты, ТЧ,
  формы, регистры, перечисления); свои — новые uuid; префикса нет.
- Модули Rayssouni не копировать целиком: брать логику, писать по нашим
  образцам и `docs/rules-1c` (запросы не в цикле — у них два лишних запроса
  на каждую подстановку цены, § 3), `НСтр` ru/fr/en/es (у них сломанные
  вложенные `НСтр` — переписать), директивы явно, экспортные методы
  документировать, обработчики форм привязывать в `<handlers>` `Form.form`.
- Подозрительные места из § 3 `rayssouni.md` при переносе исправлять, не
  копировать (присваивание несуществующего `ХозяйственнаяОперация`, деление
  на ноль, `"F"++Format(...)` и т. д.).
- Ничего из «не брать (3)»; константы `ImprimerBL`/`…` не переименовывать.

  колонки в формах списков.

### 9.2. Режим «цена без НДС» по решению владельца (R13′) — M

- Реквизит `ЦенаВключаетНДС` в `ЗаказПокупателя`, `РеализацияТоваровУслуг`,
  `НалоговаяНакладная`, `ВозвратОтПокупателя`, `ОприходованиеТоваров` (uuid
  Rayssouni для одноимённых реквизитов), флажок на форме; при изменении —
  пересчёт строк через `РассчитатьСтроку(Стр, Объект.ЦенаВключаетНДС)`;
  значение по умолчанию — по виду цен документа (`ВидыЦен.ЦенаВключаетНДС`),
  при смене вида цен — обновить флаг и пересчитать.
- `РаботаСДокументамиКлиентСервер.РассчитатьСтроку`: ветка «цена без НДС»
  (НДС сверху, скидка от суммы с НДС — проверить по § 2.1 и исправить
  отмеченные там дефекты: `Возврат` до расчёта `СуммаНДС` при
  `ОснованиеРасчёта = "Сумма"`, затирание ручной суммы скидки).
- Все вызовы `РассчитатьСтроку`/`УстановитьПараметрыНоменклатуры` в формах
  документов продаж — передавать флаг документа; умолчание `Истина`
  сохранить.
- `УстановкаЦенНоменклатуры(Вручную)`, `ПравилаЦенообразования.
  СформироватьБазовыеЦены` — цена пишется как есть по виду цен; подстановка
  цены в документ с видом «НДС сверху» в документ «с НДС снизу» и наоборот —
  пересчёт через ставку НДС номенклатуры (одним запросом на ТЧ, не по
  строке).
- Налоговый контур (волна 5) и РМК: РМК всегда «с НДС» — не трогать.

### 9.3. Ценообразование (R5, R6, R7) — M

- `ВидыЦен`: реквизиты динамического расчёта (`ДинамическийРасчет`, способ —
  наценка % / сумма, база — себестоимость / последний приход, базовый вид
  цен — состав по § 2.2 и XML Rayssouni); `ПолучитьЦенуНоменклатуры`
  переписать: один запрос на список номенклатуры, без двух лишних запросов
  на строку (§ 3).
- Регистры `ЦеныЗакупки`, `ЦеныПродажи` (цены по контрагенту, uuid
  Rayssouni), страницы в карточке контрагента/номенклатуры, приоритет:
  цена по контрагенту → вид цен документа.
- `РаботаСДокументами.ЗаполнитьПоследниеЦены` (последние цены закупки и
  продажи, `ПроцентНаценкиНаЦену` в строках заказа покупателя) — в общий
  модуль, одним запросом на ТЧ.

### 9.4. Сервис в формах (R1, R2, R8, R10) — S каждый

- Подключаемые команды на ТЧ товарных документов: «Карточка товара»,
  «История товара», «Подбор товара» (`ПодключаемыеКомандыКлиент/Сервер`,
  `Номенклатура.ФормаПодбора`, `ДобавитьНоменклатуруПоПодбору`, отчёт
  `ИсторияТовара`) — подключение через общую процедуру в
  `ПриСозданииНаСервере`, без копирования в каждую форму.
- Панель «Себестоимость / Выручка / Прибыль / Наценка» в форме РТУ и
  налоговой накладной (по нашим `ПолучитьСебестоимостьПоДокументу` с
  `СуммаНДС`); «только просмотр» РТУ при наличии налоговой накладной;
  «Срок оплаты» в накладной.
- `РазрешениеНаРедактированиеДокументов` + автозакрытие периода по константе
  `АвтозакрытиеПериода` — исправить структуру регистра (§ 3: разрешение не
  гаснет, измерение `ДатаИспользования`), интеграция с нашим
  `РаботаСДокументами.МожноРедактироватьДокумент`.
- Ввод `ЗаказПокупателя` на основании `РеализацияТоваровУслуг`; `ЗаказПоставщику`
  на основании `ЗаказПокупателя` — дописать заполнение контрагента и цен
  (у них закомментировано), без `ХозяйственнаяОперация`.

### 9.5. Печатные формы HT / без цен, проформа, Bon de commande (R14) — M

Через наш рефакторинг волны 4 (`ВывестиDevisBL`, `ТекстЗапросаDevisBL`,
`ПараметрыПечатиDevisBL`, хелперы `ВыводПечатныхФорм`): варианты «HT» и
«без цен» для BL/Devis A4/A5 как параметры, а не клоны по 230 строк; итоги
HT/TVA/Remise; проформа и «Bon de commande» из заказа покупателя; без
слогана/логотипа клиента в макетах (логотип — наш `УстановитьЛоготип`).
Макеты — из Rayssouni с нашей локализацией (4 языка в `<tl>`).

### 9.6. Отчёты (R17) — S

Суммы без НДС в `ВедомостьПоТоварамНаСкладах` (по `СуммаНДС` регистров),
`ЧистаяПрибыль` в `ВедомостьПоПродажам`.

### 9.7. Проверка

себестоимости; цена по контрагенту перекрывает вид цен; подключаемые
