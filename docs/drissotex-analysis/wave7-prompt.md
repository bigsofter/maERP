## Решения владельца

- **№ 3 принято (2026-08-22): контур переработки берём полностью,
  проведение дописываем** — у drissotex это нерабочий каркас (документы
  всегда получают `Отказ`, регистр никто не пишет, модули регистра — копии
  `ТоварыВНаличии`). Переносятся только **метаданные** с uuid drissotex,
  проведение и модули пишутся заново.
- **№ 1**: одноимённые объекты с разными uuid (`Subsystems/Производство`,
  `Constants/ИспользоватьПроизводство`, `FunctionalOptions/Производство`)
  остаются **нашими**; из drissotex берётся только состав.
- **Нужны до начала 7.2 и 7.5 (спросить, если не даны в этом же
  сообщении):**
  - **№ 12 — `СуммаНДС`** (production.md § 2.4, план п. 2.1, отложен с
    волны 2): ресурс `СуммаНДС` в `ТоварыВНаличии`/`ДополнительныеРасходы`
    и `СебестоимостьНДС` готовой продукции. Без него в 7.2 услуги в
    себестоимости переносятся, а НДС — нет (так и сделать по умолчанию,
    отметить в отчёте).
  - **№ 13 — запись `ЦеныНоменклатуры` при выпуске**: drissotex удалил
    запись розничной цены в `ВыпускПродукции.ОбработкаПроведения`
    (реквизит `ЦенаРозничная` и регистр в `RegisterRecords` оставил). По
    умолчанию — **оставить нашу** (рабочая функция «цена при выпуске»).
  - **№ 14 — роли производства**: ни одна наша роль, кроме
    `Администратор`, не имеет прав на `ВыпускПродукции`; роль
    `ОператорПроизводства` drissotex — копия торговой роли без прав на
    производственные объекты. По умолчанию — создать **свою** роль
    `ОператорПроизводства` (новый uuid) с правами только на объекты
    подсистемы `Производство` (`ВыпускПродукции`, `ПередачаВПереработку`,
    `ПоступлениеИзПереработки`, `ПроизводственноеОборудование`, чтение
    `Номенклатура`, `МестаХранения`, `Контрагенты`, регистров
    `ТоварыВНаличии`/`ТоварыВПереработке`, константы/ФО производства) и
    дать те же права `Кладовщик`.

## Правила

- Новые объекты/реквизиты/формы — с uuid из drissotex (`build/drissotex/…`
  и `*.new`): `Документ.ПередачаВПереработку`, `Документ.ПоступлениеИзПереработки`,
  `РегистрНакопления.ТоварыВПереработке`, `Справочник.ПроизводственноеОборудование`,
  `Контрагенты.Субподрядчик`, реквизиты `ВыпускПродукции`. Объекты, созданные
  заново (роль, модули, команды печати при необходимости) — новые uuid.
  Существующие не перенумеровывать; префикс не используется.
- Модули drissotex для новых объектов **не копировать** (копии
  `СписаниеТоваров`/`ТоварыВНаличии`); писать по нашим образцам и
  `docs/rules-1c`: запросы не в цикле, без разыменования в параметрах
  виртуальных таблиц, блокировки (`locks-and-transactions.md`), `НСтр`
  ru/fr/en/es, директивы явно, экспортные методы документировать,
  `Отказ = Истина` + сообщение через `ОбщегоНазначенияКлиентСервер.СообщитьПользователю`.
- `scripts/lint.sh`: база — текущий `build/bsl-json.json` (пересоздать
  `build/bsl-json-baseline.json` перед началом; сравнение по парам (файл,
  код)); `CommonModuleInvalidType` — ложное; `YoLetterUsage` на именах
  метаданных с «ё» — принимать в базу, в новых идентификаторах «ё» не
  использовать.
- Git: ветка `develop`, один коммит — один пункт, сообщения на русском.
  `build/`, `DT-INF` не трогать.
- **Не переносить**: модули `ТоварыВПереработке` drissotex; печать
  «Акт списания» из документов переработки (запрос по `СписаниеТоваров`,
  хардкод валюты/локализации); `ТЧГотоваяПродукция` и `НесколькоСтрокГП`
  в `ВыпускПродукции`; роль `ОператорПроизводства` drissotex; объекты
  `Производство` (подсистема/константа/ФО) и картинка `Производство` (у нас
  своя `Производство128`); измерение `ЗаказПокупателя` и ресурс
  `КоличествоГП` регистра (нигде не используются); `Основание` типа

### 7.5. Проведение — L

Ветки в `ТоварыВНаличии.СформироватьДвижения` (диспетчер) и модуль
`ТоварыВПереработке`:

- **Передача**: `СписатьНоменклатуру(ТЗТоварыССериями, ДокОбъект)` со склада
  `МестоХранения` (с партиями и распределёнными издержками, как в
  `СписаниеТоваров`); по сформированным расходам `ТоварыВНаличии` —
  приход в `ТоварыВПереработке` той же партией/датой партии, `Контрагент`,
  `ПередачаВПереработку = Ссылка`, `Сумма` = себестоимость списания
  (+ издержки). Недостача на складе — отказ (как у `СписаниеТоваров`).
- **Поступление**: расход из `ТоварыВПереработке` по `ТЧТовары` FIFO у
  `Контрагент` (если `Основание` — конкретная передача, сначала её партии);
  себестоимость списанного сырья распределить на строки `ТЧГотоваяПродукция`
  пропорционально `Количество × Коэффициент`, где коэффициент — доля по
  техкарте `Номенклатура.ТехнологическаяКарта`, если она есть, иначе по
  количеству (задокументировать формулу); приход ГП в `ТоварыВНаличии`
  партией `= Ссылка` (`ПриходныйДокументПартии`), `ДатаПартии = Дата`,
  через `ДобавитьПриход`. Недостача у переработчика — отказ с сообщением
  (сотрудник, номенклатура, не хватает N).
- Блокировки: `УправляемыеБлокировки.ТоварыВНаличии` + `ТоварыВПереработке`
  до чтения остатков. Проверить `ДвиженияСформированы` → `Отказ`.
- Отчёт по остаткам у переработчиков: `Reports/ТоварыВПереработке` (СКД по
  `ТоварыВПереработке.ОстаткиИОбороты`, группировка `Контрагент` →
  `Номенклатура`, колонки приход/расход/остаток) — S, в подсистему
  `Производство`.

### 7.6. Роли и интерфейс — S (решение № 14)

Своя роль `ОператорПроизводства` (права на объекты производства,
`Configuration.mdo` `<roles>`), те же права `Кладовщик`; `Администратор`
получает всё автоматически (`setForNewObjects`). Новые документы — в
`FilterCriteria`, `DocumentJournals` при наличии складского журнала.

### 7.7. Проверка

- Сквозной сценарий на `build/ib` (владелец, свои данные): передача 10 ед.
  сырья переработчику → остаток на складе −10, в `ТоварыВПереработке` +10
  с суммой = себестоимость партии; поступление 8 ед. ГП из 10 ед. сырья →
  `ТоварыВПереработке` −10, `ТоварыВНаличии` +8 ГП с себестоимостью =
  сумма сырья; второе поступление сверх остатка — отказ; выпуск продукции
  с услугой в `ТЧТовары` — себестоимость ГП включает услугу; отчёт по
  остаткам у переработчиков; `Основание`/`Оборудование`/`Оператор` в
  списке выпусков.
- Запросы для сверки и порядок — `docs/drissotex-analysis/wave7-check.md`
  (по образцу `wave6-check.md`).
