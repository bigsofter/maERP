## 1. Краткое резюме

- **Большая часть объёма диффов в этой области — шум**: перестановка языков в `НСтр` (fr/ru/en/es), имена параметров СКД на английском/русском в выгрузке (`TextColor`↔`ЦветТекста`), `Cmd+S`↔`Ctrl+S` (выгрузка на Mac/Windows), синонимы. Все «both»-макеты СКД бухгалтерских отчётов (КарточкаСубконто 4748 строк, КарточкаСчета, ОтчетПоПроводкам, ОборотыСчета, АнализСчета, АнализСубконто, ОСВ, ОСВПоСчету, ФинансовыйРезультат, Затраты) содержат **0 содержательных изменений** — только локализация имён параметров. Переносить нечего.
- **Удаления в общих модулях (ОбщегоНазначения −497 строк, ДлительныеОперации −180, ОбщегоНазначенияКлиентСервер −170, ПроцедурыРегламентныхЗаданий, ПодпискиНаСобытия, РаботаСДокументамиВызовСервера, ВызовСервера.НастроитьПанели, SessionModule.Контрагент) — это наши добавления**, которых в drissotex просто нет. Не переносить «обратно».
- **Реальный функционал drissotex в моей области невелик и сосредоточен в зарплате**: премии из регистра `ПремииСотрудников` (переписан `РегистрыНакопления.Зарплата.РассчитатьПремию/РассчитатьПоказатель`), премия как отдельная статья движений, включённая колонка «Премия» в `НачислениеЗарплаты`, восстановленный вывод премий/штрафов в `ЗарплатаСотрудника`, валюта из константы вместо «руб.», производственный календарь Марокко, исправление соединения в `ТарифныеСтавки`, Табель без отбора по сотрудникам.
- В общих модулях — **две небольшие, но сквозные доработки**: остаток товара в строке документа (`ПолучитьДанныеНоменклатуры(…, ПолучитьОстаток)` + `ТоварыВНаличии.ПолучитьОстатокПоТовару`) и представление номенклатуры с брендом/описанием при печати (`ПредставлениеНоменклатуры(…, ЭтоПечать)` + реквизит `Номенклатура.ВыводитьНаПечатьОписание`). Плюс защита от деления на ноль в `РассчитатьСтроку`, приведение ставки НДС из JSON, колонка `ЕстьПартия` в `СерииИРазмещение`.
- Сервис: новые константы `УмныйПоиск`, `ImprimerBL`, `ЗадаватьВопросПередПечатьюЧека`, `ИспользоватьПроизводство` и их переключатели в `CommonForms/Параметры`; новый модуль `ПартииИРазмещениеКлиент` (выбор партии по остаткам). Обмены (РегистрацияИзменений, ОбменССайтом, ExchangePlans, ИсторияОбменаДанными, ВидыТранспортаОфлайнОбмена) — только шум.
- Конфликтов с нашими правками этапа 1 (bddd4f5) нет: в `ГрупповоеИзменениеРеквизитов` у них только перестановка `НСтр`; `ПрисоединённыеФайлыКлиент` — то же.
- Найдено несколько **дефектов на нашей стороне**, всплывших при сравнении (см. раздел 3): массовая замена заголовков «Наименование»→«Товар» в 18 формах, ссылка на несуществующий параметр сеанса `Контрагенты` в `CommonForms/ИнтерфейсКлиент`, дублирование функций хранилища настроек.

## 3. Подозрительные места

### В коде drissotex (править при переносе)
1. `Зарплата/ManagerModule.РассчитатьПремию/РассчитатьПоказатель`: ~120 строк старой логики оставлены под `//`, в т.ч. SMART и отбор по сотрудникам; `РассчитатьПоказатель(Стр, Сотрудник, Период, 0, 0)` вызывается, а его результат для фиксированной премии частично игнорируется (`Результат.Сумма + Стр.Премия`). Пустое `Отбор = Новый Структура()` без сотрудника — премия за продажи считается по **всем** продажам показателя, а не по менеджеру; проверить, что так и задумано.
2. `РассчитатьПремию` — вызовы `РассчитатьПоказатель` в цикле по показателям, внутри — запросы к `Продажи` на каждый показатель каждого сотрудника (`ЗарплатаСотрудника` по подразделению → N×M запросов). Было и раньше, но при переносе стоит вынести в один запрос.
3. `ПроизводственныйКалендарь`: хардкод праздников Марокко с комментариями «День Победы» и т.д.; дата `31.10` выглядит случайной (в Марокко такого праздника нет — уточнить у клиента).
4. `ОбщегоНазначенияКлиентСервер.ПредставлениеНоменклатуры`: 3–4 обращения к серверу на строку из клиентского кода; объединить в `ЗначенияРеквизитовОбъекта`.
5. `ОбщегоНазначенияВызовСервера.ПолучитьДанныеНоменклатуры`: `ПолучитьОстатокПоТовару` — отдельный запрос на каждую строку при массовом подборе/заполнении (`ДобавитьНоменклатуруПоШтрихкоду`). Для больших ТЧ — пакетный вариант.
