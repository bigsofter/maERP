# Волна 7: проверка переработки на данных владельца (`build/ib`)

Обновление `build/ib` из EDT-проекта headless недоступно (1cedtcli без
JVM), поэтому проверку выполняет владелец. У drissotex документов
переработки нет — сценарий прогоняется на своих данных.

## 1. Обновить конфигурацию

EDT → Refresh, синтаксический контроль модулей `ТоварыВНаличии`,
`ТоварыВПереработке`, документов `ПередачаВПереработку`,
`ПоступлениеИзПереработки`, `ВыпускПродукции` и их форм; обновить
конфигурацию БД `build/ib`. Реструктуризация:

- `ПриходныйДокументПартии` += `ПоступлениеИзПереработки` — перестраиваются
  регистры `ТоварыВНаличии`, `ДополнительныеРасходы`, `ТоварыВПереработке`
  и реквизиты `Партия` документов;
- новые объекты: справочник `ПроизводственноеОборудование`, реквизит
  `Контрагенты.Субподрядчик`, регистр `ТоварыВПереработке`, два документа,
  отчёт `ТоварыВПереработке`, роль `ОператорПроизводства`, подчинённые
  подсистемы `Производство`;
- реквизиты `ВыпускПродукции`: `Оборудование`, `Оператор`, `Основание`.

Перед обновлением — контрольная сумма себестоимости выпусков, чтобы
убедиться, что выпуски без услуг не изменились:

```
ВЫБРАТЬ Д.Регистратор, СУММА(ВЫБОР КОГДА Д.ВидДвижения = ЗНАЧЕНИЕ(ВидДвиженияНакопления.Приход) ТОГДА Д.Сумма ИНАЧЕ 0 КОНЕЦ) КАК Приход,
	СУММА(ВЫБОР КОГДА Д.ВидДвижения = ЗНАЧЕНИЕ(ВидДвиженияНакопления.Расход) ТОГДА Д.Сумма ИНАЧЕ 0 КОНЕЦ) КАК Расход
ИЗ РегистрНакопления.ТоварыВНаличии КАК Д
ГДЕ Д.Регистратор ССЫЛКА Документ.ВыпускПродукции
СГРУППИРОВАТЬ ПО Д.Регистратор
```

## 2. Подготовить данные

1. Контрагент-переработчик: в форме элемента включить «Субподрядчик».
2. Сырьё с остатком на складе (партия известной себестоимости), готовая
   продукция с техкартой (опционально — для проверки распределения).
3. Пользователю-испытателю дать роль `ОператорПроизводства` (или
   `Кладовщик`) и проверить, что раздел «Производство» показывает выпуск,
   передачу, поступление, оборудование и отчёт.

## 3. Сквозной сценарий

1. **Передача 10 ед. сырья** переработчику: `ПередачаВПереработку`,
   склад = склад остатка, ТЧТовары — 10 ед. (партию можно выбрать кнопкой
   в колонке «Партия»). Провести. Ожидание: `ТоварыВНаличии` −10 по партии,
   `ТоварыВПереработке` +10 с `Сумма` = себестоимость списанной партии
   (+ издержки по ней), `Контрагент` = переработчик,
   `ПередачаВПереработку` = документ.

   ```
   ВЫБРАТЬ Д.ВидДвижения, Д.Контрагент, Д.Номенклатура, Д.Партия, Д.ДатаПартии, Д.ПередачаВПереработку, Д.Количество, Д.Сумма
   ИЗ РегистрНакопления.ТоварыВПереработке КАК Д
   ГДЕ Д.Регистратор = &Док
   ```

2. **Передача сверх остатка** (например, 1000 ед.) — отказ с сообщением
   «Недостаточно (…)» как у `СписаниеТоваров`.

3. **Поступление 8 ед. ГП из 10 ед. сырья**: ввести на основании передачи
   (ТЧТовары заполняется остатком переданного, ТЧГотоваяПродукция —
   ожидаемой продукцией; количество ГП поправить на 8). Провести.
   Ожидание: `ТоварыВПереработке` −10 (партии передачи-основания первыми),
   `ТоварыВНаличии` +8 ГП на склад документа, `Партия` = поступление,
   `Сумма` прихода ГП = сумма расхода сырья (проверить равенство).

   ```
   ВЫБРАТЬ "Сырьё" КАК Что, СУММА(Д.Сумма) КАК Сумма ИЗ РегистрНакопления.ТоварыВПереработке КАК Д
   ГДЕ Д.Регистратор = &Док И Д.ВидДвижения = ЗНАЧЕНИЕ(ВидДвиженияНакопления.Расход)
   ОБЪЕДИНИТЬ ВСЕ
   ВЫБРАТЬ "ГП", СУММА(Д.Сумма) ИЗ РегистрНакопления.ТоварыВНаличии КАК Д
   ГДЕ Д.Регистратор = &Док И Д.ВидДвижения = ЗНАЧЕНИЕ(ВидДвиженияНакопления.Приход)
   ```

4. **Несколько строк ГП**: поступление с двумя позициями ГП — если у обеих
   есть техкарта, суммы делятся пропорционально `Количество × Σ(Количество
   компонентов техкарты)`; иначе — по количеству. Сумма строк = сумме сырья
   (остаток округления на последней строке).

5. **Второе поступление сверх остатка** у переработчика — отказ с сообщением
   «У переработчика «…» недостаточно (…): нужно N, остаток M, не хватает K».

6. **Поступление с другим переработчиком**, чем в передаче-основании —
   отказ проверки заполнения.

7. **Выпуск продукции с услугой** в ТЧТовары (номенклатура типа «Услуга»,
   колонка «Стоимость» заполнена вручную): себестоимость прихода ГП =
   списанные компоненты + издержки + стоимость услуги. Розничная цена при
   выпуске по-прежнему записывается в `ЦеныНоменклатуры` (решение № 13).

8. **Отчёт «Товары в переработке»** (раздел «Производство»): по переработчику
   — приход 10, расход 10, конечный остаток 0; после ещё одной передачи —
   остаток.

9. **Список выпусков**: колонки «Основание», «Контрагент», «Оборудование»,
   «Оператор»; в форме выпуска выбор основания ограничен заказами
   организации документа.

10. **Перепроведение** выпусков без услуг — контрольная сумма из п. 1 не
    изменилась.

## 4. Что смотреть в журнале регистрации

Ошибки блокировок при одновременном проведении передачи и поступления по
одному переработчику (блокируются `ТоварыВПереработке` по контрагенту и
номенклатуре, `ТоварыВНаличии` по складу и номенклатуре).
