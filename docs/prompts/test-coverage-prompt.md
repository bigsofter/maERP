Расширь автотесты maERP. Сначала прочитай `docs/TESTING.md`, `docs/ROADMAP.md` (блок 6)
и код подсистемы «Автотесты»: `Обработка.СмокТест` (модуль менеджера — состав форм и
печать, модуль формы — клиентский цикл и отчёт), `Обработка.ТестовыеДанные` (образцы
объектов), `ОбщийМодуль.АвтотестыКлиент` (диспетчер `/C`), скрипты `scripts/smoke.sh`,
`scripts/fixtures.sh`, `scripts/run-lib.sh`, `scripts/initial-fill-test.sh`.

Исходное состояние (проверено по `build/smoke-report.txt` от 2026-09-02): проход на
образцах покрывает 105 форм с одним пропуском (`Справочник.ГруппыПользователей` —
осознанно, образец не заводится), печать — 53 формы без ошибок; 19 ошибок в списках
документов того прогона закрыты в 2.0.14.10. Пункт блока 6 «половина форм без образцов»
устарел — закрой его в `docs/ROADMAP.md` и `docs/TECHDEBT.md` (раздел «Прогон форм
открывает только пустые объекты») первым коммитом.

Состав работ:

1. **Уровень 3 — жизненный цикл документов.** Обработка `ТестыДокументов` в подсистеме
   «Автотесты» по образцу `СмокТест`: запуск `/C "ТестыДокументов;<путь-к-отчёту>"`,
   форма-запускатель только пишет отчёт и завершает клиент, сценарии и проверки — в
   модуле менеджера. Каждый сценарий выполняется в транзакции с откатом
   (`НачатьТранзакцию` … `ОтменитьТранзакцию`): база после прогона не меняется, тест
   можно гонять на `build/ib` и на копиях баз клиентов. Сценарии первой очереди, по
   одному на контур:
   - закупка: `ПоступлениеТоваровУслуг` → проведение → остаток в `ТоварыВНаличии` вырос
     на количество строки, долг в `ВзаиморасчётыСПоставщиками` равен сумме документа;
   - продажа: `ЗаказПокупателя` → `РеализацияТоваровУслуг` на основании → проведение →
     остаток уменьшился, `Продажи` получил выручку, долг покупателя равен сумме;
     `ПриходныйКассовыйОрдер` на основании реализации → долг закрыт;
   - возврат: `ВозвратОтПокупателя` на основании реализации → остаток и долг вернулись;
   - производство (под ФО `Производство`): `ВыпускПродукции` с техкартой → продукция
     оприходована, сырьё списано, себестоимость распределена;
   - переработка: `ПередачаВПереработку` → `ПоступлениеИзПереработки` → регистр
     `ТоварыВПереработке` обнулён;
   - зарплата: `НачислениеЗарплаты` по табелю → движения `Зарплата`, `ВыплатаЗарплаты`
     закрывает долг;
   - деньги: `ПоступлениеБезналичныхДенежныхСредств` и `СписаниеБезналичныхДенежныхСредств`
     → `ДенежныеСредстваОрганизаций` и `ДвиженияДенежныхСредств`.
   Данные для сценариев брать из образцов `ТестовыеДанные` (контрагент с договором,
   номенклатура, склад, касса, организация — через те же `ПервыйЭлемент` /
   `КонтрагентСДоговором`); чего нет — заводить внутри транзакции. Проверки — маленький
   набор хелперов в модуле менеджера (`Ожидается(Условие, Описание)`, остаток регистра
   запросом по измерениям), никаких внешних фреймворков. Строки отчёта: `СТАРТ;Сценариев=N`,
   `ОК;<сценарий>`, `ОШИБКА;<сценарий>;<шаг>;<описание>`, `ПРОПУСК;<сценарий>;<причина>`
   (например, выключенная ФО), `ИТОГ;Сценариев=N;Ошибок=M;Пропущено=K`. Скрипт
   `scripts/doctests.sh [база]` по образцу `fixtures.sh`, ожидание через `run-lib.sh`,
   доступ — `SMOKE_USER`/`SMOKE_PWD`. Только тонкий клиент.

2. **Механизмы 2.0.14.11–13 в уровень 3**: сценарий «дополнительные реквизиты»
   (`УправлениеСвойствами.ДобавитьСвойство` → запись номенклатуры со значением через
   ТЧ и сведения через регистр → `ЗначениеСвойства` возвращает записанное; повторный
   `ДобавитьСвойство` не дублирует) и сценарий «отрасль» (`НачальноеЗаполнениеВызовСервера.
   ПрименитьОтрасль(Строительство)` заводит четыре реквизита, второй вызов — ноль).
   `scripts/initial-fill-test.sh` дополни проверкой `industry_attributes_created` = 4 в
   первом прогоне и 0 во втором.

3. **Неосновные формы объектов в смоке**: в `Обработки.СмокТест.ФормыОбъектовСОбразцами`
   добавь явный список «ещё и эти формы» с образцом — `ФормаЭлементаECommerce`,
   `ФормаДокументаECommerce` и что найдёшь по `ОбработкаПолученияФормы` в модулях
   менеджеров (grep). Мобильные формы не трогать — их отсекает `ФормаДоступнаНаКомпьютере`.

4. **Регламент и реестр**: `scripts/smoke.sh` не трогай; новый шаг — отдельным скриптом
   и строкой в `docs/TESTING.md` («Состав тестов», раздел про уровень 3, «Кто что делает»,
   «Регламент»: перед релизом гоняются lint, refcheck, smoke, initial-fill-test, doctests).
   В `docs/TESTS.xlsx` строку уровня 3 переведи в «Реализован» с составом сценариев и
   форматом отчёта, лист «Правила» дополни правилом «новый документооборот — новый
   сценарий уровня 3». Обновляй по правилу «человек/машина».

5. **Что не делать**: уровень 4 (тест-клиент, Vanessa) — не начинать; `build/ib` руками
   не менять; сценарии, которые требуют торгового оборудования или бухгалтерского контура
   (Р1/Р2 в ROADMAP), — не писать, пометить ПРОПУСК с причиной.

Правила исполнения: `checklist` из MCP `tiny1c` перед правкой `.mdo` и `Form.form`
(форму обработки собирать копией формы `СмокТест`); после правок — `scripts/lint.sh`
(без новых замечаний против `build/bsl-json-baseline.json`, пути в отчёте percent-encoded)
и `scripts/refcheck.py`; строки до 140 символов, директивы компиляции явно, экспортные
методы с комментарием. Обработка тестов — объект конфигурации, поэтому поднять `Y` версии
в `Configuration.mdo` и завести секцию в `ОписаниеИзменений` (ru/fr/en/es, формулировка
для пользователя — «в поставку добавлены автотесты документов, на данные не влияют»).
Коммиты по-русски, без Co-Authored-By, push — по слову владельца. Прогон на базе — после
того, как владелец сделает Refresh и импорт в EDT и обновит `build/ib`: до этого писать
код и скрипты, а в отчёте явно сказать, что прогон не выполнялся.

В отчёте владельцу: версия, список сценариев с результатом (или «не гонялось»), что
проверить руками, что осталось (сценарии второй очереди — налоговые накладные, комплекты,
кредиты и запрет отгрузок, премии).
