## Код

- **Регистр `НДСПродажи` никем не заполняется** — менеджерный
  `СформироватьДвижения` есть, вызовов нет; налоговые накладные пишут
  только ТоварыВНаличии/ДенежныеСредства/Взаиморасчёты.
- **`Справочник.Банки`: загрузка классификатора с rbc.ru** — виндовые
  разделители путей, `КопироватьФайл` по http; мертво на macOS/Linux
  сервере и бессмысленно вне РФ. Выпилить или заменить источник.
- **Запросы в циклах** (13 мест), **виртуальные таблицы без параметров**
  (27), **`НайтиПоНаименованию`/`НайтиПоКоду` на сервере** (86) — этап
  производительности.
- **Опечатки в именах метаданных**: `ВзаиморасчётыСПоcтавщикамиНалоговый`
  (латинская «c»), элементы стиля `BottonBackgroundColor`, `BottonFont`,
  `ButonTextColor`; всего 105 имён со смесью алфавитов. Переименование
  через рефакторинг EDT, отдельными коммитами.
- **NFC/NFD в путях git** — часть кириллических путей хранится в NFD
  (наследие macOS). Привести к NFC одним переименовывающим коммитом.

## Найдено при переносе волны 2 (2026-08-22)

- **Остаток при массовом подборе** — оценено в волну 11: пакетных вызовов
  не осталось. `ДобавитьНоменклатуруПоШтрихкоду` и
  `УстановитьПараметрыНоменклатуры` вызываются только одиночно из
  интерактивных обработчиков (скан, подбор, «при изменении»), данные товара,
  цена и остаток приходят одним серверным вызовом
  `ПолучитьДанныеНоменклатуры`; единственный цикл — корзина ЛКП, где остаток
  не запрашивается (в ТЧ нет колонки «Остаток»). Если появится пакетная
  загрузка строк — остатки заполнять одним вызовом
  `ТоварыВНаличии.ЗаполнитьОстаткиСтрок` после заполнения ТЧ.
- **`ЗаказПокупателя`: остаток по складу пользователя** — у заказа нет
  реквизита `МестоХранения`, колонка «Остаток» считается по складу из
  настроек пользователя; при пустой настройке — по всем складам. Решить,
  нужен ли заказу склад отгрузки.

## Найдено при переносе волны 4 (2026-08-23)

- **Константы `ImprimerBL` и `ImprimerFactureVentesEnDetail`** — имена
  латиницей; решение владельца 2026-08-23: не переименовывать.
- **Карточки контрагентов в печати** — `Справочники.Контрагенты.ПолучитьКарточку`
  вызывается по разу на документ и организацию (кэш на время одной печати),
  а не одним запросом на пакет документов. Для массовой печати сотен
  документов стоит сделать пакетный вариант `ПолучитьКарточки(Массив, Дата)`.
- **Метки IF / PATENTE / RC / CNSS / ICE** в подвале реквизитов организации
  и шапках Devis/BL оставлены литералами (марокканские идентификаторы,
  одинаковые на всех языках); при выходе на другие рынки вынести в
  настройку организации.
- **`ДобитьСтраницуПустымиСтроками`** ограничена высотой страницы через
  `ПроверитьВывод`, предохранитель 500 строк — на случай области нулевой
  высоты. Если макет окажется без области `EmptyLine`, вывод упадёт на
  `ПолучитьОбласть`.
- **uuid команд РТУ** `ПечатьТоварнаяНакладная` / `ПечатьТоварнаяНакладнаяOld`
  у нас и drissotex поменяны местами (`a3159cc9…`/`71341228…` против
  `19b3a458…`/`a3159cc9…`) — существующие объекты не перенумеровывались;
  при сравнении ролей по uuid учитывать.
- **Макет `DevisBL` (A5) drissotex** потерял строки «Commandé par» и
  «Adresse de livraison» предыдущей версии — при необходимости адреса
  доставки вернуть область в макет и параметр `АдресДоставки` в код.

## Найдено при переносе волны 5 (2026-08-23)

- **Отказ проведения налоговых документов по складу без признака
  «Налоговый учёт»** — исторические документы drissotex перепроведутся
  только после простановки флага (см. `wave5-check.md` п. 3); если у
  клиента налоговые накладные шли по обычным складам, нужен массовый
  перенос на налоговый склад или снятие отказа (решение владельца).
- **Печать долга и оплат для налоговых документов**: `ОплатыИДолгПоДокументу`
  и `ПолучитьЗадолженностьКлиентовПоКлассификации` считают по
  `ВзаиморасчётыСПокупателями`; для `НалоговаяНакладная` печатные формы
  с оплатами не вызываются, но при появлении такой печати нужна ветка по
  налоговому регистру.
- **Потребители долга в интерфейсе** (списки РТУ/заказов, `Дашборд`,
  `СверкаВзаиморасчётов`) показывают долг без налоговых накладных —
  ожидаемое следствие решения № 2; при необходимости объединить с
  налоговым регистром.
- **`YoLetterUsage`** на вызовах регистров `ВзаиморасчётыСПокупателямиНалоговый`
  / `…СПоcтавщикамиНалоговый` в модулях денежных документов — неизбежно
  до переименования регистров; отключить правило или добавить исключение
  в `.bslls.json`.

## Найдено при переносе волны 9 (2026-08-23, Rayssouni часть 1)

- **«Чистая прибыль» в «Ведомости по продажам»** считается как выручка без
  НДС минус полная себестоимость (входной НДС не выделен). Решение
  2026-08-24: НДС-ресурсы в `Продажи` НЕ добавлять — наоборот, этапом 13
  себестоимость уходит из регистра, прибыль собирается в отчётах из
  `Продажи` и профильных регистров себестоимости.
- **Справочные цены строк** (`ЦенаРозничная`, `ЦенаМинимальная`,
  `ЦенаПоТипуЦен`) берутся из прайса и не считаются для динамических видов
  цен; колонки покажут 0, если розничный вид переведён на динамический
  расчёт.
- **Автозакрытие периода**: список исключений — строка с именами документов
  в `РаботаСДокументами.ДокументПодлежитАвтозакрытию`; при добавлении новых
  денежных документов список нужно пополнять.
- **Подбор товара** не выбирает серию (характеристика выбирается с
  волны 11); при появлении серийного учёта в подборе добавить шаг выбора
  серии по образцу характеристики.
- **Динамическая цена от последнего прихода** берёт прайс поставщиков без
  отбора по характеристике (регистр хранит характеристику, поиск в
  `ДинамическаяЦена` — только по номенклатуре, как у среза `ПоследнийПрайс`).
- **Документ `КоммерческоеПредложение` Rayssouni не перенесён** (решение
  R12): печать Devis идёт из заказа покупателя; если понадобится
  «предложение клиенту» отдельным документом — вернуться.

## Найдено при переносе волны 10 (2026-08-24, Rayssouni часть 2)

- **Количество комплекта в регистре «Продажи»** — сумма единиц составляющих,
  а не количество комплектов (свёртка группирует партии составляющих под
  комплектом, количества складываются). Суммы корректны; количественные
  колонки отчётов по продажам для комплектов завышены.
- **Комплекты с характеристиками не поддерживаются**: составляющие
  раскладываются без характеристики, и строка продажи комплекта с
  характеристикой не найдёт свои партии при свёртке (себестоимость нулевая).
  Комплекты заводить без характеристик.
- **Возврат комплекта от покупателя** приходует комплект как товар (партия
  комплекта), уменьшение прибыли по возврату не находит партии составляющих —
  прибыль по возврату комплекта не сторнируется. Ограничение Rayssouni, принято.
- **Оприходование/инвентаризация комплекта** создаёт складской остаток самого
  комплекта, который продажей не списывается (списываются составляющие) —
  двойной учёт. Комплекты не приходовать как товар (кроме возвратов).
- **Статус оплаты налоговой накладной** в списке обновляется движениями
  регистратора-накладной: оплата, проведённая после накладной, попадает в
  статус после перепроведения накладной (модель волны 5).
- **«Главная книга» — только по покупателям** (по образцу «Расчеты с
  покупателями»); вариант по поставщикам — при необходимости.
- **`ДополнительныеРасходы.РаспределитьНаСебестоимость`**: проверено в
  волну 11 — у нас база пропорции НДС издержек корректна (`Стр.Сумма`,
  остаток на последнюю строку); бага Rayssouni (`Стр.СуммаНДС` в базе) нет.
