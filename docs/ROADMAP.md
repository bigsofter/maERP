Документ `ОперацияБух` и отчёты достались от предка вместе с кодом
1С:Бухгалтерии. Пункты разбираются вместе: доводить контур или вырезать ветки.

- **Ссылки на отсутствующие объекты в `ОперацияБух`** —

  `…КнигиПродаж`, `РегистрыСведений.ЖурналУчетаСчетовФактур`. Форма открывается,

- **Валютный пересчёт проводок не реализован** — регистра курсов нет,

  базовой, суммы Дт/Кт РУ/УУ/ФО неверны. Вводить только вместе с полноценным
  валютным контуром. *(TECHDEBT: смок 2026-08-25)*
- **Статус отражения в реглучёте всегда пуст** — механизм

  отбора по организации.

## 5. Недостроенные механизмы

- **Присоединённые файлы** — `ПрисоединённыеФайлыКлиент` не содержит
  `ОткрытьФайл`, `ПрисоединитьФайлы`, `СохранитьФайлы`, а их зовут карточка
  номенклатуры и обе формы регистра: кнопки ведут в пустоту. Достраивать вместе
  с механизмом. *(TECHDEBT: refcheck 2026-08-26)*
- **Длительные операции** — `ДлительныеОперацииКлиент` открывает
  `ОбщаяФорма.ДлительнаяОперация`, которой в конфигурации нет.
- **Отложенные обработчики обновления** — все обработчики выполняются при входе,
  монопольные под монопольным режимом. Если появится обработчик на миллионы
  записей, вход будет его ждать; архитектура регистрации отложенность допускает
  (`РежимВыполнения` уже есть). *(TECHDEBT: волна У1)*
- **Константа `НомерВыполненногоЗаполненияДанных`** — пустой объект метаданных,
  живёт до тех пор, пока все базы клиентов не пройдут версию 2.0.12; потом
  удалить вместе с веткой в `СтартоваяВерсияИнформационнойБазы`.

## 8. Функциональные хвосты по контурам

**Продажи и заказы**

- Склад отгрузки у `ЗаказПокупателя`: реквизита нет, «Остаток» считается по
  складу из настроек пользователя, при пустой настройке — по всем. **Р4.**
- Статус «Доставлен» по-прежнему никем не пишется. *(волна 12)*
- Подбор товара не выбирает серию — добавить шаг по образцу характеристики,
  когда появится серийный учёт. *(волна 9)*
- Динамическая цена от последнего прихода ищет прайс поставщиков без отбора по
  характеристике. *(волна 9)*

**Производство и переработка**

- Распределение себестоимости на несколько строк ГП в
  `ПоступлениеИзПереработки` — по весу или количеству; услуги переработчика в
  себестоимость ГП не входят. Добавить ТЧ услуг или связь с
  `ПоступлениеДополнительныхРасходов`. *(волна 7)*
- Услуга переработчика: долг формируется прямым движением, без договора, авансов
  и зачётов. Полный контур — через хозяйственную операцию документа. *(волна 12)*
- Розничная цена выпуска назначается только при единственной позиции продукции;
  для мультивыпуска поле скрыто. *(волна 12)*
- `ВыпускПродукции.Основание` — связь выбора только по организации.

**Зарплата и премии**

- Плановая ветка `РассчитатьПоказатель` осталась кодом предка: для показателей
  без анализа продаж премия всегда 0; ветки `Оплаты`/`ВыручкаОтОплат`/
  `Рентабельность` делают по запросу на показатель и сотрудника. Разбирать
  отдельно. *(волна 6)*
- «Чистая прибыль» по продавцам: затраты регистра `Убытки` не распределяются, по
  сотруднику чистая прибыль равна валовой. *(волна 6)*
- Праздники с плавающей датой (исламские, Пасха) в макет `ПраздничныеДни` не
  входят, переноса праздника с выходного нет — как и у предка. *(волна 6)*

**Взаиморасчёты и налоговый учёт**

- Отказ проведения налоговых документов по складу без признака «Налоговый учёт»:
  исторические документы drissotex перепроведутся только после простановки
  флага. Нужен массовый перенос на налоговый склад или снятие отказа — решение
  владельца при миграции клиента. *(волна 5)*
- Печать долга и оплат для `НалоговаяНакладная`: `ОплатыИДолгПоДокументу` и
  `ПолучитьЗадолженностьКлиентовПоКлассификации` считают по
  `ВзаиморасчётыСПокупателями`; при появлении такой печати нужна ветка по
  налоговому регистру. *(волна 5)*
- Долг в интерфейсе (списки РТУ и заказов, `Дашборд`, `СверкаВзаиморасчётов`)
  показывается без налоговых накладных — объединить с налоговым регистром, если
  понадобится. *(волна 5)*
- «Главная книга» сделана только по покупателям; вариант по поставщикам — при
  необходимости. *(волна 10)*

**Прочее**

- `УпаковкиЕдиницыИзмерения` не подчинён, а `ФормаЭлементаУпаковка` и
  `ОбработкаПолученияФормы` обращаются к `Владелец` (наследие предка). Форма
  защищена попыткой. **Р6.** *(смок 2026-08-25)*
- `Справочники.Контрагенты.ПолучитьРеквизитыПоИНН` падает на первой строке:
  берёт `ИТСЛогин`/`ИТСПароль`, которых в конфигурации нет; вызовов у функции
  нет. **Р9.** *(автотесты 2026-08-26)*
- Общая картинка `Взаимодействие16` осталась от удалённого
  `Документ.Взаимодействие` — убрать, если не понадобится. *(волна 8)*
- Колонка «Поставщик» в `ТоварыВНаличии.ВыборПартииПоОстаткам` берётся как
  `Партия.Контрагент` через составной тип: для оприходования, выпуска,
  пересортицы и акта разбора пусто. Отдельные представления партий по типу
  документа — при необходимости. *(волны 3 и 8)*
- Скрытому администратору `tinycio-1c` физлицо не создаётся: при интерактивном

## Принято как есть

Решения приняты, работа не планируется. Если пункт всплывает снова — это не
новая находка.

- **Опечатка `ВзаиморасчётыСПоcтавщикамиНалоговый`** (латинская «c») — не
  переименовываем: регистр хранит данные клиентов, переименование только при
  большой реструктуризации с конвертацией (волна 11).
- **Константы `ImprimerBL` и `ImprimerFactureVentesEnDetail`** латиницей — не
  переименовываем (решение 2026-08-23).
- **uuid команд `ПечатьТоварнаяНакладная` / `…Old`** у нас и drissotex поменяны
  местами — объекты не перенумеровывались, учитывать при сравнении ролей по uuid.
- **`YoLetterUsage`** — в базе линтера остаются 58 имён метаданных с «ё» и
  производные, плюс `ПланыВидовХарактеристик.ПоказателиРасчётаПремий`. Правило не
  отключаем, база работает фильтром.
- **`CommonModuleNameWords` на `ОбновлениеПрограммыОбработчики`** — имя точнее
  описывает назначение, замечание принято как известное.
- **Комплекты**: количество в регистре `Продажи` — сумма единиц составляющих
  (количественные колонки отчётов завышены, суммы верны); комплекты с
  характеристиками не поддерживаются; прибыль по возврату комплекта не
  сторнируется; оприходование комплекта даёт двойной учёт. Ограничения Rayssouni,
  приняты (волна 10).
- **`Документ.КоммерческоеПредложение` Rayssouni не переносится** — печать Devis
  идёт из заказа покупателя (решение R12).
- **`СуммаНДС` в партиях**: исторические движения имеют НДС = 0 до
  перепроведения; приходы без НДС в ТЧ дают нулевой НДС по определению.
- **Запросы в циклах** — из 13 исходных осталось 7, все холодные (печать чека
  возвратов, обновление розничных цен, регистрация изменений обмена, клиент-банк).
  В горячих местах их нет.
- **Шапка `ВыпускПродукции` дублирует первую строку ТЧ** — осознанная
  денормализация ради списков, печати и совместимости, синхронизируется в
  `ПередЗаписью`.
- **Стандартные картинки платформы** (`БиблиотекаКартинок.Справочник`, `.Отчет`,
  `.РегистрНакопления`, `.РегистрСведений`, `.РегистрБухгалтерии`,
  `.УдалитьНепосредственно`) в конфигурации не заведены, но работают — внесены в
  известные расхождения `scripts/refcheck-known.txt`.
- **`ДополнительныеРасходы.РаспределитьНаСебестоимость`** — база пропорции НДС
  издержек проверена в волну 11, бага Rayssouni у нас нет.

## Правила, которые надо помнить при доработках

Не задачи, а условия: нарушишь — получишь дефект.

- **Видимость разделов по ролям** выведена из прав и проставлена в
  `Configuration/CommandInterface.cmi`. Меняешь права роли — пересматриваешь
  видимость.
- **Остатки при пакетной загрузке строк** заполнять одним вызовом
  `ТоварыВНаличии.ЗаполнитьОстаткиСтрок` после заполнения ТЧ, а не по строке.
- **Автозакрытие периода**: добавляешь денежный документ — пополняешь список
  имён в `РаботаСДокументами.ДокументПодлежитАвтозакрытию`.
- **Статус оплаты налоговой накладной** обновляется движениями
  регистратора-накладной: оплата после накладной попадает в статус только после
  её перепроведения (модель волны 5).
- **Комплекты не приходовать как товар** (кроме возвратов) — иначе двойной учёт.
