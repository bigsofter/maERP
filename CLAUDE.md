# Правила разработки 1С для Claude Code

Этот файл задаёт правила работы AI над данной конфигурацией 1С:Предприятие.
Конфигурация **самописная / снята с поддержки** — можно править основную конфигурацию напрямую.

## Язык и стиль
- Имена переменных, методов, объектов — **на русском**, по стандартам 1С (ПаскальКейс/UpperCamelCase).
- Следуй стандартам разработки 1С (ИТС, v8std) и правилам из `~/.claude/rules/` (если установлены скилы Desko77).
- Соблюдай клиент-серверное разделение директив компиляции: `&НаКлиенте`, `&НаСервере`, `&НаСервереБезКонтекста`.

## Формы — НЕ генерировать XML
- **НЕ создавай и не правь XML управляемых форм** — это приводит к ошибкам XDTO при загрузке.
- Для форм: пиши только **BSL-обработчики** + текстовую инструкцию «что добавить на форму».
- Создание элементов/команд/реквизитов формы и привязку событий делает разработчик в редакторе форм EDT.

## API платформы — проверять, не выдумывать
- **ВСЕГДА** проверяй существование методов/свойств/типов через MCP `1c-platform` (alkoleft) перед использованием.
- НЕ выдумывай функции платформы. Если не уверен — ищи в MCP или в коде базы.

## БСП и существующий код
- Если в конфигурации есть БСП — приоритет методам БСП (например `ОбщегоНазначения*`), но **сверяйся с реальным кодом**, т.к. набор подсистем БСП индивидуален.
- Перед написанием нового кода — изучи существующие общие модули и паттерны проекта (MCP `search_code` / поиск по репозиторию).

## Запросы и транзакции — особая осторожность
- Язык запросов: оптимизируй только при явном запросе и **обязательно поясняй изменение логики выборки** — не меняй смысл запроса молча.
- НЕ переписывай логику объявления/фиксации транзакций без явного согласования.
- Избегай антипаттернов: запрос в цикле, «.» в обходе выборки, обращение к виртуальным таблицам без параметров.

## Линтер — обязателен
- Прогоняй изменённый BSL через **BSL Language Server** перед финализацией.
- Обязательно исправляй диагностики уровня **Error**; Warning — по возможности.

## Чего держаться
- Сильные стороны: анализ кода, документирование, декомпозиция, ревью с линтером, поиск зависимостей.
- Слабые: бизнес-логика, формы, оптимизация запросов — здесь предлагай решение, но финальное слово за разработчиком.
