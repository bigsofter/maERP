# Учёт часов разработки → портал TinyCIO

Каждая задача уходит в портал закрытым тикетом на системного исполнителя — John Dow (разработка)
или «Ivan Gurkin (постановка)» (время владельца), вне счёта заказчику (`internal_cost`). Месяц закрывает владелец; скилл только
пишет задачи. Контракт ручки — `docs/ai/contracts/devcost-api.md` в репозитории tinycio.

## Когда

**Перед каждым коммитом** в репозитории продукта: оцени то, что сделано с прошлой записи, и отправь. Без
записанной задачи коммит не делать. Ещё — по просьбе владельца («что за день», «учти», «куда ушло время»).

Не учитываются: репозиторий **tinycio** (сам портал) и **chatben** — там скилл ничего не отправляет.
Продукт определяет `push.py product` по корню репозитория (работает и в worktree):

| Репозиторий | product |
|---|---|
| maOptique | maOptique |
| maTransports | maTransports |
| shukranpay | ShukranPay |
| MaRessources | maRessources |
| maBoutique | maBoutique |
| maERP | maERP |

## Шаг 1. Факты, а не план

```bash
git status --short; git diff --stat; git diff --staged --stat
D=$(date +%Y-%m-%d); N=$(date -v+1d +%Y-%m-%d)
git log --format='%h %ad %s' --date=format:'%H:%M' --after="$D 00:00" --before="$N 00:00" | cat
python3 ~/.claude/skills/task-time-tracking/push.py list --from $D --to $D   # что уже записано сегодня
```

Границы дня — полной формой `--after="ГГГГ-ММ-ДД 00:00"` (короткое `--since=` на этой машине отдаёт пустоту).
Тело коммита — главный источник «почему так»: читай целиком.

- Каждая подзадача привязана к реальному файлу, коммиту или выполненной команде. Пустой diff — оценивать нечего.
- Что не сделано — не приписывать; план — намерение, учёт — факт.
- То, чего не видно в git, тоже работа: разведка, отвергнутый заход, проверка на проде, разбор чужого бага.
- Не повторять уже записанное (сверься с `push.py list`).

## Шаг 2. Задача и подзадачи

**Одна задача = один логический блок работ** (тема дня, фича, сборка maERP), а не коммит: волна модуля — одна
задача с 4–8 подзадачами; пять коммитов по одной странице — одна подзадача. Заголовок задачи — коротко, о чём
блок («Обмен между базами: HTTPS и диспетчер»). Подзадачи дробить мелко (10–90 минут), граница — смена роли
или предмета.

**Роли — закрытый список:** Бэкенд · Фронтенд · QA · Продакт · Девопс · Архитектура · Дизайн.
**Категория** — бизнес-цель («Интеграция с …», «Новая фича …», «Починка данных», «Приёмка», «Документирование»).

## Шаг 3. Оценка «как делал бы человек»

Человек читает код, переключается, дебажит, обсуждает. К чистому кодингу: вникание +30–50 %, отладка и тесты
+20–40 %, переключение контекста +10–15 %. Ориентиры: мелкая правка 00:20–00:45, средняя (2–5 файлов) 01:00–02:30,
крупная 02:30–06:00. Больше двух часов на подзадачу — не разбита. Не округлять (00:47, 01:23, а не 01:00).
Сопутствующие подзадачи, когда они реально были: постановка и декомпозиция, ревью, мерж, выкат и проверка, документация.
Объём диффа калибрует, но не задаёт оценку: лок-файлы и переводы — тысячи строк за полчаса, найденная дыра — три строки за час.
Часы одной задачи — **не больше 24**; больше — значит это несколько задач.

## Шаг 4. Заказчик (billto) и исполнитель

- `billto` — `TinyCIO` (собственный продукт) или код заказчика, если работа делается под него. У **maERP** —
  по правилу «Текущий клиент» в `~/Dev/maERP/CLAUDE.md` (Drissotex, 2MZL, Afnan, FlyCDI, Isofroid, Socassif…).
  Неясно, под кого работа, — **спроси владельца**, не гадай.
- `executor` — `john_dow` (разработка) или `ivan_gurkin` (время владельца — системный
  сотрудник «Ivan Gurkin (постановка)», не сам владелец на окладе). Работу, которую владелец **явно** взял на себя
  («это я делал сам», «запиши на меня»), — целиком на `ivan_gurkin`.

### Время владельца на постановку (обязательно, решение 15.11)

Владелец платит своим временем за каждую сессию с ИИ — его тоже записывай. К каждой отправке разработки добавь
**вторую задачу** на `ivan_gurkin` с заголовком «Постановка и контроль: <тема задачи>» (тот же `billto`), если в
сессии были сообщения владельца. Подзадачи — по реальной переписке этой сессии, не по шаблону:

| Подзадача | Ориентир |
|---|---|
| Постановка: сформулировал задачу, промпт, вставил материалы | 00:05–00:20 на постановку (длинная, с файлами — до 00:40) |
| Ответы на вопросы ИИ и решения (выбор варианта, правила, цифры) | 00:03–00:10 на короткий ответ, 00:10–00:25 на решение с обдумыванием |
| Приёмка: прочитал отчёт, проверил результат, вернул на доработку | 00:10–00:30 на круг |
| Проверка на стенде/проде своими руками (если была) | по факту, 00:10–00:40 |

Считай сообщения владельца в сессии: короткие реплики («да», «выкатывай») — по 2–3 минуты, а не 0. В `descr`
перечисли, что именно владелец решал (по-русски, в прошедшем времени: «решил: доли партнёров не исключаем»).
Если владельца в сессии не было (автономный запуск) — второй задачи нет. Задача «Постановка…» отправляется тем же
`push.py send` отдельным JSON.

- Нет маршрута «продукт × заказчик» (ответ 422 «нет маршрута») — посмотри `push.py targets`; новый маршрут
  (только НОВЫЙ — существующий меняет владелец) заводится `push.py target-put '{"product":"maERP","billto":"FlyCDI","client_id":2184,"service_object_id":1893,"initiative_id":…,"competency_code":"1С"}'`
  (объект и инициатива обязаны принадлежать заказчику — сервер проверит). id спроси у владельца.

## Шаг 5. Отправка

Собери JSON и отправь:

```bash
cat > /tmp/devcost-task.json <<'EOF'
{
  "billto": "TinyCIO",
  "date": "2026-11-15",
  "title": "Обмен между базами: HTTPS и диспетчер",
  "source": "maERP develop 1a2b3c4..5d6e7f8",
  "subtasks": [
    {"task": "HTTP-сервис обмена с техпользователем и подписью", "hours": 1.4, "role": "Бэкенд",
     "category": "Интеграция между базами", "descr": "Проблема и предпосылки: … Что сделано: … Файлы: …"},
    {"task": "Ревью и правки по замечаниям", "hours": 0.6, "role": "QA", "category": "Приёмка", "descr": "…"}
  ]
}
EOF
python3 ~/.claude/skills/task-time-tracking/push.py send /tmp/devcost-task.json
```

- `hours` — десятичные часы (01:23 → 1.38). `date` — день работы, не старше 7 дней и не в будущем.
- `descr` — в прошедшем времени, от лица программиста, с решением и причиной или числом; файлы и компоненты
  перечисляй. Проверка: человек через год узнает что-то, чего нет в заголовке коммита?
- `ref` считается сам (продукт, заказчик, дата, заголовок): **повтор с тем же заголовком в тот же день вернёт
  тот же тикет** и ничего не изменит. Продолжение работы в тот же день — новый заголовок.
- Ответ 409 «ref уже записан … с другим содержимым» — та же дата и заголовок уже заняты другой задачей:
  дай новый заголовок (часы не теряются молча).
- Ответ — номер тикета. **Покажи номер(а) в итоге сессии.**
- Нет сети / портал недоступен — задача ляжет в `~/.config/tinycio/devcost-outbox/` и уйдёт при следующем
  `send` или `push.py flush`. Отказ 4xx (кроме 404) — исправь задачу; из очереди отказанные уходят в `rejected/`.

## Чего не делать

- Не писать md-отчёты в `reports/` и xlsx в «Загрузки» — старый путь (архив, его больше не разбирают).
- Не выдумывать задачи ради ровного дня и не округлять всё до 01:00.
- Не класть токен в репозиторий: он только в `~/.config/tinycio/devcost.env` (`DEVCOST_TOKEN=dct_…`).
